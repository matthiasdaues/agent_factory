## Feature

- Proposal trace: [accepted proposal](../proposals/implemented/usage-processing-and-storage.md)
- Gherkin trace: [local-usage-processing-and-analysis.feature](local-usage-processing-and-analysis.feature)
- Summary: QA protects local evidence integrity first. It proves strict all-line validation, CLI-specific conservation, deterministic view results, transcript blindness, atomic export, capture independence, and data-safe component lifecycle without duplicating arithmetic across layers.
- Rules in scope:
  - `Rule: Local operator queries only published views over a fixed local input set`
  - `Rule: Local operator obtains conservative canonical usage without duplication`
  - `Rule: Local operator diagnoses all invalid evidence before accounting`
  - `Rule: Local analyst consumes typed table, JSON, relation, and Arrow results`
  - `Rule: Local operator exports attributable Parquet without damaging prior output`
  - `Rule: Local analyst receives a verified DuckDB UI exploration path`
  - `Rule: Project maintainer manages the opt-in usage-analysis component without accidental data loss`
  - `Rule: Factory producer publishes a compatible record contract without depending on analysis`
  - `Rule: Quality maintainer assigns one deterministic owner to each observable contract`

### Spec marker convention

Pytest owners carry the scope contract ID:

```python
@pytest.mark.spec("LU-03")
@pytest.mark.contract
def test_claude_code_conserves_root_and_distinct_children(): ...
```

The marker joins tests to this owner table and lets mutation analysis classify a survivor without relying on a mutable file path.

## Test Retention Policy

- Surviving owners are the usage contract gate for record validity, SQL contract tests for arithmetic, focused deterministic gates for registry/reproducibility/preflight/dependencies, and integration tests for filesystem and process boundaries.
- Remove query-command or Parquet assertions that recalculate session totals already owned by LU-03. Retain only projection, schema, null, provenance, and replacement behavior there.
- Keep one owner per contract under [testing-strategy.md](../../packages/factory/rulebooks/conventions/testing-strategy.md).
- Before deleting overlap, prove the surviving owner detects a representative fault, remove one redundant test at a time, run the focused suite, then run the full suite as required by [Delete overlapping tests safely](../../packages/factory/rulebooks/conventions/testing-strategy.md#delete-overlapping-tests-safely).
