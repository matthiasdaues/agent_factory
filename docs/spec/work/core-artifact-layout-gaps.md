## Decisions Recorded in This Pass

- **ST-0324b, chapter 12 beside an existing glossary (stakeholder,
  2026-11-02).** The chapter 12 sections join an existing `docs/spec/glossary.md` as sections of their own, as the `CONTEXT.md` terms do (DEC-18); the script lists duplicate terms and exits 0, and `Scenario: Chapter 12 tables join an existing glossary` holds it.
- **SPEC-0024, glossary history (stakeholder, 2026-11-02).** The script does
  not keep the glossary's git history as a rename, and it commits nothing.
  The path-table outline has no glossary row. The glossary Rule states that
  git shows `docs/spec/glossary.md` as added and `docs/arc42/12_glossary.md`
  as modified, and that `git log docs/arc42/12_glossary.md` keeps the earlier
  history readable. Git cannot record a rename here, because the script
  writes a new chapter 12 at the old path and converts every table row.
- **ATAM-0003, version record (stakeholder, 2026-11-02).** `init-factory`
  writes the new `factory_version` into `install.json` only after
  `migrate-spec-layout` succeeds. A failed migration leaves the prior version,
  and `init-factory` reports that the project is still in the old layout and
  names the fix: run the update again. A missing or `unknown`
  `factory_version` counts as older. Only a missing `install.json` is a first
  install. The feature holds this in
  `Rule: Project maintainer receives the new layout with the factory update`.
  The contracts are in
  [interface-contracts.md](../interface-contracts.md) under
  `init-factory` and `update-factory`. The decision below on old updaters
  replaces the earlier handling of `update-factory` before 1.1.0 and of
  `.agent-factory/factory-install.json`.
- **ATAM-0004, git state of moved files (stakeholder, 2026-11-02).** A tracked
  file moves with `git mv`, also with uncommitted changes. An untracked or
  ignored file moves with a plain file move, because git holds no history for
  it. The migration never blocks on a file's git state. The feature holds this
  in `Rule: Project maintainer moves the project into the new layout with its history kept`, in two new Scenarios. The `migrate-spec-layout` contract
  states it in its Moves row. Removals and the state of the repository were
  settled afterwards as CAL-G17 and CAL-G18.
- **ATAM-0003 revisited, supported updaters (stakeholder, 2026-11-02).** The
  layout release supports updates only from an installed `update-factory`
  `v1.1.0-rc` or later, the first release with the full rollback. A project
  on an older release updates to 1.3.x first, as the release notes say. No
  check enforces this. The specification no longer handles the old install
  record `.agent-factory/factory-install.json` or an `update-factory` before
  `v1.1.0-rc`. This makes ATAM-0005 and M-09 of the spec review out of scope.
- **ATAM-0006 and SPEC-0028, removal of a changed tracked file (stakeholder,
  2026-11-02).** A tracked file in the removal set with uncommitted changes,
  staged or unstaged, stays in place and is listed for the developer to
  delete, the same rule as for an untracked or ignored file (CAL-G17). The
  script never runs `git rm -f`. The `migrate-spec-layout` Removes row and
  `Scenario Outline: A file that the path table removes stays and is listed when git cannot remove it safely`
  hold it. The outline also covers the ignored file of M-08.
- **SPEC-0029, version comparison (stakeholder, 2026-11-02).** `init-factory`
  compares factory versions by Semantic Versioning 2.0.0 precedence. So
  `1.4.0` is older than `1.10.0`, and `1.4.0-rc` is older than `1.4.0`. A
  missing value, `unknown`, or a value that does not parse counts as older.
  The `init-factory` Version comparison row and
  `Scenario Outline: init-factory compares factory versions by Semantic Versioning precedence`
  hold it, owned by CAL-07-CT-01.
- **Minor items (stakeholder, 2026-11-02).** The QA failure-mode row for the
  removal set and the busy repository cites its two Scenarios instead of the
  closed gaps CAL-G17 and CAL-G18 (M-07). QS-15 in chapter 10 covers only the
  supported updaters.

## Deferred Scope

The proposal defers DBML and its gates, a blocking gate for `glossary.md`, and
the merge of `todo.md` and `todos.md` (T-0008). This specification defines no
Rule for them.
