## Feature

- Proposal trace: [counter-ids-fitting.md](../../proposals/counter-ids-fitting.md)
- Gherkin trace: [counter-ids-fitting.feature](../features/counter-ids-fitting.feature)
- Summary: The highest risk is a number handed out twice during the move. A claim that lands between the read of the local counter and the marker must not reach `origin` unnoticed, because two branches would then create two files with one name. The second risk is a seed too low: `--plan-seed` that misses an ID in use, or counts an example in body text, starts a sequence on a number that exists. The third risk is a seed or a move that overwrites a counter in use. So the tests of `next-id` run against local bare repositories and local clones in `tmp_path`, force the move's race inside the test, and compare the refs before and after each call. The remaining Rules are text: the fitting step in `virgil.md`, the four orientation files, the ID producers, and `id-prefixes.md`. VIRGIL is agent text, so a text test checks what `virgil.md` tells VIRGIL to do. The behaviour that the step relies on is tested in `next-id` and `init-factory`.
- Rules in scope, with their scope identifiers from the [gaps report](counter-ids-fitting-gaps.md#actor-goal-matrix):
  - CIF-01 `Rule: User confirms the seed of the counter in a fitting step`
  - CIF-02 `Rule: VIRGIL points next-id at the project's own repository when origin is missing`
  - CIF-03 `Rule: User walks the seed step in a greenfield project`
  - CIF-04 `Rule: User sees the fitting finished only when all six fitting keys are true`
  - CIF-05 `Rule: next-id --plan-seed prints one seed command from the highest number of each ID prefix`
  - CIF-06 `Rule: next-id --plan-seed counts an old file name by its number and warns about it`
  - CIF-07 `Rule: next-id --plan-seed checks the remote before it plans a seed`
  - CIF-08 `Rule: ID Producer claims an ID from the local counter in a project without origin`
  - CIF-09 `Rule: VIRGIL offers to move a local counter to origin at the session start`
  - CIF-10 `Rule: next-id --move-to-origin moves the local counter to an origin without a counter`
  - CIF-11 `Rule: next-id --move-to-origin keeps the marker and the setting when origin holds a counter or the push fails`
  - CIF-12 `Rule: next-id --move-to-origin hands out no number twice while ID claims run during the move`
  - CIF-13 `Rule: init-factory derives counter_seeded from the remote that next-id uses`
  - CIF-14 `Rule: ID Producer names the literal ID prefix at each step that creates an indexed artifact`
  - CIF-15 `Rule: ID Producer that adds a todo entry names next-id T`
  - CIF-16 `Rule: User finds every ID prefix in one table in id-prefixes.md`
  - CIF-17 `Rule: User sees the text test fail when an ID producer or the prefix table drifts from next-id`

The harness exists: `test_next_id.py` holds the fixtures `env`, `remote`, and `clone` and the helpers `_bare`, `_set_counter`, `_counter`, and `run`. `test_init_factory_counter.py` runs `init-factory` as a subprocess on a temporary project.

Agents do not run these commands by hand. The guardrail hook blocks `uv run pytest` in an agent's shell command, so the tests run through the commit hooks.

### Test setup

Every test runs on local repositories in `tmp_path`. No test reads, fetches from, or pushes to this project's remote.

- **Remote.** A local bare repository stands in for `origin`, as in `test_next_id.py`. A fixture that needs a counter writes the claim commit inside the bare repository with `git commit-tree` and sets the ref with `git update-ref`, as `_set_counter` does. The fixture pushes nothing.
- **Local counter.** The project is a repository in `tmp_path` with no `origin`. `next-id --seed 0` writes `refs/ids/counters` into its own `.git`, and `git worktree add` creates the second worktree. A local clone gets the project's path as its `origin`.
- **Made-up remote with user info.** CIF-10 and CIF-11 need an `origin` URL such as `https://user:token@host/demo.git`. The test sets that URL on the repository and adds `url.<bare path>.insteadOf` for it to the repository's own config. So git talks to the local bare repository, and `next-id` sees the made-up URL. The token is the made-up string `token`.
- **Git config.** Each test sets `HOME` to an empty directory in `tmp_path` and sets `GIT_CONFIG_NOSYSTEM=1` and `GIT_TERMINAL_PROMPT=0`, as the `env` fixture of `test_next_id.py` does. So the developer's global identity, URL rewrites, and credential helpers never reach the test.
- **No leak.** No assertion prints a remote URL or a git config. A failing assertion shows the redacted form `https://***@host/demo.git` only. The tests reuse `_assert_no_token` of `test_next_id_redaction.py` on every output of a failing path.
- **Unreachable remote.** The test binds a socket to `127.0.0.1` on port `0`, reads the port, and closes the socket, as `_closed_port_url` does. The URL `http://127.0.0.1:<port>/remote.git` refuses at once, so no test waits for a timeout.
- **Refused push.** CIF-11-IT-02 installs a `pre-receive` hook in the bare repository. The hook prints `read-only` on standard error and exits `1`, as CID-04-IT-02 does for a claim.
- **Forced race of the move.** CIF-12-IT-01 forces the claim between the read and the marker, as `next_id_race.py` forces stale leases. It loads `next-id` with `load_script`, wraps the function that reads the local counter, and runs a real `next-id ST` subprocess in a second worktree right after the first read returns. So the local counter moves from `ST=0012` to `ST=0013` before the marker is set, on every run, with no timing. The test then lets the move continue and checks the result. The test needs the story to keep the read as one function that the test can wrap.
- **Refs compared.** CIF-05-IT-01, CIF-13-IT-02, and the failing paths list `git for-each-ref` of the clone and of the bare repository before and after the call and compare the two lists.

### Spec marker convention

The scope ID of the contract-owner row is the value of the `spec` marker. Add the layer marker beside it.

```python
@pytest.mark.spec("CIF-12-IT-01")
@pytest.mark.integration
def test_move_reads_again_after_a_claim_before_the_marker(): ...
```

The marker description in `pyproject.toml` names `CID-*` and must name `CIF-*` too (see [Gap Findings](#gap-findings)). The marker taxonomy (`acceptance`, `contract`, `integration`, `e2e`) and the test-ID naming stay with the project.

- CIF-10-IT-01 and CIF-11-IT-01 guard a counter on `origin` against an overwrite. Keep both.

- CIF-08-IT-04 and CIF-12-IT-02 both end in the marker's failure message. CIF-08-IT-04 owns the message from a local clone. CIF-12-IT-02 owns the claim from a worktree of the project after the marker. Keep both, because the two paths resolve the remote differently.

- CIF-13-CT-01 owns the read-only call and CIF-13-IT-02 owns the refs after it. Keep both, because a call that writes could pass the ref comparison on a second run.
- CIF-08-IT-03 is `test_st_0370_clone_without_origin_names_origin_remote_and_seed`. Keep the test, and set its precondition to a clone without `origin` and without `agent-factory.counterRemote`.
- The story that adds the sixth key replaces `test_all_true_is_fitted` and the "three of five" test with six-key versions. CIF-04-CT-01 then owns `_fitting_status`.
- Remove a text test of CIF-14 to CIF-16 when a later feature replaces the instruction it reads.
- Keep one owner per contract under [testing-strategy.md § One contract, one owner](../../../packages/factory/rulebooks/conventions/testing-strategy.md#one-contract-one-owner). Follow [Delete overlapping tests safely](../../../packages/factory/rulebooks/conventions/testing-strategy.md#delete-overlapping-tests-safely) before removing overlap.
