## Feature

- Proposal trace:
  [core-artifact-layout.md](../../proposals/core-artifact-layout.md)
- Gherkin trace: [core-artifact-layout.feature](../features/core-artifact-layout.feature)
- Summary: The highest risk is a migration that damages a project during a
  factory update. The tests check that `migrate-spec-layout` moves tracked files
  as git renames and other files with a plain move, rebases links, never stops
  on two vocabularies, and undoes every change it made on failure. They also
  check that `init-factory` runs the script only on an update and compares
  versions by Semantic Versioning 2.0.0 precedence. A failed migration keeps
  the prior factory version, and `update-factory` then rolls the whole update
  back. The second risk is a gate that silently skips a file at its new path, so each
  gate gets a test that seeds an error at the new path. Pure conversions, such
  as the path table, link rebasing, and glossary tables, belong to contract
  tests. Moves, git history, hooks, and the update path need real temporary
  Git repositories and belong to integration tests.
- Rules in scope, with their scope identifiers:
  - CAL-01 `Rule: Newcomer finds the whole specification core at one root`
  - CAL-02 `Rule: Project maintainer previews the layout migration without changes`
  - CAL-03 `Rule: Project maintainer moves the project into the new layout with its history kept`
  - CAL-04 `Rule: Project maintainer keeps every Markdown link working after the move`
  - CAL-05 `Rule: Project maintainer learns every old path that the script does not rewrite`
  - CAL-06 `Rule: Project maintainer gets one glossary from chapter 12 and from every vocabulary file`
  - CAL-07 `Rule: Project maintainer receives the new layout with the factory update`
  - CAL-08 `Rule: Project maintainer folds context routing into the agent context file`
  - CAL-09 `Rule: Project maintainer's gates check the core at its new paths`
  - CAL-10 `Rule: Project maintainer checks glossary terms and business rules without use-case files`
  - CAL-11 `Rule: Project maintainer publishes the architecture PDF with the glossary as chapter 12`
  - CAL-12 `Rule: CLI-invoked agent reads and writes the core at its new paths`
  - CAL-13 `Rule: Factory maintainer keeps the factory free of old paths`
  - CAL-14 `Rule: Factory maintainer migrates the factory's own repository first`
  - CAL-15 `Rule: Project maintainer starts feature work once the anchor files exist`

### Spec marker convention

Pytest tests carry the Rule's scope identifier and their layer marker:

```python
@pytest.mark.spec("CAL-07")
@pytest.mark.integration
def test_failed_migration_restores_files_and_factory_version(): ...
```

The marker ties each test to its row in this table and lets mutation testing
join a mutant to its contract.

## Test Retention Policy

- Keep the `migrate-spec-layout` contract and integration tests while the
  factory ships the script, because older installs still update through it.
- Keep CAL-13-LN-01 and CAL-13-LN-02 as regression guards, so an old path
  cannot come back into factory files.
- Keep one seeded-error test per gate (CAL-09-IT-01). Remove an older gate
  test that checks the same file at the old path.
- The acceptance runs CAL-08-AC-01 and CAL-14-AC-01 happen once and leave no
  retained test.
- Keep one owner per contract under
  [testing-strategy.md](../../../packages/factory/rulebooks/conventions/testing-strategy.md).
  Follow
  [Delete overlapping tests safely](../../../packages/factory/rulebooks/conventions/testing-strategy.md#delete-overlapping-tests-safely)
  before removing overlap.
