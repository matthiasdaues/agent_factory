# Term Candidates

Each row is a term that waits for the stakeholder's confirmation. The domain-modeling agent moves a confirmed row into `docs/spec/glossary.md` and removes it here (BR-065).

| Term         | Domain area   | Source                                                                                                     | Proposed definition                                                                                                                                                                   | Status    | Note                                                                                                                                            |
| ------------ | ------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Dispatch Run | Run lifecycle | [run-lifecycle.md § Terms](../../proposals/run-lifecycle.md#terms)                                         | Everything the Factory does for one feature branch, from `dispatch init` to `dispatch close`. Documents shorten it to run. One playbook run contains the dispatch run of its feature. | confirmed | The proposal settles the entry. Playbook Run is wider, and Unattended Run and Logical Run name other things, so their entries keep their words. |
| orchestrated | Run lifecycle | [run-lifecycle.md § Terms](../../proposals/run-lifecycle.md#terms)                                         | The way of driving a run in which the implementation agent starts stories in waves. | by hand      | Run lifecycle | [run-lifecycle.md § Terms](../../proposals/run-lifecycle.md#terms)                                         | The way of driving a run in which the human decides when each story starts. | unit of work | Run lifecycle | [run-lifecycle.md § Findings as units of work](../../proposals/run-lifecycle.md#findings-as-units-of-work) | A story or a blocking finding that runs through the story workflow on the branch `story/<id>`.                                                                                        | confirmed | `premerge-check` reads the ID of the unit of work from the branch name.                                                                         |
