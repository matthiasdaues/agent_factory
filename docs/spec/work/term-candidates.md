# Term Candidates

Each row is a term that waits for the stakeholder's confirmation. The domain-modeling agent moves a confirmed row into `docs/spec/glossary.md` and removes it here (BR-065).

| Term                  | Domain area            | Source                                         | Proposed definition                                                                                                                                                                                                                                                                        | Status   | Note |
| --------------------- | ---------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | ---- |
| Migration Agent       | Finding Classification | spec review SPEC-0079 on docs/spec/glossary.md | The agent that runs the one-time migration of every open finding without `review_class` (BR-095). It classifies each finding with the rulebook, rewrites its artifact, fills `## Possible damage` for a `critical` result, and changes the files only after the stakeholder's pause point. | proposed |      |
| Calibration Example   | Finding Classification | spec review SPEC-0079 on docs/spec/glossary.md | A finding that a class section of the rulebook lists with its basis, two or three per severity level. A reviewer agent reads them before its first classification of a session. A level without a real finding carries one invented example that names real project files.                 | proposed |      |
| Child-Result Envelope | Finding Classification | spec review SPEC-0079 on docs/spec/glossary.md | The short result that a child agent returns to the agent that started it: `disposition`, `finding_counts`, `artifact_paths`, and `next_action`, as interface-contracts.md § Child-result envelope defines. The full detail stays in the files that `artifact_paths` names.                 | proposed |      |
| Category              | Finding Classification | spec review SPEC-0079 on docs/spec/glossary.md | The first value of a finding: what kind of finding it is. A `defect` is wrong as it stands, a `risk` of the architecture class may fail a stated requirement, and a `suggestion` describes material that works but could improve. A `question` becomes a `todo.md` entry and no finding.   | proposed |      |
