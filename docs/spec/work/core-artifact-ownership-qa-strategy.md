## Feature

- Proposal trace: [core-artifact-ownership.md](../../proposals/core-artifact-ownership.md)
- Gherkin trace: [core-artifact-ownership.feature](../features/core-artifact-ownership.feature)
- Summary: The highest risk is a core artifact that silently keeps a second writer or loses its review, because then the rule of one producer holds only on paper. So the producer and review contract test and the `index-lint` reviewer check carry the weight of this feature. Both read declarations, so they belong to contract tests on fixture catalogs and to one linter check on the factory's real `INDEX.yaml`. The second risk is a wave that closes with an unhandled drift row, or never closes because a row cannot reach `confirmed`. `dispatch close-wave` therefore gets integration tests on temporary ledgers and reports. Most other Rules change agent and skill text. A linter test checks that the text states the rule; it cannot check that an agent follows it. The first real run of each new agent checks the behaviour.
- Rules in scope, with their scope identifiers:
  - CAO-01 `Rule: Factory maintainer finds exactly one producer for every core and seam artifact`
  - CAO-02 `Rule: Factory maintainer sees every declared review checked against the reviewer's inputs`
  - CAO-03 `Rule: Requirements agent keeps scope and behaviour only`
  - CAO-04 `Rule: Domain-modeling agent produces the domain structure family`
  - CAO-05 `Rule: Stakeholder confirms every glossary term before it enters the glossary`
  - CAO-06 `Rule: Agents other than the domain-modeling agent record terms as candidates`
  - CAO-07 `Rule: Architecture agent owns the components and their dependency rules`
  - CAO-08 `Rule: Spec-review agent reviews behaviour and domain structure`
  - CAO-09 `Rule: Architecture-review agent reviews the dependency rules`
  - CAO-10 `Rule: Test-strategy agent owns the test practice family`
  - CAO-11 `Rule: Implementation agent blocks a merge on a failing test guardrail`
  - CAO-12 `Rule: Test-strategy agent resolves the surviving mutants that a developer agent cannot resolve`
  - CAO-13 `Rule: Developer agent reports specification drift without editing the specification`
  - CAO-14 `Rule: Implementation agent closes a wave only after the owners have handled every drift row`
  - CAO-15 `Rule: Reconciliation agent reports drift to each artifact's owner`
  - CAO-16 `Rule: Owner receives every finding it acts on next`
  - CAO-17 `Rule: Factory maintainer sees every writer of shared working output declare its path`
  - CAO-18 `Rule: Human operator reaches the new owners through the playbooks and the routing`
  - CAO-19 `Rule: Orchestrator brings every reconciliation row back to its owner and the owner's reviewer`

### Spec marker convention

Pytest tests carry the Rule's scope identifier and their layer marker:

```python
@pytest.mark.spec("CAO-14")
@pytest.mark.integration
def test_close_wave_fails_on_fixed_row_about_core_artifact(): ...
```

The marker ties each test to its row in this table and lets mutation testing join a mutant to its contract.
