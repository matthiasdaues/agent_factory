## Feature

- Proposal trace: [run-lifecycle.md](../../proposals/run-lifecycle.md)
- Gherkin trace: [run-lifecycle.feature](../features/run-lifecycle.feature)
- Summary: The highest risk is a merge that passes a check it should fail. `premerge-check` must read the review report and the finding files at the branch head, not in the folder where it runs. It must also rerun every gate in a temporary worktree instead of reading a stored result. If one of these reads goes to the wrong place, failing code merges and nobody sees it. So integration tests on temporary git repositories own every story check and every feature merge check. Each test puts the passing state in one place and the failing state in the other. The second risk is work that a command destroys: `dispatch close` removes worktrees and branches, `--orphans` removes ledgers, and `merge-story` moves the feature branch back. Each removal gets an integration test that checks what stays: the unmerged branch, the named stash, the ledger with an unfinished story. The third risk is the guardrail in five agent tools. The shell script owns the rules, and integration tests feed it each tool's payload. The pi wrapper and the OpenCode plugin get `node:test` tests with a stub script, so a rule of their own shows up as a wrong answer. Only a real OpenCode session shows that OpenCode calls the plugin at all, as [Behaviour that needs a real agent session](#behaviour-that-needs-a-real-agent-session) describes. The ledger states, the attempt count, and the gate list are pure logic, so contract tests own them. Many Scenarios describe what an agent does, such as the stops of a run by hand. Text checks of the agent instructions own those, and the mechanical checks of `premerge-check` and the guardrail stand behind them.
- Rules in scope, with their scope identifiers from the [gaps report](run-lifecycle-gaps.md#actor-goal-matrix):
  - RL-01 `Rule: User starts a run on a feature branch in either way of driving it`
  - RL-02 `Rule: Implementation agent runs every story through the same story workflow on both ways`
  - RL-03 `Rule: User approves each step that needs a person in a run driven by hand`
  - RL-04 `Rule: Reviewer agent files reviews and findings that name their story or run`
  - RL-05 `Rule: Implementation agent retries a failing gate within the configured attempts`
  - RL-06 `Rule: User decides how a stopped story continues`
  - RL-07 `Rule: Implementation agent starts a story only when its dependencies inside the run are done`
  - RL-08 `Rule: Implementation agent merges a unit of work only when premerge-check passes at its branch head`
  - RL-09 `Rule: Test-strategy agent sets the gates of every story in docs/testing.yaml`
  - RL-10 `Rule: Developer agent learns at commit time that its imports break a dependency rule`
  - RL-11 `Rule: Implementation agent starts the next wave only after the wave close`
  - RL-12 `Rule: Implementation agent runs a blocking finding from the feature checks as a unit of work`
  - RL-13 `Rule: User merges the feature branch into dev only after the feature merge check passes`
  - RL-14 `Rule: User ends a run and leaves no run state behind`
  - RL-15 `Rule: User cleans up the runs that no active run owns`
  - RL-16 `Rule: User keeps agents from destroying work in every agent tool`
  - RL-17 `Rule: Factory maintainer finds in the dispatch contract exactly the fields the ledger holds`
  - RL-18 `Rule: Factory maintainer runs the tests against the source, not the installed copy`
  - RL-19 `Rule: Factory maintainer reads one vocabulary in every Factory document`

One contract of this feature has a working check: `index-lint --check` runs in the pre-commit hook `agent_factory_hook-index-lint`. Every other row is planned. The harness exists: the dispatch tests build temporary repositories with a feature branch and story worktrees, and `test_block_dangerous_git.py` runs the guardrail script as a subprocess.

The contract tests import `dispatch`, `dispatch_lib.py` and `premerge-check` with `load_script` and call their functions without a subprocess. A function that needs git state moves its row to the integration layer.

Agents do not run these commands by hand. The guardrail blocks `uv run pytest` in an agent's shell command, so the tests run through the commit hooks and in the gate-check step.

### Test setup on temporary git repositories

Every integration test builds its own repository in `tmp_path`. No test reads the branches, ledgers, or worktrees of this project, except the one-time check of [RL-15](#one-time-checks).

- **Branches.** A fixture runs `git init -b main`, creates `dev`, and commits `backlog/ST-0350.md` to `backlog/ST-0353.md` with their `depends_on` fields. `dispatch init` then cuts `feature/login`.
- **Two ways.** One fixture starts an orchestrated run, and one starts a run by hand. The run by hand works in the primary checkout of the temporary repository, so its fixture asserts after each step which branch that checkout has checked out.
- **Git config.** Each test sets `HOME` to an empty directory and `GIT_CONFIG_NOSYSTEM=1`. Each repository sets `user.name`, `user.email` and `commit.gpgsign=false` in its local config.
- **Test command.** A fixture writes `docs/testing.yaml` with a `test_command` that exits `0`, and a second one that exits `1` for the red suite after a merge.
- **Gates.** A fixture writes `docs/testing.yaml` with `gates.license-check` and a command that writes a marker file and exits `0` or `1`. So a test sees that the gate ran on the branch head and in which folder.
- **Review reports and findings.** A fixture commits `docs/reviews/code-review-ST-0350-2026-11-24.md` with `story` and `branch_head`, and `docs/findings/BUG-0091.md` with `story`, `run`, severity and status. The "folder holds no open finding" cases commit the finding on the story branch only.
- **Primary checkout state.** RL-08-IT-05 and RL-13-IT-04 leave a changed tracked file and an untracked file in the primary checkout. They compare file contents and `git stash list` before and after.
- **Spec-feedback reports.** RL-11 reuses the report fixtures of `test_dispatch_close_wave_reports.py`.
- **Old ledgers.** RL-15-IT-03 writes a ledger with `mode: automated` and `invocation_branch`, and nests a second one inside a linked worktree under `.current-work/`.
- **Tool payloads.** RL-16-IT-02 passes each command on standard input in the payload format of Claude Code (`PreToolUse`), Codex, Copilot CLI (`preToolUse`) and pi, as `test_guard_human_fields.py` does for its guard.

### Spec marker convention

Each pytest test carries the scope ID of its row and its layer:

```python
@pytest.mark.spec("RL-08-IT-02")
def test_rl_08_premerge_check_reads_the_open_finding_at_the_branch_head(): ...
```

The `spec` marker exists in `pyproject.toml`, but its description lists only the prefixes ACX, CAL, CAO, CID, CIF and FC. The first story adds RL, as [Gap Findings](#gap-findings) records. The `node:test` files put the Test ID at the start of the test name, as `FC-18-CT-02` does in `agent-factory.test.ts`. The marker lets mutation testing join a killed mutant to its row.

### Tests that read this repository's installed copy

The proposal moves every test that reads this repository's installed copy `.agent-factory/factory/` to `packages/factory`. A static scan of `tests/` and `packages/usage/tests/` on 2026-11-18 found this:

- `tests/conftest.py` already loads every script from `packages/factory/scripts` and puts only that folder on `sys.path`.
- No test opens a path under `REPO_ROOT / ".agent-factory" / "factory"`.
- `tests/factory/test_core_layout_gates.py`, line 484, links `REPO_ROOT / ".agent-factory"` into a baseline copy of this repository. The CAL test then runs `scope-lint`, which reads `.agent-factory/workstreams` there, not `.agent-factory/factory`. [OI-08](#open-items) asks whether this link counts.
- Every other mention of `.agent-factory/factory` in a test is either a path in a temporary project or a string that a text test looks for in a document. Both stay, as the second half of the RL-18 Scenario requires.
- `packages/factory/scripts/dispatch`, lines 1954 to 1962, copies `packages/factory` over `.agent-factory/factory` in `merge-story`. Its comment says that tests import from `.agent-factory/factory/scripts/`. That no longer holds for `conftest.py`. RL-18-IT-01 checks that the copy is gone.

A static scan cannot see a script that a test runs with `cwd=REPO_ROOT` and that reads `.agent-factory/factory` at runtime. The RL-18 story finds those reads by running the suite once in a linked worktree, which holds no `.agent-factory/` because git ignores it. After RL-08 and RL-13, `premerge-check` runs the suite in such a worktree at every merge. So a runtime read that comes back fails the next merge.

## Test Retention Policy

- Surviving owner per major contract: the integration tests of `premerge-check` (RL-08, RL-13) and of `dispatch close` (RL-14, RL-15) own the merge and the removal. The contract tests own the ledger states (RL-06-CT-01), the attempt count (RL-05-CT-01) and the gate list (RL-09-CT-01). The guardrail script's integration tests (RL-16-IT-01 to RL-16-IT-06) own every refusal, and the `node:test` files own only the hand-over to the script.
- Tests that this feature makes wrong: `test_a_null_testing_yaml_command_falls_back_to_project_json` and `test_project_json_is_the_fallback_without_testing_yaml` in `test_dispatch_run_blockers.py` (RL-01-CT-01). `test_story_branch_extracts_id`, `test_non_story_branch_returns_none` and `test_nested_story_branch_returns_none` in `test_premerge_check.py` change with the wider branch pattern (RL-08-CT-01). The `test_st_0359_*` tests of `test_premerge_check.py` that read stored results change to the rerun, except for `mutation-testing` (RL-08-IT-04, RL-09-CT-01). `block-dangerous-git.test.ts` tests pi's own rules today. Its `BUG-0124` cases move to `test_block_dangerous_git.py` when the rules leave the TypeScript file (RL-16-CT-01, RL-16-IT-04). The story that changes each behaviour rewrites or deletes these tests in the same commit.
- Expected overlap to remove later: the end-to-end journey RL-02-E2-01 passes through `init`, `prepare-story`, `merge-story` and `close`. It asserts only the end state of the run, not the details that the integration rows own. `test_dispatch_merge_safety.py` and `test_dispatch_run_blockers.py` cover parts of `merge-story` and `prepare-story` today. Where an RL row covers the same failure mode, the older test goes after the RL row has caught a representative fault.
- Consolidation rule: keep one owner per contract per [testing-strategy.md](../../../packages/factory/rulebooks/conventions/testing-strategy.md).
- Deletion protocol: follow [testing-strategy.md § Delete overlapping tests safely](../../../packages/factory/rulebooks/conventions/testing-strategy.md#delete-overlapping-tests-safely).
