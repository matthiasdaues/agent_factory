# The TypeScript measure installs and runs ESLint's dependencies without a lock

**What is wrong:** Every run of the CRAP gate on this repository starts `npx --yes eslint@10.14.0`. That runs in the gate-check step of each story and in each story merge. The command fixes only the version of `eslint` itself. The dependencies of `eslint@10.14.0` are version ranges, such as `debug ^4.3.2` and `cross-spawn ^7.0.6`. The repository holds no `package-lock.json` and no `.npmrc`. So on a machine with an empty npx cache, npm installs the newest release that matches each range. It runs the install scripts of those packages and then runs their code with the privileges of the developer or the CI job. `--yes` removes the one prompt that would show the install. A compromised release of any package in that tree runs in the gate without a review. The `debug` package of this tree had such a compromised release in September 2025. This is CWE-494 (download of code without an integrity check) and CWE-1357 (reliance on an insufficiently trustworthy component). The usage runtime closed the same path for `tiktoken` with exact, hash-checked requirements (SEC-0003).

The reproduction is `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/feature-qa/sec-npx/repro.sh`. It prints the `npx --yes` call, finds no tracked npm lock file, lists the 30 dependency ranges of `eslint@10.14.0` from the npx cache, and shows `ignore-scripts` as `false`.

**Why this severity:** The attacker runs code with the developer's privileges, so the bar starts at Critical (`execution`). The attacker must first publish a malicious release of a package in ESLint's dependency tree (`second_breach`), which lowers the bar to High. The gate runs this by default on every story of this repository, with no opt-in and no prompt. The script exists only on the feature branch, so the code is not in use. High gives `major`.

**Fix:** Install ESLint from a committed lock. Commit a `package.json` and `package-lock.json` with integrity hashes for `eslint@10.14.0` next to the measure, for example in `scripts/crap-measure-typescript.d/`. Install them with `npm ci --ignore-scripts` at an explicit setup step that a person runs, and let the measure start the installed `node_modules/.bin/eslint` with no network access. A missing install then exits 1 and names the setup command. Add a test that the measure starts no `npx` and no package download.
