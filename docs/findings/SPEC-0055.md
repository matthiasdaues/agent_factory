# The QA strategy tests a seed range of 0 to 9999, which BR-069 refuses

**What is wrong:** BR-069 accepts seed numbers from 0 to 9998 and refuses a second pair for one prefix. The QA strategy still plans the old rule in two rows:

1. Contract row CID-01-CT-01 says the seed check "accepts whole numbers from 0 to 9999". Its error names only "the argument, or the prefix and the list". The prefix alone, for a second pair such as `ST=5 ST=7`, is missing.
2. The first Boundary Cases row says "Seed numbers `0` and `9999` pass" and adds `9999` to the Outline's examples as an accepted value.

A story that follows the strategy writes a test that expects `next-id --seed 9999` to succeed. That test fails against BR-069, or it pulls the code away from BR-069. No row tests the second pair for one prefix. No row tests the refused fetch of the Claim Lifecycle (`FetchRefused`) either.

**Fix:** In CID-01-CT-01, write the range as 0 to 9998 and add the second pair for one prefix with the prefix in the message. In the Boundary Cases row, make `0` and `9998` pass and `9999`, `10000`, `-1`, and `abc` fail, and add `ST=5 ST=7` as a failing pair. Add the refused fetch to the row of the CID-04 failure cases, or record why it has no test.
