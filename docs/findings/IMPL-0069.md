# The gate misreads the file paths of the diff, so a changed function can pass without a score

**What is wrong:** A story passes the gate with exit `0` although it changed a function above the threshold. This happens for every file of a project whose git config sets `diff.noprefix=true`, and for any file whose path holds a space. The implementation agent and `premerge-check` then receive a pass that judged nothing. The problem starts in `parse_diff`. It takes the path from the `+++ ` line of `git diff` and assumes the form `+++ b/<path>`. It cuts the first two characters and keys the changes by the rest. Three other forms of that line exist:

- With `diff.noprefix=true`, the line has no `b/`, so the cut removes the first two characters of the real path, such as `src/plain.py` to `c/plain.py`. `diff.srcPrefix` and `diff.dstPrefix` change the prefix the same way.
- A path with a space ends in a tab, such as `+++ b/src/my mod.py<TAB>`. The key then holds the tab and matches no row.
- A path with a quote, a backslash or a control character comes quoted, such as `+++ "b/a\"b.py"`, also with `core.quotePath=false`.

The rows of the measuring command name the real path, so `judged_rows` finds no changes for the file and judges none of its functions. A further path exists: with `--unified=0`, an added line whose content starts with `++ ` also starts with `+++ `. `parse_diff` reads it as a new file header and gives the later hunks of that file to a wrong key.

The behavior looks wrong, not intended. BR-131 judges every function whose range holds a changed line, and no rule exempts a git setting or a path form. The tests cover only plain paths under the default prefix.

```text
user git config diff.noprefix=true, or a path with a space
        ↓
git diff writes "+++ src/plain.py" or "+++ b/src/my mod.py<TAB>"
        ↓
parse_diff cuts two characters and keys "c/plain.py" or "src/my mod.py<TAB>"
        ↓
judged_rows finds no changes for the row of "src/plain.py"
        ↓
crap-score judges 0 functions and exits 0
```

The review checked both cases in a scratch repository with the branches `dev` and `story/ST-0001`. Each of `src/plain.py` and `src/my mod.py` had one function of complexity 9 with one changed line, and the threshold was 8. `crap-score --base dev` exited `1` and named only `src/plain.py`. With `git config diff.noprefix true`, the same call printed `judged 0 functions` and exited `0`. Under `diff.noprefix`, `git diff --src-prefix=a/ --dst-prefix=b/` gave `+++ b/src/plain.py` again (git 2.34).

**Why this severity:** The script exists only on the feature branch, so `in_use` is false. The story requires that every changed function is judged, and on these paths a changed function goes unjudged and the gate passes (yes to fails_purpose).

**Fix:** In `changed_lines`, pass `--src-prefix=a/ --dst-prefix=b/` to `git diff`, so no git config changes the prefix. `--default-prefix` needs git 2.41 and is no option for older git. In `parse_diff`, read a `+++ ` line only between a `diff --git` line and the first `@@` line of that file. Strip one trailing tab, and decode a path that starts with `"` as a C-quoted string before you cut `b/`. Add one test each to `tests/factory/test_crap_gate_score.py` for `diff.noprefix=true`, for a path with a space, and for an added line that starts with `++ `.
