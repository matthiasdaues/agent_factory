# Logical run to latest snapshot cardinality contradicts the prose contract

**What is wrong:** The entity diagram declares `LOGICAL_RUN }o--|| LATEST_RUN_SNAPSHOT`, which permits multiple logical runs to reduce to one latest snapshot. The surrounding invariants instead require one selected latest snapshot per logical-run key. The diagram and prose therefore give different cardinalities for the same reduction.

**Fix:** Change the relationship to one logical run to exactly one latest snapshot, or document a different cardinality consistently in the diagram and invariants.
