# CX-MODE severity contradicts mode validity requirement

**What is wrong:** The validation-rules.md contains a contradiction between the CX-MODE code definition and the field-level rules for the `mode` field.

The CX-\* finding codes table defines CX-MODE as:

> CX-MODE | info | Reports the `mode` field value (`primary` or `index`). Informational only

The field-level rules section states:

> `mode` must be exactly `primary` or `index`. Any other value is reported by `CX-MODE`.

These two statements conflict. The first says CX-MODE is always informational. The second says invalid mode values are caught by CX-MODE. An invalid value like `mode: staging` would produce only an info finding, which does not block. Since mode is a required field that governs the entire lifecycle (primary vs. index behavior), an invalid value should produce an error, not an informational message.

The .feature file has no scenario for an invalid mode value (the gaps report notes this at "low" severity), so the expected behavior is unspecified.

**Fix:** Either split CX-MODE into two behaviors (info for valid values, error for invalid values), or introduce a separate error-severity code (e.g., `CX-MODE-INVALID`) for unrecognized mode values. Add a corresponding scenario to the .feature file specifying that an invalid mode value produces an error finding.
