# Seams-first test file ownership ambiguous across story template fields

**What is wrong:** The story template defines two fields: `tests:` ("pre-existing test file paths that cover this story's acceptance criteria") and `outputs:` ("files the story is expected to produce"). For a `strategy: seams-first` story, the seam session writes new test files. These new test files are not pre-existing, so they do not belong in `tests:`. They are files the story produces, so they should be in `outputs:`. But Phase 3 Completion Criteria state "backlog-lint rejects seams-first when test paths fall outside outputs" -- this validation operates on `tests:` (checking that test paths are within `outputs:`), conflating the two fields' semantics. Furthermore, the implementation session writes source files that are also in `outputs:`. The step-guard write guard would need to allow the seam session to write only test files from `outputs:` and the implementation session to write only source files from `outputs:`, but the manifest has a single `outputs:` list with no per-session filtering.

**Fix:** Define how the seam and implementation sessions partition the story's `outputs:`. Options: (a) add a `seam_outputs:` field to the story template that lists test file paths separately from `outputs:`, and have each session's manifest use only its own output set, (b) split `outputs:` into `test_outputs:` and `impl_outputs:` for seams-first stories, or (c) keep a single `outputs:` but specify that the seam session's manifest restricts writes to paths matching a test-file pattern (e.g., `tests/**/*`) and the implementation session's manifest restricts writes to the complement. Document the chosen approach in the Design section and update the story template.
