# The lcov records of one line are not in source order when two test processes load the file

**What is wrong:** The CRAP gate can pass a changed TypeScript function that no test calls when two test files load its file and the function shares its line with other functions. The story receives the wrong verdict. The loss starts in `deadFunctions`, which pairs the records of a line with its functions in source order. When several test processes load one file, node merges their coverage into one record. In the merged record, a function that only one process created comes after the other functions of its line. The pairing then gives the count of one function to its neighbour. The header assumes the source order, so the behavior is unintended.

```text
test a calls outer(0), so outer creates the map callback but never calls it
        ↓
test b, in another process, calls later and never creates the callback
        ↓
node merges both: FN:1,outer  FN:1,later  FN:1,anonymous_2 (the callback comes last)
        ↓
deadFunctions pairs in source order: outer=1, callback=1 (the count of later), later=0
        ↓
the callback gets 100 %, later gets 0 %, and crap-score passes the callback
```

The reproduction is `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/st0449-review/repro_typescript.sh`. Call it with the path of the command and the case `two-processes`. Four runs in a row gave `outer.(anonymous)` 100 % and `later` 0 %. The callback has complexity 6, so at 0 % it scores 42 and fails the threshold 30. With both calls in one test file, node keeps the source order and the rows are right.

**Why this severity:** The measure exists to give the gate the true coverage of each function. In this case it gives an uncalled function full coverage, so the gate can pass a story wrongly, which DEC-84 rules out. The command exists only on `story/ST-0449`, so it is not in use.

**Fix:** In `deadFunctions` of `scripts/crap-measure-typescript`, the smallest safe change is this: when a line holds more than one function and its records do not all have the same count, give 0 % to every function of that line. DEC-84 accepts that wrong failure. A function alone on its line keeps its record. A complete fix reads the V8 coverage files that `NODE_V8_COVERAGE` writes. They give each function its start offset and count, so the pairing needs no order. Add the case `two-processes` to the tests.
