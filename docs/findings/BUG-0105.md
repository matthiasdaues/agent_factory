# `run-step` sends the requirements agent to the vision interview in brownfield

**What is wrong:** The requirements agent takes the brownfield branch only on an explicit scope-map input. `run-step` dispatches through `trigger`, whose `compose_prompt` (`trigger:140`) passes no input. In a brownfield project with a confirmed scope map and no proposal, `run-step` finds the agent eligible and the agent starts the vision interview. Source: [brownfield onboarding run](../reviews/brownfield-onboarding-run-2026-10-16.md), review of ST-0315.

**Why this severity:** The lines of `compose_prompt` exist unchanged on `dev`, so `run-step` in an installed project uses them. `trigger` passes no input, so in a brownfield project with a confirmed scope map and no proposal the requirements agent skips its scope-map branch and starts the vision interview.

**Fix:** Let `trigger` pass the input that satisfied `any_of`, or let `run-step` name it.

## Possible damage

- A proposal or feature file written after a vision interview that `run-step` started in a project with a confirmed scope map and no proposal — check: in each brownfield project, run `git log --diff-filter=A --format='%h %ad %s' --date=short -- docs/proposals/ docs/spec/features/ docs/spec/scope-map.md` and confirm that no proposal followed the scope map from such a session.
- A `run-step` session of the requirements agent that took the vision branch — check: read the transcripts under `.agent-factory/usage/transcripts/` of each `run-step` session of the requirements agent in those projects and confirm that the agent started from the scope map.
