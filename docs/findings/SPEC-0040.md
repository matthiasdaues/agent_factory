# The manual-mode code review Scenario specifies behaviour of the draft proposal manual-mode-gates

**What is wrong:** The Scenario "A code review in manual mode files a finding on the story branch" has the human name the story branch of ST-1001 and the code-review agent commit `docs/findings/IMPL-1004.md` on that branch. That flow belongs to `docs/proposals/manual-mode-gates.md`, which has the status `draft`. The counter-ids proposal names it only in its Motivation. Its Scope and its `impact.boundaries` change the branching rules, `rules.md`, and `planning-agent.md`, but not `code-review-agent.md`. Today `code-review-agent.md` says nothing about manual mode or story branches. So the Scenario asks a story to change the code-review agent, which no counter-ids decision covers. The QA strategy follows it with the text test CID-08-LN-02 (SPEC-0041).

**Fix:** Replace the Scenario with one that checks what counter-ids promises: two indexed artifacts committed on two different branches get different IDs. For example, one session claims `IMPL` on a story branch while another claims `IMPL` on dev, and the two IDs differ. Leave the manual-mode code review to the specification of manual-mode-gates.

**Resolution (pass 2, 2026-11-05):** The Scenario "Two sessions on two branches get different IDs for the same ID prefix" replaces the code-review Scenario. It checks two `next-id IMPL` calls from `dev` and `feature/counter-ids`, and it names no change to `code-review-agent.md`.
