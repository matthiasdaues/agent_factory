# Native lifecycle drain e2e reads the pre-ADR-0009 verbatim filename; capture now writes the <cli>\_<session> composite name

**What is wrong:** `test_FAGAN0005_native_hook_removal_reaches_selected_terminal_state`
reads the drained record at `observed / f"{session}.jsonl"` where
`session = f"{cli}-removal-race"` — the verbatim `<session_id>.jsonl`. This
branch's ADR-0009 work changed `factory/scripts/usage-capture` so `session_path`
writes `usage_dir / f"{self._session_key(session_id)}.jsonl"` with the composite
key `<cli>_<session_id>` (usage-capture lines 121, 137–139, 189–190). The
drained record is therefore written as
`observed / "<cli>_<cli>-removal-race.jsonl"`, not the verbatim name the test
reads, so the `[claude-code-drain]` and `[copilot-drain]` params raise
`FileNotFoundError`. The `[codex-cancel]` param still passes because the cancel
branch asserts `not observed.exists()` and never reads a file. Verified: all
three params pass at the merge-base (`04256d9`); at HEAD the two drain params
fail with the missing verbatim file. This is a branch-introduced e2e
regression: the suite was green at the merge-base and is red at HEAD for these
two params. Like BUG-0009, a red suite blocks ST-0073's pre-push gate wherever
the suite is run.

**Fix:** Update the drain-branch read to the composite filename the capture now
writes — `observed / f"{cli}_{session}.jsonl"` — or compute it via the
capture's `session_path`/`_session_key` rather than a hard-coded verbatim name,
so the test tracks ADR-0009's naming. Re-run the two drain params to confirm
green.

- Test: `session = f"{cli}-removal-race"`; drain branch reads

  fail with `FileNotFoundError: …/<cli>-removal-race.jsonl`; `[codex-cancel]`
  passes.
