# The states that let a wave close contradict each other and leave out a returned story

**What is wrong:** [validation-rules.md § Dispatch ledger](../spec/validation-rules.md#dispatch-ledger-dispatch), line 171, says "`close-wave <N>` refuses if any story in wave N is non-terminal". Ledger Entry Lifecycle marks only **DONE** as terminal. The area spec Scenario "Stopped stories and handled drift rows allow wave closure" closes a wave that holds a `blocked` story, and the Wave Lifecycle description says the record is written "after every story of the wave has stopped". So `blocked` is non-terminal in one file and lets the wave close in another.

No statement covers a `pending` entry in a closed or closing wave. Take ST-0350 in wave 1 of a run by hand. It stops as `failed`, and the User returns it with `dispatch return-story` before `close-wave 1` runs. ST-0350 is now `pending` in wave 1. If `pending` counts as non-terminal, `close-wave 1` refuses for ever: `dispatch add` refuses a story ID, so no command moves ST-0350 out of wave 1. Then `prepare-story` refuses every later story, and `premerge-check dev` refuses the run because wave 1 has no wave record. The proposal says that a returned story stays `pending` until the end of the run and that the other stories continue.

**Why this severity:** No story or code encodes the run lifecycle spec yet, so it is not in use. Two statements of the spec contradict each other on `blocked`, and an implementer who reads "non-terminal" as "not **DONE**" builds a run that can never close a wave after a return (fails_purpose). A reader must compare the validation rules, the state machine and the area spec to find the gap (raises_cost).

**Fix:** Replace "non-terminal" in the close-wave rule with the list of states that let a wave close: `done`, `blocked`, `failed` that has stopped (see SPEC-0086), and `pending` after a return. Add a Scenario in which a wave with a returned story closes and the next story starts. Name the same list in the close-wave contract in `interface-contracts.md` and in the Wave Lifecycle description of the area spec.
