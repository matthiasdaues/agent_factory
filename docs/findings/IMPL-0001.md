# Two old files with one new path: the second move overwrites the first, and the script exits 0

**What is wrong:** A project can lose a file during the migration, and the script still reports success. The path table maps two old paths to one new path: `docs/spec/<name>-qa-strategy.md` and `docs/spec/supplementary_specs/<name>-qa-strategy.md` both go to `docs/spec/work/<name>-qa-strategy.md`. The check `refuse_reason` (line 1142) only tests whether a destination exists before the run. It does not test whether two planned moves share a destination. So both moves start. The second move of an untracked file uses `Path.rename` (line 1049), and on Linux and macOS a rename replaces an existing file without an error. The content of the first file is gone, git holds no copy of it, and the undo never runs. When the second file is tracked, `git mv` refuses, and the script undoes the run and exits 1. The interface contract (`Preconditions` row) requires exit 2 before the first change when a destination exists. The behaviour looks unintended: the contract's refusal rule already covers this case, and the script header says the script "never deletes a file outside git".

Failing case, with both files untracked:

```text
docs/spec/billing-qa-strategy.md                      contains "A"
docs/spec/supplementary_specs/billing-qa-strategy.md  contains "B"
$ migrate-spec-layout .     -> exit 0
docs/spec/work/billing-qa-strategy.md                 contains "B"
"A" exists nowhere
```

With the first file tracked and the second untracked, the run also exits 0. The uncommitted changes of the first file are lost, and `git status` shows `RM`.

**Fix:** Add the check in `refuse_reason` of `migrate-spec-layout`. When two planned moves share a new path, refuse with exit 2 before the first change and name both old paths. As a second guard, let `Run.move` raise `OSError` when the destination exists before a plain rename. Add a test for each git state: both files untracked, both files tracked, and one of each.

**Resolution:** Stakeholder decision (a), 2026-11-03: the second file moves to `docs/spec/work/<name>-area-qa-strategy.md`, the script lists the pair and exits 0, a move never replaces a file, and a taken or still shared destination refuses with exit 2 before the first change.
