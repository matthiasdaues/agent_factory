# The guard lets every Pi edit call through, because it does not read the edits list of Pi

**What is wrong:** A Pi agent that uses the `edit` tool can set `waived` or a human field in a finding file, and nothing refuses the call. The first point of loss is `check_edits` in `guard-human-fields`, which reads only `old_string`, `old_str`, and `oldString` from the top level of the arguments. The behavior is wrong, because BR-092 requires the guard on the edit calls of Pi.

```text
1. Pi 1.5.0 validates the edit call as {path, edits: [{oldText, newText}]}.
2. The extension sends those arguments to the guard unchanged.
3. check_call passes the whole argument object to check_edits as one edit.
4. check_edits finds no old or new text, so old and new are both empty.
5. The guard compares two empty strings and exits 0.
```

The schema is in `dist/core/tools/edit.js` of `@earendil-works/pi-coding-agent` 1.5.0, the release installed on this machine. It accepts a top-level `oldText` and `newText` as a legacy form and turns them into `edits`. The guard misses both forms. The Pi row of the payload table in `docs/spec/interface-contracts.md` says "Yes, the extension and the guard agree". That row checks the keys `toolName` and `input` only, and not the argument names inside `input`.

**Reproduction:** In a git repository that holds `docs/findings/BUG-1.md` with `status: open`, pipe this payload into the guard: `{"toolName":"edit","cwd":"<repo>","input":{"path":"docs/findings/BUG-1.md","edits":[{"oldText":"status: open","newText":"status: waived"}]}}`. The guard exits 0, and the expected exit is 2. The legacy form with a top-level `oldText` and `newText` also exits 0. The same change as a Claude Code `Edit` exits 2.

**Why this severity:** The lines exist only on the feature branch, so `in_use` is false. The guard exists to refuse this call and passes it on the ordinary edit tool of one of the five CLIs, so it gives a wrong result, which answers yes to `fails_purpose`.

**Fix:** In `check_call` of `guard-human-fields`, use the `edits` list of an `edit` call when it exists, and add `oldText` and `newText` to the keys that `check_edits` reads. Change the Pi fixtures of `tests/factory/test_guard_human_fields.py` to the schema of Pi 1.5.0, so the test fails first.
