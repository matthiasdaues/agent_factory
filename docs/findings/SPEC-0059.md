# CID-07 still makes finding-format.md the ID producer of nine prefixes, which counter-ids-fitting takes away

**What is wrong:** Rule CID-07 of `counter-ids.feature` holds the Scenario Outline row `packages/factory/rulebooks/conventions/finding-format.md` with the prefixes `SPEC, FAGAN, SEC, BUG, RECON, ATAM, IMPL, ARCH, QA`. The row requires that `finding-format.md` tells the reader to run `next-id` with each of these prefixes. The test `test_st_0372_producer_calls_next_id_with_its_prefixes` encodes this row and accepts the text `next-id <TAG>` for it. Counter-ids-fitting moves each prefix into its own review file. Rule CIF-14 and BR-107 forbid `next-id <TAG>`, and the glossary defines an ID Producer as a file that names the literal call `next-id <PREFIX>`. Rule CIF-16 and BR-108 leave `finding-format.md` only one row per tag with the review that files it. So `finding-format.md` is no ID producer any more, and the CID-07 row asks for the claim instruction that the new design removes. Gap CIF-G11 records the conflict and leaves the decision to this review.

**Why this severity:** The implementer of the CIF-16 story cannot satisfy CID-07 and CIF-16 at the same time without asking which Rule wins, because two Scenarios of the specification contradict each other (fails_purpose). The existing test then also has to change, and the QA strategy names no owner for that change (raises_cost).

**Fix:** Remove the `finding-format.md` row from the CID-07 Scenario Outline. The nine review files of CIF-14 now carry the prefixes. Alternatively, change the row so that `finding-format.md` points to `id-prefixes.md` and names no claim. Close CIF-G11 in the gaps report. Then the test-strategy agent adds a row to the Gap Findings of `counter-ids-fitting-qa-strategy.md` for the CID-07-LN-01 tests in `tests/factory/test_counter_ids_text.py` that change in the same story.

## Pass 2

Still open at commit 079034d92e7c338277c0dae154aae6b18e57f19e. Row 265 of CID-07 now names `packages/factory/rulebooks/conventions/id-prefixes.md` in place of `finding-format.md`. The row does not hold, for three reasons:

- The Outline says "Given the ID producer <file>". The glossary defines an ID Producer as a file that names `next-id <PREFIX>` at a step that creates an indexed artifact. `id-prefixes.md` creates no artifact, so it is no ID producer.
- The step "the rule tells the reader to run next-id with the ID prefix" asks `id-prefixes.md` for a claim rule that covers nine prefixes. BR-108 and the contract of `id-prefixes.md` give the file a table with three columns and no claim rule. A claim rule over a list of prefixes is what the proposal's Core Principles forbid: "No file asks an agent to choose a prefix from a list."
- `test_st_0372_producer_calls_next_id_with_its_prefixes` encodes the row. It then requires `id-prefixes.md` to hold the path of `next-id`, "standard output", and the stop-and-report rule, which the table of BR-108 does not hold.

So CID-07 and BR-108 still contradict each other, and the implementer of the `id-prefixes.md` story must ask which one wins. Gap CIF-G11 is also still open in `counter-ids-fitting-gaps.md`.

**Fix for pass 3:** Remove the row from the CID-07 Outline. The four other rows stay, and CIF-14 lists each review file with its own prefix, so no prefix loses its requirement. Close CIF-G11 with that decision. Then the test-strategy agent names the CID-07-LN-01 tests in `tests/factory/test_counter_ids_text.py` that drop the `finding-format.md` entry from `PRODUCERS`, in the same story as CIF-16.
