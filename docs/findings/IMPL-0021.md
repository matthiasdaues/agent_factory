# The guardrail lets the two destructive commands pass with an option or a leading shell word

**What is wrong:** An agent can still run `dispatch return-story` or `dispatch close --drop` in ordinary shell forms, so the User loses the protection that RL-16 promises. The first point of loss is `DISPATCH_AT` (line 28). It requires the subcommand to follow `dispatch` directly, and it accepts only `^`, `;`, `&`, `|`, `(`, a backtick, or `-c` before `dispatch`. So three groups of forms pass:

- A global option of `dispatch` before the subcommand: `dispatch --ledger <path> return-story ST-0350`. `dispatch` asks for exactly this form. When several ledgers exist and none fits the branch, its `LedgerChoiceError` ends with `pass --ledger <path>` (`packages/factory/scripts/dispatch:169`).
- A shell word that leads a command without being the command: `env`, `time`, `exec`, `command`, `nohup`, `{`, `then`, `do`, `!`, and an assignment such as `FOO=1 dispatch ...`. `guard-human-fields` already skips these words through its `WRAPPERS` set and an assignment pattern (`packages/factory/config/hooks/guard-human-fields:83`, `:370`).
- An interpreter or a quoted word: `uv run <path>/dispatch close --drop`, `python3 <path>/dispatch return-story ST-0350`, `dispatch close "--drop"`, and `dispatch "return-story" ST-0350`. The shell removes the quotes, so `dispatch` receives the same arguments as in the bare form.

The behavior looks unintended. The comment on lines 21 to 26 names a command position as the rule, and every listed form puts `dispatch` at a command position in shell grammar. The interface contract goes further and refuses "every form that names them in the command text"; only a command built from variables passes. RL-16-IT-07 tests the seven forms of the Outline and no other form, so the suite stays green.

```text
Several ledgers exist under .current-work/, and none fits the branch
        ↓
dispatch exits with LedgerChoiceError: "pass --ledger <path>"
        ↓
the agent runs dispatch --ledger <path> return-story ST-0350
        ↓
DISPATCH_AT needs "dispatch" followed directly by "return-story", so no pattern matches
        ↓
the script exits 0, and the story's work is destroyed without the User's decision
```

Reproduction at `8fd249b7`: each command below goes to the script as `{"tool_input":{"command":...}}`, run from `/tmp`. Every one exits `0`. The seven forms of the Outline exit `2`.

```text
dispatch --ledger .current-work/feature/x/dispatch-ledger.yaml return-story ST-0350
dispatch --ledger=.current-work/feature/x/dispatch-ledger.yaml close --drop
env dispatch return-story ST-0350
FOO=1 dispatch return-story ST-0350
{ dispatch return-story ST-0350; }
if true; then dispatch return-story ST-0350; fi
uv run .agent-factory/factory/scripts/dispatch close --drop
python3 .agent-factory/factory/scripts/dispatch return-story ST-0350
dispatch close "--drop"
dispatch "return-story" ST-0350
```

**Why this severity:** The script exists to refuse the two commands in every form that names them in the command text, and it lets an agent run them through the `--ledger` form that `dispatch` itself suggests (`fails_purpose`). The script is only on `story/ST-0427`. The installed copy at `.agent-factory/factory/config/hooks/block-dangerous-git.sh` has no `dispatch` rule, so the lines are not in use.

**Fix:** Change only the match in `block-dangerous-git.sh`. Between `dispatch` and the subcommand, allow any number of option words, such as `--ledger <path>` and `--ledger=<path>`. Before `dispatch`, accept the leading words of `guard-human-fields`'s `WRAPPERS`, `nohup`, `exec`, an assignment `NAME=value`, and the interpreters `python3`, `bash`, `sh`, and `uv run` with its options. Accept a quote around each word. A simpler match is also open: refuse `dispatch` followed by the subcommand anywhere in the text, and let a `grep` or a commit message that names them be refused too. That match follows the wording of the contract, and the decision on row 2 of `docs/spec/work/spec-feedback-ST-0427.md` settles which one stays. Then add the ten forms above to RL-16-IT-07 in `tests/factory/test_block_dangerous_git.py`.

**Resolution (fix iteration 2):** The fix on `story/ST-0427` keeps the match at a command position, so row 2 of `docs/spec/work/spec-feedback-ST-0427.md` stays open for the domain-modeling agent. Before `dispatch`, the match now skips the leading words of `guard-human-fields`: its `WRAPPERS`, `nohup`, `exec`, an assignment `NAME=value`, the interpreters `python3`, `bash`, `sh`, and `uv run`, and their options. Between `dispatch` and the subcommand it allows option words, such as `--ledger <path>` and `--ledger=<path>`. A quote may surround each word. The ten forms above exit `2`, and each is a case of RL-16-IT-07. A new test checks that a `grep`, an `rg`, an `echo`, and a commit message that name the two commands still pass. The rule no longer reads a `-c` after any command as `bash -c`, so `grep -c "dispatch close --drop"` now passes too. A command built from variables still passes (OI-11). Status stays `open` until the reviewer verifies the fix.
