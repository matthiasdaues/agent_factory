# The backfeed dispatches a reviewer that cannot be dispatched: the stakeholder

**What is wrong:** BR-067 says the orchestrator "dispatches the reviewer that the owner's declaration names in `reviewed_by:`". Four core entries name `stakeholder` as a reviewer: `docs/spec/scope-map.md`, `docs/spec/glossary.md`, `docs/agent-context.md`, and `docs/testing.yaml` ([interface-contracts.md, core list table](../spec/interface-contracts.md)). The stakeholder is not an agent, so nobody can dispatch the stakeholder. BR-061 says that the agent of the stakeholder session sets the status. CAO-14 carries that rule in its own Scenario, "The agent of a stakeholder session records the stakeholder's review". CAO-19 has no such Scenario. CAO-15 already sends an `agent-context.md` row to Virgil, so this case occurs in the reconciliation report. A story built from CAO-19 would write a playbook step that dispatches a reviewer named `stakeholder`. The glossary names two reviewers, and BR-067 does not say whether both act or in which order.

**Fix:** In BR-067, state that for a `stakeholder` reviewer the orchestrator presents the fix to the stakeholder and sets `confirmed` or `rejected` itself (BR-061). State the order for an entry with two reviewers. Add a CAO-19 Scenario with a `fixed` row on `docs/agent-context.md`, and extend the CAO-19-LN-01 row of the QA strategy to cover it.
