# The specification does not state how init-factory compares factory versions

**What is wrong:** ADR-0026 § Version test fixes the comparison. It follows Semantic Versioning 2.0.0 precedence, so `1.4.0` is older than `1.10.0` and `1.4.0-rc` is older than `1.4.0`. A value that is not a semantic version counts as older. The brief lists this last rule as a stakeholder decision. The `init-factory` Layout migration row names only three cases: a version older than the layout release, no `factory_version`, and `unknown`. A value such as `dev` falls into no case. `Scenario Outline: An install record without a usable version counts as older` has only the examples "no factory_version key" and "factory_version set to unknown". So CAL-07-CT-01 can pass while the implementation compares the versions as strings or treats `dev` as current.

**Fix:** Add the comparison rule and the non-semantic case to the Layout migration row. Add the example `factory_version set to dev` to the outline. Add a Scenario Outline that pairs an installed version with the layout release and expects a run or no run, with at least `1.10.0` against a `1.4.0` layout release and a prerelease of the layout release. CAL-07-CT-01 owns both.

**Resolution:** The `init-factory` Version comparison row states Semantic Versioning 2.0.0 precedence, and a Scenario Outline with the cases `1.10.0`, `1.4.0-rc`, `unknown`, and `dev` holds it, owned by CAL-07-CT-01.
