# `close-wave` cannot commit the ledger

**What is wrong:** `.current-work/` is ignored by git, so `git add` fails. The wave record is saved before the commit, so a second run exits 0 without committing. Run from the invocation worktree, the command crashes with a `ValueError`. Source: [bug-hunt report § D-5](../reviews/bug-hunt-2026-10-15.md#d-5--close-wave-cannot-commit-the-ledger).

**Fix:** Decide whether the ledger is committed. If it is, use `add -f` and save only after the commit. If it is not, change the contract.

**Resolution:** Fixed in commits `cd404785de67991123e8cf4d9306fb1c99599707`, and `062460af2a45c3e6f6acb84af54d1459f6e82859`, merged into `dev` as `36ef31f20b0af5f52a796800637e7dc9c4d88128`. The stakeholder decided that the ledger is uncommitted runtime state. `close-wave` saves it and commits nothing, and the dispatch contract says "saved" instead of "committed". A review found that the ledger saver wrote free text such as `|2` without quotes, so the ledger could not be read back; such text is now quoted. The full suite passed after the merge.
