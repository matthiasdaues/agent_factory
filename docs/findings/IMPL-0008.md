# The move pushes from the project repository, so its pre-push hooks run on every file

**What is wrong:** A project with pre-push hooks cannot move its counter to `origin`. A hook that runs longer than 30 seconds cuts off every move, and a failing hook refuses it. The User meets this at the session start, when VIRGIL runs `next-id --move-to-origin` (BR-106). `init-factory` installs the pre-commit framework with `--hook-type pre-push`, so every Factory project has such a hook.

The first point of loss is `push_to_origin` at `next-id:725`. It runs `git -C <local> push`, so git runs the pre-push hook of the project's own repository. A claim and a seed push from a throwaway repository made with `--template=`, so they run no hook (BR-075). The move is the only push of `next-id` that does not.

The pre-commit framework makes the hook as slow as it can be. C is a commit without a parent. For a pushed root commit, the framework runs every pre-push hook on all files of the project, not on the files of C. In this repository, the `run-tests` hook then runs the full suite of 3196 tests.

```text
push_to_origin runs `git -C <local> push`
        ↓
git runs <local>/.git/hooks/pre-push
        ↓
pre-commit sees a root commit and runs every hook on all files
        ↓
the hook runs past 30 seconds (GitTimedOut) or exits non-zero
        ↓
the move is cut off with the marker set, or refused with C restored
        ↓
every resume pushes again and meets the same hook
```

A scratch project reproduced both outcomes with the code at `bda10b05`. A pre-push hook that sleeps 35 seconds ends the move with "the push … ran over the time limit of 30 seconds; the local counter … holds the marker of the move". Every ID claim then fails by BR-097 until a move succeeds, and no move can succeed. A hook that exits `1` gives "the move to … failed: error: failed to push some refs", because the hook writes its reason to standard output and `next-id` drops it. The behavior looks unintended. BR-102, ADR-0033, and the stories do not mention hooks, and no test runs the move with a hook installed.

**Why this severity:** The move fails its job of carrying the counter to `origin` in every Factory project whose pre-push hooks take more than 30 seconds or report a failure on any file (`fails_purpose`). The refusal hides the hook's output, so the User must reproduce the push by hand to learn the cause (`raises_cost`). The code is only on `feature/counter-ids-fitting`, so it is not in use.

**Fix:** In `next-id`, push C as a claim does: open a throwaway repository with `throwaway(guarded=True)`, fetch the local `refs/ids/counters` into it with a guarded `git fetch`, and push C from there with the create-only lease. At that point the local ref holds the marker, and C arrives with it as the marker's parent. The throwaway repository has no hooks, and the push keeps the URL rewrites of `target`. Add an integration test to `tests/factory/test_next_id_move.py` that installs a failing pre-push hook in the project and finds that the move still exits `0`.
