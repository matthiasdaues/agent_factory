# The runtime lock pins urllib3 2.8.0 with the hashes of 2.7.0, so capture stops after an update

**What is wrong:** Commit `e1fe5fce` ("Remediate vulnerabilities", 2026-10-14) changed `urllib3==2.7.0` to `urllib3==2.8.0` in `usage-runtime-requirements.txt` and kept the two hashes of 2.7.0. The script lock `usage-capture.lock` still pinned 2.7.0. PyPI lists `urllib3-2.8.0-py3-none-any.whl` with `sha256:0cf3cae5…` and `urllib3-2.8.0.tar.gz` with `sha256:63bf2ead…`. The two hashes in the file belong to `urllib3-2.7.0.tar.gz` and `urllib3-2.7.0-py3-none-any.whl`.

`provision_usage_runtime` in `init-factory` first deletes the marker `.agent-factory/usage/runtime/.requirements-sha256`, then builds a new runtime with `uv pip sync --require-hashes`. The build stops on the hash mismatch, so the marker never comes back. `usage-capture-runtime` exits with code 70 without the marker, and the capture hooks swallow that exit. From the first `init-factory` or `update-factory` run on a release with this file, every hook of every CLI captures nothing.

```text
update-factory runs provision_usage_runtime
        ↓
the marker .requirements-sha256 is deleted
        ↓
uv pip sync stops: Hash mismatch for urllib3==2.8.0
        ↓
the old runtime stays, without its marker
        ↓
each Stop hook calls usage-capture-runtime, which exits 70
        ↓
no record is written, and nothing tells the user
```

In gigacron the last record is from 2026-11-11 19:00. The runtime folder changed on 2026-11-12 08:31, at the first update after the change. Claude Code and Copilot ran there every day until 2026-11-23, and no session of that time is captured. The update to 1.14.0 on 2026-11-23 failed the same way.

**Why this severity:** The file is in every release from `v1.3.0` (2026-10-27) to `v1.14.0`, and gigacron has it installed. After an update, the primary path fails: no capture writes a record, and there is no workaround short of building the runtime by hand. The transcripts of the sessions since then are only in the CLIs' own folders, and the usage records of those sessions are lost.

**Fix:** Upgrade `urllib3` to 2.8.0 in the script lock with `uv lock --script packages/factory/scripts/usage-capture --upgrade-package urllib3==2.8.0`, and export the lock to `usage-runtime-requirements.txt` again. Only the two `urllib3` hashes change. Add a test that the requirements file equals the `uv export` of the lock, so a hand edit fails at commit time. A rebuild in the scratchpad with the fixed file, run the way `init-factory` runs it, installs `urllib3==2.8.0` and counts tokens.

## Possible damage

- Every installation that ran `init-factory` or `update-factory` on `v1.3.0` or later has had capture switched off since that run — check: `ls .agent-factory/usage/runtime/.requirements-sha256` in the project; a missing file means capture is off.
- `housekeeping-about` reports capture as broken when the marker is missing (BUG-0070), so a project that ran it may already show the state — check: `.agent-factory/factory/scripts/housekeeping-about` in the project.
- The usage of the sessions since that run is missing from every usage report of those projects — check: the newest `recorded_at` in `.agent-factory/usage/*.jsonl` against the date of the last update in `.agent-factory/install.json`.
