# File-overlap computation algorithm unspecified

**What is wrong:** `dispatch plan` is required to "build the dependency graph, compute file-overlap sets, output a wave plan." The proposal does not specify how file-overlap is computed from story `outputs` fields. Story outputs use glob patterns (e.g., `src/**/*`, `docs/spec/use_cases/UC-*.md`). Naive glob-level intersection (checking whether two glob strings could match the same path) is computationally expensive and would over-serialize: two stories with `outputs: [src/**/*]` and `outputs: [src/foo/bar.py]` would always intersect, forcing serial execution even when bar.py is the only overlap. Conversely, two stories with specific-file outputs that happen to share a parent directory would be incorrectly parallelized if only exact-match comparison is used. The current implementation-agent performs this analysis with LLM judgment; moving it to a deterministic script requires a specified algorithm.

**Fix:** Specify the overlap-detection algorithm. Recommended approach: expand globs against the working tree to concrete file sets (or use a pattern algebra that can determine non-overlap without expansion), then compute set intersection. Document edge cases: what happens when a glob matches zero files (new directory), when two globs are nested (`src/**/*` vs `src/foo/*`), and whether the algorithm is conservative (over-serializes on ambiguity) or optimistic (parallelizes on ambiguity).
