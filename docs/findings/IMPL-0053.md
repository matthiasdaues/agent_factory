# --orphans removes a live run whose run folder is its feature worktree

**What is wrong:** `dispatch close --orphans` stashes and removes the feature worktree of a live run when that worktree is the run folder and holds the ledger at its root. The ledger goes into the stash with the worktree's other untracked files, so the live run loses its checkout and its ledger. The loss starts in `_find_ledgers` (`dispatch:3006-3049`). The fix of IMPL-0046 skips every registered worktree below `.current-work/` and walks only that worktree's own `.current-work/`. In this layout the ledger lies at `.current-work/feature/x/dispatch-ledger.yaml`, which is the root of the worktree `.current-work/feature/x`, not inside its `.current-work/`. So the walk never finds the ledger, the run has no claim, and a feature branch at the tip of `dev` counts as merged. The commit before the fix kept this run, so the behavior is a regression.

```text
init without --feature-branch puts the worktree at .current-work/<branch>
        ↓
the same init writes the ledger into that folder, at the worktree root
        ↓
_find_ledgers skips the worktree folder and walks only its .current-work/
        ↓
no claim covers the worktree, and its branch is merged into dev
        ↓
--orphans stashes the ledger and removes the worktree of the live run
```

The layout comes from dispatch and exists in this repository. `cmd_init` without `--feature-branch` creates the worktree at `.current-work/<branch>` and writes the ledger to the same folder. The worktree `.current-work/feature/counter-ids` holds the untracked file `dispatch-ledger.yaml`, and `feature/counter-ids` exists and is merged into `dev`. So the one-time run of RL-15-IT-05 would remove it.

The review checked this in scratch repositories. A worktree on `feature/x` sat at `.current-work/feature/x` with a ledger at its root and a `dispatched` story. Against `dbd46b69`, `--orphans` printed `stash: orphan feature/x 2026-11-19` and `removed worktree: .../.current-work/feature/x (feature/x)`, and it removed a nested story worktree too. The ledger was gone from disk. Against `dfe4a836`, the same repository kept both worktrees and the ledger.

**Why this severity:** The lines exist only on the story branch, so `in_use` is false. `--orphans` removes the worktree and the ledger of a run whose feature branch exists, and its job is to remove only what no active run owns (yes to fails_purpose).

**Fix:** In `_find_ledgers`, when the walk skips a registered worktree, still read `dispatch-ledger.yaml` at the root of that worktree, with its folder relative to the `.current-work/` it lies in. `_removal_refusal` already keeps a ledger that git tracks, so the case of IMPL-0046 stays covered. Add a test to `tests/factory/test_run_lifecycle_close.py` with this layout. The test checks that the worktree and the ledger stay and that no stash exists.
