# The guard handles a patch call only in Codex, and the OpenCode tool list is not named

**What is wrong:** ADR-0035 found that a Codex `apply_patch` call names its paths inside the patch text, so a path check on the call alone misses them. The architecture closes that gap for Codex only. The guard reads the patch and refuses a patch it cannot parse when the raw text names a guarded path. The same tool appears in two more CLIs. Copilot CLI guards `apply_patch` with the CLI-specific behavior "None", and Pi guards `apply_patch` with only the missing-script rule (contract table of `guard-human-fields`, 5.12, ADR-0035). So the rule for an unparseable patch does not hold there.

OpenCode is open in the same way. Its row says "the plugin's edit, write, and shell tools" and names no tool. The OpenCode source, as this reviewer knows it, also has a patch tool and a multi-edit tool. This review did not check the current OpenCode release, so that claim is unchecked. DEC-51 asks the architecture to name each gap where a CLI lacks a hook for a call, and how the guard closes it. Without a tool list, a test writer cannot derive the OpenCode cases of the QS-25 measure "every guarded call type of every CLI is refused".

Take an agent in Copilot CLI that a `critical` BUG-0037 stops. It sends an `apply_patch` call that adds `stop_confirmed_by: human` to `docs/findings/BUG-0037.md`, in a patch form the guard cannot parse. In Codex the guard refuses the call. In Copilot CLI the contract lets it through, the stop ends, and nobody ran the damage checks.

**Why this severity:** QS-25 has priority 1, so its importance is `high`. The exposure is `uncertain`: whether Copilot CLI and Pi pass the patch text in a form the guard can parse, and which edit tools OpenCode has, are assumptions nobody has checked. High importance and uncertain exposure give `major`. No code is built from ADR-0035 yet, so `in_use` is false.

**Fix:** Make the patch rule part of the shared guard rule, not a Codex-specific behavior. Every entry point that guards a patch-shaped call reads the paths and lines from the patch text and refuses a patch it cannot parse when the raw text names a guarded path. Name the OpenCode tools that the plugin guards in ADR-0035, 5.12, the DSL component `guard entry: OpenCode plugin`, and the guard contract, and check the names against the OpenCode release that the OpenCode CLI feature targets. Then state in QS-25 that the measure covers the patch tool of each CLI.
