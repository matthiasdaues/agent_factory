# An empty story passes verify-story, and a red suite then resets earlier merges away

**What is wrong:** `verify-story` accepts a commit equal to the story's base.
`merge-story` treats any story branch that is an ancestor of `HEAD` as
already merged, skips `premerge-check`, and takes `HEAD^1` as the state
before the merge. When the post-merge tests fail, it resets the branch hard
to that guess. That removes the previous story's merge and any uncommitted
edits in the checkout. Source:
[bug-hunt report § D-2](../reviews/bug-hunt-2026-10-15.md#d-2--an-empty-story-passes-and-a-red-suite-wipes-earlier-merges).

**Fix:** In `verify-story`, reject a commit that is not ahead of the story's
base. In `merge-story`, treat a story as already merged only when `HEAD` is a
merge commit whose second parent is the story's tip, and refuse a story
branch with no commits of its own. Add tests for both.
