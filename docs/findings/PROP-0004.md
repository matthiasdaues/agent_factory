# update-charter during requirements/architecture has no delivery vehicle

**Resolution (verified 2026-08-18, repeat pass v2):** Scope now includes
"requirements-agent.md updated: `update-charter` added to `skills:`" and
"architecture-agent.md updated: `update-charter` added to `skills:`"; both
agent files are also listed in `impact.boundaries`.

**What is wrong:** The "Incremental filling" design says requirements work and
the architecture-agent invoke `update-charter` as decisions emerge, and the
greenfield insertion table repeats "During requirements, architecture — agents
invoke `update-charter`." But the Scope's agent updates cover only
`planning-agent.md`, `developer-agent.md`, and `implementation-agent.md`.
Neither `requirements-agent.md` nor `architecture-agent.md` is updated — no
agent file, skill list, or playbook step in those phases will ever mention
`update-charter`, so the incremental-filling arc (the proposal's core
principle: "scaffolded early and filled incrementally across phases") cannot
happen before the planning gate. The charter would arrive at the completeness
sweep filled only at vision time, exactly the gap the design sets out to close.

**Original fix direction (applied):** Add to the in-scope list: update `requirements-agent.md` and
`architecture-agent.md` (skills list and/or workflow step) to invoke
`update-charter` when they settle charter-relevant decisions — or state
explicitly that incremental filling during requirements/architecture is
deferred and the completeness sweep carries the whole load, adjusting Core
Principles accordingly.
