# Post-merge test failure leaves invocation branch polluted with no rollback

**What is wrong:** `dispatch merge-story` merges the feature branch into the invocation branch, then runs the test suite. On a red suite it marks the story `blocked` with "post-merge test failure" and exits non-zero. However, the merge commit is already on the invocation branch. The proposal does not specify rollback (e.g., `git reset --hard` to pre-merge HEAD or `git revert`). A subsequent `merge-story` for the next story in the wave would merge on top of a broken invocation branch, compounding the failure. The invocation branch is left in an indeterminate state: it has a committed merge that breaks tests, but the story is marked `blocked`, not `done`.

**Fix:** Specify the rollback mechanism. Either (a) `merge-story` reverts the merge commit on red suite before marking blocked, restoring the invocation branch to its pre-merge state, or (b) explicitly state that a post-merge test failure blocks the entire dispatch (no further merges until resolved), and document how you recover (manual revert, re-cut of invocation branch, etc.).
