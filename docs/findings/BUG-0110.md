# `update-factory` never refreshes a project's factory hooks

**What is wrong:** `merge-precommit-config --update` says it is "used by update-factory to refresh hook entries", but `update-factory` never calls it, and `init-factory` leaves an existing `.pre-commit-config.yaml` alone (`init-factory:2981`). A project installed from an older template keeps its old hook entries through every update. Seen in another project on 2026-10-16: its hooks still called `factory/` and passed every commit unchecked.

**Fix:** Let `update-factory` run `merge-precommit-config --update` against the project's config and report the change. Related: follow-up 21 in the bug-hunt handoff.

**Resolution:** Fixed in commit `dd2fe296` on `feature/factory-hook-fixes`; the full suite passed. `update-factory` now compares the project's factory block with the new template after `init-factory`, shows the diff, and writes only on an explicit yes. `merge-precommit-config --update` replaces the block in place.
