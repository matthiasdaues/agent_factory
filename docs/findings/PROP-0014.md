# Stage 1 does not specify reverse-map as its scope-map population mechanism

**What is wrong:** Design Section 3 lists "scope-map.md populated with existing
Rules, all marked implemented" as a Stage 1 output, but does not state how the
scope map gets populated. Design Section 4 introduces the reverse-map skill,
which performs exactly this function. The connection is implicit. A planning
agent reading Section 3 cannot determine that Stage 1 depends on the
reverse-map skill without re-deriving the design from Section 4.

**Fix:** Add an explicit reference in Design Section 3's Stage 1 bullet list:
"scope-map.md populated via the reverse-map skill (see Section 4) with existing
Rules, all marked implemented."
