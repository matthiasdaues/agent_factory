# The TypeScript measure reports a function that never ran as covered

**What is wrong:** The CRAP gate can pass a changed TypeScript function that no test calls. The story receives the wrong verdict, and the risky function reaches `dev` unjudged. The loss starts in `coveragePct` of `scripts/crap-measure-typescript`. It counts the lcov lines of a function, but node marks a line as run when the code around the function runs on that line. A function on one line then shares its line with the module code, which always runs. The last line of a callback such as `});` shares it with the enclosing call. The behavior looks unintended: the header says that the command never reports a file that coverage cannot reach as covered, and DEC-84 says that the gate never passes a story wrongly.

```text
node --experimental-test-coverage marks a line as run when any code on it ran
        ↓
the lcov report gives DA:<line>,1 for the line of a never-called one-line function
        ↓
coveragePct counts that line as the body of the function, and finds it run
        ↓
the row says coverage_pct 100 instead of 0
        ↓
crap-score scores the function at its complexity and passes it
```

The reproduction is `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/st0449-review/repro_typescript.sh`. Call it with the path of the command and the case `one-line`. It plants `src/pick.ts`, whose test calls only `used`:

```text
pick            complexity 7, coverage_pct 100   (no test calls it)
(anonymous)@10  complexity 2, coverage_pct 33.33 (the callback never runs)
```

At 0 %, `pick` scores 7 × 7 + 7 = 56 and fails the threshold 30. At the reported 100 %, it scores 7 and passes. The lcov report of the same run holds `FNDA:0,pick` and `FNDA:0,anonymous_4`, so node already knows that both functions never ran.

**Why this severity:** The measure exists to give the gate the true coverage of each function, and for these functions it gives a coverage that is too high. So the gate can pass a story wrongly, which DEC-84 rules out. The command exists only on `story/ST-0449`, so it is not in use.

**Fix:** In `runTests` of `scripts/crap-measure-typescript`, also read the `FN:<line>,<name>` and `FNDA:<count>,<name>` records, merged over the records of one file as the `DA` lines are. In `measure`, report `coverage_pct` 0 for a function whose start line has only functions with a count of 0. When two functions start on one line and only some ran, keep the line count, because lcov cannot tell them apart; name that limit in the header. Add a case to CG-13-IT-02 with a one-line function that no test calls, and assert `coverage_pct` 0.
