# Freshness checks and the Pi extension read an install record that does not exist

**What is wrong:** The Claude freshness hook and the Pi freshness extension
read `.agent-factory/factory-install.json`. The installer writes
`.agent-factory/install.json`, so both exit early and never warn that the
installed factory is older than `packages/factory/`. The Pi usage extension
checks the same old name before it trusts an inherited project root, so a Pi
subagent started in a subdirectory skips usage capture. Source:
[bug-hunt report § X-4](../reviews/bug-hunt-2026-10-15.md#x-4--the-freshness-hook-reads-a-manifest-that-does-not-exist)
and the section "Found while fixing" in the same report.

**Fix:** Read `.agent-factory/install.json` in
`check-factory-freshness.sh`, `check-factory-freshness.ts`, and
`pi-usage.ts`. Add a test that runs the freshness hook against a stale
install record and expects the warning.

**Resolution:** Fixed in commits `ffde2b1f554ca8d76a2b5a5a68a9c11edde060ea`
and `3238ba3a92817edfa7296a6ae73b1a2343812af2`, merged into `dev` as
`fdd038734d94f3b6e82588607dbb3b2aebecc942`. A review found that the
guardrail's deny messages, which fire inside linked worktrees, named an
installed copy that a worktree does not have; they now name the main
checkout's copy. The branch changed 36 files, so `premerge-check` ran with
`--max-files 40`; the size comes from one mechanical path replacement. The
full suite passed after the merge.
