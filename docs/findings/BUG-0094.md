# `derive-feature` cannot run in brownfield

**What is wrong:** The skill takes a proposal path as its argument and reads `impact.boundaries` from the proposal's frontmatter (`SKILL.md` lines 21 to 25). A brownfield project has no proposal; the code is the specification. The onboarding run reached the skill only by working around its documented entry point.

**Fix:** Add a brownfield entry that takes the scope map as input.

**Resolution:** Fixed in commits `b18a65d5080b2a8ba4734d7ddb3fa8abb019f7fd`, `4630b2e0ccd758452ddb97d0bb024091b5a5806b`, merged into `dev` as `55ece0a7d9984e7e4f77e5fc69723d0083a73e66`. The full suite passed after the merge. The requirements agent takes the brownfield branch only on an explicit scope-map input, and `derive-feature` stops on a draft map. Known gaps: `run-step` passes no input, so in a brownfield project without a proposal it sends the agent to the vision interview; the agent stands at 19,995 of index-lint's 20,000-token warning.
