# Scenarios of core-artifact-ownership.feature contradict the run lifecycle

**What is wrong:** Four Scenarios of `docs/spec/features/core-artifact-ownership.feature` state behaviour that the accepted proposal replaces, and the run lifecycle spec neither changes them nor lists them:

- Line 537, the Outline "The test guardrails come from the story first, then from testing.yaml, then from the default". Its first row gives a story with `quality-gates: [crap-score]` and a `testing.yaml` that enables `crap-score` and mutation testing, and expects only `crap-score` and `dependency-check`. RL-09 and BR-066 say that `quality-gates` only adds gates, so the mutation command runs as well.
- Line 551, "The developer agent runs the gates in manual mode". RL-02 says "The developer agent runs no gate script", and the implementation agent runs the gate-check step on both ways.
- Line 557, "The developer agent resolves each surviving mutant before the merge", inside the coding loop. The proposal gives the gate-check step to the implementation agent, which files a `QA` finding for a mutant it cannot resolve.
- Line 704, "In manual mode the human closes a story only after its rows are handled". By hand, `dispatch close-wave` checks the rows after each story (BR-064, RL-11), and the human closes no story.

The text tests `test_st_0365_*` and `test_st_0362_manual_mode_*` in `tests/factory/test_core_artifact_ownership_text.py` encode the second and the fourth Scenario. The Test Retention Policy of the QA strategy does not list them among the tests that this feature makes wrong.

**Why this severity:** These Scenarios describe the behaviour that is correct on `dev` until this feature ships, so no wrong result exists yet, and the run lifecycle spec itself is not in use. Two feature files of the spec contradict each other, and the planner of the developer-agent story cannot tell whether to keep the gate run by hand that ST-0365 tests (fails_purpose). A reader finds the conflict only by reading a second feature file (raises_cost).

**Fix:** Update the four Scenarios of core-artifact-ownership.feature to the run lifecycle, or replace each with a pointer to the RL Rule that now holds the behaviour. List the change in the gaps report under the documents that change, so planning cuts it into a story. Then the test-strategy agent adds `test_st_0365_*` and `test_st_0362_manual_mode_*` to the Test Retention Policy of the run lifecycle QA strategy.

**Fix applied (2026-11-18, requirements agent):** In `core-artifact-ownership.feature`, the first two rows of the test guardrails Outline also run the mutation command. A comment that points to the run lifecycle Scenario "The developer agent runs no gate script" replaces "The developer agent runs the gates in manual mode". "The implementation agent resolves each surviving mutant in the gate-check step" replaces the Scenario of the developer agent, and the QA finding Scenario of the next Rule names the gate-check step. "In a run by hand, the wave of a story closes only after its rows are handled" replaces the Outline of the human's close. "A function above the CRAP threshold blocks the merge" names the gate-check step in place of the automated mode. The gaps report lists the change under Other Feature Files That Change. The Rule name "Test-strategy agent resolves the surviving mutants that a developer agent cannot resolve" stays, because the scope map and the core-artifact-ownership QA strategy cite it. The Test Retention Policy waits for the test-strategy agent. The status stays `open` until the repeat pass of the spec review checks the fix.
