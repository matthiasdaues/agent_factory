# BR-124 keeps a merge that git refuses in an orchestrated run `dispatched`, while BR-116 sets it `blocked`

**What is wrong:** Since `0e53d6aa` and `81f710e8`, BR-116 says that in an orchestrated run a unit of work stops as `blocked` when git refuses its merge, and `merge-story` records the reason `merge conflict`. The `On Block` comment of the Ledger Entry Lifecycle, the run-lifecycle Outline "A story stops in the state that names its cause", the area Scenario "A merge that git refuses aborts and marks blocked", and `cmd_merge_story` in `packages/factory/scripts/dispatch` agree. BR-124 still says, for both ways, that `merge-story` merges nothing "when git refuses the checkout or the merge", and that in each case the entry stays `dispatched`. The note "A refused merge is no edge" in `docs/spec/state-machines.md:1235` says the same without a restriction to a run by hand, so the state machine contradicts its own `On Block` comment at line 1172.

Take ST-0350 in an orchestrated run on `feature/login`. The worktree of `feature/login` holds an untracked file that the merge of `story/ST-0350` would overwrite. BR-116 and the code set ST-0350 `blocked` with reason `merge conflict`. BR-124 and the state-machine note keep it `dispatched`. The same split appears with `dispatch.refuse_dirty_feature_worktree: false` and an uncommitted change to a file that the merge changes.

**Why this severity:** No story or code outside the run encodes the statement, because ST-0419 built the `blocked` path on `feature/run-lifecycle` (in_use: false). Two rules of the reviewed specification contradict each other, so the implementer of ST-0416, which builds the orchestrated refusals of BR-124, cannot tell which state to set without asking (fails_purpose). Every reader must also compare BR-116 with BR-124 to find the scope of each (raises_cost).

**Fix:** Restrict the refused merge of BR-124 to a run by hand. In an orchestrated run, BR-124 keeps only the refusals before the merge, that is, `premerge-check` and the uncommitted change in the worktree of the feature branch. It then points to BR-116 for a merge that git refuses. Change the note "A refused merge is no edge" in `docs/spec/state-machines.md` in the same way. The architecture agent then checks the first sentence of `docs/arc42/06_runtime_view.md` § 6.24.1, "A refused merge changes no state (BR-124)".
