# The story scopes do not admit a review report with the new name

**What is wrong:** A code review that follows the new rule writes a report that `premerge-check` counts as out of scope, so the merge of the story stops with `BLOCK out-of-scope-paths`. The implementation agent receives this refusal first, at the merge of ST-0412 itself. The first point of loss is step 5 of `code-review-agent.md`. It moves the story ID to the front of the name, as `code-review-ST-0412-2026-11-18.md`, but the `touches` field of the story still admits `docs/reviews/code-review-*-ST-0412.md`, the old name with the ID at the end. The `touches` line came from `dev` and matched the old rule, so this commit opens the gap. Every other story of the run, ST-0408 to ST-0430, carries the same old pattern. The behavior looks wrong, not intended.

The new test RL-04-IT-01 does not catch the gap. Its fixture stories admit `docs/reviews/code-review-{id}-*.md`, which matches the new name, so the test checks a scope that no real story of the run declares.

```text
code-review-agent.md step 5 names the report code-review-ST-0412-2026-11-18.md
        ↓
backlog/ST-0412.md touches admits only code-review-*-ST-0412.md
        ↓
dispatch merge-story passes the touches as --scope-glob
        ↓
premerge-check check_out_of_scope finds the report outside every pattern
        ↓
merge-story refuses ST-0412 and every later story whose review follows the rule
```

The review checked the pattern with `glob_match` of `dispatch_lib.py`, the matcher that `premerge-check` uses: `code-review-ST-0412-2026-11-18.md` does not match, and `code-review-2026-11-18-ST-0412.md` matches. `premerge-check` on this branch has no rule that admits a report by the ID in its name; the contract assigns that rule to a later story.

**Why this severity:** The story requires that the developer agent commits the review report on the story branch and that the story then merges (Scenario "Two stories reviewed on the same day merge without a conflict on their reports"), and the declared scope refuses that report (`fails_purpose`). The new naming rule exists only on `feature/run-lifecycle`, so `in_use` is false. Only the stories of this run read the `touches` patterns.

**Fix:** In the `touches` field of each story of the run that is not merged yet, replace `docs/reviews/code-review-*-ST-NNNN.md` with `docs/reviews/code-review-ST-NNNN-*.md`, as commit `dbfc5e3a` did for the finding files. Change the fixture in `tests/factory/test_run_lifecycle_premerge.py` only if the stories take a different pattern.

**Verification (pass 2):** Commit `0c544756` on `feature/run-lifecycle` adds `docs/reviews/code-review-ST-NNNN*.md` to the `touches` of ST-0408 to ST-0430, and the refresh merge `a04faeeb` brings it into `story/ST-0412`. `glob_match` of `dispatch_lib.py` matches `docs/reviews/code-review-ST-0412-2026-11-18.md` and `docs/reviews/code-review-ST-0412-2026-11-18-2.md` against `docs/reviews/code-review-ST-0412*.md`. `dispatch merge-story ST-0412 --dry-run` exits `0` and prints `PASS out-of-scope-paths: all 15 file(s) under declared scope`, with the review report of this story among the 15 files.
