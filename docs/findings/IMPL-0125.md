# A dangling Markdown symlink in a nested folder stops handbook lint

**What is wrong:** A contributor gets a traceback and loses all handbook diagnostics when a nested Markdown symlink has a missing target. The new nested traversal calls the shared page reader. The reader checks where the symlink points, then lets a missing target raise `FileNotFoundError`. This breaks the requirement to report every failure in both handbooks.

In scratch, `docs/handbook/testing/nested/draft.md` pointed to a missing sibling `missing.md`. The user handbook also contained a page with no frontmatter. On `b3636e99`, lint reported the invalid page and the nested folder. On `6463561e`, lint printed only a traceback on stderr.

**Why this severity:** BR-147 requires a diagnostic for each failure in both handbooks. A failed page read stops the whole check. The nested traversal was introduced on the story branch.

**Fix:** Return a path-specific read failure from `_read_page` when a Markdown path cannot be opened. Add a lint test that checks for the read failure and an independent frontmatter failure in the same run.
