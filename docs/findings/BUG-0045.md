# Rules, hooks, and templates name the old factory/ layout

**What is wrong:** About fifty lines in shipped rulebooks, templates, skills,
and hook messages tell agents to run `factory/scripts/<name>` or read
`factory/rulebooks/...`. That layout no longer exists. Installed projects
have the factory under `.agent-factory/factory/`, and the source repository
has it under `packages/factory/`. Followed literally, binding rules such as
"run `factory/scripts/verify-base`" and the guardrail's deny messages name
commands that are not found. `rules.md:23` also detects the source
repository by checking for `factory/`. Source:
[bug-hunt report § X-2](../reviews/bug-hunt-2026-10-15.md#x-2--51-instruction-lines-name-the-old-factory-layout).

**Fix:** Replace the old paths with `.agent-factory/factory/...` in shipped
text. Detect the source repository by `packages/factory/` in `rules.md:23`.
Leave historical reports unchanged. Add a test that no shipped text names
the old layout.

**Resolution:** Fixed in commits `ffde2b1f554ca8d76a2b5a5a68a9c11edde060ea`
and `3238ba3a92817edfa7296a6ae73b1a2343812af2`, merged into `dev` as
`fdd038734d94f3b6e82588607dbb3b2aebecc942`. A review found that the
guardrail's deny messages, which fire inside linked worktrees, named an
installed copy that a worktree does not have; they now name the main
checkout's copy. The branch changed 36 files, so `premerge-check` ran with
`--max-files 40`; the size comes from one mechanical path replacement. The
full suite passed after the merge.
