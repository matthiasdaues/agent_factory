# `next-id` and `init-factory` print the password or token of a remote URL

**What is wrong:** A user whose remote URL carries a credential, such as
`https://ci-token:<token>@host/group/project.git`, sees that token in every
error message of `next-id` and in the warning of `init-factory`. An agent then
copies the message into its transcript, a handoff, or a finding, and a CI job
writes it into its log. git itself removes the credential from its own
messages. The loss starts in the message layer of `next-id`: every message
names the remote with the raw URL from `--remote` or from
`git remote get-url origin`. The behavior looks unintended, because the
contract asks the message to name the remote, not its credential. CWE-532
names this weakness.

Reproduction, with a closed local port:

```text
$ git remote add origin "https://ci-token:glpat-EXAMPLE123@127.0.0.1:41981/group/project.git"
$ next-id ST
next-id: cannot read refs/ids/counters on https://ci-token:glpat-EXAMPLE123@127.0.0.1:41981/group/project.git: fatal: unable to access 'https://127.0.0.1:41981/group/project.git/': Failed to connect to 127.0.0.1 port 41981 after 0 ms: Connection refused
```

`next-id --seed 1000` prints the same URL. The affected lines are
`next-id:297`, `:319`, `:323`, `:344`, `:382`, `:399`, and `:401`, and
`init-factory:3079`.

**Why this severity:** A read of credentials starts the bug bar at Critical
(`secrets`). The attacker must first read the place where the message lands,
such as a CI log or an agent transcript, so `second_breach` lowers it to High.
A credential inside the remote URL is the user's own setup and not the
factory's default, so `non_default` lowers it to Medium. Medium maps to
`major`. The path from the URL to standard error is reproduced, so the
confidence is `proven`. Nothing on `dev` runs the code yet, so `in_use` is
false.

**Fix:** Add one function to `next-id` that removes the user and password part
from a URL with a scheme, the way git does, and use it wherever a message names
the remote. Keep the raw URL for the git calls. In `init-factory`, apply the
same step to `url` in `check_counter` before the warning. Add one test that
runs a claim and a seed on `http://user:secret@127.0.0.1:<closed port>/r.git`
and checks that standard error holds the host but not `secret`.
