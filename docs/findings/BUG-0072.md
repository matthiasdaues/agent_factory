# `crap-score` shows covered code as 0 % covered

**What is wrong:** Coverage keys are relative to the project root, but the lookup uses paths relative to `--source-root`. With `--source-root src`, a fully covered function shows 0 % and fails. One file with a syntax error crashes the gate. Source: [bug-hunt report § U-9](../reviews/bug-hunt-2026-10-15.md#u-9--crap-score-shows-covered-code-as-0--covered).

**Fix:** Compare absolute paths, and handle parse errors per file.

**Resolution:** Fixed in commits `7e0e56dca317a519b73a94c2ed7f1799feb1734c`, `51b05de558293461f1caa1ab08159d90b00dfbc4`, `fd038e96602ccbeb9b912b882ecea9827c706e3e`, `db8d0c5c65de08fdd89251af6f8c50b7234040d8`, `38bfa27365083821311afc4c23119e2fc64ca4d3`, merged into `dev` as `3921e522cc31f7fd454d9c908c9e8e42ceb201fe`. The full suite passed after the merge. Known gap: when a coverage key names a file that exists under no base, the old per-key order runs, and a same-named file can take the wrong coverage.
