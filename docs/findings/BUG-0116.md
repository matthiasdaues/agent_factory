# The BUG-0115 fix makes `dispatch init` fail when several ledgers exist

**What is wrong:** An operator who starts a new dispatch with `dispatch init`
gets "several dispatch ledgers exist and none fits branch dev" and no run
starts. This repository holds four ledgers, so every new `init` on `dev` hits
it. The fix moved the default ledger from parser setup into `main`, and `main`
resolved it for every subcommand. `init` reads no existing ledger and creates
its own, so it never needed one. The behavior is wrong, not intended. The
earlier code returned a path that `init` ignored.

Reproduction: place two ledgers under `.current-work/a/` and `.current-work/b/`,
stay on a branch with no ledger of its own, and run
`dispatch init --base <sha> --stories ST-0001,ST-0002 --feature-branch feat/x --yes`
without `--ledger`. It exits `1`. The existing tests pass `--ledger` to `init`,
so none caught it.

**Why this severity:** `harms_downstream` is yes: a published CLI command fails
on a reachable path, and the script is in use.

**Fix:** Resolve the default ledger in `main` for every subcommand except
`init`. The commit `ff6245eb23fcbade7c413410370423c6c41b49b6` does this and adds
`test_bug_0115_init_needs_no_default_ledger_among_several`.
