# DuckDB UI behavior has no QA contract owner

**What is wrong:** The feature gives the local analyst a Rule requiring the documented DuckDB UI path to expose all six views and requires missing UI assets not to affect deterministic analysis. The reviewed QA contract-owner table assigns LU-01 through LU-11 but contains no UI contract, test ID, location, or command. Mentioning missing UI assets in the boundary-case table does not establish the single executable owner the feature itself requires.

**Fix:** Add a distinct contract owner and executable test for the observable UI bootstrap boundary and published-view exposure. If UI launch itself is intentionally outside automation, narrow the feature to a precise documentation contract and assign an executable documentation or smoke-check owner without duplicating accounting assertions.

**Resolution (verified 2026-09-13 against `47dc7920fdd31eca12f9f3bd54ec0435d3c26598`):** The feature narrows automation to documentation and bootstrap resolution without starting or fetching the UI. QA contract LU-12 assigns the standalone `usage-ui-doc-check` as sole owner for parsing the documented command and verifying that its bootstrap registers exactly the six published views.
