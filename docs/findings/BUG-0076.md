# A stale pending entry blocks `remove-factory` for good

**What is wrong:** A leftover `.committing.json` entry makes both `drain` and `cancel` time out. A leftover `remove-owner` file with a dead process always reports "usage removal already in progress". A crash can leave the state in `drain` or `cancel`, and `init-factory` never resets it. Source: [bug-hunt report § U-4](../reviews/bug-hunt-2026-10-15.md#u-4--a-stale-pending-entry-blocks-remove-factory-for-good).

**Fix:** Expire old `.committing.json` entries, treat an owner file with a dead process as stale, and have `init-factory` restore `active`.
