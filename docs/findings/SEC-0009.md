# A replace ref makes `crap-score` read forged gate settings from `dev`

**What is wrong:** A story agent can raise the threshold of `dev`, or add a row to its exceptions register, without moving `dev`, and the next `crap-score --base <feature-branch>` judges the story by the forged values (CWE-345). The agent runs two shell commands that the git guard passes: `git hash-object -w --stdin` and `git replace <blob of dev> <new blob>`. The replace ref lives under `refs/replace/` in the shared git directory. So the temporary worktree of `premerge-check` sees it too, and it stays for every later story in the clone.

The problem starts in `GitRefSource`, the git ref backend of the trusted gate source. It resolves the tip of `refs/heads/<integration branch>` with `git show-ref`, which returns the true commit. Then it reads `docs/testing.yaml` and `docs/findings/exceptions.md` with `git ls-tree` and `git show <tip>:<path>`. Both commands follow replace refs by default, so git hands back the replacement object. `_settings_text` reads `integration_branch` from the `--base` revision the same way. DEC-77 and DEC-78 close the routes of a tag, a remote ref and a revision expression. No decision names replace refs, so the behavior is undocumented. `read_register` on `dev` reads the register the same way today.

```text
the story agent writes a blob with the threshold 30 and runs git replace <blob of dev> <new blob>
        ↓
git stores refs/replace/<blob of dev> in the shared git directory; refs/heads/dev does not move
        ↓
premerge-check adds its worktree at the story head and runs crap-score --base feature/login
        ↓
GitRefSource reads git show <tip of dev>:docs/testing.yaml, and git returns the replacement
        ↓
crap-score judges with the threshold 30 and exits 0 for a function that scores 9 against the threshold 8
```

The review ran this in a scratch repository with `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/probe-replace.sh`. `dev` holds the threshold 8, and the story raises it to 10 and changes `tree_severity`, which scores 9:

`/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/probe-replace-worktree.sh` repeats the attack in a detached linked worktree, as `premerge-check` uses one. It replaces the `docs` tree of `dev` with one that holds a register row for `tree_severity`. The run then prints `ACCEPTED packages/factory/scripts/finding-lint tree_severity 9.00: forged` and exits 0. `guard-human-fields` refuses every direct write of that register, and this route writes no file of the worktree.

**Why this severity:** A forged threshold or register row lets a story above the threshold merge through `premerge-check`, which is a gate bypass, so the bar starts at High. The attack needs the agent's shell in the repository (`trusted_access`), which lowers it to Medium, and Medium gives `major`. The reader lines exist only on `feature/crap-gate-trusted-source`, so they are not in use. The same agent can also move `dev` with `git update-ref`, which [SEC-0010](register/security/SEC-0010.json) records. The replace route differs, because `dev` never moves, `git log dev` shows nothing, and the forged values judge every later story.

**Fix:** In `crap-score`, the layer of the trusted gate source: run every git call with the option `--no-replace-objects`, so git reads the true objects. The calls are the `git` helper and the direct calls of `_branch_tip` and `_resolve`. The review checked the option in the scratch repository: `git --no-replace-objects show dev:docs/testing.yaml` prints the threshold 8, and `git show` prints 30. The diff of `changed_lines` uses the same helper, so the changed lines also come from the true commits. Add an integration test to `tests/factory/test_crap_gate_trusted_source.py` that writes a replace ref for the `docs/testing.yaml` blob of `dev`, and one for its register, and asserts the verdict of the true values. Add one sentence to § Trusted gate source of the interface contracts that the reader ignores replace refs.

**Code review of the fix, 2026-11-23:** The fix in `eee1ed20` is not complete, so the status stays `open`. On git 2.34.1, a repository config `core.useReplaceRefs=true` overrides both `--no-replace-objects` and `GIT_NO_REPLACE_OBJECTS`. The story agent writes that key with one `git config` call, which the git guard passes, and the key sits in the shared config that the worktree of `premerge-check` reads. With the key set, the replace ref on the `docs/testing.yaml` blob of `dev` again gives the threshold 30 and exit `0`. Only a command-line `-c core.useReplaceRefs=false` wins over the file. [code-review-SEC-0009-2026-11-23.md](../reviews/code-review-SEC-0009-2026-11-23.md) holds the reproduction. The corrected fix: `git_argv` returns `["git", "-c", "core.useReplaceRefs=false", "--no-replace-objects", *args]`, and one test sets `core.useReplaceRefs true` before the replace ref.
