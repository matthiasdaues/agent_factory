# An untested module in a folder without __init__.py stops the measure instead of giving a 0 % row

**What is wrong:** A project with one `.py` file that no test imports, in a folder without `__init__.py`, gets no rows at all. The template exits `1` with `coverage cannot reach src/unused.py`. The same file in a folder with `__init__.py` gets a correct row with `coverage_pct` 0. So the result depends on a packaging detail, not on the tests. Plain folders such as `src/`, `scripts/` or `tools/` are common, so one untested helper there blocks the gate for every story, also for stories that never touch it.

The problem starts in the coverage configuration that `run_tests` writes. With `source = <root>`, coverage.py reports files that no test ran only in folders that are packages. A plain folder is a namespace package for coverage.py, and it leaves such folders out unless `[report] include_namespace_packages = True` is set. `measure` then finds no coverage entry and counts the file as unreachable. BR-130 keeps the non-zero exit for a file that coverage cannot reach. Coverage can reach this file: it measures it as not run, and 0 % is the true value. The behavior looks unintended.

```text
src/unused.py has a function and no test imports it; src/ has no __init__.py
        ↓
run_tests writes source = <root> without include_namespace_packages
        ↓
coverage.json has no entry for src/unused.py
        ↓
measure counts the file as unreachable and raises CannotMeasure
        ↓
the template exits 1 and the gate gets no rows for any function
```

The review checked this in a scratch project: `src/parser.py` with `Parser.parse`, `src/unused.py` with the function `lonely`, and one test that imports only the parser. The template exited `1` with the message above. With `src/__init__.py` added, it exited `0` and wrote `lonely` with `coverage_pct` 0.0. With `src/__init__.py` removed and `[report]` and `include_namespace_packages = True` added to the coverage configuration, it also exited `0` and wrote the same row.

**Why this severity:** The template exists only on `story/ST-0435`, so `in_use` is false. The template stops with "cannot measure" for a file it can measure, so the gate gets no rows (yes to fails_purpose).

**Fix:** In `run_tests`, add `[report]` and `include_namespace_packages = True` to the configuration text written to `rcfile`. Add a test to `tests/factory/test_crap_gate_template.py` with an untested `.py` file in a folder without `__init__.py`, which checks exit `0` and one row for that file's function with `coverage_pct` 0. The case "coverage cannot reach" of CG-03-IT-04 keeps the extensionless script, which coverage cannot find without a run.
