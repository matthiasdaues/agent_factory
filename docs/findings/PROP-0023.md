# `assess_staged_paths` return semantics undefined for FlowResult

**What is wrong:** The proposal defines `FlowResult.status` as exactly one of `allowed`, `blocked`, or `operational_error`, and `FlowResult.operation` as exactly one of `advance`, `retry`, or `check_staged`. But the mapping from `transition-lint`'s current output model to `FlowResult` is never specified. Specifically:

- What `FlowResult.status` does a clean check return? Presumably `allowed`, but that word implies "the operation may proceed" — for a staged-path check, it means "no ordering violations found." The semantics are different from `assess_advance`'s `allowed` (which means "the advance may proceed").
- What status does the `TL-NOMARKER` no-op case return? It is currently `info`-severity, not an error. Is it `allowed` (no marker means no ordering constraint) or `operational_error` (cannot evaluate)?
- How do `FlowProblem` entries map to the existing `Finding` dataclass? The fields are 1:1 (`code`, `severity`, `artifact`, `message`), but does `FlowResult.problems` include info-level findings (like `TL-NOMARKER`) or only errors?
- What is `FlowResult.target_state` for a `check_staged` operation? There is no target state in a staged-path check.

**Fix:** Add a paragraph to Design section 3 defining the `check_staged` operation's `FlowResult` contract: which status values it produces, how findings map to problems, what `target_state` and `next_marker` contain (presumably `None` for both), and how the `TL-NOMARKER` no-op maps.
