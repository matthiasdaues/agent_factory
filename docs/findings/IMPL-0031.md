# By hand, a red test suite after the merge deletes the User's uncommitted changes

**What is wrong:** By hand, a red test suite after the merge deletes every uncommitted change to a tracked file in the primary checkout, and the User loses that work without a warning. The loss starts at the checkout of the feature branch by hand (`dispatch:2283-2286`). Git carries a change to a file that the story did not touch over to the feature branch without a refusal, as BR-124 allows. The red-suite branch then runs `git reset --hard <pre-merge commit>` (`dispatch:2358`), and that command also resets the working tree. BR-116 asks only that the feature branch moves back, so the loss looks unintended. In an orchestrated run, the worktree of the feature branch belongs to the run, so the reset did not reach the User's work there. ST-0410 opens `merge-story` to the ledger of a run by hand, so the reset now runs in the User's own checkout.

```text
User edits src/.keep in the primary checkout on story/ST-0350
        ↓
premerge-check passes in its temporary worktree
        ↓
git checkout feature/login carries the change, because the story did not touch src/.keep
        ↓
merge, then the test suite runs on the merge commit plus the change, and fails
        ↓
git reset --hard deletes the change; ST-0350 is blocked
```

The review checked this in a scratch repository with a run by hand. ST-0350 was `dispatched` on `story/ST-0350`, and `test_command` failed only on `feature/login`. The User's change to `src/.keep` read `my uncommitted work`. `merge-story ST-0350` exited `1` and set ST-0350 `blocked` with `post-merge test failure`. It moved `feature/login` back, and `src/.keep` was empty afterwards.

**Why this severity:** The lines that open the hand path exist only on `feature/run-lifecycle` and the story branch, so `in_use` is false. The path loses data in the checkout that the User works in, and the story's Boundaries keep the red-suite behavior of the orchestrated path, which never touched the User's files (yes to fails_purpose).

**Fix:** In the red-suite branch of `cmd_merge_story`, move the feature branch back with `git reset --keep <pre-merge commit>` in place of `git reset --hard`. `--keep` moves the branch and the files that the merge changed, and it keeps a local change to any other file. Add a test in `tests/factory/test_run_lifecycle_dispatch.py`: a run by hand, a changed tracked file outside the story, and a suite that fails only on the feature branch. The test checks that the change survives, the feature branch is back at its old tip, and the entry is `blocked`.

**Resolution (pass 2):** Commit `06a5c718292c48197a0db606688469ee1e2af162` on `story/ST-0410` replaces the hard reset with `git reset --keep <pre-merge commit>` in the red-suite branch of `cmd_merge_story`. When `--keep` refuses, `merge-story` exits `1`, names the refused move, and leaves the entry `dispatched`. `test_RL_06_IT_02_a_red_suite_by_hand_keeps_a_change_outside_the_story` changes `src/.keep` by hand and runs a suite that fails only on `feature/login`. The test checks that the change survives, that `feature/login` is back at its old tip, and that the entry is `blocked` with `post-merge test failure`. The test passes at `06a5c718`. Against the script of `47cb227b`, it fails, because `src/.keep` is empty afterwards.
