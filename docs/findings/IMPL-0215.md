# The freshness row promises a warning that consumer projects never receive

**What is wrong:** A reader who installs the factory into a separate project expects the hook to warn when the installed copy is stale. The reference row omits that the hook checks the Git tree at `packages/factory/` in the project itself. The shell hook exits before reading the install manifest when that directory is absent. The Pi extension has the same directory check. In a scratch Claude installation without that directory, the installed hook exited 0 with empty stdout and stderr after I set the recorded tree hash to zeros.

**Why this severity:** The fix for IMPL-0200 requires the reference row to explain when the hook prompts the user to run the updater. The row still gives the wrong behavior for the documented separate-project installation. The changed row is on the story branch.

**Fix:** Limit the warning to a self-installed source checkout whose committed `packages/factory/` tree differs from the recorded tree hash. Say that the check is silent in a separate project without that directory. Keep the link to the update how-to.
