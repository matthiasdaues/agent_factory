# Session identifiers can escape the usage storage directory

**What is wrong:** `JsonlLoggingAdapter` interpolates the hook-supplied
`session_id` directly into the transcript directory and session JSONL path. A
payload containing separators, `..`, or an absolute path can redirect writes
outside `.agent-factory/usage`. For example, `--session ../../escaped` makes
the session record target escape the usage directory and also redirects the
transcript directory. A malicious or malformed lifecycle payload can therefore
create or overwrite JSONL files anywhere writable by the developer account.
This is OWASP A01: Broken Access Control, High severity.

**Fix:** Treat session IDs as opaque data and derive filesystem names through a
strict encoding or digest, retaining the original value only inside the record.
Resolve every destination and enforce containment beneath the canonical usage
root; reject symlinked path components. Use exclusive or no-follow file
creation. Add regressions for traversal, absolute paths, platform separators,
and symlink redirection.

**Resolution:** `UsageStoragePaths` now owns every session and transcript path.
The session-level storage key is `<cli>_<session_id>` (record file and
transcript directory), so a directory listing identifies which CLI produced a
run; both the CLI token and the session id pass through `filesystem_key`, so a
filesystem-safe identifier — bounded ASCII, mixed case allowed (Pi's uppercase
`...T...Z...` session ids; the usage directory is gitignored, so the pathname
carries no privacy cost) — keeps its verbatim name, and the four supported
CLIs (`pi`, `claude-code`, `copilot`, `codex`) are all safe. Identifiers that
are unsafe as a filename component (path separators, `.`/`..`, Windows device
names such as `CON`/`Com1` (matched case-insensitively), oversized, or
non-ASCII) map to a fixed `opaque-<sha256>` component, while JSON records retain
the original values. The transcript leaf inside the session directory stays
keyed by `record_id` alone. The containment property this finding mandates is
unchanged: a hostile `session_id` or CLI value still cannot redirect writes
outside `.agent-factory/usage`. Storage directories and existing files are
checked with `lstat`, symlinks and non-regular targets fail closed, transcripts
use exclusive no-follow creation, and session records use no-follow append.
Regression coverage includes cross-platform hostile identifiers, CLI-prefixed
verbatim layout, symlink redirection at every storage level, transcript
collisions, and the end-to-end CLI sequence lookup.
