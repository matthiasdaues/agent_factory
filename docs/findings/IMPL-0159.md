# The persisted database lacks several published views

**What is wrong:** The user cannot run the second SQL example against the exported file because the table `usage_by_dimension` is missing. The query and browser pages promise the published view names. The persistence code exports the relations present after the selected query. With `valid_tree.jsonl`, `session_usage --persist usage.duckdb` exported `latest_run_snapshots`, `preflight_failure`, `preflight_valid`, `session_contributions`, `session_roots`, and `session_usage`.

**Why this severity:** The story requires the handbook to describe the current code. The new instructions also direct the reader to run a query against an absent table. The affected documentation is on the story branch.

**Fix:** Describe the selection-dependent export on both pages. Run the six-view SQL examples against the bootstrap, or give an example that uses the tables actually exported by this command.
