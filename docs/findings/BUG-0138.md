# The feature merge crashes on a `gates` section that is no mapping

**What is wrong:** Take a feature branch whose `docs/testing.yaml` has a `test_command` and a `gates` section that is no mapping, such as `gates: []`. Then `premerge-check dev <feature-branch>` stops with a traceback. It does not run the test suite, and it does not print its verdict. The User receives the traceback at the merge into `dev`. At `c0ae79bd` the same file ran the test suite and printed the usual result lines.

The problem starts in `_parse_testing_yaml`, which the fix of BUG-0137 changed. For every reader it now raises `BrokenTestingYaml` when `gates` is no mapping. The feature merge reads `test_command` through `check_feature_merge` and then `check_test_suite`, `read_test_command` and `_read_testing_yaml`. Nothing on that path catches `BrokenTestingYaml`: `main` catches only `GitReadError` around `check_feature_merge`. DEC-83 names the refusal of a story merge and the exit 3 for `dev`, and it says that neither ends in a traceback. It says nothing about the feature merge, so the crash is not intended. The code review of BUG-0137 states that the feature merge reads no `docs/testing.yaml`. That statement does not hold, because `read_test_command` reads the file.

```text
docs/testing.yaml on feature/login has test_command: "true" and gates: []
        ↓
premerge-check dev feature/login runs check_feature_merge, then check_test_suite on the feature worktree
        ↓
read_test_command calls _read_testing_yaml, which calls _parse_testing_yaml
        ↓
_parse_testing_yaml raises BrokenTestingYaml for the gates section
        ↓
main catches only GitReadError, so the process ends with a traceback and exit 1
```

The review ran `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/repeat-feature-merge.sh`. It builds a repository with `dev` and `feature/login` and runs `premerge-check dev feature/login --max-files 50` twice: once with the script of the new head, and once with a copy of the script at `c0ae79bd`:

```text
== new head
  File ".../packages/factory/scripts/premerge-check", line 826, in _parse_testing_yaml
    raise BrokenTestingYaml("has a gates section that is no mapping")
BrokenTestingYaml: has a gates section that is no mapping
exit 1
== c0ae79bd
PASS open-findings: no open blocking finding of the run on feature/login
PASS test-suite: the test suite 'true' passed for feature/login
premerge-check: BLOCK — do not merge 'feature/login' without an explicit override
exit 1
```

The BLOCK of the old copy comes from the missing reports of the scratch repository, not from the file. `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/repeat-dec83.py` shows the same change at the level of `read_test_command`. It returns `'pytest -q'` at `c0ae79bd`, and it raises `BrokenTestingYaml` at the new head, for `gates: []` and for `gates: none`.

**Why this severity:** `premerge-check dev <feature-branch>` exists to give the verdict on the merge into `dev`. With this file it gives a traceback instead, so the check fails its purpose. Changing the file is the workaround. The code exists only on `feature/crap-gate-trusted-source`, so it is not in use. The traceback names no file and no fix (`raises_cost`).

**Fix:** In `premerge-check`, the layer of the merge checks: catch `BrokenTestingYaml` in `check_test_suite`, or in `check_feature_merge` around it. Turn it into a failed check line that names `docs/testing.yaml` of the feature branch and the cause, such as `BLOCK testing-yaml: docs/testing.yaml of feature/login has a gates section that is no mapping`. The merge then exits 1 without a traceback, as DEC-83 requires for a story merge. Add the case to the tests of `check_feature_merge`. Name the feature merge in DEC-83 in the Appendix of `docs/proposals/crap-gate-setup.md`.
