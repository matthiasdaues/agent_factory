# policy-validate knows only falsification artifacts, so the survey playbook's policy gate either errors out or passes without checking anything

**What is wrong:** [research-survey.md](../../factory/playbooks/research-survey.md) requires that every artifact "pass schema validation, policy where applicable, then semantic review" between steps. [policy-validate](../../factory/scripts/policy-validate) cannot perform that middle stage for a survey run. Pointed at the full artifact set it fails on an unrecognised artifact; pointed at the source records alone it returns exit 0 without evaluating a single applicable rule. Either way you learn nothing, and exit 0 reads as coverage that does not exist.

The cause is that every kind and every check in the script is shaped for falsification mode.

`_KIND_SCHEMA` (line 87) maps seven kinds: `conjecture`, `source`, `test`, `review`, `vote`, `claim-register`, and `final-report`. The three artifacts unique to survey mode — the research brief, the survey plan, and the survey report — appear nowhere in it. `_infer_kind` (line 156) returns `None` for each, and the loader then raises `SystemExit(2)` with "cannot determine artifact kind".

All six checks in `run_policy_checks` (line 601) correlate on claims:

- `check_reference_integrity` (line 302) walks only reviews, tests, and votes. A survey run has none, so it passes with nothing examined.
- `check_role_separation` (line 326) iterates `conjecture_by_claim`, which is empty.
- `check_source_family_independence` (line 371) iterates conjectures and their cited sources. With no conjectures, the source records it was meant to protect are never compared.
- `check_claim_admission` and `check_register_integrity` are claim and register machinery, absent by definition.
- `check_report_traceability` (line 564) returns immediately on `if s.report is None or s.register is None`. `s.report` is populated only for kind `final-report` and `s.register` only for a frozen claim register, so both are `None` in every survey run. Even were the report loaded, the check resolves `findings[].surviving_claim_refs`, whereas a survey finding carries `source_record_refs` against `research-survey-report.schema.json`.

The consequence is that the one traceability rule survey mode actually needs — every finding's `source_record_refs` resolves to a source record gathered in this survey — is enforced nowhere. [research-survey.md](../../factory/playbooks/research-survey.md) Step 5 assigns exactly that work to the orchestrator as a manual act, which makes the load-bearing check of the whole playbook a matter of agent diligence rather than a deterministic gate. That inverts [foundational-principles.md § Agentic Creation, Deterministic Validation](../../factory/rulebooks/conventions/foundational-principles.md#agentic-creation-deterministic-validation).

**Verification:** Observed on a completed survey run in the Gigacron project on 2026-08-14 — 43 source records across seven candidates, plus a brief, a plan, and a report.

Over the full artifact set:

```
$ factory/scripts/policy-validate --pipeline docs/research/data-modeling-dsl/
[FAIL] schema: cannot map 'docs/research/data-modeling-dsl/research-brief.json' to a schema
policy-validate: stopped at schema stage
exit=1
```

Over the source records alone:

```
$ factory/scripts/policy-validate --pipeline docs/research/data-modeling-dsl/sources/
exit=0
```

The second result is vacuous by the reading above. Two real defects sat inside that passing set and neither was surfaced. The survey report's 43 `source_record_refs` were resolved only because the orchestrator did it by hand at Step 5. And three Mermaid source records — `source-mermaid-erd-grammar.json`, `source-mermaid-erd-syntax.json`, and `source-mermaid-erd-tooling.json` — carry references to a `source-mermaid-erd-contrary-evidence.json` that was never written, because that assignment died on a session limit. The gate reported PASS with the dangling references present.

**Fix:** Give the script survey mode, in three parts.

Add the three missing kinds to `_KIND_SCHEMA`, mapping `research-brief`, `research-survey-plan`, and `survey-report` to `research-brief.schema.json`, `research-survey-plan.schema.json`, and `research-survey-report.schema.json`. `_infer_kind` already matches on file-name prefix, so correctly named artifacts resolve without further change.

Add a survey traceability check that resolves every `findings[].source_record_refs` entry to a source record loaded in the same run, failing on any reference that does not resolve. Make `check_report_traceability` dispatch on the report's kind rather than requiring a register, so a survey report is checked against source records and a final report against the frozen register.

State in [research-survey.md](../../factory/playbooks/research-survey.md) which checks apply in survey mode. The gate's present wording, "policy where applicable", lets a vacuous exit 0 be read as a pass. It should name what was checked, so that you can tell an empty result from a clean one.

Two smaller improvements are worth taking in the same pass. `check_source_family_independence` should compare the source records of a survey directly, since presenting several documents from one publisher as independent corroboration is a survey failure mode as much as a falsification one. And references between source records should be structured rather than prose: the dangling Mermaid references above sit in free-text `limitations` and `interpretation` fields, where no checker can see them. A `related_source_refs` array on the source-record schema would make them checkable.

See [BUG-0013](BUG-0013.md), which reports the format mismatch on the schema stage of the same gate.
