# The index displays escape text for an HTML comment opener

**What is wrong:** A handbook reader sees `&lt;!--` where the page description says `<!--`. The regression starts in `_literal`, which double-encodes every comment opener so the formatter cannot produce a reserved index marker.

Set `description: 'Use <!-- to start a comment.'` on an implemented page and run `handbook-index` in a scratch handbook. The new generator writes `Use \&lt;!-- to start a comment.`, which renders with the entity text visible. At `e5851118`, the generated sentence renders as written before the formatting hook. At the reviewed head, both hooks pass while the description displays the wrong characters.

**Why this severity:** BR-144 requires the generated entry to include the description. The substitution changes the syntax the sentence teaches. The reviewed code is on the story branch.

**Fix:** Restrict the double encoding to the two reserved index markers. Keep single encoding for other comment openers so the formatter can escape them, and check that the rendered description and the marker count both survive the hooks.
