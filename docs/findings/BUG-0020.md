# Unpinned `uvx ruff` toolchain: ruff 0.16.x default-rule expansion left the repo-wide ruff gate red at head

**What is wrong:** The ruff gates are wired as `uvx ruff check --fix` and
`uvx ruff format` in `.pre-commit-config.yaml` (root half
`agent_factory_hook-ruff-*` with no path exclusion, orchestrator half
`ruff-*-orchestrator` scoped to `^orchestrator/`), and the `validate` skill
documents `ruff check .` / `ruff format .` with no version pin. `uvx`
resolves the latest ruff on every run. Ruff 0.16.x widened its default rule
set (now including `I001`, `RUF012`, `PLW1510`, `PLR1730`, `UP006`, and
`RUF100`); under ruff 0.15.x the same tree was clean. As of this review,
`uvx ruff check .` reports 60+ violations, the overwhelming majority in
pre-existing, out-of-diff-scope orchestrator research test files
(`orchestrator/tests/test_research_*.py`, `test_commit_safe.py`,
`test_schema_validate.py`, ...). Consequences:

1. The repo-wide `ruff check .` gate (validate skill) fails at branch head
   `ff123986ad44494fd96f6a508a74a6294f496040`.
2. Any future commit that stages an affected orchestrator Python file will
   fail the pre-commit hook, because the violations are not auto-fixable
   (`RUF012` mutable class attributes, `PLW1510` subprocess without
   `check`).

The two in-scope violations introduced by this diff's work have been fixed
by this QA pass: `factory/scripts/dispatch_lib.py` (I001 import ordering)
and `factory/fixtures/quality-gates/high-crap/src/module.py` (PLR1730 —
intentional high-complexity fixture, now carries a file-level
`# ruff: noqa` with an explanatory comment; the directive does not change
the AST that the crap-score gate measures).

**Fix (options, in decreasing preference for the project's intent):**

1. Pin the ruff version in the hook entries
   (`uvx ruff@<pinned-version> check --fix`, `uvx ruff@<pinned-version> format` in both hook halves) and in the `validate` skill, matching the
   pinned-toolchain pattern the config header already documents for the
   orchestrator half.
2. Alternatively, add a root `[tool.ruff]` section with an explicit
   `select` (and `extend-exclude` for `factory/fixtures/`) so the rule set
   is stable across ruff releases, then either fix or explicitly waive the
   pre-existing violations.
3. Alternatively, migrate the 60+ pre-existing violations to the current
   defaults (mechanical for I001/UP006/PLR1730; `RUF012`/`PLW1510` need
   manual edits across ~25 out-of-scope files).

This finding stays open until one of the three options is chosen and the
repo-wide `ruff check .` gate is green again.
