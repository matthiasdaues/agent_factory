# The QA strategy deletes the only test of the `next-id --seed` hint for a clone without origin

**What is wrong:** The Gap Findings row at line 166 says that Rule CIF-08 changes the message of a clone without `origin` to name only `origin` and `--remote`. The retention policy at line 193 then deletes `test_st_0370_clone_without_origin_names_origin_remote_and_seed` and lets CIF-08-IT-03 replace it. The specification does not change that message. The CID-04 Scenario "A clone without origin, agent-factory.counterRemote, and --remote cannot make an ID claim" still requires that the message names `origin`, `--remote`, and `next-id --seed`. The claim error table of `interface-contracts.md` still lists `next-id --seed` for the row "no `--remote`, no setting, no `origin`". Only the marker case of BR-097 drops `--seed`, and CIF-08-IT-04 covers it. CIF-08-IT-03 asserts only `origin` and `--remote`. So after the deletion, no test checks the `--seed` part of a live contract.

**Why this severity:** A story built from the retention policy deletes the one test that guards the CID-04 message and cuts a wrong change into the suite (fails_purpose). A later edit can then drop the hint unnoticed, and a reader has to compare two feature files to see the gap (raises_cost).

**Fix:** Correct the Gap Findings row: CIF-08 keeps the message of a clone without `origin` and without the setting. Keep `test_st_0370_clone_without_origin_names_origin_remote_and_seed` as the owner of that message, and give it a precondition without `agent-factory.counterRemote`. Let CIF-08-IT-03 own only the new part: a clone without the setting fails as before. Remove the deletion from the Test Retention Policy.
