# A partial failure in `prepare-wave` blocks the story for good

**What is wrong:** When `worktree add` or `verify-base` fails, the branch made with `git branch` remains. Every retry fails with "A branch named 'story/ST-0001' already exists". This also breaks the rule that a branch and its worktree are created together. Source: [bug-hunt report § D-6](../reviews/bug-hunt-2026-10-15.md#d-6--a-partial-failure-in-prepare-wave-blocks-the-story-for-good).

**Fix:** Use `git worktree add -b`, and roll back or reuse on retry.

**Resolution:** Fixed in commits `cd404785de67991123e8cf4d9306fb1c99599707`, `cdc891ac1e42cc5439c1a7437a550d312fce0a7f`, and `236991662e3bd5e7d5d4a29d1ab5af15698bb0cc`, merged into `dev` as `36ef31f20b0af5f52a796800637e7dc9c4d88128`. `prepare-wave` and `prepare-story` create the story branch together with its worktree and remove only what the same call created when a later step fails. A leftover branch is reused only when it holds no work. A review found that the first version of this rollback could delete a live worktree on a second `prepare-wave`; both commands now prepare only `pending` stories, and `prepare-story` points a `failed` story to `re-dispatch`. The full suite passed after the merge.
