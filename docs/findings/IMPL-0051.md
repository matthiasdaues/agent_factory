# Three agent texts still put reconciliation before QA and the merge

**What is wrong:** An agent that follows its own definition still runs reconciliation before QA, on the feature branch, before the merge into `dev`. The story's Domain Rule sets the order code review, QA, merge, then reconciliation on `dev`. The implementation agent, both playbooks, and `branching-policy.md` now give that order, but these agent texts still give the old one:

- `packages/factory/agents/code-review-agent.md:137-138`: when the review is clean, the handoff sends the run to the reconciliation agent with "Code review is clean. Run reconciliation."
- `packages/factory/agents/reconciliation-agent.md:76` and `:84`: the timing is "at Phase 5, pre-merge to dev", and the handoff on line 118 sends the run to the QA agent with "Spec reconciled. Run QA agent."
- `packages/factory/agents/qa-agent.md:104`: the clean handoff says "QA passed. PR ready to merge." It names neither `premerge-check dev <feature-branch>` nor the User's merge.
- `packages/factory/playbooks/documentation-update.md:103` says that the owners of reconciliation rows commit "normally the feature branch before its merge into `dev`".

The gap starts in the story scope. The story changed the order in the implementation agent, the two playbooks, and the branching policy, but not in the handoffs of the code-review, reconciliation, and QA agents. So after a clean review of the whole feature, the code-review agent hands the run to the reconciliation agent. That agent then reconciles the feature branch before QA and hands the run to the QA agent. The behavior is not intended; the text tests of RL-13-LN-01 read only the playbooks, the implementation agent, and the branching policy.

**Why this severity:** Line 76 of `reconciliation-agent.md` exists unchanged on `dev`, so `in_use` is true. On `dev` the old order is still the rule, so the line gives no wrong result there (no to harms_downstream). On this branch, an agent executes its handoff, and these handoffs give the order that the Domain Rule of ST-0424 replaces (yes to fails_purpose). Each wrong handoff adds a reconciliation pass on the feature branch that the run must repeat on `dev` (yes to raises_cost).

**Fix:** Change the three agent definitions and `documentation-update.md` to the new order. The code-review agent hands a clean review of the whole feature to the QA agent. The QA agent hands a clean result to the implementation agent, which runs `premerge-check dev <feature-branch>`. The reconciliation agent runs once per feature, on `dev` after the merge. `qa-agent.md` is in the `touches` of ST-0424. The other three files lie outside them, so the implementation agent either extends the scope of the story or adds the fix as a unit of work with `dispatch add IMPL-0051`. The same change must say on which branch the owners of reconciliation rows commit after the merge, because the run and its feature branch end with `dispatch close`. Add a text check to `tests/factory/test_run_lifecycle_text.py` under RL-13-LN-01 that reads the three handoffs.
