# Two CONTEXT.md files with the same `###` subheading hide their duplicate terms

**What is wrong:** A project can end up with two conflicting definitions of one term in the glossary, and the script does not tell the developer. The fix for IMPL-0002 names a glossary section after its `###` subheading. Generic subheadings such as `### Orders` often repeat across `CONTEXT.md` files, so two sections get the same heading. The first point of loss is `duplicate_terms` (line 585). It records each section by its heading text, so two sections named `Orders` count as one section. A term in both of them is never listed. The `duplicate term:` line and the `next step:` line for the cleanup are both missing. The run exits 0. The Output row of the interface contract requires one `duplicate term:` line per term in more than one section (DEC-18). The behavior looks unintended. Before the fix, the script refused this input with exit 2, so no test covers the case.

```text
docs/CONTEXT.md and docs/arc42/CONTEXT.md each have "### Orders" with "Order"
        ↓
convert_context names both sections "Orders"
        ↓
duplicate_terms keys sections by heading text and sees one section
        ↓
no "duplicate term:" line and no cleanup "next step:" line, exit 0
        ↓
docs/spec/glossary.md holds two "## Orders" sections with conflicting "Order" rows
```

Failing case:

```text
docs/CONTEXT.md:        # Billing / ## Language / ### Orders / **Order**: A request to buy.
docs/arc42/CONTEXT.md:  # Shop    / ## Language / ### Orders / **Order**: A paid cart.
$ migrate-spec-layout .
docs/CONTEXT.md -> docs/spec/glossary.md: 1 terms (Orders)
docs/arc42/CONTEXT.md -> docs/spec/glossary.md: 1 terms (Orders)
next step: run capture-context --fold-context-map ...
exit=0
```

Without the subheadings, the same two files give `duplicate term: Order in Billing, Shop` and the cleanup step. Two files with the same `#` title show the same gap. The old script also had that gap, but the subheading makes it common.

**Fix:** Change `duplicate_terms` in `migrate-spec-layout` to count sections by their position, not by their heading text, so the term is listed. Add a test with two `CONTEXT.md` files that share a subheading. The line would then read `duplicate term: Order in Orders, Orders`. The stakeholder may want a clearer name for a subheading section, such as `Billing: Orders`. That choice belongs to the stakeholder, because decision (a) of IMPL-0002 does not name the section.

**Disposition (stakeholder, 2026-11-03):** minor, deferred to todo T-0013. No data is lost and the exit code is right; only the duplicate-term hint is missing for two sections with the same heading.
