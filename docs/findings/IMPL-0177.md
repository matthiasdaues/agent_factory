# The install inventory omits Codex ignore rules for existing folders

**What is wrong:** A maintainer can miss an untracked project playbook after installing for Codex. The inventory says the installer lists only files and folders it creates under `.codex/` and names Copilot as the only exception for existing paths. When `.codex/playbooks/` already exists, `symlink_factory_content` merges factory entries into that folder and adds the whole path `/.codex/playbooks` to the ignore block. In a scratch repository, `git check-ignore -v .codex/playbooks/local.md` matched the generated rule for a file created before installation. A tracked playbook in the same folder remained in `git ls-files`.

**Why this severity:** The inventory gives maintainers the wrong Git visibility for a project file. The handbook text under review exists on the story branch.

**Fix:** In the install inventory, explain that Codex lists `.codex/playbooks`, `.codex/rulebooks`, and `.codex/scripts` as whole paths even when the installer merges links into an existing directory. State how those rules affect tracked and untracked files. Update the sentence that limits the exception to Copilot.
