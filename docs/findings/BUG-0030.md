# The source-repository index hook regenerates the installed index, not the tracked one

**What is wrong:** The source-repository `index-lint` hook starts when a file
under `packages/factory/` changes. Its entry runs
`.agent-factory/factory/scripts/index-lint` without arguments. Without
arguments, the script reads agents, skills, playbooks, and rulebooks from
`.agent-factory/factory/` and writes `.agent-factory/factory/INDEX.yaml`. That
directory holds the installed copy and is not tracked. The tracked
`packages/factory/INDEX.yaml` is never regenerated, so it goes stale after
every change to an agent, skill, playbook, or rulebook. Commit `ae78926`
showed this: the new rulebook `working-discipline.md` was missing from the
tracked index, and the token counts for `rules.md`, `retrospective`, and
`reconciliation-agent` were out of date.

This also affects the fix in
[BUG-0029](BUG-0029.md). That fix keeps the source-repository hook as it is,
on the assumption that the hook works.

**Fix:** Change the hook entry to run `packages/factory/scripts/index-lint`
with `--agents-dir packages/factory/agents`, `--skills-dir packages/factory/skills`, `--playbooks-dir packages/factory/playbooks`,
`--rulebooks-dir packages/factory/rulebooks`, and `--out packages/factory/INDEX.yaml`. Add a test that changes a tracked rulebook, runs
the hook entry, and expects `packages/factory/INDEX.yaml` to change.
