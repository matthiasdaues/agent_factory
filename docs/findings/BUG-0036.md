# merge-story merges into the branch the calling checkout has open

**What is wrong:** `merge-story` checks the story against the invocation
branch with `premerge-check`, but it runs `git merge`, the status amend, and
the post-merge tests on whatever branch the current checkout has open. Run
from the main checkout on `dev`, the story merge lands on `dev`, and the
invocation branch does not move. Source:
[bug-hunt report § D-1](../reviews/bug-hunt-2026-10-15.md#d-1--merge-story-merges-into-the-wrong-branch).

**Fix:** Refuse to merge when the current branch is not the ledger's
invocation branch, and name the worktree to run from. State in
`implementation-agent.md` that `merge-story` runs from the invocation
worktree. Add a test for both cases.

**Resolution:** Fixed in commits `6c6356272db50c81b269381e284c05463d6cc78a`,
`34f6b94807ecc8c6df254a58a570a59f7e0eff3b`,
`8984d3ba378d33860057e2b997fa9dad219d12b8`, and
`80c3b9c76330938df6577416b262793f26759ffd`, merged into `dev` as
`f368a47bac30e888bfb365f1c851b83b78475ef8`. Three code review passes checked
the branch. The first found that `close-wave` could overwrite the merged head
from the main checkout. The second found that the recovery path left the
story file at `open`. Both were fixed on the branch. The full suite passed
after the merge.
