# The OpenCode plugin looks for guard-human-fields in the worktree, so it blocks every guarded call there

**What is wrong:** `guardHumanFields` in `packages/factory/config/plugins/agent-factory.ts` builds the script path from `topLevel(cwd)`, that is `git rev-parse --show-toplevel`. In a linked worktree, such as a story worktree, that names the worktree, which has no `.agent-factory/`. The plugin then finds no script and throws, so every `edit`, `write`, `patch`, `shell`, and `execute` call fails. ADR-0035 sets that the guard looks for its script in the primary checkout, through `git rev-parse --git-common-dir`. `blockDangerousGit` in the same file already does this through `commonRoot(cwd)`. Note N7 of `docs/reviews/code-review-ST-0428-2026-11-18.md` records the same case. `guardScript` in the Pi extension `packages/factory/config/extensions/guard-human-fields.ts` has the same lookup and breaks ADR-0035 the same way.

**Why this severity:** The plugin loads only since ST-0428, which exists only on `feature/run-lifecycle`, so `in_use` is false. An OpenCode agent in a story worktree cannot edit a file or run a command, and ADR-0035 requires the lookup in the primary checkout, so the answer to `fails_purpose` is yes. The call still fails closed, so no human field is at risk.

**Fix:** In `agent-factory.ts`, build the path of `guard-human-fields` from `commonRoot(cwd)` and remove `topLevel`. In `guard-human-fields.ts`, find the root through `git rev-parse --path-format=absolute --git-common-dir`, as `block-dangerous-git.ts` does. Keep `cwd` as the working directory and as the `cwd` of the payload, so the guard checks the paths of the worktree. Keep the refusal when the script is missing in the primary checkout. Add a test for each entry point that runs from a linked worktree: a call that sets no human field passes, a call that sets one is refused, and a missing script in the primary checkout blocks the call.
