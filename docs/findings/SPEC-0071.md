# A stop ends when an agent changes the status of an unconfirmed critical finding

**What is wrong:** The Lift row of the stop contract at line 1465 ends the stop once a stopping finding "has a status other than `open`". The Condition row and BR-091 also test only `status: open`. The Finding Lifecycle in `state-machines.md` says the opposite. **STOPPING** leaves only on **StopConfirmed**, and it rejects **FixVerified** and **Waived**. So two paths let an agent end a stop without the damage checks:

- The agent sets `status: deferred`. BR-086 lets an agent set `deferred`, `guard-human-fields` does not guard it, and no `finding-lint` rule ties `deferred` to the two confirmation fields.
- The agent writes `status: resolved` into the working tree. `finding-lint` rejects that file only at the next commit or `validate` run. `dispatch` and `premerge-check` read the working tree and lift the stop at once.

Take BUG-0037 in a headless run. The orchestrator cannot write `stop_confirmed_by`, because the guard refuses it. It can write `status: deferred`, and the next `dispatch prepare-wave 3` runs.

**Why this severity:** No story or code encodes the specification yet, so it is not in use. The stop contract and the Finding Lifecycle contradict each other, and the implementer of the stop cannot tell which one to build without asking (fails_purpose). A reader must also compare four files to find the gap (raises_cost).

**Fix:** Tie the end of a stop to the confirmation fields, not to the status. The recommended rule is this. A file with `severity: critical` and an empty confirmation field stops the run when its status is `open`, or when it carries `review_class` and any other status. The second clause keeps the old resolved `critical` files without `review_class`, such as BUG-0037, from stopping every run. Add a `finding-lint` rule that a `deferred` `critical` finding needs both confirmation fields, as a `resolved` or `waived` one does. Then align the Condition and Lift rows, BR-091, BR-086, the glossary entry **Stop**, and the Finding Lifecycle, which gains a rejected **Deferred** event on **STOPPING**. If the domain-modeling agent prefers a guard rule instead, ask the stakeholder first, because it adds a human field.
