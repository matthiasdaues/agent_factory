# The session-start check prints the origin URL with its token to the agent

**What is wrong:** At every session start with a local counter, VIRGIL sees the token in the `origin` URL in the clear. This affects a project whose `origin` URL carries user info, such as `https://user:token@host/demo.git`. The token lands in the agent's context and in the session transcript.

The first point of loss is check 2 of § Counter check in `session-menu.md:12`. It tells VIRGIL to check that `git remote get-url origin` succeeds. That command prints the URL unredacted on standard output. BR-077 runs the redaction inside `next-id` and `init-factory` "so an AI process never sees a token in the clear". ST-0382 sets the boundary "It prints no URL with user info". The sentence that follows in `session-menu.md` ("VIRGIL names a remote only by the redacted form that `next-id` prints") governs what VIRGIL says, not what the command shows VIRGIL. `test_fitting_text.py:115` asserts the literal command, so the test keeps the leak in place. The behavior looks unintended: the story names the command and the boundary together and does not see that they conflict.

**Why this severity:** The check fails the story's own boundary and BR-077 on the only new path where an agent reads the URL (`fails_purpose`). One sentence and one test assertion change, so no later cost follows (no to `raises_cost`). The text is only on `feature/counter-ids-fitting`, so it is not in use.

**Fix:** In `session-menu.md`, replace check 2 with a command that prints no URL, such as `git remote` with a check that one line reads `origin`, or `git remote get-url origin >/dev/null`. Change the assertion in `tests/factory/test_fitting_text.py:115` to the new command. Add an assertion that § Counter check names no command that prints the URL.
