# Agents sometimes report a wrong commit SHA

**What is wrong:** In an onboarding run one agent reported commit `d3618d2f06b52f02d54c593d47c4f29b510d58bd`. The real commit was `d3618d22d273577ebe702690c2449ca4cd91213f`: the first seven characters match, the rest is invented. Two later agents reported correctly, so the fault is intermittent, and a spot check usually passes. In a related case an agent claimed it had verified every path it cited, yet one path pointed to `tests/unit/` instead of `tests/integration/`. In automated mode `dispatch verify-story` already checks every reported SHA; work dispatched by hand has no such check.

**Fix:** State in the dispatch contract that the parent checks every reported SHA with `git cat-file -e <sha>^{commit}` and `git branch --contains`, and that agents copy SHAs from `git rev-parse` output instead of typing them.
