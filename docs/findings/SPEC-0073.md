# Two git-check Scenarios leave out origin/dev and origin/main

**What is wrong:** The Scenario "A consumer project skips the installed copy step" at lines 607-610 says that `finding-lint` "checks dev, main, and the tags that release_tag_patterns names only". The Scenario "An empty release setting counts no tag" at lines 643-646 says that it checks `dev`, `main`, and the installed copy. BR-088, DEC-50, and the Scenario "Lines on origin/dev count when the local dev lags behind" add `origin/dev` and `origin/main` to every git check. A test written from the first Scenario asserts that the lint reads no remote-tracking branch. That test fails against BR-088.

**Why this severity:** No story or code encodes the specification yet, so it is not in use. Two statements of the specification contradict each other, so the test author must ask which list of places holds (fails_purpose). A reader must also find the later Scenario to learn the full list (raises_cost).

**Fix:** Name `origin/dev` and `origin/main` in both Then steps. For example: "Then it checks dev, main, origin/dev, origin/main, and the tags that release_tag_patterns names, and not the installed copy". The second Scenario reads: "Then it checks dev, main, origin/dev, origin/main, and the installed copy, and no tag".
