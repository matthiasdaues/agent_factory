# The glossary row of the path-table outline cannot show a git rename

**What is wrong:** `Scenario Outline: A file of the path table moves with git` requires "git records the change as a rename" for every row. The last row moves `docs/arc42/12_glossary.md` to `docs/spec/glossary.md`. The script then writes a new chapter 12 at the old path and converts every table row (new column names, an added Avoid column). Git detects a rename only when the old path is gone from the index. A check in a scratch repository with the factory's real `12_glossary.md` shows `M  a/12.md` and `A  s/g.md`: a modified file and a new file, no rename. So the test for this row fails on a correct implementation. `git log --follow docs/spec/glossary.md` also stops at the migration, so the glossary does not keep its history the way the Rule's title promises.

**Fix:** Remove the `docs/arc42/12_glossary.md` row from this outline. The glossary Rule already covers the move. Then state in the glossary Rule what the history check is for chapter 12, for example "git shows `docs/spec/glossary.md` as added and `docs/arc42/12_glossary.md` as modified". If the stakeholder wants the glossary history kept, that is a design question for the proposal and goes back to the stakeholder.

**Resolution:** The glossary row is gone from `Scenario Outline: A file of the path table moves with git`. The glossary Rule has the new `Scenario: Git shows the glossary as a new file and keeps the history of chapter 12`: git shows `docs/spec/glossary.md` as added and `docs/arc42/12_glossary.md` as modified, and `git log docs/arc42/12_glossary.md` lists the earlier commits. The stakeholder decided on 2026-11-02 that the script keeps no rename and commits nothing; the gaps report records the decision. The QA strategy owns the scenario with CAL-06-IT-02.
