# Published query results have no declared schema or grouping interface

**What is wrong:** The reviewed usage-query contract names six published views and four output forms, but it does not declare the columns, types, keys, ordering, or null rules for any view. The feature nevertheless requires each view's "declared empty schema" and says `usage_by_dimension` groups by any supported dimension set without specifying how a caller selects that set. The QA plan cannot assert schema preservation, empty results, or dimensional totals against an absent external contract.

**Fix:** Add a versioned schema contract for every published view, including columns, DuckDB types, keys, nullability, and stable row-order guarantees where applicable. Define the command or relation parameters for selecting dimensions and their time granularity, then trace the corresponding cases into the QA owner table and correct the gaps report.
