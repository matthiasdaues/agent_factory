# The Python template reports an untested one-line function as 100 % covered

**What is wrong:** The gate passes a changed one-line function that no test runs, also when its true score is far above the threshold. The implementation agent and the person who merges then trust a pass that the numbers do not support. The coverage is lost in the template, in `function_coverage`: it counts only the lines from `start + 1` to `end`, so a function whose body stands on its `def` line has no executable line and gets `100.0`. The `def` line itself runs at import, so its line data cannot tell whether the function ran. The header of the template says that the command never reports a case it cannot measure as covered, so the behavior looks unintended. The proof does not catch it, because its planted functions have a body of their own.

```text
src/shape.py holds `def pick(a, b, c): return a if a else b if b else c if c else 0`, complexity 4
-> no test calls pick
-> function_coverage finds no executable line in range(start + 1, end + 1) and returns 100.0
-> crap-score computes 4 * 4 * 0 + 4 = 4.00, at or below the threshold 8
-> the gate passes pick; at 0 % the score is 20.00 and the gate would fail it
```

Reproduction: the scratch repository of BUG-0133 with `src/shape.py` replaced by a tested class and the untested one-line function `pick` above.

```text
$ crap-score --all
PASS src/shape.py pick 4.00
PASS src/shape.py Box.__init__ 1.00
PASS src/shape.py Box.width 1.00
exit 0
```

The report row of `pick` holds `"coverage_pct": 100.0`. Expected: `FAIL src/shape.py pick 20.00` and exit `1`.

**Why this severity:** The template exists only on the feature branch (`in_use: false`). A consumer that takes `coverage_pct` as the contract states it reads a false 100 % and draws a false verdict, which is the first risk of the QA strategy: a gate that passes code it should fail (`fails_purpose`).

**Fix:** In the template, decide whether a function ran from data that the `def` line cannot fake. Run coverage with `branch = True` in the generated `coveragerc`, and read the arcs of each file through `CoverageData.arcs()`. An arc into or out of the function's code object, with the negative line number `-start_line`, shows that the function ran. coverage.py 7.17 on Python 3.14 records the exit arc `(3, -3)` for a called one-line function on line 3, and no such arc for an uncalled one. For a function without a body line of its own, report `100.0` when such an arc is there and `0.0` when it is not. Add a test with an untested and a tested one-line function to `tests/factory/test_crap_gate_template.py`.
