# The test execution reference puts binding rules in ordinary prose

**What is wrong:** An agent reading the Test execution section gets command permissions without a link to their rule. The “Agents may run it” column declares which commands agents can invoke. The section also describes skipping hook checks without linking to the instruction to fix failing hooks.

**Why this severity:** BR-149 requires sourced callouts for binding rules. The QA strategy treats violations as blocking. The change exists only on the story branch.

**Fix:** Keep the test triggers and command purposes in the table. Link the execution permissions to their source or put them in a sourced callout. Link the hook description to the Git workflow guidance.

## Repeat pass

The command permissions now appear in sourced callouts. The sentence “You fix a failing hook instead of skipping it” still states the rule in ordinary prose. The adjacent callout already states the rule in the form BR-149 requires. The prose also reads as a rule for pre-push hooks, while the cited rule names pre-commit hooks.

**Fix:** Keep the factual explanation of the Git flag. State the binding pre-commit instruction only in its sourced rule summary.
