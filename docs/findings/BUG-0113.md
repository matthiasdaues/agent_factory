# Factory hook entries break YAML line-length rules

**What is wrong:** Each factory hook's `entry` is one line of 375 to 490 characters, and three `name` lines run past 80. yamllint's `line-length` rule fails on all of them, both at its default of 80 and at gigacron's 150. gigacron works around it with a per-file ignore in `.yamllint`.

**Fix:** Write each `entry` as a folded YAML scalar (`>-`) broken at spaces, so the command string stays the same. Shorten the three names. The two long `files:` regexes move to their own line, which yamllint allows as a non-breakable word. A shared `run-hook` script was weighed and not taken: it would live inside `.agent-factory/`, so it could not report that folder missing, and every entry would still need the inline guard.
