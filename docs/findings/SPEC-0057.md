# The structure files and the glossary use "claim" alone, which the glossary says to avoid

**What is wrong:** The glossary term **ID Claim** names "Claim, without the qualifier" in its Avoid column. The counter-ids sections of the structure files still use the noun "claim" alone throughout:

- `validation-rules.md`, BR-068 to BR-075: "A claim for any other prefix", "A claim raises the line", "the claim fails".
- `state-machines.md`, Claim Lifecycle: "the next claim sees the number", "ends the claim after one push", "the claim error table".
- `interface-contracts.md`, `next-id`: "Claim usage", "Claim output", "A claim fails in these cases".
- `entity-model.md`, Counter IDs Entities: "is replaced on every claim", "no two claims share a SHA".

The glossary entry **Stale Lease** says "a claim push" and "another caller". "Caller" has no glossary entry. The feature file avoids both words.

This finding does not block. The blocking glossary gate stays deferred.

**Fix:** Write "ID claim" where these files mean an ID claim, and keep "claim commit" as it is. In **Stale Lease**, write "the rejection of the push of an ID claim because another ID claim replaced the claim commit first". Or, if the stakeholder prefers the short form inside the counter-ids sections, narrow the Avoid entry to the feature file.
