# Tests check the installed scripts, so they fail in worktrees and miss source changes

**What is wrong:** `tests/conftest.py:16` sets
`SCRIPTS_DIR = INSTALLED_SCRIPTS_DIR`, and 13 test files in `tests/factory/`
build script paths from `.agent-factory/`. The directory `.agent-factory/`
holds the installed copy and is not tracked. This has two effects:

1. A new worktree has no `.agent-factory/`. On branch
   `feature/update-keeps-init-manifest`, the commit hook failed 51 tests in
   `test_characterization_checks.py`, `test_characterization_safety.py`,
   `test_context_lint.py`, `test_context_lint_legacy.py`,
   `test_format_detection.py`, and `test_testing_yaml_resolution.py`. Clean
   `dev` passed the same tests in the main checkout. The commit passed only
   after the main checkout's `.agent-factory/` was linked into the worktree.
   The branching rules require worktrees for automated work, so every
   automated commit hits this.
2. In the main checkout, these tests check the installed scripts. A change to
   a script under `packages/factory/scripts/` is not tested until the next
   install.

**Fix:** Point `SCRIPTS_DIR` and the 13 hard-coded paths at
`packages/factory/scripts/` when that directory exists, and fall back to the
installed copy only in a consumer project. Then run the test hook in a new
worktree with no `.agent-factory/` and expect it to pass.
