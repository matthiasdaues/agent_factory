# No test checks that a tag or a remote ref as `integration_branch` cannot measure

**What is wrong:** A later change to the reader could take a tag or a remote ref as the trusted source, and no test would fail. So the clause of DEC-77 that keeps a tag or a remote ref out has no check. The Scenario Outline "Broken gate settings on the integration branch cannot measure" of CG-14 has the Examples rows `v1.10.0, which names a tag and no local branch` and `origin/main, which names a remote ref and no local branch`. Its test, CG-14-IT-07 in `test_cg_14_broken_settings_on_the_branch_cannot_measure`, has no case for either row. No other test in `tests/factory/` sets `integration_branch` to a tag or a remote ref.

The gap starts in the test layer. The row CG-14-IT-07 of `docs/spec/work/crap-gate-setup-qa-strategy.md` lists its cases, and the list stops before these two rows. The rows came with DEC-77 after the strategy row, so the omission looks unintended. The spec review routed the gap to QA.

The code behaves as the rows say today. With `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/probe-keys.sh`, both values exit 2 and name the key and the value:

```text
== tag: integration_branch: v1.10.0
crap-score: cannot measure: the key integration_branch in docs/factory-settings.yaml names the branch v1.10.0, and git holds no branch v1.10.0
exit 2
== remote: integration_branch: origin/main
crap-score: cannot measure: the key integration_branch in docs/factory-settings.yaml names the branch origin/main, and git holds no branch origin/main
exit 2
```

`/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/probe-mutant.sh` runs a copy of `crap-score` whose `_branch_tip` resolves through `git rev-parse` instead of `git show-ref`. The tested row "only a tag refs/heads/main" still exits 2 with that copy. The untested row `v1.10.0`, with a tag at a commit whose threshold is 30, gives `PASS ... tree_severity 9.00` and exit 0. So only the missing row would catch that change.

**Why this severity:** CG-14-IT-07 owns the Scenario Outline, and two of its rows have no test, so an owned contract has no test (`fails_purpose`). The test file exists only on `feature/crap-gate-trusted-source`, so it is not in use. A later change to the reader must be checked by hand against DEC-77 (`raises_cost`).

**Fix:** In `tests/factory/test_crap_gate_trusted_source.py`, add two cases to the parametrization of `test_cg_14_broken_settings_on_the_branch_cannot_measure`. The first creates a tag `v1.10.0` at a commit whose `docs/testing.yaml` has the threshold 30 and commits `integration_branch: v1.10.0` on `feature/login`. The second creates `refs/remotes/origin/main` at such a commit and commits `integration_branch: origin/main`. Each asserts exit 2, the key and the value in the message, and no started measuring command. In the row CG-14-IT-07 of `docs/spec/work/crap-gate-setup-qa-strategy.md`, name both values. The planning agent cuts the unit of work. The developer agent writes the test, and the test-strategy agent updates the strategy row.
