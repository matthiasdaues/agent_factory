# Estimate claims decomposition basis but provides no ranges

**What is wrong:** The frontmatter declares `basis: decomposition` and `confidence: low`, but every estimate field — `human_review_hours`, `normalized_tokens`, and `estimated_consumption` — is `unknown`. The Design section decomposes the work into seven ordered implementation steps with named files and test suites. That decomposition is enough to produce at least a rough token range (count the boundary files, estimate the edit volume per step) and a review-hour range (two adapter redirections, one architecture model update, one smoke test review). A decomposition basis with no ranges is a contradiction: either the basis is `judgment` (which would justify `unknown`), or the decomposition should produce numbers.

**Fix:** Either downgrade `basis` to `judgment` (honest about the current state), or fill in rough ranges from the decomposition. The seven steps, fifteen boundary files, and two adapter redirections suggest a normalized-token range in the low thousands and a multiplier in the 15-25x range typical for feature-additions with review loops. Human review hours are estimable from the completion criteria count (14 checkable items, each requiring a verification pass).
