# The Scenario "The next wave waits for the wave record" contradicts BR-113 and `prepare-wave` as built

**What is wrong:** Commit `47618a65` rewrites BR-113 and the Prepare transition of the Ledger Entry Lifecycle to match `cmd_prepare_wave` in `packages/factory/scripts/dispatch`. In an orchestrated run, `prepare-wave <N>` no longer reads the wave records. It refuses only while an entry of an earlier wave is `prepared`, `dispatching`, `dispatched`, or `pending` and not held back. The Scenario "The next wave waits for the wave record" in `docs/spec/features/run-lifecycle.feature:930` still says the old rule. Its only Given is that the ledger holds no wave record for wave 1, and it expects `dispatch prepare-wave 2` to exit non-zero.

Take an orchestrated run on `feature/login`. Wave 1 holds ST-0350, which is `done`, and the ledger holds no wave record for wave 1. BR-113, the state machine and the code let `prepare-wave 2` prepare the stories of wave 2 and exit `0`. The Scenario expects a non-zero exit and no prepared story. A test written from the Scenario fails against correct code.

**Why this severity:** No story or code outside the run encodes the Scenario (in_use: false). Two statements of the specification contradict each other, and a test writer who follows the Scenario reports correct code as a defect (fails_purpose). ST-0421 is `pending` and plans the test RL-11-IT-02 from this Scenario, so its developer meets the contradiction next.

**Fix:** Rewrite the Scenario to the check that BR-113 defines for an orchestrated run. For example: "Given an orchestrated run is active on feature/login, And wave 1 holds ST-0350, which is dispatched, When the implementation agent runs dispatch prepare-wave 2, Then dispatch exits non-zero, And the message names ST-0350 and its state, And no story of wave 2 is prepared." The by-hand wave-record check keeps its own Scenario at line 936. Check whether the Rule "Implementation agent starts the next wave only after the wave close" at line 845 still holds as a rule of the agent, because `dispatch` itself does not enforce the wave record in an orchestrated run. SPEC-0114 asks the test-strategy agent to follow with the row RL-11-IT-02.

**Verified (2026-11-19, spec review repeat pass, fix check):** The fix holds. The domain-modeling agent kept the Scenario and changed the rule instead, because the Scenario states the target rule. Commit `87cc12ca` puts BR-113 and `On Prepare` back to that rule: both commands refuse until the previous wave has a wave record, and by hand each story is a wave of its own (BR-064). The Scenario at `docs/spec/features/run-lifecycle.feature:930` now agrees with BR-113 and the state machine. `cmd_prepare_wave` does not check the wave record yet. The pending ST-0421 builds that check, and its Domain Rule says that both commands refuse until the previous wave has a record. The status is now `resolved`.
