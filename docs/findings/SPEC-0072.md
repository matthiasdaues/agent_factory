# An agent can set a blocking finding to deferred and so drop it from the review loop

**What is wrong:** BR-086 at line 533, the `status` row of the finding-file contract, and the Scenario "The status values of a finding file" let an agent set `status: deferred` on any finding file. The review loop lists only files with `status: open`. So a deferred `major` finding drops out of the loop, as a waived one does. Only the human may accept a blocking finding unfixed, with `override_by` and `override_reason` (DEC-13, DEC-44). A deferred finding needs neither field. No rule names who may defer a finding, from which state, or with what record. The Finding Lifecycle reaches **DEFERRED** only through **NoArtifact** in the migration, and **IN_LOOP** has no edge to it. So the specification gives two answers to one question: may an agent set FAGAN-0042 to `deferred` while it is open and `major`?

**Why this severity:** No story or code encodes the specification yet, so it is not in use. The Scenario and the Finding Lifecycle answer the question differently, so a planner cannot cut the `finding-lint` and guard stories without asking the author (fails_purpose). A reader must also trace the status through three files (raises_cost).

**Fix:** Ask the stakeholder whether an agent may set `deferred` on an open `critical` or `major` finding. The recommended answer is no. `deferred` then stays the status that the migration gives a finding without an artifact, and that file carries no `review_class` (BR-095). `finding-lint` rejects `deferred` on a file that carries `review_class`. Record the answer in BR-086, the finding-file contract, the Scenario "The status values of a finding file", and the Finding Lifecycle. Add the question to the gaps report, so the decision has a record. The fix of SPEC-0071 depends on this answer.

## Resolution

The stakeholder answered no (DEC-55, FC-G09). BR-086 lets an agent set only `open` or `resolved`, and only the migration sets `deferred`, on a file without `review_class`. `finding-lint` rejects `deferred` on a file that carries `review_class`. The Scenario "The status values of a finding file" states this, the new Scenario "The human sets a blocking finding aside with waived, not deferred" covers the waiver path, and "A structural rule is broken" gains the row for `deferred`. The stakeholder also decided that only a person lowers a filed finding (DEC-56, FC-G10), so BR-109 and five Scenarios of FC-10 close the second path out of the loop. The finding-file contract and the Finding Lifecycle belong to the domain-modeling agent, which mirrors both decisions with SPEC-0071.
