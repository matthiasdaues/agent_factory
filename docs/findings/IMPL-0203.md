# The generator changes literal whitespace inside inline code

**What is wrong:** A reader who copies an inline command from a generated description can get a different argument from the one the author wrote. The new `_single_spaced` helper splits all whitespace before the Markdown renderer can distinguish prose from inline code. The formatter keeps the original spaces inside the code span.

```text
YAML description: Run `printf "a  b"`.
Base generator:   Run `printf "a  b"`.
Head generator:   Run `printf "a b"`.
Formatter:        Run `printf "a b"`.
```

**Why this severity:** BR-144 requires the index entry to include the page description. The fix changes the contents of a shell argument in that description, while both index checks pass. The reviewed fix exists on the story branch.

**Fix:** Keep literal content when giving the generated region one formatting owner. Add a regression case that checks the inline code after generation and formatting.
