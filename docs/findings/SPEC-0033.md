# The owner of a finding is defined as the artifact's owner, but two cases name another agent

**What is wrong:** The entity model, the interface contract [Finding frontmatter owner:](../spec/interface-contracts.md#finding-frontmatter-owner), and the CAO-16 Scenarios define `owner:` as "the agent that owns the artifact the finding is about". The interface contract for report rows defines Owner as "the producer of the artifact". Two decided cases break that definition. A `BUG` finding has `owner: developer-agent` (CAO-14), and the developer agent produces no artifact. A `QA` finding for a missing test moves to `owner: planning-agent` (CAO-G10, line 557), and the planning agent does not own the QA strategy. The glossary defines Producer but not Owner, so the spec uses two terms for one concept in some places and one term for two concepts in others. A finding-format story written from this definition would route `BUG` and missing-test findings wrongly. No Scenario states that the implementation agent skips an open `QA` finding whose owner is the planning agent, which CAO-G10 requires.

**Fix:** Define Owner in the glossary as the agent that must act on a finding or a report row. State that it is the artifact's producer by default, and name the two exceptions: the developer agent for a `BUG` finding and the planning agent for a missing test. Use that definition in the entity model and the interface contract. Add a CAO-12 Scenario: QA-0003 is open with `owner: planning-agent`, and the implementation agent does not dispatch the test-strategy agent for it.

**Resolution:** The glossary term Owner, `FINDING.owner`, and the `owner:` contract define the owner as the agent that acts on the finding next, with the `BUG` and missing-test cases. CAO-16 is renamed to `Rule: Owner receives every finding it acts on next`, and `Scenario: The test-strategy agent skips an open QA finding whose owner is the planning agent` joins CAO-12.
