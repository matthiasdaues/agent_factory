# The hook refresh drops a project's `args:` on factory hooks

**What is wrong:** `merge-precommit-config --update`, which `update-factory` runs since 1.3.0, replaces each `agent_factory_hook-*` stanza with the template's and keeps no key the project added. gigacron sets `args: [--exclude, "ST-*-details.md"]` on `agent_factory_hook-backlog-lint` (GB-5494). The refresh in 1.3.1 removed the line, so `backlog-lint` checked every `ST-*-details.md` as a story, and each commit that touched `backlog/` failed with 20 `BL-MISSING` errors.

**Fix:** The refresh replaces only the keys the factory uses in its template: `id`, `name`, `entry`, `language`, `pass_filenames`, `files`, `exclude`, `types`, `stages`. It keeps every other key a project set on a factory hook, such as `args:`, `verbose:`, or `additional_dependencies:`. A `backlog-lint` default that skips `*-details.md` was weighed and not taken: the name of a companion file is the project's convention, not the factory's.

**Resolution:** Fixed in commit `8c09c3b7` on `feature/hook-refresh-args-and-length`; the full suite passed. `merge-precommit-config --update` replaces only the keys the template uses and carries every other key a project set on a factory hook, such as `args:`, over to the refreshed stanza. gigacron must add its `args:` line to `agent_factory_hook-backlog-lint` once more; the next refresh keeps it.
