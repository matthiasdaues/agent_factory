# The stale-lease check matches English git messages, and git may print them in another language

**What is wrong:** The contract says that `next-id` retries only on the git messages `stale info` and `cannot lock ref … is at <sha> but expected <sha>`. git translates many of its messages into the language of the user's locale. If it translates either of these two, a real stale lease reads as `PushRefused`, and a claim that lost a race fails instead of retrying. On a local bare repository the remote side runs with the caller's locale too. This review did not check which of the two messages git translates, because this machine has no git translation installed.

**Fix:** State in the contract that `next-id` runs every git command with `LC_ALL=C`, so the local messages are in English. State that a remote server prints its messages in its own language, and that GitHub prints English. Or check the two messages in git's translation files and record the result.
