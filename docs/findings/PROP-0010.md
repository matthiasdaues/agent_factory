# Scope matching mismatch between step-guard globs and premerge-check prefix matching

**What is wrong:** Phase 2 specifies that the step-guard uses "gitignore-style" glob semantics with `**` for recursive matching, and "one shared matching implementation in step-guard used by both the guard and the resolver." However, `dispatch merge-story` passes story outputs to `premerge-check --scope`, and the existing `premerge-check` script uses simple prefix matching (`f.startswith(s.rstrip("/") + "/")`) -- not glob matching. If story outputs are glob patterns like `docs/spec/use_cases/UC-*.md` or `src/**/*`, premerge-check's prefix matcher will not match actual changed file paths correctly. A file `docs/spec/use_cases/UC-13.md` would not match the prefix `docs/spec/use_cases/UC-*.md`. This creates an enforcement gap where premerge-check falsely blocks clean merges or, worse, where step-guard and premerge-check disagree about whether a file is in scope.

**Fix:** Either (a) update `premerge-check` to use the same gitignore-style glob matching as step-guard (share the implementation or the library), (b) specify that `dispatch merge-story` resolves output globs to concrete file paths before passing them to `premerge-check --scope`, or (c) constrain story `outputs` to directory prefixes only (no wildcards) and document that constraint in the story template. Option (a) is most consistent with the proposal's "one shared matching implementation" principle.
