# SEC-0005 — Bash Guard False Positives

**Date:** 2026-08-26  
**Severity:** Low  
**Category:** A03:2021 – Injection  
**Status:** Acceptable tradeoff — not a defect

---

## Summary

Best-effort bash path extraction in `step-guard` may produce false positives (e.g., `echo 'x' > docs/spec/prd.md` is denied even if `docs/spec/prd.md` is in declared outputs) because `echo` is not in the `WRITE_COMMANDS` set.

## Evidence

```python
# factory/scripts/step-guard
READ_COMMANDS = {"cat", "rg", "grep", "head", "tail", "less", "wc"}
WRITE_COMMANDS = {"tee"}
```

The implementation does not include `echo` in `WRITE_COMMANDS` to keep the logic simple.

## Impact

A user may see a false positive denial if they use `echo 'x' > docs/spec/prd.md` to write to a file that is in their declared outputs. This is a minor inconvenience, not a security issue.

## Mitigation

This is an acceptable tradeoff:
- **Pros:** Simplicity, maintainability, low false negative rate
- **Cons:** Occasional false positives for `echo` commands

**Recommendation:** No action required. The security risk is minimal — the guard is a best-effort check, not airtight enforcement.

---

## Specification Alignment

From `mechanized-dispatch.md`:
> "Best-effort path extraction from common shell commands, checked against declared inputs and outputs. Shell syntax is Turing-complete; this catches common patterns, not all patterns."

The current implementation is consistent with the spec's "best-effort" requirement.
