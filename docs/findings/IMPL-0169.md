# The rewrite changes links inside multiline code spans

**What is wrong:** A reader sees a code example change during migration. The section rewrite uses `mask_code`, whose inline pattern stops at newlines and internal backticks. A probe with an opening backtick, `example`, a newline, `[x](docs/arc42/concepts.md)`, and a closing backtick returned one edit.

**Why this severity:** L-26 requires code spans to keep their bytes. The change exists only on the story branch.

**Fix:** Mask spans by matching opening and closing backtick runs of equal length. Cover multiline spans and spans with internal backticks. Keep the existing move-docs contract.

## Repeat pass

The inline scanner now refuses the original example. The reference definition scanner still edits code. In `README.md`, put an opening backtick and some text on line 1, `[x]: docs/arc42/concepts.md` on line 2, and the closing backtick after some text on line 3. The scanner collects the destination as a sure edit because it checks multiline code regions only for inline links.

**Fix:** Apply the multiline code region check to reference definitions before accepting their destinations. Add a regression test that checks the file and line in the refusal.
