# The glossary term Wave Record still says that both prepare commands refuse without one

**What is wrong:** The glossary defines Wave Record in `docs/spec/glossary.md:177` with the sentence "`dispatch prepare-wave` and `dispatch prepare-story` refuse until the previous wave has one." Commit `47618a65` removes that rule from BR-113. BR-113 now says that only `prepare-story` in a run by hand refuses until the previous wave has a wave record. In an orchestrated run, `prepare-wave <N>` reads the states of the entries of the earlier waves, and `prepare-story` checks no wave. The note on Prepare in `docs/spec/state-machines.md` and `cmd_prepare_wave` in `packages/factory/scripts/dispatch` agree with BR-113. The commit did not change the glossary.

**Why this severity:** No story or code outside the run encodes the definition (in_use: false). The glossary and BR-113 contradict each other, so an implementer who builds from the definition adds a wave-record check to `prepare-wave` that BR-113 forbids (fails_purpose).

**Fix:** Change the second sentence of the definition to the rule of BR-113, for example: "In a run by hand, `dispatch prepare-story` refuses until the previous wave has one. In an orchestrated run, `dispatch prepare-wave` reads the states of the earlier waves instead (BR-113)."

**Verified (2026-11-19, spec review repeat pass, fix check):** The fix holds. Commit `87cc12ca` puts BR-113 back to the rule that both commands refuse until the previous wave has a wave record. The glossary definition at `docs/spec/glossary.md:177` states the same rule, so the two no longer contradict each other. ST-0421 builds the check in `dispatch`. The status is now `resolved`.
