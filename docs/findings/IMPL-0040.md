# With status.showUntrackedFiles=no, close deletes untracked files without a stash

**What is wrong:** A User whose git config sets `status.showUntrackedFiles=no` loses every untracked file of a run worktree at `dispatch close`, and the close exits `0` without a stash. The loss starts in `_stash_and_remove` (`dispatch:2788`). The close asks `git status --porcelain` whether the worktree has changes, and that command follows the config, so it prints nothing for an untracked file. The close then makes no stash. `git worktree remove` without `--force` follows the same config, finds the worktree clean, and deletes the folder. BR-119 requires the close to stash the untracked files before it removes a worktree, so the behavior looks unintended.

```text
User sets status.showUntrackedFiles=no; notes.txt is untracked in story/ST-0350
        ↓
git status --porcelain prints nothing
        ↓
close makes no stash
        ↓
git worktree remove finds the worktree clean and deletes it
        ↓
notes.txt is gone; the output names no stash
```

The review checked this in a scratch repository. ST-0350 was returned and `pending`, its worktree held an untracked `notes.txt`, and the repository config held `status.showUntrackedFiles=no`. `dispatch close --drop` printed `deleted branch: story/ST-0350` and exited `0`. `git stash list` was empty, and `notes.txt` was gone.

**Why this severity:** The lines exist only on the story branch, so `in_use` is false. The close exists to end a run without losing work, and for this config it deletes the untracked files that BR-119 says it stashes (yes to fails_purpose).

**Fix:** In `_stash_and_remove`, run `git status --porcelain --untracked-files=all` so that the check ignores the config. Add a test to `tests/factory/test_run_lifecycle_close.py` under RL-14-IT-03: a worktree with only an untracked file and `status.showUntrackedFiles=no` in the repository config. The test checks that the stash holds the file.
