# Existing in-process test migration path unspecified

**What is wrong:** `tests/factory/test_transition_lint.py` contains 23 test functions that call internal adapter functions directly through the loaded module namespace: `tl.parse_marker()`, `tl.parse_fsm()`, `tl.state_outputs()`, `tl.successors()`, `tl.states_for_file()`, `tl.check_transitions()`, and `tl.main()`. After extraction, these functions either move to the engine (codec, service) or become engine-internal helpers no longer exported by the adapter. The proposal says "Neither adapter retains a duplicate implementation" but does not specify what happens to these 23 existing tests.

Three migration paths exist, and the proposal should commit to one:

1. The adapter re-imports and re-exports engine names so the existing test namespace (`tl.parse_marker`) still resolves. The tests survive unchanged but test through a re-export indirection.
2. The tests are rewritten to import directly from `engine.flow_control`. They become engine unit tests, and the adapter gets only subprocess characterization tests.
3. The tests are deleted, replaced by the new engine unit tests and subprocess characterization tests.

Each path has different implications for test coverage during the migration. Option 1 is the lowest risk during extraction (tests stay green throughout). Options 2 and 3 produce cleaner test ownership but require a coordinated rewrite.

**Fix:** Add a paragraph to Design section 2 or Design Details specifying which migration path applies to the existing `test_transition_lint.py` tests, and whether the same approach applies to the (not yet existing) `test_phase.py` in-process tests.
