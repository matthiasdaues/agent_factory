# `integration_branch` takes a revision expression, so a story judges itself by its own parent commit

**What is wrong:** A story can still be its own trusted source. It sets `integration_branch: "story/ST-1~1"` in `docs/factory-settings.yaml`, and `crap-score` then reads `threshold`, `files`, `exclude` and the register from the parent commit of the story head. That parent is a commit of the story itself, so the story chooses its own threshold. The gate-check step receives exit `0` for a function that the threshold of `dev` fails, and the output prints no notice. `premerge-check` runs the same call in a worktree detached at the same head, so it gets the same result; the review did not run `premerge-check` itself. The problem starts in `GitRefSource.__init__`. It builds the string `refs/heads/<value>` and passes it to `git rev-parse`, `git ls-tree` and `git show` as a revision, not as a ref name. Git resolves `refs/heads/story/ST-1~1` to the parent of the branch tip, and `story/ST-1^` or `dev@{3}` work the same way. The check of DEC-76 compares only that resolved commit with `HEAD`, so any commit other than the tip passes. DEC-74 and DEC-76 speak of a branch name, so the behavior is wrong, not intended.

The same string also lets git guess the ref. Without a `refs/heads/main`, the value `main` resolves to a tag `refs/tags/refs/heads/main`, so a named branch that does not exist does not exit `2` when such a tag exists.

```text
the story commits a raised threshold, then a code change and integration_branch: "story/ST-1~1"
        ↓
integration_branch accepts the value, because it is a non-empty string
        ↓
GitRefSource builds refs/heads/story/ST-1~1, and git resolves it to the parent of HEAD
        ↓
the DEC-76 check passes, because that commit is not HEAD
        ↓
gate_values and exceptions read docs/testing.yaml and the register of the story's own commit
        ↓
the gate passes a function that the threshold of dev fails
```

The review checked this in a scratch repository with `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/st0450/repro.sh`. In it, `dev` has threshold 8, and the story raises the threshold to 100 in one commit and changes `src/a.py` in the next. The planted function scores 9:

```text
== integration_branch: <none>
FAIL src/a.py f 9.00
exit=1
== integration_branch: story/ST-1
crap-score: cannot measure: the key integration_branch in docs/factory-settings.yaml names the branch story/ST-1, whose tip is HEAD, the commit under judgement; a story cannot be its own trusted source
exit=2
== integration_branch: story/ST-1~1
crap-score: judged 1 functions, 0 failed and 0 accepted above the threshold 100; wrote /tmp/claude-1000/st0450-repro-2bmW/out/ST-1.json
PASS src/a.py f 9.00
exit=0
```

The scope check of `premerge-check` refuses the change to `docs/factory-settings.yaml` when the story's `touches` does not name the file (DEC-68). A story whose `touches` names it gets past both checks.

**Why this severity:** The reader exists to keep a story from judging itself by its own values (DEC-67, DEC-76), and this value makes the story its own trusted source with exit `0`, so the reader fails its job. The code exists only on `story/ST-0450`, so it is not in use.

**Fix:** In `crap-score`, the layer of the trusted gate source: refuse a value of `integration_branch` that `git check-ref-format refs/heads/<value>` rejects, with exit `2` that names the key, as for a value that is not a string. Resolve the tip with `git show-ref --verify --hash refs/heads/<value>`, so git guesses no tag or remote ref. Then pass the resolved commit, not the ref string, to `ls-tree` and `show` in `_holds`, `gate_values` and `exceptions`. With the commit, both methods also read the same commit when the branch moves during a run. Add rows to CG-14-IT-07 for `<story branch>~1` and for a tag `refs/tags/refs/heads/<named branch>` without the branch.
