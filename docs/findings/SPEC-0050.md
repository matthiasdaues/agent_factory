# The counter-ids feature file uses glossary terms in another sense and terms the glossary lacks

**What is wrong:** The glossary check found two terms used in another sense and three terms the glossary does not define.

1. **Producer.** The glossary defines it as "the one agent that declares a core or seam artifact as an output". The feature file defines "Factory producer" as "a skill, agent, convention, or playbook that tells its reader how to number a new indexed artifact" and then says "producer" alone. The two definitions name different things.
2. **Claim.** The glossary defines it as a research claim. The feature file uses "claim" alone for an ID claim, in Rule names and in Scenarios. The term candidate "ID Claim" separates the two, but the feature file never uses it.
3. **factory maintainer**, the actor in the When steps of CID-07, CID-08, and CID-09, is not in the glossary.
4. **the human**, in "the human names the story branch of ST-1001", is not in the glossary. The glossary has User and Stakeholder.
5. **caller**, in four Rule names, is not in the glossary. The gaps report defines it as "the User or a CLI-Invoked Agent".

This finding does not block. The blocking glossary gate stays deferred.

**Fix:** Settle one term for each concept with the stakeholder, together with SPEC-0044 and SPEC-0049. For example, call the file a "numbering rule" or keep "Factory Producer" and add it to the Avoid column of **Producer**. Use "ID claim" where the feature file means an ID claim. Add **Caller** and **Factory Maintainer** as term candidates, or replace them with User. Replace "the human" with User.

**Resolution (pass 2, 2026-11-05):** The feature file says "ID producer" and "ID claim". It no longer uses "factory maintainer", "the human", or "caller". SPEC-0057 covers the same words in the structure files and the glossary.
