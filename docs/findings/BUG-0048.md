# A failed update would leave unrecorded wiring behind and block every later update

**What is wrong:** When the sourced `init-factory` fails during an update,
`_rollback_update` restores `.agent-factory/factory/`, `install.json`,
`checksums.json`, and the instruction headers. It leaves every other file
that `init-factory` wrote before it failed: generated agents in
`.codex/agents/` and `.github/agents/`, links in the tool directories,
`.gitignore`, `.pre-commit-config.yaml`, and `.agent-factory/config/`. The
restored `install.json` does not list the new generated agents. The next
update finds a Codex agent with the factory marker that the record does not
know, and stops with "foreign Codex agent collision". The Copilot check
stops the same way on a generated Copilot agent ("unmanifested Copilot agent
ownership marker"). Every later update stops until someone deletes each file
by hand.

No failed update has caused this yet. On 2026-10-15 the source repository
showed the same symptom for a different reason: an installed `update-factory`
from before commit `3f7b0df9bc5acac2aeac5007983212b6a0e34fb5` wrote the
install record from before `init-factory` ran, so the record lost the lector
agents that `init-factory` had generated. Three update runs were needed, each
after deleting the unrecorded files by hand. A rollback that leaves wiring
behind ends in the same state.

**Fix:** Before `update-factory` applies anything, take a snapshot of every
path that `init-factory` or the header step can write outside
`.agent-factory/factory/`. On a failure, restore the snapshot: remove paths
the run created, rewrite paths it changed, and recreate paths it deleted.
Add a test whose `init-factory` stub writes a generated agent and a
`.gitignore` line and then fails, and which expects both gone after the
rollback.

**Resolution:** Fixed in commits `3053fc7571d4260257e9ecdc8c092ebdfba093a5`,
`5cfff52500564d1e2518c6b80fe2f72351ef9cc6`,
`b2df2a16a73f357161df5967ccfbd370c5f89ef4`, and
`4a64c78db8e022618d437083bbec4ca65441cd5a`, merged into `dev` as
`8e77dc33b5cc6e3bbafd0568cc2aaa217426e506`. A review found that the first
fix, a snapshot of whole tool directories, reverted and deleted files the
developer owns there. The rollback now restores the files `init-factory`
writes by name. In the tool directories, it removes a new path only when the
path carries the generated-file marker or links into the installed factory.
Each path is restored on its own, and the paths that fail are listed. An
unreadable wiring file stops the update before any change. The full suite
passed after the merge.
