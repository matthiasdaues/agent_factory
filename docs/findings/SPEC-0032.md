# The term candidate lifecycle keeps a rejected row terminal against the accepted answer to CAO-G09

**What is wrong:** The stakeholder accepted the recommendation of CAO-G09 on 2026-11-03: a rejected row returns to `proposed` with a new definition, and the stakeholder sees it in the next session. The [Term Candidate Lifecycle](../spec/state-machines.md#term-candidate-lifecycle) still has `State: REJECTED  # terminal until the stakeholder decides gap CAO-G09` and no outbound transition. BR-065 says only that a rejected row "stays with the stakeholder's note". No Scenario of CAO-05 covers a second proposal. The domain-modeling agent's workflow story would encode a dead end, and a rejected term such as Slot could never enter the glossary.

**Fix:** Add `On DomainModelingProposesDefinition: ChangeState(PROPOSED)` to `State: REJECTED` in the pseudocode and derive the Mermaid edge. Add the transition to BR-065. Add a Scenario to CAO-05 in which the domain-modeling agent proposes a new definition of Slot from the note and the row returns to `proposed`. Update the CAO-G09 entry in the gaps report.

**Resolution:** The Term Candidate Lifecycle has `REJECTED → PROPOSED` on `DomainModelingProposesDefinition` in pseudocode and Mermaid, and the row keeps the note. BR-065, the Note column, and the new `Scenario: A rejected term returns to proposed with a new definition` follow, and `statemachine-lint` passes.
