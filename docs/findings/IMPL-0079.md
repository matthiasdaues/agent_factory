# A tag named `dev` makes `crap-score` read the register from the story branch

**What is wrong:** A row that exists only on a story branch can accept a function of that story. The gate then exits 0, and the merge sees a passing gate for code that no person accepted on `dev`. This happens when a tag named `dev` points at a commit of the story branch. Any agent in the story's worktree can create that tag with one `git tag dev`, and no hook refuses the command. The problem starts in `read_register`. Its probe checks `refs/heads/dev`, but the two reads that follow pass the short name `dev` to `git ls-tree` and `git show`. Git resolves a short name to `refs/tags/dev` before `refs/heads/dev`, and it writes the warning `refname 'dev' is ambiguous` only to standard error, which `git()` drops. BR-132 says that a row on a story branch has no effect until a person commits it on `dev` (DEC-25), so the behavior looks unintended.

The review checked it. A scratch test with the `repo` fixture of `tests/factory/test_crap_gate_score.py` committed the register only on the story branch, kept the branch `dev` without the file, and ran `git tag dev HEAD`. `crap-score` printed this and exited 0:

```text
ACCEPTED packages/factory/scripts/finding-lint tree_severity 9.00: Each branch handles one finding class
```

```text
an agent on story/ST-0440 commits a register row and runs git tag dev
        ↓
the probe finds refs/heads/dev and goes on
        ↓
git show dev:docs/findings/exceptions.md resolves dev to refs/tags/dev
        ↓
parse_register reads the row of the story branch
        ↓
the function gets accepted and crap-score exits 0
```

**Why this severity:** `crap-score` exists only on the feature branch, so `in_use` is false. Reading the register from the branch `dev` and from nowhere else is the duty that BR-132 and DEC-25 give this code, and one unguarded command in the story's own worktree breaks it (yes to fails_purpose).

**Fix:** In `packages/factory/scripts/crap-score`, pass the full name `refs/heads/dev` to `git ls-tree` and to `git show`, for example through a constant `REGISTER_REF = f"refs/heads/{REGISTER_BRANCH}"`. The review checked that `git show refs/heads/dev:<path>` ignores a tag `dev`. Keep the short name `dev` in the messages. Add a case to CG-05-IT-01 in `tests/factory/test_crap_gate_score.py`: commit the row on the story branch, run `git tag dev HEAD`, and assert exit 1 and `pass_fail` `fail`.
