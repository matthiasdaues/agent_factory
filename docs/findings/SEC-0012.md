# Without a local `dev`, the merge judges a story by its own settings

**What is wrong:** When the default `dev` is missing, `crap-score --base <feature-branch>` judges the story with the threshold and patterns of the story head and reads no register. That is the story's own setting. It happens in a clone that holds only `refs/remotes/origin/dev`. It also happens after a story agent runs `git update-ref -d refs/heads/dev`, which the git guard passes ([SEC-0010](register/security/SEC-0010.json)). Take `ST-0350`, which raises its threshold from 8 to 10 and changes `tree_severity`, which scores 9. After the deletion, the merge passes it with exit 0. The output names the fallback in a notice, and `premerge-check` does not refuse on it.

The problem starts in `GitRefSource.gate_values` and `GitRefSource.exceptions`. When the ref of the default `dev` is missing, both fall back to the folder for every call. DEC-13 and DEC-69 keep this fallback so that the first setup and a repository without the branch keep working. The first row of the CG-14 outline "Without gate settings on the integration branch the settings come from the folder" asks for it with `--base`, and the row "only origin/dev" of CG-14-IT-06 asserts it. So the code follows the specification. On 2026-11-23 the stakeholder decided that the merge path must not fall back, because every feature branch is cut from `dev`.

```text
the clone holds no refs/heads/dev, or a story agent ran git update-ref -d refs/heads/dev
        ↓
premerge-check runs crap-score --base feature/login in its worktree at the story head
        ↓
GitRefSource finds no tip for the default dev, so gate_values takes the folder values
        ↓
crap-score judges with the threshold 10 of the story head and exits 0
```

The review ran `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/qa/probe-move-refs.sh`. It sets up an orchestrated run: the primary checkout holds `dev`, and the story has a linked worktree. The script deletes `dev` from the story worktree:

```text
== git update-ref -d refs/heads/dev from the story worktree
exit 0
crap-score: judged 1 functions, 0 failed and 0 accepted above the threshold 10; ...
crap-score: took the threshold and the files and exclude patterns of every measure from docs/testing.yaml of the folder, because no branch dev exists
crap-score: read no exceptions register, because no branch dev exists
PASS packages/factory/scripts/finding-lint tree_severity 9.00
crap-score exit 0
```

`probe-delete-dev.sh` in the same folder shows the same result with `refs/remotes/origin/dev` present and the local `dev` deleted.

**Why this severity:** A story above the threshold passes `crap-score` at the merge, which is a gate bypass, so the bar starts at High. The attack needs the agent's shell in the repository or a clone without a local `dev` (`trusted_access`), which lowers it to Medium, and Medium gives `major`. The fallback lines of the reader exist only on `feature/crap-gate-trusted-source`, so they are not in use.

**Fix:** In `crap-score`, the layer of the trusted gate source: with `--base`, a missing default `dev` exits 2 and names the branch `dev`, as a missing named branch does (DEC-76). The fallback to the folder stays only for `--all` and `--settings-from-folder`. `open_source` knows whether `base` is set and can pass that to `GitRefSource`. With `--base`, no register notice "read no exceptions register" can occur, because the call exits 2 first. In the specification, change DEC-13 and DEC-69 in `docs/proposals/crap-gate-setup.md`. Move the first row of the CG-14 outline "Without gate settings on the integration branch the settings come from the folder" to an `--all` call, and add a `--base` row with no `dev` to the outline "Broken gate settings on the integration branch cannot measure". In `tests/factory/test_crap_gate_trusted_source.py`, the rows "no branch dev" and "only origin/dev" of CG-14-IT-06 become cases of CG-14-IT-07 with exit 2, and one `--all` case keeps the fallback.
