# --orphans deletes a project file named dispatch-ledger.yaml in every worktree under .current-work/

**What is wrong:** `dispatch close --orphans` deletes any file named `dispatch-ledger.yaml` in the checked-out files of a worktree under `.current-work/`, also in a worktree of a live run. It makes no stash, so an uncommitted change to that file is lost. The deletion starts in `_find_ledgers` (`dispatch:2980-2994`). The walk of `.current-work/` of the primary checkout descends into every worktree folder below it and reads the whole checkout, not only the `.current-work/` folder of that worktree. A tracked fixture or example file with that name, whose feature branch does not exist and whose stories are all `done`, then counts as an orphaned ledger, and `cmd_close_orphans` unlinks it. BR-120 and the Analysis speak of run ledgers below `.current-work/`, so the behavior looks unintended.

```text
the project tracks tests/fixtures/dispatch-ledger.yaml, which names feature/example
        ↓
every worktree under .current-work/ checks out that file
        ↓
_find_ledgers walks into each worktree checkout and finds it
        ↓
feature/example does not exist and the stories are done, so the verdict is "remove"
        ↓
the file and its uncommitted edit are gone from the worktree of the live run
```

The review checked this in a scratch repository. The repository tracked `tests/fixtures/dispatch-ledger.yaml`. A live run on `feature/x` had its ledger in `.current-work/feature/x/` and its feature worktree in `.current-work/feature/x/invocation`, where the review appended a line to the fixture. `--orphans` printed `removed ledger: .../invocation/tests/fixtures/dispatch-ledger.yaml` and exited `0`. `git status` of the feature worktree showed ` D tests/fixtures/dispatch-ledger.yaml`, and the appended line was gone. This repository tracks no such file today. The factory ships `dispatch`, and its tests write ledgers, so a fixture of that name is a plausible future file in this project.

**Why this severity:** The lines exist only on the story branch, so `in_use` is false. `--orphans` deletes a file of a live run's worktree without a stash, and its job is to remove only what no active run owns (yes to fails_purpose).

**Fix:** In `_find_ledgers`, drop from `subfolders` every folder that is a registered worktree. Each worktree already has its own `.current-work/` in the roots, so the walk then reads only `.current-work/` folders. Add a test to `tests/factory/test_run_lifecycle_close.py` with a tracked `dispatch-ledger.yaml` outside `.current-work/` and a change to it in a linked worktree. The test checks that the file and the change stay.

**Resolution (pass 2):** Commit `dbd46b695490b3766154157f29c84f52dfce2b34` on `story/ST-0426` skips each registered worktree in the walk, which then reads only `.current-work/` folders. `_removal_refusal` also keeps a ledger that git tracks in the worktree that holds it. `test_RL_15_IT_03_orphans_keeps_a_project_file_named_like_a_ledger` and `test_RL_15_IT_03_orphans_keeps_a_ledger_that_git_tracks` cover both. The review reran the probe against `dbd46b69`: the tracked fixture stayed, and `git status` showed it as ` M` with the appended line. The skip opens a new path for a run folder that is itself a worktree, which IMPL-0053 records.
