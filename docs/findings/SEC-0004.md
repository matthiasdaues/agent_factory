# Pi agent names can escape the agent directory

**What is wrong:** `run_agent` and `dispatch_wave` interpolate the
model-supplied agent name into `.agent-factory/factory/agents/${agent}.md`, normalize it
through `join`, and accept the result when `existsSync` succeeds. Neither
extension validates the identifier or proves that the canonical target remains
inside the canonical agent directory. An agent name containing `../` can
therefore select another Markdown file in the workspace; a symlink inside the
agent directory can select a file outside it. The selected content is read and
installed as the child session's system persona, exposing unintended file
content to the model and allowing an attacker-controlled workspace file to
replace Factory policy. This is path traversal and broken access control
(OWASP A01).

**Why this severity:** `run_agent` and `dispatch_wave` join a model-supplied agent name into a path and load the file as the system prompt of the child, so `../` in the name reads another Markdown file of the workspace. The path is traced from the parameter to `readFileSync` and the lines are on `dev`. Text that the agent reads can steer the name, and `init-factory` installs the Pi extension by default, so no precondition lowers the High level.

**Fix:** Resolve agent names through one shared loader. Accept only canonical
Factory agent identifiers present in the generated local index, reject path
separators and traversal components, resolve symlinks, and require the
canonical file to remain below the canonical agent directory. Apply the same
loader to `run_agent` and `dispatch_wave`. Add installed-path regression tests
covering relative traversal, absolute paths, encoded or platform-specific
separators, symlink escape, unknown identifiers, and a valid indexed agent.
