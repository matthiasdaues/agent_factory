# A remote that refuses the fetch has no case in the claim lifecycle or the error table

**What is wrong:** The interface contract says that a credential helper in the clone's own `.git/config` does not reach the claim. So a clone that pushes to `origin` without trouble can fail to fetch `refs/ids/counters`, for example on a private GitHub repository. The remote answers, but it refuses the fetch. The state `READING` knows only `CounterRead`, `CounterMissing`, and `RemoteUnreachable`. The claim error table has no row for a refused fetch. So it is open whether the message names the remote and git's message, and whether the case counts as "remote unreachable".

**Fix:** Add a `FetchRefused` event from `READING` to `FAILED`, or define `RemoteUnreachable` as "any fetch that fails". Name the message in the claim and seed error tables: the remote and git's error message. Add a Scenario if the stakeholder wants the case tested.
