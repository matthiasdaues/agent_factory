# The OpenCode plugin needs the plugin API of v2.2.7, but the accepted minimum version is 1.18.31

**What is wrong:** The accepted proposal `docs/proposals/opencode-cli-integration.md` supports OpenCode CLI `1.18.31` and later. The scenario "Installer accepts a supported OpenCode version" of `docs/spec/features/opencode-cli-integration.feature`, item 3 near line 352 of `docs/spec/validation-rules.md`, and the version check row of `docs/spec/interface-contracts.md` say the same. Since ST-0428, `setup` in `packages/factory/config/plugins/agent-factory.ts` registers its hook through `ctx.tool.hook("execute.before", hook)`, the plugin API of OpenCode v2.2.7. An OpenCode older than v2.2.7 has no `ctx.tool.hook`, so the plugin loads no guard. On such a version, `block-dangerous-git.sh` and `guard-human-fields` check no call. `init-factory` also runs no `opencode --version` check yet, so nothing stops the installation on an old version.

**Why this severity:** The plugin with this API exists only on `feature/run-lifecycle`, so `in_use` is false. On a version that the specification calls supported, the guards do not run, so the answer to `fails_purpose` is yes.

**Fix:** The stakeholder decides between two ways first. One way raises the minimum version to the first OpenCode release with `ctx.tool.hook`. Then the requirements agent changes the proposal and the feature file, the domain-modeling agent changes the validation rule and the contract, and `init-factory` checks the new minimum. The other way keeps `1.18.31`, and the plugin then also registers its guards through the plugin API of that version. Either way, a test checks that the minimum version loads both guards.
