# A generated index can fail the commit hook after formatting

**What is wrong:** A contributor can regenerate an index and still have the next commit rejected. `handbook-index` writes description whitespace verbatim. The repository runs `mdformat` before `handbook-lint`, so the formatter can change the generated text before the lint compares it byte for byte. This contradicts the documented regenerate-and-commit workflow.

In a scratch handbook, use `description: A sentence with   spaces.` on an implemented page. Run the index generator, then apply the repository's `mdformat` with its four plugins. The generated entry loses the extra spaces, and `handbook-index --check` exits 1. Running the generator again restores the extra spaces.

**Why this severity:** BR-144 defines the generated entry, and BR-146 makes the generated bytes the lint baseline. Under BR-148, the hook rejects a valid page after formatting. The reviewed feature is on the feature branch.

**Fix:** Give the generated region one formatting owner. Keep the formatter from changing it, or generate text that the repository formatter leaves unchanged. Check a valid noncanonical description with both hooks in their repository order.
