# Lint reports a missing root index when the file contains invalid UTF-8

**What is wrong:**

A contributor who runs lint on an existing root index with invalid UTF-8 gets an incorrect instruction about the root layout. The layout check treats `Folder.has_index` as evidence that the index file exists. That property is true only after the reader loads and decodes the file. The new condition suppresses the missing-index diagnostic only for failures at or above the root.

In a scratch checkout with both handbook roots, write the single byte `0xff` to `docs/handbook/index.md` and run `handbook-lint`. Both `28811a06` and `9aac3f87` report the UTF-8 error and exit 1. Only `9aac3f87` also prints `docs/handbook/: handbook root has no index.md`.

**Why this severity:**

BR-141 requires a missing-index diagnostic when the root lacks an index. The lint contract requires one report per failure. This change adds a report for a layout failure that did not occur. The defect is on the story branch.

**Fix:**

In the root layout check, treat a reader failure for the exact root index path as evidence that the reader found the entry. Keep the missing-index diagnostic when the only failure is on a different page. Add a lint test that expects the UTF-8 diagnostic alone for the existing index.
