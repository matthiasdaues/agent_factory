# The Python template drops every function under a decorator named overload

**What is wrong:** The gate never judges a real function whose decorator is named `overload`, when the decorator comes from a library other than `typing`. A library such as `multimethod` or `overloading` uses `@overload` on functions that run. The template writes no row for such a function, so `crap-score` passes the story while the function scores far above the threshold. The information is lost in the template, where the fix of BUG-0133 puts the bare name `overload` into `OVERLOAD_DECORATORS`, whatever module the file imports it from. `overload_names` adds aliases only for `typing` and `typing_extensions`, and the header says that only an `overload` of those two modules marks a stub. So the behavior looks unintended.

```text
src/multi.py imports `from overloading import overload` and decorates `area`, complexity 4, with it
-> overload_names starts from OVERLOAD_DECORATORS, which holds the bare name overload
-> row_name returns None for area, and the template writes no row
-> crap-score judges no function of src/multi.py and exits 0
-> at 0 % coverage area scores 20.00 and should fail against the threshold 8
```

Reproduction: the scratch repository of BUG-0133 at `2ea722b9`, with a local package `overloading` whose `overload` returns the function, and `src/multi.py` as above, without a test.

```text
$ crap-score --all
...
crap-score: judged 9 functions, 1 failed and 0 accepted above the threshold 8
```

No output line names `src/multi.py`. Expected: `FAIL src/multi.py area 20.00`.

**Why this severity:** The template exists only on the feature branch (`in_use: false`). A consumer reads the rows as the list of the measured functions and draws a false pass for a function that the rows leave out (`fails_purpose`).

**Fix:** In the template, take the bare name `overload` out of `OVERLOAD_DECORATORS`. In `overload_names`, add the bare name, or its alias, only for `from typing import overload` and `from typing_extensions import overload`, and add `overload` for `from typing import *`. Add a test to `tests/factory/test_crap_gate_template.py` with an `overload` from a local module that the template must measure.
