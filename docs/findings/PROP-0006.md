# Write guard always-allows .current-work/ contradicting ledger isolation principle

**What is wrong:** The Core Principles state "The LLM never runs branch, worktree, merge, or ledger commands directly during a dispatch." Phase 1 Completion Criteria require "The ledger is never written by the LLM directly." However, Phase 2's write guard declares `.current-work/` as an always-allowed write prefix. The dispatch ledger lives at `.current-work/dispatch-ledger.yaml` and the step manifest at `.current-work/current-step.yml`. The always-allowed write prefix creates an enforcement hole that directly contradicts the ledger isolation invariant: any step agent can write to the ledger, the step manifest, or the premerge-check marker through `Edit`/`Write` tool calls and the guard will permit it.

**Fix:** Narrow the `.current-work/` always-allowed write set to specific safe paths (e.g., `.current-work/verify-base-ok`, `.current-work/premerge-check-ok`). Explicitly deny writes to `dispatch-ledger.yaml` and `current-step.yml` in the write guard. Alternatively, add a deny-list that takes precedence over the always-allowed prefix for script-owned state files.
