# `crap-score --all` exits `2` on the integration branch that `integration_branch` names

**What is wrong:** Setup step 6 cannot run in a project that sets `integration_branch`. The test-strategy agent runs `crap-score --all` from the root of the project. When the checkout is on the integration branch, such as `main` with `integration_branch: main`, `crap-score` exits `2` with "names the branch main, whose tip is HEAD, the commit under judgement; a story cannot be its own trusted source". The skill then sends the User back to step 4, and no step of the skill can fix the cause. The same project without the key, on `dev`, gets exit `1` and the report. So only the projects that need the key are hit, and the key exists for them.

The problem starts in `GitRefSource.__init__`. It runs the check of DEC-76 for every named branch, whatever the call. DEC-76 exists to stop a story from naming its own branch on the merge path. With `--base`, the key comes from the base revision (DEC-77), and `HEAD` is the story head, so the check is right there. With `--all`, nothing is merged, and the tip of the checked-out integration branch is `HEAD` in the normal case. The specification states the check for every call, so the code follows the text, and the text did not foresee `--all`. The Example row `in the folder of crap-score | has integration_branch: main | --all | main` of CG-14 expects the gate to read `main`. It has no integration test, which is the known gap that QA holds.

```text
the project sets integration_branch: main, and the primary checkout is on main
        ↓
setup step 6 runs crap-score --all from the root of the project
        ↓
open_source reads the key from the folder (DEC-77) and builds GitRefSource with named=True
        ↓
GitRefSource.__init__ finds tip == HEAD and raises GateError (DEC-76)
        ↓
crap-score exits 2, writes no report, and step 6 cannot count the failing functions or take the run time
```

The review checked this in a scratch repository with `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/feature-review/setup-step6.sh`. The script commits `docs/factory-settings.yaml` on `main`, writes the uncommitted entry of setup step 4 and a stub measuring command, and runs `crap-score --all --story-id setup`:

```text
$ setup-step6.sh packages/factory/scripts/crap-score key
crap-score: cannot measure: the key integration_branch in docs/factory-settings.yaml names the branch main, whose tip is HEAD, the commit under judgement; a story cannot be its own trusted source
exit=2
$ setup-step6.sh packages/factory/scripts/crap-score nokey
crap-score: judged 1 functions, 1 failed and 0 accepted above the threshold 8; wrote .current-work/crap-score/setup.json
crap-score: took the threshold and the files and exclude patterns of every measure from docs/testing.yaml of the folder, because no branch dev exists
crap-score: read no exceptions register, because no branch dev exists
FAIL src/a.py f 12.00
exit=1
```

**Why this severity:** Setup step 6 exists to measure the whole project and report the run time, and for every project that sets `integration_branch` it gets exit `2` on the integration branch, so the setup fails its job. The code exists only on `feature/crap-gate-trusted-source`, so it is not in use.

**Fix:** In `crap-score`, the layer of the trusted gate source: run the `HEAD` check of DEC-76 only when the call has `--base`. `open_source` knows whether `base` is set and can pass that to `GitRefSource`. Keep the check of a missing named branch for every call. In the specification, limit the `HEAD` sentence of DEC-76 to calls with `--base` in BR-128, § Trusted gate source, and § `docs/factory-settings.yaml`. Add an integration test for the `--all` row of CG-14 that runs on the checked-out branch `main`.
