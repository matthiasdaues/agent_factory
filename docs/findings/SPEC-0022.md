# Parent-conflict preflight has contradictory fixture coverage

**What is wrong:** The accepted proposal now defines `USAGE_ANCESTRY_PARENT_CONFLICT` in addition to the five rooted-tree ancestry codes, but completion criterion 04 still requires fixture coverage for “all five malformed-ancestry preflight codes.” The proposal's operational-preflight gate proof also lists only the five rooted-tree cases and omits snapshots of one logical run that disagree on `parent_run_id`. The feature and QA strategy assign that conflict to LU-05, so the design origin and its executable owner no longer agree on whether the new failure mode must have deterministic fixture coverage.

**Fix:** Require deterministic fixture coverage for `USAGE_ANCESTRY_PARENT_CONFLICT` in the proposal's operational-preflight gate and change completion criterion 04 to distinguish the one parent-conflict code plus the five rooted-tree ancestry codes, or to require all six exact codes.

**Resolution (verified in the fifth and final review on 2026-09-13 against `1a7a27d833b4037c4a2612fa1eb97465c90835c4`):** The proposal's operational-preflight proof requires a conflicting-parent fixture plus missing-parent, cross-boundary-parent, self-parent, cycle, and root-count fixtures to produce all six exact `USAGE_ANCESTRY_*` diagnostics. Completion criterion 04 independently requires the accounting fixture matrix to cover all six malformed-ancestry preflight codes.
