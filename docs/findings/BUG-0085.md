# `dispatch` cannot find the test command in an installed project

**What is wrong:** `dispatch init` and `merge-story` read `test_command`
from `config/project.json`. Installed projects have no such file:
`init-factory` records the test command in `docs/testing.yaml`, and
`.agent-factory/config/project.json` holds only the project identity. So
`dispatch init` stops with "config/project.json must contain a
'test_command' key", and no automated dispatch can start. This came up
while fixing BUG-0082.

**Fix:** Read `test_command`, or else `test_all`, from `docs/testing.yaml`.
Keep `config/project.json` as a fallback for older projects. Add a test
that runs `dispatch init` in a project that has only `docs/testing.yaml`.

**Resolution:** Fixed in commits `cd404785de67991123e8cf4d9306fb1c99599707`, `cdc891ac1e42cc5439c1a7437a550d312fce0a7f`, and `236991662e3bd5e7d5d4a29d1ab5af15698bb0cc`, merged into `dev` as `36ef31f20b0af5f52a796800637e7dc9c4d88128`. `dispatch` reads `test_command`, or else `test_all`, from `docs/testing.yaml`, and falls back to `config/project.json`. Because `dispatch` runs without PyYAML, the stdlib YAML loader in `dispatch_lib.py` learned quoted values, trailing comments, flow lists, and block scalars. A test compares it with PyYAML on the skill's schema example and on generated cases. If the loader still fails, `dispatch` reads the two top-level keys alone and warns. Known gap: whitespace-only lines before the first content line of a block scalar can read differently from PyYAML. The full suite passed after the merge.
