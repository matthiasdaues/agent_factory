# `StateMachine` model omits per-state `outputs` globs

**What is wrong:** The proposal describes `StateMachine` as holding "states, transitions, gate conditions, and halt conditions." But `transition-lint`'s core logic depends on per-state `outputs:` globs to map staged files to their owning state (`state_outputs()` and `states_for_file()`). The `assess_staged_paths` service function must use this data to evaluate ordering violations. Without `outputs` as a named field of `StateMachine`, the model cannot support the `check_staged` operation.

The current `parse_fsm` output already contains `outputs` under each state's dictionary. The model definition should make this explicit rather than leaving it implicit in the parsed structure.

**Fix:** Add `outputs` (per-state file-ownership globs) to the `StateMachine` model description in Design section 3, alongside states, transitions, gate conditions, and halt conditions.
