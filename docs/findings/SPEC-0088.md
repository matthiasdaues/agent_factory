# premerge-check runs dependency-check also in a project without dependency rules

**What is wrong:** The proposal says in [Fast gates as pre-commit hooks](../proposals/run-lifecycle.md#fast-gates-as-pre-commit-hooks): "`premerge-check` makes the same check before it runs the gate at the merge." The same check is the test for `docs/spec/dependency-rules.dsl`, so the merge skips `dependency-check` when the rules file is missing. The spec drops this. The Scenario "The gate list of a story" lists `dependency-check` without any condition. BR-066 in `validation-rules.md` line 485 makes `dependency-check` a gate of every unit of work and states the skip only for the hook. The `premerge-check` contract states no skip either. Called without the rules file, `dependency-check` exits `2`, as the RL-10 Scenario "The script called directly still exits 2 without a rules file" requires.

Today `premerge-check` reads stored gate results, so the missing file did no harm. After this feature it reruns every gate on the branch head. A project without `docs/spec/dependency-rules.dsl`, such as a migrated project that core-artifact-ownership.feature allows, then fails every story merge on `dependency-check`.

**Why this severity:** No story or code encodes the run lifecycle spec yet, so it is not in use. An implementer who follows the Scenario and BR-066 builds a `premerge-check` that refuses every merge in a project without dependency rules, which is a wrong result (fails_purpose).

**Fix:** Add a Scenario to the Rule "Implementation agent merges a unit of work only when premerge-check passes at its branch head": without `docs/spec/dependency-rules.dsl`, `premerge-check` skips `dependency-check`, names the skip, and still passes the other checks. Make "The gate list of a story" state that the rules file exists. Then the domain-modeling agent adds the condition to BR-066 and to the Gates pass row of the `premerge-check` contract, and the gate-check step follows the same rule.
