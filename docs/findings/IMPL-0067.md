# A method of a nested class gets no row and no non-zero exit, so a story can change it unscored

**What is wrong:** A story that changes a method of a nested class, such as `Parser.Options.strict`, passes the gate without a score for that method. The template writes no row for the method and still exits `0`. The lines of the method lie in no row, because the template drops the class blocks, so `crap-score` cannot count the method as changed (BR-131). BR-130 asks for one row per function. The template's own header says that the command exits non-zero when it cannot measure a case. This silent gap breaks both statements.

The problem starts in `function_blocks`. `cc_visit` returns the methods of a top-level class as blocks of their own, and the methods of a nested class only inside `Class.inner_classes`. The filter `not hasattr(block, "methods")` drops every class block, so it also drops the nested classes and their methods. Row 3 of `docs/spec/work/spec-feedback-ST-0435.md` says that radon lists no method of a nested class. That is not correct: radon lists them under `inner_classes`. The radon name of such a method is `Options.strict`, not the qualified name `Parser.Options.strict` that DEC-12 asks for. The gap is documented in the spec-feedback report, but the reason given for it is wrong, and no decision is open.

The review checked this with the template in a scratch project. `src/parser.py` held `Parser.parse` and the nested class `Options` with the method `strict` and one `if`. The template exited `0` and wrote rows for `Parser.parse` and the test function only. A direct call of `cc_visit` on a second source, with the method `b` of the class `Inner` nested in `Outer`, returned the class block `Outer` with `inner_classes=[Class(name='Inner', ..., methods=[Function(name='b', ..., classname='Inner', ...)], ...)]`.

**Why this severity:** The template exists only on `story/ST-0435`, so `in_use` is false. A function that BR-130 requires a row for goes unmeasured, and the gate passes it without a score (yes to fails_purpose).

**Fix:** In `function_blocks`, walk `inner_classes` of each class block recursively and give each method the qualified name from the chain of class names, such as `Parser.Options.strict`. `measure` then writes that name instead of `block.fullname`. Add a test to `tests/factory/test_crap_gate_template.py` with the nested class `Parser.Options` and its method `strict`, which checks one row named `Parser.Options.strict`. Delete row 3 of `spec-feedback-ST-0435.md`, because the template can then meet BR-130 as written.
