# BR-066 picks test-design-verify from a story field that cannot name it

**What is wrong:** BR-066 says that the implementation agent picks `crap-score`, `test-design-verify`, and mutation testing from the story's `quality-gates` field first. The field is a closed enum of `crap-score`, `mutation-analysis`, and `dependency-check` ([interface-contracts.md § Optional fields](../spec/interface-contracts.md#optional-fields)). So a story can never name `test-design-verify`. The [`gates` section schema](../spec/interface-contracts.md#docstestingyaml--gates-section-schema) says instead that `test-design-verify` runs whenever the story has test-design output. Take a story with `quality-gates: [crap-score]` and a Test Design section. Under BR-066 `test-design-verify` does not run. Under the schema it runs. The outline in CAO-11 only shows stories without a Test Design section, so it does not settle the case. The mutation gate also has three names: `mutation-analysis` in the enum, `mutation-testing` in the glossary term Test Guardrail, and "mutation testing" in BR-066. The enum still lists `dependency-check`, and `backlog-lint` asks for a note when a story omits it, although BR-066 now runs it after every story. CAO-11-CT-01 cannot be written until the case is decided.

**Fix:** State in BR-066 that `test-design-verify` is not picked: it runs whenever the story has a Test Design or Prior Tests section, as the schema says. Then the field picks only `crap-score` and the mutation gate. Pick one name for the mutation gate and use it in the enum, the glossary, and BR-066. Remove `dependency-check` from the `quality-gates` enum, or state that the field ignores it. Add an outline row with `quality-gates: [crap-score]` and a Test Design section.

**Resolution:** BR-066, the `quality-gates` enum, the term Test Guardrail, the CAO-11 outline, and CAO-11-CT-01 follow the stakeholder decision recorded as gap CAO-G25.
