# Pi dispatch executes caller-side persona and model configuration

**What is wrong:** `dispatch_wave` creates each item from its declared base in
an isolated worktree, but reads the agent persona and resolves its model from
the caller's checkout. When the caller and item base contain different Factory
agent definitions or `model.conf` values, the child executes code from the
item worktree under policy and model selection from another revision. The
reported branch is therefore not a reproducible account of what governed the
agent, and the promised per-worktree isolation is incomplete.

**Fix:** After creating the worktree, load and validate the persona from that
worktree and resolve the model against that worktree's configuration. Use the
same worktree-scoped agent loader as `run_agent`, including the containment
controls required by SEC-0004. Add an end-to-end regression with deliberately
different caller and item-base personas and model tiers; assert that the
spawned child receives only the item worktree's values.
