# An empty mutants list passes a mutation command that failed for another reason

**What is wrong:** BR-066 passes the mutation gate after a non-zero exit when the command ran within the time limit, the result file holds a list `mutants`, no entry is `unresolved`, and every `file-qa-finding` entry names an existing finding. The Gates pass row of `premerge-check` and the gate result table say the same. No condition ties the non-zero exit to a survivor.

Take ST-0350 with a mutation command that stops with exit `1` on a broken configuration, before it mutates a line. The native report is empty. The gate-check step writes one entry per mutant, as BR-066 asks, so it writes `mutants: []`. The list exists, and no entry is `unresolved`. So `premerge-check` passes the mutation gate, and ST-0350 merges without any mutation result. A list that holds only `killed` entries passes the same way. RL-G25 lets a story merge once every surviving mutant is resolved. It does not let a failed run count as a run without survivors.

**Why this severity:** No story or code encodes the run lifecycle spec yet, so it is not in use. A `premerge-check` built as BR-066 reads passes a mutation gate whose command failed, which is a wrong result (fails_purpose). The rule is short and reads clearly, so the reader needs no second reading (no to raises_cost).

**Fix:** After a non-zero exit, let the gate pass only when the list `mutants` holds at least one entry with `status: survived`, and every such entry is resolved as BR-066 defines. An empty list, or a list without a survivor, fails like a missing list. Change BR-066, the Gates pass row of `premerge-check`, and the Passes when cell of the gate result table. The test-strategy agent then adds the case to the contract test RL-12-CT-03.

**Fix applied (2026-11-18, domain-modeling agent):** After a non-zero exit, BR-066 lets the mutation gate pass only when the list `mutants` holds at least one entry with `status: survived`, besides the other conditions. The Gates pass row of `premerge-check` and the Passes when cell of the gate result table in [interface-contracts.md](../spec/interface-contracts.md) say the same. The test-strategy agent adds the case to the contract test RL-12-CT-03. The status stays `open` until the repeat pass of the spec review checks the fix.

The core-artifact-ownership Scenario "The implementation agent runs the project's mutation command as a gate" now requires at least one survivor in `mutants`. The status stays `open` until the repeat pass of the spec review checks the fix.
