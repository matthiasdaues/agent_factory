# The QA agent writes no bug-hunt report, so the feature merge cannot find one

**What is wrong:** The accepted proposal `docs/proposals/run-lifecycle.md` makes `premerge-check dev <feature-branch>` refuse while the bug-hunt report of the QA agent is missing. BR-122, the Scenario Outline "A feature-level report names its run" and the feature merge in `docs/spec/interface-contracts.md` count that report. The `bug-hunt` skill files findings and fixes them, but it names no report file. The `outputs:` of `packages/factory/agents/qa-agent.md` declare `docs/reviews/fagan-review-*.md` and `docs/reviews/security-review-*.md`, but no bug-hunt report. `report-format.md` gives the report "the name the skill gives", and the skill gives none.

**Why this severity:** No code reads the report yet, because ST-0424 builds the feature merge check and is `pending`, so `in_use` is false. A QA agent that follows the skill as written writes no bug-hunt report. ST-0424 then refuses every feature merge, or has no name to look for, so the answer to `fails_purpose` is yes.

**Fix:** Give the `bug-hunt` skill a report step that writes `docs/reviews/bug-hunt-YYYY-MM-DD.md` per `report-format.md`, with `run` and `branch_head` set as BR-122 says. Add the path pattern `docs/reviews/bug-hunt-*.md` to the `outputs:` of `qa-agent.md`. ST-0424 then checks that name at the feature merge.

**Resolution (code review of ST-0424):** Commit `8b78b5c01db700b89ba0054ed3f70e7d2319fd17` on `story/ST-0424` gives `packages/factory/skills/bug-hunt/SKILL.md` the section "Phase: Report". It writes `docs/reviews/bug-hunt-YYYY-MM-DD.md` per `report-format.md`, also after a hunt that found no bug, and in the feature checks it sets `run` to the feature branch and `branch_head` to the full SHA of the head it hunted. The `outputs:` of `packages/factory/agents/qa-agent.md` declare `docs/reviews/bug-hunt-*.md`, and step 4 of the QA workflow names the report. `check_feature_reports` in `premerge-check` looks for the prefix `bug-hunt-`. `test_RL_04_LN_04_the_bug_hunt_skill_writes_its_report` checks the skill text and the output declaration. The review ran `premerge-check dev feature/x` in a scratch repository: without the bug-hunt report it printed `BLOCK feature-reports: the bug-hunt report is missing`, and with `docs/reviews/bug-hunt-2026-11-19.md` it printed `PASS feature-reports`.
