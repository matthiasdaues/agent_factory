# One-escalation-per-wave has no disposition for second failure

**What is wrong:** Core Principles state "one escalation per story, one escalation per wave." The `dispatch escalate` predicate requires "no other story in the wave has escalated." If two stories in the same wave independently fail with `acceptance_unmet` or `contradictory_evidence`, only the first one to call `dispatch escalate` succeeds. The proposal does not specify what happens to the second story. It cannot escalate (blocked by the per-wave rule). It cannot re-dispatch at the same tier (it already failed there). It cannot be marked `done` (acceptance is unmet). The story is stuck in a state the proposal's lifecycle does not cover.

**Fix:** Specify the disposition for the blocked-from-escalation case. Options: (a) the second story is marked `blocked` with reason "wave escalation budget exhausted" and deferred to the next wave where it gets its own escalation slot, (b) the per-wave limit is raised or removed (making the per-story limit the only constraint), or (c) the second story is marked `failed` as terminal and requires human intervention. Whichever option is chosen, add it to the failure-class disposition table and the Completion Criteria.
