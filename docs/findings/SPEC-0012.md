# .feature @ references use pre-rename paths

**What is wrong:** The .feature file's Rule comments reference the current (pre-implementation) skill and script paths instead of the post-rename paths declared in the proposal. Specifically:

- Lines 48, 71: `@factory/skills/capture-charter/SKILL.md` should be `@factory/skills/capture-context/SKILL.md`
- Line 110: `@factory/skills/update-charter/SKILL.md` should be `@factory/skills/update-context/SKILL.md`
- Lines 184, 276: `@factory/scripts/charter-lint` should be `@factory/scripts/context-lint`

The specification describes the post-implementation system. These @ references serve as traceability markers that the reconciliation-agent uses to verify scenarios resolve to implementing code. If the markers point to pre-rename paths, reconciliation will report false broken references because the old paths will no longer exist after implementation.

**Fix:** Update all six @ references in the .feature file to use the post-rename paths: `capture-context`, `update-context`, and `context-lint`.
