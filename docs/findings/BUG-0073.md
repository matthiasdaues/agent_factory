# `build-release` deletes an existing output directory

**What is wrong:** On every failure path, the script deletes the output directory, even one that existed before the run. With `--output ../precious`, an existing `important.txt` was gone and the script printed nothing. `--output .` would delete the working tree. The archive is also built from the working tree, so untracked `__pycache__` files and uncommitted changes end up in a "reproducible" release. Source: [bug-hunt report § I-1](../reviews/bug-hunt-2026-10-15.md#i-1--build-release-deletes-an-existing-output-directory).

**Fix:** Delete only files this run created, and print the reason for the failure. Build the archive from `git archive` or `git ls-files`.

**Resolution:** Fixed in commits `db61709072a480b3305d40641ac30927273a41a2`, `c14a81e05654dd5b6bb161605243e5318f7c7c1c`, `cb35edcc64d54922941a4227d873624a043957cd`, `4d87021e2c5aacf245c6a34fa0cc2a618d42c6a3`, merged into `dev` as `3921e522cc31f7fd454d9c908c9e8e42ceb201fe`. The full suite passed after the merge. Known gap: a rename that fails after an earlier rename leaves mixed output.
