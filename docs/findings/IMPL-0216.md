# The freshness row omits the warning for an install with no recorded tree hash

**What is wrong:** A reader can see an update warning even when the install manifest contains no tree hash. The reference row introduced by this fix describes only a mismatch with a hash recorded at install. With a committed `packages/factory/` tree and a valid manifest, both checks also warn when `factory_tree_hash` is missing, null, or empty. In a scratch Git repository, both checks printed the update command with a manifest of `{}` and again with `{"factory_tree_hash":null}`.

**Why this severity:** IMPL-0200 requires the row to explain when the check prompts the user to update. The new condition omits a case that both checks handle. The documentation change is on the story branch.

**Fix:** Say that the check warns when the install manifest has no recorded tree hash or the committed tree differs from the recorded hash. Keep the sentence about projects without `packages/factory/` and the link to the update how-to.
