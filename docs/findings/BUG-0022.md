# Five gate-opt-out stories lack the `notes` justification backlog-lint requires

**What is wrong:** `backlog-lint` (extended by this branch's work to enforce
the quality-gates contract) reports `BL-NOTES` errors for a story whose
`quality-gates` field omits a default gate but whose `notes` field does not
justify the exclusion. At branch head
`ff123986ad44494fd96f6a508a74a6294f496040` this failed with 15 errors across
five stories that all declare `quality-gates: []` with no `notes`:
`ST-0106`, `ST-0107`, `ST-0109`, `ST-0110`, `ST-0111`. The backlog gate
(`factory/scripts/backlog-lint --backlog-dir backlog`) was therefore red on
the branch head, and the pre-commit `backlog-lint` hook would reject any
commit that stages one of these files.

**Fix:** Added a single-line `notes:` justification to each of the five
stories (the story template documents this pattern:
`factory/rulebooks/templates/story.md` — "required justification when
quality-gates omits [a default gate]"). The justifications match each
story's actual nature: ST-0106 builds gate infrastructure (its output is
covered by `tests/test_module_graph_check.py` and `validate`); ST-0107,
ST-0109, ST-0110, ST-0111 change agent/playbook documentation only, so the
default semantic gates (crap-score, mutation-analysis, dependency-check)
have no code to measure. After the fix, backlog-lint reports 0 errors
(5 pre-existing warnings remain, all `BL-DUP`/`VR-028` and out of scope).

Note: `notes` must be a single-line value. The hand-rolled frontmatter
parser in `backlog-lint` (deliberately dependency-free) does not support
YAML block scalars, so a `notes: >-` block is silently dropped; real YAML
consumers (e.g. `premerge-check` via PyYAML) would read the block correctly,
making the two parsers disagree. The single-line form is the
cross-compatible syntax.
