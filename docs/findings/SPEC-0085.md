# The area spec rejects the --feature-branch value that run-lifecycle.feature creates

**What is wrong:** The area spec Scenario "Non-existent feature branch is rejected" says that `dispatch init --feature-branch feature/missing` exits non-zero when no branch `feature/missing` exists. The Rule "User starts a run on a feature branch in either way of driving it" in `run-lifecycle.feature` says the opposite. Its first Scenario starts from "no ledger exists for feature/login", runs `dispatch init --mode by-hand --base dev --feature-branch feature/login`, and expects "the branch feature/login exists and points at the tip of dev". Every other RL-01 Scenario passes `--feature-branch feature/login` the same way. The proposal also says that `init` cuts the feature branch from `dev`. The code at `packages/factory/scripts/dispatch:627-662` creates a missing branch, so the area spec Scenario matches neither the proposal nor the code. The area spec also leaves open whether an orchestrated run on an existing branch gets a worktree for it, because "Existing feature branch is adopted without creating a new one" names no worktree.

**Why this severity:** No story or code encodes the run lifecycle spec yet, so it is not in use. The two Scenarios contradict each other, and the implementer of `init` cannot satisfy both RL-01-IT-01 and the area spec Scenario without asking which one wins (fails_purpose). A reader must also compare the area spec, the feature file and the code to find the conflict (raises_cost).

**Fix:** Replace the area spec Scenario "Non-existent feature branch is rejected" with one that matches RL-01: `init` creates a missing `--feature-branch` from the tip of the base, with a worktree in an orchestrated run and without one by hand. State in "Existing feature branch is adopted without creating a new one" whether an orchestrated run creates a worktree for the adopted branch.

**Fix applied (2026-11-18, requirements agent):** The area spec Scenario Outline "A missing feature branch is created from the tip of the base" replaces "Non-existent feature branch is rejected". `init` cuts `feature/missing` from the tip of the base, with a worktree in an orchestrated run and without one by hand. "Existing feature branch is adopted without creating a new one" now runs with `--mode orchestrated` and creates a worktree for the adopted branch. A comment says that `init` by hand adopts the branch without a worktree. The status stays `open` until the repeat pass of the spec review checks the fix.

**Verified (2026-11-18, spec review pass 2):** The fix holds. The area spec Scenario Outline "A missing feature branch is created from the tip of the base" agrees with the RL-01 Scenarios and with the code. "Existing feature branch is adopted without creating a new one" now runs with `--mode orchestrated` and creates a worktree. The status is now `resolved`.
