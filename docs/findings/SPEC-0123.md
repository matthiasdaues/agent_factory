# Three accepted feature files still state the default gate and the default threshold

**What is wrong:** `test-design.feature` lines 294 and 374 make the dispatcher pass the threshold to `crap-score` and let the script fall back to "the hardcoded default of 30". The Outline at line 546 of `core-artifact-ownership.feature` is titled "then from the default", and its last row runs `crap-score` when `docs/testing.yaml` has no `gates` section. BR-128, BR-066 and DEC-20 forbid both defaults. The gaps report lists only run-lifecycle Scenarios as changing, so no story changes these.

**Why this severity:** An agent that checks the rewritten `crap-score` and `premerge-check` against these Scenarios reports correct code as a defect, and a planner cuts no story to change them (fails_purpose). The reader must also compare four feature files to find the target state (raises_cost). No story or code outside the run encodes the new statements.

**Fix:** Add the Scenarios to the list of Scenarios that change in `docs/spec/work/crap-gate-setup-gaps.md`, and rewrite them to the target state (DEC-40).

Review report: [spec-review-2026-11-21.md](../reviews/spec-review-2026-11-21.md).

## Pass 2 (2026-11-21)

Still open. The rewrite of DEC-40 fixed the Scenarios at `test-design.feature` lines 294 and 374 and the Outline at `core-artifact-ownership.feature` line 546. Two statements of the same kind remain:

- `test-design.feature` lines 268 to 281 require `gates.crap_score` with `enabled: true` and a threshold, and a charter template with a `crap_score` entry. The template `packages/factory/rulebooks/templates/charter-testing.yaml` ships `crap_score: enabled: true, threshold: 8` without `timeout_minutes` and `measures`. Under BR-128 such an entry makes `crap-score` exit 2, so a project that copies the template blocks every story. Neither the proposal's boundaries nor the spec name the template.
- `core-artifact-ownership.feature` line 503 sets only `gates.crap_score.threshold` to 30 and expects a failing score, while BR-128 makes that entry exit 2.

Fix: rewrite both Scenarios to the target state. Add the charter template to the change, so that its `gates` section holds no enabled `crap-score` entry and points to `setup-crap-score`.

## Pass 3 (2026-11-21)

Resolved. `test-design.feature` now requires a template without a CRAP gate entry and an entry with threshold, `timeout_minutes`, and `measures` after the setup (DEC-41). `core-artifact-ownership.feature` line 503 gives the entry all three values. The proposal's boundaries name the template, and the QA strategy plans the template change and its test.
