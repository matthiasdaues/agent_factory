# 96 broken local link paths have accumulated because link-check only ever sees changed files

**What is wrong:** A repository-wide run of `factory/scripts/link-check` over
every tracked Markdown file reports **96 broken path links**. These predate
[BUG-0015](BUG-0015.md) and are unrelated to it: the path check has always
worked. They accumulated because the pre-commit hook passes only the files
changed in a commit, so a link breaks the moment its *target* moves and nothing
re-checks the *source* until that source happens to be edited again.

The largest identified cluster is 20 links in
`factory/rulebooks/templates/research-*.md` pointing at
`../../schemas/<name>.schema.json`; the schemas live at
`factory/rulebooks/schemas/`, one directory level away from where the links
look.

A second cluster of 13 is a repeated relative-path error in
`factory/skills/*/SKILL.md`, where links read
`../../factory/rulebooks/conventions/<name>.md`. From `factory/skills/<skill>/`
the prefix `../../` already reaches the repository root's `factory/`, so the
path resolves to `factory/factory/rulebooks/...`. The correct form is
`../../rulebooks/conventions/<name>.md`.

**Fix:** Two parts, neither attempted here.

1. Correct the 96 paths. The two clusters above are mechanical and account for
   33 of them; the remaining 63 need individual judgment about the intended
   target.
2. Close the detection gap that let them accumulate. A changed-files-only gate
   cannot catch a link broken by moving its target. Add a repository-wide
   `link-check` run to the validation surface — either in
   [validate](../../factory/skills/validate/SKILL.md) or as a scheduled full
   scan — so a break is found when it happens rather than when the source file
   is next touched.

Until part 1 lands, any commit that touches one of the affected files fails the
hook for reasons unrelated to that commit's change.
