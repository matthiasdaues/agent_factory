# BUG-0017 — Empty Outputs List

**Date:** 2026-08-26\
**Severity:** Low\
**Category:** Edge case\
**Status:** Not a defect — working as designed

______________________________________________________________________

## Summary

If a story declares `outputs: []`, `premerge-check` receives an empty list of globs. The current implementation returns `True` for scope violation, blocking the merge.

## Evidence

```python
# factory/scripts/dispatch_lib.py:_story_scope_violation
def _story_scope_violation(
    project_root: Path, story_id: str, commit_sha: str | None
) -> bool:
    if not commit_sha:
        return True
    outputs = _story_output_globs(project_root, story_id)
    if not outputs:  # Empty outputs list
        return True  # Block merge
    ...
```

## Expected Behavior

**Option A (Current):** Block merge if no outputs declared — prevents scope violations by default.
**Option B (Alternative):** Skip validation if no outputs declared — assumes all files are in scope.

## Recommendation

**Current behavior is acceptable.** The design choice to block stories with no outputs declared is defensive — it prevents accidental scope violations. Add a test case to document this behavior.

**Action Required:** Add `test_scope_violation_empty_outputs()` to `tests/test_dispatch_merge_integration.py`.
