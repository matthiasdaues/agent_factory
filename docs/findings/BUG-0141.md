# A pytest that a test starts stops on the piled-up `--basetemp` of the template

**What is wrong:** The template `crap-measure-python` from ST-0451 has a `sitecustomize.py` that adds `--basetemp=<work>/pytest/<pid>` and `-p no:cacheprovider` to `PYTEST_ADDOPTS` in every Python process. It appends to the value it inherits, so the options pile up. A pytest that a test starts receives the `--basetemp` of every process above it. pytest checks each `--basetemp` it gets, and one of them is the temp folder of the outer xdist worker, which lies above the nested pytest's working folder. pytest then stops with exit 4: `argument --basetemp: basetemp must not be empty, the current working directory or any parent directory of it (config source: via PYTEST_ADDOPTS)`.

**How it shows:** In ST-0449, the Python proof of this repository selects `tests/factory/test_crap_gate_proof.py::test_cg_02_the_proof_passes_the_real_python_template`. That test runs a pytest inside pytest. It fails under the measure and passes alone, so the measure exits non-zero, and the checks Repeatable, Catches CRAP and Sees the folder fail. The tests of ST-0451 start pytest only one level deep, so they did not catch it.

**Fix:** the `sitecustomize.py` replaces an inherited `--basetemp` and `-p no:cacheprovider` instead of appending another, so each process passes exactly one of each. A test starts pytest two levels deep under the template and asserts that the innermost run passes and keeps its own `tmp_path`.

**Why this severity:** The defect makes the Python measure fail on this repository, so the gate cannot be set up (`fails_purpose`), and every story whose selection holds such a test would end blocked (`raises_cost`). The template is not on `dev` yet, so it is not in use.
