# Generated links break when a page or chapter name contains a hash

**What is wrong:** A contributor following the generated link to `changes#2.md` reaches a reference to `changes` with fragment `2.md`. The shared link formatter leaves the hash unescaped. In scratch, generation wrote `- [Example](changes#2.md)` and lint accepted the result. Chapter links use the same formatter.

**Why this severity:** BR-144 and BR-145 require each link to point to the listed file. The formatter was introduced on the story branch.

**Fix:** Percent-encode hash characters in path components. Check the generated targets for a page filename and chapter folder containing a hash.
