# SEC-0006 — Logging Sensitive Data

**Date:** 2026-08-26  
**Severity:** Low  
**Category:** A01:2021 – Broken Access Control  
**Status:** Acceptable risk — not a defect

---

## Summary

Error messages in `dispatch` and `step-guard` may include file paths and story IDs in stderr output. If stderr is logged to a shared system, this could leak sensitive path information.

## Evidence

```bash
# Example error messages from dispatch
error: story ST-0123 is already at strong tier
error: wave escalation slot already taken for wave 2
error: story not found: ST-0123
```

## Impact

Minimal risk in typical development environments. The paths and story IDs are not sensitive — they are internal project metadata. The risk would only be elevated in a multi-tenant CI/CD environment where logs are shared across projects.

## Mitigation

1. **Low priority:** Add environment-based log level control (e.g., `DISPATCH_LOG_PATHS=0` to redact paths).
2. **Acceptable:** Keep as-is — the risk is minimal for local development.

**Recommendation:** No action required for typical usage. Consider the mitigation if deploying in a multi-tenant environment.

---

## Specification Alignment

The spec does not address logging. The current behavior is acceptable for a CLI tool.
