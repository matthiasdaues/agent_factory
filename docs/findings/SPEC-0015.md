# Restored feature specifies the superseded agent-context model

**What is wrong:** The reviewed feature specifies four YAML files, `context-lint`, primary/index modes, and writes through `update-context`. The implemented [Concern-Oriented Agent Context proposal](../proposals/factory-concern-oriented-agent-context.md) supersedes that model with one directly maintained `docs/agent-context.md`, `concern-lint`, and `docs/testing.yaml`. The current [concern-lint interface contract](../spec/supplementary_specs/interface-contracts.md#factoryscriptsconcern-lint) already reflects the replacement, while the scope map marks the restored YAML Rules as live `specified` behavior.

**Fix:** Retire the restored file again, or rewrite it to specify only the implemented concern-oriented behavior. Remove or replace its ten legacy scope-map rows and remove the obsolete YAML, `context-lint`, and `update-context` sections from the live supplementary specifications so one current contract remains.

**Repeat review (2026-09-13):** The feature and its scope-map rows now describe the concern-oriented model, but the live specification still requires `docs/charter/testing.yaml` in the PRD, test-design and test-gate feature files, scope map, entity model, interface contracts, and validation rules. Those requirements conflict with the new feature's single `docs/testing.yaml` path and its rule that `docs/charter/` is legacy residue. The finding remains open until the live specification has one test-configuration contract.

**Second repeat review (2026-09-13):** The test-configuration references now consistently use `docs/testing.yaml`, but the live [`charter-lint` interface contract](../spec/supplementary_specs/interface-contracts.md#factoryscriptscharter-lint) still requires `docs/charter/{tech-stack,development,house-rules}.md`. That requirement conflicts with the concern-oriented feature and `CTX-LEGACY`, which require `docs/charter/` to be absent beside `docs/agent-context.md`. The finding remains open until the live specification retires or reconciles the charter contract.

**Resolution (verified in the final repeat review on 2026-09-13 against `476d0b4770f3695a3d98b485bc3c4b58cf102269`):** The obsolete live `charter-lint` interface contract is absent. The feature, scope map, PRD, test-design contracts, entity model, interface contracts, and validation rules consistently use `docs/agent-context.md` for concern routing and `docs/testing.yaml` for machine-consumed test configuration; none requires a live `docs/charter/` path.
