# Page metadata can add a second marker to a generated index

**What is wrong:** A contributor can generate an index that both scripts reject on the next run. The renderer copies marker text from page metadata into the generated list. In scratch, the description `Write <!-- handbook-index:start --> first.` produced a second start marker. Generation exited 0 and the next check reported two markers.

**Why this severity:** BR-143 requires exactly one marker of each kind in every index. The renderer was introduced on the story branch.

**Fix:** Encode marker literals in generated link labels and descriptions. Check that generation succeeds and a second run recognizes exactly one marker pair.
