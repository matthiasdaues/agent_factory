# The DONE list waits on every report, but the backfeed dispatches only rows of the new report

**What is wrong:** BR-067 says that "after a reconciliation run" the orchestrator dispatches the owner of each `open` row. The rule ties this dispatch to the report that the run just wrote. The same rule says the playbook is done only when no row of *any* reconciliation report is `open`, or `fixed` on a core artifact. The two scopes differ in two cases, and the spec does not decide either one:

1. A row from an earlier report is still `open`, or a session stopped after the owner set `fixed` and before the reviewer ran. No step dispatches its owner or reviewer, so the DONE list never passes.
2. CAO-15 says the next run "checks each fixed row" of the previous report. The spec does not say whether the new report repeats that row. If it does, one drift has rows in two reports, and each row needs its own fix and review.

A story would build a DONE check that can stay open for good, or a backfeed that handles the same drift twice.

**Fix:** Make the dispatch scope match the DONE scope. One way: the backfeed step reads every reconciliation report, dispatches the owner of each `open` row, and dispatches the reviewer of each `fixed` row on a core artifact. Then the step can resume after a stopped session. State which report holds a row that a later run checks again. Add a Scenario for a `fixed` row left by an earlier report.
