# Run ancestry does not determine roots and descendants

**What is wrong:** Claude Code and Pi totals require a root plus distinct children or descendants, while Codex and Copilot totals require an inclusive root and treat descendants as attribution-only. The specification says only that `parent_run_id` defines ancestry. It does not define how a root is identified or require one root per `(cli, session_id)`, and it does not classify missing parents, cross-session or cross-CLI parents, self-parenting, cycles, or multiple roots. Records can therefore pass the declared contract while conforming implementations select different roots or descendant sets and produce different canonical totals.

**Fix:** Define root and descendant identity and add ancestry invariants for every session. Specify whether malformed ancestry fails preflight or canonical accounting, including stable failure codes for missing parents, cross-boundary parents, self-links, cycles, and multiple roots. Add fixture cases to LU-03 or the preflight owner without duplicating ownership, and update the feature, entity model, interface and validation contracts, QA boundary cases, and gaps report.
