# link-check validated no anchors at all, while documenting that it validated same-document ones

**What is wrong:** `factory/scripts/link-check` parsed each local link with
`urlsplit` and then tested only `target.exists()`. It never read
`parsed.fragment`. A cross-document anchor passed whenever the file existed,
whatever the fragment said. A same-document anchor passed unconditionally:
with an empty `parsed.path` the target resolved to the source file itself,
which exists by definition.

The script's own docstring claimed it "catches broken repository paths and
missing same-document anchors". The second half was false, and the existing
test named `test_accepts_existing_relative_path_and_anchor` asserted only that
a *valid* anchor passes — which it would have done with no anchor logic at all.

The consequence reaches past the script.
[rules.md § Cross-references](../../factory/rulebooks/rules.md#cross-references)
carries a MUST: "anchor every cross-reference to the specific section where the
target has one." That rule had no mechanical enforcement, while a gate in the
pre-commit chain reported "all local links resolve" and read as though it
provided one. A repository-wide scan found **22 broken anchors** across 14
files, concentrated in two systematic patterns:

- **Em-dash headings.** `## Step 3 — Write the review report` slugs to
  `step-3--write-the-review-report` with a doubled hyphen, because the em dash
  is dropped and its two surrounding spaces each become a hyphen. Sixteen links
  used a single hyphen. Every review rulebook pointing at a skill's "Step N"
  section was broken.
- **Silently renumbered sections.**
  [state-machine-notation.md](../../factory/rulebooks/conventions/state-machine-notation.md)
  pointed at "Step 2.2 — Document State Machines" in the brownfield playbook,
  which has been Step 3.7 for some time. Nothing detected the drift.

**Fix:** Applied in this change.

1. `link-check` now extracts every heading from a Markdown target, slugifies it
   the way GitHub does, and rejects a fragment that matches no heading. Errors
   are reported as `broken anchor` to distinguish them from `broken link`.
2. Heading extraction skips fenced code blocks, so a heading shown inside a
   ```` ```markdown ```` example is not treated as a real anchor.
3. Link extraction skips fenced blocks *and* inline code spans, so an
   illustrative link such as the one in
   [cross-reference-format.md](../../factory/rulebooks/conventions/cross-reference-format.md)
   is not checked. Anchor extraction deliberately does **not** strip inline
   code: a heading like `` ### `run_agent` Envelope Error `` keeps `run_agent`
   in its slug, and stripping it first produced wrong slugs during development
   of this fix.
4. Underscores are preserved. They are word characters in a GitHub slug, and an
   earlier draft that stripped them as emphasis markers produced five false
   positives.
5. All 22 broken anchors were corrected, and three link texts that had drifted
   from their target's section title were corrected with them.
6. Ten tests were added to `orchestrator/tests/test_link_check.py` covering
   broken and valid anchors in both directions, em-dash slugs, inline code in
   headings, duplicate-heading suffixes, fenced and inline-code exclusion, and
   fragments on non-Markdown targets.

Author and fixer are the same session; no independent verification pass has
run against this finding.

**Related:** the same scan exposed 96 broken *paths* that predate this change
and remain unfixed — see [BUG-0016](BUG-0016.md).
