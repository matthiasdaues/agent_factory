# Nine `status: done` stories fail `VR-027` after commit 8245d14 deleted their sole declared output

**What is wrong:** `factory/scripts/backlog-lint --backlog-dir backlog` reports
9 `VR-027` errors at the current `feature/agent-context` branch head (base
`9da186491f87d9227648d70b3caf555c08503e15`, itself a descendant of
`8245d14`): `ST-0041`, `ST-0050`, `ST-0052`, `ST-0053`, `ST-0054`, `ST-0070`,
`ST-0071`, `ST-0122`, `ST-0139`. Each declares `status: done` with an
`outputs:` list consisting solely of one or more test files under
`tests/orchestrator/` or `tests/factory/`. Commit `8245d14` ("refactor: tear
down stale test suite, rebuild with contract tests") deleted all 83 files of
the prior test suite, including every file these 9 stories name as their
sole output, and did not update the affected stories' frontmatter. The
`backlog-lint` pre-commit hook has `files: ^backlog/ST-.*\.md$` and
`pass_filenames: false`, so it scans the whole `backlog/` directory on any
commit that touches a single story file — meaning this pre-existing failure
now blocks every story commit on this branch that updates a story's
`status:` field, not just commits touching the 9 affected stories.

Two of the nine (`ST-0122`, `ST-0139`) are dispatch-lifecycle tests and two
more areas (research-agent tests for `ST-0050`) have no successor coverage
anywhere in the rebuilt suite — `8245d14`'s replacement suite covers only
`usage-capture`, `verify-base`, and `premerge-check`. There is no 1:1
successor file to point `outputs:` at for most of the nine; this is not a
simple path-rename.

**Fix:** This needs a decision the backlog schema does not currently
support, not a one-line correction: `VALID_STATUSES` in
`factory/scripts/backlog-lint` (`{pending, in-progress, review, blocked, done}`) has no value for "this story's output was later legitimately
removed by an unrelated, accepted refactor." Two directions, either of
which is a dedicated follow-up story, not a drive-by fix from an unrelated
story's commit:

1. Add a schema-supported way to mark a story's output superseded (e.g. a
   `superseded-by:` frontmatter field, or a new valid status) and apply it
   to these 9 stories with the correct rationale per story — most need the
   dispatch/research test coverage question answered first (was it
   deliberately dropped, or does it need rebuilding under the new
   contract-test approach `8245d14` established?).
2. Or accept the coverage loss as intentional (consistent with `8245d14`'s
   stated scope) and simply move these 9 stories out of `done` — but confirm
   with whoever authored `8245d14` first, since 2 of the 9 (dispatch
   idempotency/interruption/immutability, dispatch e2e) reference behavior
   with no test coverage anywhere in the repo after the deletion, which may
   itself be a separate, more serious gap worth its own finding.

Until one of these lands, any story commit that updates `status:` on any
backlog story will fail the `backlog-lint` pre-commit hook through no fault
of that story.
