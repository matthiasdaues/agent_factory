# newcomer-onboarding.feature still specifies docs/CONTEXT.md, against this feature

**What is wrong:** This feature replaces `docs/CONTEXT.md` with `docs/spec/glossary.md` and `docs/agent-context.md` (DEC-07, CAL-G01). Four Rules of `newcomer-onboarding.feature` keep the old behaviour, and the scope map marks all four `implemented`:

- `Rule: Brownfield onboarding exits after three anchor files` requires "docs/CONTEXT.md exists seeded with domain vocabulary" (line 103).
- `Scenario: Reverse-map seeds docs/CONTEXT.md with domain vocabulary` (lines 165-168).
- `Scenario: Feature-addition grows docs/CONTEXT.md with new domain terms` (lines 187-190).
- `Rule: Feature-addition prerequisite checks anchor file presence, not a gate marker` checks three files with `docs/CONTEXT.md` (lines 200-217).

The new Rule `Project maintainer starts feature work once the anchor files exist` and `validation-rules.md` now state four files, so the specification contradicts itself. `validation-rules.md` even cites `newcomer-onboarding.feature` as a source for the four-file rule. Gap CAL-G01 notices the conflict and closes it with "this pass does not own it", so no one owns it. This feature also has no scenario for where `reverse-map` seeds the vocabulary after the change. The grep criterion on `CONTEXT(-MAP)?\.md` forces `reverse-map` to stop writing `docs/CONTEXT.md`, but no Rule says what it writes instead.

**Fix:** Bring `newcomer-onboarding.feature` in line within this specification: the brownfield exit and the feature-addition prerequisite name the four anchor files, and `reverse-map` and feature-addition write terms to `docs/spec/glossary.md`. Alternatively, mark those Rules as superseded in the scope map and point them at this feature. Add one scenario to `Rule: CLI-invoked agent reads and writes the core at its new paths` that has `reverse-map` seed `docs/spec/glossary.md`. Reopen CAL-G01 until both are done.

**Resolution:** `newcomer-onboarding.feature` stays unchanged, because its four Rules describe today's behaviour. Gap CAL-G15 assigns their update, and the update of their scope-map rows, to the stories of this feature that change `brownfield-onboarding.md`, `feature-addition.md`, and `reverse-map`. CAL-G01 points at CAL-G15. The new `Scenario: reverse-map seeds the domain vocabulary into the glossary` states that `reverse-map` writes terms to `docs/spec/glossary.md` (DEC-07); CAL-12-LN-01 owns it. `validation-rules.md` no longer cites `newcomer-onboarding.feature` as a source of the four-file rule.
