# A line whose function records do not pair one to one keeps a never-run function covered

**What is wrong:** The CRAP gate can still pass a changed TypeScript function that no test calls. The story receives the wrong verdict. The loss starts in `deadFunctions`. When the number of lcov records on a line differs from the number of functions that start there, the function marks no function of that line as never run, unless every record of the line has the count 0. Every function of the line then keeps its line count. A function that no test calls gets that count whenever a function next to it ran. The fix of IMPL-0106 and IMPL-0110 creates such a line: a function that is the value of a key now starts on the line of the key, but node records it on the line where the function itself starts. The behavior looks unintended, because the header promises 0 % for a function that never ran.

```text
the object key `pick:` stands on line 1, its arrow function on line 2
        ↓
crap/range takes the Property as the outer node, so the row starts on line 1
        ↓
node records FN:2,pick with FNDA:0, so line 1 holds one record for two functions
        ↓
deadFunctions sees no one-to-one pairing and a non-zero record (used), so it marks nothing
        ↓
pick keeps the line count of 100 %, and crap-score passes it
```

The reproduction is `/tmp/claude-1000/-home-matthiasdaues-Documents-datenschoenheit-agent-factory/89fd1670-49e4-4a59-97db-e1035150aa04/scratchpad/st0449-review/repro_typescript.sh`. Call it with the path of the command and the case `split-property`. It reports `pick` with complexity 6 and `coverage_pct` 100. At 0 %, the function scores 6 × 6 + 6 = 42 and fails the threshold 30. The command at `c23aa019` stopped with exit 1 on the same file, so this wrong row is new.

**Why this severity:** The measure exists to give the gate the true coverage of each function. In this case it still gives too high a coverage, so the gate can pass a story wrongly, which DEC-84 rules out. The command exists only on `story/ST-0449`, so it is not in use.

**Fix:** The fix has two parts, both in `scripts/crap-measure-typescript`:

1. In the rule `crap/range`, also report the start line of the function node itself, and pair the lcov records by that line. The row keeps the range of the outer node.
2. In `deadFunctions`, give 0 % to every function of a line whose records do not pair one to one. DEC-84 allows a wrong failure but no wrong pass. Name that rule in the header.

Add the case `split-property` to `test_cg_13_a_function_that_no_test_calls_gets_zero_coverage`.
