# CC-4 "optionally deepens" is not testable

**What is wrong:** Completion Criterion 4 states a feature-addition run
"optionally deepens the DSL." There is no criterion to distinguish success from
failure on the deepening part — when should deepening occur and when should it
not? A planning agent cannot write an acceptance test for an optional outcome
with no trigger condition.

**Fix:** Rephrase CC-4 to state the mechanically verifiable outcome: "A
feature-addition run against a brownfield-lite baseline completes without error
and adds at least one Rule row to scope-map.md. If the feature changes the
structural shape, architecture.dsl is also updated."
