# An interrupted move leaves no ref to the claim commit, so recovery can hand out an ID twice

**What is wrong:** A claim commit has no parent and sits on the empty tree. The marker commit holds one line, `moved=<remote>` (BR-097). So once the move sets the marker in step 2 of ADR-0033, no ref in the main repository points to the claim commit `C`. Until the push in step 3 ends, only the throwaway bare repository holds `C`, and `next-id` deletes that repository at exit (BR-075). The main repository keeps no reflog for `refs/ids/counters`, so `git gc` later prunes `C` as well.

Take the project of section 6.16, with `ST=0012` on the Local Counter. A session in a second worktree claimed `ST-0012` and is still writing the story, so no commit holds it yet. VIRGIL runs `next-id --move-to-origin` in an agent shell. `origin` is new, and git waits for credentials that the shell cannot give. The shell kills the call after its timeout, between the marker and the push. Every claim now reads the marker and names `origin` as the holder, but `origin` holds no counter. Gap CIF-G05 leaves the recovery open. The only path the specification offers is a new seed. `--plan-seed` counts only IDs that a commit holds on a branch (BR-099, CIF-G10). So the new seed gives `ST=11`, and the next claim hands out `ST-0012` a second time. QS-22 requires that a move hands out no ID twice.

**Why this severity:** QS-22 has priority 1, so its importance is `high`. The exposure is `uncertain`: the analysis shows the path, but its likelihood rests on how often a move dies between two git calls, and nobody has checked that. High importance and uncertain exposure give `major`. No code is built from ADR-0033 yet, so `in_use` is false.

**Fix:** Keep `C` reachable from the marker. Make the marker commit a child of `C`, with `C` as its only parent, and state that in BR-097, in the marker contract of the `next-id` contract, and in step 2 of ADR-0033 and section 8.18. Then define in the Move Lifecycle that a move whose read finds a marker with parent `C`, while `origin` holds no counter, goes on to `PUSHING` with `C`. When `origin` already holds `C` itself, the earlier move finished, so the move keeps the marker, removes the setting, and never puts `C` back. Without that check, a second move from another worktree would revive the Local Counter next to the counter on `origin` (ATAM-0016). A second run of `next-id --move-to-origin` then finishes an interrupted move, and no recovery needs a new seed. Add an environment to QS-22, or a new scenario, for a move that stops between the marker and the push, with the measure that a second move ends with `C` on `origin`. This settles gap CIF-G05 within DEC-09, so the stakeholder only confirms it. Claims are unaffected, because a claim reads only the message of the marker.
