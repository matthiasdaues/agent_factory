# Pi run_agent fails on verbose child streams

**What is wrong:** `run_agent` executes Pi with `spawnSync` and captures stdout
and stderr in memory behind a 64 MiB `maxBuffer`. A valid child JSONL stream
larger than that fails with `ENOBUFS`, even when its final `message_end` is
usable. The synchronous execution also prevents progress updates, and usage
capture cannot receive the complete stream after the buffer failure.

**Fix:** Spawn Pi asynchronously, spool stdout to a protected staging file,
parse arbitrarily chunked JSONL incrementally, and retain only bounded parsing
and stderr-tail state plus the final result. Report bounded progress through
the tool update callback. On cancellation, terminate the child and clean the
staging file. Hand the completed file to best-effort usage capture without
assembling the full stream in memory, and do not retry an ambiguous invocation.
Add an installed-path regression that generates more than 64 MiB at runtime.

**Resolution:** `run_agent` now performs one asynchronous spawn, parses JSONL
incrementally across arbitrary chunks, caps individual event lines and the
stderr tail, and emits byte-count progress updates. It spools raw stdout
directly to protected capture staging and hands the file to the existing
detached capture lifecycle. Spawn errors, capture failures, and cancellation
clean bridge-owned staging; cancellation terminates the child and never
retries. Installed-path regressions cover a runtime-generated stream larger
than 64 MiB, seven-byte final-event chunks, bounded updates, complete raw
capture handoff, and cancellation cleanup.
