# Dispatch integration tests fail at branch head because story fixtures lack the `quality-gates` opt-out

**What is wrong:** At branch head
`ff123986ad44494fd96f6a508a74a6294f496040`, the acceptance suite
`pytest --tb=short -q` reports 9 failures out of 273 tests, all in the
dispatch merge/integration paths:

- `tests/test_dispatch_e2e.py::test_smoke_two_story_two_wave_dispatch_to_completion`
- `tests/test_dispatch_e2e.py::test_smoke_failure_escalation_and_redispatch_to_completion`
- `tests/test_dispatch_immutability_integration.py::test_merge_story_premerge_check_does_not_use_mutating_git_commands`
- `tests/test_dispatch_interruption_integration.py::test_merge_story_reuses_existing_merge_commit_after_interruption`
- `tests/test_dispatch_merge_integration.py::test_successful_merge_green_suite`
- `tests/test_dispatch_merge_integration.py::test_merge_conflict_aborts_marks_blocked`
- `tests/test_dispatch_merge_integration.py::test_red_suite_reverts_marks_blocked`
- `tests/test_dispatch_merge_integration.py::test_dry_run_reports_without_merging`
- `tests/test_dispatch_merge_integration.py::test_premerge_check_receives_scope_globs`

Root cause: `premerge-check` gained the fail-closed semantic-gate check in
`411747b` (ST-0105), which merged into this branch after the dispatch
integration tests were written against a 231-test green baseline (see
[wave5-dispatch.md](../handoffs/wave5-dispatch.md)). For a branch named
`story/ST-NNNN`, `get_quality_gates` in
[premerge-check](../../factory/scripts/premerge-check) resolves the
precedence chain (story field > `house-rules.md` > Factory default of all
three gates). The synthetic story fixtures in the four test files above
declare no `quality-gates` field and the tmp repos contain no
`.agent-factory/<gate>/<story-id>.json` results, so `check_semantic_gates`
reports every gate as "result not found" and blocks the merge. The full
suite was not re-run after the ST-0105 merge, so the regression was never
seen.

**Fix:** Add `quality-gates: []` (the documented story-level opt-out,
ST-0100; empty-list handling fixed in `fd8e79b`) to the story fixtures in
the four affected test files so they exercise dispatch merge mechanics
instead of the gate-precondition default:

1. `tests/test_dispatch_merge_integration.py` — the shared `_write_story_file` helper
2. `tests/test_dispatch_e2e.py` — the inline `ST-001.md` and `ST-002.md` fixtures
3. `tests/test_dispatch_immutability_integration.py` — the `ST-002.md` fixture of `test_merge_story_premerge_check_does_not_use_mutating_git_commands`
4. `tests/test_dispatch_interruption_integration.py` — the `ST-777.md` fixture of `test_merge_story_reuses_existing_merge_commit_after_interruption`

Gate enforcement itself stays fail-closed and is covered by
[orchestrator/tests/test_premerge_check.py](../../orchestrator/tests/test_premerge_check.py); no
change to `premerge-check` behaviour is needed. After the fixture change,
re-run `pytest --tb=short -q` and require 0 failures.

## Resolution

Applied the `quality-gates: []` opt-out to all four fixture locations.
Verification at head of this QA pass: `pytest --tb=short -q` → 273 passed,
0 failed.
