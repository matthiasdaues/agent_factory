# `arch-lint` checks nothing when chapter 5 has plain first columns

**What is wrong:** `ch5_core_components()` (`arch-lint`, around line 181) matches `r"\|\s*\*\*([^*]+)\*\*.*?\|"`, so it reads a component only when the first table column is bold, and it scans only from the literal heading `## 5.2`. An onboarding baseline wrote plain first columns (`| API routes |`) and extraction returned zero components. `ARCH-COUPLE` then compared an empty set with the DSL and reported success. After the column was bolded, extraction returned 19 components. The `scaffold-arc42` skill never states the requirement. A gate that passes while it checks nothing is worse than no gate, because it gives unearned confidence.

**Fix:** Document the table format in `scaffold-arc42`. Make "no components found in chapter 5" an error. Accept plain first columns as well. The stakeholder folded this into the fix iteration of story ST-0296.

**Resolution:** Fixed in commits `d97e5883b68d1056e47b6b8577856f66168e22c9`, `78c5a4b73c1b9ec699199c3bfe2980e6b82952ae`, `52dd2969d5cc0fa41e229d7fdf51010efdd41011`, merged into `dev` as `3921e522cc31f7fd454d9c908c9e8e42ceb201fe`. The full suite passed after the merge. A plain first column counts under a `Component` header. An empty chapter 5 is an error only when the DSL declares components. Known gaps: tables without outer pipes, all-dash body rows, components declared without a name.
