# Usage capture omits transcript-provided model attribution

**What is wrong:** usage records leave `model` null unless a capture caller
passes `--model`. Native root-session hooks do not supply that argument, even
though all four supported transcript formats expose the effective model:
Claude assistant messages carry `message.model`, Copilot emits
`session.model_change.data.newModel`, Codex turn contexts carry
`payload.model`, and Pi assistant messages carry `message.model`. This makes
otherwise attributable usage impossible to group reliably by model and
violates the tightened rule that script-derivable fields must be populated.

**Fix:** Extend the shared normalized-transcript result with the latest
non-empty native model identifier, populate it in every CLI normalizer, and
persist it when no explicit invocation model was supplied. Preserve explicit
context as the higher-precedence authoritative value. Add a registry-complete
contract test that fails if any supported CLI lacks a model-bearing fixture,
plus capture-boundary tests for derived attribution and explicit precedence.

**Resolution:** Every transcript normalizer now returns its latest native model
identifier, and capture persists that value unless explicit invocation context
overrides it. The contract fixture set must exactly equal `SUPPORTED_CLIS`, so
adding a CLI without model-attribution coverage fails deterministically.
Capture-boundary regressions prove derived persistence and explicit precedence.
The complete capture unit suite passes 76 tests; native installed-hook suites
pass 14 tests and the Pi installed-path suite passes 28 tests.
