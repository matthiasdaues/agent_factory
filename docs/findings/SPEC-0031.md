# The specification does not follow the accepted answer to CAO-G11 on BUG finding writers

**What is wrong:** The stakeholder accepted the recommendation of CAO-G11 on 2026-11-03. Every agent that runs a stakeholder review declares `docs/findings/BUG-*.md`: the requirements agent, the domain-modeling agent, the test-strategy agent, and Virgil. The outline `Each writer of a shared working-output file declares its path` (line 713) lists `BUG-*.md` only for the spec-review agent and the architecture-review agent. `Scenario: The requirements agent declares three core outputs and its working output` (line 151) names the requirements agent's other outputs as a closed list without `BUG-*.md`. `Scenario: The domain-modeling agent definition declares the domain structure family` (line 179) says "the outputs are" six files, which leaves out `term-candidates.md`, both report paths, and `BUG-*.md` that CAO-17 gives the same agent. So CAO-03-LN-01 and CAO-04-LN-01 would fail a correct definition, and CAO-17-LN-01 would pass an incomplete one. The gaps report still says that the specification lists only the two reviewers.

**Fix:** Add `docs/findings/BUG-*.md` rows for `requirements-agent`, `domain-modeling-agent`, `test-strategy-agent`, and `virgil` to the CAO-17 outline. Add `BUG-*.md` to the closed list at line 155. Change line 185 to "the core outputs are" and name the working outputs in a second step. Update the CAO-G11 entry in the gaps report.

**Resolution:** The CAO-17 outline has `docs/findings/BUG-*.md` rows for the requirements, domain-modeling, and test-strategy agents and Virgil. The output Scenarios of CAO-03 and CAO-04 say "its outputs include" and name `BUG-*.md`, and the gaps report records the answer to CAO-G11.
