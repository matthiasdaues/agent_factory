# A feature branch with ".." in the ledger lets close --drop delete the folder of another run

**What is wrong:** A ledger whose `feature_branch` holds `..` lets `dispatch close --drop` delete the folder of another run, with its briefs and scratch files. The guard is `_close_run_dir` (`dispatch:2709-2714`). It resolves `.current-work/<feature-branch>` and accepts every result inside `.current-work/` other than `.current-work/` itself. So `feature/../feature/other` resolves to `.current-work/feature/other` and passes. `--drop` checks no branch, so nothing else refuses the name. `_remove_run_dir` then deletes that folder when no registered worktree is left in it. The same resolve also follows a symlink: when `.current-work/<feature-branch>` is a symlink to the folder of another run, the close deletes the target folder. The review did not probe the symlink case. The guard exists to keep the close inside its run, so the gap looks unintended.

```text
ledger names feature_branch: feature/../feature/other
        ↓
_close_run_dir resolves it to .current-work/feature/other, inside .current-work/
        ↓
--drop runs no branch check
        ↓
_remove_run_dir finds no worktree there and runs shutil.rmtree
        ↓
the briefs of feature/other are gone
```

`dispatch init` writes a ledger only after git has created the branch, and git refuses `..` in a branch name. So this needs a ledger that a person or a tool edited by hand. The review checked it in a scratch repository with such a ledger and a file `.current-work/feature/other/briefs/ST-0901.md`. `dispatch close --drop` exited `0` and printed `closed the run on feature/../feature/other`. The file `ST-0901.md` was gone.

**Why this severity:** The lines exist only on the story branch, so `in_use` is false. The close deletes files of another run, which the contract of the close and the guard in `_close_run_dir` rule out (yes to fails_purpose). The path needs a ledger edited by hand. The brief of this review rates any path out of the run as at least `major`.

**Fix:** In `_close_run_dir`, refuse a feature branch that `git check-ref-format --branch` rejects, or whose parts hold `.` or `..`. Then compare the path without `resolve()` and refuse when `.current-work/<feature-branch>` or a folder on the way to it is a symlink. Add a test to `tests/factory/test_run_lifecycle_close.py` with a ledger that names `feature/../feature/other`. The test checks that `close --drop` exits `1` and that the folder of `feature/other` stays.

**Resolution (pass 2):** Commit `891bd93d7c96ca2dab3753b772a35c8e765d6977` on `story/ST-0425` makes `_close_run_dir` refuse a name unless `git check-ref-format --branch` prints it back unchanged. The function no longer resolves the path, and it refuses a symlink on each part of the way to the run folder. `test_RL_14_IT_01_close_refuses_a_feature_branch_that_git_rejects` covers `feature/../feature/other`, `feature/./other`, `feature//other`, and `@{-1}`. `test_RL_14_IT_01_close_refuses_a_symlinked_run_folder` covers a link `feature/link` to `feature/other`. Both tests check that the ledger and the brief of `feature/other` stay. The review reran the probe of pass 1 against `891bd93d`: `close --drop` exited `1` with `is not a valid branch name`, and `ST-0901.md` stayed.
