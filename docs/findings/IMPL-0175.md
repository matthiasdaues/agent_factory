# A literal link suffix makes the rewrite refuse the file

**What is wrong:** A contributor cannot migrate a file that uses a literal link suffix in prose. In `README.md`, the line `A literal suffix is ](docs/arc42/concepts.md).` raises `AmbiguousLink` for a nested bracket. The previous revision leaves the line alone. The new fallback treats every unmatched `](` as a possible label end, even when the file contains no opening bracket.

**Why this severity:** The fallback stops migration on text that contains no link under BR-150. The change exists only on the story branch.

**Fix:** Require evidence of an opening label bracket before classifying a suffix as doubtful. Keep the refusal for the nested-label test and add a case for a bare suffix.
