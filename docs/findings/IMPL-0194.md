# The installation page omits interactive test-command selection

**What is wrong:** A user who selects one of several detected test commands can find a new `docs/testing.yaml` that the page says setup cannot create. The new bullet limits creation to a scan that finds exactly one command. With several candidates, the installer prompts for a choice and writes the selected command (`packages/factory/scripts/init-factory:3529-3559`).

**Why this severity:** The procedure gives users an incorrect account of which files setup creates. That fails the purpose of the step that lists the changes.

**Fix:** In the installation page, say that setup records a single detected command automatically or a command the user selects when several are detected.
