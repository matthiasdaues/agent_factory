# The Python template stops a measure for a script that the measure leaves out

**What is wrong:** A Python measure that starts from the template cannot measure a project that holds one script without a file ending that no test runs. This holds also when the `files` pattern of the measure leaves the script out or an `exclude` pattern names it. So the User who follows setup step 3 and excludes such a script still gets exit `2` from every gate run, and the proof fails "Repeatable". The problem starts in `measure` of the template. The template measures every Python file of the folder, and it stops with "coverage cannot reach" for each script that coverage has no data for. `crap-score` applies `files` and `exclude` only to the rows that a command wrote (DEC-10), and here the command writes no rows. The template header names this duty for the whole folder, so the behavior is intended for the template alone. It contradicts setup step 1, which plans one measure per part of the code, and setup step 3, which proposes an exclusion for code that the tests cannot reach.

This repository shows the case. The template source `packages/factory/skills/setup-crap-score/crap-measure-python` starts with `uv run --script` and has functions. `tests/factory/test_crap_gate_template.py` runs only a copy of it in a temporary project. So coverage of this repository's test run has no data for the source file. A measuring command `scripts/crap-measure-python` copied from the template leaves out only itself, so it stops on the source file. An `exclude` pattern for that file does not help.

The review checked the stop on a small project. It held `a.py`, a test for it, and the untested script `tools/helper`. The filled-in template printed this and exited `1`:

```text
crap-measure-python: cannot measure: coverage cannot reach tools/helper
```

```text
setup step 3 excludes tools/helper in gates.crap-score.measures[].exclude
        ↓
crap-score starts the measuring command; the command does not know the exclusion
        ↓
the template finds tools/helper without coverage data and exits 1
        ↓
crap-score exits 2 before it applies the exclusion to any row
        ↓
every gate run and every proof run of the measure cannot measure
```

**Why this severity:** The template exists only on the feature branch, so `in_use` is false. BR-139 makes the template the start of every Python measure, and it cannot measure a project with one untested script without a file ending that the measure leaves out, such as this repository (yes to fails_purpose).

**Fix:** In the template, stop with "coverage cannot reach" only for a file that the measure keeps. Add two constants next to `TEST_COMMAND`, `FILES` and `EXCLUDE`, which setup step 4 fills with the `files` and `exclude` patterns of the measure. Check reachability only for the files that match `FILES` and no pattern of `EXCLUDE`, with `glob_match` of BR-131 copied into the template, because the template names no path under `.agent-factory/`. Name both constants in step 4 of `setup-crap-score/SKILL.md`. Add a case to `tests/factory/test_crap_gate_template.py`: an untested script without a file ending outside `FILES` gives exit `0` and no row for it. Another way is that `crap-score` passes both patterns in environment variables; that changes BR-129, so it needs the stakeholder.
