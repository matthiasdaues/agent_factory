# Without --ledger, dispatch loses the ledger when several dispatches exist

**What is wrong:** `_default_ledger` uses a ledger under `.current-work/` only
when it finds exactly one. With two or more, it returns
`.current-work/dispatch-ledger.yaml`, a path that does not exist. This repository
holds four ledgers, one per feature branch, so every `dispatch` call without
`--ledger` fails. `dispatch init --feature-branch feature/counter-ids` wrote
`.current-work/feature/counter-ids/dispatch-ledger.yaml`, and the next
`dispatch plan` failed with "ledger not found".

A second fault hides the first. `prepare-wave <n>` on a wave that holds no
story exits `0` and prints nothing. When `plan` fails, no story gets a wave, so
`prepare-wave 1` reports success and prepares nothing. Seen on the counter-ids
run on 2026-11-06.

**Fix:**

1. When `_default_ledger` finds several ledgers, it takes the one under
   `.current-work/<current branch>/`, and for a story branch, the ledger whose
   `stories` hold that story. When none matches, the error names the ledgers
   found and asks for `--ledger`.
2. `prepare-wave <n>` exits non-zero and names the wave when no story in the
   ledger carries that wave.
3. By the stakeholder's request on 2026-11-06: `verify-story --sha` also
   accepts an abbreviated SHA. It expands the SHA with
   `git rev-parse --verify <sha>^{commit}` and records the full SHA. An
   ambiguous or unknown abbreviation fails with git's message. `verify-base --expect-base` keeps its demand for the full 40 characters.

Add a test for each point to the dispatch tests.
