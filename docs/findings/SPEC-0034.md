# Thirteen Scenarios have no row in the QA strategy's contract-owner table

**What is wrong:** The contract-owner table maps groups such as "the definition, schema, and handoff Scenarios of CAO-04". Read by name, these Scenarios have no owner layer:

- CAO-02: `A reader is never counted as a review`
- CAO-04: `The domain-modeling agent becomes eligible after the requirements agent`, `The domain-modeling agent writes the other structure files only when the domain needs them`, `The domain-modeling agent takes over existing structure files without a move`
- CAO-07: `The architecture agent builds the baseline before the domain structure exists`, `run-step does not restart the architecture agent by itself`
- CAO-09: `The architecture-review agent checks the rules against the component view`
- CAO-10: `No other agent declares the test practice files`, `The test-strategy agent writes testing.yaml in a project without a feature file`, `The test-strategy agent writes a QA strategy only when its inputs exist`, `The test-strategy agent hands off to the planning agent`, `The mutation tool's configuration stays in the project's own files`
- CAO-17: `The single-producer rule does not count working output`

Four of them are `run-step` eligibility checks that an integration test on a fixture project can own. The testability probe needs one owner per contract.

**Fix:** Add a contract-owner row for each Scenario, or name it in an existing row by its full Scenario title. Give the `run-step` eligibility Scenarios an integration test that runs `intent select` on a fixture project.

**Resolution:** Each of the thirteen Scenarios is named by its title in a contract-owner row. The new rows are CAO-02-CT-03, CAO-04-IT-01, CAO-07-IT-02, CAO-10-LN-02, CAO-10-IT-01, and CAO-17-CT-01, and the eligibility Scenarios run `intent select` on fixture projects.
