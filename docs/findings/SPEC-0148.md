# The order test can pass when the generator ignores zero and negative values

**What is wrong:** FH-04-CT-06 checks that zero and negative orders pass validation. In the shared fixture, either value keeps the page ahead of the page at default order 100, just as its original order 20 did. The sort checks never need a non-positive order to change relative position. [docs/spec/work/factory-handbooks-qa-strategy.md:96](../spec/work/factory-handbooks-qa-strategy.md)

**Why this severity:** A test author can implement every stated assertion and pass a generator that accepts zero and negative order but clamps both values to 1 when sorting. No code or completed story outside the run encodes this review target.

**Fix:** Add a sort case where using zero or a negative value changes the expected relative position, and keep the format acceptance check.
