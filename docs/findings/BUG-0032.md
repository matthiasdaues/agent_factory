# update-factory drops the agents init-factory records

**What is wrong:** `update-factory` read `install.json` into memory, ran
`init-factory`, and then wrote the copy from before the run back to disk. That
dropped the agents `init-factory` had just recorded, such as the lector agent
and the Codex agents. A later update then met agent files with no record.

**Fix:** Commit `3f7b0df9bc5acac2aeac5007983212b6a0e34fb5` writes the header
changes before `init-factory` runs and reads the record back from disk
afterwards. Where `init-factory` wrote the string `"injected"` for an
orientation entry, the digest record from before the run is kept. An
unreadable record after `init-factory` produces a warning, and the update
keeps the copy from before the run. The fix was merged into `dev` as
`998da852413e515e07e66fddfb1e951430b3e431`. Two code reviews passed it, and
the full test suite passed after the merge.

**Not yet tested:** No test checks the write to the record before
`init-factory` runs. No test checks `install.json` after a rollback. Both gaps
are named in the fix commit message.
