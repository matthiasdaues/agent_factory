# BUG-0018 — Zero-Length Files in Context Guard

**Date:** 2026-08-26\
**Severity:** Low\
**Category:** Edge case\
**Status:** Not a defect — acceptable behavior

______________________________________________________________________

## Summary

Zero-length files are counted as 0 bytes in the context guard, which is correct. However, the context guard does not account for YAML parsing overhead when loading the manifest.

## Evidence

```python
# factory/scripts/step-guard:_estimate_input_tokens
def _estimate_input_tokens(patterns: list[str], cwd: Path) -> int:
    total_bytes = sum(path.stat().st_size for path in _expand_inputs(patterns, cwd))
    return total_bytes // 4
```

## Impact

If a story declares a very small `max_input_tokens` (e.g., 1000) and all input files are 0 bytes, the context guard allows spawn. However, the agent may still exceed the token budget due to YAML parsing overhead.

## Example

```yaml
id: ST-0000
inputs:
  - docs/spec/prd.md  # 0 bytes
max_input_tokens: 1000  # Very small budget
```

Context guard calculation: `0 bytes // 4 = 0 tokens < 1000 budget` → **ALLOW**

Actual agent token usage: `0 (files) + 500 (YAML parsing) = 500 tokens` → **May exceed budget depending on YAML size**

## Recommendation

**Current behavior is acceptable.** The context guard is a "best-effort" budget check, not a precise measurement. Users should not declare extremely small budgets (below 4000 tokens) as this is below practical thresholds.

**Alternative:** Add a small buffer (e.g., +100 bytes) for YAML parsing overhead, but this would require estimating YAML size, which is complex.
