# The counter-ids feature file does not parse as Gherkin

**What is wrong:** The feature file wraps the Scenarios of each Rule in Markdown code fences and writes the actor comments as `\# actor:`. A Gherkin parser reads the closing fence after the last step of a Rule as the start of a doc string. That doc string swallows the next `Rule:` line and its actor line, up to the next opening fence. So every Rule after the first one disappears, and the file ends inside an open doc string. The parser `gherkin-official` stops with these errors:

````text
(215:1): expected: #EOF, #TableRow, #TagLine, #ExamplesLine, #ScenarioLine, #RuleLine, #Comment, #Empty, got '```'
(363:0): unexpected end of file, expected: #DocStringSeparator, #Other
````

The layout looks like the output of `mdformat` run on the `.feature` file. The template in `derive-feature` Step 6 has indented Rules and Scenarios, `# actor:` comments, and no fences.

**Fix:** Rewrite the file in the layout of the `derive-feature` template: `Rule:` indented by two spaces, `# actor:` and `# @`-references as plain Gherkin comments, Scenarios indented by four spaces, and no code fences. Do not run `mdformat` on `.feature` files. Check the result with a Gherkin parser: it must report 11 Rules.

**Resolution (pass 2, 2026-11-05):** `gherkin-official` parses the file at commit `97584ca1` into 11 Rules and 39 Scenarios. The file has no code fences and no `\#` comments.
