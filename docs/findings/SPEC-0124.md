# The run-lifecycle Scenarios that change have no writer

**What is wrong:** The gaps report says that "the domain-modeling agent and the planning agent decide how each Scenario changes". Neither agent writes feature files, and `run-lifecycle.feature` is unchanged. Its Scenario "premerge-check reads the old key crap_score" (line 752) still makes `premerge-check` pass the threshold 8, and "crap-score reads the old key crap_score" (line 758) still judges every function. The comments "changes run-lifecycle" sit in `crap-gate-setup.feature`, so a reader of `run-lifecycle.feature` never sees them.

**Why this severity:** An agent that checks the new code against `run-lifecycle.feature` reports correct behaviour as a defect (fails_purpose). A reader must open a second feature file to learn which Scenarios no longer hold (raises_cost). No story or code outside the run encodes the new statements.

**Fix:** The requirements agent rewrites the eight listed Scenarios to the target state, and the gaps report names it as their writer (DEC-40).
