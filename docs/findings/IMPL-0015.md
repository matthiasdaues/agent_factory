# The guard passes a shell write when the path stands in a heredoc or the writer is not the first word

**What is wrong:** An agent whose `Edit` is refused can set `status: waived` with an ordinary shell command, and `guard-human-fields` lets the call through. The field name and the path both stand as plain text in the command. So the stakeholder loses the rule that only a human writes these values.

The first point of loss is `shell_write_targets`, which reads the targets in two narrow ways. `_strip_heredoc_bodies` drops each heredoc body before the words are read, so a script fed to `python3` or `bash` names no path. `_simple_targets` takes the writing command from the first word only, so `then sed -i` or `env X=1 sed -i` is not `sed`. The behavior looks wrong, not intended. The blind spot of the docstring and of the contract covers a hidden field name, `cp`, `git checkout`, and `cd "$DIR"`. It covers none of these forms. The docstring also says that the guard checks "an interpreter that names the path".

The review ran the guard of the branch head with a `Bash` payload for each command:

```text
exit 0  python3 - <<'PY' whose body is open('docs/findings/IMPL-0004.md','w').write('status: waived')
exit 0  bash <<'EOF' whose body is sed -i 's/status: open/status: waived/' docs/findings/IMPL-0004.md
exit 0  if true; then sed -i 's/status: open/status: waived/' docs/findings/IMPL-0004.md; fi
exit 0  { sed -i 's/status: open/status: waived/' docs/findings/IMPL-0004.md; }
exit 0  env X=1 sed -i 's/status: open/status: waived/' docs/findings/IMPL-0004.md
exit 0  cat <<< 'x', then a second line with the same sed -i
exit 2  python3 -c "open('docs/findings/IMPL-0004.md','w').write('status: waived')"
exit 2  sed -i 's/status: open/status: waived/' docs/findings/IMPL-0004.md
```

The last two rows show the refusal that the first six should also get. The sixth row fails because the pattern `HEREDOC` also matches `<<<`, so every later line counts as a heredoc body.

**Why this severity:** BR-092 requires a refusal for a shell call that writes into a guarded path and assigns a human value, and a heredoc script is an agent's usual next step after a refused edit, so the guard fails its purpose (`fails_purpose`). The guard exists only on `feature/finding-classification`, so the code is not in use and `harms_downstream` is false.

**Fix:** Change `packages/factory/config/hooks/guard-human-fields` in three places. Read the heredoc body of an interpreter or shell as its script, so its path words count as targets. A heredoc that writes a fixture outside `docs/findings/` still passes, because its body names no guarded path. Skip leading shell keywords and wrappers before `_simple_targets` reads the first word: `{`, `then`, `do`, `else`, `!`, `env`, `command`, `time`, and `sudo`. Make `HEREDOC` refuse `<<<`. Add one test per row of the list above to `tests/factory/test_guard_human_fields.py`.
