# The migration checks can pass when guide content is missing

**What is wrong:** [FH-05-01](../spec/features/factory-handbooks.feature) checks map rows and destinations. The [story criteria](../spec/work/factory-handbooks-gaps.md#acceptance-criteria-for-the-stories) omit a content check for most guide sections. The [accepted scope](../proposals/factory-handbooks.md#scope) requires the guide content to move into the user handbook, split by page type.

**Why this severity:** A migration can map “Runtime usage capture” to the user handbook index and omit its content. The Scenario and story criteria can still pass, so the gap answers yes to `fails_purpose`. No story or code outside this run encodes the new check.

**Fix:** Add a story acceptance criterion requiring a reviewer to compare each guide section at the baseline commit with its mapped page. Have the reviewer record where the migrated content appears, allowing it to be rewritten and split by page type.
