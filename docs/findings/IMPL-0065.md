# The template measures ignored files, so a run by hand in a Factory project always exits 1

**What is wrong:** A person who runs the gate-check step by hand in a project with the Factory installed never gets rows. The template exits `1` with `coverage cannot reach .agent-factory/factory/scripts/...`, because it measures the installed Factory scripts that no project test runs. The feature file runs `crap-score` from the primary checkout in a run by hand (Scenario Outline "The gate-check step runs crap-score in the folder of the story"), and the primary checkout holds `.agent-factory/`.

The problem starts in `code_files`. It walks every file below the folder with `root.rglob("*")`, which also enters dotted folders, and skips only the names in `EXCLUDED_DIRS`. Git ignores `/.agent-factory/`, so the folder is not code of the project, but the walk does not ask git. The installed scripts have no file ending and start with `#!/usr/bin/env -S uv run --script`, so `is_python_script` takes them. Coverage records nothing for them, and `measure` raises `CannotMeasure`. The template must not name `.agent-factory/` (BR-130, CG-03-LN-02), so adding the folder to `EXCLUDED_DIRS` is not a way out. The behavior looks unintended: the tests build a project without `.agent-factory/` only and never meet the case.

```text
run by hand: crap-score runs the measure in the primary checkout
        ↓
code_files walks .agent-factory/factory/scripts/, which git ignores
        ↓
is_python_script accepts next-id and the other installed scripts
        ↓
coverage has no entry for them, so measure raises CannotMeasure
        ↓
the template exits 1 on every run, whatever the story changed
```

The review checked this in a scratch project with the demo files and one copy of the installed `next-id` under `.agent-factory/factory/scripts/`, ignored by `.gitignore`. The template exited `1` and printed `crap-measure-python: cannot measure: coverage cannot reach .agent-factory/factory/scripts/next-id`.

**Why this severity:** The template exists only on `story/ST-0435`, so `in_use` is false. The template exists to give the gate its rows, and in a run by hand it gives none in any Factory project (yes to fails_purpose).

**Fix:** In `code_files`, take the candidate files from git when the folder is a git work tree: `git ls-files --cached --others --exclude-standard -z`. Keep `EXCLUDED_DIRS` and the walk as the fallback for a folder outside git. The list then leaves out `.agent-factory/`, `.venv`, build output and every other ignored file without naming any of them. Add a test to `tests/factory/test_crap_gate_template.py` that builds the demo project as a git repository with an ignored folder that holds an extensionless Python script, and checks exit `0` and no row for that folder. State in the header under Files that the command skips files that git ignores.
