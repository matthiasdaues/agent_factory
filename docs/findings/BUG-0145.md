# A capture stuck in "committing" blocks the transcript migration for good

**What is wrong:** `migrate-usage-transcripts --apply` refuses to run while `.agent-factory/usage/control/pending/` holds a marker, and asks to run again when the captures are done. A capture whose process died while committing leaves its `capture-<id>.committing.json` marker and its snapshot `.agent-factory/usage/.capture/capture-<id>.jsonl` behind for good. Nothing in the Factory clears them: `usage-capture-lifecycle` only registers and supervises a capture, and no command recovers or drops a stuck one. So the migration can never run, and the transcript copies keep filling the disk.

**How it showed:** On 2026-11-24 this repository held four such markers, from 2026-10-15, 2026-10-16, 2026-10-27 and 2026-11-17, most likely from the time when the broken usage runtime stopped every capture (BUG-0144). The migration refused with "4 captures are pending", while `.agent-factory/usage/transcripts` held 76 GB and the disk had 18 GB free. The four snapshots held 395 MB. Each was already in the stored transcripts: one byte for byte identical to a stored copy, three as the byte prefix of a later copy of the same session. The User moved them aside by hand into `.agent-factory/usage-stuck-captures-2026-11-24/`, and the migration then freed about 60 GB.

**Fix:** give the Factory a way to settle a stuck capture, for example in `migrate-usage-transcripts` or a `usage-capture-lifecycle` subcommand. A marker counts as stuck when no capture process holds its lock and it is older than a time limit. A stuck snapshot whose bytes are a prefix of a stored copy of the same session is dropped with its marker, and the output names it. Any other stuck snapshot is reported and kept. The migration then proceeds instead of refusing.

**Why this severity:** The migration exists to free the disk, and a stuck capture stops it without a way out (`fails_purpose`). The copies keep growing by gigabytes per long session (`raises_cost`). Version 1.14.1 is installed, so the script is in use.
