# `tests:` field workflow has no timing or ownership decision

**Resolution (verified 2026-08-18, repeat pass v2):** the new "Timing and
ownership" paragraph states who writes the pre-existing tests (humans, when
house-rules mandate manual test-first), when (before planning begins), and who
populates or amends `tests:` (planning-agent at story creation; the
orchestrating session for post-approval amendments before implementation
dispatch).

**What is wrong:** The proposal's Open Questions section claims "All resolved
during grilling. No open questions remain," but the `tests:` workflow leaves
the load-bearing sequencing decision unstated. `backlog-lint` must validate
that `tests:`-listed files exist, and greenfield Step 3.2 runs `backlog-lint`
at planning time. Yet the motivating house-rule is "test cases written manually
*before the code is implemented*" — implementation happens *after* planning.
If the manually written tests exist before planning, they were written against
acceptance criteria that are only finalised at planning; if they are written
between backlog approval and implementation, `tests:` is empty at planning,
`backlog-lint` never sees them, and no step names who records them on the
story afterwards. Either way the workflow as described only functions under a
test-authoring order the proposal never states, and the developer-agent's
"Green, not Red-Green" branch may never trigger in practice.

**Original fix direction (applied):** State the timing decision explicitly in the `tests:` field section:
who writes the pre-existing tests, at which workflow point, against what
acceptance criteria, and who populates or amends a story's `tests:` field when
tests arrive after backlog approval (e.g. planning-agent records only tests
existing at planning; tests authored later require a story amendment step, or
the field is populated by a named actor before dispatch). Then the Open
Questions claim becomes true.
