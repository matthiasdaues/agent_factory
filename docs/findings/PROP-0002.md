# Post-Epic-0 development.md reconciliation has no owner or mechanism

**Resolution (verified 2026-08-18, repeat pass v2):** the "Two-phase nature"
paragraph now derives an explicit Epic 0 story — "Update development.md with
actual commands and paths" — that depends on all other Epic 0 stories and is
the last story in Epic 0; feature stories carry `deps:` on it; Completion
Criterion 4 ("including a final 'update development.md' story that depends on
all other Epic 0 stories") verifies it.

**What is wrong:** The "Two-phase nature" paragraph says that after Epic 0,
"the developer who implements the last Epic 0 story updates development.md
with the actual commands and paths. This reconciliation happens naturally — no
special mechanism needed." Three problems: (1) no Epic 0 story in the
derivation table or elsewhere carries this work, so it is unplanned effort
that violates the proposal's own "every concrete decision maps to a setup
story" rule; (2) a developer-agent is dispatched a single story and has no way
to know it is implementing the *last* Epic 0 story — "the developer who
implements the last Epic 0 story" identifies nobody; (3) no Completion
Criterion checks that development.md was reconciled, so the update can be
silently dropped. This contradicts the Open Questions claim that no questions
remain.

**Original fix direction (applied):** Give the reconciliation an owner. Either derive a final Epic 0 story
("reconcile development.md with the as-built setup", depending on all other
Epic 0 stories via `deps:`), or assign the update to the implementation-agent
at wave-1 closeout, or to the completeness-sweep skill on its next run. Add a
matching Completion Criterion so the update is verified, not assumed.
