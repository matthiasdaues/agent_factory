# The ledger's `deps` field means two different things

**What is wrong:** `prepare-story` reads the first entry of a story's
`deps` in the ledger as its serial-chain predecessor and bases the story on
that predecessor's merge. Since BUG-0082, `deps` holds the dependencies the
backlog declares, which can be a story from an earlier wave. Nothing writes
the real chain predecessors, which come from file overlap in the wave plan.
So `prepare-wave` prepares the links of an overlap chain in parallel, and
`prepare-story` can base a story on the wrong merge. A review of the
BUG-0082 fix found this.

**Why this severity:** The lines of `cmd_prepare_story` exist unchanged on `dev`, so every automated dispatch uses them. `prepare-story` reads `deps[0]` as the chain predecessor, although `deps` holds the backlog dependencies since BUG-0082, so a chain link starts from the wrong merge. `prepare-wave` holds back only same-wave `deps`, so overlapping chain links are prepared in parallel, against the Scenario "Serial chain heads are prepared but chain links stay pending" of `mechanized-dispatch.md`.

**Fix:** Decide how the ledger records chain predecessors, for example in a
field of their own that `plan` fills from the wave plan. Then make
`prepare-wave` hold back every chain link but the first, and make
`prepare-story` read the new field.

## Possible damage

- Stories with overlapping `touches` that were prepared from one base in one wave, 35 pairs in five ledgers, for example ST-0314 and ST-0315 in `feature/brownfield-onboarding` — check: run `git log --first-parent --oneline feature/brownfield-onboarding` and confirm that the second merge of each pair lost no lines of the first.
- A chain link cut from the merge of an earlier-wave story instead of its chain predecessor — check: run `grep -nE '^  ST-|wave:|base_sha|commit_sha|^    - ST' .current-work/feature/core-artifact-layout/dispatch-ledger.yaml` and compare each `base_sha` with the merge of the story before it in the chain.
- The same two effects in other projects that ran automated dispatch — check: run the `grep` above on each `.current-work/**/dispatch-ledger.yaml` in a project that holds `.agent-factory/install.json`.
