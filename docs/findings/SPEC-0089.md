# The report contract still runs the drift sessions after each merge

**What is wrong:** The table of reports in [interface-contracts.md § Report rows](../spec/interface-contracts.md#report-rows-spec-feedback-and-reconciliation), line 1105, names "implementation agent, after each merge" as the dispatcher of the owner and the reviewer of a spec-feedback row. The proposal moves these drift sessions to the wave close, "so a story merge and a drift session never commit on the feature branch at the same time". The Rule "Implementation agent starts the next wave only after the wave close" and its Scenario "The implementation agent runs the drift sessions and closes the wave" say the same. So the contract tells the implementer of the implementation agent to spawn the owner after each merge, while the feature file tells it to spawn the owner only at `close-wave`.

**Why this severity:** No story or code encodes the run lifecycle spec yet, so it is not in use. The contract and the feature file contradict each other, and an implementer who follows the contract starts drift sessions that commit on the feature branch while the next story of the wave merges, which the proposal rules out (fails_purpose).

**Fix:** Change the cell to "implementation agent, at the wave close, after `dispatch close-wave` lists the row (BR-062)".
