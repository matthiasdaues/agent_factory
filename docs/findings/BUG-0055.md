# `module-graph-check` reports "no change" for input it could not parse

**What is wrong:** With an empty architecture file and a contracts file it cannot read, the script prints `architecture_change=false` and exits 0. Its docstring promises exit 2 on a parse error. The routing gate then skips the architecture phase. Source: [bug-hunt report § L-5](../reviews/bug-hunt-2026-10-15.md#l-5--module-graph-check-reports-no-change-for-input-it-could-not-parse).

**Fix:** Exit 2 when it finds no components or no contract headings.

**Resolution:** Fixed in commits `42e37fad34fbe5ab074090c38c40d5c42a074e94`, `6ff3a90fa9f7025562655c80989982e27f78b122`, `79c3e074ebe3e0b1938df72156718bb867f94c7a`, `05644e32873e0ae1d69b099cc63beee0b783cbc6`, merged into `dev` as `3921e522cc31f7fd454d9c908c9e8e42ceb201fe`. The full suite passed after the merge. A contracts file with no `## ` heading and no `Reads` or `Writes` row declares no contracts and passes with a warning; any other unreadable file exits 2. Known gap: rows under a `###` heading count toward the previous `##` contract, so this repository's `interface-contracts.md` loses three sections.
