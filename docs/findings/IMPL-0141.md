# The manual dispatch how-to states push ownership outside a sourced callout

**What is wrong:** The operator reads a binding rule as ordinary prose.
The revised paragraph says the user pushes and links to the implementation
agent's branching model. The rule belongs to the Dispatch section of the
rulebook. The link to the agent definition leaves the rule outside the
callout that the story requires.

**Why this severity:** The new wording resolves the conflicting push
instructions in IMPL-0139. It introduces a separate BR-149 violation.
The QA strategy treats binding rules in ordinary prose as a failure of the
story's purpose.

**Fix:** Keep the concrete push step in the procedure. Put the ownership rule
in a rule summary sourced to
[Dispatch](../../packages/factory/rulebooks/rules.md#dispatch). Preserve the
exception for the claim push by `next-id` if the summary covers pushes
beyond this step.
