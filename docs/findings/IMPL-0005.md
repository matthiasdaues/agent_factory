# The rules send every ID to next-id, including PROP IDs that next-id refuses

**What is wrong:** An agent that follows the rules is told to claim IDs from `next-id` that `next-id` refuses. The proposal review agent is the first to meet this, when it adds a `PROP-NN` row to a proposal. Three texts state the scope too widely:

- `rules.md:158` says: "**MUST** claim every ID through `next-id`".
- `rules.md:101` says that `next-id` hands out the ID of "any other file with a sequential ID".
- `branching-policy.md:41` names `PROP-NN` as an example and says that `next-id` hands out each ID. `planning-agent.md:110` says that `next-id` hands out "(ST-NNNN, PROP-NN, etc.)".

`next-id` serves only the twelve prefixes of BR-068, and BR-068 names `PROP` as a prefix that fails. DEC-09 says that PROP findings inside a proposal get no counter. Split letters (`ST-NNNNA`) and `RETRO` IDs also stay outside the counter. So `rules.md`, which every session reads in full, contradicts `proposal-review-agent.md:124` ("the next free `PROP-NN`") and `create-backlog-slice-story/SKILL.md:90`. An agent that obeys the MUST runs `next-id PROP`, gets exit 1, and has no rule that tells it what to do next. The first point of loss is the new text of ST-0373 and ST-0374. The old `dev`-index wording carried the `PROP-NN` example, and the new wording kept it and tied it to `next-id`. The behavior looks unintended. The text tests check only that `next-id` is named. They do not check which IDs it covers.

**Why this severity:** The rule tells agents to number `PROP` rows with a script that refuses them, so the text fails its job of telling an agent how to number an artifact (`fails_purpose`). Three files repeat the wrong scope, so a later fix must find all three (`raises_cost`). The text is only on `feature/counter-ids`, so it is not in use.

**Fix:** In the three files, limit the `next-id` statements to the prefixes of BR-068 and link `finding-format.md` § File location and name for the list. Remove `PROP-NN` from the examples of IDs that `next-id` hands out. In `rules.md:158`, write "every ID of a prefix that `next-id` serves". Add one sentence that names the IDs outside the counter: `PROP` rows in a proposal, split letters of a story, and other IDs keep their own numbering rule. Extend `test_counter_ids_text.py` so that no file says `next-id` hands out `PROP`.
