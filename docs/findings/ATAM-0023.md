# A temporary worktree left by a crash blocks every later merge of its unit of work

**What is wrong:** `premerge-check` adds a detached worktree at the fixed path `.current-work/<feature-branch>/premerge/<id>`. ADR-0038 says that a crash can leave this worktree behind and that `dispatch close` removes it. Nothing removes it before that. On the next `merge-story` of the same unit of work, `git worktree add` meets a path that exists and is still registered, and refuses. So `premerge-check` fails with a git error on every retry.

`dispatch close` cannot help during the run. It refuses while a unit of work is `failed` or `blocked`, and the unit of work cannot reach `done` without a passing merge check. The architecture names no other step that cleans the path. ADR-0037 and 6.22 claim QS-5 for runs: a new session continues an interrupted run from the ledger.

Take ST-0350 in an orchestrated run. The session dies while `crap-score` runs in `.current-work/feature/login/premerge/ST-0350`. A new session reads the ledger and runs `dispatch merge-story ST-0350` again. `git worktree add` refuses, and every later attempt fails the same way until a person removes the worktree by hand.

**Why this severity:** The architecture rests run resume on QS-5, which has priority 1, so its importance is `high`. The exposure is `uncertain`: the failure depends on how `premerge-check` adds its worktree, and the architecture does not say. High importance and uncertain exposure give `major`. No code is built from ADR-0038 yet, so `in_use` is false.

**Fix:** State in ADR-0038, 6.24, and the DSL component `premerge-check` that `premerge-check` removes an existing worktree at its own path, with `git worktree remove --force` and `git worktree prune`, before it adds the new one. The path belongs to the unit of work, so nothing else uses it. Route the same sentence for the `premerge-check` contract to the domain-modeling agent as a drift row.

## Resolution

Before `premerge-check` adds its temporary worktree, it removes any worktree at the same path with `git worktree remove --force` and then runs `git worktree prune` (BR-123). The path belongs to one unit of work: `premerge/<id>` for a story or a finding, and `premerge/feature` for the feature merge.
