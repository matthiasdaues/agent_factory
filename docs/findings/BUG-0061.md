# `link-check` gives wrong answers

**What is wrong:** It reports valid links as broken: anchors in a file with a byte order mark, setext headings, `<a id>` anchors, headings with emphasis, `<my file.md>`, `file(1).md`, and links inside nested code fences. It misses reference-style links to missing files, and it reports success for a missing input file. A Latin-1 file crashes it. Source: [bug-hunt report § L-8](../reviews/bug-hunt-2026-10-15.md#l-8--link-check-gives-wrong-answers).

**Fix:** Use a CommonMark parser, read files as `utf-8-sig`, and report unreadable input as a finding.

**Resolution:** Fixed in commits `db7d0f798c532c5f24dfdc5dfbcb2f7f886fe26f`, `87b8ee8187a761e430b9215d57b06963b4e419d9`, `0ec3ccede6eb27f98e3ab2b20a1d8dfb55024fb3`, merged into `dev` as `3921e522cc31f7fd454d9c908c9e8e42ceb201fe`. The full suite passed after the merge. Fixed with stdlib code, not a CommonMark parser, so the hook keeps no dependency. Known gaps: a heading holding U+E000 or U+E001 crashes `slugify`; padded code spans keep their spaces.
