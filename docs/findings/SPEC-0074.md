# A capped suggestion cannot give its "no to fails_purpose" sentence

**What is wrong:** The Scenario "A suggestion is at most minor" at lines 149-152 gives a code suggestion a basis with `fails_purpose` true and expects the severity `minor` (BR-084). BR-087 requires every `minor` finding of the document, code, or runtime class to give the reason for its "no" to `fails_purpose`, with the marker `no to fails_purpose`. `finding-lint` rejects a register line without the marker. This finding has no "no" to give. So the reviewer agent writes a false marker, or the lint rejects a line that BR-084 makes valid. The proposal also defines a suggestion as a finding where "the artifact works", and a true `fails_purpose` says that it does not.

**Why this severity:** No story or code encodes the specification yet, so it is not in use. BR-084 and BR-087 contradict each other for this case, so the implementer of the marker check and the author of test FC-10-CT-03 must ask which rule wins (fails_purpose). A reader must also hold both rules side by side to see the conflict (raises_cost).

**Fix:** Pick one rule and state it in BR-084, BR-087, and the Scenario. The recommended rule: a suggestion of the document, code, or runtime class answers false to `harms_downstream` and `fails_purpose`, because it describes material that works. `finding-lint` then rejects a suggestion with either answer true. The cap of BR-084 stays as a guard for the rules of the other classes. The alternative is that BR-087 exempts a suggestion, and its sentence names the cap instead of the marker.
