## How a story branch can reach the register

The caller asked whether a story branch can ever change which rows count. The review checked each way in:

- **The folder and `HEAD`.** `read_register` never opens the file in the folder and never reads `HEAD`. A scratch mutant that falls back to `HEAD:docs/findings/exceptions.md` when `dev` lacks the file fails `test_cg_05_a_row_only_on_the_story_branch_has_no_effect`, because `repo.change` commits the row with `git add -A`. So the tests catch that mistake.
- **A missing branch `dev`.** The probe checks `refs/heads/dev^{commit}` and prints the line of DEC-13. A story branch that holds the file still fails the gate.
- **A ref named `dev` that is no branch.** The two reads pass the short name `dev` to git, which picks `refs/tags/dev` before `refs/heads/dev`. A tag `dev` at the story head makes the story's row count. That is IMPL-0079.
- **Moving the branch `dev` itself.** An agent could run `git branch -f dev`. No hook refuses it, but the spec draws the line at the branch: whatever `dev` holds counts. The review files nothing on it.
