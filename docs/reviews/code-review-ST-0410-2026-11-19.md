# Code review of ST-0410, the merge of a story by hand

## Result

The review found one blocking defect, IMPL-0031, so ST-0410 goes back to the developer agent before the merge. By hand, a red test suite after the merge runs `git reset --hard` in the primary checkout. That command deletes every uncommitted change to a tracked file that the checkout of the feature branch carried over.

The order of BR-124 holds on every path that the review tried. `premerge-check` runs while the story branch is checked out. The feature branch is checked out only after exit `0`. A refused check, checkout, or merge leaves the story branch checked out, merges nothing, and keeps the entry `dispatched`. The orchestrated path behaves as before. Removing `mark-done` breaks no script, agent, skill, or playbook.

The review also found a defect that the story did not cause: a refused amend of the merge commit. The section [Outside the diff](#outside-the-diff) describes it. The review did not file it, because its rule computes `critical`, and a `critical` finding stops the run. The caller decides whether to file it.

Next, the developer agent fixes IMPL-0031. Then the code-review agent reviews the story again.

## Correctness

**The order by hand.** `cmd_merge_story` now loads any ledger and sets `by_hand` from its mode. By hand, it refuses a checkout that is on neither the story branch nor the feature branch. Every step before `premerge-check` only reads git. Then `premerge-check` runs, and only after its exit `0` does `_checkout_feature_branch_by_hand` check out the feature branch. RL-03-IT-03 records the branch from inside the gate and checks that it was `story/ST-0350`.

**A refused check.** `merge-story` returns before any checkout. RL-03-IT-04 checks that the branch, every tracked file, the feature branch tip, and the entry stay unchanged, also with a changed file of the story.

**A refused checkout.** `_checkout_feature_branch_by_hand` prints git's own message, names the primary checkout, and exits `1`. When a failing `post-checkout` hook has already switched the branch, it checks out the story branch again. RL-03-IT-05 checks the message, the kept change, and that the rerun runs `premerge-check` again.

**A refused merge.** The probe with a failing `pre-merge-commit` hook confirmed the path. `merge-story` aborted the merge, checked out `story/ST-0350` again, and exited `1`. The feature branch tip, the clean status, and the `dispatched` entry stayed. No test covers this path, and no row of the QA strategy owns it.

**An interrupted merge.** The checks for "already merged" read `<feature-branch>^2` and the ancestry against the feature branch by name. So they give the same answer from either branch. The probe created the merge commit by hand and then ran `merge-story` once from `feature/login` and once from `story/ST-0350`. Both runs exited `0`, left `feature/login` checked out, set the entry `done`, and put `status: done` into the merge commit. By hand, from the feature branch, a merge that has not started is refused and the message names the story branch. So `merge-story` never checks out the feature branch before the gate.

**The orchestrated path.** It still refuses a checkout that is not on the feature branch, refreshes the story branch, and blocks on a conflict. In that path the current branch is the feature branch, so reading the feature branch by name gives the same commit as `HEAD`. `pre_merge_sha` still reads `HEAD^1`, which is correct after the checkout on both ways.

**The red suite.** `merge-story` moves the feature branch back to the commit before the merge, makes no revert commit, and sets `blocked` with `post-merge test failure`, as BR-116 says. The primary checkout stays on the feature branch. Neither BR-116 nor BR-124 says which branch to leave checked out after a red suite, so this is not a finding. The same path loses uncommitted changes by hand, which IMPL-0031 records.

**mark-done.** `cmd_mark_done`, its parser entry, its call in `main`, and its name in `READ_SUBCOMMANDS` are gone. RL-02-CT-01 checks the refusal, the usage text, and both lists. `test_finding_stop.py` drops `mark-done` from its list of subcommands that run during a stop. The `git grep` found no script, agent definition, skill, or playbook that calls it. The two documents that still list it, `docs/arc42/06_runtime_view.md` line 1024 and `docs/spec/features/finding-classification.feature` line 889, are rows of `docs/spec/work/spec-feedback-ST-0410.md`.

**done and commit_sha.** RL-02-IT-02 checks that only the merge commit sets `status: done`, and RL-17-IT-01 checks that `commit_sha` holds the merge commit and seeds the next story. ST-0421 owns `close-wave` by hand, so RL-17-IT-01 writes the wave record itself. The story's Analysis names this.

## Outside the diff

`merge-story` creates the merge commit first, and then amends it to add `status: done`. When a `pre-commit` hook refuses the amend, `merge-story` prints `error: failed to amend merge commit` and exits `1`. The feature branch then already holds the merge commit without `status: done`. The status change stays staged, and the entry stays `dispatched`. By hand, the primary checkout also stays on the feature branch. So this path leaves exactly the half-done merge that the brief asked about.

The rerun is worse. The resume path reads the status from the story file in the working tree, which already says `done`, so it skips the amend. The probe removed the hook and ran `merge-story` again. It exited `0` and set the entry `done`. `git show feature/login:backlog/ST-0350.md` did not contain `status: done`, and `git status` still showed `M  backlog/ST-0350.md`. That breaks BR-118, which puts the status into the merge commit. In an orchestrated run, the next `merge-story` would amend the staged file into the next story's merge commit.

ST-0410 did not cause this. The lines (`dispatch:2288-2297` and `dispatch:2333-2338`) exist unchanged on `dev` and in the installed copy, so `in_use` is true. The rerun gives a wrong ledger state, so the rule of the class computes `critical`. A `critical` finding stops the run, so the review leaves the filing to the caller. The smallest fix lies in `cmd_merge_story`. The resume path reads the status from `git show HEAD:backlog/<id>.md` in place of the working tree. A refused amend by hand runs `git reset --merge HEAD^1` and checks out the story branch again.

## Notes

A later `step-guard` that reads the story path would treat a merged story as still active.

- No test covers a merge refused by hand or an interrupted merge resumed by hand. The probes above showed that both behave as BR-124 says.
