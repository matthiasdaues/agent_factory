## Correctness

**The transitions.** `VALID_TRANSITIONS` gains `failed -> pending` and `blocked -> pending` and no new state. `RL-06-CT-01` compares the whole table with the edges of the state machine, and runs `return-story` from every state. Only `failed` and `blocked` reach `pending`.

**return-story.** `Ledger.return_story` refuses every state outside `RETURNABLE_STATES` and names the state. `cmd_return_story` changes the ledger in memory, writes `status: pending` into `backlog/<id>.md` of the current checkout, and saves the ledger last. When the backlog file has no status line, the command exits 1 and the ledger stays unchanged, and a test checks this. `returned` is written only when it is true, and an old ledger without the field loads as `false`. `dispatch-contract.md` lists the field and the command.

**The stop causes.** RL-06-IT-01 builds all five causes on real branches and checks the state, the `reason`, and HasStopped. RL-06-IT-02 checks that a red suite moves `feature/login` back to the commit before the merge with no revert commit. RL-06-IT-03 removes the cause of a merge conflict, runs `re-dispatch`, and merges the same branch tip.

**The scope check of `escalate`.** The old check read only the files of the latest counted attempt's commit and compared them with the declared outputs alone. So it missed an out-of-scope file from an earlier commit, and it refused the story's own backlog file and review report. The new `_story_scope_violation` reads `git diff --name-only <feature>...<story>`, the same diff that `premerge-check` reads in `merge-story`. It accepts the same five parts of the scope: the declared outputs, `backlog/<id>.md`, the spec-feedback report, `packages/factory/INDEX.yaml`, and the owned review and finding files. `_in_declared_scope` matches an entry with `*` or `?` as a glob and any other entry as a path prefix, as `premerge-check` does with `--scope-glob` and `--scope`. Every file in the diff must fall inside that scope.

So `escalate` now refuses every path that `premerge-check` would refuse, and accepts only what it would accept. This is stricter than before, because every commit on the branch counts. A refresh merge does not widen the diff, because the three-dot diff starts at the merge base, which is the feature tip of the last refresh. An empty diff, a git error, or a missing branch still counts as a violation, as before. The target is `entry.feature_branch`, which both prepare paths set. Only an old entry without it falls back to `base_sha`. RL-06-IT-05 checks the refusal, the record `escalate refused: scope`, and the grant after the User removes the file.

**The quoting in `_scalar`.** `_scalar` now quotes a string that holds `": "` or ends with `":"`, with `json.dumps`. The stdlib loader reads a JSON-quoted string back unchanged, and PyYAML reads it as the same string. The probe confirmed this for every record that `dispatch` writes itself: `merge conflict`, `refresh conflict`, `post-merge test failure`, and the three `escalate refused:` records. It also confirmed it for branch names, worktree paths, tiers, and failure classes. Free text from `mark-blocked --reason` can still break a PyYAML reader, for example a text that starts with `[`, `-`, or a backtick (IMPL-0032).

## Architecture, SOLID, maintainability, consistency

The ledger rule lives in `dispatch_lib.py`, and the file change and the command line live in `dispatch`. This keeps the split that the other subcommands use. `return-story` joins `READ_SUBCOMMANDS`, so a finding stop allows it, and `test_finding_stop.py` lists it.

The scope of a story is now built twice, once for `premerge-check` and once for `escalate` (IMPL-0033).

The tests carry `@pytest.mark.spec` with the Test IDs of their QA strategy rows, and every git test builds its own repository in `tmp_path`.
