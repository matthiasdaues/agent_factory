# Code review of ST-0425, the end of a run with dispatch close

## Result

The review found three blocking findings, so ST-0425 goes back to the developer agent. Each one is a path on which `dispatch close` deletes files without a stash:

- IMPL-0040 (`major`): with the git config `status.showUntrackedFiles=no`, the close deletes the untracked files of a worktree and makes no stash.
- IMPL-0041 (`major`): a worktree that the ledger does not name, inside an ignored folder of a run worktree, is deleted with its uncommitted work.
- IMPL-0042 (`major`): a ledger whose feature branch holds `..` lets `close --drop` delete the folder of another run.

The review also filed two `minor` register files. IMPL-0043 records that `_remove_run_dir` deletes the run folder when `git worktree list` fails. IMPL-0044 records that no test checks the two stops on a failed stash or removal, or the path guards.

The rest of the close holds. It refuses the states BR-119 names, deletes branches only with `git branch -d`, only pushes stashes, runs each stash in the worktree it removes, and stops before the ledger goes when a stash or a removal fails.

Next, the developer agent fixes IMPL-0040, IMPL-0041, and IMPL-0042 on `story/ST-0425`, and the code review runs again.

## Correctness

### What the close deletes

The close takes a worktree only when `git worktree list` names it, it lies under `.current-work/` of the primary checkout, and it is not the primary checkout. It takes the worktree of each ledger entry, by `worktree` or by `branch`, each worktree under `.current-work/<feature-branch>/premerge/`, and the worktree of the feature branch. Every path is resolved, so a symlink under `.current-work/` that points outside is skipped. The feature worktree comes last, so an old run with nested story worktrees loses no story worktree to the outer removal.

The guard has three holes. First, the check for uncommitted work follows the git config of the User (IMPL-0040). Second, it ignores a worktree that the ledger does not name when that worktree lies inside a run worktree (IMPL-0041). Third, the run folder is taken from the resolved path, so `..` or a symlink leads to another run's folder (IMPL-0042).

Gate results go only by the IDs of the ledger, and the IDs must match `^[A-Za-z0-9_.-]+$`. A symlinked gate folder and a symlinked result file are skipped. `premerge-check-ok` goes only when its `branch=` line names a branch of the run, and `verify-base-ok` only in a run by hand, as the contract says.

### Branches and stashes

`_delete_run_branches` runs only `git branch -d`. A branch that git refuses stays, and the output names it as `unmerged branch:` or `kept branch:`. The close runs no `stash apply`, `pop`, or `drop`.

Each stash runs as `git -C <worktree> stash push --include-untracked -m <name>`. The `-C` makes git stash the changes of that worktree, even though the stash stack is shared by every worktree of the repository. The close only pushes and names each stash, so a push of another session in between changes nothing for it. The test RL-14-IT-03 reads the third parent of the stash and finds `notes.txt`, and it finds the change to `src/login.py` in the diff to the first parent.

### Order and stops

The close stashes and removes each worktree before it touches the ledger. A failed `git status`, `git stash push`, or `git worktree remove` stops it with exit `1` and keeps the ledger. A rerun skips the worktrees already removed, because git no longer lists them. A stash comes before its removal, so a failed removal leaves the work in the stash, and the output names that stash. The probes checked both stops. No test checks them (IMPL-0044).

### Refusals

`close_refusals` accepts only `done` and `pending`, so it refuses `failed` and `blocked`, as BR-119 says. It also refuses `prepared`, `dispatching`, and `dispatched`, and the first row of the spec-feedback report records that. The review agrees with the extra refusal. In those states an agent may still write into the worktree, and the close would remove the folder under a running session. BR-119 also says that the close accepts a run whose units of work are `done` or `pending`, which reads as the full list. The message does not tell the User how to leave a `dispatched` story for `--drop`: `mark-failed` and then `return-story`. That is a note below.

Without `--drop`, `_unmerged_feature_refusal` refuses a feature branch that is not an ancestor of `dev`, and it also refuses when either branch is missing. Both messages name `dispatch close --drop`. With `--drop`, no merge is checked, and `git branch -d` keeps each unmerged branch. RL-14-IT-05 and RL-14-IT-06 check both paths.

### The stop of BR-091

`close` is in `READ_SUBCOMMANDS`, so a stop on a critical finding allows it. `close --drop` uses the same subcommand. RL-14-IT-08 runs both forms with and without a stop and compares the outcomes.

## Architecture, SOLID, maintainability, consistency

`cmd_close` reads like the Analysis: load, refuse, collect, stash and remove, then the files and branches. Each step is a helper with one job. The two pure helpers, `close_refusals` and `stash_name`, live in `dispatch_lib.py`, next to the other ledger rules. The new `_git_in` runs git with `-C`, which the close needs because it runs from any folder. The older helpers of `dispatch` run git in the current folder, so the module now has two ways to call git. That is acceptable here, because the close must not depend on the folder it is called from.

The section Close of `dispatch-contract.md` replaces the old text with its forced branch delete and its `abandonment:` entry. The new text matches the code, including the output lines. It says that the close acts only on what its ledger names, and IMPL-0041 and IMPL-0042 break that sentence.

The tests carry `@pytest.mark.spec` with the Test IDs of their QA strategy rows. Each test builds its own repository in `tmp_path`, strips the `GIT_` variables, and runs `dispatch` as a subprocess. The module fixture `finished_run` closes one run and serves five tests, which keeps the suite fast.
