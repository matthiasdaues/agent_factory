# Code review of ST-0438, run a measure that needs a running service within one time limit

## Verdict

ST-0438 does not pass the code review. One `major` defect blocks the story: IMPL-0072. Two `minor` findings go to the register, IMPL-0073 and IMPL-0074, and the report records three notes.

`crap-score` now runs the `ready` command before the measuring command, under one time limit for the whole run, and holds an `flock` per measure with a `ready` command. The order, the stop at the limit, the lock wait, and the release of the lock after `SIGKILL` work as BR-129, DEC-43 and DEC-47 state. IMPL-0072 concerns a run that `SIGTERM` or Ctrl-C stops. Its command keeps running in its own session after the lock is gone, so the next run overlaps it.

Next, the developer agent fixes IMPL-0072 on `story/ST-0438`, commits this report and the three finding files, and submits the story for review again.

## Scope

The review covers the diff `290a619f...4e1e51df`: one merge of the feature branch and two story commits. The diff changes five files:

- `packages/factory/scripts/crap-score`: the field `ready` in `_measures`, and the new `Clock`, `_signal_group`, `_stop_group`, `run_command` and `measure_lock`. `run_measure` and `measure_all` take the clock.

## Focus areas

| Focus area         | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Correctness        | The order `ready`, measuring command, next measure holds, also with `enabled: false`. A failing `ready` command stops the run with exit 2 and names the measure, the command and its message. One `Clock` covers every lock wait and every command. At the limit, `_stop_group` sends `SIGTERM` to the group and `SIGKILL` after 5 seconds, also when the leader has exited, so the child process of CG-04-IT-08 ends. The lock lies under `--git-common-dir`, and a measure without `ready` opens no file. IMPL-0072 is the gap: the lock ends with `crap-score`, but the command does not. |
| Clean Architecture | The changes stay inside `crap-score`. Reading the settings, running the commands, and judging the rows remain separate steps. `run_command` and `measure_lock` each have one job.                                                                                                                                                                                                                                                                                                                                                                                                            |
| SOLID              | No violation. `measure_lock` is a context manager, so `run_measure` cannot forget to release the lock.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Maintainability    | The lock descriptor comes from `os.open`, which Python makes non-inheritable, and `Popen` closes other descriptors by default, so no command holds the lock. The commands write to temporary files, not pipes, so a child process that keeps the output open cannot block `crap-score`. Every test carries `@pytest.mark.spec` and builds its repository in `tmp_path`. CG-04-IT-16 asserts the overlap that IMPL-0072 describes and must change with the fix. IMPL-0073 and IMPL-0074 concern the timing margins and the missing `ready` case.                                              |
| Consistency        | The message of a failing command keeps the earlier form, "the measuring command of measure X exited N", and adds the same form for the `ready` command. The module header gains a section Runs. The spec-feedback report records the two gaps of BR-128 and BR-129 with owners.                                                                                                                                                                                                                                                                                                              |
