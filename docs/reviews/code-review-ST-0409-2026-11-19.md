# Code review of ST-0409, prepare-story in a run by hand

## Result

The review found no blocking defect, so ST-0409 can merge. It filed two `minor` register files, IMPL-0028 and IMPL-0029, and the report holds three notes.

In a run by hand, `prepare-story` now cuts `story/<id>` from the tip of the feature branch, checks it out in the primary checkout, writes the step manifest and the handoff contract, and runs `verify-base`. It gives an entry without a wave the next free wave number and refuses while a dependency is open or the previous wave has no record. The orchestrated path behaves as before.

IMPL-0028 covers one gap in the rollback: a failing post-checkout hook leaves the primary checkout on the story branch. IMPL-0029 covers a ledger of one repository that is used from a checkout of another one. Both need an unusual setup, and neither blocks the merge.

Next, the Implementation Agent merges ST-0409. The developer of a later story, or a bug-fix pass, takes up the two register files.

## Correctness

**The orchestrated path behaves as before.** `cmd_prepare_story` now loads the ledger with `_load_ledger` and sends a ledger with `mode: by-hand` to `_prepare_story_by_hand` before any other step. Every other ledger reaches the same code as before: the seams-first branch, the chain predecessor, the worktree, and `verify-base`. The status refusals moved into `_pending_entry_error`, and the messages are the same text, because `story_id` and `entry.id` hold the same value. The suite for the orchestrated path passes unchanged. Note N1 names the one difference: a ledger with an unknown mode no longer gets a refusal.

**The command follows the contract by hand.** The story branch starts at the tip of the feature branch, and no worktree is added. The manifest and the contract land in `.current-work/<feature-branch>/story/<id>/` of the primary checkout, as the contract says. The entry gets `branch`, `base_sha`, and `prepared`, and `worktree` stays empty. RL-03-IT-01 checks each of these values.

**The checks of BR-113 and BR-064 hold.** Only dependencies inside the run count, and each one must be `done`. An entry without a wave takes the highest wave of the run plus one. A wave that `dispatch add` wrote stays. The command refuses while the previous wave has no wave record, and it names `close-wave`. The tests check the open dependency, the next free wave, and the missing record. The refusal of a returned entry is out of reach, because the ledger has no `returned` field yet, as the story says.

**The rollback after a failed `verify-base` restores the earlier state.** The review checked three starting points in a scratch repository. From branch `topic`, the checkout returned to `topic` at the same commit, and the new story branch was gone. From a detached HEAD, the checkout returned to the same commit. With a leftover `story/ST-0350` at the feature tip, the checkout returned to `topic`, and the leftover branch stayed, because the call did not create it. In each case the entry stayed `pending`.

**The rollback after a failed checkout misses one case.** When a post-checkout hook fails, git has already switched the branch. The code then passes no earlier branch to the undo, and its `branch -D` fails on the checked-out branch. IMPL-0028 records this.

**The command works only in the primary checkout of the current repository.** Every git command runs with `-C <main_root>` or reads a shared ref, so a call from a linked worktree still changes only the primary checkout. The manifest, the contract, the `verify-base` marker, and the story file it reads all sit in that primary checkout. The primary checkout comes from the current directory, though, not from the ledger. IMPL-0029 records the case of a ledger from another repository.

**RL-02-IT-01 pins behaviour that exists.** `mark-dispatching` and `mark-dispatched` already load a ledger of either mode. The test brings a story from `prepare-story` to `dispatched` in the primary checkout.

## Architecture, SOLID, maintainability, consistency

The by-hand path is one function with three small helpers: `_pending_entry_error`, `_wave_by_hand`, and `_undo_checkout_by_hand`. Each helper has one job. `_pending_entry_error` now serves both paths, so the two refusal texts have one home. The orchestrated `cmd_prepare_story` stays long, but the commit makes it shorter, not longer.

`_prepare_story_by_hand` follows the order of the orchestrated path: checks, branch, `verify-base`, manifest, ledger. It reuses `_write_story_manifest`, `_run_verify_base`, and `_branch_tip`. The refusal of a leftover branch with work uses the rule of BUG-0084.

The tests use the `run_repo` fixture of the same module and name each scenario in a `spec` marker and in the docstring. No test drives a rollback by hand; IMPL-0028 asks for one.
