- `PYTEST` of `tests/select_tests.py` holds the same words as `TEST_COMMAND`, so both runs use the same markers and the same options.
- The selector passes test files below `tests/`, and `testpaths` of `pyproject.toml` is `["tests"]`. No `conftest.py` and no setting ignores or deselects tests, so an explicit file runs the same tests as in the full run.

## Second repeat pass on 193633ad

The fallback answers the question of the coordinator. On a line that does not pair one to one, a non-zero record keeps every function of the line on its line count. A function that never ran then shows the coverage of the line, which is 100 % for a one-line function and often more than 0 % for a longer one. So the fallback can make an uncalled function look covered. `split-property` is one way to reach it; any other mismatch of record lines and range lines reaches it too. At `c23aa019` the same file stopped with exit `1`, so the wrong row is new.

The three new tests assert `box.assigned` at 0 %, two functions on one line with only the second called, and the row `Box.f`. The four Python test files passed 77 tests on `193633ad`.

## Third repeat pass on 2a25983e

The diff `193633ad..2a25983e` pairs each function by the line of the function node itself. Any function that does not pair with exactly one record gets 0 %, and the fallback to the line count is gone. This pass blocks only on a wrong pass, as the coordinator asked.

| Check                                                                                       | Result                                                                                                                                     |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `repro_typescript.sh` cases `one-line`, `property-function`, `member-assign`, `class-field` | Unchanged from the second repeat pass                                                                                                      |
| `repro_typescript.sh` case `split-property`                                                 | `pick` 0 % (was 100 %), `used` 100 %, so IMPL-0111 is resolved                                                                             |
| One test file calls `outer(0)` and `later()` on one line                                    | Rows right: the callback 0 %, `later` 100 %; lcov keeps the source order                                                                   |
| `repro_typescript.sh` case `two-processes`: the same calls in two test files                | The callback of complexity 6 gets 100 %, and `later` gets 0 %, in four runs of four; the merged record lists the callback last (IMPL-0112) |

The pairing by order is safe only while lcov lists the records of a line in source order. Node keeps that order for one test process. For several processes, it merges the records, and a function that only one process created moves to the end of its line. A count can then move from a called function to an uncalled one, which is a wrong pass. The new 0 % rule for a line that does not pair one to one does not help here, because the number of records still matches.

The three new tests assert `split-property` uncalled at 0 % and called at 100 %, and both functions at 0 % on a line with one record. The four Python test files passed 78 tests on `2a25983e`.
