## The Python measure

The command names no path under `.agent-factory/`. The copy in `.agent-factory/` of the main checkout is older and lacks `SELECT_COMMAND`. The repository copy follows the source template of ST-0451, which is the right base.

The selector cannot make a function look more covered:

- `PYTEST` of `tests/select_tests.py` holds the same words as `TEST_COMMAND`, so both runs use the same markers and the same options.
- The selector passes test files below `tests/`, and `testpaths` of `pyproject.toml` is `["tests"]`. No `conftest.py` and no setting ignores or deselects tests, so an explicit file runs the same tests as in the full run.
- A change of `tests/conftest.py`, `pyproject.toml` or `uv.lock` selects `tests`, the whole suite.
- The selector process only reads the text of the changed files and runs none of them.

So the selected tests are a subset of the full run, and coverage can only fall. When the selector selects no test, the command exits 1 with "coverage recorded no data for the test run: No data to report". The full run gives "coverage cannot reach" for the same script. The gate exits 2 in both cases, and no story passes wrongly.

## Repeat pass on c23aa019

The diff `8c4bc215..c23aa019` changes `scripts/crap-measure-typescript` and `tests/factory/test_crap_gate_repository.py`, and adds this report and the four finding files. The command now reads the lcov records `FN` and `FNDA` and merges them over the records of one file. It gives 0 % to a function whose record has the count 0, and to every function inside such a function. The rule crap/range takes the Property as the outer node of a function expression value.

| Check                                                                           | Result                                                                                                    |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `repro_typescript.sh` case `one-line`                                           | `pick` 0 % (was 100 %), `(anonymous)@10` 0 % (was 33.33 %); `used` and both callbacks that ran keep 100 % |
| `repro_typescript.sh` case `property-function`                                  | Exit `0`, one row `first` with complexity 2 (was exit `1`)                                                |
| A called function with an uncalled and a called inner function                  | `outerCalled` 100 %, `outerCalled.inner` 100 %, `outerCalled.unused` 0 %                                  |
| An uncalled function with an inner function                                     | `outerUncalled` 0 %, `outerUncalled.inner` 0 %                                                            |
| A method, `export default`, and two functions on one line                       | `K.m` 0 %, `default` 0 %, `never` 0 %, the `map` callback on the same line 100 %                          |
| `repro_typescript.sh` case `member-assign`: `box.pick = …`, which no test calls | `pick` 100 %; lcov names the record `box.pick`, so no record matches (IMPL-0109)                          |
| `repro_typescript.sh` case `class-field`: `f = (a) => …` in a class             | Exit `1`, "pairs with no single function", as at `8c4bc215` (IMPL-0110)                                   |

A 0 % from the nesting rule cannot hide a called function. A function inside another function exists only after the outer function ran. So the rule can only lower coverage, and only when a name match goes wrong. A wrong match needs two functions on one line whose names from ESLint and from V8 differ, and it then gives 0 %, which DEC-84 allows.

The five new tests assert the 0 % cases, the row of the object value and the three failure cases. Each failure test asserts a non-zero exit, the cause and no output file. IMPL-0107 is therefore resolved. The four Python test files passed 76 tests on `c23aa019`.
