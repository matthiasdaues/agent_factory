# Code review of ST-0443, block a story at the merge when the CRAP gate cannot measure

## Verdict

ST-0443 passes the code review. The review filed no blocking finding. It filed one `minor` finding, IMPL-0082, as a register file, and five notes that stay in this report.

`premerge-check` exits `3` only when a gate could not measure and every other check that ran passed. A failed `ready` command stops the check before the gates and the test suite. `dispatch merge-story` turns exit `3` into `blocked` with the reason `gate cannot measure: crap-score`, on both ways, and merges nothing. The review found no path on which `merge-story` counts an attempt or merges after exit `3`. The section [Exit 3 against exit 1](#exit-3-against-exit-1) gives the cases the review traced.

Next, the developer agent commits this report and the register file on `story/ST-0443`. Then the implementation agent runs the gate-check step.

## Exit 3 against exit 1

The review traced each case through `main`, `check_story_gates` and `cmd_merge_story`.

| Case                                                  | `premerge-check` | `merge-story`                                     | Test                                |
| ----------------------------------------------------- | ---------------- | ------------------------------------------------- | ----------------------------------- |
| `crap-score` exits `2`, every other check passes      | `3`              | `blocked`, reason set, no attempt, no merge       | CG-08-IT-03, RL-06-IT-01            |
| `crap-score` exits `2`, `dependency-check` fails      | `1`              | `dispatched`                                      | CG-08-IT-04                         |
| `crap-score` exits `2`, the test suite fails          | `1`              | `dispatched`                                      | none; traced in `check_story_gates` |
| A `ready` command fails, every earlier check passes   | `3`, no suite    | `blocked`                                         | CG-08-IT-05, CG-08-IT-08            |
| A `ready` command fails, the review report is missing | `1`              | `dispatched`                                      | CG-08-IT-05                         |
| `quality-gates` names `crap-score` without an entry   | `1`              | `dispatched`, attempts unchanged                  | CG-11-IT-05                         |
| `crap-score` exits `1`                                | `1`              | `dispatched`; refusal names the failing functions | CG-08-IT-09                         |
| Exit `3` with `--dry-run`                             | `3`              | exit `1`, entry `dispatched`                      | CG-08-IT-03, dry-run row            |
| The rerun after a refused amend                       | not called       | no exit-3 branch                                  | existing BR-118 tests               |

`merge-story` cannot count an attempt on exit `3`. It appends no attempt itself, and `_block_gate_cannot_measure` returns before the merge, the dirty-worktree check, and the checkout by hand. A later `mark-failed` refuses, because `VALID_TRANSITIONS` allows only `prepared` and `pending` after `blocked`. A failed save of the ledger returns `1` with the entry still `dispatched` on disk.

After a failed `ready` command, the gates do not run, so a gate refusal such as RL-G09 does not count either. BR-136 asks for exit `3` when every check that ran passed, so this is the specified behavior. The User then sees the refusal of that gate after `resume-gates`.
