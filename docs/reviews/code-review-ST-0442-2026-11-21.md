## The run-tests hook

The developer reported that the `run-tests` hook exited `0` while its output showed a failing test. The review found no way for the hook to pass a red suite:

- The hook runs `uv run pytest --tb=short --quiet -n auto -m "not container"` with `language: system`. pytest exits `1` on a failing test, and `uv run` passes the exit code on.
- `pyproject.toml` sets no `addopts`, and no conftest changes the exit status.
- pre-commit shows the output of a hook only when the hook fails, because no hook sets `verbose: true`. So output with a failing test comes from a failed run, for example the first pass of a two-pass commit.
- A scratch repository with the same hook and one failing test made `pre-commit run --all-files` exit `1` and print `1 failed`.
- The full suite at `1d7ea364` passed.
