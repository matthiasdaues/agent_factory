# Code review of ST-0426, the cleanup of old runs with dispatch close --orphans

## Result

The review found two blocking findings, so ST-0426 goes back to the developer agent. On each path, `--orphans` removes something that a live run owns:

- IMPL-0045 (`major`): when a live run's ledger lies inside a linked worktree and dispatch cannot read a feature branch from it, `--orphans` stashes and removes the worktrees of that run.
- IMPL-0046 (`major`): the walk for ledgers reads the whole checkout of every worktree under `.current-work/`. It deletes a project file named `dispatch-ledger.yaml` there, also in a live run's worktree, without a stash.

The review also filed three `minor` register files. IMPL-0047 records that a locked worktree loses its changes to a stash before the removal fails. IMPL-0048 records that a symlinked run folder hides a live ledger from the walk. IMPL-0049 records three paths of `--orphans` that no test checks.

The rest of `--orphans` holds. A ledger whose feature branch exists keeps every worktree in its folders, on its branches, and in its story entries, also when every branch is merged into `dev`. A detached HEAD, a missing `dev`, an unmerged branch, a held ledger, a held worktree, and the folder dispatch runs in each keep the worktree. Every removal stashes first with `--untracked-files=all`, a failure stops the run with exit `1`, and no branch is deleted.

Next, the developer agent fixes IMPL-0045 and IMPL-0046 on `story/ST-0426`, and the code review runs again.

## Correctness

### What a live run keeps

A ledger whose feature branch exists is live. `orphan_ledger_verdict` returns "stay, no line" for it before it reads any story. `_claim_of` then gives the live ledger its folder, `.current-work/<feature-branch>/` of the primary checkout, the worktree of each story entry, and the branches `story/<id>`, `branch`, and `feature_branch` of each entry. A worktree that any of these matches stays. So a story worktree of a live run stays when its branch is merged into `dev`, when it lies outside the run folder, and when the ledger records a wrong path. The live run of this repository has its ledger in the primary checkout's `.current-work/feature/run-lifecycle/` and every worktree below it, so the folder claim alone keeps them.

The claim has one hole. A ledger that stays but yields no feature branch, because dispatch cannot read it or it names none, claims only its own folder. In the layout that `cmd_init` makes when it runs in a linked worktree, that folder is not where the worktrees are (IMPL-0045). The Analysis calls this fallback "fails closed", but it claims less than the normal path.

### What the walk finds

`_find_ledgers` walks `.current-work/` of the primary checkout and of each registered worktree, and it follows no symlink. Below `.current-work/` it also descends into each worktree checkout, so it reads project files as ledgers (IMPL-0046). A symlinked folder is skipped without a line, so a ledger behind it stays unseen (IMPL-0048).

### What it removes

Ledgers go only when `check-ref-format --branch` prints the feature branch back unchanged, the branch does not exist, and every story is `done`. A worktree goes only when it lies under `.current-work/` of the primary checkout, is not the primary checkout, is not `.current-work/` itself, exists on disk, and no claim owns it. `_orphan_keep_reason` then keeps it for the folder dispatch runs in, a detached HEAD, a missing `dev`, a branch that is not an ancestor of `dev`, a failed `merge-base`, a ledger that stays below it, or a registered worktree below it. The deepest worktrees go first, and the worktree list is read again before each one.

### Order and stops

Each removal runs `_stash_and_remove` of BR-119. It reads `git status --porcelain --untracked-files=all`, stashes in that worktree with `git -C <worktree> stash push --include-untracked -m "orphan <branch> <date>"`, and only then runs `git worktree remove` without `--force`. A failed `git worktree list`, ledger unlink, `git status`, stash, or removal stops the run with exit `1`. The new code runs no `git branch` command, and the probe left every branch in place. The stash comes before the removal, so a failed removal leaves the work in a listed stash. For a locked worktree, that order empties the checkout (IMPL-0047).

The ledgers go before the worktrees. That order is safe, because a removed ledger claimed nothing, and a later stop leaves the remaining worktrees for a rerun.

### The stop of BR-091 and the parser

`--orphans` is part of `close`, which is in `READ_SUBCOMMANDS`, and `test_RL_14_IT_08_a_stop_allows_dispatch_close_orphans` covers it. `--drop` and `--orphans` form a mutually exclusive group, so `argparse` refuses both together with exit `2`. `main` skips the default ledger for `--orphans`, so several ledgers raise no `LedgerChoiceError`.

## Architecture, SOLID, maintainability, consistency

The decision on a ledger, `orphan_ledger_verdict`, is pure and lives in `dispatch_lib.py` beside `close_refusals`, with a contract test of six rows. The git work stays in `dispatch`, split into small helpers with one job each. `_LedgerClaim` keeps the ownership rules in one place. Its `owns` method mixes three rules, folder, entry, and text, which is readable at this size. The new code calls git through `_git_in`, as `close` does, so it does not depend on the folder it runs in.

The output lines follow the style of `close`: `stash:`, `removed ...:`, `kept ...: (<reason>)`, and a last line with `done`. The tests carry `@pytest.mark.spec` with the Test IDs of the QA strategy, build their repositories in `tmp_path`, and run `dispatch` as a subprocess. Three fail-closed paths have no test (IMPL-0049).
