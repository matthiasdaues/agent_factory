# Bug hunt across the factory source repository

## Summary

Six agents hunted for bugs in parallel, one per area. They found 72
distinct defects after duplicates were merged: 11 critical, 38 major, and 23
minor. No finding is filed as a `docs/findings/` file yet, and nothing is
fixed. The user decides which findings to file and in which order to fix
them.

Four results need attention first:

1. **Usage capture has recorded nothing since 2026-09-24.** Three separate
   defects each stop every record ([X-1](#x-1--capture-hooks-look-for-the-usage-runtime-in-the-old-layout), [U-1](#u-1--usage-capture-runtime-finds-the-project-root-one-level-too-low), [U-2](#u-2--usage-capture-reads-the-project-identity-from-the-wrong-path)).
   This repository's `.agent-factory/usage/records/` directory is empty.
2. **Dispatch can lose merged work.** A story with no commits passes the
   checks, and a red test suite then hard-resets the previous story's merge
   away, together with uncommitted edits ([D-2](#d-2--an-empty-story-passes-and-a-red-suite-wipes-earlier-merges)). `merge-story` also
   merges into whatever branch the calling checkout has open ([D-1](#d-1--merge-story-merges-into-the-wrong-branch)).
3. **Several safety gates fail open.** The step guard never runs
   ([G-1](#g-1--the-step-guard-never-runs-and-its-denials-would-not-block)). Four lint gates exit 0 at exactly 256 errors
   ([L-1](#l-1--four-gates-exit-with-the-error-count)). Consumer gates pass without running in every worktree
   ([G-10](#g-10--consumer-gates-pass-without-running-in-worktrees)). The git guardrail lets simple variants such as
   `git -C . commit` through ([G-2](#g-2--the-verify-base-and-premerge-gates-are-easy-to-get-around)).
4. **The documented update command fails.** The session menu and the
   orientation files tell agents to run `init-factory --update .`, which
   exits with a usage error ([X-3](#x-3--the-documented-update-command-does-not-exist)).

## How the hunt worked

Each agent worked in its own scratch directory and changed nothing in the
repository. Each agent ran the source scripts under `packages/factory/` against
scratch projects and marked every bug with its evidence:

- **reproduced**: the agent ran commands and saw the wrong behavior.
- **code reading**: the agent found the fault in the code but did not run
  it.
- **checked**: the main session also confirmed the fault against the code or
  the repository while compiling this report. This was done for every
  critical finding and for a sample of major ones.

The six areas were the install lifecycle, guardrails and gates, dispatch and
routing, lint gates, usage capture and tools, and instructions against
reality. The section [Not covered](#not-covered) lists what the agents did
not reach.

## Causes shared by many findings

Most of the 72 findings come from four causes. Fixing a cause fixes several
findings at once.

- **Three directory layouts.** The factory lives at `factory/` (an old
  layout that no longer exists), at `.agent-factory/factory/` (an installed
  project), and at `packages/factory/` (this source repository). Hooks,
  scripts, rules, and skills still name the old layout or the wrong one. This
  cause explains [X-1](#x-1--capture-hooks-look-for-the-usage-runtime-in-the-old-layout), [X-2](#x-2--51-instruction-lines-name-the-old-factory-layout), [G-1](#g-1--the-step-guard-never-runs-and-its-denials-would-not-block), [G-9](#g-9--seven-source-repository-hooks-fail-without-agent-factory),
  [G-10](#g-10--consumer-gates-pass-without-running-in-worktrees), [U-1](#u-1--usage-capture-runtime-finds-the-project-root-one-level-too-low), [U-2](#u-2--usage-capture-reads-the-project-identity-from-the-wrong-path), [D-11](#d-11--model-resolution-fails-open-on-a-malformed-modelconf), and
  [R-8](#r-8--the-validate-skill-looks-for-modelconf-in-the-wrong-place).
- **Gates that fail open.** A missing script, a missing directory, an
  unparsable file, or an error count of 256 ends in exit code 0. A gate
  that cannot check should fail loudly. See [L-1](#l-1--four-gates-exit-with-the-error-count), [L-5](#l-5--module-graph-check-reports-no-change-for-input-it-could-not-parse),
  [L-10](#l-10--gates-pass-on-a-directory-that-does-not-exist), [G-10](#g-10--consumer-gates-pass-without-running-in-worktrees), [D-11](#d-11--model-resolution-fails-open-on-a-malformed-modelconf), [D-12](#d-12--session-reconcile-fails-open),
  [U-8](#u-8--dependency-check-passes-files-it-cannot-parse), and [U-12](#u-12--housekeeping-about-reports-a-dead-pipeline-as-healthy).
- **Pattern matching instead of parsing.** The git guardrail matches
  substrings of a command line, so quoting, option order, and git's own
  abbreviations defeat it. See [G-2](#g-2--the-verify-base-and-premerge-gates-are-easy-to-get-around) to [G-5](#g-5--the-guardrail-denies-harmless-commands).
- **The orientation record changed shape.** Orientation entries in
  `install.json` can be a string or a dictionary. Code that compares with
  the string `"injected"` misses dictionary entries. The fix for
  [BUG-0032](../findings/BUG-0032.md) keeps dictionaries on purpose, so it
  makes [I-2](#i-2--remove-factory-leaves-headers-recorded-as-dictionaries) more frequent.

## Cross-cutting findings

### X-1 — Capture hooks look for the usage runtime in the old layout

Critical. Reproduced and checked.

  `capture-codex-usage.sh:22`, `capture-copilot-usage.sh:23`,
  `pi-capture-bootstrap.mjs:72`.
- **What happens:** Each hook checks
  `$PROJECT_DIR/factory/scripts/usage-capture-runtime`. That directory does
  not exist, so the hook exits 0 without a message and records nothing.
- **Fix:** Point all four at `.agent-factory/factory/scripts/`. Add a test
  that runs the hook against an installed layout.

### X-2 — 51 instruction lines name the old `factory/` layout

Major. Reproduced by a bulk check.

- **Location:** for example `rules.md:113`, `rules.md:114`, `rules.md:156`,

- **Fix:** Use `.agent-factory/factory/scripts/` in shipped text, and

### X-3 — The documented update command does not exist

Critical. Reproduced and checked.

- **Location:** `packages/factory/config/session-menu.md:54`,

### X-4 — The freshness hook reads a manifest that does not exist

  The installer writes `.agent-factory/install.json`. The hook never warns

## Install lifecycle

### I-1 — `build-release` deletes an existing output directory

Critical. Reproduced and checked.

- **Location:** `packages/factory/scripts/build-release:145-148`, `:153-156`,
  `:181-184`.
- **What happens:** On every failure path, the script deletes the output
  directory, even one that existed before the run. With
  `--output ../precious`, an existing `important.txt` was gone and the
  script printed nothing. `--output .` would delete the working tree. The
  archive is also built from the working tree, so untracked `__pycache__`
  files and uncommitted changes end up in a "reproducible" release.
- **Fix:** Delete only files this run created, and print the reason for the
  failure. Build the archive from `git archive` or `git ls-files`.

### I-2 — `remove-factory` leaves headers recorded as dictionaries

Major. Reproduced and checked.

- **Location:** `remove-factory:128-130`; `_codex_artifact_owned` at
  `remove-factory:433`.
- **What happens:** The script strips a header only when the entry equals
  the string `"injected"`. Installs and updates now store dictionaries, so
  after install and removal `AGENTS.md` still carries the orientation block.
- **Fix:** Read `entry["status"]` when the entry is a dictionary, and take
  the newline record from the entry.

### I-3 — The bootstrap installer writes its header into the installed factory

Major. Reproduced.

- **Location:** `install-agent-factory:870-897`, `:938-958`.
- **What happens:** For Codex, Pi, and Copilot installs, `AGENTS.md` is a
  symbolic link into `.agent-factory/factory/config/`. The installer writes
  its header through the link and marks the entry "injected". The next
  `update-factory` sees a user change and refuses to run without `--force`.
- **Fix:** Skip symbolic links and files that `init-factory` linked.

### I-4 — The Claude orientation header points outside the project

Major. Reproduced.

- **Location:** `install-agent-factory:41-43`, `:905-907`.
- **What happens:** The root `AGENTS.md` starts with
  `@../../.agent-factory/factory/config/AGENTS.claude.md`. From the project
  root, that path resolves above the project. Every nested `AGENTS.md` gets
  the same fixed text.
- **Fix:** Compute each include path relative to the file it is written
  into.

### I-5 — `remove-factory` leaves the freshness hook wired

Major. Reproduced.

- **Location:** `remove-factory:63-73`; the command is defined at
  `init-factory:176`.
- **What happens:** After removal, `.claude/settings.json` still runs
  `check-factory-freshness.sh` before every Bash call, but the script is
  gone.
- **Fix:** Add the freshness command to the strip list and remove the empty
  `.claude/hooks/` directory.

### I-6 — `update-factory` wires command-line tools the user never chose

Major. Reproduced.

- **Location:** `update-factory:367-375`; `init-factory:4393-4396`.
- **What happens:** `update-factory` calls `init-factory` without `--cli`,
  so `init-factory` guesses from folders. A Claude-only project with
  `.github/workflows/` gains Copilot wiring after an update.
  `init-factory --remove copilot` does not last for the same reason.
- **Fix:** Pass the `cli` list from `install.json` to `init-factory`.

### I-7 — Smaller install and removal faults

Minor. Mostly reproduced.

- `remove-factory` rewrites `.claude/settings.json` instead of restoring it
  byte for byte.
- When Codex is added after a Claude install, the original
  `.codex/hooks.json` is never saved (`init-factory:1482-1485`).
- The receipt prints the uninstall command with an unquoted path, which
  breaks for paths with spaces.
- A local update rewrites `install.json` to `"version": 1` and drops
  `resolved_source` and `archive_sha256`.
- `migrate-layout --dry-run` always reports that `install.json` is missing
  (`migrate-layout:91-95`, code reading).
- `remove-factory` deletes an empty `.codex/` directory that existed before
  the install.

## Guardrails and gates

### G-1 — The step guard never runs, and its denials would not block

Critical. Reproduced and checked.

- **Location:** `packages/factory/config/hooks/step-guard.sh:13`;
  `step-guard:300-334`.
- **What happens:** The hook looks for `$PROJECT_DIR/factory/scripts/step-guard`.
  That path does not exist, so the hook exits 0 on every Read, Edit, Write,
  and Bash call. The manifest boundary in `rules.md` is not enforced.
  Second, `step-guard` returns 1 on a denial, and Claude Code blocks a tool
  call only on exit code 2.
- **Fix:** Use the installed path, and turn a denial into exit code 2.

### G-2 — The verify-base and premerge gates are easy to get around

Major. Reproduced.

- **Location:** `config/hooks/block-dangerous-git.sh:50`, `:113`.
- **What happens:** Both gates match only commands that start with
  `git commit` or `git merge`. These all passed in a worktree without a
  marker: `git -c user.name=a commit`, `git -C . commit`,
  `command git commit`, `GIT_X=1 git commit`, `(git commit …)`,
  `cd . && git commit`, and the repository's own `commit-safe`. The merge
  gate let `git -C . merge …` and `git pull . story/ST-0001` through.
- **Fix:** Split commands at shell separators, strip environment prefixes
  and `command`, parse git's global options, and treat `pull` as a merge.
  `commit-safe` should check the marker itself.

### G-3 — Hook bypasses and destructive commands pass the pattern list

Major. Reproduced.

- **Location:** `block-dangerous-git.sh:134-164`.
- **What happens:** `git commit -nm x`, `git commit --no-verif`, and
  `git -c core.hookspath=/dev/null commit` all committed past a failing hook.
  Destructive commands also passed: `git  push` with two spaces,
  `git reset -q --hard`, `git clean -xdf`, `git branch --delete --force x`,
  `git checkout -- .`, `git restore --worktree -- .`, and `git stash clear`.
- **Fix:** Parse the git subcommand and its options, including bundled short
  flags, abbreviations, and configuration keys in any letter case.

### G-4 — The branch and worktree rules leak

Minor. Reproduced.

- **Location:** `block-dangerous-git.sh:85-110`.
- **What happens:** `git switch --create x`, `git checkout -bx`, and
  `git checkout --orphan x` create branches without a worktree. The path
  `.current-work/../../escape` passes, while the valid
  `./.current-work/z` is denied.
- **Fix:** Resolve the path before checking it, and cover the long and
  attached option forms.

### G-5 — The guardrail denies harmless commands

Minor. Reproduced.

- **Location:** `block-dangerous-git.sh:119-151`.
- **What happens:** These are denied:
  `git commit -m "docs: explain why git push is blocked"`,
  `grep -rn "reset --hard" docs`, and `git log --grep="git push"`. In
  `git merge --no-ff -m "merge msg" story/ST-0001`, the message is read as
  the branch name.
- **Fix:** Split quoted text into tokens, and skip the values of options
  such as `-m`.

### G-6 — A stale premerge marker allows an unchecked merge

Major. Reproduced.

- **Location:** `premerge-check:79-88`, `:375-385`.
- **What happens:** The marker records only the branch and its head, not the
  target. A failed run does not delete it. After a pass against `dev` and a
  `BLOCK` against `main`, `git merge feat` on `main` was allowed.
- **Fix:** Clear the marker at the start of every run, record the target and
  its head, and compare them in the guardrail.

### G-7 — A verify-base marker survives a branch switch

Minor. Reproduced.

- **Location:** `block-dangerous-git.sh:61-64`; `verify-base:118-130`.
- **What happens:** The guardrail checks only that the marker's head is an
  ancestor of `HEAD`. After `git switch other2` in the same worktree, a
  commit was allowed without a new check. `--expect-base` accepts any
  ancestor, so it does not prove where the branch was cut.
- **Fix:** Record the branch in the marker and compare it.

### G-8 — `commit-safe` commits unrelated changes

Major. Reproduced.

- **Location:** `commit-safe:43`.
- **What happens:** After a hook modifies files, the second pass runs
  `git add -u`, which stages every modified tracked file. Work in progress in
  another file ended up in the commit. `commit-safe -m` without a value
  exits 1 and prints nothing.
- **Fix:** Re-stage only the paths that were staged before the first pass.

### G-9 — Seven source-repository hooks fail without `.agent-factory/`

Major. Reproduced.

- **Location:** `.pre-commit-config.yaml:122`, `:129`, `:136`, `:143`,
  `:151`, `:158`, `:172`.
- **What happens:** `mdformat`, `link-check`, `spec-lint`, `arch-lint`,
  `backlog-lint`, `concern-lint`, and `statemachine-lint` run the installed
  copy. In a worktree or a fresh clone, they fail with "No such file". Every
  worktree commit that touches matching files is blocked. The eighth hook,
  `matrix-lint`, has the same path but never runs
  ([BUG-0029](../findings/BUG-0029.md)).
- **Fix:** Run the scripts from `packages/factory/scripts/`, as the
  `index-lint` hook now does.

### G-10 — Consumer gates pass without running in worktrees

Major. Reproduced.

- **Location:** `packages/factory/config/pre-commit-config.yaml:29-113`.
- **What happens:** Every entry starts with `[ -d .agent-factory ] || exit 0`.
  A worktree has no `.agent-factory/`, so `mdformat` and `spec-lint`
  reported "Passed" without running. Automated commits are made in
  worktrees, so they skip every Factory gate.
- **Fix:** Find the main checkout's `.agent-factory/` through
  `git rev-parse --git-common-dir`, or fail loudly.

### G-11 — `merge-precommit-config` adds duplicate hooks

Minor. Reproduced.

- **Location:** `merge-precommit-config:247`, `:276-278`.
- **What happens:** The "already merged" check looks for
  `agent_factory_hook-mdformat`. The merge step removes that hook when the
  project runs its own mdformat. Two runs and one `--update` left three
  copies of `agent_factory_hook-link-check`.
- **Fix:** Detect an earlier merge by the `agent_factory_hook-` prefix.

## Dispatch and routing

### D-1 — `merge-story` merges into the wrong branch

Critical. Reproduced and checked.

- **Location:** `packages/factory/scripts/dispatch:1528-1545`.
- **What happens:** `premerge-check` checks the invocation branch, but
  `git merge` runs on the branch the calling checkout has open. Run from the
  main checkout on `dev`, as `implementation-agent.md` describes, the story
  merge landed on `dev`, and the invocation branch did not move.
- **Fix:** Run the merge in the invocation worktree with `git -C`, or refuse
  when the current branch is not the invocation branch.

### D-2 — An empty story passes, and a red suite wipes earlier merges

Critical. Reproduced.

- **Location:** `dispatch:1383`, `:1487`, `:1538`, `:1584`.
- **What happens:** `verify-story` accepts a commit equal to the base.
  `merge-story` then treats the empty branch as already merged, skips
  `premerge-check`, and takes `HEAD^1` as the state before the merge. With a
  failing test command, it ran `git reset --hard` to that guess. The
  previous story's merge and uncommitted edits in the checkout were lost.
  With a passing suite, the empty story is marked `done` with an unrelated
  merge SHA.
- **Fix:** Reject a commit that is not ahead of the base. Treat a story as
  already merged only when `HEAD` is a merge whose second parent is the story
  tip. Never reset to a guessed parent.

### D-3 — The ledger's `branch_head` is never updated

Critical. Reproduced.

- **Location:** `dispatch:775`; the only assignment is at `dispatch:586`.
- **What happens:** After wave 1 merged and closed, `prepare-wave 2` cut the
  next story from the original root. The dispatch contract says
  `branch_head` is updated after each merge and wave closeout.
- **Fix:** Set `branch_head` in `merge-story` and `close-wave`.

### D-4 — Story dependencies are never filled

Major. Reproduced.

- **Location:** `dispatch:575`, `dispatch:633`; `dispatch_lib.py:400-405`.
- **What happens:** `init` and `plan` do not copy dependencies from the
  story frontmatter. `next_ready` therefore lists a story whose dependency is
  still pending, and `prepare-story` always reports "has no chain
  predecessor recorded". Even with dependencies filled, `next_ready` counts a
  failed or blocked dependency as satisfied.
- **Fix:** Copy the dependencies from the frontmatter, and require them to
  be done.

### D-5 — `close-wave` cannot commit the ledger

Major. Reproduced.

- **Location:** `dispatch:1674-1683`.
- **What happens:** `.current-work/` is ignored by git, so `git add` fails.
  The wave record is saved before the commit, so a second run exits 0
  without committing. Run from the invocation worktree, the command crashes
  with a `ValueError`.
- **Fix:** Decide whether the ledger is committed. If it is, use `add -f`
  and save only after the commit. If it is not, change the contract.

### D-6 — A partial failure in `prepare-wave` blocks the story for good

Major. Reproduced.

- **Location:** `dispatch:802-830`.
- **What happens:** When `worktree add` or `verify-base` fails, the branch
  made with `git branch` remains. Every retry fails with "A branch named
  'story/ST-0001' already exists". This also breaks the rule that a branch
  and its worktree are created together.
- **Fix:** Use `git worktree add -b`, and roll back or reuse on retry.

### D-7 — Two commands bypass the state machine

Minor. Code reading.

- **Location:** `dispatch:1281` (escalate: any state to blocked);
  `dispatch:906` (seams-first prepare-story: dispatched to prepared).
- **What happens:** Neither move is in `VALID_TRANSITIONS`.
- **Fix:** Route both through `ledger.transition`, or add the edges on
  purpose.

### D-8 — `mark-done` reaches done without verification or merge

Major. Code reading.

- **Location:** `dispatch:1070-1093`.
- **What happens:** The command moves a story from dispatched straight to
  done. The contract defines done as merged after `premerge-check`.
- **Fix:** Remove the command, or require a verified and merged commit.

### D-9 — A closed wave can get a running story back

Minor. Code reading.

- **Location:** `dispatch_lib.py:362-364`; `dispatch:1204`.
- **What happens:** `close-wave` counts a failed story as finished, but
  re-dispatch can return it to prepared. A second `close-wave` returns the
  old record unchanged.
- **Fix:** Refuse re-dispatch into a closed wave, or reopen the wave record.

### D-10 — The ledger can land in a feature worktree as an untracked file

Minor. Reproduced.

- **Location:** `dispatch:533`, `:565`.
- **What happens:** When `.current-work/` is not ignored and `init` runs
  without `--feature-branch`, the ledger is written into the feature
  worktree. A `git add -A` there commits it.
- **Fix:** Always write the ledger under the main checkout's
  `.current-work/`.

### D-11 — Model resolution fails open on a malformed `model.conf`

Major. Reproduced.

- **Location:** `resolve-model:105-108`; `trigger:133-137`.
- **What happens:** With `on_missing = halt  # fail closed`, an unconfigured
  tier exits 0 with empty output, which means the client silently picks a
  model. With `claude.strong = claude-opus  # top tier`, the resolver returns
  `claude-opus  # top tier` as the model ID, and `matrix-lint` does not
  flag it. `trigger` copies the resolver instead of sharing it. Run from the
  source tree, `resolve-model` looks for `packages/config/model.conf`, which
  does not exist.
- **Fix:** Treat any value other than `auto` as halt, strip or reject inline
  comments, and share one resolver.

### D-12 — `session-reconcile` fails open

Minor. Reproduced.

- **Location:** `session-reconcile:77-85`, `:119-124`, `:143-147`.
- **What happens:** An invalid `--base` is ignored. Outside a git repository,
  the script reports "0 error(s)" and exits 0. A JSON line that is not an
  object crashes it.
- **Fix:** Exit 2 on an invalid base or a missing repository, and skip
  lines that are not objects.

### D-13 — Nothing prevents duplicate story IDs across sessions

Major. Reproduced.

- **Location:** story ID allocation; `backlog-lint` (`BL-DUP-ID`).
- **What happens:** `backlog-lint` checks for duplicates only within one
  tree. Two parallel sessions can create the same `ST-NNNN`, and only a git
  add/add conflict at merge time shows it. A blocked story's leftover
  `story/<ID>` branch also blocks any later dispatch of that ID.
- **Fix:** Allocate IDs with a lock or a session prefix.

### D-14 — The Pi guard requires a different worktree directory

Minor. Code reading.

- **Location:** `packages/factory/config/extensions/block-dangerous-git.ts:57`.
- **What happens:** The Pi guard requires worktrees under
  `.current-work/worktrees/`. `branching-policy.md` and `dispatch` use
  `.current-work/<feature-branch>/`.
- **Fix:** Use the policy's path in the Pi guard.

## Lint gates

### L-1 — Four gates exit with the error count

Critical. Reproduced and checked.

- **Location:** `spec-lint:603`, `backlog-lint:629`, `context-lint:973`,
  `matrix-lint:237`.
- **What happens:** The exit code is the number of errors. Exit codes wrap at
  256, so 256 errors exit 0, which pre-commit reads as a pass. Two errors
  exit 2, which is the usage-error code.
- **Fix:** Return 1 when there are errors and 0 otherwise.

### L-2 — `conjecture-lint` cannot run

Major. Reproduced and checked.

- **Location:** `packages/factory/scripts/conjecture-lint` (git mode
  `100644`).
- **What happens:** The script is not executable. Running it gives
  "Permission denied". `research-topic.md:190` and the `claim-formulation`
  skill call it directly.
- **Fix:** Set the executable bit, and add a test that every script is
  executable.

### L-3 — `statemachine-lint` misses edges and one documented check

Major. Reproduced.

- **Location:** `statemachine-lint:188`, `:40`.
- **What happens:** The edge pattern requires spaces around `-->`, so
  `A-->C` is not seen. The documented check `SM-RESTORE-OOB` is never
  emitted. A diagram with two edges that the pseudocode lacks passed with 0
  errors.
- **Fix:** Allow optional spaces around the arrow, and implement the check.

### L-4 — Block-style `concerns:` escapes two gates

Major. Reproduced.

- **Location:** `backlog-lint:146`; `concern-lint` (`_parse_story_frontmatter`).

## Usage capture and tools

### U-1 — `usage-capture-runtime` finds the project root one level too low

Critical. Reproduced and checked.

- **Location:** `usage-capture-runtime:7`.
- **What happens:** `PROJECT_DIR=$SCRIPT_DIR/../..` lands on
  `.agent-factory/`, so the script looks for
  `.agent-factory/.agent-factory/usage/runtime`. Every capture fails with
  exit code 70.
- **Fix:** Go up three levels, or take the root from `--root`.

### U-2 — `usage-capture` reads the project identity from the wrong path

Critical. Reproduced and checked.

- **Location:** `usage-capture:1604`; test fixture
  `tests/integration/test_capture_independence.py:24`.
- **What happens:** The script reads `<root>/config/project.json`.
  `init-factory` writes `.agent-factory/config/project.json`. Every capture
  is dropped. The test seeds the same wrong path, so it passes.
- **Fix:** Read `.agent-factory/config/project.json`, and correct the
  fixture.

### U-3 — The Pi bootstrap leaks its pending marker and transcript copy

Major. Reproduced.

- **Location:** `pi-capture-bootstrap.mjs:72-73`, `:176-179`.
- **What happens:** The bootstrap rejects the launcher path it is given.
  Because `ctx` is never set, the cleanup does nothing, and the marker and
  transcript copy stay behind without a message.
- **Fix:** Correct the path, and clean up whenever the marker passed
  validation.

### U-4 — A stale pending entry blocks `remove-factory` for good

Major. Reproduced.

- **Location:** `remove-factory:527-530`, `:533-559`, `:571-578`.
- **What happens:** A leftover `.committing.json` entry makes both `drain`
  and `cancel` time out. A leftover `remove-owner` file with a dead process
  always reports "usage removal already in progress". A crash can leave the
  state in `drain` or `cancel`, and `init-factory` never resets it.
- **Fix:** Expire old `.committing.json` entries, treat an owner file with a
  dead process as stale, and have `init-factory` restore `active`.

### U-5 — Claude Code token counts are inflated

Major. Reproduced.

- **Location:** `usage-capture:974-990`.
- **What happens:** Claude Code writes one transcript line per content
  block, and each line repeats the message's usage. The normalizer adds every
  line. On a real transcript, output tokens came to 7,611 instead of 3,982,
  and cache reads to 574,421 instead of 372,773.
- **Fix:** Count usage once per message ID.

### U-6 — Record IDs collide, so analysis keeps one record per session

Major. Collision reproduced; the effect on analysis is from code reading.

- **Location:** `usage-capture:136`, `:143`, `:205-225`;
  `packages/usage/src/usage/accounting.py:41-48`.
- **What happens:** Each capture numbers its records from `-0001` again. Two
  captures of one session both produced `s1-0001`. The analysis groups by
  session and record ID, so subagent and main-session records of a session
  collapse into one.
- **Fix:** Give each record a unique ID, such as the transcript ID or a
  UUID.

### U-7 — One cut-off character drops a whole capture

Minor. Reproduced.

- **Location:** `usage-capture:941`, `:1059`, `:1180`, `:1294`.
- **What happens:** A strict UTF-8 read fails on a final line cut in the
  middle of a character. The stated rule is to skip bad lines.
- **Fix:** Decode with `errors="replace"`.

### U-8 — `dependency-check` passes files it cannot parse

Major. Reproduced.

- **Location:** `dependency-check:187-194`, `:85`.
- **What happens:** A file with a forbidden import and a syntax error passes
  the rule. A Latin-1 file crashes the gate. The default rules file is

### U-9 — `crap-score` shows covered code as 0 % covered
