# Code review of ST-0431, keep a run going after a finding is added

## Result

The review found one blocking finding, so ST-0431 goes back to the developer agent.

- IMPL-0061 (`major`, defect): `close-wave` records a wave that never held an entry. After `close-wave 3` while wave 2 runs, `add` gives wave 4, and `prepare-wave 4` prepares a finding before wave 2 closes. That breaks the wave order of BR-113. The fix is a refusal of `close-wave N` while wave N-1 has no record, and the fix keeps option (a).
- IMPL-0062 (`minor`, register file): the spec-feedback report misses the idempotency line of `validation-rules.md` § Dispatch ledger. `re-dispatch` of a `prepared` entry was a no-op with exit `0` and now refuses.

The other three fixes hold. `re-dispatch` refuses only states that no flow sends to it. `prepare-wave` cuts from the tip of the feature branch on every path the story names. `--class` is required, and every caller passes it. The changed BUG-0084 test keeps its intent.

Next, the developer agent fixes IMPL-0061 on `story/ST-0431` and resubmits the story for review. IMPL-0062 does not block the merge, and its row fits into the same commit.

The register file of IMPL-0062 sits under `docs/findings/register/document/`, because the material is a document. The `touches` field of the story names only `docs/findings/register/code/*.json`. Before `merge-story`, either add `docs/findings/register/document/*.json` to `touches`, or let the stakeholder decide where the file goes.

## Notes on the spec-feedback report

Row 5 of `spec-feedback-ST-0431.md` asks the domain-modeling agent to decide whether `close-wave` of an empty wave must wait for the record of the wave before it. BR-113 already sets the order of the waves, so no decision is open, and IMPL-0061 treats the gap as a code defect. Once IMPL-0061 is fixed, row 5 becomes a plain contract row for § `dispatch close-wave`.

A wave with entries has a related path, and the story did not create it. Wave N can close while wave N-1 runs when every entry of wave N waits behind a returned dependency. The fix of IMPL-0061 in `cmd_close_wave` closes that path too, because it checks every wave. The review filed no finding for it.
