## Correctness

**Removal in all cases.** `main` adds the worktree, and the next statement opens a `try` block whose `finally` calls `remove_worktree`. The gate list, the warnings, and every gate run sit inside that block. When `git worktree add` fails, the code calls `remove_worktree` once more and exits `2`. The contract defines `2` as a git error, and `dispatch merge-story` refuses on any exit code other than `0`. So a failed add also blocks the merge.

**Removal of a leftover.** `remove_worktree` passes an absolute path to `git worktree remove --force`. The path comes from `git rev-parse --path-format=absolute --git-common-dir`, or else from `--show-toplevel`, which is also absolute. Git matches a worktree by a path ending only when the argument is relative. So an absolute path names only the worktree at exactly that path, and the third probe confirms this. On a plain folder that is no worktree, git refuses the remove and deletes nothing. The path always holds the segment `premerge`, and a story worktree holds the segment `story`. So the two paths cannot be the same.

**Checkouts stay unchanged.** Each gate gets `--report-dir` inside the temporary worktree, and `uv` builds its `.venv` there. `git worktree remove --force` deletes that folder with every untracked and ignored file in it. The empty parent folders `.current-work/<target>/premerge/` stay, inside the ignored `.current-work/`. IT-05 and the first probe check the status and the stash list.

**A failing gate blocks.** `rerun_gate` passes a gate only on exit `0`. `dependency-check` exits `1` on a broken rule and `2` without a rules file or source root. `test-design-verify` exits `0` only on a pass or a skip. A missing or non-executable script raises `OSError`, and the gate fails with `cannot run <script>`. Each failure lands in `failed_gates`, and the check exits `1`.

**Gate list.** `resolve_gates` reads the story and `docs/testing.yaml` from the worktree, so the list comes from the branch head (BR-066). Without `docs/spec/dependency-rules.dsl` at the head, the list holds no `dependency-check`, and `dependency_skip_notice` prints the skip. IT-13 checks that the installed stub never runs.

**Gate scripts.** `gate_script` takes the installed copy of the primary checkout, and the script next to `premerge-check` when that copy lacks the gate. The contract names the copy of "the checkout it was called from". In an orchestrated run, that checkout is the worktree of the feature branch, which holds no `.agent-factory/`. The spec-feedback report names this gap for the domain-modeling, requirements, and architecture agents. The review agrees with the code's choice.

## Architecture, SOLID, maintainability, consistency

The new functions each do one thing: find the primary checkout, build the path, add, remove, pick the script, build the command, and run one gate. `check_semantic_gates` keeps its old signature and adds two optional arguments, so the stored-result path for `crap-score` and `mutation-testing` is unchanged. The functions follow the style of the file: `run_git` for git, tuples of `(ok, detail)` for results, and docstrings that name the rule. The test changes replace the stored `dependency-check` results with a rules file, as the QA strategy lists under "Tests that this feature makes wrong".
