## Correctness

**The checks read the branch head.** `files_at_head` lists the files with `git ls-tree` at the branch, and `read_at_head` reads them with one `git cat-file --batch` call as `<branch>:<path>`. No path of the working folder is read. RL-08-IT-02 puts a resolved copy of BUG-0091 in the folder and an open one at the head, and the reverse, and both cases give the right answer. A path that git cannot read raises `GitReadError`, and `main` exits `2` and names the path. One gap remains: `git ls-tree` reads its path relative to the current folder. IMPL-0026 describes the consequence.

**The blocking rule.** `is_blocking` returns true only for `category` `defect` or `risk` together with `severity` `critical` or `major`. That is BR-085 and the shared table of `finding-classification.md`, word for word. `check_open_findings` reads only `docs/findings/<ID>.md`, never a register file, and only `status: open` counts. The statuses `resolved`, `waived` and `deferred` leave the merge open, as `finding-format.md` defines. The finding check trusts the frontmatter as written. A file that `yaml.safe_load` cannot read gives no record and does not block, but the `finding-lint` hook refuses such a file at commit (note 1).

**Stale and foreign reports.** `check_code_review` takes `docs/reviews/code-review-*.md` at the head, keeps a report only when its `story` field equals the story ID, and passes only when `branch_head` is an ancestor of the head. A report of ST-0351 or a report with a commit outside the branch fails, and the parametrized RL-08-IT-01 test covers both. An older ancestor passes, as BR-122 requires. Two weaknesses remain. A ref name as `branch_head` always passes (IMPL-0025). An ancestor from before the story's first commit also passes, because BR-122 asks only for an ancestor (note 2).

**The story's own files and the file limit.** `story_owned_files` takes the changed files in `docs/reviews/` and `docs/findings/`. A file belongs to the story when its name holds the story ID or its `story` field at the head names the story. A file that the branch deleted belongs to the story only by its name, and the spec-feedback report has a row for that. `check_blowout` leaves these files out of the count and names how many it left out. `merge-story` passes the same list as `--scope`. A finding of another story keeps its own `story` field, so it is out of scope and RL-08-IT-08 refuses it. The branch can still rewrite that field and take the file in (IMPL-0027).

**The loaded copy of premerge-check.** `_load_premerge_check` loads `SCRIPT_DIR / "premerge-check"` with `SourceFileLoader`. `merge-story` builds its call from the same `SCRIPT_DIR / "premerge-check"`, and `SCRIPT_DIR` is the resolved folder of `dispatch`. The module is not put into `sys.modules`, so no earlier import under the name `premerge_check` can stand in for it. Both uses therefore run the same file.

## Architecture, SOLID, maintainability, consistency

The change adds small functions with one task each: `files_at_head`, `read_at_head`, `parse_record`, `is_blocking`, `story_owned_files`, `check_code_review` and `check_open_findings`. The two checks follow the `(ok, line)` pattern of the other checks in `premerge-check`. `parse_frontmatter` now serves the story file and the review records, so the frontmatter rule has one home. `dispatch` takes the ownership rule from `premerge-check` and does not copy it. The test helper `write_review_report` in `tests/conftest.py` gives the six fixture files one way to commit a report.
