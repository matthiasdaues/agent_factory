# Session Retrospective — 2026-07-12

**Session scope**: One long session on the `agent_factory` monorepo. Rewrote onboarding docs and reformulated `rules.md`; wrote and implemented ADRs 0020/0021 (single model-tier vocabulary); built proof-of-concept slices for two proposals (`transition-lint`/`phase advance`, `_session_log.py`/`session-reconcile`); added a git-safety guardrail hook and folded it into `init-factory`; migrated `INDEX.md` to `INDEX.yaml` and built `trigger` and `phase retry`; produced factory's first spec and arc42 architecture; weeded dead code from `orchestrator/` and reconciled its docs against the result.
**Duration**: Single extended multi-hour session; exact timestamps not tracked.
**Mode**: Mixed — inline work by the orchestrating session plus several rounds of worktree-isolated background subagents (opus).

## ✅ Went Well

- **Independent pre-merge diff against `dev` caught two contaminated subagent diffs before they merged** — in Phase 3 a subagent branched from a base predating the whole tier-everywhere migration and produced a 165-file diff; in Phase 5 the weeding agent produced two commits of deletions reasoned against an old `model_resolver.py`. Both were caught by manually running `git diff --stat` between the agent's branch and `dev`, not by trusting the agent's self-report. No bad state reached `dev`.
- **Re-running tests and gates independently before every merge caught a real, unreported issue** — after the reconciliation merge, `arch-lint` flagged `ARCH-STALE`. The cause was a false positive: `git merge` resets file mtimes, so the mtime-based staleness check compared a freshly-checked-out DSL against images whose mtimes had also just been reset. Diagnosed from the check's own source, then fixed by re-exporting the diagrams.
- **Two subagents stopped and asked instead of guessing on a suspect base** — the spec agent and the architecture agent each noticed their worktree was branched from a commit predating the session's flow-control work and halted for instruction rather than proceeding blind. Both resumed successfully once told to branch fresh off `dev`.
- **The external safety classifier caught two real permission-design flaws** — it blocked a first draft that used blanket bypass flags (`--dangerously-skip-permissions`, `--allow-all-tools`) and a second draft whose allowlist contained bare interpreter wildcards (`Bash(python3 *)`, `Bash(uv *)`) that scope nothing. Both were genuine flaws, not false alarms.
- **Inline, incremental work with per-step verification went smoothly** — Phase 4 (`INDEX.yaml`, `trigger`, `phase retry`) and Phase 6 (playbook edits) were done directly by the orchestrating session in small edits, each verified with a real test before the next. No rework.
- **Deriving the permission allowlist from repository evidence produced a correct result** — grepping playbooks, skills, agents, rulebooks, and both pre-commit configs for the commands actually used yielded a correctly scoped allowlist on the third pass.

## 🛑 Stop Doing

- **Stop dispatching a worktree-isolated agent without a mandatory verify-base-first step.** The stale base recurred across Phase 2, Phase 3, and Phase 5, and it is the same class of worktree-isolation failure flagged in the 2026-07-10 retro. Evidence: the Phase 3 165-file diff and the Phase 5 weeding agent's two wrong-base commits.
- **Stop relying on the orchestrating session to remember to diff a finished branch against its target before merge.** The habit worked, but it is manual and it fired late. Evidence: both contaminated diffs were caught only because someone remembered to run `git diff --stat`.
- **Stop letting an agent that spawns sub-agents address them by agent type rather than a resolvable instance ID.** Evidence: the reconciliation agent's stranded sub-agent replies.
- **Stop drafting deliverable prose without applying the Plain Prose principle from the first draft.** Evidence: the three-pass rewrite of one short passage.
- **Stop writing permission allowlists from imagination.** Derive them from repository evidence first. Evidence: the two classifier-blocked drafts.

## ▶️ Continue Doing

- **Independently diff every finished subagent branch against its target and re-run the relevant tests and gates before merge.** It caught every contamination this session and one false-positive gate failure. Evidence: the two `git diff --stat` catches and the `ARCH-STALE` diagnosis.
- **Let subagents halt and ask when their base or scope looks wrong, rather than guessing.** The spec and architecture agents did this and recovered cleanly; the weeding agent, which did not, cost a full restart. Evidence: the contrast between the three Phase 5 agents.
- **Treat a block from the safety classifier as real signal.** Both blocks this session were genuine design flaws.
- **Do small, incremental work inline with per-step verification.** Evidence: Phases 4 and 6 landed without rework.

## 🆕 Start Doing

- **Put a verify-base preamble in every worktree-isolated dispatch prompt** — a required first tool call that asserts the worktree is branched from the declared base and is not behind the target branch, halting if it is. How to adopt: standard boilerplate plus a helper script; see the companion proposal. Emerged from: the recurring stale-base incidents.
- **Give a dispatched agent a resolvable reply address for any sub-agents it spawns, and forbid indefinite blocking on a sub-agent reply.** How to adopt: a sub-agent-addressing clause in the dispatch contract. Emerged from: the reconciliation agent's stranded replies and indefinite wait.
- **Make the pre-merge diff-against-target a required, scripted step, not an orchestrator habit.** How to adopt: a `premerge-check` script that flags file-count blowout and out-of-scope paths. Emerged from: the two late-caught contaminated diffs.
- **Adopt the 2026-07-10 retro's phase-branch convention (its action item #1), which is still unadopted.** A dispatch recorded against a declared base SHA would have made every stale-base incident this session detectable up front. Emerged from: the same worktree problem recurring one session later.
- **Cap the scope of a single dispatch and checkpoint long tasks, so a spend-limit death loses less.** Emerged from: the weeding and reconciliation dispatches each hitting the spend limit multiple times at 300k–465k tokens per resume cycle.
