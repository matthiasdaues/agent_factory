## Correctness

### Where the check runs

`cmd_merge_story` calls `_refuse_dirty_feature_worktree` inside the block `if not already_merged:`, right after the exit-`0` check of `premerge-check`. The call has the guards `not by_hand` and `not args.dry_run`. So the check runs only in an orchestrated run, only after a passing `premerge-check`, and only before a new merge. A failing gate still prints its own message first, and `test_RL_08_IT_15_a_changed_tracked_file_does_not_hide_a_failing_gate` checks that no word about an uncommitted file appears then.

### The rerun after a refused amend

`test_RL_08_IT_16_the_rerun_after_a_refused_amend_passes` reaches the `already_merged` path. The pre-commit hook refuses only the amend, because `git merge` runs no `pre-commit` hook. The test asserts the hook message and asserts that `git status --porcelain --untracked-files=no` in the feature worktree names `backlog/ST-0350.md`. The rerun then exits `0`. If the check ran on the rerun, it would see that staged change and exit `1`. So the test fails when the check moves out of the `not already_merged` block, and it guards SPEC-0110.

### Tracked files only

The check runs `git -C <feature worktree> status --porcelain --untracked-files=no`. Staged and unstaged changes to tracked files count, and an untracked file does not. Tests cover all three cases. `_git` strips the output, so the code splits the status letters off each line instead of cutting a fixed width. A rename line prints as `old -> new`, which still names both files.

### The key

`_read_refuse_dirty_feature_worktree` reads `docs/testing.yaml` from the working tree of the feature worktree, because `merge-story` runs there. Only when that file is missing does it read the primary checkout. A missing file, section, or key gives `true`. A value that is no bool refuses the merge with exit `1` and names the file, also when the worktree is clean.

A story branch cannot turn the refusal off for its own merge. The key is read before `git merge`, and the refresh merges the feature branch into the story branch, not the other way round. So the story's own `docs/testing.yaml` is not in the feature worktree yet when the key is read. A story that sets the key to `false` would change it for the later merges of the run. `premerge-check` lets that change through only when `docs/testing.yaml` is in the story's scope.

### The older test

`_interrupt_merge_story` in `tests/factory/test_dispatch_run_blockers.py` writes a test command that kills `merge-story` after the merge commit. It writes that command into `docs/testing.yaml` of the feature worktree as an uncommitted change. Without the key, the new check would refuse the first run before the merge, and the test could not create the interrupted state. With the key `false`, the first run merges and dies in the test suite as before. The rerun takes the `already_merged` path and skips the check anyway. The test still checks the same thing: `refresh-story` refuses after an interrupted `merge-story`, and the rerun of `merge-story` finishes the story. So the change keeps the intent of the test.

### Step 4d of the implementation agent

Step 4d now says that a refused `premerge-check` exits `1`, merges nothing, and keeps the story `dispatched`. It sends the story to the [fix-iteration loop](../../packages/factory/agents/implementation-agent.md#fix-iteration-loop), where a fresh developer agent gets the `premerge-check` output, and then runs step 4d again. For the dirty-worktree refusal, the step tells the agent to report the message unchanged and not to change the worktree. This matches the story's Domain Rule and RL-08-LN-01, and the anchor `#fix-iteration-loop` exists. The step does not say what the agent does once the User has acted, and it names a rerun after a refused amend that no instruction asks for. IMPL-0038 records this gap.

## Architecture, SOLID, maintainability, consistency

The new code stays in `dispatch`, next to the other readers of `docs/testing.yaml`. The shared root lookup moved into `_checkout_roots`, and `_read_attempt_limits` uses it without a change of behavior. The reader and the refusal are two functions: one parses the key, and one decides and prints. The messages follow the `error: ...` form and name the entry state, as the other refusals of `merge-story` do.

The tests carry `@pytest.mark.spec` with the Test IDs of their QA strategy rows. Each test builds its own repository in `tmp_path` and runs `dispatch` as a subprocess. RL-08-IT-15 passed before the change, because ST-0410 already runs `premerge-check` first. The Analysis says so.
