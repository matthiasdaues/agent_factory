## Correctness

### Old ledgers in this repository

Six of the seven ledgers load, save, and load again without loss. They are the ledgers of `brownfield-onboarding`, `bug-hunt-fixes`, `counter-ids`, `finding-classification`, `run-lifecycle`, and the ledger nested in the `counter-ids-fitting` worktree. Each loads with `mode: orchestrated` and its branch in `feature_branch`. Each saved copy has no `invocation_branch`, `closed`, or `gate_results`. Every story field, the story count, and the list `waves` match the source.

The ledger of `core-artifact-layout` does not load. Line 181 holds `reason: not started: dispatch held at …`, and the second unquoted colon breaks the YAML. The code of `7e796bf6` fails on the same line, so this commit did not cause the fault. BR-120 and ST-0425 cover that ledger.

No other script reads the old names. `block-dangerous-git.sh` searches ledgers only for `branch:` lines of entries, and `step-guard` only names the file. Both keep working.

A resume on an old ledger writes nothing. So `init` never rewrites the ledger of the active run `feature/run-lifecycle`.

### A second orchestrated run

`init` has four refusals that look at existing state. None of them can block a second orchestrated run on a new feature branch:

- The ledger check reads only `.current-work/<feature-branch>/dispatch-ledger.yaml` of the new branch.
- The check for a run by hand runs only with `--mode by-hand`.
- The dependency check reads only the backlog stories of the new run.
- The check for untracked files runs only without `--feature-branch`, as before.

RL-01-IT-04 tests the second orchestrated run beside an orchestrated run and beside a run by hand.

### The resume check

The resume check moved to the start of `init`. It returns before the test command, the backlog, or git are read. So a resume and a refusal of other stories change no branch, no worktree, and no file. RL-01-IT-05 compares a snapshot of the ledger folder before and after, with the stories in another order.

The check also comes before the refusal of a second run by hand. Without that order, a resume of a run by hand would refuse itself.

### The rest of BR-111 and BR-112

`--mode` accepts only `orchestrated` and `by-hand`, so `--mode automated` exits `2`. A run by hand creates its branch with `git branch` and leaves the primary checkout on its branch. `branch_root` is the tip of the feature branch, also when that branch is ahead of `dev`. The refusal for a missing test command names `docs/testing.yaml`, and `config/project.json` no longer counts. The commands that needed `mode: automated` now need `mode: orchestrated`, as the story states.

## Architecture, SOLID, maintainability, consistency

The change stays inside the `dispatch` command layer and the ledger model of `dispatch_lib.py`. No dependency direction changes.

`cmd_init` is shorter than before. The helpers `_impl_branch_name`, `_create_run_branch`, `_active_run_by_hand`, and `_open_outside_deps` each do one thing, and the one place for the branch creation serves both modes.

The field list of `dispatch-contract.md` is now checked against the code by RL-17-LN-01. The sample ledger `full_ledger()` sets every field of `StoryEntry`, and the test asserts that, so a new field breaks the test until the contract lists it.

Each new test carries `@pytest.mark.spec` with its Test ID, and each git test builds its own repository in `tmp_path`. The fixture moves in the three files change only the source of the test command.
