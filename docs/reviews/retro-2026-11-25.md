## ✅ Went Well

- **The merge check found a real data-loss bug.** CAL-07-IT-03 failed on `dev` after 1.14.1 and blocked the merge of ST-0449. The cause was BUG-0147: a failed runtime build removed the capture marker, so capture went off without a word. Since BUG-0144 that had cost weeks of usage records. Commits `2f94f9da` and `ada2cabd` fixed it, and the 1.15.0 update kept capture running: the marker carries the update time, and the newest record came after it.
- **Measuring only the changed files made the gate affordable.** At first, the full Python suite under coverage would have run twice per story. DEC-84 and DEC-85 (ST-0451) hand the changed paths to the measure and select the tests. DEC-87 records `measured_minutes: 12` against `timeout_minutes: 20`.
- **"Fail wrongly, never pass wrongly" settled the TypeScript measure.** IMPL-0105 showed that an uncalled one-line function of complexity 7 scored 100 % and passed. The fixes `c23aa019` to `34087347` pair functions by their own start line and give 0 % when the lcov records disagree.
- **The code review of SEC-0013 closed a supply-chain path.** The ESLint call through `npx --yes` resolved versions at run time. ESLint now installs from `scripts/crap-eslint/package-lock.json` with `npm ci --ignore-scripts`, and `setup-crap-score` asks every project for the same.
- **The transcript migration freed 60 GB, with checked evidence.** Before the User moved the four stuck captures aside, each one was shown to be a byte prefix of a stored copy, or identical to one. The migration took the 57 sessions from 61.97 GB to 1.58 GB. BUG-0145 and BUG-0146 record the two gaps with their reproductions.
- **Checking the claim before the commit kept a false fix out of the changelog.** The first 1.15.0 draft listed BUG-0141 as a fix. Its finding says the template was never on `dev`, so the bullet moved into the template change before commit `4a3a87a5`.
