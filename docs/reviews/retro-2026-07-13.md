## 🛑 Stop Doing

- **Introducing env vars without a provisioning mechanism.** `AF_SESSION_LOG` was declared in `_session_log.py`, documented in the factory guide and a proposal, but never actually set by any script. An env var without a setter is a configuration leak. Evidence: user caught this after the orchestrator was "complete" and correctly called it negligence. Rule: every env var must have exactly one provisioning point per workflow, documented inline at the point of export.

- **Attempting interactive rebase on stale branches when the safety hook is active.** The `block-dangerous-git.sh` hook blocks `git reset --hard`, `git branch -D`, and other recovery commands. A failed rebase leaves conflicted files — including the hook script itself — with no clean recovery path. Evidence: the `feat/guardrail-in-init-factory` rebase left conflict markers in the hook, which then blocked ALL git commands. Rule: before rebasing, verify the branch has unique content worth preserving. If redundant, skip it.

- **Proposal document before implementation.** The `run-playbook` proposal went through three user corrections (one-step not loop, playbooks-as-rails, requirements always human) before a line of code was written. All three would have been rework if discovered during implementation. Continue writing proposals for any feature that introduces a new architectural shape.

- **Following the feature-add playbook end-to-end.** Spec → Architecture → Planning → Implementation → QA. No phase was skipped. The gates (spec-lint, arch-lint, backlog-lint) caught real problems at each phase boundary. The discipline pays for itself in prevented rework.

- **User-stated design principles as hard constraints.** "Creation is agentic, validation is deterministic" and "playbooks are rails" shaped every decision. These should be read from `docs/CONTEXT.md` or foundational-principles at session start, not rediscovered through user correction mid-session.

- **Condensed PRD from conversation history.** The orchestrator PRD was derived from the session's own discussion, not invented. This ensured the spec reflected what was actually agreed, not what an agent imagined.

## 🆕 Start Doing

- **Env var registry.** Create a single file (`factory/docs/env-vars.md` or a section in the factory guide) listing every env var the system uses: name, purpose, who provisions it, who reads it, default value. Today `AF_SESSION_LOG` is the only one, but the pattern will recur. Emerged from: the `AF_SESSION_LOG` provisioning gap.

- **Branch staleness check before merge plans.** Before planning a merge, run `git log --oneline dev..<branch>` and compare against `git log --oneline <branch>..dev` — if incoming content is a subset of what dev already has, skip the branch immediately. Don't attempt rebase. Emerged from: the `feat/guardrail-in-init-factory` redundancy that cost 10 minutes and a broken hook.

- **Pre-commit hook self-test on conflict.** The safety hook (`block-dangerous-git.sh`) should detect its own corruption (presence of conflict markers) and fail open with a warning rather than blocking all commands. A hook that prevents its own repair is a trap. Emerged from: the mid-rebase hook corruption incident.

- **Subproject pre-commit hooks should inherit patterns from factory, not invent their own.** The orchestrator hooks initially used `uv run --project orchestrator mdformat` instead of the established `factory/scripts/mdformat` wrapper. Rule: when adding a subproject, copy hook entries from the factory section and change only the `files:` pattern. Emerged from: the `pyproject.toml` false start.
