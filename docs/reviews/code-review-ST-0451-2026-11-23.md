## Checks of crap-score

`main` computes `changes` once and passes it both to `changed_paths` and to `judged_rows`. So the paths in `GATE_CHANGED_FILES` are exactly the files whose lines the gate judges. A file that the story deletes has no `+++ b/` header and is not among them. A target change after the merge base is not among them either; CG-03-IT-06 checks that case.

| Call                                    | `GATE_SCOPE` | `GATE_CHANGED_FILES`             |
| --------------------------------------- | ------------ | -------------------------------- |
| `--base <ref>`                          | `changed`    | the paths of the merge-base diff |
| `--all`                                 | `all`        | empty                            |
| `--base <start> --settings-from-folder` | `changed`    | the same paths as with `--base`  |

The last row is the call of `gate-setup-proof`. The option changes only where the trusted values come from, so the scope follows `--base`.

A path name can break the variable in two ways. A line break would split one path into two, so `changed_paths` refuses it with exit `2`, and the test checks that no command starts. A path that git quotes, such as one with a tab, is decoded by `_unquote_c`, and a path that is not UTF-8 travels with `surrogateescape` both ways. The second way is size: Linux refuses to start a program when one environment string is longer than 128 KiB. A diff of 3000 paths reaches that limit, and `crap-score` then ends in a traceback with exit `1` ([IMPL-0102](../findings/register/code/IMPL-0102.json)). `crap-score` at `38579fdc` judges the same diff with exit `0`.

## Checks of the template

"Fail wrongly, never pass wrongly" holds for the code of the template. Under `changed`, coverage traces only the changed kept files, and the rows of a traced file hold the same lines and arcs as under `source`. A function can only lose coverage when fewer tests run. A changed kept file that no selected test reaches is not in the coverage data. The template then exits `1` and names the file, as CG-03-IT-04 checks, and that stops the gate with exit `2`.

The guarantee rests on one assumption that no text states: `SELECT_COMMAND` runs a subset of the tests of `TEST_COMMAND`. A selector that runs tests that `TEST_COMMAND` leaves out, such as a marker that the full run skips, can make a function look better covered than the full run does. The review records this as a note.

`SELECT_COMMAND` gets the paths as separate list items through `subprocess.run` without a shell, so no path can inject a command. A path that starts with `-` reaches the selector as an option, because the template puts no `--` before the paths. The review records this as a note.

The template writes each traced path as one line of the coverage.py setting `include`. coverage.py splits that list at commas and reads each item as a file pattern. So a changed file such as `src/a,b.py` or `src/a[1].py` gets no coverage data under `changed`, while `all` measures it at 100 % ([IMPL-0103](../findings/register/code/IMPL-0103.json)).

`PYTEST_ADDOPTS` behaves as follows:

| Case                                                 | Result                                                                                                                                                                |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TEST_COMMAND` is not pytest                         | No process reads `PYTEST_ADDOPTS`, so the variable changes nothing.                                                                                                   |
| A script that starts pytest                          | The pytest process runs `sitecustomize.py` and sets its own `--basetemp`. CG-03-IT-10 checks this case.                                                               |
| A test that starts pytest as a new process           | The inner process appends its own `--basetemp` after the inherited one, and pytest takes the last. The nested test of CG-03-IT-10 checks this case.                   |
| A test that calls `pytest.main()` in its own process | The inner pytest gets the `--basetemp` of the outer one and clears it, so the outer test fails ([IMPL-0104](../findings/register/code/IMPL-0104.json)).               |
| `pytester`                                           | `pytester` removes `PYTEST_ADDOPTS` and sets its own `--basetemp`, so it is not affected.                                                                             |
| The project already sets `PYTEST_ADDOPTS`            | The template keeps the project's value and appends its own options. Its `--basetemp` wins over one of the project.                                                    |
| The project's pytest settings use `--lf` or `cache`  | `-p no:cacheprovider` removes those options and the `cache` fixture, so the test run fails. DEC-85 decides that the cache provider is off; the review records a note. |

`gate-setup-proof` still passes its four checks with the new template. Its runs use `--base <start>`, where `<start>` is the parent of the first planted commit. So the diff holds the setup files and all of `base/`, and in run 3 also `gap/`.
