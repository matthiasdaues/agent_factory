## 🛑 Stop Doing

- **Stop trusting a subagent's success report without checking git state.** Evidence: the ST-0041 developer reported "7 passed" from a base missing 144 commits; only `premerge-check` and a direct git check revealed it.
- **Stop introducing per-feature subdirectory nesting for factory content.** Evidence: the nested `research-topic/PLAYBOOK.md` forced an `index-lint` change and was reverted to flat storage; flat with a `research-` prefix is the convention.
- **Stop letting a shipped agent's `inputs:` point at `docs/proposals/*`.** Evidence: `research-orchestrator` depended on the untracked proposal; proposals are design origins, not runtime contracts.
- **Stop assuming uncommitted config drift is an agent error.** Evidence: the intentional init-factory pi.dev changes (`.gitignore`, `.pre-commit-config.yaml`, `.pi/`, `AGENTS.md`, `.agent-factory/`) were diagnosed as a wave-1 agent mishap and reverted — even attempting `rm` — when they were the user's deliberate action. Check authorship or ask before reverting user-owned files.
- **Stop prefixing git commands with `cd` in a compound Bash line.** Evidence: `cd …; git merge …` tripped the guardrail. The Bash cwd persists between calls, so issue git as a lone command.

## 🆕 Start Doing

- **Start closing the verify-base enforcement gap.** A developer committed on a stale base despite both the preamble and the worktree commit-marker guardrail. Investigate why the `verify-base-ok` marker did not block the ST-0041 commit, and strengthen the mechanical check. Emerged from: the ST-0041 incident.
- **Start generalizing `remove-factory`'s settings-hook stripping.** `strip_settings_hook` is hardcoded to the guardrail's `PreToolUse` shape and does not remove the new `Stop`/`SubagentStop` capture entries when `.claude/settings.json` pre-existed. Emerged from: the token-tracking ST-0040 flag.
- **Start declaring each story's test file in its `outputs:`.** Token-tracking did this and `premerge-check --scope` covered the tests automatically; research did not and needed manual widening. Emerged from: the contrast between the two features.
- **Start filing an upstream report on the Claude Code worktree stale-base provisioner bug.** It recurred across both features (`849481f`, `da899a9`). Emerged from: repeated worktree mis-provisioning.
- **Start treating a compound shell line containing `git merge` as guardrail-hostile** — run `git merge <branch>` as a lone command. Emerged from: the "cd"-misparse merge block.
- **Start surfacing spend-limit history and confirming headroom before a large autonomous dispatch**, or split it into smaller sub-dispatches / lighter tiers. Evidence: the token-tracking implementation was killed repeatedly at the monthly limit, each kill forcing a salvage cycle.
- **Start hardening the git guardrail's command parser** so a compound line does not mis-identify the operative branch. Emerged from: the `cd …; git merge …` false block — a factory-side fix, not just an assistant habit.
- **Start defining an official proposal format and making it a first-class feature-addition input.** Three proposals drove this session (`pi-invocation-layer.md`, `falsification-driven-research-workflow.md`, `token-usage-tracking.md`), each ad-hoc in shape, yet each fed planning directly. Define a proposal template and wire "proposal → planning" into the feature-addition playbook as a named, official step. Emerged from: planning straight from undefined-format proposals.
- **Start using a deterministic two-pass commit sequence to absorb linter/formatter rewrites.** Instead of researching each "files were modified by this hook" abort, adopt a fixed pattern — run the repo's formatters/linters on the staged set first (or commit, then `git add -u` and re-commit once) so the second pass is always clean. Consider a small commit helper that does this. Emerged from: the recurring re-add-and-retry loop.
