## Correctness

**Every enabled gate runs and fails closed.** `_picked_gates` takes each entry of `gate_entries` with `enabled: true`, then each gate of the story's field. `rerun_gate` calls `gate_refusal` first. A gate other than `crap-score`, `mutation-testing`, `dependency-check`, and `test-design-verify` without an entry fails with `no entry gates.<gate>`. The same gate with an entry and an empty or missing `command` fails with `has no command`. A non-zero exit fails, and an `OSError` fails with `cannot run`. Only exit `0` passes. `premerge-check` sets no time limit of its own; note 1 explains why a hang still never passes.

**The field only adds.** The field never filters the list of enabled entries. It appends each of its gates that is not in the list yet, also a gate whose entry has `enabled: false`. A story can change its own `backlog/<id>.md`, because the scope always holds it. That edit can only add gates. The one exception is the default of BR-066: an empty field drops the default `crap-score` (note 3).

**The test suite.** `check_test_suite` reads `test_command` from the temporary worktree and runs it there, with `VIRTUAL_ENV` and `UV_PROJECT_ENVIRONMENT` removed. The worktree is a checkout of the branch head, so an untracked file of the story's checkout or the primary checkout is not in it. RL-08-IT-17 checks both the refusal of a red suite and an untracked failing test. A non-zero exit prints `BLOCK test-suite` with the command and appends a failure. Without `test_command`, the check prints `SKIP test-suite` and passes; the spec-feedback report names that gap.

**The old key forms.** `gate_entries` maps `crap_score`, `mutation_testing`, and `test_design_verify` to their names with hyphens. With both forms, the key with hyphens wins, and the warning names the old key. `crap-score` and `mutation-testing` read the old key the same way. The template `charter-testing.yaml` and this repository's `docs/testing.yaml` still use the old keys, and RL-09-CT-04 to RL-09-CT-06 and RL-09-IT-02 cover them.

**The built call of crap-score.** The call passes `--source-root <worktree>` and no file list and no coverage file. IMPL-0024 describes the consequence and the fix.

**Gate commands from branch content.** `premerge-check` reads `docs/testing.yaml` at the branch head, as the Reads row of the contract defines. A story whose scope does not admit `docs/testing.yaml` cannot change its gates, because the scope check refuses the change. Note 2 names the case where the scope admits the file.

## Architecture, SOLID, maintainability, consistency

The change replaces the stored-result path with one rerun path. `gate_entries`, `_picked_gates`, `gate_refusal`, `gate_command`, and `rerun_gate` each do one thing, and `check_test_suite` follows the `(ok, line)` pattern of the other checks. The constants `BUILT_IN_GATES`, `CONDITIONAL_GATES`, and `OLD_GATE_KEYS` name the three kinds of gates in one place. `crap-score` and `mutation-testing` each carry their own copy of the old-key rule, because each script stands alone; the duplication is small and matches the existing scripts. The text changes in `test-strategy-agent.md` and `skills/crap-score/SKILL.md` name the keys with hyphens.
