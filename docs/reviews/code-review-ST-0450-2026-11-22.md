## Verdict

With [IMPL-0094](../findings/IMPL-0094.md), a story can set `integration_branch: "story/ST-1~1"`, and `crap-score` then judges it by the threshold of the story's own parent commit with exit `0`. ## Question for the stakeholder

The story agent shares the refs of the repository with every worktree, so it can create a local branch. Take a story `story/ST-0350` whose `touches` names `docs/factory-settings.yaml`. Its agent commits a raised threshold, creates the branch `loose` at that commit, and sets `integration_branch: loose` in the next commit. Even after the fix of IMPL-0094, `crap-score` judges the story by threshold 10 of `loose` and exits `0`. The tip of `loose` is not `HEAD`, so DEC-76 does not apply.

- **Keep DEC-76 as it stands.** The story passes with threshold 10. Only the planner's `touches` and the code review keep the key in check.
- **Also refuse a named branch whose tip is a commit of the story.** `crap-score` exits `2` when the tip is an ancestor of `HEAD` and not an ancestor of `--base`. The story with `loose` exits `2`. A branch `loose` cut from `dev` with its own new commit still passes.

The review recommends the second option. It closes every commit that the story itself made, and it costs one `git merge-base --is-ancestor` call. The answer changes DEC-76, the § Trusted gate source contract, and the rows of CG-14-IT-07.

### A tag can stand in for the base branch

Git resolves a bare name as a tag before a branch. The review checked this with `git rev-parse` in a scratch repository that holds both `refs/heads/feature/x` and `refs/tags/feature/x`, and the tag won. `premerge-check` passes the feature branch by its bare name, as `--base feature/x`. So a story agent that writes a tag `refs/tags/feature/x` into the shared repository changes what `--base` names:

- With the tag at the story commit that holds `integration_branch: loose`, `_settings_text` reads the key from the tag. The gate judges the function by threshold 100 of `loose` and exits `0`.
- With the tag at the story head and no key, `changed_lines` finds an empty diff. The gate judges 0 functions and exits `0`.

The second route goes through `changed_lines` and the merge base. ST-0450 did not change that code, and it is on `dev` today. So the gap is older than this story, and DEC-77 adds one more reader of the same ambiguous name. The review files no finding against ST-0450, because a fix in `_settings_text` alone would leave the older route open.

This is a security question, and the code review does not classify security findings. The review recommends a security review of how `crap-score` resolves `--base`. The fix that the review would suggest belongs in `crap-score`: resolve `--base` once, through `refs/heads/<base>` when that branch exists and else as a commit, and pass that commit to `changed_lines` and `_settings_text`. `premerge-check` could also pass `refs/heads/<target>`, but ST-0450 leaves `premerge-check` unchanged.
