# Code review of ST-0424, the feature merge check

## Result

The review found two blocking findings, so ST-0424 goes back to the developer agent before the gate-check step:

- IMPL-0050 (`major`): in a run by hand, `premerge-check dev <feature-branch>` passes while a story of the run has never started.
- IMPL-0051 (`major`): the handoffs of the code-review, reconciliation, and QA agents still put reconciliation before QA and the merge.

It also filed IMPL-0052 (`minor`) as a register file. That finding does not block the merge.

The rest of the feature merge check matches the contract. Each row of the Scenario Outline refuses and names its cause. A report or a finding of another run does not count. The temporary worktree is removed in every outcome the review tried. The fixes of BUG-0130, IMPL-0025, IMPL-0026, and IMPL-0034 hold. The review set BUG-0130 to `resolved` and confirmed the `resolved` of the three register files.

Next, the developer agent fixes IMPL-0050 and IMPL-0051 and returns the story for a repeat review.

## Points the brief asked about

**Refusals.** Each refusal of the contract holds: a `failed` or `blocked` unit of work, a wave without a record, each missing report, a report of another run, a `branch_head` that is no ancestor or no full SHA, an open blocking finding by `run` or by `story`, and a red suite. A missing ledger and a missing `test_command` refuse too, and the spec-feedback report records both. The one way to pass with something unfinished is IMPL-0050. The review found no case that refuses a ready feature for a wrong reason. A finding with neither `run` nor `story` does not block, which matches the contract.

**Feature merge or story merge.** `is_feature_merge` treats every branch into `dev` that is not `story/ST-NNNN` as a feature merge. A story branch never matches, and `dispatch-wave.ts` passes a wave base SHA as the target, so its story merges never match either. A finding branch `story/<finding-id>` into `dev` would count as a feature merge and refuse for the missing ledger, but no flow merges a finding branch into `dev`. The reverse case, a feature merge that skips the feature checks, happens when the target is not spelled `dev` (IMPL-0052).

**Temporary worktree.** `check_feature_merge` adds a detached worktree at `.current-work/<feature-branch>/premerge/feature` after the read-only checks and removes it in a `finally` block. A failed `add` removes the path too and exits `2`. The worktree is detached, so it works while the primary checkout has the feature branch checked out. The test `test_RL_13_IT_04_the_suite_runs_in_a_temporary_worktree` checks the changed tracked file, the untracked file, the stash list, and the removal.

**File limit.** `--max-files` now defaults to no value. The story merge and every other branch still get the limit of 20 through `DEFAULT_MAX_FILES`, and `merge-story` passes its own value. Only a feature merge without `--max-files` skips the limit, so the story merge check keeps its strength.

**FC-14-IT-05.** The test checks that the stop reads only the worktree it runs in. In the primary checkout, it now checks that no `STOP:` line appears and that `PASS stale-base-signature` is printed, instead of exit `0`. Both lines show that the stop did not fire and the checks ran, so the test keeps its intent.

**Order in the playbooks.** `implementation-agent.md`, `branching-policy.md`, `feature-addition.md`, and `greenfield-development.md` give the order code review, QA, merge, reconciliation on `dev`, and the step list of `feature-addition.md` follows it. Three agent handoffs and one line of `documentation-update.md` still give the old order (IMPL-0051).

## Not checked

- The review did not run pytest, as the brief says. The commit hooks ran the suite when the developer agent committed.
- The review did not run an agent session, so it did not check that an agent follows the new order.

One probe went wrong. Its first version did not stop when its setup failed, so it ran in the invocation worktree `.current-work/feature/run-lifecycle/invocation`. There `premerge-check` exited `2` at the diff step, because `feature/x` does not exist, and wrote nothing. The probe's `rm -f .current-work/premerge-check-ok` deleted the pass marker of that worktree. The next `git merge` from that worktree needs a new run of `premerge-check` for its branch.
