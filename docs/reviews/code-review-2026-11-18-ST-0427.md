# Code review of ST-0427, the git guardrail in four agent tools

## Result

The review found one major defect. The script lets an agent run `dispatch return-story` and `dispatch close --drop` in shell forms that the seven forms of the Outline do not cover. The worst case is `dispatch --ledger <path> return-story ST-0350`, the form that `dispatch` itself asks for when it cannot choose a ledger. IMPL-0021 blocks the merge of the story.

The other parts hold. The payload reading of Copilot and pi is correct. The run lookup admits the commit of a real run and refuses a branch that no ledger lists. The TypeScript wrapper blocks the call when the script is missing or fails.

Next, the Implementation Agent sends IMPL-0021 to the developer agent and submits the branch for review again. The story is not ready for reconciliation.

## Checked and correct

- **Payloads.** Copilot's `toolArgs` as a JSON string now gives the command, so `git push origin dev` and `dispatch close --drop` exit `2`. Before the change, the script read an empty command and allowed every Copilot call. A `toolArgs` string that is not JSON gives an empty command, and the script then allows the call, as for any payload without a command. pi's `.input.command` gives the command.
- **Run lookup.** `story/ST-0427` is found in `.current-work/feature/run-lifecycle/dispatch-ledger.yaml`. `story/ST-0426` has `branch: null` in that ledger and is not found. So is `story/ST-042`, a prefix of a listed branch. The pattern needs leading spaces before `branch:`, so the keys `feature_branch:` and `invocation_branch:` never match. The check runs only in a linked worktree, so a commit in the primary checkout on `dev` skips it, as RL-16-IT-06 requires.
- **Fail closed in pi.** The wrapper blocks the call when the script is missing, when `bash` cannot start (`run.error`), and on any exit code other than `0`. It finds the script of the primary checkout from a linked worktree through `--git-common-dir`, and a test covers that path.
- **Rules of the old TypeScript file.** Every rule has a counterpart in the script, as the Analysis of the story states.

## Not checked

- The review ran no real Claude Code, Codex, Copilot, or pi session. The payload shapes come from the tests and the contract.
- The review did not run `dispatch close` or `dispatch return-story`, because no subcommand of that name exists in `packages/factory/scripts/dispatch` yet.
