## 🛑 Stop Doing

- **Retrying `run_agent` blindly after repeated envelope errors without first
  checking whether the child already produced artifacts.** Evidence: 5+
  identical planning dispatches when `backlog/ST-0073.md` was committed after
  the first attempt. Check `git log`/working tree before re-dispatching.
- **Treating the `run_agent` envelope error as a real dispatch failure.** It is
  a *final-message handshake* failure; the child persists artifacts first, so
  the work is usually done. Evidence: reconciliation + planning both committed
  before the error surfaced.

## ▶️ Continue Doing

- **Scope-boundary discipline in dispatch tasks** — telling the agent exactly
  which paths it may and may not touch (root/factory/orchestrator only) kept
  the reconciliation run clean and prevented collateral edits to
  `docs/spec`/`docs/adr`. Evidence: reconciliation changed only in-scope files.
- **One-question-at-a-time decision grilling** — irreversible-scope decisions
  (domain boundary, contract location) were each locked before the next.
- **Recording strategy decisions in the proposal inline** with the acceptance
  — so the accepted baseline and planning inputs all live in one place.
- **Using the repo's own gates for validation** (`backlog-lint` on ST-0073,
  pre-commit hooks on the acceptance commit) instead of trusting agent reports.

## 🆕 Start Doing

- **Treat `run_agent` artifact-check as a pre-retry step.** Before re-dispatching
  after an envelope error: run `git log --oneline -5` + `git status` in the
  worktree; if the child committed, do not retry. Emerged from: 8 spurious
  failures this session.
- **File a BUG for the `run_agent` envelope-parse gap.** The strict
  single-JSON-object requirement on the child's final message is flaky and
  produces false negatives that hide completed work — a reliability defect in
  the Pi invocation layer (UC-10). Emerged from: all 8 failures this session.
- **Surface partial child output on envelope failure.** The error returns no
  artifact listing; showing committed SHAs/artifact paths would have told me
  instantly the work was done. Emerged from: ~30 min of uncertainty resolving.
- **Recheck claimed defects before filing** — the suspected RETRO-FORMAT path
  defect was a false positive: the skill references `RETRO-FORMAT.md` relative
  to its own directory and the file exists there correctly. The ENOENT hit was
  my own hardcoded path, not a skill bug. Emerged from: ENOENT on first format
  lookup, initially misattributed to the skill.
