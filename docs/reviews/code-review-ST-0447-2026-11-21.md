## Catches CRAP and the refusals

"Catches CRAP" passes only when gate run 1 exits 1 and the first row named `proof_untested` has `pass_fail: fail`. The complexity check reads the same first row of each name in the same rows, so it judges the row that "Catches CRAP" judges. The review walked each way a lying command could reach that pass:

| Case of the rows of gate run 1                                                    | Result                                                                                                                                                       |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 100 % coverage for every function, complexity at or below the threshold           | The score equals the complexity, so `proof_untested` passes and "Catches CRAP" fails with exit 1.                                                            |
| 100 % coverage, a planted complexity above the threshold                          | The complexity check refuses with exit 2 before any check.                                                                                                   |
| Two different planted complexities                                                | Refused with exit 2.                                                                                                                                         |
| No row of `proof_untested` or `proof_tested`, also an empty array                 | Refused with exit 2, and the message names the missing function.                                                                                             |
| A complexity of 0, a negative one, a fraction, a text, or `true`                  | `crap-score` refuses the row with exit 2, so gate run 1 has no rows and "Repeatable" fails with exit 1.                                                      |
| Two rows of `proof_untested` in two files                                         | Both the complexity check and `find_row` take the first row, so a refused first row stops the proof and an accepted one is the row that "Catches CRAP" sees. |
| A plant whose code lies outside the `files` pattern, or without `base/` or `gap/` | Refused with exit 2 before the measuring command starts.                                                                                                     |

A command that reports 0 % coverage for `proof_untested` and 100 % for `proof_tested` looks like an honest command to all four checks. That lie names the planted functions, so no refusal of this story can see it, and DEC-31 does not ask for it.
