## Stop Doing

- **Trusting that QA-in-worktree validates the same code that pre-commit hooks will test.** The QA agent tests against `packages/factory/` in its worktree, but the pre-commit hook tests against the installed `factory/` copy in the main checkout. These can diverge after implementation without an intervening `update-factory --force`. Evidence: 25 test failures surfaced only after the QA agent reported clean.
- **Letting branch and worktree cleanup accumulate across sessions.** 28 worktrees and 38 merged branches accumulated over multiple sessions before being cleaned. The cleanup itself took significant time and required 12 individual `-D` approvals. Evidence: this session's cleanup pass.

## Continue Doing

- **Multiple adversarial review passes on proposals before planning** — three passes caught distinct categories of errors (factual, structural, process). A single pass would have missed at least one. Evidence: three separate proposal-review-agent dispatches, each finding new issues.
- **Fixing output path mismatches on the invocation branch before dispatch** — catching the `factory/` vs. `packages/factory/` discrepancy before story agents ran prevented 5 stories from writing to wrong paths. Evidence: commit `4929600`.
- **Running Fagan inspection after merge to the feature branch, before merge to dev** — the inspection found a major defect that would have shipped to dev. Evidence: 7 findings in `74f7041`, all fixed before the merge commit `5461b09`.
- **Tagging releases with changelog updates** — v0.8.0 tagged with a changelog commit (`3334258`) gives a clear audit trail for what shipped.

## Start Doing

- **Enforce `dispatch init` mechanically** — add a gate in `verify-base` or `block-dangerous-git` that requires a dispatch ledger (produced only by `dispatch init`) before a story branch can receive commits. Without this, the implementation agent can bypass the dispatch workflow entirely. Emerged from: implementation agent creating story branches directly without `dispatch init`.
- **Fix index-lint to preserve symlinks** — when the target path is a symlink, index-lint should write to the symlink target (the real file in `packages/factory/`) rather than replacing the symlink with a regular file. Alternatively, `update-factory` should handle the case where a regular file exists at the expected symlink location. Emerged from: `update-factory` collisions after every index-lint run.
- **Add `update-factory --force` to the pre-commit or pre-merge workflow** — when testing code that changed `packages/factory/`, ensure the installed `factory/` copy is current before tests run. Emerged from: 25 stale-factory test failures.
- **Add `--check`/`--dry-run` to init-factory** — feature parity with `update-factory`. A user should be able to preview what init-factory would do without modifying the filesystem. Emerged from: user expectation mismatch.
- **Schedule periodic branch/worktree cleanup** — either a post-merge hook or a session-start check that reports orphaned worktrees and fully-merged branches, prompting cleanup before they accumulate. Emerged from: 28+38 cleanup debt.
- **Batch-approve guardrail-blocked cleanup operations** — `git branch -D` on orphaned agent branches is routine maintenance, not a dangerous operation. Consider an allowlist pattern for `worktree-agent-*` branch deletion in `block-dangerous-git.sh`, or a `dispatch cleanup` script that handles this in one pass. Emerged from: 12 individual approval rounds for routine cleanup.
