# Code review of the IMPL-0197 handbook index fix

## Verdict

Two major findings block the fix. Ordinary prose spaces now survive the hook sequence. A bracketed title still fails lint after formatting, and the generator changes whitespace inside inline code.

## Scope

The review covered the generator and its regression tests, the two changed files. The Fix section of `docs/findings/IMPL-0197.md` defines the scope. BR-140 and BR-144 to BR-148 define the relevant inputs, generated lists, and checks.

## Standards

The generator keeps formatting in its existing rendering functions. The only dependency issue is in the test, where the formatter wrapper resolves packages outside the locked default-suite environment.

## Spec

The new tests cover repeated spaces in a page title and description. They use `handbook-index --check` after formatting. The repository hook calls `handbook-lint`, which uses the same stale-list comparison and also checks the handbook rules.

The bracket case blocks the fix because BR-140 permits the title and the formatter still rewrites generated bytes. The absence of bracketed titles in current pages limits exposure. The description regression changes text that BR-144 requires the list to include.

## Verification

All 109 tests in `test_handbook_index.py` and `test_handbook_lint.py` passed with the wrapper's four plugins available from a writable scratch cache. The initial run passed 107 tests and failed both added cases because the sandbox blocked writes to the default uv cache. An intermediate offline run with an incomplete cache also failed to load a formatter dependency.

On scratch copies, `mdformat --number` followed by `handbook-lint` passed for a description with repeated prose spaces. With a bracketed title, lint passed before formatting and failed after formatting. A base-to-head comparison showed the inline command change during generation. The full formatter kept the base command's two spaces on a separate input.

The current worktree passed `handbook-index --check`, `handbook-lint`, and the scoped `git diff --check`. The review invoked the hook commands directly in repository order and skipped pre-commit's staging wrapper.
