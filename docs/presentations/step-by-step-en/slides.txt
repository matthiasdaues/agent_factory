```grid 99x25
    **FIVE WORDS**
    %%all the vocabulary you need to start%%


    ┌──────────────────┐ calls  ┌──────────────────┐delivers┌──────────────┐     ┌─────────────┐
    │     PLAYBOOK     │───────►│      AGENT       │───────►│   ARTEFACT   │────►│    GATE     │
    │    the recipe    │    ┌──►│     one job      │        │  a document  │     │  checks it  │
    └──────────────────┘    │   └──────────────────┘        └──────────────┘     └─────────────┘
                            │             │ follows
              knowledge     │             ▼
    ┌──────────────────┐    │   ┌──────────────────┐
    │     CONTEXT      │────┘   │      SKILL       │
    │  the fact sheet  │        │  the procedure   │
    └──────────────────┘        └──────────────────┘


    **Agent**      one job: write the requirements, review the architecture, fix one bug
    **Skill**      the written procedure an agent follows to do its job well
    **Playbook**   the recipe: which agents run, in what order, for a common situation
    **Gate**       an automatic check that catches mistakes before they cost you time
    **Context**    a few files where the project declares its stack, workflow and rules
```

```grid 99x25
   ~~Reviewer~~
   spec-review     architecture-   backlog-lint    code-review     bug hunt        findings to
                   review (ATAM)   and you                         with tests      their owner


    **You approve every handover.**
    Small tasks use shorter playbooks that touch only the kinds of work they need.
    If something needs rework, you fix the artefact directly.
    There is no "going back to an earlier phase".
```

```grid 99x25

    **5  QUALITY AND RECONCILIATION**
    %%review independently, hunt bugs, then match the docs to the code%%

   ┌────────────────────────────┐     ┌────────────────────┐     ┌─────────────────────────────┐
   │          QA AGENT          │     │   PREMERGE-CHECK   │     │       RECONCILIATION        │
   │        new session         │     │   then you merge   │     │     on dev, new session     │
   │      Fagan inspection      │────►│      into dev      │────►│      specification and      │
   │   OWASP security review    │     │                    │     │    architecture against     │
   │          bug hunt          │     │                    │     │      the code as built      │
   │                            │     │                    │     │                             │
   └────────────────────────────┘     └────────────────────┘     └─────────────────────────────┘


    **The bug hunt, one bug at a time:**
      1  write a test that shows the bug: it fails
      2  fix the code: the test passes, and stays
      3  hunt again, until a full round finds nothing

    **Every drift found in reconciliation goes to its owner:**
      code defects to the developer, document drift to the document's author.

    **No open findings left: done. The project is ready for the next feature.**
```

```grid 99x25
    The code as built tests the         │  docs against  │◄─│    review,    │◄─│   the whole   │

    **Going forward, each stage settles what the stage before left open.**
    Each decision rests on assumptions. They are firm enough to build on,
    but only the code shows whether they hold.

    **When an assumption fails, its owner corrects the document, not only the code.**
```

```grid 99x25

    **WHICH PLAYBOOK, WHEN**
    %%the recipe that matches your situation%%

    **You want to …**                                             **Start with**
    ───────────────────────────────────────────────────────────────────────────────────────────
    See whether a rough idea works at all                     poc-spike
    Validate a technical risk before committing to it         technical-poc
    Fix one reported bug                                      bug-fix
    Bring the docs back in line with the code                 documentation-update
    Build a new project properly, start to finish             greenfield-development
    Add the factory to code that already exists               brownfield-onboarding
    Add a feature to a project the factory manages            feature-addition
    Restructure code without changing behaviour               refactoring
    Evaluate an architecture against quality goals            architecture-review
    Survey a topic with sourced citations                     research-survey
    Test a specific claim by trying to refute it              research-topic


    A playbook describes a typical path, not a fixed one. Which agents may run next
    follows from the artefacts that already exist.
```

```grid 99x25
    **EXTENDING THE FACTORY**
    %%fit it to your project, and add what only your project needs%%

   ┌─** FIT IT TO YOUR PROJECT **─────────────────┐   ┌─** ADD YOUR OWN PARTS **───────────────────────┐
   │                                          │   │                                            │
   │ model matrix  which model for what       │   │ skills     a procedure only you need       │
   │ agent context where knowledge lives      │   │ agents     a job only your project has     │
   │ test regime   how the project tests      │   │ templates  the shape of your documents     │
   │ hooks         which checks run on commit │   │                                            │
   │ conventions   yours override the defaults│   │ Ask the agent to add the part and to       │
   │                                          │   │ refresh INDEX.yaml and the Copilot agents. │
   └──────────────────────────────────────────┘   └────────────────────────────────────────────┘

    **EXAMPLE: A CAMUNDA TEAM**
    "Add a skill bpmn-model-review that checks our BPMN models, and refresh INDEX.yaml."
    Copilot writes the skill into .agent-factory/factory/skills/ and runs index-lint.

    **An update saves your parts, but does not put them back.**
    update-factory stops and names each file you added. With --force, it copies the files
    to .agent-factory/user-changes/ and installs the new release. Ask the agent to copy them back.
    ~~Git ignores .agent-factory/, so your parts stay on your machine. Share them by hand.~~

    **Useful for every project? Propose it for the factory core.**
```
