    **FÜNF BEGRIFFE**
    %%mehr Wortschatz braucht es für den Anfang nicht%%


    ┌──────────────────┐ ruft   ┌──────────────────┐ liefert┌──────────────┐     ┌─────────────┐
    │     PLAYBOOK     │───────►│      AGENT       │───────►│   ARTEFAKT   │────►│    GATE     │
    │    das Rezept    │    ┌──►│   eine Aufgabe   │        │ ein Dokument │     │    prüft    │
    └──────────────────┘    │   └──────────────────┘        └──────────────┘     └─────────────┘
                            │             │ folgt
               Wissen       │             ▼
    ┌──────────────────┐    │   ┌──────────────────┐
    │     CONTEXT      │────┘   │      SKILL       │
    │  der Steckbrief  │        │   das Vorgehen   │
    └──────────────────┘        └──────────────────┘


    **Agent**      eine Aufgabe: Anforderungen schreiben, Architektur prüfen, einen Fehler beheben
    **Skill**      die Arbeitsanweisung, nach der ein Agent seine Aufgabe erledigt
    **Playbook**   das Rezept: welche Agenten in welcher Reihenfolge, für eine typische Lage
    **Gate**       eine automatische Prüfung, die Fehler fängt, bevor Sie Zeit verlieren
    **Context**    wenige Dateien, in denen das Projekt Stack, Ablauf und Regeln festhält

    ~~Den Katalog liest der Assistent selbst: INDEX.yaml listet jeden Agenten, Skill und Playbook.~~

               ▲                                                                  │
               │                        ~~Befunde gehen an den Autor zurück~~         │
               ┌──────────────────────────────────────────────────────────────────┘

    Warum: Den Fehler, den man selbst übersieht, findet man selbst nicht.
    Derselbe blinde Fleck, der ihn erzeugt, verbirgt ihn auch.

    **Autor**                        **Prüfer**
    requirements-agent     ──►   spec-review-agent
    architecture-agent     ──►   architecture-review-agent
    implementation-agent   ──►   code-review-agent, qa-agent
    die gebaute Software   ──►   reconciliation-agent

    **Die Trennung machen Sie: Für jede Prüfung öffnen Sie eine neue Sitzung.**

    **5  QUALITÄT UND ABGLEICH**
    %%unabhängig prüfen, Fehler jagen, dann Doku und Code abgleichen%%

   ┌────────────────────────────┐     ┌────────────────────┐     ┌─────────────────────────────┐
   │          QA-AGENT          │     │   PREMERGE-CHECK   │     │       RECONCILIATION        │
   │        neue Sitzung        │     │     dann Merge     │     │    auf dev, neue Sitzung    │
   │      Fagan-Inspektion      │────►│      nach dev      │────►│      Spezifikation und      │
   │   Sicherheit nach OWASP    │     │     durch Sie      │     │    Architektur gegen den    │
   │         Fehlerjagd         │     │                    │     │        gebauten Code        │
   │                            │     │                    │     │                             │
   └────────────────────────────┘     └────────────────────┘     └─────────────────────────────┘


    **Die Fehlerjagd, Fehler für Fehler:**
      1  Test schreiben, der den Fehler zeigt: er ist rot
      2  Code reparieren: der Test wird grün und bleibt
      3  erneut jagen, bis eine Runde nichts mehr findet

    **Jede Abweichung im Abgleich geht an ihren Eigentümer:**
      Code-Fehler an den Developer, Doku-Drift an den Autor des Dokuments.

    **Keine offenen Befunde mehr: fertig. Das Projekt ist bereit für das nächste Feature.**
