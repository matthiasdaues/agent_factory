# SR-0009 — OpenCode Official Permissions Documentation

## Provenance

- **URL**: https://opencode.ai/docs/permissions/
- **Accessed**: 2026-09-18
- **Type**: official documentation
- **Freshness**: current (2026)

## Evidence

### Permission Model

Three outcomes: `"allow"` (runs without approval), `"ask"` (prompts user), `"deny"` (blocks execution).

### Configuration

In `opencode.json`:

```json
{
  "permission": {
    "*": "ask",
    "bash": "allow",
    "edit": "deny"
  }
}
```

Uniform: `"permission": "allow"`.

### Granular Rules

Wildcard matching (`*` for multiple, `?` for single). Last matching rule wins:

```json
{
  "bash": {
    "*": "ask",
    "git *": "allow",
    "rm *": "deny"
  }
}
```

### Available Permission Keys

`read`, `edit`, `glob`, `grep`, `bash`, `task`, `skill`, `lsp`, `question`, `webfetch`, `websearch`, `external_directory`, `doom_loop`.

### Defaults

Most default to `allow`. Exceptions: `doom_loop` and `external_directory` default to `ask`. `.env` files denied by default.

### Auto Mode

`--auto` flag auto-approves non-denied requests. Explicit `deny` rules remain enforced.

### Agent-Specific Permissions

Agent-level rules take precedence over global. Configurable in JSON config or markdown frontmatter.

### Approval Prompts

Options: `once` (single), `always` (session duration), `reject`.

## Limitations

- Does not document how permissions interact with hooks (hooks not yet supported from Claude Code).
- Does not document permission inheritance for subagent sessions.
