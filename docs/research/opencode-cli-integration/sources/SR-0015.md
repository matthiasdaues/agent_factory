## Evidence

### 1. Subagent Depth Configuration

The `subagent_depth` key in `opencode.json` controls how many nesting
levels the Task tool allows.

- **Default**: 1 (primary agents can launch subagents; those subagents
  cannot launch further subagents).
- **Range**: 0 (disable all subagent launches) to any positive integer.
- **Location**: project-level `opencode.json` or global
  `~/.config/opencode/opencode.json`.

The official config documentation states: "Controls nesting levels for
subagent invocation."

### 2. No Built-In Recursion Guard

GitHub issue #18100 (opened 2026, closed as "not planned") reported
that OpenCode has no runtime recursion depth guard on the Task tool. A
real-world example produced 47 sessions with 20 nesting levels and 18
layers of explore-to-explore delegation. The issue proposed a default
limit of 3 levels. The maintainers closed the issue without
implementing a guard.

The `subagent_depth` configuration key is the only built-in control.
When the configured depth is reached, the Task tool is removed from the
subagent's tool set.

### 3. Plugin Override of Subagent Depth

The official plugin API documentation (SR-0013) does not expose a
`subagent_depth` setter on the plugin context. However, the `context`
session hook can remove the `task` tool from a child session's tool map:

```ts
await ctx.session.hook("context", (event) => {
  if (depthExceedsLimit(event)) {
    delete event.tools.task
  }
})
```

A community plugin (`opencode-subagent-depth-limit`) provides
per-session depth configuration with a `maxDepth` option (default 2).
This demonstrates that plugins can enforce depth limits through tool
removal, even though no dedicated API exists.

The `subagent_depth` config key cannot be set per-agent in agent
frontmatter. It is a global setting. A plugin that needs per-agent
depth limits must implement the logic itself using the `context` hook.

### 4. Model Inheritance Bug

The model inheritance bug persists in V2. Three GitHub issues document
the problem across versions:

**V1 (issue #17870, closed as not planned)**: When a parent switches
to a non-default model during a session, subagents spawned via the Task
tool use the global `model` from `opencode.json` instead of the
parent's active session model. A PR (#14961) added an explicit `model`
parameter to the Task tool as a workaround.

**V1 (issue #26536, closed as not planned)**: Feature request to add a
`model` parameter to the Task tool schema for dynamic model selection
at invocation time. Proposed resolution hierarchy: invocation parameter
greater than agent configuration greater than parent session model.

**V2 (issue #49765, open as of 2026-09-18)**: On OpenCode 2.0.8, the
`agents.<name>.model` field loads into the agent catalog but is not
applied when a subagent spawns. The root cause is identified:
`SessionRunnerModel.resolve` in
`packages/core/src/session/runner/model.ts` only checks `session.model`
and never consults `agent.model`. Subagents inherit the parent session's
model with the variant reset to default.

**Documented behavior vs. actual behavior**: The agent documentation
states subagents inherit the invoking primary agent's model if
unspecified. The code does not implement this inheritance.

### 5. Plugin Workaround for Model Inheritance

The `context` session hook receives the model information and could
override it. The `ctx.model` domain allows setting defaults via
transforms. A community plugin (`opencode-subagent-models`) implements
per-session model switching for subagents. However, the `context` hook
provides `event.model` as a readonly property (per SR-0013's
`SessionRequestHook` interface), so the override mechanism is unclear.

A separate approach: the `ctx.session.hook("prompt")` hook can modify
the prompt to include explicit model instructions, but this does not
change the model the session uses.

- **Search**: "opencode V2 model inheritance fixed resolved" on GitHub

  V2 regression.
- **Search**: "opencode subagent_depth per-agent frontmatter" on

  model.

## Limitations

- Issue #49765 was open as of 2026-09-18. Its status may have changed
  since that date.
- The `subagent_depth` documentation does not state what happens when a
  subagent at the configured depth tries to invoke the Task tool. The
  behavior (tool removed, error returned, or silently blocked) is
  inferred from the community plugin's approach (tool removal), not
  from official documentation.
- The model override through plugins is documented only indirectly.
  No official example shows a plugin changing the model for a child
  session. The `context` hook's `event.model` field is typed `readonly`
  in the documented interface, which suggests modification is not
  supported through this hook.
- The community plugin `opencode-subagent-depth-limit` is a third-party
  artifact. Its approach (tool removal via context hook) is consistent
  with the official API but is not endorsed by the OpenCode team.
