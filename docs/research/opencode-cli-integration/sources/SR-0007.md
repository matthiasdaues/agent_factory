# SR-0007 — OpenCode Claude Code Hooks Compatibility (GitHub Issue #12472)

## Provenance

- **URL**: https://github.com/anomalyco/opencode/issues/12472
- **Accessed**: 2026-09-18
- **Type**: GitHub issue (feature request)
- **Freshness**: open issue as of 2026-09-18

## Evidence

### Status

**Open** — unresolved feature request. Claude Code hooks are NOT natively supported in OpenCode.

### What Is Missing

OpenCode reads `.claude/CLAUDE.md` and `.claude/skills/*/SKILL.md` from Claude Code projects, but does NOT read or execute `.claude/settings.json` hooks. Three Claude Code hook events are requested:

- **PreToolUse** — executes before tool operations
- **PostToolUse** — tracks state changes after tool execution
- **Stop** — validates workflow completion before session termination

### Critical Gap: Stop Hook Re-activation

Claude Code's Stop hook can exit with code 2, injecting stderr back as a prompt so the agent continues working. OpenCode's `session.idle` event is "fire-and-forget" — it cannot signal the agent to resume with injected feedback.

### Proposed Implementation

Map Claude Code hooks to OpenCode events with exit code signaling (0=allow, 2=block/re-activate). Add `OPENCODE_DISABLE_CLAUDE_CODE_HOOKS` environment variable.

## Limitations

- This is an open feature request, not implemented functionality.
- No timeline or milestone attached to the issue.
- The factory's step guards and git safety hooks rely on PreToolUse — without this, the factory's guardrail system cannot be ported to OpenCode via `.claude/settings.json`.
