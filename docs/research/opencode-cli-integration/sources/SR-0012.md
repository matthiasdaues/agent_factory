## Evidence

### Six-Layer Prompt Assembly Order

1. **Provider Header** — identity assertion, knowledge cutoff, date.
2. **Provider-Specific Prompt** — model-tailored instructions per provider (Anthropic/OpenAI/Google).
3. **Environment Information** — working directory, git status, platform, current date, project file structure.
4. **Custom Instructions (AGENTS.md / CLAUDE.md)** — project-specific guidelines from discovered instruction files.
5. **Agent-Specific Prompt** — custom agent instructions from `.opencode/agents/` definitions.
6. **User Override** — `--system` flag for single-session customization.

### Discovery Mechanism

AGENTS.md files found via upward path traversal from working directory. "Local files found first stop the search for that file type." All discovered sources combine (cumulative) into unified context.

### Implication for Factory Integration

The factory's orientation file (AGENTS.md or CLAUDE.md) would be injected at layer 4. Agent-specific prompts from `.opencode/agents/` arrive at layer 5. This means the factory's session start instructions would load before any agent-specific prompts — the same order as Claude Code.

## Limitations

- Community documentation, not official. May lag behind OpenCode releases.
- Does not document whether the `instructions` config field merges with or replaces discovered AGENTS.md files.
