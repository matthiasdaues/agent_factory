## Evidence

### Task Tool (Subagent Dispatch)

OpenCode's `task` tool spawns subagent sessions. Subagents with `mode: "subagent"` are invocable via `@agent-name` mentions or the `task` tool.

### Subagent Depth

`subagent_depth` config key (default: 1) limits nesting. However, GitHub issue #18100 notes there is no recursion depth guard at runtime — subagents at any depth can spawn further subagents without a hard limit.

### Model Inheritance Issue

GitHub issue #17870: subagents spawned via the `task` tool do not inherit the parent session's active model — they fall back to the global `model` in `opencode.json`.

### Nested Subagent Spawning

GitHub issue #9280: feature request to allow subagents to spawn subagents, which was implemented.

### Parallel Execution

OpenCode is identified as one of six tools that run sub-agents in parallel as of 2026. Multi-session support enables parallel tasks.

### Worktree Isolation

Not built into OpenCode natively at the session level. Each subagent gets a child session, but worktree isolation is advisory (suggested via instructions), not enforced by the runtime. External tools (Superset, opencode-skein) provide worktree management on top.

## Limitations

- Native worktree isolation per subagent is not available — must be orchestrated externally or via instructions.
- Model inheritance between parent and subagent is broken (known bug).
- `subagent_depth` default of 1 means single-level nesting by default; must be configured higher for multi-level dispatch.
