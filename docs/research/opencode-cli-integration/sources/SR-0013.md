## Provenance

- **URL**: https://opencode.ai/v2/docs/build/plugins
- **Accessed**: 2026-09-21
- **Type**: official documentation (vendor-published)
- **Author**: OpenCode team (opencode.ai)
- **Publisher**: opencode.ai
- **Source family**: OpenCode official V2 documentation
- **Freshness**: current as of 2026-09-21; page updated July 2026 per site metadata

## Evidence

### 1. Plugin Structure

A V2 plugin exports a default object created by `Plugin.define()` from
`@opencode/plugin`. The object carries an `id` string and a `setup(ctx)`
function. The setup function receives a plugin context and may return a
cleanup function.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    // context properties:
    // ctx.app.version — OpenCode version string
    // ctx.location.directory — plugin instance directory
    // ctx.location.project — { id, directory, canonical }
    // ctx.options — config options from opencode.json
    // ctx.storage — persistent key-value store
    return () => console.log("unloaded")
  },
})
```

V1 plugins used `server()` returning a hooks object. V1 implementations
do not run in V2. A package can support both versions by exporting both
`setup()` (V2) and `server()` (V1) on the same default export.

### 2. Tool Registration and Removal

The `ctx.tool` domain uses synchronous transforms to add, update, or
remove tools. Transforms are replayable registrations that edit OpenCode
state.

```ts
interface ToolContext {
  list(): Promise<readonly (ToolInfo & { readonly id: string })[]>
  transform(callback: (editor: ToolEditor) => void): Promise<Registration>
  reload(): Promise<void>
}

interface ToolEditor {
  list(): readonly (ToolInfo & { readonly id: string })[]
  get(id: string): (ToolInfo & { readonly id: string }) | undefined
  namespace(namespace: { name: string; description: string }): void
  add(tool: ToolInfo): void
  update(id: string, update: (tool: Types.Mutable<ToolInfo>) => void): void
  remove(id: string): void
}
```

A plugin can remove any tool by its effective ID (including built-in
tools). Calling `registration.dispose()` removes the transform and
rebuilds the tool set from remaining transforms.

### 3. Tool Interception (Pre/Post Hooks)

Two tool-execution hooks exist:

- `execute.before` — fires before the tool runs; receives tool name and
  input; can inspect or replace input.
- `execute.after` — fires after execution; receives completion status,
  result or error; can modify the result.

```ts
interface ToolHooks {
  "execute.before": ToolExecuteBefore
  "execute.after": ToolExecuteCompleted | ToolExecuteFailed
}

await ctx.tool.hook("execute.before", (event) => {
  if (event.tool === "read") console.log(event.input)
})

await ctx.tool.hook("execute.after", (event) => {
  if (event.status === "completed")
    event.result = { ...event.result, metadata: { observed: true } }
  if (event.status === "error")
    console.error(event.error.message)
})
```

### 4. Permission Evaluation

The `ctx.permission` domain exposes an `evaluate` hook. The hook runs
after configured `allow` and `ask` rules but before action execution. An
explicit configured `deny` is final and does not invoke hooks.

A hook may change the `effect` field to `allow`, `ask`, or `deny`. The
`message` field appears in escalated requests or becomes the denial
reason.

```ts
interface PermissionEvaluation {
  readonly sessionID: string
  readonly agent?: string
  readonly action: string
  readonly resources: readonly string[]
  readonly metadata?: Record<string, unknown>
  readonly source?: { type: "tool"; messageID: string; id: string }
  effect: "allow" | "ask" | "deny"
  message?: string
}

await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return
  event.effect = "deny"
  event.message = "Factory policy: write denied outside manifest boundary"
})
```

### 5. Session Observation

The `ctx.session` domain provides hooks for multiple session lifecycle
events:

| Hook name       | Purpose                                                           |
| --------------- | ----------------------------------------------------------------- |
| `prompt`        | Intercept user prompts before attachment and skill resolution     |
| `context`       | Modify system instructions, messages, tools before the agent loop |
| `compaction`    | Override or supply checkpoint summary generation                  |
| `generate`      | Modify standalone generation calls                                |
| `title`         | Supply or modify session title                                    |
| `http.request`  | Modify outbound HTTP requests                                     |
| `http.response` | Modify inbound HTTP responses                                     |
| `retry`         | Override retry decisions and delays                               |

The `context` hook is particularly relevant for the Factory. It receives
the full agent-loop context and can modify system instructions, remove
tools from the tool map, adjust temperature and max tokens, and inject
additional system text.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text",
    text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
})
```

The `prompt` hook can modify user input, attach files, and control
delivery mode (`queue`). It fires before skill and attachment resolution.

Event subscription to the server event stream is available through
`ctx.event.subscribe()`.

### 6. Worktree Management

The `ctx.worktree` domain allows a plugin to register a custom worktree
strategy and perform worktree operations.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(
    input: { directory: string; force: boolean },
    context: { signal: AbortSignal },
  ): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Operations: `ctx.worktree.create()`, `ctx.worktree.list()`,
`ctx.worktree.refresh()`, `ctx.worktree.remove()`. All require a
`projectID`.

### 7. Additional Domains

- **Model management** (`ctx.model`) — list models, set defaults, enable
  or disable per provider via transforms.
- **Provider management** (`ctx.provider`) — modify provider headers,
  rename models via transforms.
- **Command registration** (`ctx.command`) — add slash commands.
- **Storage** (`ctx.storage`) — persistent key-value store with scan
  and prefix support.

## Limitations

- Official vendor documentation. May describe intended behavior rather
  than implemented behavior. The documentation does not carry version
  numbers for individual API methods.
- The `execute.before` hook documentation does not state whether
  returning or throwing prevents tool execution. The cc-safety-net
  plugin (SR-0016) demonstrates that returning a `Tool.Error` achieves
  denial, but the official docs do not specify this mechanism.
- No documentation on whether permission hooks fire for child sessions
  or only the root session.
- The `context` hook can delete tools from the tool map, but the
  documentation does not state whether this removal persists across
  turns within the same session or applies per-turn only.
