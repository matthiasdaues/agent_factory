## Evidence

### 1. What cc-safety-net Demonstrates

The cc-safety-net plugin is a safety-enforcement plugin that migrated
from V1 to V2. The PR demonstrates that the following V2 plugin
capabilities work in practice (not just in documentation):

- **Tool interception with typed denials**: The plugin registers
  `tool.execute.before` hooks that return typed `Tool.Error` denials,
  preventing tool execution.
- **Shell validation**: The plugin registers `shell.create.before`
  hooks that enforce explicit shell dialect matching at spawn time and
  block dangerous commands.
- **Command registration**: The plugin registers a `/cc-safety-net`
  command, extending the host's command interface.
- **Code-mode child call protection**: The plugin guards nested
  execution contexts beyond direct tool invocations.
- **Context preservation**: The plugin preserves command prompt context
  and built-in command context across operations.

### 2. Enforcement vs. Observation

The PR demonstrates that V2 plugins can enforce behavioral constraints,
not just observe events. The plugin actively blocks tool calls and shell
commands that violate its policy. This distinguishes V2 plugins from
passive event listeners.

### 3. Relevance to Factory Integration

The cc-safety-net plugin's capabilities map directly to three Factory
requirements:

| cc-safety-net capability                         | Factory equivalent                                |
| ------------------------------------------------ | ------------------------------------------------- |
| Tool execution denial via `execute.before`       | Step guard (reject reads/writes outside manifest) |
| Shell command blocking via `shell.create.before` | Git safety hook (block destructive git commands)  |
| Command registration                             | Factory slash commands                            |

The PR does not demonstrate permission evaluation hooks, worktree
management, or session observation. These capabilities are documented in
the official API (SR-0013) but not exercised by this plugin.

## Limitations

- This is a third-party plugin, not an OpenCode team project. Its
  correct operation does not guarantee that all documented API features
  work correctly.
- The PR demonstrates enforcement via `Tool.Error` returns from
  `execute.before`, but the official API documentation (SR-0013) does
  not document this return-type mechanism. The official docs show hooks
  as void or Promise-of-void callbacks.
- The plugin does not exercise permission hooks, worktree transforms,
  or model overrides. These remain documented but unverified by
  independent source.
- The PR description does not include test results or CI status.
  Correct behavior is claimed but not independently verified.
