# SR-0014 — Claude Code Compatibility Mode and Instruction Conflicts

## Provenance

- **URL (primary)**: https://opencode.ai/docs/rules/
- **URL (supporting)**: https://gist.github.com/zeke/c6bed98a445e559b0d3563087b5e6764
- **Accessed**: 2026-09-21
- **Type**: official documentation (opencode.ai) supplemented by community

- **Author**: OpenCode team (official page); zeke (community gist)
- **Publisher**: opencode.ai; github.com
- **Source family**: OpenCode instruction discovery documentation
- **Freshness**: official page current as of 2026-09-21; gist undated,
  content consistent with current OpenCode behavior

## Evidence

### 1. Claude Code Compatibility Behavior

OpenCode reads Claude Code files as a fallback when no OpenCode-native
equivalent exists:

- **Project level**: reads `CLAUDE.md` if no `AGENTS.md` exists in the
  same directory.
- **Global level**: reads `~/.claude/CLAUDE.md` if no
  `~/.config/opencode/AGENTS.md` exists.
- **Skills**: discovers `~/.claude/skills/` and `.claude/skills/`
  directories.

The community gist confirms: "If you have different instructions for
Claude Code vs OpenCode, you may get unexpected behavior. Your Claude
Code instructions will be applied to OpenCode sessions automatically."

### 2. Instruction Precedence

When both file types exist at the same location, `AGENTS.md` takes
precedence and `CLAUDE.md` is not loaded. The official documentation
states: "The first matching file wins in each category."

The `instructions` config field in `opencode.json` supplements
auto-discovered files. The official page states: "All instruction files
are combined with your `AGENTS.md` files." The `instructions` field
therefore merges with discovered files rather than replacing them.

### 3. Environment Variables to Control Compatibility

Three environment variables disable parts of Claude Code compatibility:

| Variable                                | Effect                                      |
| --------------------------------------- | ------------------------------------------- |
| `OPENCODE_DISABLE_CLAUDE_CODE=1`        | Disables all Claude Code support            |
| `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` | Disables only `~/.claude/CLAUDE.md` loading |
| `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1` | Disables only `.claude/skills/` discovery   |

The implementation condition in source code is:
`if (!Flag.OPENCODE_DISABLE_CLAUDE_CODE_PROMPT)`.

### 4. Double-Loading Risk in a Factory Project

In a project with both `.claude/` and `.opencode/` directories:

- If both `AGENTS.md` (root) and `.claude/CLAUDE.md` exist: OpenCode
  loads `AGENTS.md` and ignores `CLAUDE.md`. No double-load.
- If only `.claude/CLAUDE.md` exists (no root `AGENTS.md`): OpenCode
  loads `.claude/CLAUDE.md` as a fallback. If a Factory plugin also
  injects orientation via the `context` session hook, both the
  fallback-loaded `CLAUDE.md` and the plugin-injected orientation would
  be present. This is a double-load scenario.
- If a Factory plugin injects orientation and `AGENTS.md` exists at the
  project root: both `AGENTS.md` (layer 4 in the prompt assembly) and
  the plugin-injected text (via `context` hook, which modifies the agent
  loop) would be present. This is a second double-load scenario.

### 5. Mitigation Options

Three approaches prevent double-loading:

1. **Environment variable**: Set `OPENCODE_DISABLE_CLAUDE_CODE=1` to
   stop all Claude Code file discovery. The Factory plugin then provides
   all orientation.
2. **Dedicated `AGENTS.md`**: Provide a root `AGENTS.md` that
   supersedes `.claude/CLAUDE.md`. The plugin does not inject duplicate
   orientation.
3. **Plugin-only orientation**: The plugin injects orientation via the
   `context` hook and sets `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` to
   prevent file-based discovery of `.claude/CLAUDE.md`. Skills remain
   discoverable.

The proposal at `docs/proposals/opencode-cli-integration.md` states:
"The integration must not rely on OpenCode's Claude Code compatibility
mode or legacy V1 plugin hooks." This aligns with option 1 or 3.

### 6. No Configuration-File Toggle

The official documentation contains no `compatibility` field in
`opencode.json` to toggle Claude Code support. The toggle is
environment-variable-only.

## Contrary-Evidence Searches

- **Search**: "opencode CLAUDE.md AGENTS.md both loaded double" on
  Google and GitHub issues, 2026-09-21. No issues reporting accidental
  double-loading of instructions from both `.claude/CLAUDE.md` and
  `AGENTS.md`.
- **Search**: "opencode compatibility config field" on opencode.ai docs,
  2026-09-21. The config reference at `opencode.ai/docs/config/` does
  not list a `compatibility` field. Environment variables are the only
  documented control.

## Limitations

- The official documentation does not state whether a plugin's `context`
  hook injection combines with or replaces auto-discovered instruction
  files. The evidence supports combination (additive), but replacement
  behavior is not ruled out.
- The community gist is not authored by the OpenCode team. The
  environment variable names match what the official documentation
  describes, so the gist is consistent but not independently
  authoritative.
- The documentation does not describe the interaction between
  `OPENCODE_DISABLE_CLAUDE_CODE=1` and `.claude/skills/` discovery
  when a plugin registers its own skills via transforms. It is unclear
  whether disabling Claude Code support also prevents discovery of
  skills placed under `.claude/skills/` that the Factory expects
  OpenCode to find.
