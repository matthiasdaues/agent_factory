- README: "Once the channel is open all `NOTIFY` commands in the database that reference the channel will cause a WebSockets message to be sent to all clients listening to the channel."

- main.go, listenForNotify: on an error from `WaitForNotification`, the function logs at debug level and returns.
- Statement S10: supported. pg_eventserv relays NOTIFY payloads on a channel to WebSocket clients.
- Inferred from the code: the server issues LISTEN when the first WebSocket client opens a channel, so notifications sent before that are not seen. It keeps no buffer and replays nothing to a client that reconnects. The listen loop ends on a connection error, and the code shows no reconnect. The relay therefore inherits the loss rules of A1-SR-08 and needs the outbox of S9 for events that must not be lost.
