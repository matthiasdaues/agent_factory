# "Contradicting message" names two cases that the Server handles in opposite ways

**What is wrong:** The specification uses one term for two different cases,
and the cases have opposite storage rules.

- `interface-contracts.md:244` defines a **contradicting message** in bold: a
  message that passes the wait but matches no state change, such as a
  `PROCESS_STARTED` without a `process_identity`. The Server **stores** it in
  the `INBOX` without `applied`.
- `gigacron.feature:667` (Scenario "Contradicting message arrives"),
  `gigacron-gaps.md:61`, and the `INBOX` scope note in `entity-model.md` use
  the same word for a message with different content under a `sequence_no`
  that already exists (DEC-29). The Server **stores nothing** for it.
- `backlog/epics.md` (EPIC 4) (This refers to an epic that was cancelled on 2026-10-29. The number is now assigned to a new epic) says "log a contradicting message with its full
  payload", which fits only the second case.

A test author who reads the bold definition and then the Scenario cannot
tell whether a contradicting message produces an `INBOX` row. The two cases
need different assertions: one row with `applied` false, or no row.

**Fix:** Give each case its own term and define both once, in
`interface-contracts.md § Server Handling of Agent Messages`. For example,
call the DEC-29 case a **conflicting copy** (same number, different content,
not stored) and the other case an **unmatched message** (stored without
`applied`). Then use the chosen terms in the feature Scenario at
`gigacron.feature:667`, in `gigacron-gaps.md:61`, in the `INBOX` scope note
and column comment of `entity-model.md`, and in EPIC 4 (This refers to an epic that was cancelled on 2026-10-29. The number is now assigned to a new epic) of
`backlog/epics.md`. Add the terms to `docs/CONTEXT.md` under "Execution".
