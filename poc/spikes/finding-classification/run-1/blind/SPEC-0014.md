# The spec and the delivered code name two different Task publication routes

**What is wrong:** The interface contracts define one publication route per
draft: `POST /task-drafts/{task_draft_id}/publish`. Its only request field is
`confirm_voided`, the draft carries `runs_from`, and a refusal carries the
code of the first check that fails (`interface-contracts.md:132`,
`validation-rules.md` § Publication, DEC-48). The Task Draft state machine
says the same: "the publish request has no body".

The code that `dev` delivered with ST-0003B and ST-0003D publishes through
`POST /api/v1/publications`. That route takes `domain_id`, up to 100
`task_draft_ids` and an optional `runs_from` for all of them. It publishes all
drafts or none, and a refusal "lists the problem for every draft, not only the
first" (`backlog/ST-0003B.md:25-32`, `task_registry/routes.py::publish_task_drafts`).

The merge `1166092` ties the target-state spec to that route. The DOM-03
Scenario "Non-active Domain rejects Task Draft publication"
(`gigacron.feature:330`) now carries code references to
`routes.py::publish_task_drafts` and `DefinitionStoreService.publish_drafts`.
The scope map marks DOM-03 `implemented` (`scope-map.md:83`), and the QA row
DOM-03-API-02 points at `test_publication_routes.py`
(`gigacron-qa-strategy.md:154`). No spec artifact names `/publications`.

So the next story that builds a publication check, for example the Folder
checks of FLD-05 or `TASK_RETIRED` of DEC-53, has two contracts to follow.
They differ in three ways that a test can see:

- the route and the request body, including who sets `runs_from`;
- one draft against a batch of drafts that publishes all or none;
- the first failing code against one problem for each draft.

This differs from the known drift of successor drafts in § Task Draft. That
drift is about which drafts exist. This one is about the route that every
publication check runs behind.

**Fix:** The stakeholder decides which contract is the target. Either the
spec adopts `POST /publications` and states how the ordered checks of
§ Publication apply to each draft of a batch, how `confirm_voided` and the
request-level `runs_from` fit in, and what the refusal body holds. Or the spec
keeps the per-draft route, and the gaps report names the batch route as
delivered code that a story replaces. Then the requirements agent writes the
answer into interface-contracts.md, the Task Draft state machine and
validation-rules.md § Publication.
