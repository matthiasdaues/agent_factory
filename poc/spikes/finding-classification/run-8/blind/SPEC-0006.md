# DEF-07 Scenarios put the operational state on the Task Version

**What is wrong:** The Scenarios "Publication starts INACTIVE by default"
(gigacron.feature:81) and "Publication can start ACTIVE"
(gigacron.feature:87) assert "the Task Version is INACTIVE" and "the Task
Version is ACTIVE". The state lives on `TASK`, and a version row has no state
(DEC-19, entity-model.md § TASK and § TASK_VERSION, state-machines.md:203).
`TASK_DRAFT.start_state` is copied to `TASK.state`. This run edited both
Scenarios for the first day and kept the old wording. A test written from
them asserts a column that does not exist, or it pushes the implementation to
put state back on the version.

**Fix:** Reword the outcomes: "Then the Task is INACTIVE and its version's
first day is the next Odate" and "Then the Task is ACTIVE and its version
takes part in planning from the next Odate". Check the other DEF-07
Scenarios for the same wording.
