# Two scope rules carry the ID `DSP-05`

**What is wrong:** The scope map now has two rows with the ID `DSP-05`:

- `scope-map.md:98` (new, `specified`): Manual Execute runs the newest
  published version of an active Task at once, without Plan or Gates.
- `scope-map.md:99` (existing, `deferred`): Operators can intervene at all
  times, also while a release rolls out.

Every link to `scope-map.md#dispatch` with the text `DSP-05` now points to
two rules. The existing references mean the deferred rule:
`todo.md:1166` and `proposals/plan/03-plan-product-decisions.md:500`. The
companion proposal also cites "DSP-04, DSP-05" as a source of Manual
Execute (`first-execution-slice-scope.md:115`), and that citation was
written against the deferred rule. The feature Rule "Operator runs a Task at
once with Manual Execute" carries `# scope: DSP-05` (`gigacron.feature:581`),
so a reader cannot tell which rule it covers. `spec-lint` does not catch a
duplicate scope ID, so the gate passes.

**Fix:** Give the Manual Execute rule a new, unused ID in the Dispatch
section, for example `DSP-06`. Change `# scope:` on the feature Rule at
`gigacron.feature:581` and every new reference to it. Leave `DSP-05` on the
intervention rule, where the existing references expect it.
