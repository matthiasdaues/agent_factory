# The decided code for a draft with a stale first day and another error reaches only the state machine

**What is wrong:** The stakeholder decided open point 1: publication answers
`RUNS_FROM_NOT_IN_FUTURE` only when a stale `runs_from` is the draft's only
failure, and `TASK_DRAFT_INVALID` with all field errors otherwise. Only the
Task Draft state machine (state-machines.md:92-122) carries this rule. Four
other places do not:

- The DEF-12 Rule has no Scenario for a draft that fails `runs_from` and
  another field, so no acceptance test covers the decision.
- validation-rules.md:44 answers every stale first day with
  `RUNS_FROM_NOT_IN_FUTURE`, without the condition "only failure".
- The QA strategy keeps the boundary case "Code for a draft that fails
  `runs_from` and another field" as `blocked` on open point 1, with no test ID
  (gigacron-qa-strategy.md:349).
- `TASK_DRAFT_INVALID` has no row in any code table of
  interface-contracts.md, so its HTTP status is not defined. The decision now
  depends on this code.

**Fix:** Add a Scenario to DEF-12: a draft with a stale `runs_from` and no
dispatch target is refused with `TASK_DRAFT_INVALID`, and the body carries
both field errors. Add the condition to the row "First day still in the
future" in validation-rules.md and a row for `TASK_DRAFT_INVALID`. Add
`TASK_DRAFT_INVALID` (`422`, field errors in the body) to the code table of
"Task Draft and Task API" in interface-contracts.md. Set the QA boundary row
to `planned` with a test ID and point it at the new Scenario.
