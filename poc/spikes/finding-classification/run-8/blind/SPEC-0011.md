# A state change on the root Folder can answer RIGHT_MISSING, but FLD-02 expects FOLDER_INVALID_TRANSITION

**What is wrong:** The Scenario Outline "The root Folder has no lifecycle"
(gigacron.feature:1167-1175) expects "the administrator" who deactivates or
retires the root Folder to get `FOLDER_INVALID_TRANSITION`. The proposal's
criterion says the same without condition (`folder.md:1155-1156`). The
Lifecycle requests table (validation-rules.md:153-155) has two rows that
both refuse this request:

- "Folder transition allowed": a regular Folder refuses every transition
  with `FOLDER_INVALID_TRANSITION`.
- "Right to change the state": the caller holds `ACTIVATE` on the Folder,
  "which an Administrator of its Area holds", else `RIGHT_MISSING`.

The root Folder belongs to no Area (`folder.md:158-159`). So no Area
Administrator holds `ACTIVATE` on it, and both rows fail for every such
user. The table states no order, unlike the Task transition checks
(state-machines.md:270-275), so the Scenario cannot be asserted. A Finance
Administrator who deactivates the root Folder may get `RIGHT_MISSING` or
`FOLDER_INVALID_TRANSITION`. The same question arises for an imported
regular Folder of the caller's own Area, and for the retire route, where
`FOLDER_INVALID_TRANSITION` meets `RETIRE_DATE_INVALID` and `RIGHT_MISSING`.

**Fix:** Fix the order in the Lifecycle requests table and say that a
refusal carries the code of the first check that fails. The proposal
criterion decides the root case, so the kind check comes before the right
check: `FOLDER_NOT_FOUND` for a Folder the caller cannot read, then
`FOLDER_INVALID_TRANSITION` for a regular Folder, then `RIGHT_MISSING`, then
the transition check. State the same order for the retire route of a
regular Folder in validation-rules.md § Dated retirement, and in the
regular-Folder paragraph of state-machines.md § SMART Folder. In the FLD-02
Outline, name the caller, for example "an administrator of Finance". No
stakeholder decision is needed, because `folder.md:1155-1156` already fixes
the answer for the root Folder.
