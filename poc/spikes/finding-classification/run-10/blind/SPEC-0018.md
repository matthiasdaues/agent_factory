# Manual Execute creates a Task Instance in `RUN` without a Plan, but the state machine and the entity model have no such Instance

**What is wrong:** The global specification now states in two places that
Increment 01 creates a Task Instance that the global model does not allow.

- `interface-contracts.md:447` says that the new Task Instance "starts in
  `RUN` without a `plan_id`" and that the Server "copies its `execution`
  section onto the Task Instance".
- `gigacron.feature:583` asserts `201` with `state RUN`.

The rest of the global specification does not allow that Instance:

- The Task Instance state machine starts only in `WAITING`
  (`state-machines.md:574`: `[*] --> WAITING`). No transition creates an
  Instance in `RUN`, and `run_at` is defined as the time of
  `QUEUED → RUN`.
- `TASK_INSTANCE.plan_id` is a foreign key without a `NULL ALLOWED` entry
  (`entity-model.md:245`, `:707`). Only `folder_version_id` may be null.
- `TASK_INSTANCE` has no column for a copy of `execution`. It has
  `filled_values`, which holds the dispatch target and all six sections.

The companion proposal says the slice Instance differs and that "the global
specification keeps its model" (rule 3, DEC-04). The spec followed that for
the state machine and the entity model, but stated the slice Instance as an
Increment 01 contract in the interface contracts and the feature file. A
developer who writes the Alembic migration from the entity model gets a
`NOT NULL` `plan_id`, and the Manual Execute route then cannot insert its
Instance.

**Fix:** Pick one of two ways and apply it in all four documents.

1. Make the Manual Execute Instance part of the global model: add an entry
   transition `[*] --> RUN : ManualExecuteCommitted` to the Task Instance
   state machine, mark `plan_id` as `NULL ALLOWED` with the reason, and say
   where the `execution` copy lives (a column, or the `execution` key inside
   `filled_values`).
2. Keep the global model unchanged, and mark the `plan_id`-less `RUN` start
   in `interface-contracts.md` and the feature Scenario as a deviation of the
   first execution slice, with a link to the companion's "What we left out"
   table.
