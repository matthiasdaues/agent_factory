# The Task Draft state machine lets a draft without a name publish

**What is wrong:** DEC-46 makes a missing name a draft failure that answers
`TASK_DRAFT_INVALID`, and every needed value a fill gap that answers
`TASK_VALUE_UNRESOLVED`. Commit `6a6f618` carries this into
validation-rules.md, interface-contracts.md and FLD-08, but not into the Task
Draft state machine. The state machine still says two things that contradict
it:

- The pseudocode, in both states (`state-machines.md:96` and `:138`), refuses
  with `TASK_DRAFT_INVALID` only when "stored content breaks a format rule on
  a field other than runs_from". A missing name breaks no format rule. The
  name is no needed value either, so the fill check further down does not
  catch it. A draft without a name passes every branch and publishes.
- The prose (`state-machines.md:200-203`) says "A value that is only missing
  is a gap when the SMART Folder does not give it either", and that
  publication then answers `TASK_VALUE_UNRESOLVED`. A SMART Folder never
  gives a name, so this sentence sends a missing name to
  `TASK_VALUE_UNRESOLVED`.

Take the new FLD-08 Scenario "A missing name fails the draft content before
the fill": a draft in the root Folder sets no name and no command. The
Scenario expects `TASK_DRAFT_INVALID`. An implementation that follows the
pseudocode answers `TASK_VALUE_UNRESOLVED` for the command. An implementation
that follows the prose also answers `TASK_VALUE_UNRESOLVED`, naming the name.
Both fail the Scenario, and the developer agent reads the pseudocode as the
contract for the order.

Two records in gigacron-gaps.md use the same wording without the exception:
§ Configuring Future Behaviour, open point 1 (`gigacron-gaps.md:121-122`),
and § Folders, reading 01 (`gigacron-gaps.md:263-266`). Reading 10 states
the rule correctly, so the records are not wrong, but they read as the
general rule.

**Fix:** In the Task Draft pseudocode, in both states, change the
`TASK_DRAFT_INVALID` branch to "stored content breaks a rule on a field
other than runs_from: a missing name or a value in the wrong format". In the
prose, write "A [needed value](validation-rules.md#needed-values) that is
only missing is a gap …", and add one sentence that a missing name fails the
draft content and answers `TASK_DRAFT_INVALID`, whose body carries no
`REQUIRED` error on a needed value. In the two gaps records, write "a needed
value" for "a value". No stakeholder decision is needed, because DEC-46
decides the answer.
