# Folder Scenarios publish with a first day that the Folder draft cannot hold

**What is wrong:** Two Scenarios publish a SMART Folder with a chosen
`runs_from`: "Folder rename frees the old Folder name" (gigacron.feature:653)
and "Name of an emptied regular Folder is free from its end"
(gigacron.feature:868). `FOLDER_DRAFT` has no `runs_from` column
(entity-model.md:76-87 and :989-1008), and no rule says how a Folder draft
gets its first day. So neither Scenario can be built from the spec. Open point
5 in the gaps report hands the field to the Folder run.

The proposal already settles that the Folder draft carries the field. Folder
versions follow the same rules as Task versions
(`configuring-future-behaviour.md:482`, Scope :749-751). A first day is always
later than today's Odate (Core Principles :102-103). Two completion criteria
publish a Folder with a chosen first day (:1005-1007 and :1077-1080). Only the
draft field, with its validation, is missing.

**Fix:** Add `runs_from` to `FOLDER_DRAFT` in the ERD, the constraint table
(the validation row of `TASK_DRAFT`), and the column comments, with the rules
of DEF-12: optional, later than today's Odate of the Domain, `INVALID` with
`RUNS_FROM_NOT_IN_FUTURE` on save and on a stale read, the next Odate at
publication when empty. Add the Folder draft to the Draft table of
validation-rules.md, and close open point 5 with the citations above. The
Folder run then adds the field to the `folder-drafts` routes. If the
stakeholder wants the Folder run to own the field, list the two Scenarios as
depending on that run in the gaps report instead.
