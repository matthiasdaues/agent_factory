# `DISPATCH_TARGET_UNKNOWN` has two meanings in one file

**What is wrong:** The error code `DISPATCH_TARGET_UNKNOWN` has two
definitions in `interface-contracts.md`:

- `:476` (Manual Execute API): "The Task's `dispatch_target` names no
  Agent." The check reads the Agent table.
- `:545` (codes of open proposals): "The draft names a dispatch target that
  is not in its Domain's catalogue." The check reads the dispatch target
  catalogue. The row adds that Manual Execute "already answers the code".

A client that handles the code cannot tell which check failed. When the
catalogue arrives, a dispatch target can be in the catalogue and still name
no Agent row, and both cases then answer with the same code.

**Fix:** State one meaning for the code. Either give Manual Execute its own
code, such as `DISPATCH_TARGET_NO_AGENT`, or define `DISPATCH_TARGET_UNKNOWN`
once as "the dispatch target resolves to no Agent" and let both checks use
that meaning.
