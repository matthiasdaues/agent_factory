# The DSL leaves out two writes that rebuild the next Plan

**What is wrong:** PLN-02 names six writes after which the HorizonResolver
rebuilds the next Odate's `PENDING` Plan: a Task version publication, a Task
lifecycle change, a dated retirement, its withdrawal, a SMART Folder
publication, and a SMART Folder state change. The spec carries the Task
cases as Scenarios (`gigacron.feature:345-348` and `:1187-1196`). The
HorizonResolver description (`architecture.dsl:65`) and the edge
`apiLayer -> horizonResolver` (`:137`) list only four: "a Task or Folder
publication, a Folder state change, or a dated retirement". The Task
deactivation and activation and the withdrawal of a dated retirement are
missing.

Under choice 2, a route calls the rebuild only when the DSL tells it to. So
the developer agent wires no rebuild into these two routes. Take Task `load`
on Odate 10-11:

- An administrator deactivates `load`. The Instance of `load` stays in the
  Plan of 10-12. When 10-12 opens, the gate "Task state ACTIVE" holds it back,
  and it ends without a run. If `load` is a member of SMART Folder
  `billing`, the Instance ends `MISSED` and holds the Folder Run of `billing`
  open until an Operator ends it. FLD-03 expects the Instance to be gone.
- An administrator withdraws the retirement of `load` from 10-12. The
  retirement had removed the Instance from the Plan of 10-12, and nothing
  puts it back. `load` does not run on 10-12, although its last version now
  runs on that day.

**Fix:** Add "a Task state change" and "the withdrawal of a dated retirement"
to the description of the HorizonResolver and of the edge
`apiLayer -> horizonResolver`. Use the PLN-02 wording, so the list has one
source. A Folder retirement and its withdrawal belong to the same list
(DEF-19). Check that the spec names them in PLN-02 too, and add them if not.
