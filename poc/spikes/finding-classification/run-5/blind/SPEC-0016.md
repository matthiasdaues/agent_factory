# The wait rule and the contract table block the exits from `UNKNOWN` that the state machine allows

**What is wrong:** The Attempt state machine and the Server's message rules
disagree on how an Attempt leaves `UNKNOWN`.

The state machine lets three events end `UNKNOWN`
(`state-machines.md:756`, `:783`): `SuccessEvidenceAccepted` and
`FailureEvidenceAccepted`, which are a final `RETURN` with a PID, and
`StartFailureAccepted`, which is a `RETURN` without a PID.

Two rules in the same specification stop these exits:

- The contract table in `interface-contracts.md:231` applies a `RETURN` with
  a `process_identity` only while `attempt_state` is `RUNNING`. It has no row
  for `UNKNOWN`. Row `:232` does list `UNKNOWN` for a `RETURN` without a
  `process_identity`, so the two `RETURN` kinds are treated differently
  without a reason.
- The wait rule (`interface-contracts.md:193`, `state-machines.md:795`) makes
  a `RETURN` with a PID wait until `PROCESS_STARTED` is applied, and a
  `RETURN` without a PID wait until `COMMAND_ACK` is applied. An Attempt that
  entered `UNKNOWN` from `DISPATCHING` or `DISPATCHED` has no such applied
  step, and the state machine has no `UNKNOWN → RUNNING` transition that
  could apply it later. So the `RETURN` waits until `max_age` deletes it.

An example: Agent `5001` goes `UNREACHABLE` while Attempt 1 of Task Instance
`2001` is `DISPATCHED`. The Attempt becomes `UNKNOWN`. The Agent comes back
and sends `PROCESS_STARTED` and then `RETURN` with exit code `0`.
`PROCESS_STARTED` matches no transition. The `RETURN` waits for an applied
`PROCESS_STARTED` that never comes. The Attempt stays `UNKNOWN`, and its slot
stays held, although the state machine says the `RETURN` ends it as
`SUCCEEDED`.

The slice leaves out `UNKNOWN`, so this does not block the slice. It blocks
the reconciliation work that builds on the global rules.

**Fix:** Decide how an Attempt in `UNKNOWN` accepts its final message, and
state the decision in all three places. One way: the wait rule names
`UNKNOWN` as a state in which a final `RETURN` waits for nothing, and the
contract table lists `UNKNOWN` for both `RETURN` rows. The other way: drop
the three exits from `UNKNOWN` in the state machine and let reconciliation
settle the Attempt. Then add a Scenario under RES-01 that asserts the chosen
behaviour.
