# Several summaries leave out `COMMAND_REJECTED` or the Attempt lock

**What is wrong:** DEC-33 adds `COMMAND_REJECTED` as a fourth transition
point message that ends the Attempt and releases the slot. DEC-15 fixes the
lock order as Task Instance, then Attempt, then `OUTBOX` row. The main rules
state both correctly. Five summaries do not:

- `entity-model.md:1437`: "The slot is released in the transaction that
  accepts the final `RETURN`". `COMMAND_REJECTED` releases it too.
- `entity-model.md:1313`: the `INBOX` table comment lists `COMMAND_ACK`,
  `PROCESS_STARTED`, and `RETURN`, but not `COMMAND_REJECTED`. The
  `message_type` column of the same table lists all four.
- `runtime-views.md:42`: the Result Calculator releases the slot "in the
  transaction of the final `RETURN`".
- `architecture.dsl:236`: `inboxReceiver -> resultCalculator` hands over only
  "a final RETURN". The Result Calculator's own description includes
  `COMMAND_REJECTED`.
- `architecture.dsl:73`: the Inbox Receiver "locks the Task Instance row
  before the OUTBOX row". The Attempt row is missing from the lock order.

**Fix:** Add `COMMAND_REJECTED` to each of the first four places, for
example "in the transaction that accepts the final `RETURN` or
`COMMAND_REJECTED`". Change the DSL description at `architecture.dsl:73` to
"locks the Task Instance row, then the Attempt row, then the OUTBOX row".
