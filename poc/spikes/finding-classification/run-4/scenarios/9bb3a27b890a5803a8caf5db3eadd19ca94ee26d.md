4. Reliability: an Operator submits End Folder Run twice. The `operator_intent` applies once, and one audit event is written (`EndFolderRun`).
5. Performance: at the estate size of 2 Domains with 200,000 Tasks each, a publication of a SMART Folder with many members rebuilds the next `PENDING` Plan inside the publication transaction. The review judges how long that transaction holds the exclusive `FOLDER` row lock (`FolderPublicationReprojection`).
6. Responsiveness: member `load` has reached its release time when its Folder Run becomes `ACTIVE`. It moves to `QUEUED` in the check that follows the activation, without waiting for a polling interval (`FolderRunActivation`).

8. Modifiability: no capability cycle exists among the TaskRegistry, the DomainRegistry and the Planning Engine, and the ownership of `FOLDER` rows is clear (open item a).
9. Data integrity: a dated retirement from the next Odate ends every claim at F in its own transaction. When F opens, the HorizonResolver sets the Task `RETIRED` and releases no claim (`DatedRetirement`).
