# The Manual Execute rule lacks Scenarios for most of its contract and has no QA or backlog trace

**What is wrong:** The Manual Execute rule is `specified` in the scope map,
but the feature file, the QA strategy, the backlog, and the runtime view do
not cover it.

The feature Rule "Operator runs a Task at once with Manual Execute"
(`gigacron.feature:579`) has four Scenarios: success, `404 TASK_NOT_FOUND`,
`409 TASK_NOT_ACTIVE`, and one combined `422`. It has no Scenario for:

- `409 NO_AGENT_SLOT`, which is half of the slice's done criterion (a second
  Manual Execute answers `201` only after the slot is free), and the race of
  two requests for the last slot;
- the conversion codes `INVALID_COMMAND_SYNTAX`, `EMPTY_COMMAND`,
  `EXECUTABLE_NOT_ABSOLUTE`, and `UNSUPPORTED_TASK_FIELD`
  (`interface-contracts.md:476` to `:480`);
- `GET /task-instances/{task_instance_id}`, its `404 TASK_INSTANCE_NOT_FOUND`,
  and its `422 REQUEST_INVALID`;
- the newest published version whose `runs_from` lies in the future;
- the Command built from the Instance's copy of `execution`, not from the
  Task Version.

The trace is also missing outside the feature file:

- `gigacron-qa-strategy.md` has no row for the Manual Execute rule.
- `backlog/epics.md` names no EPIC or story for Manual Execute, although the
  companion lists `backlog/epics.md` among the documents to update.
- The runtime view "Manual Execute" lists `DSP-04` as an exercised rule
  (`runtime-views.md:260`). `DSP-04` is the deferred rule for reaching the
  open plan, not Manual Execute.

**Fix:** Add Scenarios for each missing case under the Manual Execute Rule,
using the companion's acceptance table as the source. Add QA strategy rows
that bind the Rule to an integration test layer. Add Manual Execute to an
EPIC in `backlog/epics.md`, with the scope ID chosen in SPEC-0017. Replace
`DSP-04` with that ID in `runtime-views.md:260`.
