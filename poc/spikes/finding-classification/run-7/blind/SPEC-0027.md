# The publication refusal answers a content failure with field codes, which the publication rules forbid

**What is wrong:** `interface-contracts.md:207-209` says that a draft whose
content fails "gets one problem for each field error, with the field error's
code: `REQUIRED`, `INVALID_FORMAT`, `INVALID_TYPE` or `INVALID_RANGE`". The
publication rules answer a content failure with one `TASK_DRAFT_INVALID`
whose body carries the field errors (`validation-rules.md:46`, the "Draft
content valid" row of § Publication at `validation-rules.md:98`, and the
`TASK_DRAFT_INVALID` row of the code table at `interface-contracts.md:148`).
Three artifacts state the per-draft form and only this paragraph states the
field-code form, so `interface-contracts.md:207-209` is the wrong side.

The code follows the wrong side.
`DefinitionStoreService._require_publishable_drafts`
(`task_registry/services/definition_store_service.py:310`) returns one
problem for each field error, and `test_publication_routes.py:316` asserts
`["REQUIRED", "REQUIRED"]` for a draft without a name and a command.

**Fix:** Rewrite `interface-contracts.md:207-209` so that a content failure
arrives as one problem per draft with the code `TASK_DRAFT_INVALID` and the
field errors in its body. Then change `_require_publishable_drafts` and the
assertion at `test_publication_routes.py:316` to match.
