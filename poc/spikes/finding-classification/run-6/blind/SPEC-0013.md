# Merged todo items tell a story to build a configuration check that the entity model replaced

**What is wrong:** The merge of `dev` in `4012a45` brought the todo items
T-0051 to T-0055 and one as-built note into the target-state spec. Three of
the items describe the entity model as dev knew it, not as this branch
defines it. A planning agent that cuts the Folder or claims stories reads
them as open work and builds the wrong schema.

- T-0052 (`todo.md:1263`) says that the entity model defines a generated
  `config_hash` column on `TASK_VERSION` with the partial unique index
  `uq_task_version_current_config`, "so no two current versions in a Domain
  share a configuration". It asks to add the column, the function and the
  index "when Folder work resumes". The entity model says the opposite:
  "`TASK_VERSION` stores no hash" (`entity-model.md:446`). The validator
  computes `config_hash` over the filled values, and the table
  `CONFIG_CLAIM` with the exclusion constraint `ex_config_claim_range`
  refuses an overlap per day (`entity-model.md:541-550`). A unique index on
  "current versions" would also refuse a prepared version that the claim
  model allows.
- T-0053 (`todo.md:1270`) says that the `TASK_VERSION` table of
  `entity-model.md` "does not yet list" `runs_from` and `runs_until`, and asks
  to add them. Both columns are there (`entity-model.md:73-74`), with the
  range model of DEF-08 to DEF-13.
- T-0054 (`todo.md:1277`) says that the entity model marks
  `TASK_VERSION.dispatch_target` as required. On this branch the column is
  null when the Task takes the dispatch target from its SMART Folder, and
  the fill check answers a missing one with `TASK_VALUE_UNRESOLVED`
  (`entity-model.md:1006`, FLD-08). The part of T-0054 that asks for a check
  against the AgentRegistry still holds.

The Task Draft pseudocode points at T-0052 from the target state. The
`TASK_CONFIG_CONFLICT` branch of state `VALID` carries the comment
`# deferred: not enforced in code yet, see T-0052`
(`state-machines.md:122`). The same branch in state `INVALID`
(`state-machines.md:166`) has no comment. Dev's original comment said "no
`config_hash` column yet", so the merge kept the pointer but not its
premise.

**Fix:** Rewrite T-0052 against the claim model: the code lacks
`CONFIG_CLAIM`, `task_config_hash` and the check `TASK_CONFIG_CONFLICT`, and
the story that builds DEF-15 adds them; `TASK_VERSION` gets no hash column.
Rewrite T-0053 as code drift only: the code stores `runs_from`, leaves
`runs_until` empty and has no cut-back, while the entity model already
carries the range model. In T-0054, drop the claim that the column is
required and keep the AgentRegistry check. Then either put the as-built
comment on both `TASK_CONFIG_CONFLICT` branches or move it out of the
pseudocode into the prose below it, as the other as-built notes are. No
stakeholder decision is needed, because the entity model decides the
target.
