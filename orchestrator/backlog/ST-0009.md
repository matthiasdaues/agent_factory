# Implement FilesystemFindingsStore

File-per-finding JSON store under `findings/`. Monotonic ID allocator (`FND-NNNN`). Schema-validates every write (VR-006). IDs assigned by the orchestrator, never by sources (VR-007).

## Acceptance Criteria

- `ingest(raw_findings, phase, iteration)` writes one JSON file per finding, stamps `id`/`phase`/`iteration`.
- IDs are monotonically increasing, unique across the store.
- Each file validates against the Finding schema on write.
- `supersede_prior(phase, iteration)` marks prior iteration's open findings as `superseded`.
- `open_count(phase, iteration)` returns the count of open findings for the given iteration.
- `list_open(phase, iteration)` returns the open findings.
- Finding files are valid JSON, readable, and round-trip through load/save.
- Unit tests with a temp directory covering ingest, supersede, open_count, schema validation rejection.
