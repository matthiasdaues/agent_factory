# Implement TomlAdapterRegistry over config.toml

Implement `AdapterRegistry` persisted in `.orchestrator/config.toml` alongside the operator defaults: register and unregister adapters, enforce name uniqueness and path validity, and cascade the model dictionary on removal — all as atomic, all-or-nothing writes.

**Priority:** must-have

## Acceptance Criteria

- `register()` accepts an adapter only when its binary path resolves to an executable file and the logical name is unique (BR-042, BR-043).
- `unregister()` removes the adapter and its dictionary entries in one atomic change (BR-044, VR-036).
- Model-dictionary CRUD (`set_model`/`remove_model`) persists atomically; a tier accepts at most one model (BR-045).
- Any failed validation or write leaves the last committed registry state intact (BR-048).
- Tests cover register, duplicate-name rejection, invalid-path rejection, dictionary CRUD, cascade delete, and failed-write rollback.

## Analysis

**Dependency check.** Before implementing, I verified the worktree against master rather than trusting the frontmatter. `git log --oneline -8 -- src/orchestrator/entities.py src/orchestrator/ports.py src/orchestrator/adapters/config_store.py` showed all three dependencies already merged: `AdapterEntry`, `ModelDictionary`, and `Tier` (ST-0045, commit d378d1f) in `entities.py`; the `AdapterRegistry` protocol (ST-0045, same commit) in `ports.py`; and `TomlConfigStore` (ST-0042, commit 29b940a) in `adapters/config_store.py`. No stale-base gap: nothing needed stubbing, and there is no separate scaffolding commit to cherry-pick away.

**Test-filename deviation.** The frontmatter names `tests/test_adapter_registry.py` as an output, but that path already holds ST-0045's suite for the abstract port contract (a `FakeAdapterRegistry` exercising `AdapterEntry`, `ModelDictionary`, and the `AdapterRegistry` protocol itself). Overwriting it would destroy ST-0045's coverage. This story's tests exercise the concrete TOML-backed adapter instead, so they live in the new file `tests/test_toml_adapter_registry.py`, matching the naming convention already used for `TomlConfigStore`'s own suite (`tests/test_toml_config_store.py` alongside the abstract `tests/test_config_store.py`).

**Coordinating table names with `TomlConfigStore`.** Both stores persist into `.orchestrator/config.toml`, so their table names must not collide, and each must treat the other's tables as opaque, byte-for-byte-preserved text. `TomlConfigStore` owns exactly one table, `[defaults]`. `TomlAdapterRegistry` owns two kinds of table:

- `[adapters]` — one flat table; each key is a registered adapter's logical name, each value its quoted binary path. This shape was not invented for this story — `tests/test_toml_config_store.py::test_save_preserves_unrelated_toml_sections` (landed with ST-0042) already fixtures a `[adapters]` table with exactly this shape as the "foreign" table `TomlConfigStore.save()` must leave untouched. `TomlAdapterRegistry` renders that same shape, so the two adapters' notions of "the adapter table" agree.
- `[models.<name>]` — one table per adapter that has at least one tier mapping, keyed by tier (`economy`/`standard`/`strong`) with a quoted model_id. An adapter with an empty dictionary has no `[models.*]` table at all.

Each store's writer identifies its own tables purely by header name (`[defaults]` for `TomlConfigStore`; `[adapters]` and `[models.*]` for `TomlAdapterRegistry`) and reproduces every other table verbatim, in its original position, exactly like `TomlConfigStore._replace_defaults_table` already does. `TomlAdapterRegistry._splice` generalizes that same splice to a *set* of owned table names (since the registry, unlike the single-table `ConfigStore`, may own zero, one, or many `[models.*]` tables depending on how many adapters carry tier mappings).

**Seam.** The public boundary is the `AdapterRegistry` port (`ports.py`); `TomlAdapterRegistry` is the concrete adapter implementing it, mirroring `TomlConfigStore`'s relationship to `ConfigStore`. No new port was needed.

**Extra validation beyond the acceptance criteria.** BR-043 requires rejecting both a duplicate logical name and the same binary path re-registered under a different name; `register()` checks both. I also constrain adapter names to `[A-Za-z0-9_-]+` so every registered name round-trips safely as a bare TOML key in the flat `[adapters]` table — undocumented in the AC list but necessary for the chosen `[adapters]` table shape to stay legible and parseable.

**Atomicity.** Every mutating method (`register`, `unregister`, `set_model`, `remove_model`) re-reads the file, validates the requested change against that freshly loaded state, and only mutates in memory and writes if validation passes. The write itself reuses the same write-to-temp-then-`os.replace` pattern as `TomlConfigStore` (VR-032). A failed validation never reaches the write path; a failed write (verified in tests by revoking directory write permission) never reaches `os.replace`, so the last committed file is untouched either way (BR-048).

**Spec drift.** None found. UC-10, ADR-0017, and the `AdapterRegistry` port docstring already described this adapter's responsibilities accurately; no updates to `docs/spec/` or `docs/adr/` were needed.
