# Implement WorkingTreeGate adapter

Replace `PreCommitGateRunner` with `WorkingTreeGate`. The new gate does not stage, commit, or run pre-commit — agents commit their own work. The gate is a working-tree cleanliness check:

- `verify(cwd, exit_code) → GateResult`
- Uses `git status --porcelain` to check for uncommitted changes
- Maps the four-cell matrix (exit_code × tree_state) to `GateResult`:
  - exit 0 + clean → `passed=True`
  - exit 0 + dirty → `passed=False, errored=True, hook="confabulation"` (VR-025)
  - non-zero + dirty → `passed=False, errored=False` (clean tree first)
  - non-zero + clean → `passed=False, errored=False`

Preserve `artifacts_changed()` for the resume path (VR-012).

**Priority:** must-have

## Acceptance Criteria

- `WorkingTreeGate` implements the `GateRunner` protocol (or a new `WorkingTreeGate` protocol if the port changes)
- `verify()` returns the correct `GateResult` for all four exit_code × tree_state combinations
- Confabulation (exit 0 + dirty) produces `errored=True, hook="confabulation"`
- `artifacts_changed()` still works for resume scenarios
- `PreCommitGateRunner` is removed or renamed
- Unit tests cover all four quadrants
