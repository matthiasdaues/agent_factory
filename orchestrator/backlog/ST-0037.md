# Define the MenuRenderer port and its DTOs

Add the `MenuRenderer` port and the `MenuItem` / `KeyEvent` DTOs to the ports module, so the core can render menus and read keys without importing any terminal library (Dependency Inversion). This is the seam that keeps the concrete framework deferred (T-29).

**Priority:** must-have

## Acceptance Criteria

- `MenuRenderer` declares `render_menu(items, selected_index)`, `render_display(content)`, and `get_keypress() -> KeyEvent`.
- `MenuItem` carries `label`, optional `suffix` (e.g. a `[strong]` tier tag), and `is_default`.
- `KeyEvent` is a normalised enum: `UP`, `DOWN`, `ENTER`, `BACK`, `EXIT`.
- The port imports no terminal library; only the concrete adapter (ST-0038) may.
- The `Ports` component list in chapter 5 already names `MenuRenderer`; the code matches it.

## Analysis

**Seams**: The public boundary is the `MenuRenderer` port protocol in `src/orchestrator/ports.py`. The DTOs (`MenuItem`, `KeyEvent`) are defined as frozen dataclass and enum in the same module per the existing pattern (cf. `InvocationResult`). The port itself is a runtime-checkable Protocol, keeping the core free from terminal library dependencies.

**Design decisions**:

1. `MenuItem` is a frozen dataclass (immutable DTO) with fields: `label: str`, `suffix: str | None`, `is_default: bool`.
2. `KeyEvent` is a normalized enum (not a string) with exactly five events: `UP`, `DOWN`, `ENTER`, `BACK`, `EXIT`, matching UC-08 and interface-contracts.md.
3. `MenuRenderer` is a Protocol with three methods:
   - `render_menu(items: list[MenuItem], selected_index: int) -> None` — owner of cursor presentation (`->` marker) and layout.
   - `render_display(content: str) -> None` — read-only display (e.g., agent detail, backlog summary).
   - `get_keypress() -> KeyEvent` — normalized navigation events (no raw terminal bytes exposed to core).
4. No terminal library import in ports.py; the concrete adapter (ST-0038) owns the implementation.

**Test approach**: TDD red-green. First, write a test that checks the port shape and instantiates a stub `MenuRenderer`; then implement the port and DTOs to satisfy it. Tests live in `tests/test_ports.py`.
