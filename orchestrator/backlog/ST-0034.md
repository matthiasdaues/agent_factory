# Add done-requires-outputs rule to backlog-lint

Enhance `backlog-lint` with two new validation rules:

1. **Rule 1 (error, blocks commit — VR-027):** A story with `status: done` must have ≥1 file matching its `outputs` globs present on the branch (same or prior commit).
2. **Rule 2 (warning, does not block — VR-028):** Committed files match a story's outputs or commit message references `(ST-NNNN)` but the story's status ≠ `done`.

Association signals: both outputs-glob match AND conventional-commit reference `(ST-NNNN)`.

**Priority:** could-have

## Acceptance Criteria

- `backlog-lint` rejects `status: done` stories whose outputs don't exist (VR-027)
- `backlog-lint` warns on committed files matching undone story outputs (VR-028)
- New rules do not break existing backlog validation
- Tests cover both rules with positive and negative cases
