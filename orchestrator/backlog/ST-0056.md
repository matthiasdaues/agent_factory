# BacklogStore read API — story body, by-epic, and ready filter

Extend `MarkdownBacklogStore` with the read projections the backlog views need: expose each story's prose body through `get_story()` (today only frontmatter is public), group stories by epic, and compute the dependency-ready set — all in memory from one loaded snapshot, without mutating any file.

**Priority:** should-have

## Acceptance Criteria

- `get_story()` returns the full frontmatter and the prose body for detail views (FR-U5, BR-060).
- A by-epic grouping returns stories under their epic while retaining each story's status.
- A ready filter returns only stories whose status is `pending` and whose every dependency resolves, in the same snapshot, to a story with status `done` (FR-U4, BR-057, VR-040).
- All reads are observational; no method writes, reorders, or deletes backlog data.
- Unit tests cover body exposure, epic grouping, the ready filter (including an unmet dependency), and the empty backlog.

## Analysis

**What changes:**

- `Story` entity (`src/orchestrator/entities.py`) gains a `body: str = ""` field. Default keeps `list_stories()` and every existing call site (`_to_story`, `cli.py` classification lookup) unaffected — only `get_story()` populates it from the parsed prose.
- `MarkdownBacklogStore._to_story()` (`src/orchestrator/adapters/backlog_store.py`) takes an optional `body: str = ""` param and forwards it to `Story(...)`.
- `MarkdownBacklogStore.get_story()` passes the parsed prose body (already produced by the private `_parse_frontmatter()`, previously discarded) into `_to_story()`. `list_stories()` is unchanged — it does not need bodies, so it keeps discarding them and stays cheap.
- Two new read-only `MarkdownBacklogStore` methods, both built on top of `list_stories()` (single snapshot, no extra file reads, no mutation):
  - `stories_by_epic() -> Dict[str, List[Story]]` — groups the snapshot's stories under their `epic`, preserving each story's `status` (BR-059, FR-U3). Epics are ordered alphabetically for deterministic display; stories within an epic keep `list_stories()`'s id-sorted order.
  - `ready_stories() -> List[Story]` — returns stories with `status == StoryStatus.PENDING` where every `deps` entry resolves, within the same snapshot (a `dict` keyed by id built once from `list_stories()`), to a story with `status == StoryStatus.DONE`. An empty `deps` list passes trivially. A dep id absent from the snapshot excludes the story (BR-057, VR-040).
- `BacklogStore` Protocol (`src/orchestrator/ports.py`) gains `stories_by_epic()` and `ready_stories()` so the port stays the seam the future TUI depends on, not the concrete adapter. `get_story()`'s docstring is updated to note it returns the prose body too. No signature changes to existing methods — purely additive, so `MarkdownBacklogStore` (the only implementation) stays a structural match for the `Protocol` with no other adapter to update.

**Why no new port/adapter:** UC-12 designates `MarkdownBacklogStore.list_stories()` / `get_story()` as the sole read paths for backlog views (Postconditions, T&DV List). The by-epic and ready projections are pure in-memory derivations of `list_stories()`'s output, so they belong on the same store rather than a new service — consistent with FR-U3/FR-U4 describing them as computed "from the loaded backlog snapshot," not from a second read.

**Test scenarios (tests/test_backlog_store_views.py):**

1. `get_story()` returns the frontmatter fields *and* the prose body (FR-U5, BR-060).
2. `stories_by_epic()` groups stories from more than one epic under their epic headings, retaining each story's status (FR-U3, BR-059).
3. `stories_by_epic()` on an empty backlog returns an empty mapping (empty-backlog edge case, BR-058 analog for the store layer).
4. `ready_stories()` includes a pending story whose deps are all done, and excludes a pending story with an unmet (non-done) dependency, in the same snapshot (FR-U4, BR-057).
5. `ready_stories()` treats an empty `deps` list as trivially satisfied (VR-040).
6. `ready_stories()` excludes a story whose dep id does not resolve to any story in the snapshot (unmet/unresolvable dependency edge case).
7. `ready_stories()` on an empty backlog returns an empty list (empty-backlog edge case).
8. Read-only guarantee: `stories_by_epic()`/`ready_stories()` do not write to disk — asserted via unchanged file mtimes/content after the calls (BR-056).
