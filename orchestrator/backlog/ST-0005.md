# Implement PhaseRunner state machine

The heart of the system. Drives one phase through the `Authoring → Gating → Reviewing → (RetryOrHalt | AwaitingApproval)` state machine from state-machines.md.

One iteration:

1. **Authoring** — resolve author from AgentRegistry; compose prompt (PromptComposer) from agent definition + context + open findings; invoke via CLIAdapter.
2. **Gating** — stage declared outputs, commit on run branch via GateRunner; map result: pass → continue; findings → ingest + loop; empty commit → no-progress; gate error/timeout → halt.
3. **Reviewing** (if phase has reviewer) — invoke reviewer via CLIAdapter; ingest semantic findings.
4. **Decide** — LoopPolicy supersedes prior findings, evaluates exit: zero open → AwaitingApproval; else RetryOrHalt.

Halt edges bypass RetryOrHalt: adapter auth failure (BR-018), adapter config error (BR-020), gate error/timeout (BR-015/BR-020).

## Acceptance Criteria

- PhaseRunner drives a phase from Idle through to AwaitingApproval or Halted.
- Auth failure halts without counting an iteration.
- Config error halts without counting an iteration.
- Gate error halts without counting an iteration.
- Gate timeout halts without counting an iteration.
- Empty commit → RetryOrHalt.
- Gate findings → ingest + loop.
- Reviewer findings → loop if open > 0, AwaitingApproval if 0.
- Cap exhaustion → Halted.
- Gate-only phase (no reviewer) → AwaitingApproval on gate pass.
- Unit tests with stub ports covering every state transition and halt edge.
