# Define AdapterEntry, ModelDictionary, and the AdapterRegistry port

Add the `AdapterEntry` (`name`, `binary_path`) and `ModelDictionary` (tier → model_id) entities and the `AdapterRegistry` port (`list_adapters`, `get_adapter`, `register`, `unregister`, plus dictionary access). Each registered adapter owns exactly one dictionary keyed by the fixed tier vocabulary.

**Priority:** must-have

## Analysis

Following Clean Architecture and Dependency Inversion (ADR-0001), the implementation separates concerns:

1. **Tier vocabulary** — Immutable enum {economy, standard, strong} (BR-045, UC-10 TDVL).
2. **AdapterEntry entity** — Immutable DTO carrying `name` (primary key, logical adapter identifier) and `binary_path` (filesystem path to executable). Mirrors interface-contracts.md schema.
3. **ModelDictionary entity** — Manages tier→model_id mappings. Exposes four dict-like methods: get_model(tier), set_model(tier, model_id), remove_model(tier), list_models(). Validates tier membership against the fixed vocabulary at write time. Internally keyed by tier string.
4. **AdapterRegistry port** — Abstract seam (Protocol) the core depends on, never a concrete file store. Methods: list_adapters(), get_adapter(name), register(name, binary_path), unregister(name). The last method documents its all-or-nothing semantics: removes the adapter record AND its model dictionary in one atomic operation (BR-044).

**Seams**: The public boundary is the `AdapterRegistry` protocol and the two entities. The concrete adapter (ST-0046) implements AdapterRegistry backed by a persistence layer (TOML + JSON). This story defines only the protocols and entities; no I/O.

**TDD plan**: Write a failing test first: a FakeAdapterRegistry satisfying the protocol, with a tier outside {economy, standard, strong} rejected on set_model(). Then implement minimal code to pass.

## Acceptance Criteria

- `AdapterEntry` carries a logical name (primary key) and a binary path.
- `ModelDictionary` exposes `get_model(tier)`, `set_model(tier, model_id)`, `remove_model(tier)`, and `list_models()`; tier ∈ {economy, standard, strong}.
- `AdapterRegistry.unregister()` is documented to remove the adapter and its dictionary as one logical operation (BR-044).
- The port imports no TOML library; the concrete adapter (ST-0046) does.
- Entities and port appear in the lists chapter 5 names.
