# Implement ModelResolver

Resolves the model for an invocation following the precedence chain: explicit `--model` flag → matrix lookup → adapter default.

For a task-phase invocation the matrix key is the story's classification; for a non-task phase it is the phase name. The matrix maps to a tier, and the tier plus the active CLI resolves to a concrete model.

When the matrix has no model for the active CLI and a required tier, behaviour depends on `on_missing`: `halt` raises a config error (BR-020); `auto` falls back to the adapter default (None → adapter decides).

## Acceptance Criteria

- `resolve(cli, phase, classification, explicit_model)` returns a model string or `None`.
- Explicit `--model` always wins, matrix is not consulted.
- Matrix lookup follows class → tier → CLI model path.
- Phase-level tier lookup works for non-task phases (e.g. `planning → strong`).
- `on_missing = halt` raises `ConfigError` when a tier is unresolvable.
- `on_missing = auto` returns `None` (adapter default).
- Unit tests with a stub ModelMatrix covering all precedence cases and both `on_missing` modes.
