# Move top-level docs/ back into orchestrator/docs/

A prior pass copied `orchestrator/docs/*` up to a top-level `docs/` in the
repo. That content — arc42 chapters 01-12, `architecture.dsl`, `adr/`,
`findings/`, `reviews/`, `spec/`, `assets/`, `README.md` — is 100% specific
to the orchestrator Python CLI ("Agent Session Orchestrator"), not to the
repo as a whole. `orchestrator/.pre-commit-config.yaml` already hardcodes
`--docs-dir orchestrator/docs` / `--spec-dir orchestrator/docs/spec`, i.e.
it assumes the docs stay nested beside the code they describe. Move the
content back and remove the stale top-level copy.

**Priority:** must-have

## Acceptance Criteria

- Every file that currently sits under top-level `docs/` and originated
  from `orchestrator/docs/` (arc42 chapters 01-12, `architecture.dsl`,
  `adr/`, `findings/`, `reviews/`, `spec/`, `assets/`, `README.md`) is
  tracked under `orchestrator/docs/` with the same relative structure.
- The top-level `docs/` directory no longer exists (or contains nothing
  that originated from the orchestrator docs copy); the removal is staged
  in git, not left as an untracked deletion.
- `orchestrator/CONTEXT.md` — already correctly placed — still sits beside
  the restored `orchestrator/docs/`, unmoved.
- No other file in the repo (root `README.md`, `factory/config/*`) is left
  pointing at the removed top-level `docs/` path for orchestrator-specific
  content.
- `orchestrator/.pre-commit-config.yaml`'s `--docs-dir orchestrator/docs` /
  `--spec-dir orchestrator/docs/spec` hooks resolve against the restored
  directory without modification.
