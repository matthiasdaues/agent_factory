# Decide and clean up orchestrator/USAGE.md

`orchestrator/USAGE.md` is stale: it describes the old `agent_hq/`
top-level layout (`agents/`, `skills/`, `scripts/` at repo root), which
matches neither the old ADR-0010 distribution model nor the current
`factory/`-copied-wholesale model. Rather than silently deleting it,
review its content and decide: rewrite it to reflect current reality, or
fold its still-useful content into the root `README.md` and delete it.

**Priority:** could-have

## Acceptance Criteria

- `orchestrator/USAGE.md` is reviewed section by section against the
  current `factory/` + `orchestrator/` layout, and a decision is recorded
  (in the file itself, in the PR/commit description, or in
  `orchestrator/docs/spec/todos.md`) between "rewrite in place" and
  "fold into root README.md and delete."
- If rewritten: every path and directory-tree example in
  `orchestrator/USAGE.md` matches the current layout (`factory/agents/`,
  `factory/skills/`, `orchestrator/src/`, `orchestrator/docs/`, etc.), not
  the old top-level `agents/`/`skills/`/`scripts/`/`prompts/` layout.
- If folded and deleted: every piece of `USAGE.md` content still relevant
  today (activation steps, prerequisites, directory layout) is represented
  in root `README.md` before `orchestrator/USAGE.md` is removed, and
  `orchestrator/USAGE.md` no longer exists afterward.
- No other file in the repo is left linking to a deleted
  `orchestrator/USAGE.md`.
