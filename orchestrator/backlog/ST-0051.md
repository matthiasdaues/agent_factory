# Parse agent skills and interactive policy; resolve interactivity

Extend `AgentRegistry` to parse the agent's declared `skills` and optional `interactive: true|false` frontmatter into `AgentInfo`, and resolve the effective interactivity. Interactive is the default when a TTY is attached; a non-TTY degrades to headless. For phases the agent's declared `interactive` policy applies; for a direct `run-step`, `--no-interactive` forces headless for that one invocation only.

**Priority:** must-have

## Acceptance Criteria

- `AgentInfo` gains `skills: list[str]` and `interactive: bool` parsed from frontmatter (FR-S5).
- Interactive is the default with a TTY; a non-TTY degrades to headless. For phases the agent's declared `interactive` policy applies; a `--no-interactive` override applies to that invocation only and does not change the stored default (FR-S6, BR-054).
- An agent that declares no skills yields an empty list, and any `--skill` value is rejected downstream (ST-0052).
- Unit tests cover skills parsing, interactive default, and override precedence.

## Analysis

Implementing ST-0051 requires parsing and storing two agent frontmatter fields in AgentInfo:

1. **skills** — already implemented and working (tests green)
2. **interactive** — new boolean field, defaulting to true if absent from frontmatter
3. **tier** — new optional string field (economy/standard/strong), defaulting to None if absent

**Files to modify:**

- `orchestrator/src/orchestrator/ports.py` — add `interactive: bool` and `tier: str | None` to AgentInfo dataclass
- `orchestrator/src/orchestrator/adapters/agent_registry.py` — add parsing for `interactive` and `tier` frontmatter keys
- `orchestrator/tests/test_agent_registry.py` — add tests for interactive parsing, tier parsing, and defaults

**Key behavior:**

- Parse optional `interactive: true|false` from frontmatter (scalar boolean value)
- Parse optional `tier: {economy|standard|strong}` from frontmatter (scalar value)
- Default `interactive` to `true` when key absent (interactive-by-default policy per CLI spec §6)
- Default `tier` to `None` when key absent (allows fallback to standard tier per SPEC-0006)
- TTY-aware resolution and `--no-interactive` override are orchestrated at invocation time, not in the registry

**Test coverage:**

1. Happy path: agent with all fields (skills, tier, interactive)
2. Interactive defaults to true when key absent
3. Interactive false explicitly declared
4. Tier parsing (economy/standard/strong)
5. Tier defaults to None when absent
6. Agent without skills returns empty list (existing test, verify still passes)
7. Interactive key with invalid format rejected gracefully

## Implementation

**Changes made:**

1. **ports.py** — Extended `AgentInfo` dataclass:

   - Added `tier: Optional[str] = None` field
   - Added `interactive: bool = True` field
   - Fields placed after `skills` to maintain backward compatibility with existing code that constructs AgentInfo positionally

2. **agent_registry.py** — Added parsing functions:

   - `_parse_tier(definition_path)` — parses optional `tier: {value}` line from frontmatter, returns None if absent
   - `_parse_interactive(definition_path)` — parses optional `interactive: true|false` line from frontmatter, returns True if absent
   - Updated `resolve()` method to populate tier and interactive fields in AgentInfo return value

3. **test_agent_registry.py** — Enhanced test helper and added test cases:

   - Extended `_write_agent()` helper to accept optional `tier` and `interactive` parameters
   - Added 6 new test cases covering all scenarios per acceptance criteria
   - Existing 8 tests continue to pass with default values

**Key design choices:**

- Scalar parsing (not list-style) for `tier` and `interactive` keys, matching the agent definition frontmatter format
- Interactive defaults to True (interactive-by-default policy)
- Tier defaults to None, allowing fallback to standard tier at invocation time
- No validation of tier values here (validation is orchestrator responsibility)
- Boolean parsing is case-insensitive (`"true"` or `"True"` both parse as true)

**Test results:** All 331 tests pass (14 agent registry tests + 317 existing tests)
