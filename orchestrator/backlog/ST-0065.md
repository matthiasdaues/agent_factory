# Fix stale factory/agents + factory/skills resolution in cli.py

`_tooling_root()` in `orchestrator/src/orchestrator/cli.py` hardcodes the
pre-pivot agent_hq layout: it resolves
`Path(__file__).resolve().parents[3]` and checks for bare `agents/` and
`skills/` directories at that root. Under the current agent_factory
layout, those directories live at `factory/agents/` and `factory/skills/`
instead, so `_tooling_root()` raises `RuntimeError` (or, worse, silently
resolves the wrong root if bare `agents`/`skills` happen to exist) under
every current checkout. `_resolve_agents_dir()` compounds the same
assumption via `_tooling_root() / "agents"` and its `repo_root / "agents"`
fallback.

**Priority:** must-have

## Acceptance Criteria

- `_tooling_root()` checks for `factory/agents` and `factory/skills` under
  the resolved root, not bare `agents`/`skills`.
- `_resolve_agents_dir()`'s package-relative branch resolves
  `_tooling_root() / "factory" / "agents"`; its cwd-fallback branch
  resolves `repo_root / "factory" / "agents"` instead of `repo_root / "agents"`.
- Any other function in `cli.py` sharing the same bare-`agents`/bare-`skills`
  assumption (checked, not just these two) is updated to the
  `factory/agents` / `factory/skills` convention.
- `tests/test_init.py`'s assertions on `_tooling_root()` are updated to
  assert against `factory/agents` / `factory/skills`, not bare
  `agents`/`skills`.
- `tests/test_integration_menu_mode.py`'s use of `_resolve_agents_dir` (it
  monkeypatches the function directly, so unaffected by the internal path
  change) still passes unchanged; any other test asserting the old bare
  paths is updated.
- The full orchestrator test suite passes after the change.

## Analysis

**Functions fixed.** Grepped `cli.py` for every `_tooling_root()` /
`_resolve_agents_dir()` call site and every bare `root / "agents"`,
`root / "skills"`, `root / "scripts"` construction anchored at
`_tooling_root()`. Four spots shared the stale bare-path assumption:

1. `_tooling_root()` — now checks `factory/agents` + `factory/skills`.
2. `_resolve_agents_dir()` — package-relative branch now
   `_tooling_root() / "factory" / "agents"`; cwd-fallback branch now
   `repo_root / "factory" / "agents"`.
3. `_run_menu_mode()`'s inline `except ValueError: agents_dir = ...`
   fallback (~line 2132) duplicates `_resolve_agents_dir`'s cwd-fallback
   logic inline (its own comment references `_resolve_agents_dir`
   directly) — updated the same way, to
   `repo_root / "factory" / "agents"`.
4. `_handle_init()`'s `_COPY_DIRS` loop (~line 2419) resolves
   `src = root / name` for `name in ["agents", "skills", "scripts"]`,
   where `root = _tooling_root()` — the same bare-root assumption applied
   to a third directory (`scripts`) that isn't named in this story's
   title but sits under the identical `factory/` prefix and is copied by
   the same loop. Left unfixed, `_tooling_root()` alone resolving
   correctly would make every `src.is_dir()` check silently `False`
   (`root/agents` doesn't exist, only `root/factory/agents` does) and the
   whole copy step would no-op — which is exactly the "worse, silently
   resolves wrong" failure mode this story's own problem statement warns
   about. Fixed to `src = root / "factory" / name`. The **destination**
   (`project_dir / name`, bare) is deliberately untouched — that's the
   scaffolded target project's own convention (`ADR-0010`, itself flagged
   stale/pending-supersession by ST-0064, but not superseding this
   target-side detail), tested unchanged by `TestInitCopiedDirs` et al.

**Judgment call — ADR-0010 vs. the literal acceptance criteria.**
ADR-0010 (`orchestrator/docs/adr/0010-...md`) documents the pre-pivot
symlink-based distribution model and states `_resolve_agents_dir`'s
cwd-fallback exists for a downstream *project's own* bare `agents/`
directory — which would argue for leaving the cwd-fallback bare. But
ST-0064 (pending) already flags ADR-0010 itself as describing "the old
agent_hq distribution model" that "does not match agent_factory's actual
model" and is due for supersession once real shipping/distribution is
designed — so it isn't authoritative here. The acceptance criteria above
are explicit and unambiguous that the cwd-fallback becomes
`repo_root / "factory" / "agents"` too, consistent with the current
"factory/ copied wholesale into a project" model (ST-0064's description
of `init-factory`). No existing test exercises this branch directly
(`test_integration_menu_mode.py` monkeypatches `_resolve_agents_dir`
itself), so implementing the literal criterion carries no regression
risk either way. Followed the literal criteria.
