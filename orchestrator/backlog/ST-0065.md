# Fix stale factory/agents + factory/skills resolution in cli.py

`_tooling_root()` in `orchestrator/src/orchestrator/cli.py` hardcodes the
pre-pivot agent_hq layout: it resolves
`Path(__file__).resolve().parents[3]` and checks for bare `agents/` and
`skills/` directories at that root. Under the current agent_factory
layout, those directories live at `factory/agents/` and `factory/skills/`
instead, so `_tooling_root()` raises `RuntimeError` (or, worse, silently
resolves the wrong root if bare `agents`/`skills` happen to exist) under
every current checkout. `_resolve_agents_dir()` compounds the same
assumption via `_tooling_root() / "agents"` and its `repo_root / "agents"`
fallback.

**Priority:** must-have

## Acceptance Criteria

- `_tooling_root()` checks for `factory/agents` and `factory/skills` under
  the resolved root, not bare `agents`/`skills`.
- `_resolve_agents_dir()`'s package-relative branch resolves
  `_tooling_root() / "factory" / "agents"`; its cwd-fallback branch
  resolves `repo_root / "factory" / "agents"` instead of `repo_root / "agents"`.
- Any other function in `cli.py` sharing the same bare-`agents`/bare-`skills`
  assumption (checked, not just these two) is updated to the
  `factory/agents` / `factory/skills` convention.
- `tests/test_init.py`'s assertions on `_tooling_root()` are updated to
  assert against `factory/agents` / `factory/skills`, not bare
  `agents`/`skills`.
- `tests/test_integration_menu_mode.py`'s use of `_resolve_agents_dir` (it
  monkeypatches the function directly, so unaffected by the internal path
  change) still passes unchanged; any other test asserting the old bare
  paths is updated.
- The full orchestrator test suite passes after the change.
