# MVP integration test — requirements phase end-to-end

The walking skeleton from the PRD: drive the requirements phase through the Copilot adapter, exercising the full loop — author → gate (spec-lint) → reviewer → findings → loop-back → clean → awaiting-approval.

Uses stub/mock adapters for the CLI (no real Copilot) but real filesystem stores (findings, run state) and real spec-lint as the gate hook, to validate the wiring end to end.

## Acceptance Criteria

- Test creates a temp project with a pre-commit config pointing at spec-lint.
- Stub CLIAdapter returns a spec with a known error on iteration 1, then a clean spec on iteration 2.
- FindingsStore receives findings from iteration 1, supersedes them on iteration 2.
- GateRunner runs spec-lint against the authored spec.
- PhaseRunner loops once, then reaches AwaitingApproval.
- RunState is persisted and loadable throughout.
- Log file has entries for both invocations.
- The test is self-contained (tmp_path) and does not require Copilot auth.
