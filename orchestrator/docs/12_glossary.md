# 12. Glossary

The domain vocabulary. The authoritative source is [`../CONTEXT.md`](../CONTEXT.md); this chapter reproduces it and adds the architecture-level terms introduced in this documentation. Keep both consistent.

> **Scope note (amended 2026-07-12, PhaseRunner collapse):** several entries below described the author→gate→review execution surface deleted from the orchestrator and moved to `factory/`. Each affected entry is marked inline. See the repo-root `docs/spec/prd.md` and `docs/adr/0002-factory-owns-flow-control-orchestrator-is-a-trigger.md`.

## Domain terms (from CONTEXT.md)

| Term                  | Definition                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Orchestrator**      | _(Amended)_ The Python CLI (`orchestrate`) that observes and manages run state for the Agent HQ agent chain: status, phase-gate approval, halted-run recovery, project init, and a TUI for backlog browsing and adapter/model configuration. It no longer drives the chain itself — that moved to `factory/`. Resolves agents, skills, and scripts from the package-relative path (ADR-0010). |
| **Phase**             | One unit of the chain, with an author agent and an optional reviewer agent. The four phases: requirements, architecture, planning (no reviewer), implementation.                                                                                                                                                                                                                              |
| **Author agent**      | The agent that produces a phase's artifacts (e.g. `requirements-agent`).                                                                                                                                                                                                                                                                                                                      |
| **Reviewer agent**    | The agent that independently reviews a phase's artifacts in a fresh session (e.g. `spec-review-agent`). A phase may have none.                                                                                                                                                                                                                                                                |
| **Session isolation** | _(Moved to factory.)_ Running each agent in a fresh CLI subprocess with no inherited context, so a reviewer never sees the author's reasoning. `factory/` invokes agents now; the orchestrator invokes none.                                                                                                                                                                                  |
| **CLI adapter**       | _(Moved to factory.)_ The abstraction that let the orchestrator drive any AI CLI (Copilot first; Claude, Gemini later) through one `invoke` contract. The `CLIAdapter` port and its `CopilotAdapter` implementation are deleted from the orchestrator.                                                                                                                                        |
| **Gate**              | The deterministic check between steps, run via `pre-commit` hooks on the phase's commit. Blocks only on error-severity findings.                                                                                                                                                                                                                                                              |
| **spec-lint**         | The deterministic spec linter used as the requirements phase's gate hook.                                                                                                                                                                                                                                                                                                                     |
| **Finding**           | A single reviewed defect, stored as one validated JSON file. Has a `source` (`spec-lint` or `semantic`), `severity`, `iteration`, and `status` (`open`, `superseded`, `resolved`).                                                                                                                                                                                                            |
| **Findings store**    | The local, file-per-finding directory that is the source of truth for loop state (external ticket tools deferred).                                                                                                                                                                                                                                                                            |
| **Iteration**         | One author→gate→review cycle within a phase.                                                                                                                                                                                                                                                                                                                                                  |
| **Loop-back**         | Re-running the author with the open findings; bounded by the cap (default 3), after which the run halts.                                                                                                                                                                                                                                                                                      |
| **Supersede**         | At the start of each iteration, the prior iteration's open findings are marked `superseded` so the loop can terminate.                                                                                                                                                                                                                                                                        |
| **Run**               | One execution of a phase or the chain, tracked in `.orchestrator/run.json`, isolated by a run lock on a dedicated run branch.                                                                                                                                                                                                                                                                 |
| **Awaiting-approval** | The persisted state a clean phase reaches; the orchestrator exits and the human runs `approve`/`reject`.                                                                                                                                                                                                                                                                                      |
| **Phase gate**        | The human sign-off point at a phase boundary; the judgment a linter cannot make.                                                                                                                                                                                                                                                                                                              |
| **Halt**              | A safe stop (cap exhausted, gate error, adapter-auth failure, adapter-config failure, rejection) that summons the human rather than proceeding.                                                                                                                                                                                                                                               |

## Architecture terms (introduced in this documentation)

| Term                                | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Port**                            | _(Amended)_ An abstract interface the core depends on (`GateRunner`, `FindingsStore`, `RunStateStore`, `RunLock`, `AgentRegistry`, `InvocationLogReader`, `BacklogStore`, `ModelMatrix`, `MenuRenderer`, `ConfigStore`, `AdapterRegistry`). The seam that keeps the core VCS-, terminal-, and filesystem-agnostic (Dependency Inversion). `CLIAdapter`, `FindingIngestor`, `PromptComposer`, and `Logger` were ports too, until they moved to `factory/` with the components that used them. |
| **Adapter**                         | _(Amended)_ A concrete implementation of a port (e.g. `WorkingTreeGate`, `FilesystemFindingsStore`, `TerminalMenuRenderer`, `TomlConfigStore`, `MarkdownAgentRegistry`). Wired to the core at the composition root. `CopilotAdapter` is deleted — it implemented the now-deleted `CLIAdapter` port.                                                                                                                                                                                          |
| **Composition root**                | The CLI entry point, where concrete adapters are constructed and injected into the core, and where the direct-mode dispatcher or the menu controller is chosen by argument vector and terminal. The only place that knows both a port and its concretion.                                                                                                                                                                                                                                    |
| **Core**                            | _(Amended)_ The CLI-agnostic domain + application logic: `StatusService`, `ApprovalService`, `MenuController`, `SettingsResolver`, and the domain entities. Depends only on ports. `PhaseRunner`, `LoopPolicy`, and `ModelResolver` were core components too, until they moved to `factory/`.                                                                                                                                                                                                |
| **Dual-mode entry**                 | The single process serves two interaction modes over one core: direct-mode subcommands and an interactive TUI menu. A function reaches the same service whichever mode invokes it (FR-V, ADR-0016).                                                                                                                                                                                                                                                                                          |
| **MenuController**                  | The core service that traverses the menu tree, holds navigation state, and dispatches each function leaf to its direct-mode-equivalent service.                                                                                                                                                                                                                                                                                                                                              |
| **MenuRenderer**                    | The port that abstracts the terminal: renders one menu/display node at a time, returns normalised `KeyEvent`s. Its concrete framework is deferred (T-29).                                                                                                                                                                                                                                                                                                                                    |
| **SettingsResolver**                | The core service applying the four-layer precedence `menu selection > CLI flag > config.toml > built-in default`.                                                                                                                                                                                                                                                                                                                                                                            |
| **Config store / adapter registry** | The `ConfigStore` and `AdapterRegistry` ports over `.orchestrator/config.toml`: persisted operator defaults, registered adapters, and per-adapter model dictionaries.                                                                                                                                                                                                                                                                                                                        |
| **Model dictionary**                | A registered adapter's map from tier (`economy`/`standard`/`strong`) to a concrete model id — a local cache for menu-mode display, populated from `model.conf` on a gap-fill basis, not read at resolution time (ADR-0021).                                                                                                                                                                                                                                                                  |
| **Tier**                            | _(Amended)_ The model-capability band (`economy`/`standard`/`strong`) declared in front-matter — an agent's own, or a story's own. The orchestrator still parses and displays it; resolving it to a concrete model by reading `model.conf` now happens in `factory/` (ADR-0020).                                                                                                                                                                                                             |
| **PhaseRunner**                     | _(Deleted; moved to factory.)_ Was the application service that drove one phase's state machine (Authoring → Gating → Reviewing → RetryOrHalt / AwaitingApproval). The state machine itself is unchanged — see [`spec/supplementary_specs/state-machines.md`](spec/supplementary_specs/state-machines.md) — but `factory/` drives it now.                                                                                                                                                    |
| **LoopPolicy**                      | _(Deleted; moved to factory.)_ Was the component that owned the cap, the supersede step, and the loop-exit predicate.                                                                                                                                                                                                                                                                                                                                                                        |
| **GateResult**                      | The structured outcome of a gate: `passed`, `errored` (infra failure, distinct from a findings failure), `hook`, `error_count`. Still real — `WorkingTreeGate` returns it, now called only from `ApprovalService`'s staleness re-gate.                                                                                                                                                                                                                                                       |
| **InvocationResult**                | _(Deleted; moved to factory.)_ Was the DTO the `CLIAdapter` port returned: `exit_code`, `stdout`, `stderr`, `timed_out`, `auth_error`, `config_error`.                                                                                                                                                                                                                                                                                                                                       |
| **Run branch**                      | _(Moved to factory.)_ The dedicated git branch a run commits to, created from a clean tree; never the operator's working branch, never force-pushed. The orchestrator's `RunStateStore` records the branch name but no longer creates or selects it.                                                                                                                                                                                                                                         |
| **Run lock**                        | The lockfile (`.orchestrator/run.lock`) enforcing the single-active-run invariant.                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Monotonic allocator**             | The orchestrator-owned counter that assigns each finding its unique `FND-NNNN` id on ingest; sources never mint ids.                                                                                                                                                                                                                                                                                                                                                                         |
