# Validation Rules — Agent Session Orchestrator

Cross-cutting rules not owned by a single use case. Each is numbered and cross-referenced to the use case(s) and business rule(s) it enforces. These are the natural home for property-based tests later.

> **Scope note (amended 2026-07-12, PhaseRunner collapse):** rules marked `_(Now factory's.)_` were enforced by `PhaseRunner` and its supporting components, all deleted from the orchestrator; the equivalent enforcement now happens in `factory/` (`factory/scripts/{phase,trigger,transition-lint}`, `factory/skills/run-step`). Unmarked rules remain enforced by the orchestrator today. See the repo-root `docs/spec/prd.md` and `docs/adr/0002-factory-owns-flow-control-orchestrator-is-a-trigger.md`.

| VR-001 | The gate blocks a phase only on error-severity findings; warning and info are recorded but non-blocking.                                                                                                                                                                                                                                                                                                                                                                                                                  | Gate semantics           | UC-02, BR-002                       |

| VR-003 | A phase gate is presented for approval only when the gate passed and the latest iteration's open-findings count is zero.                                                                                                                                                                                                                                                                                                                                                                                                  | Approval precondition    | UC-04, BR-007                       |
| VR-004 | _(Now factory's.)_ Every agent invocation runs in a fresh CLI subprocess with no inherited context.                                                                                                                                                                                                                                                                                                                                                                                                                       | Isolation                | UC-01, UC-02, BR-004                |
| VR-005 | _(Now factory's — the orchestrator's own `resume` command is deleted.)_ Resume must not re-run any phase already recorded as complete.                                                                                                                                                                                                                                                                                                                                                                                    | Resume integrity         | UC-06, BR-009                       |

| VR-009 | _(Deferred with unattended execution, NG6.)_ In unattended mode, auto-approve applies only when the gate passed and open findings equal zero.                                                                                                                                                                                                                                                                                                                                                                             | Bounded autonomy         | NG6                                 |
| VR-010 | `.orchestrator/run.json` records branch, phase, iteration, and mode, is written atomically, and validates against the run-state schema.                                                                                                                                                                                                                                                                                                                                                                                   | State integrity          | UC-06, BR-017                       |
| VR-011 | _(Now factory's.)_ An unknown agent name is rejected before any subprocess is launched.                                                                                                                                                                                                                                                                                                                                                                                                                                   | Fail-fast                | UC-01, BR-011                       |
| VR-012 | If tracked artifacts changed since the checkpoint, the gate is re-run before the run continues.                                                                                                                                                                                                                                                                                                                                                                                                                           | Staleness                | UC-06, BR-013                       |
| VR-013 | _(Now factory's.)_ At the start of each authoring iteration, the phase's prior open findings are marked superseded; the loop-exit condition counts only the latest iteration's open findings.                                                                                                                                                                                                                                                                                                                             | Loop termination         | UC-02, BR-014                       |
| VR-014 | _(Now factory's.)_ A gate that errors (infra/tooling failure) halts immediately and does not count an author iteration; only a gate that reports findings loops the author.                                                                                                                                                                                                                                                                                                                                               | Gate error handling      | UC-02, BR-015                       |
| VR-015 | The phase's `pre-commit` gate hook exits non-zero if and only if at least one error-severity finding exists.                                                                                                                                                                                                                                                                                                                                                                                                              | Gate exit contract       | UC-02, BR-002                       |
| VR-016 | _(Amended — the orchestrator still runs this check, but only from `approve`'s staleness re-gate, VR-012, not per phase iteration.)_ Agents commit their own artifacts on the run branch; the orchestrator verifies the working tree is clean after the agent exits. A clean tree = gate passed.                                                                                                                                                                                                                           | Working-tree gate        | UC-02, FR-D3                        |
| VR-017 | Only one run may be active; the orchestrator refuses to start while a lock is held or a run is `running`.                                                                                                                                                                                                                                                                                                                                                                                                                 | Single-run invariant     | UC-03, BR-017                       |
| VR-018 | _(Now factory's.)_ An adapter authentication or availability failure halts the run without counting an author iteration.                                                                                                                                                                                                                                                                                                                                                                                                  | Adapter failure          | UC-02, BR-018                       |
| VR-019 | _(Now factory's.)_ Completion of a gated phase requires artifacts and a passing gate; completion of `run-step` requires artifacts only; a clean reviewer that writes no findings completes on a zero-exit session.                                                                                                                                                                                                                                                                                                        | Completion detection     | UC-01, UC-02, BR-005                |
| VR-020 | _(Now factory's.)_ A not-author-fixable, deterministically-repeating failure — an adapter `config_error` (bad model id / unknown flag) or a gate timeout — halts the run without counting an author iteration, rather than looping to the cap. Checked before the generic author-failed edge.                                                                                                                                                                                                                             | Failure classification   | UC-02, BR-020                       |
| VR-021 | _(Now factory's.)_ Each CLI adapter forces a clean session and never passes a resume/continue flag, so a fresh process cannot inherit a persisted session.                                                                                                                                                                                                                                                                                                                                                                | Isolation                | UC-02, BR-004                       |
| VR-022 | Every story's frontmatter validates against the StoryFrontmatter schema, with `tier ∈ {economy, standard, strong}`; `backlog-lint` enforces this and the story→use-case traceability, and is the planning phase's gate.                                                                                                                                                                                                                                                                                                   | Backlog integrity        | BR-021, FR-K1                       |
| VR-023 | _(Now factory's.)_ Model selection has two axes at two levels that never combine. For every agent the orchestrator invokes directly, the precedence is `--model` flag (run-step only) → agent's declared tier resolved directly against `model.conf` → adapter default. During implementation the dispatcher selects each tier-less developer sub-agent's model from the story's own `tier` alone, below the adapter boundary. There is no per-story model field beyond `tier` itself, so the backlog stays CLI-agnostic. | Model selection          | BR-021, FR-K3, FR-R11, FR-R12, FR-M |
| VR-024 | `matrix-lint` requires every `model.conf` `[facts]` entry to be a well-formed `<cli>.<tier>` mapping and `on_missing` (if set) to be `halt` or `auto`; an unresolved tier at run time halts as a config error unless `on_missing` is set to the adapter default.                                                                                                                                                                                                                                                          | Matrix integrity         | BR-020, FR-K2, FR-K4                |
| VR-025 | _(Now factory's.)_ Exit code 0 with a dirty working tree (confabulation) halts the run immediately; the agent claimed success but did not commit all artifacts.                                                                                                                                                                                                                                                                                                                                                           | Confabulation detection  | FR-D5                               |
| VR-026 | _(Now factory's.)_ On RetryOrHalt with a dirty working tree, the orchestrator cleans uncommitted changes before re-invoking the agent, preserving session isolation. Committed work on the run branch survives.                                                                                                                                                                                                                                                                                                           | Clean tree before retry  | FR-D6, ADR-0002                     |
| VR-027 | A story's `status: done` in its frontmatter is allowed only if at least one file matching its `outputs` globs exists on the branch (same or prior commit). `backlog-lint` enforces this at error severity.                                                                                                                                                                                                                                                                                                                | Story-commit consistency | FR-N1                               |
| VR-028 | If committed files match a story's `outputs` globs or the commit message references `(ST-NNNN)` but the story's status is not `done`, `backlog-lint` emits a warning.                                                                                                                                                                                                                                                                                                                                                     | Story status nudge       | FR-N2                               |
| VR-029 | `release` restores a halted phase to its `halted_from` sub-state and resets the iteration count. Requires `halted_from` to be non-null.                                                                                                                                                                                                                                                                                                                                                                                   | Release precondition     | FR-A7                               |

Schemas referenced by VR-006 and VR-010 are defined in [interface-contracts](interface-contracts.md).
