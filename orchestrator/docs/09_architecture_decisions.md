## Relationships

- **0001** is foundational; **0002–0006** each specify the concretion behind one port or cross-cutting concern it establishes.
- **0002** (fresh subprocess) and **0003** (pre-commit gate) together realize the determinism-under-isolation strategy: the LLM runs isolated, bracketed by a deterministic gate.
- **0004** (findings store) and **0005** (run state) share the atomic write-then-rename discipline and the "plain, git-diffable JSON" ethos.
- **0007** (uv) is **complementary to 0006**, not a revision of it: 0006 bounds the *runtime* dependency surface; 0007 chooses the *build/dev/distribution* tooling and pins the environment. Dev/gate tools (`pre-commit`, `ruff`, `pytest`) live in a uv dev group, leaving the runtime surface untouched.
- **0008** (backlog format) and **0009** (classification + model matrix) both come from the planning-phase grill: 0008 defines *where* stories live, 0009 defines *how* a story's difficulty picks a model. 0008 deliberately diverges from the JSON findings store ([ADR-0004](adr/0004-file-per-finding-store.md)) — different readers, different formats.
- **0011** and **0012** are the semantic-source counterpart to **0004** (findings store): 0004 decides where findings live and how they are identified; 0011/0012 decide how the reviewer's findings reach that store. **0012 supersedes the ingest *mechanism* of 0011** — reading the filed `docs/findings/*.md` rather than the reviewer's stdout — after the stdout channel proved unavailable in interactive mode (ST-0022). 0011's option A/B/C analysis stands; only its chosen mechanism is replaced.
- **0013** partially supersedes **0003**: the hook configuration (which hooks, versioning, phase-specific checks) remains as 0003 describes, but the *commit responsibility* shifts from orchestrator to agent. The orchestrator's gate becomes a working-tree cleanliness check, not a stage-commit-parse sequence. 0013 also introduces confabulation detection (exit 0 + dirty tree).
- **0014** extends **0001**'s port structure: `PromptComposer` gains an `InvocationContext` parameter, a breaking protocol change to all callers. The five call-to-action templates cover every state-machine transition where an agent is invoked.
- **0015** extends **0005**: `PhaseRecord` gains `halted_from` to enable recovery without discarding completed phases. The `release` command is the recovery mechanism.
- **0019** closes what 0012 left open: the JSON store keeps the loop-state role (identity, lifecycle, phase/iteration scoping) and `docs/findings/*.md` stays the ingestion input — a projection relationship, not two independently-authored stores. No further store-model change follows from ST-0021.
- **0016, 0017, and 0018** together introduce the TUI addendum. **0016** extends **0001**'s port structure with a `MenuRenderer` port and adds `MenuController`/`SettingsResolver` to the core, mirroring how **0002** put the CLI behind `CLIAdapter`: the terminal is just another concretion behind a seam. **0017** persists operator defaults and the adapter registry, giving **0002**'s adapter selection a runtime catalog for the first time. **0018 revises 0009**: the classification model and the facts/policy separation stand, but runtime resolution now reads the per-adapter dictionary (populated from the matrix facts) rather than the matrix directly, and the agent-tier axis joins classification. All three keep the dependency rule — the presentation layer, the config store, and the resolver depend only on ports.
- **0020 supersedes 0009's mechanism and revises 0018's vocabulary**, but not its architecture: the two-axis, two-level split from 0018 (agent tier for every orchestrator-invoked agent; the story's own value for the dispatcher's tier-less developer sub-agents) stands unchanged. What changes is that the story-level axis now stores `tier` directly instead of a `classification` that 0009's policy table translated — collapsing the model matrix's `[policy]` section entirely and leaving `[facts]` as a flat per-CLI tier router. Resolves [SPEC-0009](findings/SPEC-0009.md).
