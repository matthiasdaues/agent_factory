# Entering an empty runtime-populated menu is a silent dead end

**What is wrong:** Selecting a `MenuNodeType.MENU` leaf whose `children` list is empty at runtime (e.g. `configure > defaults > adapter` when `AdapterRegistry.list_adapters()` returns `[]`, the state of every freshly-initialised project) produces **no visible output whatsoever**. `MenuController._select_child()` pushes the empty node onto the stack and transitions state exactly as it would for a populated menu, but `TerminalMenuRenderer.render_menu([], ...)` intentionally no-ops on an empty item list (guard added so an empty render doesn't emit a stray blank line). The result: pressing Enter on `adapter` appears completely indistinguishable from a dropped keypress or a frozen terminal — the screen shows the exact same frame before and after. Confirmed live: the state transition did happen (verified by pressing Back immediately afterward, which re-rendered the *same* parent frame, only possible if a push-then-pop actually occurred), but nothing on screen ever indicated it.

The existing "no adapters registered" error message (`tests/test_configure_defaults.py::test_no_adapters_registered_rejects_any_selection`) does not cover this path — it only fires when a `FUNCTION` leaf is dispatched directly by node id, which is unreachable through real menu navigation when the adapter list is empty, since there is no leaf to select in the first place.

**Fix:** When a `MENU`-type node's `children` list is empty at the point of entry, render an explicit empty-state message (e.g. "No adapters registered — run configure > cli-list > auto-detect first.") instead of silently pushing into a blank frame. Likely lands as a small addition to `MenuController._select_child()` (detect empty children before pushing, render a message and stay put — or push and have `_render_current_menu()` fall back to a placeholder line when `items` is empty) plus a corresponding `TerminalMenuRenderer` test asserting a non-empty frame for this case. Applies to every runtime-populated menu node, not just `configure.defaults.adapter` — `cli-list > remove-adapter` and `model-matrix` family nodes have the same shape and should be checked for the same gap.
