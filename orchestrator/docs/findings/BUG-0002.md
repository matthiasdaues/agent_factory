# Every `orchestrate init`-created project gets a `.pre-commit-config.yaml` whose gate hooks reference paths init never creates

**What is wrong:** `orchestrate init` (`_handle_init` in `orchestrator/src/orchestrator/cli.py`)
copies its tooling into a brand-new project with a **flat** destination layout — bare
`project_dir/agents`, `project_dir/skills`, `project_dir/scripts`
(`_COPY_DIRS`/`shutil.copytree`), and bare `project_dir/model-matrix.conf`
(`shutil.copy2(src_matrix, dst_matrix)`) — confirmed live by running
`orchestrate init <tmp-dir>` and inspecting the result (also matches this
destination-side behaviour's own existing, passing test coverage:
`test_init.py::TestInitCopiedDirs::test_copies_tooling_dirs`,
`TestInitModelMatrix::test_copies_template`, both asserting the flat form).

But `_handle_init` also copies `orchestrator/pre-commit-config.yaml` **verbatim** as
the new project's `.pre-commit-config.yaml` (step 6b), and `ST-0066` (this same
range, commit `d2292c1`) rewrote that template's five gate hooks to invoke
`python3 factory/scripts/<name>` and to point `matrix-lint` at
`config/model-matrix.conf` — paths that only exist in **agent_factory's own**
self-hosted layout (and in a project bootstrapped by the *different*
`init-factory` script), not in anything `orchestrate init` itself creates.

Reproduced directly:

```
$ orchestrate init /tmp/scratch-project
Project initialized at /tmp/scratch-project
...
$ cat /tmp/scratch-project/.pre-commit-config.yaml | grep entry
        entry: uv run mdformat
        entry: uv run ruff check --fix
        entry: uv run ruff format
        entry: python3 factory/scripts/spec-lint
        entry: python3 factory/scripts/arch-lint --docs-dir docs --no-validate
        entry: python3 factory/scripts/backlog-lint --backlog-dir backlog
        entry: python3 factory/scripts/matrix-lint --matrix config/model-matrix.conf
        entry: python3 factory/scripts/statemachine-lint --spec-dir docs/spec

$ ls /tmp/scratch-project/scripts/spec-lint     # the real, copied location
/tmp/scratch-project/scripts/spec-lint

$ cd /tmp/scratch-project && python3 factory/scripts/spec-lint
Traceback (most recent call last):
  ...
FileNotFoundError: [Errno 2] No such file or directory: '.../factory/scripts/spec-lint'

$ python3 scripts/spec-lint   # works — this is where init actually put it
[ERROR  ] STRUCT005  actor-goal-list.md: required spec artifact is missing
...
```

All five gate hooks (`spec-lint`, `arch-lint`, `backlog-lint`, `matrix-lint`,
`statemachine-lint`) in every freshly `orchestrate init`-ed project are broken:
the first four fail loudly with "command not found"/`FileNotFoundError` the
first time their `files:` pattern matches a staged file; `matrix-lint`'s own
`files: ^config/model-matrix\.conf$` pattern additionally never matches the
real file (`model-matrix.conf`, no `config/` prefix — no `config/` directory
is created by `orchestrate init` at all), so that hook is permanently inert on
top of being unreachable.

`ST-0065` (source-side fix, same range) and `ST-0066` (this template fix, same
range) were each scoped to a single file and each internally self-consistent,
but never cross-checked against each other's effect on the same end-to-end
flow — `test_init.py::TestInitPreCommitConfig::test_copies_pre_commit_config`
only asserts the hook **names** are substrings of the copied file, never that
the `entry:`/`files:` paths resolve against what init actually creates, so
neither existing test suite nor the two stories' own manual verification
caught the cross-file inconsistency.

**Fix:** Revert the five gate hooks' `entry:` lines in
`orchestrator/pre-commit-config.yaml` from `factory/scripts/<name>` back to
bare `scripts/<name>`, and revert `matrix-lint`'s `--matrix` argument and
`files:` pattern from `config/model-matrix.conf` back to bare
`model-matrix.conf` — matching `_handle_init`'s real, current, already-tested
destination convention (flat `scripts/`, flat `model-matrix.conf`). This is
the smaller, verifiable-today fix; it does not require changing
`_handle_init`'s destination layout to nest a `factory/`/`config/` structure,
which would be a materially larger change entangled with `ADR-0010`'s already
tracked, not-yet-designed distribution-model supersession (`T-41`) —
`orchestrate init` and `init-factory` are two distinct, differently-conventioned
bootstrap mechanisms in this repo today, and this fix only needs the template
to match the one it actually feeds. Add regression coverage that resolves
every `python3 <path>`-form `entry:` in the copied config against the
init'd project root and asserts the path exists, plus a check that
`matrix-lint`'s `files:` pattern actually matches `model-matrix.conf`'s real,
copied location — not just that the hook names appear as substrings.
