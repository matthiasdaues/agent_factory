# Adapter registry persistence location is inconsistent across three artifacts

**What is wrong:** `prd-tui-addendum.md`'s T-32 resolution states that the adapter registry and its per-adapter model dictionaries "are persisted in `.orchestrator/config.toml`." `interface-contracts.md`'s `ConfigStore`/`Config` — explicitly bound to `.orchestrator/config.toml` — carries only `adapter`, `timeout`, `cap`, and `auto_approve`; it has no adapter-registry or model-dictionary fields, and `AdapterRegistry` is defined as a separate port with no stated persistence target. `entity-model.md` says the registry "is persisted alongside the configuration store," which reads as a second, co-located file rather than the same file. The three artifacts do not agree on whether the adapter registry lives inside `config.toml` or in its own store.

**Fix:** Pick one persistence design. Either fold `AdapterEntry`/`ModelDictionary` fields into the `Config` schema so the design matches T-32's wording, or name a distinct file or store for the registry and correct T-32's resolution note to match. Update `interface-contracts.md`, `entity-model.md`, and `prd-tui-addendum.md` T-32 so all three agree.

**Resolved:** [ADR-0021](../adr/0021-adapter-registry-discovery-and-precedence.md) picks the first option — `AdapterRegistry`/`ModelDictionary` persist in `.orchestrator/config.toml`, alongside `Config`, matching T-32's original wording. `interface-contracts.md` § Adapter Registry now states this explicitly; `entity-model.md`'s "alongside" is corrected to "in the same store." All three artifacts agree. (`discover_models()`/T-31 is a separate, still-open question — see ADR-0021's Follow-up.)
