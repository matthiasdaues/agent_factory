# The model matrix's phase-to-tier policy contradicts the agent-frontmatter-tier resolution chain

**What is wrong:** FR-K2 states that model selection resolves "a classification (or a phase) to a tier" through the model-matrix policy, and the Model Matrix schema in `interface-contracts.md` still carries `phase.<name> = <tier> | by-class`. But FR-R10 through FR-R12 and VR-023 establish a different mechanism for the same case: for every agent the orchestrator invokes directly, the tier comes from the agent's own frontmatter `tier` field, resolved through the adapter's model dictionary. Neither VR-023 nor FR-R11/FR-R12 mentions consulting the matrix's phase policy at all. Nothing in the specification says whether `phase.<name> = <tier>` is superseded by the agent's own declared tier, still consulted as a fallback, or applies to some other case the spec does not name. If the phase-tier entry is dead, its retention is unjustified spec content; if it is still live, the two sources for a phase agent's tier can disagree with no stated precedence.

**Fix:** State explicitly whether `phase.<name> = <tier>` in the model matrix still governs anything now that FR-R10 through FR-R12 exist. If the agent's own frontmatter tier fully replaces it for orchestrator-invoked agents, remove or explicitly deprecate the `phase.<name>` policy line (keeping `class.<name>` for developer-agent classification and `phase.implementation = by-class`, which the dispatcher still needs) and update FR-K2 and FR-K5 to match. If it still serves a purpose, define the precedence between it and the agent's frontmatter tier.
