# Model resolution is undefined when an agent declares no tier

**What is wrong:** FR-R11 and FR-R12 resolve the default model from "the selected agent's declared tier," but the tier is optional. `interface-contracts.md` types `AgentInfo.tier` as `str | None`, and `entity-model.md` marks the tier nullable. No agent definition under `agents/` currently declares a `tier` frontmatter key, so at present every agent resolves to a null tier. The specification does not define what the orchestrator does when the agent's tier is absent: whether it halts as a configuration error, falls back to the adapter default, or infers a tier some other way.

**Fix:** Add a requirement (and a matching validation rule) that defines model resolution when an agent declares no tier — for example, halt as a configuration error consistent with FR-K4, or use the adapter default when fallback is enabled. State whether `tier` is mandatory for any agent reachable by `run-step`, `run-phase`, or `run-all`, and reconcile that with the nullable type in the contracts.
