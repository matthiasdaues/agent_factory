# The tier-to-model mapping is duplicated in two artifacts with no authority declared

**What is wrong:** Two separate artifacts map an (adapter, tier) pair to a concrete model, and the specification does not say which one is authoritative:

- The Model Matrix `[facts]` section in `interface-contracts.md` maps `<cli>.<tier> = <model id>` (for example `copilot.economy = …`).
- The per-adapter model dictionary — `ModelDictionary` in `interface-contracts.md` and `MODEL_DICT_ENTRY` in `entity-model.md` — maps `tier → model_id` for each registered adapter.

A reader cannot tell whether the adapter dictionary supersedes the matrix facts, mirrors them, or is a second independent source that could disagree at run time. This is both a contradiction risk and redundant specification of the same data.

**Fix:** Designate one artifact as the single source of truth for the tier-to-model mapping and state the relationship explicitly — for example, that the per-adapter model dictionary replaces the matrix `[facts]` section, or that the matrix facts are derived from the dictionaries. Update `interface-contracts.md` and `entity-model.md` to reflect the decision. Coordinate with open question T-32 on where the adapter catalog lives.
