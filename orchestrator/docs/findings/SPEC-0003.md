# The model-resolution rule for phase runs contradicts itself across four statements

**What is wrong:** Four parts of the specification give incompatible rules for how a phase run selects a model:

- `cli_specification.md` design rule 4 states that for phase runs "the higher of the two [agent tier, story classification] determines the effective tier."
- The `cli_specification.md` model-resolution-chain diagram, `prd-tui-addendum.md` FR-R12, and the `system-use-cases.md` CLI adapter management section all state that phase and chain runs resolve each agent independently from that agent's declared tier alone, with no classification input.
- The existing `system-use-cases.md` Model selection section and VR-023 state that model selection maps the story's classification (or the phase) to a tier through the model matrix.

Open question T-34 acknowledges this tension, yet the requirements are written as if the policy were already settled, and they settle it three different ways.

**Fix:** Resolve T-34 and make the four statements agree on a single rule for phase-run model resolution. Update `cli_specification.md` design rule 4, the model-resolution-chain diagram, FR-R12, and the Model selection requirements (with VR-023) so they express the same policy, or mark the affected requirements provisional until T-34 closes.
