# Business-rule cross-references in the TUI requirements resolve to the wrong rules

**What is wrong:** The EARS requirements in the Configuration management, CLI adapter management, Skill-scoped execution, Enhanced status views, and Backlog views sections of `system-use-cases.md` cite business-rule identifiers whose numbers resolve to unrelated rules defined for earlier use cases. Examples:

- "persist operator defaults … (BR-033)" — BR-033 is UC-08 menu-state isolation; the governing rule is BR-037 (config persistence).
- "apply the precedence order … (BR-036)" — BR-036 is UC-08 function-leaf dispatch; the governing rule is BR-040 (precedence).
- "write `.orchestrator/config.toml` atomically (BR-034)" — BR-034 is UC-08 back-navigation; the governing rule is BR-038 (atomic writes).
- "refuse the affected action … (BR-037)" — BR-037 is config persistence; the governing rule is BR-041 (malformed config).
- The Skill-scoped requirements cite BR-039/040/041/043 and reference none of UC-11's own BR-050 through BR-055.
- The Backlog requirements cite BR-041/042/044/045 and reference none of UC-12's own BR-056 through BR-060.

Because every cited number is defined somewhere, `spec-lint` cannot catch the mismatch; it surfaces only as ten `TRACE003` "defined but never referenced" notices for BR-046 through BR-055. The pattern indicates the section was authored against a pre-renumber draft and never re-synced with the per-use-case business-rule blocks.

**Fix:** Re-map every business-rule citation in the five TUI sections of `system-use-cases.md` to the rule that actually governs the stated behavior — the BR-037 through BR-041 range for configuration, BR-042 through BR-049 for adapters and model dictionaries, BR-050 through BR-055 for skill-scoped execution, and BR-056 through BR-060 for backlog views. Re-run `spec-lint` and confirm no business rule in that range remains unreferenced.
