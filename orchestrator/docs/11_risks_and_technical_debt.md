## 11.2 Architectural risks

| ID  | Risk                                                                                                                                                                                   | Likelihood × Impact | Mitigation                                                                                                                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-1 | **Completion-detection false positive** — an agent writes a declared output *partially* (e.g. an empty file), which the filesystem check accepts as "done" (assumption A1).            | Med × High          | The gate (`spec-lint`) catches malformed content; the empty-commit rule (BR-016) catches no-change; consider a min-content check per output. Tracked for the ATAM review.                                               |
| R-2 | **Gate/finding source mismatch** — `spec-lint --format json` or the reviewer emits a shape the ingest mapper doesn't expect, producing an invalid finding.                             | Med × Med           | Schema validation on write (VR-006) rejects it loudly rather than storing garbage; the ingest mappers are the single translation point.                                                                                 |
| R-3 | **Auto-fixing hook loop** — a `pre-commit` hook that rewrites files could, if mishandled, ping-pong.                                                                                   | Low × Med           | BR-015 / ext. 5c bounds it: re-stage and re-commit **once**, then treat as a normal gate result — no unbounded rewrite loop.                                                                                            |
| R-4 | **Prompt-composition drift** — as agent definitions evolve, the composed prompt may omit context an agent now needs.                                                                   | Med × Med           | `PromptComposer` is the single composition point and reads the agent definition as-is; agent-definition changes are the source of truth, reducing drift.                                                                |
| R-5 | **Cost blow-up under loop-backs** — a phase that loop-backs to the cap across a long chain could be expensive; unattended autonomy (deferred, NG6) would amplify this when it returns. | Med × Med           | Per-invocation timeout (NFR-6) + iteration cap (BR-001) bound cost per phase; every run is human-attended for now; CI cost ceilings deferred to T-08.                                                                   |
| R-6 | **Run-branch divergence** — the dedicated run branch may drift from the operator's working branch, complicating the eventual merge.                                                    | Low × Low           | Out of scope for the orchestrator; the operator owns the merge. Documented so it is not a surprise.                                                                                                                     |
| R-7 | **Terminal-compatibility surprises** — arrow-key escape sequences and cursor control vary across terminals; menu mode could misrender or trap input.                                   | Med × Med           | The `MenuRenderer` port confines terminal handling to one adapter (ADR-0016); a non-interactive or unsupported terminal degrades to a direct-mode diagnostic (FR-V4). Framework choice (T-29) will weigh compatibility. |
| R-8 | **Config/registry corruption** — a malformed or partially written `.orchestrator/config.toml` could break settings resolution or the adapter catalog.                                  | Low × Med           | Atomic write-then-rename (VR-032); a malformed file makes the orchestrator refuse the affected action and report the offending key rather than run on garbage (FR-Q6). Built-in defaults apply when the file is absent. |

## 11.3 ATAM review outcomes

The independent ATAM review ([reviews/atam-review.md](reviews/atam-review.md)) evaluated all 17 quality scenarios and raised 11 risks (1 High, 6 Medium, 4 Low), with the verdict that the architecture is sound enough to proceed to planning and no risk is blocking. The recurring theme was a single weak seam — **failure classification**. That seam has since been closed in this documentation and, where concrete, in code:

- The High risk (no `config_error` signal — the confirmed spike defect) is resolved: `InvocationResult.config_error` + the `Authoring → Halted` edge (BR-020), verified live.
- The Medium risks — gate `errored`-vs-`findings` discriminator, gate timeout, `last_gate` in run state, the `Logger` sink, resume idempotency, and the brittle `auth_error` regex — are resolved at the contract/architecture level and scheduled for Phase 4 implementation.
- The Low risks (ID-allocator crash-safety, lock liveness, clean-tree enforcement, clean-session isolation) are specified in the relevant ADRs and validation rules.

Each is tracked with its resolution status in [`spec/todos.md`](spec/todos.md) as **T-11…T-18**. Per the workflow, the review report itself is left as the record of what was found; the reviewer closes the items on the next review pass.

## 11.4 Deliberate technical debt (accepted for the MVP)

- **MVP is the requirements phase only** (NG5). The other three phases are configuration + hooks on the same control flow, but they are not yet exercised end-to-end — architecture and planning phases in particular depend on T-10.
- **No external ticket adapter** (NG3, T-04). The store schema is designed to map cleanly to a future GitHub Issues/Jira adapter, but that adapter does not exist.
- **Single-machine only** (NFR-5, T-08). CI/container deployment and its auth/cost model are deferred.
- **No preflight `doctor` command.** The Tier-A system prerequisites (git, an authenticated adapter, Docker) are documented as a manual checklist ([chapter 7](07_deployment_view.md)), not verified by a command. A missing prerequisite therefore surfaces as a halt during the run (BR-015/BR-018) rather than up front. An `orchestrate doctor` preflight was considered and deferred; if adopted it is new functional scope and should enter through the spec-feedback loop (prompt 08a) before being reflected here.
