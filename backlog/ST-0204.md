# Add reading-guide maintenance to update-context

Extend `update-context` to maintain `reading-guides.yaml` whenever a key is added or a source pointer changes. When this happens, `update-context` asks the operator which concern the key belongs to and updates the reading guide immediately. See [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05).

**Priority:** must-have

## Demo

An operator uses `update-context` to add a `source:` pointer to `workflow.yaml#observability`. After writing the pointer, `update-context` asks: "Which concern does this belong to? Your current concerns are: backend, testing, architecture, packaging. Pick one, or name a new one." The operator picks "backend." `update-context` adds `workflow.yaml#observability` to the backend concern in `reading-guides.yaml`.

## Acceptance Criteria

- When `update-context` adds a new key to any index file, it asks the operator which concern the key belongs to.
- When `update-context` changes a `source:` pointer on an existing key, it asks the operator whether the concern assignment is still correct.
- `update-context` updates `reading-guides.yaml` with the operator's answer before completing the write.
- The operator can name a new concern not already in the reading guide, and `update-context` creates it.
- If `reading-guides.yaml` does not exist, `update-context` creates it with the first concern assignment.

## Scope

**Status quo:** `update-context` on `feature/agent-context` writes index-file fields and manages source pointers. It proposes creating `reading-guides.yaml` when the first source pointer is written but does not maintain concern assignments.

**Adds:** Concern-assignment question on key add or source change. Reading-guide maintenance as a core responsibility of `update-context`.

**Out of scope:** Interview guide creation (ST-0203). Skill discovery rewrite (ST-0205).
