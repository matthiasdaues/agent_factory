# Auto-detect YAML format and offer interactive migration; retire update-context

Add a YAML migration path to `capture-context` and retire the `update-context` skill. When `capture-context` is invoked without flags on a project that has YAML agent-context files, it detects the old format and offers interactive migration to the concern model. The `update-context` skill body is replaced with a deprecation notice.

**Priority:** must-have

## Demo

The user runs `capture-context` (bare, no flags) in a project with `docs/agent-context/stack.yaml`, `workflow.yaml`, `governance.yaml`, and `reading-guides.yaml`. The skill detects the YAML format and says: "I found YAML agent-context files. Want to migrate to the concern model?" The user confirms. The skill reads the YAML content, proposes concern sections (cross-cutting from governance.yaml, technical from stack.yaml, routing from reading-guides.yaml), and presents the proposed `agent-context.md` for review. The user confirms. `agent-context.md` is written, `testing.yaml` moves to `docs/testing.yaml`, and the YAML files and `docs/agent-context/` directory are deleted. The user invokes `update-context` and sees: "update-context is deprecated. Edit docs/agent-context.md directly."

## Acceptance Criteria

- Bare `capture-context` (no flags) detects old YAML agent-context files (`docs/agent-context/stack.yaml` or any of the four YAML files) and offers interactive migration.
- Migration reads existing YAML files and `reading-guides.yaml` and proposes concern sections derived from their content.
- On user confirmation: `docs/agent-context.md` is written with concern sections, `testing.yaml` moves to `docs/testing.yaml`, old YAML files are deleted, and `docs/agent-context/` directory is removed.
- `concern-lint` passes on the migration output.
- `update-context` skill body is a deprecation notice pointing to direct `agent-context.md` editing.
- Invoking `update-context` produces no error and no side effects -- only the deprecation notice is shown.
- `factory/rulebooks/templates/context-*.yaml` (stack, workflow, governance, reading-guides, interview-guide) are deleted from the factory.

## Scope

**Status quo:** `capture-context` produces YAML files. `update-context` writes to YAML fields. Five `context-*.yaml` templates exist in `factory/rulebooks/templates/`. The greenfield concern-format capture-context mode exists (ST-0218 deliverables).

**Adds:** YAML auto-detection and interactive migration path in capture-context. Deprecation notice in update-context. Deletion of YAML templates.

**Out of scope:** Deletion of YAML files in this project's `docs/agent-context/` directory (EPIC 12 handles cleanup after all consumers are updated). Resolution chain updates for testing.yaml in other consumers (ST-0223).

## Notes for the Implementer

The YAML-to-concern mapping requires judgment, so the migration is interactive. A reasonable mapping: governance.yaml keys map to cross-cutting concerns, stack.yaml keys map to technical concerns, reading-guides.yaml concern entries inform the concern section names. The `source:` pointers from YAML fields become `Read:` paths in concern sections. The user confirms the proposed structure before anything is written.
