# Publish reproducible release assets from a version tag

**Priority:** must-have

## Goal

A release maintainer pushes a version tag and each approved distribution remote independently builds and publishes `install-agent-factory`, `agent-factory.tar.gz`, and `SHA256SUMS`. Archives built from the same tagged source, workflow, and pinned toolchain share the same SHA-256 digest.

## Contract

| Operation                                   | Input state                                    | Outcome                                                                                | Persistence                                                                                                      |
| ------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `build-release --version <semver>`          | Clean tagged source tree                       | Three files in output dir; `sha256sum -c SHA256SUMS` passes                            | `install-agent-factory`, `agent-factory.tar.gz`, `SHA256SUMS` written to `--output <dir>` (default `./release/`) |
| `build-release --version <semver>` (repeat) | Same tagged source, workflow, pinned toolchain | Archive SHA-256 digest identical to first run                                          | Same three files, same content                                                                                   |
| `build-release` fails mid-execution         | Any                                            | Non-zero exit; no partial output remains                                               | Output directory cleaned                                                                                         |
| Tag push triggers workflow                  | Tag matching `v*` on approved remote           | Workflow checks out tag, runs `build-release`, attaches three assets to GitHub release | Release assets on remote                                                                                         |
| Workflow with `build-release` failure       | `build-release` exits non-zero                 | Workflow run fails; no assets attached                                                 | No release assets                                                                                                |

## Boundaries

- Each remote builds from its local copy of the immutable tag. No artifact or digest transfer between remotes.
- Deterministic tar: sorted entries, fixed timestamps (`1970-01-01`), fixed owner (`root:root`), no platform-specific metadata.
- No network access, external registries, or tools beyond the pinned build environment.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Affected Paths

- `packages/factory/scripts/build-release` — new script.
- `.github/workflows/build-release.yml` — new workflow.
- `tests/factory/` — new `test_build_release.py`.

## Demo Scenario

1. Push tag `1.0.0` to two approved remotes with the same tagged commit and release workflow.
2. Each remote's workflow runs `build-release --version 1.0.0`.
3. Verify each release contains three assets.
4. Run `sha256sum -c SHA256SUMS` against each remote's archive. Both pass.
5. Compare archive digests from both remotes. The digests match.

## Evidence

- [ ] `build-release --version 1.0.0` produces exactly `install-agent-factory`, `agent-factory.tar.gz`, and `SHA256SUMS`.
- [ ] `sha256sum -c SHA256SUMS` passes for the produced archive.
- [ ] Two runs from the same source produce archives with identical SHA-256 digest.
- [ ] Failed `build-release` leaves no partial output in the output directory.
- [ ] `.github/workflows/build-release.yml` triggers on `v*` tags and attaches three assets to the GitHub release.

## Verification

```bash
uv run pytest tests/factory/test_build_release.py -v --tb=short
```

## Out of Scope

- Distribution remote setup, mirroring, tag propagation, credentials, access administration.
- Signing or GPG verification — SHA-256 digest comparison only.
- Artifact transfer between remotes.

## Stop Conditions

- Deterministic tar settings produce different digests across platforms in the build environment → report which platform and settings diverge.
- Bootstrap template format for `install-agent-factory` is not in supplementary specs → report and ask.
- GitHub Actions workflow requires secrets or permissions not documented in the repository → report which ones.
- Code in `packages/factory/scripts/` and the feature spec disagree on the asset set contents or the reproducibility contract → report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. What is the exact bootstrap template format for `install-agent-factory`?
2. What is the pinned build environment for the GitHub Actions workflow (OS, shell, tool versions)?
3. Does `build-release` support building from a working tree or only from a clean tagged checkout?
