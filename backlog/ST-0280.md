# Publish reproducible release assets from a version tag

**Priority:** must-have

## Goal

A release maintainer pushes a version tag and each approved distribution remote independently builds and publishes `install-agent-factory`, `agent-factory.tar.gz`, and `SHA256SUMS`. Archives built from the same tagged source, workflow, and pinned toolchain share the same SHA-256 digest.

## Required Script Behavior

### `build-release`

- Reads the version from `packages/factory/VERSION`.
- On `main`: VERSION must contain `N.N.N` (no suffix). On `dev`: VERSION must contain `N.N.N-rc`. Any mismatch exits non-zero without output.
- Produces three files in `--output <dir>` (default `./release/`): `install-agent-factory`, `agent-factory.tar.gz`, and `SHA256SUMS`.
- `install-agent-factory` is bundled verbatim from `packages/factory/scripts/install-agent-factory` (stdlib-only Python 3.8+ script).
- `agent-factory.tar.gz` is a deterministic archive: sorted entries, fixed timestamps (`1970-01-01`), fixed owner (`root:root`), no platform-specific metadata.
- `SHA256SUMS` contains the SHA-256 digest of `agent-factory.tar.gz`.
- On failure: exits non-zero and removes any partial output from the output directory.

### `build-release.yml` (GitHub Actions workflow)

- Two triggers:
  - `v*` tag push on `main`: checks out the tag, runs `build-release`, attaches three assets to a GitHub release.
  - Push to `dev`: runs `build-release`, creates a GitHub pre-release tagged `vN.N.N-rc` with three assets.
- Pinned environment: `ubuntu-24.04`, Python 3.10, bash.
- The same workflow file runs on all three distribution remotes.

## Contract

| Operation                                    | Input state                                 | Outcome                                                                                        | Persistence                                                                                                      |
| -------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `build-release` on `main`                    | Clean checkout, VERSION contains `N.N.N`    | Three files in output dir; `sha256sum -c SHA256SUMS` passes                                    | `install-agent-factory`, `agent-factory.tar.gz`, `SHA256SUMS` written to `--output <dir>` (default `./release/`) |
| `build-release` on `dev`                     | Clean checkout, VERSION contains `N.N.N-rc` | Same three files; version stamped as RC                                                        | Same output dir                                                                                                  |
| `build-release` (repeat)                     | Same source, workflow, pinned toolchain     | Archive SHA-256 digest identical to first run                                                  | Same three files, same content                                                                                   |
| `build-release` with version-branch mismatch | VERSION suffix does not match branch        | Non-zero exit; no output                                                                       | Output directory cleaned                                                                                         |
| `build-release` fails mid-execution          | Any                                         | Non-zero exit; no partial output remains                                                       | Output directory cleaned                                                                                         |
| `v*` tag push on `main`                      | Tag on approved remote                      | Workflow checks out tag, runs `build-release`, attaches three assets to GitHub release         | Release assets on remote                                                                                         |
| Push to `dev`                                | HEAD on approved remote                     | Workflow runs `build-release`, creates GitHub pre-release tagged `vN.N.N-rc` with three assets | Pre-release assets on remote                                                                                     |
| Workflow with `build-release` failure        | `build-release` exits non-zero              | Workflow run fails; no assets attached                                                         | No release assets                                                                                                |

## Constraints

- Builds run only on `main` and `dev`. No other branch produces release assets.
- Before merging `dev` to `main`, the `-rc` suffix must be removed from `packages/factory/VERSION`.
- No network access, external registries, or tools beyond the pinned build environment (`ubuntu-24.04`, Python 3.10, bash, OS-provided `tar` and `sha256sum`).
- Each remote builds from its local copy of the immutable tag. No artifact or digest transfer between remotes.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Demo Scenario

1. On `dev`, set VERSION to `1.0.0-rc`. Run `build-release`. Verify three files appear and `sha256sum -c SHA256SUMS` passes.
2. Run `build-release` again from the same checkout. Verify the archive digest matches the first run.
3. On `main`, set VERSION to `1.0.0`. Run `build-release`. Verify three files appear without the `-rc` suffix.
4. On `main` with VERSION `1.0.0-rc`, run `build-release`. Verify non-zero exit and no output.
5. Push tag `v1.0.0` to two approved remotes. Each workflow runs `build-release` and attaches three assets to a GitHub release. Compare archive digests — they match.

## Out of Scope

- Distribution remote setup, mirroring, tag propagation, credentials, access administration.
- Signing or GPG verification — SHA-256 digest comparison only.
- Artifact transfer between remotes.

## Stop Conditions

- Deterministic tar settings produce different digests across platforms in the build environment → report which platform and settings diverge.
- GitHub Actions workflow requires secrets or permissions not documented in the repository → report which ones.
- Code in `packages/factory/scripts/` and the feature spec disagree on the asset set contents or the reproducibility contract → report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. What is the exact bootstrap template format for `install-agent-factory`?

   > Stdlib-only Python 3.8+ script following the `init-factory` pattern. `build-release` bundles it verbatim from `packages/factory/scripts/install-agent-factory`. Resolved from interface contracts. Decided 2026-09-24.

2. What is the pinned build environment for the GitHub Actions workflow (OS, shell, tool versions)?

   > `ubuntu-24.04`, Python 3.10, bash. Pinned identically across all three distribution remotes. No additional tools — scripts are stdlib-only; `tar` and `sha256sum` come from the runner OS. Decided 2026-09-24.

3. Does `build-release` support building from a working tree or only from a clean tagged checkout?

   > Builds only from `main` (clean release `N.N.N`) or `dev` (release candidate `N.N.N-rc`). The version comes from `packages/factory/VERSION`. The script validates that the suffix matches the branch: `-rc` required on `dev`, no suffix on `main`; mismatch fails the build. Before merging to `main`, the `-rc` suffix must be removed from the VERSION file. Decided 2026-09-24.

4. What triggers the workflow and where do RC assets go?

   > Two triggers: `v*` tag push on `main` (creates a GitHub release with assets) and push to `dev` (creates a GitHub pre-release tagged `vN.N.N-rc` with assets). Pre-releases use the same URL structure so `update-factory --check` can resolve RC versions. Decided 2026-09-24.

5. How many distribution remotes and what CI system?

   > Three GitHub remotes, all using GitHub Actions. The same workflow and script run on each. The reproducibility contract ensures identical digests from the same tag across all three. Decided 2026-09-24.
