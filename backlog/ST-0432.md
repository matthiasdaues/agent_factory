# Add a story to a running ledger

**Priority:** should-have

## Goal

The User runs `dispatch add ST-0350` during a run, and `dispatch status` shows ST-0350 as `pending` in the next free wave. Today `add` takes only an open blocking finding, and `plan` only reassigns the waves of entries already in the ledger. A story that comes up during a run therefore needs a hand edit of the ledger.

## Domain Rule

- `add` accepts a story ID when `backlog/<id>.md` exists on the feature branch with `status: pending`, and no entry with that ID is in the ledger. It puts the story into the next free wave, as it does for a finding (BR-117).
- The story keeps its `deps` and `tier` from the backlog file. A dependency outside the run counts as done. A dependency inside the run that is not `done` holds the story back (BR-113).
- `add` refuses a story whose backlog file is missing or not `pending`, and an ID that is already in the ledger. It names the reason and writes nothing.
- A stop refuses `add`, as it does today (BR-091).

## Outputs

- `dispatch add` accepts a story ID.
- `dispatch-contract.md` describes `add` for a story.
- Tests for the accepted case and each refusal.

## Demo Scenario

1. A run on `feature/login` has closed wave 2. The User writes `backlog/ST-0350.md` with `status: pending`, commits it on the feature branch, and runs `dispatch add ST-0350`.
2. `dispatch status` shows ST-0350 `pending` in wave 3, and `prepare-wave 3` cuts `story/ST-0350` from the tip of the feature branch.
3. A second `dispatch add ST-0350` refuses and names the existing entry.

## Inputs

- `docs/reviews/retro-2026-11-20.md`, Start Doing: ST-0431 went into the ledger of the run-lifecycle feature by hand, with a backup and a hand move of `branch_head`.

## Evidence

- [ ] `add` of a pending story writes one entry in the next free wave with the story's `deps` and `tier`.
- [ ] `add` refuses a missing backlog file, a story that is not `pending`, and an ID already in the ledger, and the ledger stays byte for byte the same.
- [ ] A stop refuses `add` of a story.

## Out of Scope

- Changing the waves of entries already in the ledger.
- Adding a story to a run by hand, where `prepare-story` already starts each story.
