# Check that a feature is ready before the merge into dev

**Priority:** must-have

## Goal

`premerge-check dev feature/login` refuses a run that is not ready for the merge into `dev` and names the cause. It passes once every check holds, with the full test suite run on the feature branch head. The implementation agent shows the result, and the User merges.

## Domain Rule

- The check refuses while a unit of work of the run is `failed` or `blocked`, or a wave is not closed.
- It refuses while the code-review report of the whole feature or a Fagan, security or bug-hunt report of the QA agent is missing, or has a `branch_head` that is not an ancestor of the feature branch head.
- It refuses while a blocking finding is open whose `run` names the feature branch or whose `story` names a story of the run. A report or finding of another run does not count.
- It runs the full suite in a temporary worktree and removes it afterwards (BR-123).
- The feature checks run after the last wave closes: code review of the whole feature, then QA, then the merge, then reconciliation on `dev`.

## Outputs

- `premerge-check dev <feature-branch>`.
- `implementation-agent.md` runs and shows it; its line that names reconciliation first goes.
- The playbooks and `branching-policy.md` describe the order and the User's merge.
- The `bug-hunt` skill gets a report step that writes `docs/reviews/bug-hunt-YYYY-MM-DD.md` per `report-format.md`, with `run` and `branch_head` set as BR-122 says. The `outputs:` of `qa-agent.md` gain `docs/reviews/bug-hunt-*.md`, and the feature merge check looks for that name (BUG-0130).
- `check_code_review` in `premerge-check` accepts a `branch_head` only when it matches `^[0-9a-f]{40}$`, and otherwise names the report and the value in the BLOCK line (IMPL-0025).
- `files_at_head` in `premerge-check` calls `git ls-tree` with `--full-tree`, so the check finds the reports and findings at the head from any folder of the repository (IMPL-0026).
- `rules.md` drops the marker `(automated only)` from the rule that runs `premerge-check` before `git merge`, because the rule holds on both ways (BR-124). Its worktree rule says that a run by hand checks out each story branch in the primary checkout and that only `premerge-check` adds a temporary worktree (BR-123, IMPL-0034).

## Demo Scenario

1. After the last wave of `feature/login` closes, the code-review agent writes `docs/reviews/code-review-feature-login-2026-11-24.md`, and the QA agent writes its three reports.
2. The implementation agent runs `premerge-check dev feature/login`. It exits 1 and names `BUG-0090` with `run: feature/login`.
3. After BUG-0090 is `resolved`, the check exits 0, and the agent shows the output.
4. The User runs `git merge feature/login` on `dev`.

## Analysis

**What is built.** `premerge-check dev <feature-branch>` gets a feature merge mode. A non-story branch checked against `dev` is a feature merge. The mode reads the ledger `.current-work/<feature-branch>/dispatch-ledger.yaml` of the primary checkout and refuses a `failed` or `blocked` unit of work and a wave number without a wave record. It reads `docs/reviews/` at the branch head through git and refuses while one of the four feature reports lacks `run: <feature-branch>` with a full-SHA `branch_head` that is an ancestor of the head. It refuses an open blocking finding file whose `run` names the branch or whose `story` names a unit of work of the ledger. It runs `test_command` in a temporary worktree at `.current-work/<feature-branch>/premerge/feature` and removes it afterwards. The story mode keeps its checks; `check_code_review` refuses a `branch_head` that is not 40 hex characters and names the report and the value (IMPL-0025), and `files_at_head` passes `--full-tree` (IMPL-0026).

**Files.** `packages/factory/scripts/premerge-check`; the texts `implementation-agent.md`, `feature-addition.md`, `greenfield-development.md`, `branching-policy.md`, `bug-hunt/SKILL.md`, `qa-agent.md`, `rules.md`; `INDEX.yaml` by the hook; tests in `test_run_lifecycle_premerge.py` and `test_run_lifecycle_text.py`.

**Scenarios.** The Rule "User merges the feature branch into dev only after the feature merge check passes": the Outline rows 1 to 10, "A QA report of another run does not count", "The feature merge check runs the test suite in a temporary worktree", "A finding of another run does not block", "The feature checks run after the last wave closes" and "The User merges after the implementation agent shows the result". Also RL-04-LN-04 (bug-hunt report), RL-08-IT-01 and RL-08-IT-02 (IMPL-0025, IMPL-0026).

**Decisions where the contract is silent.** These become rows of the spec-feedback report.

- Without a ledger, the feature merge refuses and names the missing ledger, because it cannot show that no unit of work is `failed` or `blocked`.
- Without `test_command`, the feature merge refuses, because it cannot show that the full suite passes. The story merge keeps its skip.
- The feature merge applies the file limit only when `--max-files` is given, because a feature diff into `dev` always exceeds 20 files.

**Seams.** `premerge-check` as a subprocess on a repository in `tmp_path` with a hand-written ledger, the four reports, and finding files committed on the feature branch. The text checks read the agent, skill, playbook and rule files.

**Outside `touches`.** `tests/factory/test_finding_stop.py`: FC-14-IT-05 expects `premerge-check dev feature/...` to exit 0 in a repository without a ledger or reports. The feature merge now refuses there, so the test checks that the checks ran instead of the exit code.

**Fix iteration 1.** `check_run_state` also refuses each `pending` unit of work for which `held_back` is false, so an unstarted story of a run by hand blocks the feature merge (IMPL-0050). `is_feature_merge` resolves the target, so `refs/heads/dev` and the SHA of `dev` get the feature checks too (IMPL-0052). The handoffs of the code-review, QA and reconciliation agents and the backfeed step of `documentation-update.md` follow code review, QA, merge, then reconciliation on `dev` (IMPL-0051). `code-review-agent.md`, `reconciliation-agent.md` and `documentation-update.md` lie outside `touches`.
