# Pass --max-files to premerge-check from story count in dispatch

Modify `cmd_merge_story()` in `factory/scripts/dispatch` (around line 1263) to pass `--max-files` to `premerge-check`, scaled by the story's output count. Add a `dispatch suggest-merge-args` subcommand that reads the ledger and prints recommended `--max-files` for the final feature-to-dev merge. This prevents file-count-blowout errors on multi-story feature branches.

**Priority:** should-have

## Acceptance Criteria

- `cmd_merge_story()` passes `--max-files <N>` to the `premerge-check` invocation at line 1263, where N is derived from the story's `outputs` list length plus a reasonable margin
- A new subcommand `dispatch suggest-merge-args` exists
- `suggest-merge-args` reads the dispatch ledger, sums output file counts across stories, and prints a recommended `--max-files` value for the final feature-to-dev merge
- The default of 20 is preserved when no scaling information is available
- A test file `tests/orchestrator/test_dispatch_max_files.py` covers: single-story merge (default), multi-story merge (scaled), and the `suggest-merge-args` subcommand output

## Implementation Notes

- The 12-story test-gate-presence campaign had 74 files, far exceeding the default 20
- The scaling formula should be simple: e.g. `max(20, len(outputs) * 2)` for per-story, and sum-of-all-outputs for suggest-merge-args
- Tier is standard per dispatch-contract tier rubric: dispatch script modification with arithmetic logic

## Analysis

`traces: []` — no UC-XX or `.feature` file governs this story; it is a
self-contained change to `factory/scripts/dispatch`, so the story text
above is the acceptance spec. Retro origin:
`docs/reviews/retro-2026-08-29.md` line 40 ("the default limit of 20 files
will always block feature branches that span 12 stories and 74 files").

**Seam.** `premerge-check` already accepts `--max-files N` (default 20,
`factory/scripts/premerge-check` line 327) — no change needed there. All
the work is on the `dispatch` side:

- `_scaled_max_files(output_count: int) -> int` — new helper next to the
  existing `_story_output_globs()`, returns `max(20, output_count * 2)`.
- `cmd_merge_story()` — one line added at the existing `premerge_cmd`
  construction (originally line 1263, now a few lines later after the
  `outputs` computation): `premerge_cmd += ["--max-files", str(_scaled_max_files(len(outputs)))]`. `outputs` was already being
  computed there for `--scope-glob`; reused rather than re-parsed.
- `cmd_suggest_merge_args()` — new function alongside `cmd_merge_story()`.
  Reads the ledger, sums `len(_story_output_globs(project_root, story_id))`
  across every `ledger.stories` entry, prints
  `--max-files <max(20, total)>`. Read-only: no ledger writes, no git
  mutation.
- New `suggest-merge-args` subparser (no positional/flag args beyond the
  global `--ledger`), wired into `main()`'s dispatch table.

**Formula resolution.** The story's implementation notes give two related
but distinct formulas: per-story is explicitly `max(20, len(outputs) * 2)`;
suggest-merge-args is described only as "sum-of-all-outputs". Read literally
(no `* 2` mentioned for the aggregate case — each story's own margin already
carries through the sum), `suggest-merge-args` recommends
`max(20, sum(len(outputs) for each story))`, not `sum(...) * 2`. This is
also the more conservative reading: a 2x margin appropriate for a single
story's own diff would compound unnecessarily across many stories.

**Tests** (`tests/orchestrator/test_dispatch_max_files.py`), Chicago-school
integration style matching `tests/factory/test_dispatch_merge_integration.py`
(real temp git repos via subprocess, not mocked): a single-output story
merge asserting `(limit 20)` in premerge-check's own stdout line; a
15-output-declared story merging a 26-file diff — over the unscaled default
of 20, under the scaled `max(20, 15*2)=30` — to prove the scaling actually
reaches premerge-check and not just that small diffs happen to pass;
`suggest-merge-args` summing two stories' declared outputs (12 + 15 = 27)
and asserting `--max-files 27` in stdout; and an empty-ledger case asserting
the `--max-files 20` default holds when no scaling information exists.
