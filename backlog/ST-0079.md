# Add tests field to story template and backlog-lint

Add an optional `tests:` field to the story frontmatter schema. When present and non-empty, it lists pre-existing test files that cover the story's acceptance criteria. The developer-agent reads these as its specification and implements code to make them pass (Green, not Red-Green).

**Priority:** must-have

## Acceptance Criteria

- `factory/rulebooks/templates/story.md` documents the optional `tests:` field in the frontmatter example and description
- `backlog-lint` accepts `tests` as a valid optional field (added to `OPTIONAL_FIELDS`)
- `backlog-lint` validates that `tests:` is an array when present
- `backlog-lint` validates that listed files in `tests:` exist on disk (warning if missing, not error — tests may be written between planning and implementation)
- Existing stories without `tests:` pass validation unchanged

## Implementation Notes

The `tests:` field validation in `backlog-lint` follows the same pattern as `outputs:` validation — check type, check file existence. Use warning severity for missing test files since the timing of test creation is flexible per the proposal.
