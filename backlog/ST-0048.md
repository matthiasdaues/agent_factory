# Make feature closure and handoff evidence bounded and auditable

The token-usage feature finished with strong verification, but its test ownership
was difficult to explain, 31 absorbed worktrees remained until final cleanup,
routine phase gates caused repeated confirmation turns, and the handoff mixed
authoritative state with superseded history. The session retrospective records
the concrete evidence in
[retro-2026-07-22.md](../docs/reviews/retro-2026-07-22.md).

**Priority:** should-have

## Acceptance Criteria

- The usage-capture documentation maps every capture test file to its test layer
  and unique contract boundary; additions are expected to extend or replace an
  existing owner instead of silently duplicating coverage.
- The Git and implementation workflows remove a clean, absorbed worktree and
  safely delete its merged branch after verification, unless it remains an
  explicitly named active review base.
- The feature-addition playbook groups reversible work into one approved phase
  with stated invariants and stop conditions, while retaining separate approval
  for destructive actions, scope expansion, and unresolved design choices.
- A CLI-agnostic handoff convention separates authoritative current state from
  optional history and records local tip, upstream tip, and ahead/behind counts
  with exact SHAs.
- The retrospective action table links all confirmed improvements to this story.
- Markdown, backlog, index, and architecture validation pass.

## Analysis

These are process-documentation changes. Existing Git commands already provide
safe cleanup and branch-state evidence, so a new script would add maintenance
without strengthening enforcement. One story is sufficient because all outputs
serve the same outcome: a bounded, inspectable feature closeout.
