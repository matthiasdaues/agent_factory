# Read one vocabulary in every living Factory document

**Priority:** must-have

## Goal

No Markdown file under `packages/factory/` or `docs/spec/` uses the terms automated mode, manual mode, mechanized dispatch, invocation branch, gate-check loop, drift report or main checkout. No error message of `dispatch` or `premerge-check` says "invocation branch" or "main checkout", and `index-lint --check` passes.

## Domain Rule

- Each concept has one term, as the proposal's § Terms defines: run, orchestrated, by hand, feature branch, story branch, gate-check step, spec-feedback report, drift session, primary checkout.
- Accepted ADRs, superseded proposals and file names keep their terms.
- `counter-ids.feature` line 314 quotes `rules.md` and changes with it; `finding-classification.feature` lines 704 to 709 and 896 to 899 say "main checkout" and change to "primary checkout".

## Outputs

- The replaced terms in every living document and in the messages of `dispatch` and `premerge-check`.
- The rows of the two feature files and `test_counter_ids_text.py` in the same commit.
- `packages/factory/INDEX.yaml` regenerated.

## Demo Scenario

1. The maintainer runs `grep -rniE 'manual mode|main checkout|invocation branch|gate-check loop|drift report|automated mode|mechanized dispatch' packages/factory docs/spec --include='*.md'`. The only hits are file names such as `mechanized-dispatch.md` in links.
2. `dispatch merge-story` on a wrong checkout prints "feature branch", not "invocation branch".
3. `index-lint --check` exits 0.

## Demo Data

None.

## Boundaries

- No file is renamed.
- No accepted ADR or superseded proposal changes.
- The edits change words, never rules. A sentence whose meaning would change goes to its owner as a spec-feedback row.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.

- `docs/spec/` — living Markdown files and the two feature files named above

## Agent Stop Conditions

- A replaced term appears in a core-list artifact owned by another agent, and the replacement changes its meaning. Write a spec-feedback row for its owner.
- The proposal's term list and the glossary disagree on a term. Report both and the decision needed; do not add a workaround.

## Analysis

- **What changes.** Every living Markdown file under `packages/factory/` and `docs/spec/`, outside `docs/spec/work/`, and every `.feature` file swaps the seven replaced terms for the terms of the proposal's § Terms. The headings Workflow — Orchestrated Run, Gate-Check Step, Feature Branch, Run By Hand and Dispatch runs replace the old ones, and every link to them follows. `dispatch` says "feature branch" in its `merge-story` error, its `refresh-story` help and its docstrings.
- **What stays.** The ledger key `invocation_branch`, the worktree folder `invocation`, the mode values `automated` and `manual` and the flag `--manual`, because code reads them back. The Avoid column of the glossary and the two RL-19 Scenarios, because they name a term only to forbid it. Accepted ADRs, superseded proposals and `docs/spec/work/`.
- **Seams.** RL-19-LN-01 reads the living documents, RL-19-LN-02 reads the string constants of `dispatch`, `dispatch_lib.py` and `premerge-check`, and both live in `tests/factory/test_run_lifecycle_text.py`. RL-19-LN-03 is the `index-lint` hook. The text tests that read a renamed heading change in the same commit.
- **Concerns.** Several sentences were already stale before the rename, such as the claim that a run by hand uses no `dispatch` command. The rename keeps their meaning, and each one is a row of `docs/spec/work/spec-feedback-ST-0430.md`.
