# Require implementation-agent to state git-tracked status of target directories before dispatch

`factory/agents/implementation-agent.md` Workflow Step 1 ("Load backlog +
cut invocation branch") cuts the invocation branch from `main` and parses
ready stories, but never checks whether the directories those stories will
write to are already git-tracked. This session's dispatch (2026-07-10
retrospective, Caused Friction row 2) had to discover mid-run that
`orchestrator/` and root `backlog/` were fully untracked (0 commits),
improvise an unplanned baseline commit, and that scramble is the likely
direct cause of the worktree-isolation race recorded separately (this
repo's ST-0005).

**Priority:** should-have

## Acceptance Criteria

- `factory/agents/implementation-agent.md` Workflow Step 1 gains an explicit
  sub-step, performed before the invocation branch is cut: for every
  distinct directory implied by ready stories' declared `outputs:` globs,
  determine and state whether it is already git-tracked (at least one
  commit reachable from `main`) or untracked.
- If any target directory is untracked, the same sub-step requires creating
  an explicit baseline commit for it as a planned, reported action —
  before the invocation branch or any per-story branch/worktree is cut —
  rather than an improvised mid-dispatch fix.
- The tracked/untracked finding for each directory is included in the
  dispatcher's report to the user alongside the branch-root SHA, so a
  git-tracking gap is visible up front instead of discovered mid-run.
- The added sub-step cross-references
  `factory/rulebooks/conventions/branching-policy.md`'s "Invocation Branch"
  section as the reason a clean, known starting point matters.
- No other Workflow step is restructured.

## Analysis

Prose-only story: no application code, no test suite for this file. Edited `factory/agents/implementation-agent.md` Workflow Step 1 only.

Seam: a new sub-step inserted inside Step 1 ("Load backlog + cut invocation branch"), positioned before the invocation branch is cut. To make that ordering possible, the backlog-parsing and ready-story-identification sentences (previously written after the branch-cut sentence) moved ahead of it within the same step — the tracked/untracked check needs each ready story's declared `outputs:` globs, so parsing has to happen first. The branch-cut sentence now closes the step instead of opening it. No other Workflow step (2-5) touched; Step 3 left untouched for ST-0005.

The new sub-step states: for every distinct directory implied by ready stories' `outputs:` globs, determine and report git-tracked (>=1 commit reachable from `main`) vs. untracked; if untracked, plan and make a baseline commit before any invocation/per-story branch or worktree is cut, not as a mid-dispatch improvisation; report each finding alongside the branch-root SHA; cross-references `branching-policy.md`'s "Invocation Branch" section for the rationale (a feature branch's starting point is only clean/known if the directory it writes to is actually tracked there).

Verified against every Acceptance Criteria bullet in turn: sub-step present and before the branch cut; untracked case requires a planned baseline commit before any branch/worktree, not an improvised fix; report includes the finding alongside branch-root SHA; branching-policy.md cross-reference present; Steps 2-5 unchanged (diff confirms only Step 1's line touched).
