# Require implementation-agent to state git-tracked status of target directories before dispatch

`factory/agents/implementation-agent.md` Workflow Step 1 ("Load backlog +
cut invocation branch") cuts the invocation branch from `main` and parses
ready stories, but never checks whether the directories those stories will
write to are already git-tracked. This session's dispatch (2026-07-10
retrospective, Caused Friction row 2) had to discover mid-run that
`orchestrator/` and root `backlog/` were fully untracked (0 commits),
improvise an unplanned baseline commit, and that scramble is the likely
direct cause of the worktree-isolation race recorded separately (this
repo's ST-0005).

**Priority:** should-have

## Acceptance Criteria

- `factory/agents/implementation-agent.md` Workflow Step 1 gains an explicit
  sub-step, performed before the invocation branch is cut: for every
  distinct directory implied by ready stories' declared `outputs:` globs,
  determine and state whether it is already git-tracked (at least one
  commit reachable from `main`) or untracked.
- If any target directory is untracked, the same sub-step requires creating
  an explicit baseline commit for it as a planned, reported action —
  before the invocation branch or any per-story branch/worktree is cut —
  rather than an improvised mid-dispatch fix.
- The tracked/untracked finding for each directory is included in the
  dispatcher's report to the user alongside the branch-root SHA, so a
  git-tracking gap is visible up front instead of discovered mid-run.
- The added sub-step cross-references
  `factory/rulebooks/conventions/branching-policy.md`'s "Invocation Branch"
  section as the reason a clean, known starting point matters.
- No other Workflow step is restructured.
