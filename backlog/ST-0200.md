# Write agent-context guidance in factory documentation

Write the "Agent Context" section in `factory/docs/factory-guide.md` using the design decisions from the stakeholder grilling session (ST-0199). Update `factory/README.md` with a cross-reference. Update `factory/skills/newcomer-tour/SKILL.md` to mention agent-context as part of project setup.

**Priority:** should-have

## Demo

A new project owner opens `factory/docs/factory-guide.md` and finds an "Agent Context" section. The section explains that `docs/agent-context/` is a routing switchboard pointing at the project's own documentation -- not a copy of it. The guide explains that VIRGIL sets up the agent context concern by concern during project setup, creating only the keys the operator confirms as relevant. The guide shows how to customize the reading guide by adding project-specific concerns (e.g. `pipeline:`, `ml:`) and mapping them to index-file sections. The guide explains that `name:` is a display label and `source:` is the authority -- either inline prose or a link to a file. The guide explains what the factory reads versus what the project owner controls. The operator opens the README and finds a cross-reference to the agent-context section. A new user runs the newcomer-tour and the tour mentions agent-context as part of project setup, pointing at the factory guide for details.

## Acceptance Criteria

- `factory/docs/factory-guide.md` contains an "Agent Context" section that explains the two-layer system (reading guide over index files) using the vocabulary from the grilling session: routing switchboard, stable endpoint, functional framing.
- The factory-guide section does not mention mode (primary/index) -- it describes the natural lifecycle: early on you write values directly under `source:`; as your project documents decisions, you add file-path source pointers; the agent context grows with your project.
- The factory-guide section explains the two valid field states: valued (`name:` + `source:`) and deferred (`deferred: "reason"`). Key absence means not applicable. `null` is an error.
- The factory-guide section shows how to customize concerns in the reading guide (adding, removing, renaming concern keys) and that second-level keys are project-owned.
- The factory-guide section explains the control boundary: the factory owns top-level key schema and lint; the project owns everything below top level.
- `factory/README.md` contains a cross-reference to the agent-context section in the factory guide, replacing any stale charter references.
- `factory/skills/newcomer-tour/SKILL.md` mentions agent-context as part of project setup and points at the factory guide for details.

## Scope

**Status quo:** The factory guide has no agent-context section. The README references the charter era. The newcomer-tour does not mention agent-context. The grilling session has produced design decisions recorded in the proposal (ST-0199). The rework stories (ST-0201 through ST-0206) bring the implementation in line with those decisions.

**Adds:** An "Agent Context" section in `factory/docs/factory-guide.md`. Updated cross-reference in `factory/README.md`. Agent-context awareness in `factory/skills/newcomer-tour/SKILL.md`.

**Out of scope:** Convention and rules.md entries (already updated in implementation). Rework implementation (ST-0201 through ST-0206).

## Notes for the Implementer

Write the factory-guide section using the vocabulary and mental model from the [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05). The section should be written for a project owner who has never seen the proposal or the ADRs -- it explains "what this is and how you use it," not "how it was designed." Structure: (1) what agent-context is (one paragraph -- routing switchboard, stable endpoint), (2) how VIRGIL sets it up (concern-by-concern, functional framing), (3) the two field states and what they mean, (4) customizing the reading guide and second-level keys, (5) what you control vs. what the factory reads. The README cross-reference should be a single line pointing at the factory-guide section. The newcomer-tour update should be a brief mention during the project-setup phase of the tour.
