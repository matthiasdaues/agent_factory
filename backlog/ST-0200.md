# Write agent-context guidance in factory documentation

Write the "Agent Context" section in `factory/docs/factory-guide.md` using the design brief from the stakeholder grilling session (ST-0199). Update `factory/README.md` with a cross-reference. Update `factory/skills/newcomer-tour/SKILL.md` to mention agent-context as part of project setup.

**Priority:** should-have

## Demo

A new project owner opens `factory/docs/factory-guide.md` and finds an "Agent Context" section. The section explains that `docs/agent-context/` is a routing table pointing at the project's own documentation -- not a copy of it. The guide walks through primary mode (values written directly during greenfield setup) and index mode (pure links to source documents after conventions exist). The guide shows how to customize the reading guide by adding project-specific concerns (e.g. `pipeline:`, `ml:`) and mapping them to index-file sections. The guide explains what the factory reads versus what the project owner controls -- the factory never writes to source documents, and mode transition requires explicit operator confirmation. The operator opens the README and finds a cross-reference to the agent-context section. A new user runs the newcomer-tour and the tour mentions agent-context as part of project setup, pointing at the factory guide for details.

## Acceptance Criteria

- `factory/docs/factory-guide.md` contains an "Agent Context" section that explains the two-layer system (reading guide over index files) in terms determined by the grilling session.
- The factory-guide section explains primary mode and index mode from the user's perspective, not the implementation's.
- The factory-guide section shows how to customize concerns in the reading guide (adding, removing, renaming concern keys).
- The factory-guide section explains the control boundary: the factory reads the routing table but never writes to the user's source documents, and mode transition requires explicit operator confirmation.
- `factory/README.md` contains a cross-reference to the agent-context section in the factory guide, replacing any stale charter references.
- `factory/skills/newcomer-tour/SKILL.md` mentions agent-context as part of project setup and points at the factory guide for details.

## Scope

**Status quo:** The factory guide has no agent-context section. The README references the charter era. The newcomer-tour does not mention agent-context. The grilling session has produced a design brief with vocabulary, mental model, customization points, and control boundaries (from ST-0199). The agent-context machinery is fully implemented (EPICs 1-3).

**Adds:** An "Agent Context" section in `factory/docs/factory-guide.md`. Updated cross-reference in `factory/README.md`. Agent-context awareness in `factory/skills/newcomer-tour/SKILL.md`.

**Out of scope:** Path-only find-replace updates in agents, skills, playbooks, scripts, and hooks (EPIC 4). Convention and rules.md entries (EPIC 1). The grilling session itself (ST-0199).

## Notes for the Implementer

Write the factory-guide section using the vocabulary and mental model from the ST-0199 grilling output. The section should be written for a project owner who has never seen the proposal or the ADRs -- it explains "what this is and how you use it," not "how it was designed." Structure: (1) what agent-context is (one paragraph), (2) primary mode (greenfield), (3) index mode (mature projects), (4) customizing the reading guide, (5) what you control vs. what the factory reads. The README cross-reference should be a single line pointing at the factory-guide section. The newcomer-tour update should be a brief mention during the project-setup phase of the tour.
