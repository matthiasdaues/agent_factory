# Read story concerns in developer-agent and follow matching agent-context.md sections

Update the developer-agent to read its story's `concerns:` field and follow the matching sections in `agent-context.md` instead of using a hardcoded project-native file list. Update the implementation-agent to note that concern resolution is implicit via the include chain -- no dispatcher-side concern resolution logic is needed.

**Priority:** must-have

## Demo

A developer-agent is dispatched with a story that has `concerns: {domain: [billing], technical: [backend]}`. The developer-agent reads the `concerns:` field, opens `agent-context.md`, and follows the "billing" and "backend" sections to discover which convention files, specs, and cookbooks to read. It does not read a hardcoded file list from its agent definition for project-native knowledge. The implementation-agent dispatches the developer without any concern resolution step -- the `@docs/agent-context.md` include in the CLI orientation file makes the registry available.

## Acceptance Criteria

- The developer-agent's Analyse step reads the story's `concerns:` field.
- For each declared domain and technical concern, the developer-agent follows the matching section in `agent-context.md` to discover `Read:` paths.
- The developer-agent does not use a hardcoded project-native file list from its `inputs:` section for context navigation -- it uses concerns.
- Cross-cutting concerns are always read regardless of the `concerns:` field.
- The implementation-agent notes that concern resolution is implicit via the include chain and does not add concern resolution logic.
- When `concerns:` is absent from a story (backward compatibility), the developer-agent reads the full concern registry by judgment.

## Scope

**Status quo:** The developer-agent reads project context from `docs/agent-context/*.yaml` (per its `inputs:` list) and follows hardcoded paths for project-native knowledge. The planning-agent writes `concerns:` into story frontmatter (ST-0221 deliverables). The implementation-agent dispatches developers with story references.

**Adds:** Developer-agent reads `concerns:` field and follows matching `agent-context.md` sections. Implementation-agent notes implicit concern resolution. Backward compatibility for stories without `concerns:`.

**Out of scope:** Removal of project-native paths from the developer-agent's `inputs:` list (ST-0225 -- the sweep story handles all agent definitions together). Other agent updates (EPIC 12).
