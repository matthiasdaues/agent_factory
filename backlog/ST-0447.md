# Refuse a wrong call or wrong planted code in gate-setup-proof

The proof refuses to run when its call or its planted code could not show what the checks claim.

**Priority:** must-have

## Goal

`gate-setup-proof` exits 2, names the cause, and runs no check when its call is wrong or its planted code cannot decide the checks by coverage alone. For a wrong call it starts no measuring command. For wrong planted code it refuses before any check is judged.

## Domain Rule

- A call without `--plant`, without `--measure`, or with a measure that `docs/testing.yaml` lacks exits 2 and starts no measuring command (DEC-18).
- A plant without `base/` or `gap/`, or whose files match no `files` pattern of the measure, exits 2 before any command starts (DEC-30).
- The proof reads both planted complexities from the rows of the first commit first. A missing `proof_untested` or `proof_tested`, a complexity above the threshold, or two complexities that differ exit 2 and name the cause, so Catches CRAP can fail only by coverage (DEC-31).
- The threshold comes from `docs/testing.yaml`, and the call takes none: with threshold 2 in the file, a plant of complexity 3 exits 2 and names the threshold 2.

## Outputs

- `gate-setup-proof`: the checks of the call, the plant, and the planted complexities.
- Rows in `tests/factory/test_crap_gate_proof.py`.

## Demo Scenario

1. In the repository of ST-0446, the User runs `gate-setup-proof --measure python` without `--plant`. It exits 2, names `--plant`, and the stub's log shows no start.
2. The User removes `gap/` from the plant folder. The proof exits 2 and names `gap/`.
3. The stub reports `proof_untested` with complexity 3 and `proof_tested` with complexity 4. The proof exits 2, names both complexities, and prints no check result.
4. The User sets the threshold 2 in the working tree. The plant of complexity 3 makes the proof exit 2 and name the threshold 2.

The story seeds nothing. It uses the plant folder and the honest stub of ST-0446, and the tests vary them.
