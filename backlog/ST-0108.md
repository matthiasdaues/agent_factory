# Update greenfield and brownfield playbook terminal conditions

Update both onboarding playbooks to declare their terminal state as:
scope-map + `architecture.dsl` + arc42 prose. After either playbook
completes, all feature work enters through `feature-addition`.

**As a** playbook orchestrator,
**I want** greenfield and brownfield playbooks to terminate with a scope
map as a required deliverable,
**so that** the project is ready to receive feature work through the
`feature-addition` pipeline regardless of how it started.

**Priority:** should-have

## Acceptance Criteria

1. `greenfield-development.md` terminal condition: playbook ends when
   `docs/spec/scope-map.md` exists with all Rules from the initial
   specification marked `deferred`, `architecture.dsl` models the planned
   module structure, and arc42 prose passes architecture review.
2. `brownfield-onboarding.md` terminal condition: playbook ends when
   `docs/spec/scope-map.md` exists with Rules backfilled from the existing
   codebase (all marked `implemented`), `architecture.dsl` models the
   as-built module structure, and arc42 prose passes architecture review.
3. Both playbooks state that after completion, all feature work enters
   through `feature-addition`.
4. Greenfield terminal: no `.feature` files exist yet — those are produced
   per-slice when `feature-addition` begins.
5. Brownfield terminal: the scope-map migration skill handles the backfill
   if `derive-spec` artifacts exist; otherwise the scope map is populated
   directly from code inspection.
6. All changes pass `factory/scripts/validate`.
