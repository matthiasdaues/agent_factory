# Bring the factory hook block to the new hook template during the migration

**Priority:** must-have

## Goal

After `migrate-spec-layout` runs, each `agent_factory_hook-*` entry of the
project's `.pre-commit-config.yaml` has the `files:` value of the factory's
hook template, so `pre-commit run --files docs/spec/architecture.dsl` runs
`arch-lint`. When any step fails after the hook rewrite, the script restores
`.pre-commit-config.yaml` and every other file it changed.

## Contract

| Operation             | Input state                                                              | Outcome                                                                                                                             | Persistence                      |
| --------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `migrate-spec-layout` | Factory hook block with the old `arch-lint` pattern (see Inputs)         | Each factory hook's `files:` equals the template's value; no question asked                                                         | Content edit in the undo journal |
| `migrate-spec-layout` | Factory hook block already equal to the template                         | No edit                                                                                                                             | None                             |
| `migrate-spec-layout` | Project's own hooks in the same file                                     | Unchanged; ST-0321 lists their old paths                                                                                            | None                             |
| `migrate-spec-layout` | No `.pre-commit-config.yaml`                                             | No hook step; the rest of the run proceeds                                                                                          | None                             |
| `migrate-spec-layout` | A step fails after moves, a link rewrite, and the hook rewrite succeeded | Every move, removal, link rewrite, hook edit, and the `theme` line are undone; `git status` equals the state before the run; exit 1 | Restored                         |

## Demo Scenario

1. The maintainer copies the fixture `old-layout-hooks` (Demo Data) into
   `/tmp/demo` and runs `packages/factory/scripts/migrate-spec-layout /tmp/demo`.
2. In `/tmp/demo`, the maintainer runs
   `pre-commit run --files docs/spec/architecture.dsl`. Pre-commit runs
   `agent_factory_hook-arch-lint`.
3. On a fresh copy, the maintainer makes `docs/spec/work/` read-only after the
   first move, as the failure test does, and runs the script. It exits 1.
4. `git -C /tmp/demo status` shows no change, and `.pre-commit-config.yaml`
   holds the old `arch-lint` pattern.

## Boundaries

- Risk domain: `data_integrity`. This story extends the undo to every content
  edit of the script, so the tier is `strong` per the tier rubric.
- The script takes each `files:` value from the template
  `packages/factory/config/pre-commit-config.yaml` of the same factory tree. It
  never builds the value by path substitution, because the old paths sit inside
  regular expressions.
- Only entries whose `id` starts with `agent_factory_hook-` change. Every other
  hook and every other key of a factory hook stays as it is.
- The script keeps comments and key order of `.pre-commit-config.yaml`
  outside the changed `files:` values.
- After this story, the undo covers moves, removals, link rewrites, the hook
  block, and the `theme` line. ST-0323 and ST-0324 add their own edits to the
  same journal.

## Out of Scope

- The hook block during an update through `init-factory` and
  `merge-precommit-config` (ST-0333).
- The repository's own local hooks (ST-0343).

## Agent Stop Conditions

- The step order of the script puts every move after every content edit, so
  the feature's scenario "one planned move fails after ... the rewrite of the
  factory hook block succeeded" cannot happen. Report the order. The test then
  forces the failure on the first step that follows the hook rewrite; confirm
  that this still covers every kind of change.
- A forced failure needs a test-only switch in the script. Stop and report.
- The template and the installed project's hook block disagree on hook IDs,
  so a factory hook has no template value. Report the IDs.

## Resolve Before Implementation

None. The contract fixes the source of the `files:` values and the full undo.
