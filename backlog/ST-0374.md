# Let an agent claim an ID without waiting for a push

**Priority:** must-have

## Goal

In manual and in automated mode, an agent runs `next-id` and gets its ID without asking the human to push. `rules.md` states the claim push by `next-id` as the one exception to the human's ownership of pushes, and the guardrail hook lets `next-id` pass.

## Contract

| Item                                             | Outcome after the story                                                                 |
| ------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `rules.md` § Dispatch                            | States the claim push by `next-id` as an exception to the human's pushes in manual mode |
| `rules.md` § Git workflow                        | States the same exception for manual and automated mode                                 |
| `block-dangerous-git.sh` on `next-id ST`         | Exit `0`                                                                                |
| … on `next-id ST --remote /tmp/remote.git`       | Exit `0`                                                                                |
| … on `.agent-factory/factory/scripts/next-id ST` | Exit `0`                                                                                |

## Demo Scenario

1. In manual mode, the User asks an agent to claim a finding ID in the project of Demo Data. The agent runs `.agent-factory/factory/scripts/next-id FAGAN`. The hook lets the command pass, and the agent prints `FAGAN-1001` without asking the User to push.
2. The User reads `rules.md` § Dispatch. It names the claim push by `next-id` as the one exception to the human's pushes in manual mode.
3. The User reads § Git workflow. It states the same exception for both modes.

## Demo Data

| Item    | Value                                                                                         |
| ------- | --------------------------------------------------------------------------------------------- |
| Project | A clone whose `origin` is a local bare repository seeded with `next-id --seed 1000` (ST-0368) |

## Boundaries

- The guardrail hook `packages/factory/config/hooks/block-dangerous-git.sh` stays unchanged (DEC-16, DEC-22).
- The exception covers only the push that `next-id` makes. Every other push stays with the human in manual mode.
- The text follows ADR-0032: a push outside `next-id`, such as `git -C . push` with a hand-written claim commit, can set a line back, and then IDs repeat. So agents claim only through `next-id`. The text never says that such a push can only leave a gap (CIDP-C09).
- The story regenerates `INDEX.yaml` in the same commit, and `index-lint --check` passes.
