# Strip mode concept from capture-context and update-context

Remove all mode references from the `capture-context` and `update-context` skills and the `agent-context-composition` convention. Each field is self-describing: `name:` is display, `source:` is authority. No mode field, no transition condition, no atomic flip. See [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05).

**Priority:** must-have

## Demo

A developer reads `capture-context/SKILL.md` and finds no mention of `mode: primary` or `mode: index`. The brownfield scan (Mode 2) populates fields with `name:` and `source:` without a mode-determination step. `update-context/SKILL.md` writes fields without checking or setting mode, and has no transition procedure. The `agent-context-composition.md` convention describes field states (valued or deferred) without mode rules.

## Acceptance Criteria

- `capture-context/SKILL.md` contains no references to `mode: primary`, `mode: index`, mode determination, or mode transition.
- `capture-context` brownfield scan (Mode 2) removes Step 6 (mode determination) entirely.
- `update-context/SKILL.md` contains no references to mode checking, mode transition condition, or atomic flip.
- `agent-context-composition.md` convention removes all mode-related MUST/MUST NOT rules.
- `agent-context-composition.md` documents the two valid field states: valued (`name:` + `source:`) and deferred (`deferred: "reason"`).
- `agent-context-composition.md` documents that key absence means not applicable.
- `agent-context-composition.md` documents that `null` is an error, not a valid state.

## Scope

**Status quo:** Both skills and the convention reference mode throughout. `capture-context` has a mode-determination step. `update-context` has transition logic.

**Adds:** Mode-free versions of both skills and the convention.

**Out of scope:** Template changes (ST-0203). Reading-guide maintenance in update-context (ST-0204).
