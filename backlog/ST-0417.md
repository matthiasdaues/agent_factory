# See a dependency-rule break in the commit hook

**Priority:** must-have

## Goal

A commit that stages a Python file under the source root and breaks a rule of `docs/spec/dependency-rules.dsl` fails in the `dependency-check` hook. A project without the rules file skips the hook with a notice, and fitting leaves the hook out of such a project.

## Domain Rule

- The hook runs on the whole source root when a commit stages a `.py` file under it, because `dependency-check` reads Python imports only.
- The hook entry checks for the rules file first. Without it, the hook prints `dependency-check: no docs/spec/dependency-rules.dsl, skipped` and passes, also when `uv` is missing.
- Called directly without the rules file, `dependency-check` still exits 2.
- The metadata entry has `availability: requires-path:docs/spec/dependency-rules.dsl`, so fitting leaves the hook out of a project without the file.

## Outputs

- The hook `agent_factory_hook-dependency-check` in the Factory hook block of `pre-commit-config.yaml`.
- Its entry in `hook-metadata.yaml`, as the proposal's § Fast gates as pre-commit hooks shows.

## Demo Scenario

1. In a project with `docs/spec/dependency-rules.dsl`, the developer agent stages `src/app/domain/order.py` that imports `src/app/web/` against a rule and runs `git commit`. The hook fails and names the rule.
2. In a project without the rules file, the same commit passes and prints the skip notice.
3. Fitting a project without the rules file leaves `agent_factory_hook-dependency-check` out of its `.pre-commit-config.yaml`.

## Demo Data

None. The tests build each project in `tmp_path` with one rule that forbids `domain` to import `web`.

## Boundaries

- The script's behaviour stays; only the hook entry checks for the rules file.
- The hook never runs for a commit without a staged `.py` file under the source root.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.
