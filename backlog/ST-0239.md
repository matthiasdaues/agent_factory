# Migrate developer-agent reading cues to new story section headings

Update the developer-agent's story-reading logic so it checks for the new section headings (Goal instead of Demo/Scope, Inputs instead of Notes for the Implementer) while keeping backward compatibility with old-format stories that still use Failure scenarios and Prior Tests sections.

**Priority:** must-have

## Demo

1. Open `packages/factory/agents/developer-agent.md`.
2. Step 1 (Analyse) completeness check reads: "If the story lacks a Goal section, flag it as incomplete." The old check for "Demo or Scope" is replaced.
3. Step 2 (Agree seams) pre-existing test lookup reads: "If the story's Inputs section lists pre-existing tests..." The old reference to "Notes for the Implementer" is replaced.
4. Step 3 (Red-Green-Refactor) still contains the backward-compatibility path: "If `#### Failure scenarios` section exists" and "If `#### Prior Tests` section exists" remain unchanged.
5. A new-format story (with Goal, without Failure scenarios) is processed without the agent flagging it as incomplete.
6. An old-format story (with Demo, Scope, Failure scenarios) is processed without errors through the backward-compatibility path.

## Acceptance Criteria

- Step 1 (Analyse) completeness check uses "Goal" as the required section heading, not "Demo or Scope" (agent-ready-story-format.md § Developer-agent reading cue updates, line 69).
- Step 2 (Agree seams) pre-existing test lookup reads from the Inputs section, not "Notes for the Implementer" (agent-ready-story-format.md § Developer-agent reading cue updates, lines 70, 76).
- The `#### Failure scenarios` backward-compatibility path in Step 3 remains unchanged (agent-ready-story-format.md § Developer-agent reading cue updates, non-migration clause).
- The `#### Prior Tests` backward-compatibility path in Step 3 remains unchanged.
- New-format stories without Failure scenarios or Prior Tests sections use the `test-design-pass` frontmatter field as the control signal, same as before.
- No other developer-agent workflow steps change.

## Scope

**Status quo:** `packages/factory/agents/developer-agent.md` (v0.6.1) step 1 checks "If the story lacks a Demo or Scope section, flag it as incomplete." Step 2 reads "If the story's Notes for the Implementer section lists pre-existing tests." Step 3 has three conditional branches: Failure scenarios, Prior Tests, and the default Red-Green-Refactor cycle.

**Delivers:** Updated heading references in steps 1 and 2. Unchanged backward-compatibility paths in step 3. Both old-format and new-format stories work without errors.

**Out of scope:** Changes to the developer-agent's TDD cycle, commit conventions, or spec-feedback workflow. Migration of old stories to the new format. Changes to the Failure scenarios or Prior Tests logic.
