# Document QA-in-worktree vs installed-copy divergence in dispatch contract

Add guidance to the dispatch contract so that dispatchers and QA agents know that QA passing in a worktree does not guarantee the installed factory copy is current. Today QA runs against `packages/factory/` (source) in the worktree, but pre-commit hooks run against `factory/` (installed copy) in the main checkout. QA can pass while pre-commit fails with test failures due to a stale installed copy.

**Priority:** should-have

## Demo

1. Open `factory/rulebooks/conventions/dispatch-contract.md` and locate the new "QA-in-Worktree Divergence" subsection.
2. The subsection explains that QA in a story worktree validates against `packages/factory/` (source), while pre-commit hooks in the main checkout validate against `factory/` (installed copy).
3. The subsection states that the dispatcher should run `update-factory` on the main checkout before the final merge when the dispatch touched `packages/factory/` files.

## Acceptance Criteria

- dispatch-contract.md contains a "QA-in-Worktree Divergence" subsection documenting the gap between worktree QA and installed-copy pre-commit validation (PROP-qa-divergence)
- The subsection names the specific path pair: `packages/factory/` (source in worktree) vs `factory/` (installed copy in main checkout) (PROP-qa-divergence)
- The subsection states a concrete mitigation: run `update-factory` on the main checkout before final merge when `packages/factory/` files changed (PROP-qa-divergence)

**Status quo:** dispatch-contract.md covers ledger, waves, close ceremony (from ST-0212), and enforcement. No mention of worktree-vs-installed-copy test divergence. The dispatch close ceremony from ST-0212 is in place.
