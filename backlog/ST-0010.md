# Add --staged mode to run-tests for agent test iteration

Extend `factory/scripts/run-tests` with a `--staged` mode that runs tests on
staged files only, without requiring commit completion (BR-028, ATAM-0001 fix).
This enables agents to iterate on test development ("write test → stage test →
run test → fix test") before committing, addressing the TDD workflow friction
identified in architecture review.

The staged mode uses `git diff --staged --name-only` to determine which files
are staged, then applies the same framework-specific filters as `--changed-only`
mode but scoped to the staging area.

**Priority:** must-have

## Acceptance Criteria

- `--staged` flag implemented in `factory/scripts/run-tests`.
- Reads `git diff --staged --name-only` to get list of staged files.
- Applies framework-specific filtering to staged files:
  - pytest: filters to `test_*.py` or `*_test.py` files, passes paths to pytest
  - jest: uses jest's `--findRelatedTests` with staged file paths
  - go: derives package paths from staged `.go` files, passes to `go test`
  - cargo: derives crate paths from staged `.rs` files, passes to `cargo test`
- If no staged files: exit `2` with message "No staged files to test".
- If staged files but none are test files: exit `0` with message "No tests in
  staged files" (success, because there's nothing to validate).
- If staged test files exist: runs tests for those files only, emits JSON
  summary, exits with appropriate code (0/1/2).
- Same stderr/stdout separation as `--full` mode (test output on stderr, JSON
  on stdout).
- Usage help updated to document `--staged` mode.

## Implementation Notes

**Relationship to --changed-only:**

- `--changed-only` runs tests for files changed since last commit (fast
  pre-commit feedback)
- `--staged` runs tests for files currently staged (agent iteration before
  commit)
- Both use similar filtering logic, but different git commands to determine file
  list

**Agent workflow (addresses ATAM-0001):**

1. Agent writes test file `test_foo.py`
2. Agent stages: `git add test_foo.py`
3. Agent runs: `factory/scripts/run-tests --staged`
4. Sees immediate feedback without committing
5. Fixes test if needed
6. Re-stages and re-runs until green
7. Commits when satisfied

This unblocks TDD while preserving "tests run via factory mechanisms" principle
(not bare pytest commands).
