# Read and write the architecture model in docs/spec/

**Priority:** must-have

## Goal

The architecture agent and its skills write the Structurizr DSL to
`docs/spec/architecture.dsl` and the theme to `docs/assets/themes/`.
`module-graph-check` reads the DSL, the interface contracts, and the entity
model at their new paths and exits 0 on a consistent migrated project.

## Contract

| Operation                       | Input state                                          | Outcome                                                                                                                                          | Persistence                   |
| ------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| `scaffold-arc42`                | Empty project                                        | `docs/spec/architecture.dsl` with `theme ../assets/themes/default/theme.json`; theme in `docs/assets/themes/default/`; chapters in `docs/arc42/` | New files                     |
| `module-graph-check` (defaults) | Migrated project, model and code consistent          | Reads `docs/spec/architecture.dsl`, `docs/spec/interface-contracts.md`, `docs/spec/entity-model.md`; exit 0                                      | Report under `.current-work/` |
| `module-graph-check` (defaults) | Migrated project with a module the DSL does not name | Finding on stdout; exit 0 (the contract and the playbook read stdout)                                                                            | Report                        |

## Demo Scenario

1. In an empty fixture, the maintainer runs `scaffold-arc42`.
2. `ls docs/spec/` shows `architecture.dsl`, and `ls docs/assets/themes/default/`
   shows `theme.json`. `docs/arc42/` holds only chapters.
3. In the migrated fixture `graph-project` (Demo Data), the maintainer runs
   `packages/factory/scripts/module-graph-check`. It exits 0.

## Demo Data

`scaffold-arc42` runs in a session. `module-graph-check` is covered by a test
fixture in `tmp_path`.

| Fixture         | Content                                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `graph-project` | `docs/spec/architecture.dsl` with containers `api` and `db`; `docs/spec/interface-contracts.md` and `docs/spec/entity-model.md` matching them; `src/api/`, `src/db/` |

## Boundaries

- The DSL lives at `docs/spec/`; the theme at `docs/assets/themes/` (DEC-14).
- `module-graph-check` reads only the new paths (DEC-11). New defaults are
  recorded in `interface-contracts.md` § `module-graph-check`.
- Every old path leaves the files this story owns (CAL-G08).
- `tests/factory/test_hook_demo.py` is not part of this story; its old path is a
  docstring reference that ST-0343 fixes.
