# Add quality-gates field to story.md template

Add the `quality-gates` field to the story template and update
`backlog-lint` to validate it. The field declares which semantic gates
apply to a story's outputs and follows a three-level precedence chain:
story field > project `house-rules.md` default > Factory hardcoded default.

**As a** planning-agent,
**I want** a `quality-gates` field in each story file that the dispatcher
and `premerge-check` can read,
**so that** gate applicability is declared per-story and resolved through
a documented precedence chain.

**Priority:** must-have

## Acceptance Criteria

1. `factory/rulebooks/templates/story.md` includes a `quality-gates` field
   in its frontmatter schema with documentation of defaults and override
   semantics.
2. The field accepts a list of gate names, each corresponding to a CLI
   script under `factory/scripts/`.
3. Precedence is documented: (1) story-level field, (2) project-level
   `house-rules.md` `default_quality_gates`, (3) Factory hardcoded default
   (all three gates: `crap-score`, `mutation-analysis`, `dependency-check`).
4. Exclusion of a gate requires a justification line in the story's
   `notes:` field.
5. `factory/scripts/backlog-lint` validates the field when present: each
   entry must be a known gate name.
6. `backlog-lint` does not error when the field is absent (the Factory
   default applies).
7. All amended files pass `factory/scripts/validate`.

## Analysis

- Implement `quality-gates` as an optional frontmatter list in the story template.
- Teach `factory/scripts/backlog-lint` to accept only known gates: `crap-score`, `mutation-analysis`, and `dependency-check`.
- Require a `notes` justification when the story omits any default gate.
- Update the template docs to explain precedence and the default fallback chain.
- Files to modify: `factory/rulebooks/templates/story.md`, `factory/scripts/backlog-lint`, and this story file.
- Coverage focus: template field presence, known/unknown gate validation, absent-field acceptance, and omission-with-justification behavior.
- Concern: the current YAML parser only handles simple scalar/list frontmatter, so `notes` will be validated as a plain string.
