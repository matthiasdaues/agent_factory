# Record found and settled terms as candidates

**Priority:** must-have

## Goal

When `reverse-map`, `grilling`, `domain-modeling`, or `reconcile-spec` meets a term outside the domain-modeling agent's session, it records a row and leaves `glossary.md` unchanged. So the glossary keeps one producer.

## Contract

| Operation                                                                    | Input state                                          | Outcome                                                                    | Persistence                             |
| ---------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------- |
| `reverse-map` sweep                                                          | Code holds the class `PaymentBatch`                  | Row `PaymentBatch` with status `candidate` and Source naming the code path | `docs/spec/work/term-candidates.md`     |
| `grilling` or `domain-modeling` without the domain-modeling agent's argument | The stakeholder settles `Payout` in the session      | Row `Payout` with status `confirmed` and the settled definition            | `docs/spec/work/term-candidates.md`     |
| `grilling` or `domain-modeling` with the domain-modeling agent's argument    | The stakeholder settles `Payout` in the session      | Term written into the glossary                                             | `docs/spec/glossary.md`                 |
| `reconcile-spec`                                                             | Code uses `Payout`, the glossary says `Disbursement` | Drift row with `owner: domain-modeling-agent` and status `open`            | `docs/reviews/reconciliation-<date>.md` |
| Any of the four, without the argument                                        | —                                                    | `docs/spec/glossary.md` unchanged                                          | None                                    |

## Demo Scenario

1. The operator runs `reverse-map` on the fixture `payments-code` (Demo Data). `docs/spec/work/term-candidates.md` gains the row `PaymentBatch | payments | src/payments/batch.py | | candidate |`.
2. `docs/spec/glossary.md` is unchanged.
3. The operator runs `grilling` from Virgil, and the stakeholder settles `Payout`. The work file gains a row with status `confirmed`.

## Analysis

The story turns four skills from glossary writers into candidate writers. The Rule `Agents other than the domain-modeling agent record terms as candidates` in `docs/spec/features/core-artifact-ownership.feature` and BR-065 govern it. The row and report shapes come from `docs/spec/interface-contracts.md` § `docs/spec/work/term-candidates.md` and § Report rows.

- **The argument.** No spec names the domain-modeling agent's argument, so the skills define it as `--write-glossary`. Only the domain-modeling agent passes it. A skill run without it writes `docs/spec/work/term-candidates.md` and leaves `docs/spec/glossary.md` unchanged.
- **`reverse-map`.** The section "Seed `docs/spec/glossary.md`" becomes "Record term candidates". Each name found in the sweep becomes a row with status `candidate`, its domain area, and its code path as Source. Boundaries and Unattended mode follow.
- **`domain-modeling`.** A new section, "Where a settled term goes", sends a settled term to the glossary with `--write-glossary` and to a `confirmed` row without it. The section "Update `docs/spec/glossary.md` inline" keeps its rules and applies only with the argument, so the CAL-12 checks stay green.
- **`grilling`.** Domain-modeling mode records settled terms through `domain-modeling` and passes `--write-glossary` on only when it received the argument.
- **`reconcile-spec`.** Terminology drift becomes a report row with Artifact `docs/spec/glossary.md`, `Owner` `domain-modeling-agent`, and status `open`. The skill writes neither the glossary nor the work file.
- **Tests.** New class `TestSt0350TermsBecomeCandidates` (CAO-06-LN-01) in `tests/factory/test_core_artifact_ownership_text.py`. The ST-0337 check `test_reverse_map_seeds_term_rows_into_the_glossary` in `tests/factory/test_core_layout_references.py` asserts the old behaviour, so this story removes it.

Seams: the skill texts and the agent output declarations, read by text checks. The `.feature` Scenarios describe agent runs with a stakeholder; no Gherkin runner executes them in this repository, so the text checks own them, as the QA strategy row CAO-06-LN-01 prescribes.

Files outside `touches:` that still describe the old behaviour are listed under Spec feedback.
