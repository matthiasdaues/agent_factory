# Extend capture-context with update and scan mode for agent context maintenance

The capture-context skill gains an `--update --scan` mode so the developer can refresh `docs/agent-context.md` from the Housekeeping lane without recreating it from scratch.

**Priority:** could-have

## Goal

After this story ships, the developer selects "Update agent context" in the Housekeeping K lane. The factory runs `capture-context --update --scan`, which requires an existing `docs/agent-context.md`. The skill scans the repository, compares discovered concerns and Read paths against the existing file, presents differences, and writes confirmed changes. After writing, `concern-lint` passes. When `docs/agent-context.md` does not exist, the factory directs the developer to run `capture-context --init --scan` instead.

## Domain Rule

- `--update --scan` requires an existing `docs/agent-context.md`; if the file is absent, the skill tells the developer to use `--init --scan` and writes nothing
- The scan discovers concerns and Read paths the same way `--init --scan` does (repository scan, documentation discovery)
- Differences are computed by comparing discovered concerns and paths against the existing file content
- Differences are presented to the developer as additions, removals, and path changes
- Changes are written only after the developer confirms each difference
- `concern-lint` must pass after writing; if it fails, the skill reports the findings and stops
- The existing file structure is preserved: only confirmed additions, removals, and path updates are applied
- Concerns the developer declines to add remain absent; concerns the developer declines to remove remain present

## Demo Scenario

1. Ensure `docs/agent-context.md` exists with the current concern sections.
2. Add a new Python package to the project that introduces a backend framework.
3. Select K (Housekeeping), then "Update agent context".
4. The factory runs `capture-context --update --scan`. It discovers the new framework and proposes adding a "backend" technical concern with Read paths pointing to the new package.
5. The developer confirms the addition. The concern is added to `docs/agent-context.md`.
6. `concern-lint` runs and passes.
7. Remove `docs/agent-context.md`. Select "Update agent context" again.
8. The factory says: "docs/agent-context.md does not exist. Run capture-context --init --scan to create it."

## Out of Scope

- Modifications to the `--init` or `--init --scan` procedures
- Automated concern addition without developer confirmation
- Changes to `concern-lint` itself

## Agent Stop Conditions

- If the scan logic in `--init --scan` is too tightly coupled to the greenfield flow to reuse, ask whether to duplicate or refactor
- If the diff format for presenting changes is unclear, ask what level of detail the developer expects

## Resolve Before Implementation

1. Should the diff presentation group changes by concern category (cross-cutting, technical, domain) or list them flat?
2. When a Read path changes (same concern, different path), should the skill show a before/after diff or just the new path?
