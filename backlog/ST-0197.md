# Update factory scripts, hooks, and configuration for agent-context paths

Update all factory scripts, hooks, and configuration files to resolve context paths through the format-detection chain instead of hardcoded `docs/charter/` references. This includes `init-factory` (creates `testing.yaml` at the new path for new projects), `crap-score`, `phase`, `premerge-check`, `block-dangerous-git.sh` and `.ts` (resolve `testing.yaml` via format detection for test-command allowlisting), and FSM files.

**Priority:** must-have

## Demo

Operator triggers the `block-dangerous-git` hook in a project where `testing.yaml` lives at `docs/agent-context/testing.yaml`. The hook resolves the test command from the new location and correctly allowlists it. Operator runs `factory/scripts/phase advance` in the same project. The script resolves `testing.yaml` via format detection and evaluates the test-command gate condition. Operator repeats both operations in a legacy project with `docs/charter/testing.yaml`. Both the hook and the phase script resolve the test command from the old location -- legacy behavior is preserved. Operator runs `factory/scripts/init-factory` in a new project -- `testing.yaml` is created at `docs/agent-context/testing.yaml`.

## Acceptance Criteria

- `block-dangerous-git.sh` and `.ts` resolve `testing.yaml` via the format-detection chain and correctly allowlist the test command from either `docs/agent-context/testing.yaml` or `docs/charter/testing.yaml` (agent-context.feature Rule: Factory consumers resolve context file paths via format detection).
- `factory/scripts/phase` resolves `testing.yaml` via format detection for `charter:test_command` gate conditions (agent-context.feature Rule: testing.yaml operates as a lifecycle-exempt peer file, Scenario: testing.yaml resolution walks both paths).
- `factory/scripts/init-factory` creates `testing.yaml` at `docs/agent-context/testing.yaml` for new projects.
- `factory/scripts/crap-score` resolves `testing.yaml` via format detection.
- `factory/scripts/premerge-check` resolves context paths via format detection.
- FSM files (`greenfield-development.fsm.yml`, `bug-fix.fsm.yml`) reference `testing.yaml` through the format-detection chain, not hardcoded paths.
- No hardcoded `docs/charter/` path remains in any updated script, hook, or FSM file (legacy template files exempt).

## Scope

**Status quo:** Factory scripts and hooks reference `docs/charter/testing.yaml` with hardcoded paths. The format-detection chain and testing.yaml resolution logic exist in context-lint (from ST-0192). Scripts cannot resolve context files at the new `docs/agent-context/` location.

**Adds:** Format-detection path resolution in `init-factory`, `crap-score`, `phase`, `premerge-check`, `block-dangerous-git.sh`, and `block-dangerous-git.ts`. Updated `testing.yaml` path references in FSM files.

**Out of scope:** Agent, skill, and playbook prose updates (ST-0198). factory-guide.md and README.md (EPIC 5). Backlog story path updates (explicitly deferred per proposal). SVG diagram regeneration (explicitly deferred per proposal).

## Notes for the Implementer

Import or source the format-detection function from context-lint (ST-0192 should have made it reusable). Each script needs to replace its hardcoded `docs/charter/testing.yaml` reference with a call to the format-detection function. For bash scripts, this may be a sourced helper; for Python scripts, an imported module. The FSM files need their path references updated but do not execute the detection chain themselves -- they reference the path symbolically, and the `phase` script resolves it at runtime.
