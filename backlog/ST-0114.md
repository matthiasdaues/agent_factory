# Gitignore-style glob matching library and premerge-check --scope-glob

Implement a shared gitignore-style glob matching function in `dispatch_lib.py`
and add a `--scope-glob` flag to `premerge-check` that uses it. This shared
implementation is the single source of matching semantics for `step-guard`,
`dispatch plan` (file-overlap detection), and `premerge-check` (merge-time
scope validation). Establishing one matcher prevents semantic mismatches
between enforcement points.

**As a** dispatch operator,
**I want** glob-based file matching to use identical semantics everywhere it
appears,
**so that** a path allowed by the step guard is never denied by premerge-check
(or vice versa).

**Priority:** must-have

## Acceptance Criteria

1. A `glob_match(pattern, path)` function in `dispatch_lib.py` implements
   gitignore-style matching: `*` matches within a path segment, `**` matches
   across segments, `?` matches one non-separator character, and literal
   characters match case-sensitively.
2. `premerge-check` accepts `--scope-glob <pattern>` (repeatable) alongside the
   existing `--scope` flag. When `--scope-glob` is given, changed files are
   matched using the shared glob function instead of prefix matching.
3. The glob function is importable by `step-guard` (Phase 2) without
   modification.
4. Edge cases are handled: empty pattern, pattern with only wildcards, paths
   with special characters, zero intermediate segments for `**`.
