# dispatch prepare-story: serial chain link preparation

Implement `dispatch prepare-story <story-id>` for lazily preparing serial chain
links after their predecessor merges. The subcommand verifies the chain
predecessor is `done`, cuts the story branch from the predecessor's merge
commit, creates the worktree, runs `verify-base` against the merge commit, and
records `prepared` in the ledger.

**As a** dispatch operator,
**I want** serial chain links to be prepared automatically from their
predecessor's merge commit,
**so that** dependent stories start from the correct base without manual branch
management.

**Priority:** must-have

## Acceptance Criteria

1. `dispatch prepare-story <story-id>` exits non-zero unless the chain
   predecessor is `done`.
2. The story branch is cut from the predecessor's merge commit.
3. `verify-base` runs against the predecessor's merge commit.
4. The story is recorded as `prepared` in the ledger.
5. Re-running after success is a no-op.

## Analysis

Implemented `dispatch prepare-story <story-id>` in `dispatch_lib`/`dispatch`
(argparse wiring for `prepare-story` already existed, dispatching to
`cmd_not_implemented`; only the handler was missing).

- Looks up the story entry; if already `prepared`, returns 0 (no-op, AC5).
- Determines the chain predecessor as the story's first `deps` entry (single
  serial-chain link per story, consistent with how `prepare-wave` treats
  same-wave deps).
- Requires the predecessor's ledger status to be `done`; otherwise exits 1
  (AC1).
- Uses the predecessor's `commit_sha` (set by `verify-story`) as the "merge
  commit" the branch is cut from — the codebase has no separate `merge_sha`
  field yet (`merge-story` is not implemented in this codebase), so
  `commit_sha` is the existing field that records a verified commit on a
  story's branch and is the natural stand-in until `merge-story` lands.
- Cuts `story/<id>` from that commit, creates the worktree, verifies
  registration via `git worktree list --porcelain`, and runs `verify-base`
  with both the target and `--expect-base` set to the merge commit (AC2/AC3)
  — this is trivially satisfiable since HEAD of the new branch equals the
  merge commit itself.
- Records `branch`, `worktree`, `base_sha` and transitions the ledger entry
  to `prepared` (AC4). Uses the existing `base_sha` field rather than
  introducing a new `declared_base` field, for consistency with
  `prepare-wave`'s ledger shape.

Files modified: `factory/scripts/dispatch` (added `cmd_prepare_story`, wired
into `main`), `tests/test_dispatch_prepare_integration.py` (added three new
tests). No changes were needed in `dispatch_lib.py` — `prepared` was already
a valid `StoryState`.

Concern: the predecessor-lookup strategy (first `deps` entry) is a
simplification. If a story ever has multiple deps where only one is the
serial-chain predecessor, this would need a discriminator. No such case
exists in the current backlog/tests, so YAGNI applies.
