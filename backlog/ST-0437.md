# Refuse a measuring-command report in the wrong shape

When a measuring command reports rows the gate cannot trust, `crap-score` exits 2 and names the measure and the fault.

**Priority:** must-have

## Goal

When a measuring command writes a report that is not an array of valid rows, or reports one function twice, `crap-score` judges nothing. It exits 2 and names the measure and the missing field, the wrong value, or the duplicate function. No report is written.

## Domain Rule

- A report that is not a JSON array, a row without one of the six fields, a value that breaks `measure-output-rows.json` such as `coverage_pct` 120, and a row whose `start_line` lies above its `end_line` are in the wrong shape (BR-130).
- Two kept rows of one measure with the same `file` and `function` give exit 2 that names the file and the function. Two measures that keep the same pair give exit 2 that names the function and both measures.
- A file that holds the same qualified name twice cannot be judged, so the gate exits 2 and names the file and the name.
- A row that the `files` or `exclude` filter drops counts in no duplicate check (BR-131).

## Outputs

- `crap-score`: the shape check of each report and the two duplicate checks, run before any function is judged.
- Rows in `tests/factory/test_crap_gate_judging.py`.

## Demo Scenario

1. In the repository of ST-0436, the stub of the measure `python` writes a row of `tree_severity` without `end_line`.
2. The User runs `crap-score --base feature/login --story-id ST-0350`. It exits 2 and names `python` and `end_line`, and no new report appears.
3. The stub writes `coverage_pct` 120. The gate exits 2 and names `python` and `coverage_pct`.
4. A second measure `scripts` with `files: "packages/factory/scripts/**"` reports `tree_severity` too. The gate exits 2 and names `tree_severity`, `python` and `scripts`.
