# Install the guard-only OpenCode plugin with init-factory --cli opencode

**Priority:** must-have

## Goal

A user runs `init-factory --cli opencode` and gets `.opencode/plugins/agent-factory.ts` linked to the Factory plugin. An OpenCode agent is then refused when its `edit`, `write`, `patch`, `shell`, or `execute` call sets a human field, and a missing guard script blocks the call. The plugin holds only the guard.

## Contract

| Entry point or call                                                    | Result                                                                     |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `init-factory --cli opencode` on a project without `.opencode/`        | accepts `opencode`, creates `.opencode/plugins/`, links `agent-factory.ts` |
| OpenCode `edit`, `write`, `patch`, or `shell` that sets a human field  | blocked by `execute.before`                                                |
| `execute` whose JavaScript writes `status: waived` into a finding file | blocked; the guard checks the JavaScript as shell text                     |
| unparsable `patch` that names a guarded path                           | blocked                                                                    |
| any listed call while the guard script is missing                      | blocked                                                                    |
| a listed call that sets no human field                                 | runs                                                                       |

## Demo Scenario

1. The User runs `init-factory --cli opencode` on `/tmp/guard-demo`. `.opencode/plugins/agent-factory.ts` links to `.agent-factory/factory/config/plugins/agent-factory.ts`.
2. In OpenCode, the User asks the agent to write `stop_confirmed_by: human` into BUG-0037. The `edit` is blocked.
3. The User renames the guard script and asks for a harmless `write`. The call is blocked.

## Demo Data

Reuses `/tmp/guard-demo` and its findings from ST-0400.

## Boundaries

- The plugin holds only the guard in `execute.before`. The rest of OpenCode support belongs to [opencode-cli-integration.md](../docs/proposals/opencode-cli-integration.md), whose stories extend this file and keep the guard (gaps report, Other Gaps).
- `init-factory` adds `opencode` to its CLI table with `.opencode` as dot-dir, and changes nothing for the other four CLIs. `remove-factory` removes the link.
- The plugin defines the format in which it hands a call to the guard; the guard script accepts that format (FC-18-IT-17).
- The test runs in the `typescript` suite, and the story adds the OpenCode API stub to `envelope-resolver.mjs`. No package is added (ADR-0036).
