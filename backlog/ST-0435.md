# Measure Python code with the Factory template

A project gets a Python measuring command that reports each function's complexity and coverage in the gate's row format.

**Priority:** must-have

## Goal

A person runs the Python measuring-command template in a project without `.agent-factory/` and gets one JSON array of rows at the path in `GATE_OUTPUT`. The rows cover scripts without a file ending and name methods by their qualified name. When the template cannot measure, it exits non-zero and names the cause.

## Domain Rule

- Each row holds the six fields of `measure-output-rows.json`: `file` relative to the project root, `function`, `start_line`, `end_line`, `complexity`, `coverage_pct` (BR-130).
- A method `parse` of the class `Parser` is reported as `Parser.parse` (DEC-12).
- A Python file with a syntax error is one row with `file` and `parse_error`, the parser's message, and none of the six fields; the template then exits 0 (DEC-34).
- After a failed test run, and for a file that coverage cannot reach, the template exits non-zero and names the cause. It never writes a 0 % row for such a file (BR-130).
- The project's test command is a constant at the top of the template, which `setup-crap-score` fills in.
- The template's header names this duty, declares `radon` and coverage.py in its `uv run --script` header, and refers to nothing under `.agent-factory/`.

## Outputs

- A template under `packages/factory/skills/setup-crap-score/`, holding the `radon` and coverage.py code that `crap-score` holds today. The skill file itself comes in ST-0448.
- `tests/conftest.py` clears every `COVERAGE_*` variable for subprocesses, as it clears `GIT_*` ([QA gap 13](../docs/spec/work/crap-gate-setup-qa-strategy.md#gap-findings)).
- New `tests/factory/test_crap_gate_template.py` and rows in `tests/factory/test_crap_gate_text.py`.

## Demo Scenario

1. A temporary project without `.agent-factory/` holds `src/parser.py` with the class `Parser` and its method `parse`, the script `scripts/import-orders` without an ending, and a test that runs both.
2. The User runs the template with `GATE_OUTPUT=rows.json`. `rows.json` holds a row for `Parser.parse` and a row for `scripts/import-orders`, each with six fields.
3. The User adds a failing test and runs the template again. It exits 1 and names the failed test run, and `rows.json` holds no 0 % row.
4. The User adds `src/broken.py` with a syntax error. The template exits 0 and writes a row for `src/broken.py` with `parse_error`.
