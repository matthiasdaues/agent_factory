# Playbook step declarations for feature-addition and rules.md step-boundary update

Add the `steps:` block to `feature-addition.md` declaring each step's inputs,
outputs, and context cap. The dispatch script reads these declarations when
writing the step manifest for non-dispatch steps (dispatch steps use the story's
`outputs` and `tests` fields instead). Update `rules.md` with step-boundary
enforcement rules.

**As a** Factory playbook author,
**I want** step declarations that define what each playbook step may read and
write,
**so that** step isolation is configured declaratively and enforced mechanically,
not left to agent judgment.

**Priority:** must-have

## Acceptance Criteria

1. `feature-addition.md` includes a `steps:` block with one entry per playbook
   step.
2. Each step entry declares `inputs` (glob list), `outputs` (glob list), and
   `max_input_tokens` (integer).
3. The dispatch script reads step declarations when writing the manifest for
   non-dispatch steps.
4. `rules.md` includes step-boundary enforcement rules under a new section,
   stating that step agents must not read outside declared inputs or write
   outside declared outputs.

## Gherkin Scenario Traceability

From **Feature: Step Manifest Lifecycle** (Bounded Context 2):

- "Manifest is written with story declarations" (for dispatch steps, the
  manifest is written from story frontmatter; for playbook steps, from the
  playbook's step declarations)
