# Detect context format, validate legacy charters, and enforce testing.yaml carve-out

Implement the three-step format-detection chain in context-lint (YAML agent-context at `docs/agent-context/stack.yaml` first, legacy YAML charter at `docs/charter/tech-stack.yaml` second, legacy markdown charter at `docs/charter/tech-stack.md` third). Enforce CX-FORMAT when files exist at more than one location. Retain CH-\* finding codes for legacy markdown projects. Apply CX-PARSE-only validation to testing.yaml, exempting it from lifecycle checks and from CX-FORMAT mixed-location detection.

**Priority:** must-have

## Demo

You have only `docs/charter/*.md` files (no `docs/agent-context/`). Runs `context-lint` -- context-lint detects the legacy markdown format and reports CH-\* findings. You create `docs/agent-context/stack.yaml` alongside the existing `docs/charter/tech-stack.md` and re-runs -- context-lint reports a CX-FORMAT error for mixed locations. You remove `docs/agent-context/`, keeps the legacy charter, places `testing.yaml` at `docs/charter/testing.yaml`, and runs context-lint -- CX-PARSE validation runs against testing.yaml, but no CX-SRC, CX-MODE, or CX-NULL checks apply to it, and no CX-FORMAT error is raised for the testing.yaml location.

## Acceptance Criteria

- Format detection selects YAML agent-context mode when `docs/agent-context/stack.yaml` exists (agent-context.feature Rule: Factory consumers resolve context file paths via format detection, Scenario: Format detection selects YAML agent-context mode).
- Format detection falls back to legacy YAML charter when `docs/agent-context/stack.yaml` does not exist and `docs/charter/tech-stack.yaml` exists (agent-context.feature Rule: Factory consumers resolve context file paths via format detection, Scenario: Format detection falls back to legacy YAML charter).
- Format detection falls back to legacy markdown charter when neither YAML location exists and `docs/charter/tech-stack.md` exists (agent-context.feature Rule: Factory consumers resolve context file paths via format detection, Scenario: Format detection falls back to legacy markdown charter).
- context-lint reports a CX-FORMAT error when files exist at more than one location in the detection chain (agent-context.feature Rule: context-lint validates, Scenario: CX-FORMAT reports mixed locations).
- context-lint does not raise CX-FORMAT when testing.yaml exists at `docs/charter/testing.yaml` while index files exist at `docs/agent-context/` (agent-context.feature Rule: context-lint validates, Scenario: CX-FORMAT does not flag split testing.yaml location).
- context-lint applies CH-\* finding codes when validating legacy markdown charter projects (agent-context.feature Rule: Legacy projects continue working without migration, Scenario: Legacy markdown charter passes context-lint).
- context-lint applies CX-PARSE only to testing.yaml, skipping CX-SRC, CX-MODE, and CX-NULL checks (agent-context.feature Rule: testing.yaml operates as a lifecycle-exempt peer file, Scenario: context-lint validates testing.yaml with CX-PARSE only).
- testing.yaml resolution checks `docs/agent-context/testing.yaml` first and falls back to `docs/charter/testing.yaml` (agent-context.feature Rule: testing.yaml operates as a lifecycle-exempt peer file, Scenario: testing.yaml resolution walks both paths).
- When testing.yaml exists at both paths, `docs/agent-context/testing.yaml` takes precedence (agent-context.feature Rule: testing.yaml operates as a lifecycle-exempt peer file, Scenario: testing.yaml at new path takes precedence).

## Scope

**Status quo:** context-lint exists with ten CX-\* codes (CX-FILE through CX-GUIDE-REF) from ST-0190 and ST-0191. No format-detection chain exists. CH-\* codes from the original charter-lint are present but not integrated with the format-detection chain. testing.yaml is not given any special treatment.

**Adds:** Three-step format-detection chain logic. CX-FORMAT finding code for mixed-location detection. CH-\* fallback path for legacy markdown charters. testing.yaml carve-out logic (CX-PARSE only, independent path resolution). Contract tests in `tests/factory/test_format_detection.py` covering ACX-11. Integration tests in `tests/factory/test_context_lint_legacy.py` covering ACX-12 and `tests/factory/test_testing_yaml_resolution.py` covering ACX-13 and ACX-14. Additional test fixtures for legacy charter and mixed-location scenarios.

**Out of scope:** capture-context and update-context skills (EPICs 2, 3). Consumer path updates in scripts and hooks (EPIC 4). Automated migration tool (explicitly deferred per proposal).

## Terminology

- Format-detection chain: The three-step resolution order used to find context files: `docs/agent-context/stack.yaml` first, `docs/charter/tech-stack.yaml` second, `docs/charter/tech-stack.md` third.
- CX-FORMAT: The error finding code emitted when context files exist at more than one location in the detection chain (excluding testing.yaml).
- CH-\* codes: The existing finding codes from the original charter-lint, retained for validating legacy markdown charter projects.
- testing.yaml carve-out: The rule that testing.yaml receives CX-PARSE validation only, is exempt from lifecycle checks (CX-SRC, CX-MODE, CX-NULL), and its location does not trigger CX-FORMAT.

## Notes for the Implementer

The format-detection chain is a shared function that other consumers will reuse in EPIC 4. Implement it as a callable module or function within context-lint, not as inline logic, so that scripts and hooks can import it. Testing.yaml resolution is independent of the main format-detection chain -- it walks `docs/agent-context/testing.yaml` then `docs/charter/testing.yaml` without consulting the main chain. New tests span both contract and integration test layers under `tests/factory/`.
