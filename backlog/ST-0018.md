# Deterministic schema validator for research artifacts

Add a deterministic validator that checks a completed research artifact
against its JSON Schema. This is the first of the three-stage validation
order (schema → policy → semantic) and the load-bearing gate every later
artifact and playbook step depends on.

The validator takes an artifact file and its schema path, reports missing
required fields, wrong field types, disallowed enum values, malformed
identifiers, and bad reference or hash formats, and exits non-zero on any
violation. It has no third-party dependencies, matching the other
`factory/scripts/*-lint` tools. This story also creates the new
`factory/rulebooks/schemas/research/` category folder that the artifact
schemas will populate.

**Priority:** must-have

## Acceptance Criteria

- A new executable `factory/scripts/schema-validate` validates one artifact
  against one JSON Schema and exits non-zero when the artifact violates the
  schema.
- The validator checks required fields, field types, allowed enum values,
  identifier formats, artifact types, artifact states, timestamps,
  references, hashes, vote values, and defect levels, as listed in the
  proposal's "Schemas" section.
- The validator does **not** attempt semantic judgements (evidence support,
  source independence, test severity, claim atomicity) — those belong to
  policy and semantic stages.
- A required-tests fixture proves that an artifact missing a required field
  fails schema validation (proposal "Required Tests", item 1).
- The `factory/rulebooks/schemas/research/` directory exists and is tracked.
- The validator runs with no third-party dependencies (stdlib only), matching
  `spec-lint` and `arch-lint`.
