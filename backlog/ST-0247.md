# Convert published views to typed table, JSON, relation, and Arrow output formats

Deliver Result Adapters that project any published view as table, JSON, DuckDB relation, or PyArrow table without reimplementing accounting.

**Priority:** must-have

## Goal

After this story ships, the operator runs `usage-query canonical_session_usage --format table` and `--format json` and sees the same logical rows, field types, and null states as the published view. In Python, requesting a DuckDB relation returns the view directly. Requesting a PyArrow table returns a `pyarrow.Table` with the same schema. Requesting a Pandas or Polars conversion is rejected without changing the SQL model. Factory capture does not import DuckDB or PyArrow.

## Domain Rule

- Table and JSON outputs represent the same logical rows, field types, and null states as the published view.
- Programmatic DuckDB relation and PyArrow table outputs preserve the same schema, rows, and null states.
- PyArrow is a direct locked dependency. Factory capture does not import DuckDB or PyArrow.
- Pandas and Polars conversions are rejected without changing the SQL model.

## Demo Scenario

1. Run `usage-query canonical_session_usage --format table`. Verify the terminal output preserves all column types and null values from the published view.
2. Run `usage-query canonical_session_usage --format json`. Verify the JSON output represents the same logical rows, field types, and null states.
3. In Python, call the programmatic interface and request a DuckDB relation and a PyArrow table. Verify both preserve the published view's schema, logical rows, and null states.
4. Request a Pandas conversion. Verify the interface rejects the unsupported format.

## Outputs

- `packages/usage/src/usage/adapters.py` — module containing four Result Adapters:
  - `table`: terminal-formatted output preserving column types and null values.
  - `json`: JSON output with typed fields and explicit null representation.
  - `relation`: pass-through returning the DuckDB relation directly.
  - `arrow`: conversion to `pyarrow.Table` preserving schema, rows, and null states.
  - Format validation: rejects `pandas` and `polars` with a clear error message.
- `packages/usage/src/usage/cli.py` integrates the Result Adapters into `--format` handling. Supported values: `table` (default), `json`, `relation`, `arrow`.
- `packages/usage/pyproject.toml` gains PyArrow as a direct, version-locked dependency.
- Integration tests verify each format adapter preserves the published view's schema, rows, and null states.

## Constraints

- Result Adapters read from published DuckDB views only. They do not reimplement or modify accounting SQL.
- PyArrow must be a direct, version-locked dependency in `pyproject.toml`.
- Factory capture (`packages/factory/scripts/usage-capture`) must not import DuckDB or PyArrow.
- No format adapter changes the column order, type, nullability, or row order of the source view.
