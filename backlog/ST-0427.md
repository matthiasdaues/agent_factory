# Refuse the two destructive commands in four agent tools

**Priority:** must-have

## Goal

In Claude Code, Codex, Copilot and pi, the git guardrail refuses an agent `dispatch return-story` and `dispatch close --drop` in every form. It refuses no other `dispatch` command, and on `dev` a ledger of another branch blocks nothing. pi's guardrail holds no rule of its own.

## Domain Rule

- The script refuses both commands through any path to `dispatch`, in a chain after `&&` or `;`, and inside `bash -c`. A command built from variables still passes (OI-11).
- The script finds the run of a folder from the folder's branch: a feature branch has its ledger at `.current-work/<feature-branch>/`, and a story branch belongs to the run whose ledger lists it. A ledger of another branch never counts.
- A merge still needs `premerge-check-ok` for the current head of the branch. In an orchestrated run, the implementation agent's `merge-story` runs without a refusal.
- The other checks of the proposal's § The git guardrail stay.
- `block-dangerous-git.ts` passes each command to the script and returns its answer, as `guard-human-fields.ts` does.

## Outputs

- `block-dangerous-git.sh` gains the two refusals and the run lookup by branch; today's lookup of any ledger in the primary checkout (around line 75) goes.
- `block-dangerous-git.ts` becomes a thin wrapper.

## Demo Scenario

1. In Claude Code, an agent runs `.agent-factory/factory/scripts/dispatch return-story ST-0350`. The guardrail exits 2 and names the command.
2. `cd x && dispatch close --drop` and `bash -c 'dispatch close --drop'` are refused as well; `dispatch status` passes.
3. With `dev` checked out and `.current-work/feature/search/dispatch-ledger.yaml` present, an agent's `git commit` on `dev` passes.
4. In pi, the same `return-story` is refused, and the answer comes from the script.

## Analysis

- **What changes.** `block-dangerous-git.sh` refuses `dispatch return-story` and `dispatch close --drop` before every other check, so the refusal holds in every session. It finds `dispatch` at a command position: the start of a line, after `;`, `&`, `|`, `(` or a backtick, or after the `-c` of `bash -c`, with or without a path. A quoted mention in a `grep` or a commit message is not at a command position and passes.
- **Payloads.** The script reads Copilot's `toolArgs` as an object or a JSON string, and pi's `.input.command`. Today a Copilot `toolArgs` string gives an empty command, so the script allows every Copilot call.
- **Run lookup.** A commit on `story/<id>` in a linked worktree needs a ledger under `.current-work/` of the primary checkout whose entry has `branch: story/<id>`. Any other ledger no longer counts. A commit in the primary checkout skips the ledger check, so a ledger of another branch changes nothing on `dev`.
- **pi.** `block-dangerous-git.ts` becomes a wrapper like `guard-human-fields.ts`. It finds the script in the primary checkout through `git rev-parse --git-common-dir`, because a linked worktree has no `.agent-factory/`. It passes `{toolName, input}` to the script, returns the script's stderr as the reason on a refusal, and blocks when the script is missing.
- **Rules of today's TypeScript file.** Every rule has a counterpart in the script. The `BUG-0124` cases of `block-dangerous-git.test.ts` already exist for the script in `tests/factory/test_finding_stop.py`, so the rewritten TypeScript test drops them.
- **Files.** `block-dangerous-git.sh`, `block-dangerous-git.ts`, `__tests__/block-dangerous-git.test.ts`, `tests/factory/test_block_dangerous_git.py`. `block-dangerous-git.json` needs no change.
- **Scenarios covered.** The two Outlines for Claude Code, Codex, Copilot and pi, the refusal of no other `dispatch` command, the orchestrated `merge-story`, the merge marker, the run lookup by branch, the ledger of another branch on `dev`, and pi's wrapper. OpenCode is ST-0428.
- **Tests.** RL-16-IT-01 to RL-16-IT-07 in `tests/factory/test_block_dangerous_git.py`; RL-16-CT-01 in `block-dangerous-git.test.ts`. The existing test with a ledger of `stories: {}` changes to a ledger that lists the branch.
