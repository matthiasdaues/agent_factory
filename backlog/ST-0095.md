# Amend cross-reference-format.md with @-reference notation and validate enforcement

Document the `@`-reference notation for `.feature` files alongside the
existing markdown link convention. The `@`-ref is scoped to `.feature` files
only — it is not a general cross-reference format for prose documents.
Update the `validate` script to reject `@`-ref syntax (`# @<path>`) in
`.md` files.

**As a** Factory contributor,
**I want** a documented `@`-reference notation for `.feature` files and
mechanical enforcement that it stays out of prose documents,
**so that** code traceability in Gherkin specifications follows a single,
validated convention.

**Priority:** must-have

## Acceptance Criteria

1. `cross-reference-format.md` documents `@`-reference notation:
   `# @<path>::<Symbol>` (class or top-level function),
   `# @<path>::<Symbol>.<member>` (method or nested function),
   `# @<path>` (module-level, no specific symbol).
2. The convention states that `@`-references are scoped to `.feature` files
   only; prose documents (`.md`) continue to use full markdown links.
3. `factory/scripts/validate` rejects `@`-ref syntax (`# @<path>`) in `.md`
   files and reports a diagnostic naming the offending file and line.
4. `factory/scripts/validate` does not flag `@`-ref syntax in `.feature`
   files.
5. All amended files pass `factory/scripts/validate`.

## Implementation Notes

**Inputs:**

- `factory/rulebooks/conventions/cross-reference-format.md` — current

- `factory/scripts/validate` — current validation script
- `docs/proposals/agentic-quality-gates-and-specification-consolidation.md`
  § Design 8 (Code Traceability)

**Strategy:** two changes — (a) amend the convention file with a new
subsection for `@`-references, (b) add a check to the validate script that
greps `.md` files for `# @` patterns and errors on match.

**Tier rationale:** economy. Prose amendment plus a small regex check in an
