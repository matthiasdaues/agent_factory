# Require git worktree isolation for parallel developer-agent dispatch

`factory/rulebooks/conventions/branching-policy.md` already defines an
**Invocation Branch** (cut from `main`, tracked as branch-root) and requires
tracking a **branch-root**/**branch-head** SHA pair per dispatch. It does not
say *how* a parallel-safe set of feature branches is materialized before each
developer-agent subagent starts working — only that they are "cut" and
"spawned simultaneously." This session's `implementation-agent` dispatch
(2026-07-10 retrospective, Caused Friction row 2) hit a worktree-isolation
race: a subagent's first git command executed against the shared main
checkout instead of its own isolated working directory, chain-renaming the
main branch through four story names before being caught. No commits were
lost, but the race was real and the dispatcher had to manually verify every
branch afterward via `git worktree list` rather than trusting subagent
self-reports.

The fix is to make physical working-directory isolation — not just a branch
name — an explicit, checked precondition before any subagent's first command
runs.

**Priority:** must-have

## Acceptance Criteria

- `factory/agents/implementation-agent.md` Step 3 ("Dispatch: one feature
  branch per story") explicitly states that each developer-agent subagent
  must be spawned into its own dedicated git worktree (e.g. via the Agent
  tool's `isolation: "worktree"` parameter) so its first command never
  executes against the shared/main checkout.
- The same step requires the dispatcher to confirm, before considering a
  subagent dispatched, that the subagent's worktree exists and is checked
  out to the correct feature branch (e.g. via `git worktree list`) — not
  just trust the subagent's own report of having done so.
- `factory/rulebooks/conventions/branching-policy.md` gains a new
  subsection (alongside "Invocation Branch" and "Two SHAs Tracked Per
  Invocation") stating the worktree-isolation requirement as a rule, with a
  one-line pointer to this session's race as the motivating example,
  consistent with the file's existing "Example" section style.
- The two edits cross-reference each other the same way the file's existing
  sections cross-reference `agents/implementation-agent.md` and the other
  convention files.
- No change to `factory/agents/developer-agent.md` — worktree isolation is
  the dispatcher's responsibility, not the sub-agent's.
