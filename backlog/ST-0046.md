# Harden the git-guardrail command parser

The shared git guardrail (`factory/config/hooks/block-dangerous-git.sh`) mis-parsed two classes of command, established in the 2026-07-21 retrospective:

1. A compound line (`cd repo; git merge feat/x`) leaked `cd` as the operative merge branch, falsely blocking a valid merge.
2. The `--no-verify` block matched as a bare substring, so a benign non-git command carrying the string (for example `grep --no-verify …`) was blocked.

**Priority:** must-have

## Acceptance Criteria

- The merge-branch check isolates the `git merge …` segment before parsing, so a multi-line compound (`cd …` then `git merge <branch>`) resolves `<branch>`, never `cd`.
- `--no-verify` is blocked only in a git context; a non-git command carrying the string is allowed.
- Real bypasses stay blocked: `git commit --no-verify`, `git push --no-verify`, `git commit -m x -n`.
- Tests drive the hook directly (JSON on stdin, exit code) and cover each case, including controls (`git status` allowed, `git push --force` blocked).
