# Clean up old runs with dispatch close --orphans

**Priority:** must-have

## Goal

`dispatch close --orphans` removes each worktree that no ledger owns and whose branch is merged into `dev`, and each ledger without a branch whose stories are all `done`. It lists everything else for the User. In this repository it leaves only the `core-artifact-layout` ledger.

## Domain Rule

- It lists the worktrees and branches that belong to no ledger, removes each such worktree whose branch is merged into `dev`, and lists every other one (BR-120).
- It finds each ledger whose feature branch is gone, also inside a worktree. It removes a ledger whose stories are all `done` and lists every other one.
- It does not read `mode`, so it handles an old ledger with `mode: automated` like any other.

## Outputs

- The flag `--orphans` of `close`.
- No run of `dispatch close --orphans` in this repository. The User runs it once in the primary checkout after the feature merge into `dev` and watches it, because other sessions share the checkout. The story's tests build their ledgers and worktrees in `tmp_path`.

## Demo Scenario

1. After the merge into `dev`, the User runs `dispatch close --orphans` in this repository's primary checkout.
2. The ledgers of `brownfield-onboarding` and `bug-hunt-fixes` are gone.
3. The output lists the `core-artifact-layout` ledger with ST-0344 `blocked`, and lists each worktree whose branch is not merged, such as those of `data-model-dsl-poc`.

## Analysis

### What will be implemented

`dispatch close --orphans` in `cmd_close_orphans`, with the pure decisions in `dispatch_lib.py`. It runs in three steps.

1. It finds every file `dispatch-ledger.yaml` below `.current-work/` of the primary checkout and of each registered worktree. The walk skips each registered worktree below such a folder, because that worktree's own `.current-work/` is a root of its own. So it never reads the files of a checkout (IMPL-0046). In each skipped checkout it reads only the ledger files that git does not track, outside that checkout's `.current-work/`. `cmd_init` writes a ledger to `.current-work/<branch>/` of the checkout it runs in, and without `--feature-branch` that folder is the feature worktree itself (IMPL-0053).
   - The walk reads the folder behind a symlink, because a ledger there may own worktrees. It prints `kept link: <path>` for each link and removes no ledger behind one (IMPL-0048).
2. It sorts each ledger into one of four kinds:
   - A live ledger names a feature branch that exists. It stays, and dispatch prints nothing for it.
   - An orphaned ledger names a valid feature branch that is gone, and every story in it is `done`. Dispatch removes it, unless git tracks the file in the worktree that holds it (IMPL-0046).
   - An orphaned ledger with a story that is not `done` stays and is listed, with each such story and its state.
   - A ledger that dispatch cannot read, or that names no valid feature branch, stays and is listed.
3. Each ledger that stays owns worktrees: the worktree of each story entry, each worktree on a branch it names, and each worktree below its folder and below `.current-work/<feature-branch>/`. A ledger that dispatch cannot read owns each worktree below its folder and each worktree whose path or branch appears in its text. This fails closed.
4. Each ledger that stays also claims the folder of the primary checkout's `.current-work/` that matches its own folder below its `.current-work/` (IMPL-0045). `cmd_init` writes each ledger to `.current-work/<feature-branch>/` of the checkout it runs in, and dispatch puts every worktree of the run below `.current-work/<feature-branch>/` of the primary checkout. So this folder bounds what a ledger that yields no feature branch could own: an empty, truncated, or unreadable ledger, or one that names none. A ledger directly in a `.current-work/` claims the whole `.current-work/` of the primary checkout.

A registered worktree under `.current-work/` that no remaining ledger owns is an orphan. Dispatch removes it only when all of these hold:

- It is not the primary checkout.
- Its branch is merged into `dev`.
- It holds no ledger that stays and no other registered worktree.
- Dispatch does not run inside it.
- git does not list it as locked. The check comes before the stash, so a locked worktree keeps its changes (IMPL-0047).

Every other orphan is listed with its branch and the reason. The removal reuses the stash and removal of `close` (BR-119), so ignored files go with the worktree. The deepest worktrees go first. `--orphans` reads no `mode` and needs no `--ledger`. It is in `READ_SUBCOMMANDS` as part of `close` (BR-091).
