# Derive retrospective session input signals

Turn provider-qualified per-turn usage into deterministic session-end evidence
that retrospectives can use without controlling a live run.

**Priority:** must-have

## Acceptance Criteria

- Cache hygiene requires bounded on-demand reads, provider-qualified
  measurement, and no prose-only cache-restabilisation ritual.
- Usage capture derives cache-miss turn count and input total only for complete
  cache capability, and independently derives the BR-042 late/early ratio when
  per-turn input is complete.
- Tests cover full-cache, input-only, unavailable, no-miss zero, missing-input,
  fewer-than-two-turn, and zero-denominator outcomes.
- Stored signals include CLI, provider, and capability class and remain
  nullable exactly as BR-042 specifies.
- Retrospective guidance consumes the three signals in Caused Friction and
  never treats them as a live budget gate.

## Analysis

ST-0068 implements the session-end evidence contract in UC-11, FR-K5 through
FR-K7, and BR-041/BR-042. `factory/scripts/usage-capture` will retain the
chronological provider-reported usage of eligible top-level assistant response
turns, derive the three nullable session signals once after transcript
normalization, and persist them on `UsageRecord` with CLI, provider, and the
`full-cache`, `input-only`, or `unavailable` capability class. Provider values
remain native and are never replaced with normalized-token estimates.

The implementation modifies only the declared outputs: it adds the cache
hygiene convention, extends usage capture and retrospective guidance, adds the
focused acceptance test module, and updates this story. The tests cover the
UC-11/BR-042 numeric full-cache and input-only scenarios plus unavailable,
no-miss zero, missing-input, fewer-than-two-turn, and zero-denominator
outcomes. They also verify persisted identity/capability fields and the
retrospective-only wording. No live token budget, cache detector, transcript
unification, or prose-only cache-restabilisation ritual is introduced.

**Test seams.** The primary seam is a pure
`derive_session_usage_signals(turns, cli, provider)` function observed through
its immutable result, which isolates the deterministic BR-042 arithmetic and
nullability rules. The existing `TranscriptNormalizer.parse()` boundary
collects only eligible provider-native turn values, and the existing
`UsageRecord.to_dict()`/capture boundary proves the derived values and identity
are stored. Canonical Markdown contract tests observe the cache-hygiene and
retrospective guidance at their public file surfaces.

No ambiguity requires a new architecture decision: BR-042 already defines the
eligible turn, partition, formula, capability classes, and zero/null outcomes.
The explicit `--provider` capture context is nullable for legacy callers, just
as other unavailable provider metadata remains nullable rather than guessed.

The required new rulebook is catalogued by deterministic `index-lint`, making
`factory/INDEX.yaml` a generated output of this story. The original output list
missed that overlap with ST-0065; implementation was serialized by merging the
completed predecessor before regenerating the catalog, rather than bypassing a
hook or leaving the generated index stale.
