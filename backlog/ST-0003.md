# Write root ADR for the pre-commit monorepo-scoping pattern

Orchestrator's ST-0067 merges orchestrator's dev-scoped pre-commit hooks
into the shared root `.pre-commit-config.yaml`, because pre-commit only
auto-discovers one top-level config per repo. That merge is not a one-off
— it is a general, hard-to-reverse, generalizable pattern this repo now
needs for good: one shared root `.pre-commit-config.yaml`, with each
subproject's hooks scoped via `files:`/`exclude:` regex rather than living
in their own discovered config. Three subprojects — `factory/`,
`orchestrator/`, and the future `factory_api/` — will all need to coexist
under this one gate. This is root-scoped, whole-repo architecture, not
orchestrator-specific, so it gets the **first** entry in a new top-level
`docs/adr/` (a separate sequence from `orchestrator/docs/adr/`'s existing
0001-0019), not an entry appended to orchestrator's own ADR log.

Informed by orchestrator's ST-0067 design work but not blocked on it
landing first — the pattern is already decided; this story records it.
That relationship is tracked informally in this prose note, not as a
formal `deps:` entry, since `backlog-lint` validates `deps:` referential
integrity per-directory and ST-0067 lives in `orchestrator/backlog/`, a
separate lint pass from this repo's root `backlog/`.

**Priority:** should-have

## Acceptance Criteria

- `docs/adr/0001-precommit-monorepo-scoping.md` exists, following this
  repo's ADR format (Status / Context / Decision / Consequences).
- The Decision section states the pattern: one shared root
  `.pre-commit-config.yaml`; each subproject's hooks are namespaced
  (id suffix, e.g. `-orchestrator`) and scoped with `files:`/`exclude:`
  regex rather than relying on pre-commit's single-config discovery.
- The Decision section documents `factory/scripts/merge-precommit-config`
  as the reusable mechanism in **both** directions: factory merging its
  own hooks into an existing project's config (its current documented
  use), and any future subproject-specific `*/pre-commit-config.yaml`
  template merging into the shared root config the same way.
- The Context section names all three subprojects this pattern must scale
  to (`factory/`, `orchestrator/`, future `factory_api/`) and why a
  per-subproject discovered config doesn't work (pre-commit only
  auto-discovers one top-level file).
- The ADR cross-references
  `orchestrator/docs/adr/0003-pre-commit-as-gate-bus.md` as the prior,
  single-project decision this one generalizes.
