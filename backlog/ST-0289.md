# See a gate demonstration before choosing hooks

**Priority:** should-have

## Goal

A newcomer who accepts the gate demonstration sees a real Factory gate report a failure on a disposable fixture, corrects the fixture, sees the gate pass, and sees the fixture removed without changing the target project. Skipping the demonstration does not change recommended hook defaults.

## Contract

| Operation                      | Input state                              | Outcome                                                                            | Persistence                               |
| ------------------------------ | ---------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------- |
| Accept gate demonstration      | First-session insight complete (ST-0287) | `hook-demo` creates a disposable fixture; a real Factory gate fails on the fixture | Fixture exists in temporary location      |
| Correct the fixture            | Gate reported failure                    | Same gate passes on the corrected fixture                                          | Fixture corrected in place                |
| Gate passes                    | Corrected fixture                        | `hook-demo` removes the fixture and verifies its absence                           | Fixture removed; target project unchanged |
| Skip gate demonstration        | First-session insight complete (ST-0287) | Session proceeds to hook configuration with the same recommended defaults          | No fixture created; no file changes       |
| Interrupt during demonstration | Fixture exists                           | `hook-demo` removes the fixture on exit                                            | Fixture removed; target project unchanged |

## Boundaries

- The disposable fixture is owned by Factory, not created from project files.
- The gate is a real Factory gate, not a mock or simulation.
- The fixture and any temporary files are removed after the demonstration, whether the demonstration succeeds or is interrupted.
- The script does not require tool installation beyond what preflight already verified.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Affected Paths

- `packages/factory/scripts/` — new `hook-demo` script.
- `tests/factory/` — new `test_hook_demo.py`.

## Demo Scenario

1. Open a Factory session. The session reports project insight (ST-0287). Accept the gate demonstration.
2. The `hook-demo` script creates a disposable fixture (a temporary markdown file with a formatting error).
3. A real Factory gate (e.g., `mdformat --check`) runs against the fixture. The gate reports a failure.
4. The session shows the failure and corrects the fixture (or guides the newcomer to correct it).
5. The gate runs again. The gate passes.
6. The `hook-demo` script removes the fixture. Verify the fixture is gone and the target project is unchanged.
7. (Alternative) Skip the demonstration. Verify the recommended hook defaults are the same as without skipping.

None. The `hook-demo` script creates and removes its own disposable fixture. No existing project data is needed.

## Stop Conditions

- No Factory gate is available that produces clear pass/fail output on a single file without side effects → ask which gate to use.
- The disposable fixture must live under `.current-work/` but that directory does not exist → verify that `init-factory` creates the directory before writing the fixture.
- Code in `packages/factory/scripts/hook-demo` and the feature spec disagree on what the demonstration shows → report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. Which Factory gate should the demonstration use? `mdformat --check` is a candidate, but the choice affects fixture design.
2. Should the script correct the fixture automatically, or should the newcomer correct it manually? The feature scenario says "the corrected fixture passes" but does not specify who corrects it.
3. Where should the disposable fixture live — under `.current-work/`, under the system temp directory, or in the project root?
