# Build the scope map first in brownfield Stage 1 and let run-step reach the architecture agent

**Priority:** must-have

## Goal

A developer onboarding an existing project follows the brownfield playbook.
In Stage 1 the scope map is built before the architecture DSL, and
`run-step` offers the architecture agent once the scope map exists, without
a `.feature` file.

## Findings

- [BUG-0093](../docs/findings/BUG-0093.md): `architecture-agent` requires
  inputs the playbook produces later.

## Decisions

The stakeholder decided on 2026-10-16:

- Reorder Stage 1: 2.0 Archive; 2.1 `reverse-map` (today 2.5); 2.2 Locate
  IaC; 2.3 DSL; 2.4 Structurizr; 2.5 arch-lint; 2.6 Stage 1 exit. The archive
  stays first, because it would otherwise sweep away the new scope map.
- Add an `any_of` form for required inputs in agent definitions. An entry
  lists alternatives; it is met when one of them exists. The architecture
  agent requires a `.feature` file or `docs/spec/scope-map.md`. Greenfield
  keeps its order: there the requirements step writes the `.feature` file.

## Acceptance criteria

- The playbook lists the steps in the order above. Section headings, the
  step-transition sentences, the overview near the top, and
  `packages/factory/docs/factory-guide.md` (around line 476) agree with it.
- `eligibility.py` treats an `any_of` entry as met when one alternative
  exists, and `index-lint` accepts and renders the form into `INDEX.yaml`.
- A test shows: a project with `docs/spec/scope-map.md` and no `.feature`
  file makes the architecture agent eligible; a project with neither does
  not. Existing eligibility tests stay green.
- Each new test fails on the code before this story and passes after it.
- The full suite passes with `pre-commit run run-tests --all-files`.
- Commits name the finding, `fix: <what changed> (BUG-0093)`.
- No file outside the list below changes. Nothing under `.agent-factory/`
  changes.
