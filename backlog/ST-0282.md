# Complete a remote installation with digest verification and receipt

**Priority:** must-have

## Goal

A newcomer runs `install-agent-factory --from-remote <URL> --target <path> --version <ver>` and the bootstrap resolves an immutable versioned release URL, verifies `agent-factory.tar.gz` against `SHA256SUMS` before extraction, and presents a preview including the resolved URL and digest. A missing or mismatched digest blocks extraction and leaves the target unchanged.

## Contract

| Operation                                                   | Input state                                | Outcome                                                                                                                                    | Persistence                                                                            |
| ----------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `install-agent-factory --from-remote <URL> --version <ver>` | Valid URL, version exists on remote        | Resolves immutable versioned release URL from `<URL>/releases/<ver>/`                                                                      | No file changes until consent                                                          |
| Download and verify archive                                 | Remote archive matches `SHA256SUMS` digest | Verification passes; extraction proceeds                                                                                                   | Archive ready for installation                                                         |
| Download and verify archive                                 | Archive digest missing from `SHA256SUMS`   | Extraction refused; non-zero exit                                                                                                          | Target unchanged                                                                       |
| Download and verify archive                                 | Archive digest differs from `SHA256SUMS`   | Extraction refused; non-zero exit                                                                                                          | Target unchanged                                                                       |
| Remote installation preview                                 | Verification passed                        | Preview shows resolved URL, verified digest, source, version, target, interfaces, affected paths, instruction files, and uninstall command | No file changes                                                                        |
| Approved remote installation                                | Affirmative consent after preview          | Receipt confirms remote source, digest, and changed paths                                                                                  | Factory tree installed; `.agent-factory/install.json` records remote source and digest |

## Required Script Behavior

### Remote URL resolution

The bootstrap resolves assets from a distribution remote with this layout:

- `<base>/latest` — HTTP 302 redirect to `<base>/releases/<latest-version>/`.
- `<base>/releases/<version>/install-agent-factory`
- `<base>/releases/<version>/agent-factory.tar.gz`
- `<base>/releases/<version>/SHA256SUMS`

When `--version <ver>` is given, the bootstrap fetches directly from `<base>/releases/<ver>/`. When `--version` is omitted, the bootstrap follows the `<base>/latest` redirect to discover the current version.

### Download and verification

The bootstrap uses `urllib.request.urlopen()` (stdlib, Python 3.8+). No external dependencies.

1. Download `SHA256SUMS` from the resolved version URL.
2. Download `agent-factory.tar.gz` from the same version URL.
3. Compute SHA-256 of the downloaded archive.
4. Compare against the digest in `SHA256SUMS`. If missing or mismatched, refuse extraction, report the expected and actual digests, and exit non-zero.
5. On match, proceed to the installation preview.

Default timeout per request is 30 seconds. Network failures (connection refused, timeout, DNS resolution failure, HTTP 4xx/5xx) produce a message naming the URL and the error, then exit non-zero without changes.

### Manifest fields

The manifest records `"source_selector": "remote"`, `"resolved_source": "<resolved URL>"`, and `"archive_sha256": "<verified digest>"`. These fields join the `"source_selector"` and `"resolved_source"` keys introduced by ST-0281.

## Boundaries

- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

- No fallback to unverified extraction when the digest check fails.
- The local installation path from ST-0281 is not modified. The remote path extends the bootstrap.
- Default HTTP timeout is 30 seconds per request. No retry logic.

## Analysis

**What was implemented.** `install-agent-factory` (ST-0281) previously
stopped with "not yet implemented" for `--from-remote`. This story
replaces that stub with:

- `resolve_release_base_url(base_url, version)` — direct
  `<base>/releases/<version>/` when `--version` is given (no network
  call); otherwise a HEAD request to `<base>/latest` using a
  redirect-suppressing opener (`_NoFollowRedirect`) that reads the
  `Location` header directly, rather than letting `urlopen` transparently
  follow the redirect. The direct-follow approach was tried first and
  failed: `urlopen` requires the *final* URL to independently return 2xx,
  and a release directory has no fetchable index — the fix reads
  `Location` off the raw 302 instead.
- `download_and_verify_archive(resolved_base_url)` — downloads
  `SHA256SUMS` and `agent-factory.tar.gz` via `urllib.request.urlopen()`,
  parses the expected digest for `agent-factory.tar.gz`, computes the
  actual SHA-256, and refuses (missing or mismatched) before any
  extraction.
- `extract_archive(archive_bytes, staging_root)` — extracts into
  `staging_root/packages/factory/` (with a path-traversal guard) so the
  existing local-source convention (`source/packages/factory/...`) used by
  `validate_local_source`, `read_factory_version`, and the `init-factory`
  delegation is reused unchanged.
- `resolve_remote_source(base_url, version)` orchestrates the three
  above and returns `(error, resolved_url, digest, source_path, staging_dir)`.
- `main()` calls `resolve_remote_source` in place of the stub, before
  preflight (mirrors the local path, which validates source content
  before preflight). The staging directory is registered with `atexit`
  for cleanup.
- `show_preview` and `show_receipt` gained `resolved_url` /
  `archive_digest` parameters, shown only for the remote selector.
- `migrate_manifest_v1_to_v2` gained an `archive_sha256` parameter;
  `resolved_source` is the resolved release URL for remote installs (not
  a filesystem path).

**Files changed.**

- `packages/factory/scripts/install-agent-factory` — remote resolution,
  download, verification, extraction, preview/receipt/manifest fields.
- `tests/factory/test_install_agent_factory.py` — 5 new test classes (12
  tests) covering version resolution, digest verification, network
  failures, preview/receipt content, and manifest fields. A same-file
  local HTTP server fixture (stdlib `http.server`, real sockets on
  `127.0.0.1`) stands in for a distribution remote, so redirect-following
  and digest verification run against real HTTP rather than mocks.

**Scenarios covered** (`docs/spec/value-first-onboarding-journey.feature`,
Rule "Newcomer installs a verified Factory release with explicit
consent"): "Remote release resolves to immutable verified assets",
"Missing or mismatched digest blocks extraction", "Installation preview
names every planned effect" (remote content).

**Concerns / ambiguities — resolved.**

- The story's Inputs section cites `VFO-010` through `VFO-015` for
  remote verification rules; `validation-rules.md`'s actual numbering
  places the remote-relevant rules at `VFO-002` through `VFO-004`
  (release/source validation) and `VFO-014` (preview). This is spec
  drift from renumbering after ST-0281 — flagged in the spec-feedback
  step below. Rule content was unambiguous, so this did not block
  implementation.
- Neither the feature file nor `validation-rules.md` mandates an
  HTTPS-only scheme check in the bootstrap itself. The implementation
  does not reject non-`https://` URLs, which lets tests exercise the
  real `urllib` path against a local `http://127.0.0.1` server instead
  of mocking network calls.
- Full-suite local test collection required a one-time local
  `.agent-factory/factory/` bootstrap (`./init-factory .`) — documented
  in `README.md` as the standard way to work on this repo, and gitignored
  (no tracked-file changes). This was an environment setup gap unrelated
  to this story's code, not a spec or implementation issue.

## Resolve Before Implementation

1. What is the exact URL layout of the distribution remote? The spec describes `<base>/latest` (redirect) and `<base>/releases/<version>/` (versioned assets) — does `latest` redirect to the newest version directory, or does it contain the assets directly?

   > `<base>/latest` is an HTTP 302 redirect to `<base>/releases/<latest-version>/`. The bootstrap follows the redirect, then fetches the three assets (`install-agent-factory`, `agent-factory.tar.gz`, `SHA256SUMS`) from the resolved version directory. When `--version` is given, the bootstrap skips the redirect and goes directly to `<base>/releases/<version>/`. This matches how GitHub Releases' "latest" endpoint works across the three distribution remotes. Decided 2026-09-24.

2. How does the bootstrap download the archive and checksum? Does it use `curl`, `wget`, or another tool? What error handling is expected for network failures?

   > `urllib.request.urlopen()` — stdlib-only, no external dependencies. Network failures (connection refused, timeout, HTTP 4xx/5xx) produce a clear message naming the URL and the HTTP status, then exit non-zero without changes. Default timeout is 30 seconds. No fallback to `curl` or `wget`. Decided 2026-09-24.
