# Check glossary terms and business rules without use-case files

**Priority:** must-have

## Goal

`spec-lint` reads its terms from the tables of `docs/spec/glossary.md` and
reports a term as `GLOSS001` info when no core file outside the glossary and
`work/` uses it. It blocks an undefined business rule with `TRACE002` and exit
1, whether or not `use_cases/` exists, and it runs no check that reads
use-case files.

## Contract

| Operation                | Input state                                                                                          | Outcome                                                    | Persistence |
| ------------------------ | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ----------- |
| `spec-lint`              | "Settlement" in the glossary table; used only in `glossary.md` and `docs/spec/work/payments-gaps.md` | `GLOSS001` info for "Settlement"; exit 0                   | None        |
| `spec-lint`              | "Settlement" also used in `docs/spec/entity-model.md`                                                | No `GLOSS001` for "Settlement"                             | None        |
| `spec-lint`              | "Settlement" also used in `docs/spec/features/payments.feature` and nowhere else                     | No `GLOSS001` for "Settlement"                             | None        |
| `spec-lint`              | No `use_cases/`; `payments.feature` references `BR-099`; no core file defines it                     | `TRACE002` error; exit 1                                   | None        |
| `spec-lint`              | New layout                                                                                           | Runs `TRACE002`, `TRACE003`, `TRACE004`; no use-case check | None        |
| `spec-lint`              | Seeded error in `docs/spec/validation-rules.md`                                                      | Error finding; exit non-zero                               | None        |
| `spec-lint --gate-todos` | Open entry in `docs/spec/work/todo.md`                                                               | Todo finding names `docs/spec/work/todo.md`                | None        |

## Demo Scenario

1. The maintainer builds the fixture `new-layout-spec` (Demo Data), which has
   no `use_cases/` folder.
2. The maintainer runs `packages/factory/scripts/spec-lint`. It reports
   `GLOSS001` as info for "Settlement" and exits 0.
3. The maintainer adds `BR-099` to `docs/spec/features/payments.feature` and
   runs `spec-lint` again. It reports `TRACE002` as an error and exits 1.
4. The output names no use-case check.

## Boundaries

- `GLOSS001` stays `info`. No story adds a blocking glossary gate.
- `glossary.md` itself and every file under `docs/spec/work/` never count as a
  use. A feature file counts.
- `TRACE002` is an error with or without `use_cases/`. The downgrade to a
  warning goes.
- The four checks that read use-case files go (DEC-10). `TRACE002`, `TRACE003`,
  and `TRACE004` stay.
- `spec-lint` reads only the new paths (DEC-11). The repository's own local
  `spec-lint` hook must stay green on the old layout until ST-0343. Today
  `spec-lint` reports no `TRACE002` warning on this repository, so the change
  to an error does not block its commits.
