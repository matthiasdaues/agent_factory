# Configure pre-commit hook to run tests in changed-only mode

Add `factory/scripts/run-tests --changed-only` to the pre-commit hook
configuration so tests run automatically on every `git commit`, catching
failures immediately before the commit completes. You can bypass with
`git commit --no-verify` for WIP commits (discouraged but available).

This is the first of three hook integration points (pre-commit, pre-push, phase
advance FSM gate) where test execution becomes unavoidable.

**Priority:** must-have

## Acceptance Criteria

- `.pre-commit-config.yaml` gains a new hook entry for `run-tests --changed-only`.
- Hook runs at `pre-commit` stage (after formatting, before commit creation).
- Hook invokes: `factory/scripts/run-tests --changed-only`.
- If `run-tests` exits `0`: commit proceeds.
- If `run-tests` exits `1` or `2`: commit is blocked, stderr shows test
  failures or error message.
- You can bypass with `git commit --no-verify` (pre-commit framework's
  standard escape hatch).
- Hook configuration includes a brief comment explaining its purpose: "Fast test
  feedback — runs tests for changed files only".

## Implementation Notes

**pre-commit-config.yaml hook definition:**

```yaml
- repo: local
  hooks:
    - id: run-tests-changed
      name: Run tests (changed files only)
      entry: factory/scripts/run-tests --changed-only
      language: system
      pass_filenames: false
      always_run: true
      stages: [pre-commit]
```

**Hook ordering:**

Place after formatting hooks (mdformat, ruff format) but before lint-stage
hooks, so tests run on formatted code.

**Bypass guidance:**

The `.pre-commit-config.yaml` or root README should document: "Pre-commit tests
can be bypassed with `--no-verify` for WIP commits, but pre-push cannot —
pre-push is the 'ready to share' gate."
