# Update greenfield playbook with charter workflow

Insert charter steps into the greenfield development playbook: scaffold after vision, update during requirements and architecture, completeness sweep before planning, planning gate enforcement.

**Priority:** must-have

## Acceptance Criteria

- New Step 1.0 (before current Step 1.1): `capture-charter --init` — scaffold skeleton, fill what is known from vision
- During requirements and architecture phases: agents invoke `update-charter` as decisions emerge (documented in the phase descriptions)
- After architecture review passes: `capture-charter` completeness sweep — fill gaps, derive Epic 0
- Before planning: planning gate checks `charter-lint --planning-gate` + stakeholder approval of charter and Epic 0 together
- Planning step acknowledges Epic 0 stories exist in backlog and derives feature stories after them
- Implementation wave 1 is Epic 0 — no feature stories until wave 1 complete
- Phase Boundary Contract table updated if new transitions are introduced

## Implementation Notes

The planning gate follows the same approval pattern as backlog approval in Step 3.3. The charter completeness sweep and planning gate are between architecture review and planning — a new decision point in the flow.
