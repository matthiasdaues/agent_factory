# Name the architecture agent as owner of every dependency violation

**Priority:** must-have

## Goal

Every violation in the JSON report of `dependency-check` names the architecture agent as its owner. Whoever reads the report knows which agent fixes the rules.

## Contract

| Operation          | Input state          | Outcome                                           | Persistence |
| ------------------ | -------------------- | ------------------------------------------------- | ----------- |
| `dependency-check` | One forbidden import | The violation carries `owner: architecture-agent` | JSON report |
| `dependency-check` | No violation         | Report unchanged in shape; no owner entry         | JSON report |

## Demo Scenario

1. The architect runs `packages/factory/scripts/dependency-check` on the fixture `forbidden-import` (Demo Data).
2. The JSON report lists one violation, `payments → ledger`, with `owner: architecture-agent`.

## Analysis

**Behavior added.** `dependency-check` sets `owner: architecture-agent` on each result row with `pass_fail: fail`. A row with `pass_fail: pass` keeps its current keys and gets no `owner` key. The JSON report file and stdout carry the same rows.

**Scenario covered.** `Scenario: The dependency-check report names the architecture agent as owner` in [core-artifact-ownership.feature](../docs/spec/features/core-artifact-ownership.feature), Rule `Architecture agent owns the components and their dependency rules`. Its `@`-reference names `write_report`.

**Files.**

- `packages/factory/scripts/dependency-check`: modified. One owner constant and one serializer that `write_report` and the stdout payload share.
- `tests/factory/test_core_layout_gates.py`: modified. One test function, `test_CAO_07_IT_01_...`, on the fixture `new-layout-gates`.

**Seam.** The `dependency-check` CLI, run as a subprocess. It is observed through the JSON file and stdout. `test_core_layout_gates.py` already runs this seam for CAL-09. No new seam is needed. The owner field gets its contract test here (CAO-07-IT-01).

**Concerns.**

- The interface contract, section `dependency-check`, says each result entry carries the owner. This story's Contract says only violations carry it, and pass rows carry no owner entry. The story follows its own Contract, which the scenario also states. The gap is logged under Spec feedback.
- Demo Data names a fixture `forbidden-import`. No such fixture exists. The test adds its files to `new-layout-gates`, as the module docstring prescribes.
- A parse failure is a row with `pass_fail: fail`. It gets the owner too.

**Plan.** One vertical slice. Red: CAO-07-IT-01 fails because no row has an `owner`. Green: add the owner to fail rows only.
