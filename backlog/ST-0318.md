# Move a project's files into the new layout with their git history kept

**Priority:** must-have

## Goal

The project maintainer runs `migrate-spec-layout` on a project in the old
layout and finds every moving file of the path table at its new path. Git
records each tracked file as a rename, and `--dry-run` prints the planned
moves without changing a file. This story builds the script itself; removals,
link rewrites, the old-path listing, the hook block, and the glossary arrive
in later stories.

## Contract

| Operation                       | Input state                                                                                       | Outcome                                                                                                               | Persistence                                             |
| ------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `migrate-spec-layout`           | Tracked file at an old path of the path table                                                     | File at its new path; `git status` shows `renamed:`; exit 0                                                           | `git mv`; index and working tree                        |
| `migrate-spec-layout`           | Tracked file with an uncommitted change                                                           | File at its new path with the change; git shows a rename; exit 0                                                      | `git mv`                                                |
| `migrate-spec-layout`           | Untracked or ignored file at an old path                                                          | File at its new path with its content; nothing left at the old path; exit 0                                           | Plain file move                                         |
| `migrate-spec-layout`           | `docs/arc42/themes/default/theme.json` and a DSL that loads it                                    | Theme in `docs/assets/themes/default/`; DSL `theme` line reads `theme ../assets/themes/default/theme.json`            | Move plus one line edit in `docs/spec/architecture.dsl` |
| `migrate-spec-layout`           | Repository in a merge, a rebase, or with a held `index.lock`                                      | No file changes; the output names the state; exit 2                                                                   | None                                                    |
| `migrate-spec-layout`           | Project in the new layout; chapter 12 holds only a link line and a list; `CONTEXT-MAP.md` present | No output; exit 0                                                                                                     | None                                                    |
| `migrate-spec-layout`           | A step fails after earlier moves                                                                  | Every move of the run is undone, a plain move with a plain move; `git status` equals the state before the run; exit 1 | Restored working tree and index                         |
| `migrate-spec-layout --dry-run` | Project in the old layout                                                                         | Prints one line per planned move; exit 0                                                                              | None; `git status` unchanged                            |
| `migrate-spec-layout [TARGET]`  | `TARGET` names a project directory                                                                | The script works on `TARGET` instead of the current directory                                                         | As above, inside `TARGET`                               |

## Demo Scenario

1. The project maintainer copies the fixture `old-layout-payments` (Demo Data)
   into `/tmp/demo` and runs `git status`. It shows no change.
2. The maintainer runs `packages/factory/scripts/migrate-spec-layout --dry-run /tmp/demo`.
   The output lists `docs/spec/payments.feature -> docs/spec/features/payments.feature`
   and the other planned moves. `git -C /tmp/demo status` still shows no change.
3. The maintainer runs `packages/factory/scripts/migrate-spec-layout /tmp/demo`.
   It exits 0.
4. `git -C /tmp/demo status` shows
   `renamed: docs/spec/payments.feature -> docs/spec/features/payments.feature`
   and `renamed: docs/spec/payments-gaps.md -> docs/spec/work/payments-gaps.md`.
5. `ls /tmp/demo/docs/spec/` shows no `schemas/` folder, and
   `docs/assets/themes/default/theme.json` exists.
6. The maintainer runs the script a second time. It prints nothing and exits 0.

## Boundaries

- Risk domain: `data_integrity`. The script moves project files that a
  developer may not have committed, so the tier is `strong` per the tier rubric.
- The script never runs `git rm -f`, never deletes a file with a plain removal,
  and never commits.
- The git state of a single file never stops the migration. Only the state of
  the repository does: a merge, a rebase, or a held index lock.
- The script reads only the new layout's target paths as "done". It never keeps
  a second code path for an old layout reader (DEC-11).
- `CONTEXT-MAP.md` and a routing-only `CONTEXT.md` never count as work.
- A failed run leaves `git status` as it was before the run.
- Source edits go to `packages/factory/scripts/`, never to `.agent-factory/`.
- Every new test carries `@pytest.mark.spec("CAL-03")` or the Rule identifier
  it covers, and the `container` marker where it needs Docker.
- The script needs no test-only flag or environment variable. Tests force a
  failure through the file system, for example a read-only target folder.
- Pre-alpha: no handling for updaters before `v1.1.0-rc`.

  and maps `docs/spec/scope-map.md` to itself (CAL-03-CT-01).

## Agent Stop Conditions

- `structurizr validate` rejects `theme ../assets/themes/default/theme.json`
  (CAL-G06). Stop and report the error text; the stakeholder decides.
- Docker is not available, so the container test cannot run once by hand.
  Report it; do not mark CAL-03-IT-02 as passing.
- The path table in the proposal and the Scenario Outline in the feature file
  disagree on a row. Report both files and the row; do not pick one.
- A failure partway cannot be forced without a test-only switch in the script.
  Report the step order and the seam you need.
- The repository's own pre-commit hooks fail on this story's commit for a
  reason outside this story's files.

## Resolve Before Implementation

1. CAL-G10, project directory argument. Default: an optional positional
   `TARGET`, defaulting to the current directory, as in `migrate-layout`.
   `init-factory` passes its `--target` value (ST-0330).
2. CAL-G12, exit codes. Default: `0` on success, on no work, and for
   `--dry-run`; `1` on a failure partway after the undo; `2` on a refusal before
   the first change (busy repository, bad arguments). Record the values in
   `interface-contracts.md`.
