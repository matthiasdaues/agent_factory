# Keep every Markdown link working after the move

**Priority:** must-have

## Goal

After `migrate-spec-layout` runs, `link-check` passes on every Markdown file
under `docs/`. A link to an old path points at the new path, a relative link
inside a moved file resolves from its new folder, and a link to a removed file
becomes its link text in a code span. `--dry-run` prints each planned link
rewrite next to the planned moves.

## Contract

| Operation                       | Input state                                                                                                             | Outcome                                                                                                     | Persistence                      |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `migrate-spec-layout`           | `docs/arc42/09_architecture_decisions.md` links to `../spec/supplementary_specs/entity-model.md`                        | Link reads `../spec/entity-model.md`                                                                        | Content edit in the undo journal |
| `migrate-spec-layout`           | `docs/spec/todo.md` links to `../reviews/retro.md`                                                                      | `docs/spec/work/todo.md` links to `../../reviews/retro.md`                                                  | Content edit in the undo journal |
| `migrate-spec-layout`           | `docs/spec/scope-map.md` links to `../~archive/spec/use_cases/UC-04-dispatch-an-agent-via-trigger.md` with text `UC-04` | The scope map shows `` `UC-04` `` in place of the link                                                      | Content edit in the undo journal |
| `migrate-spec-layout`           | A link with an anchor, such as `../spec/supplementary_specs/state-machines.md#dispatch`                                 | Anchor kept: `../spec/state-machines.md#dispatch`                                                           | Content edit                     |
| `migrate-spec-layout`           | An external link, or a link to a path outside the path table                                                            | Unchanged                                                                                                   | None                             |
| `migrate-spec-layout --dry-run` | Old-layout project                                                                                                      | Prints each planned move, removal, and link rewrite (file, old target, new target); changes nothing; exit 0 | None                             |
| `migrate-spec-layout`           | A step fails after a link rewrite                                                                                       | The rewritten file has its old content; exit 1                                                              | Restored                         |

## Demo Scenario

1. The maintainer copies the fixture `old-layout-links` (Demo Data) into
   `/tmp/demo` and runs `packages/factory/scripts/migrate-spec-layout --dry-run /tmp/demo`.
2. The output contains the rewrite of `../spec/supplementary_specs/entity-model.md`
   in `docs/arc42/09_architecture_decisions.md` to `../spec/entity-model.md`.
   `git -C /tmp/demo status` shows no change.
3. The maintainer runs the script without `--dry-run`. It exits 0.
4. The maintainer runs `packages/factory/scripts/link-check` on every Markdown
   file under `/tmp/demo/docs/` with `find /tmp/demo/docs -name '*.md'`. It passes.
5. `docs/spec/scope-map.md` shows `` `UC-04` `` where the link was.

## Boundaries

- The script rewrites only Markdown links. Old paths in other text stay and are
  ST-0321's listing.
- Every content edit is recorded in the undo journal before it is written.
- The rewrite never changes the link text, except that a link to a removed file
  becomes its link text in a code span.
- No old-layout fallback: after the run, no rewritten link points at an old path.

## Out of Scope

- The old-path listing for non-Markdown files (ST-0321).
- Links to `CONTEXT.md` or `CONTEXT-MAP.md`. The fold rewrites them (ST-0328).
- Reference-style Markdown links (`[text][id]` with a `[id]: path` line) unless
  `link-check` checks them today.

## Agent Stop Conditions

- `link-check` and the proposal disagree on how a relative link resolves.
  Report the case; do not change `link-check`.
- The scan set needed for `link-check` to pass reaches files outside the
  project's working tree. Report the path.
