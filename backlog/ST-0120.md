# dispatch verify-story: SHA verification without state mutation

Implement `dispatch verify-story <story-id> --sha <sha>`. The subcommand
verifies the reported 40-character commit SHA exists (`git cat-file -e`) and
is on the story's branch (`git branch --contains`). On success, records the
verified SHA in the ledger. The command must not modify the working tree, index,
or HEAD.

**As a** dispatch operator,
**I want** SHA verification to confirm the subagent's reported commit is real
and on the correct branch,
**so that** merge-story operates on a verified commit, not a fabricated or
misattributed one.

**Priority:** must-have

## Acceptance Criteria

1. `dispatch verify-story <story-id> --sha <sha>` exits zero when the SHA
   exists and is on the story's branch. The verified SHA is recorded in the
   ledger.
2. A non-existent SHA is rejected (non-zero exit).
3. A SHA that exists but is on the wrong branch is rejected (non-zero exit).
4. The command leaves the index and working tree unchanged (no `git add`,
   `git checkout`, or `git reset`).
5. `git status --porcelain` produces identical output before and after the
   command.
