# Extend reconciliation agent with test traceability audit step

The reconciliation agent gains a test traceability audit: verify that every story's `tests:` field matches its actual test files, backfill missing entries, and file `RECON` findings for contracts with ownership assignments but no test coverage.

**Priority:** must-have

## Demo

The reconciliation agent runs post-QA on a completed feature. It reads each story's `tests:` field and checks whether the listed test files exist on disk. Story ST-0228 lists `tests/test_widget.py` but the file was renamed to `tests/test_widget_v2.py` during implementation — the agent backfills the correct path and files a `RECON-TEST-PATH` finding noting the correction. Story ST-0229 has an ownership assignment for contract "validation rule" in `epics.md` but no corresponding test in the owning story's `tests:` field — the agent files a `RECON-TEST-COVERAGE` finding. All corrections and findings appear in `docs/findings/RECON-*.md` following the standard finding format.

## Acceptance Criteria

- The reconciliation agent at `factory/agents/reconciliation-agent.md` includes a test traceability audit step that runs alongside its existing `@`-reference backfill (completion criterion 10).
- The audit verifies that every story's `tests:` field lists test files that exist on disk (completion criterion 10).
- The audit backfills missing `tests:` entries where the developer omitted them but test files matching the story's scope exist (completion criterion 10).
- The audit files `RECON` findings for contracts with ownership assignments in `epics.md` but no corresponding test coverage in the owning story (completion criterion 10).
- Test references stay in story files (`backlog/ST-NNNN.md`), not in `.feature` files — consistent with the cross-reference-format convention.

## Scope

**Status quo:** The reconciliation agent at `packages/factory/agents/reconciliation-agent.md` (v0.4.0 area) runs `reconcile-spec` and `model-structurizr-slice` skills. It backfills `@`-references in `.feature` files and populates the scope map's `Feature Link` column. It files `RECON-*` findings for code defects, missing `@`-refs, and scope-map drift. It does not audit test traceability. ST-0229 delivers the `tests:` field in story files; the testability-probe (ST-0226) writes ownership assignments into `epics.md`.

**Delivers:** A new audit step in the reconciliation agent (or its `reconcile-spec` skill) that verifies `tests:` fields, backfills missing entries, and files RECON findings for ownership-without-coverage gaps.

**Out of scope:** QA agent criteria (ST-0230). Gate script changes (ST-0232). Modifying the reconciliation agent's existing `@`-reference or scope-map logic.

## Notes for the Implementer

The reconciliation agent's skill `reconcile-spec` at `packages/factory/skills/reconcile-spec/SKILL.md` is the likely home for the new audit step. The test traceability audit reads `epics.md` ownership tables (produced by the testability-probe), then reads each story's `tests:` field and checks file existence. The finding format follows `factory/rulebooks/conventions/finding-format.md`. Consider adding a `RECON-TEST-PATH` code for path mismatches and a `RECON-TEST-COVERAGE` code for ownership-without-coverage gaps.
