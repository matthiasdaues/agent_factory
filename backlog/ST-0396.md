# Run finding-lint through validate and the pre-commit hook

**Priority:** must-have

## Goal

The user runs `validate` or `git commit` and gets the result of `finding-lint`: a commit with a broken finding fails, and the user's `validate` run lists the gate. A project installed earlier gets the hook from `update-factory`, and an agent cannot skip it with `--no-verify`. A committed lowering of a `critical` finding fails at the hook, so the stop holds.

## Contract

| Entry point                                         | Input                                                                                            | Outcome                                                                                           |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `validate`                                          | `docs/findings/` exists                                                                          | runs `finding-lint` without `--staged`; the row shows pass or fail                                |
| `git commit` with the hook                          | staged finding whose severity does not match its basis                                           | the hook `agent_factory_hook-finding-lint` runs `finding-lint --staged`, and the commit exits `1` |
| `git commit` with the hook                          | `HEAD` holds BUG-0037 `critical`, `open`; the agent stages it at `major` without override fields | commit exits `1`; `dispatch` and `premerge-check` still stop                                      |
| `update-factory` on an earlier install              | hook block without `agent_factory_hook-finding-lint`                                             | the block gets the hook                                                                           |
| agent shell `git commit -m fix --no-verify` or `-n` | any                                                                                              | `block-dangerous-git.sh` denies it                                                                |

The hook has `files: ^docs/findings/` and `pass_filenames: false`. Its `hook-metadata.yaml` entry has `trade_off: none` and `availability: always`, so fitting includes it without asking.

## Demo Scenario

1. The User installs the Factory from this branch into `/tmp/hook-demo` with `init-factory --cli claude` and runs the fitting's hook step. `.pre-commit-config.yaml` holds `agent_factory_hook-finding-lint`.
2. The User stages `docs/findings/FAGAN-0042.md` with `severity: minor` and `fails_purpose: true` and runs `git commit`. The hook fails, and the commit exits `1`.
3. The User asks the agent to run `validate`. Its table lists `finding-lint` with FAIL; after the fix, PASS.
4. The User commits BUG-0037 at `critical`, then stages it at `major`. `git commit` exits `1`, and `dispatch prepare-wave 1` still prints the stop notice.
