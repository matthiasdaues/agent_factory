# Complete a first task in a repository with commits

**Priority:** must-have

## Goal

A newcomer approves a first-task preview and receives a detached worktree sandbox from HEAD at `.current-work/onboarding-spike/<session-id>/`. The poc-spike playbook runs inside the sandbox and produces an inspectable result within ten minutes of session start. The newcomer then discards the sandbox, retains selected artifacts to `docs/spikes/`, or begins real work through a normal workstream.

## Contract

| Operation                              | Input state                                     | Outcome                                                                          | Persistence                                                     |
| -------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Approve first-task preview             | Repository with HEAD, installation complete     | Detached worktree created; no branch or commit added; active-tree changes absent | `.current-work/onboarding-spike/<session-id>/` exists           |
| Blank or declined approval             | Repository with HEAD, installation complete     | No sandbox created                                                               | No new directories                                              |
| poc-spike playbook runs in sandbox     | Sandbox exists                                  | Inspectable result displayed with check results and removal instructions         | Result files inside sandbox path                                |
| Newcomer chooses discard               | Sandbox with completed task                     | Worktree removed; path verified absent                                           | `.current-work/onboarding-spike/<session-id>/` no longer exists |
| Newcomer chooses retain with selection | Sandbox with completed task, artifacts selected | Only confirmed artifacts copied; sandbox not promoted                            | Selected artifacts at `docs/spikes/<name>/`                     |
| Newcomer chooses production handoff    | Sandbox with completed task                     | Normal workstream created or selected; sandbox not promoted                      | Workstream active; sandbox does not become production work      |
| Complete journey on ready host         | Ready host, one detected interface              | Inspectable result within ten minutes of session start                           | No more than five user decisions after installation approval    |

## Required Script Behavior

### Sandbox creation

The sandbox module creates a detached worktree at `.current-work/onboarding-spike/<uuid4>/` from HEAD using `git worktree add --detach`. The session-id is a UUID4 string generated by `uuid.uuid4()`, consistent with all other init-factory identifiers. The worktree creates no branch and no commit. Uncommitted changes from the active working tree do not appear in the sandbox.

### First-task preview

Before creating the sandbox, Virgil presents a preview with five fields:

- **Goal**: what the poc-spike playbook produces.
- **Expected duration**: the fixed string "approximately 5–10 minutes". No measured baseline exists.
- **Expected artifacts**: files the playbook creates inside the sandbox.
- **Required decisions**: the number of decisions the newcomer will make.
- **Cleanup method**: how the sandbox is removed after the task.

Blank or declined approval skips sandbox creation. No directory is created.

### Task execution

The poc-spike playbook runs inside the sandbox directory. On completion the session displays the result, which checks ran, and how to remove the sandbox.

### Outcome selection

After the task completes the session offers three outcomes:

1. **Discard**: `git worktree remove` on the sandbox path. Verify the directory no longer exists.
2. **Retain**: the newcomer selects individual artifacts. Only confirmed artifacts are copied to `docs/spikes/<name>/`. The sandbox is removed after copying. The sandbox is not promoted to a branch.
3. **Production handoff**: the session asks whether to create a new workstream or select an existing one. Both paths delegate to the existing workstream mechanism. The sandbox is not promoted to production work.

### Timing constraint

The full journey from session start to inspectable result completes within ten minutes on a ready host. No more than five user decisions occur after installation approval.

## Boundaries

- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.
- The poc-spike playbook is invoked without modification.
- The sandbox creates no branch or commit.
- Production handoff delegates to the existing workstream mechanism without reimplementing it.
- The sandbox is a detached worktree, not a regular branch checkout.

## Demo Scenario

01. Open a Factory session on a repository with at least one commit.
02. Complete installation (ST-0281) and first-session insight (ST-0287).
03. The session recommends a first task. The preview shows goal, expected duration ("approximately 5–10 minutes"), expected artifacts, required decisions, and cleanup method.
04. Approve the task.
05. A detached worktree appears at `.current-work/onboarding-spike/<uuid4>/`. No new branch or commit exists. Uncommitted changes from the active working tree are absent.
06. The poc-spike playbook runs inside the sandbox. An inspectable file appears.
07. The session shows which checks ran and how to remove the result.
08. Choose discard. The sandbox directory is removed. `.current-work/onboarding-spike/<uuid4>/` no longer exists.
09. (Alternative to step 8) Choose retain. Select one artifact. The artifact appears in `docs/spikes/<name>/`. The sandbox is removed after copying.
10. (Alternative to step 8) Choose production handoff. The session asks: create a new workstream or select an existing one. The sandbox does not become production work.
