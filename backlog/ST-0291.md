# Complete a first task in a repository with commits

**Priority:** must-have

## Goal

A newcomer approves a first-task preview and receives a detached worktree sandbox from HEAD at `.current-work/onboarding-spike/<session-id>/`. The poc-spike playbook runs inside the sandbox and produces an inspectable result within ten minutes of session start. The newcomer then discards the sandbox, retains selected artifacts to `docs/spikes/`, or begins real work through a normal workstream.

## Contract

| Operation                              | Input state                                     | Outcome                                                                          | Persistence                                                     |
| -------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Approve first-task preview             | Repository with HEAD, installation complete     | Detached worktree created; no branch or commit added; active-tree changes absent | `.current-work/onboarding-spike/<session-id>/` exists           |
| Blank or declined approval             | Repository with HEAD, installation complete     | No sandbox created                                                               | No new directories                                              |
| poc-spike playbook runs in sandbox     | Sandbox exists                                  | Inspectable result displayed with check results and removal instructions         | Result files inside sandbox path                                |
| Newcomer chooses discard               | Sandbox with completed task                     | Worktree removed; path verified absent                                           | `.current-work/onboarding-spike/<session-id>/` no longer exists |
| Newcomer chooses retain with selection | Sandbox with completed task, artifacts selected | Only confirmed artifacts copied; sandbox not promoted                            | Selected artifacts at `docs/spikes/<name>/`                     |
| Newcomer chooses production handoff    | Sandbox with completed task                     | Normal workstream created or selected; sandbox not promoted                      | Workstream active; sandbox does not become production work      |
| Complete journey on ready host         | Ready host, one detected interface              | Inspectable result within ten minutes of session start                           | No more than five user decisions after installation approval    |

## Boundaries

- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.
- The poc-spike playbook is invoked without modification.
- The sandbox creates no branch or commit.
- Production handoff delegates to the existing workstream mechanism without reimplementing it.
- The sandbox is a detached worktree, not a regular branch checkout.

## Affected Paths

- `packages/factory/` — new sandbox management module (creation, cleanup, retention, handoff).
- `packages/factory/agents/virgil.md` — existing, extended with first-task preview and outcome selection.

## Demo Scenario

01. Open a Factory session on a repository with at least one commit.
02. Complete installation (ST-0281) and first-session insight (ST-0287).
03. The session recommends a first task. The preview shows the goal, expected duration, expected artifacts, required decisions, and cleanup method.
04. Approve the task.
05. A detached worktree appears at `.current-work/onboarding-spike/<session-id>/`. No new branch or commit exists. Uncommitted changes from the active working tree are absent.
06. The poc-spike playbook runs inside the sandbox. An inspectable file appears.
07. The session shows which checks ran and how to remove the result.
08. Choose discard. The sandbox directory is removed. `.current-work/onboarding-spike/<session-id>/` no longer exists.
09. (Alternative to step 8) Choose retain. Select one artifact. The artifact appears in `docs/spikes/<name>/`. The sandbox is not promoted.
10. (Alternative to step 8) Choose production handoff. A normal workstream is created. The sandbox does not become production work.

## Stop Conditions

- `git worktree add --detach` behaves differently across Git versions in a way that affects sandbox isolation — report the Git version and the observed difference.
- The `.current-work/` directory structure has constraints not documented in `init-factory` — report the constraint.
- The poc-spike playbook requires modifications to run inside a detached worktree — report what fails and why.
- The existing workstream mechanism requires parameters not available at handoff time — report the missing parameters.
- Code in `packages/factory/` and the feature spec disagree on sandbox lifecycle or outcome paths — report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. What session-id format does the sandbox path use — a UUID, a timestamp, or a sequential identifier?
2. Does the preview's "expected duration" come from a fixed estimate in Virgil's flow or from a measured baseline?
3. When the newcomer chooses production handoff, does the session create a new workstream or ask to select an existing one?
