# Build scope-lint script to validate scope declarations on governed artifacts

A deterministic lint script validates that every governed artifact carries a scope declaration in the correct format with a valid value.

**Priority:** should-have

## Goal

After this story ships, the developer runs `scope-lint` and sees validation results for every governed artifact in the repository. The script checks seven artifact types, each with its own scope format: YAML frontmatter for proposals, epics, stories, and the scope map; a first-line comment for feature files and the Structurizr DSL; and a top-level YAML field for the entity model. The script rejects missing declarations and unknown scope values, skips non-governed artifacts, and exits with the count of errors.

## Domain Rule

- Seven governed artifact types: proposals (`docs/proposals/*.md`), epics (`backlog/epics-*.md`), stories (`backlog/ST-*.md`), feature files (`docs/spec/*.feature`), Structurizr DSL (`docs/arc42/architecture.dsl`), entity model (`docs/spec/supplementary_specs/entity-model.yaml`), scope map (`docs/spec/scope-map.md`)
- Proposals carry scope in YAML frontmatter, replacing the `title` field; the display name moves to the document heading
- Epics, stories, and scope map carry scope in YAML frontmatter
- Feature files carry scope as a first-line comment: `# scope: <value>`
- Structurizr DSL carries scope as a first-line comment: `// scope: global`
- Entity model YAML carries scope as a top-level field: `scope: <value>`
- Valid scope values: a known workstream identifier (from `.agent-factory/workstreams/<id>.yaml`) or `global`
- A governed artifact without a scope declaration is an error
- A governed artifact with an unknown scope value is an error
- Non-governed artifacts (ADRs, conventions, templates, supplementary specs other than entity-model) are skipped
- Exit code equals the number of errors (0 = clean)

## Demo Scenario

1. Create a proposal at `docs/proposals/test-proposal.md` without a `scope` field in its YAML frontmatter.
2. Run `scope-lint`. The output shows: "ERROR: docs/proposals/test-proposal.md — missing scope declaration in YAML frontmatter". Exit code 1.
3. Add `scope: nonexistent-workstream` to the proposal frontmatter. Run `scope-lint`. The output shows: "ERROR: docs/proposals/test-proposal.md — unknown scope value 'nonexistent-workstream'". Exit code 1.
4. Create a workstream state file at `.agent-factory/workstreams/test-workstream.yaml`. Change the proposal scope to `scope: test-workstream`. Run `scope-lint`. The proposal passes. Exit code 0.
5. Create a feature file at `docs/spec/test.feature` without a first-line scope comment. Run `scope-lint`. Error: missing scope declaration.
6. Add `# scope: test-workstream` as the first line. Run `scope-lint`. The feature passes.
7. Verify that `docs/adr/ADR-0001.md` is skipped by scope-lint — no error, no check.
8. Run `scope-lint` across the full repository. All governed artifacts are checked; non-governed artifacts are skipped.

## Outputs

- `packages/factory/scripts/scope-lint` — Python script (stdlib only, `#!/usr/bin/env -S uv run --script`) that:
  - Discovers governed artifacts by path pattern (7 types)
  - Reads scope declaration in the format specific to each type (YAML frontmatter, first-line comment, top-level YAML)
  - Reads known workstream identifiers from `.agent-factory/workstreams/*.yaml`
  - Validates: declaration present, value is a known workstream ID or `global`
  - Reports errors with file path, error type, and detail
  - Skips non-governed artifacts
  - Exits with error count (0 = clean)
- `tests/test_scope_lint.py` — contract tests for scope-lint covering: missing declaration per type, unknown value, valid value, `global` value, non-governed artifact skipped

## Constraints

- Follow the existing lint script pattern: `#!/usr/bin/env -S uv run --script`, `--format json` option, findings as dataclass list
- Do not modify governed artifacts — this story builds the lint; ST-0274 adds scope declarations
- The entity model spec references `entity-model.yaml` but the current file is `entity-model.md`; handle both extensions or check which exists
