# Start a workstream and select any cycle

The human starts a workstream from the session menu and moves between cycles through a command that loads the delivery model, validates it, and writes state.

**Priority:** must-have

## Goal

After this story ships, the human selects option B in the session menu and provides a topic. A workstream state file appears under `.current-work/cycles/` at cycle IDEA. The state file records the topic, cycle IDEA, revision 1, and attempt 1. A session binding file records which workstream this session works on. When the human names an existing proposal, the state file's `origin_ref` field contains the proposal path.

The human runs `cycle select` on an existing workstream to move to any cycle. The state file updates to the chosen cycle at attempt 1 with an incremented revision. Selecting a cycle absent from the route table shows a warning but still records the choice. No override flag or justification is required for any selection.

When `delivery.yaml` breaks the JSON Schema, contains an executable command in a validator field, references an undeclared artifact, or carries a `direction` or `classification` field on a route, the adapter shows a named error and refuses to write state.

## Domain Rule

- The engine returns decisions and never writes repository state. Adapters own every write.
- A route declares `from`, `to`, and `recommend_if`. No other fields are permitted.
- The delivery model names validators by identifier. It never contains a shell command.
- Failed or missing evidence produces a warning. It never prevents a human from selecting a cycle.
- Entering a cycle sets attempt to 1.
- A new workstream starts at revision 1 and attempt 1.
- Assessments read the current commit. The state file never copies requirements or assessment results.

## Demo Scenario

1. Select option B in the session menu. Provide the topic "Add rate limiting to the public API".
2. Read `.current-work/cycles/add-rate-limiting.yaml`. It records topic "Add rate limiting to the public API", cycle IDEA, revision 1, attempt 1.
3. Confirm a session binding file exists under `.current-work/session-bindings/` for the current session.
4. Run `factory/scripts/cycle select --state .current-work/cycles/add-rate-limiting.yaml CONCEPT`. The state file records cycle CONCEPT, attempt 1, revision 2.
5. Run `factory/scripts/cycle select --state .current-work/cycles/add-rate-limiting.yaml REALIZE`. The command shows a warning that no declared route exists from CONCEPT to REALIZE. The state file records cycle REALIZE, attempt 1, revision 3.
6. Edit `packages/factory/engine/models/delivery.yaml`: add `direction: forward` to the IDEA→CONCEPT route. Run `factory/scripts/cycle select`. The adapter shows "rejected: route IDEA→CONCEPT contains forbidden field 'direction'" and does not write state.
7. Remove the `direction` field. Remove the `from` field from the same route. Run `factory/scripts/cycle select`. The adapter shows "rejected: route missing required field 'from'" and does not write state.

## Outputs

**Engine package (`packages/factory/engine/`):**

- `cycle_model.py` exports `load_delivery_model(path)`. Given a valid YAML path, it returns a typed object containing cycles, routes, artifacts, validators, and per-cycle attempt limits. Given an invalid or schema-violating model, it raises `CycleModelError` with the fault description. Given a model with unknown artifact references, executable commands, or direction/classification fields on routes, it raises `CycleModelError` naming the violation.
- `models/delivery.yaml` declares the five delivery cycles (IDEA, CONCEPT, ROADMAP, REFINE, REALIZE), the terminal DONE node, artifact types with canonical paths, trusted validator identifiers, per-cycle `delegated_attempt_limit` values, and every route with `from`, `to`, and `recommend_if` fields.
- `schemas/cycle-model-v1.schema.json` enforces structural rules: required cycle names, required route fields, positive integer attempt limits, no additional properties on routes.
- `schemas/cycle-state-v1.schema.json` enforces state file structure: required fields for topic, cycle, revision, attempt, and optional `origin_ref`.

**Adapter (`packages/factory/scripts/cycle`):**

- `cycle select --state STATE TARGET [--work REF]` creates a new workstream or transitions an existing one. On creation, writes a state file with the topic, cycle TARGET, revision 1, attempt 1. On transition, reads the existing state, writes cycle TARGET, resets attempt to 1, increments revision. When TARGET is absent from the model's route table for the current cycle, shows a warning and records the selection. Exit codes: 0 (selected), 1 (conflict), 2 (invalid).
- Creates or updates a session binding under `.current-work/session-bindings/`.

**Session menu (`packages/factory/config/session-menu.md`):**

- Option B captures a topic description and optional proposal path, then runs `cycle select` to create a workstream at IDEA. The playbook selection tree under option B is replaced.

**Tests (`tests/factory/`):**

- `test_cycle_model.py`: valid model loads with five cycles and DONE; missing route field raises named error; missing cycle raises named error; unknown artifact reference raises named error; executable in validator field raises named error; direction field on route raises named error; engine package imports nothing from scripts, config, agents, skills, or orchestrator.
- `test_cycle_select_integration.py`: `cycle select` creates state file on new workstream; `cycle select` transitions existing workstream; attempt resets to 1 on cycle change; revision increments on each transition; undeclared route produces warning and state update; invalid model produces error and no state write; session binding appears after creation; `origin_ref` recorded when proposal path given.

## Resolve Before Implementation

1. What Python type represents the validated cycle graph — frozen dataclasses, Pydantic models, or typed dicts? The choice shapes every downstream consumer. Frozen dataclasses keep the engine dependency-free. Pydantic adds validation but introduces a library dependency. Typed dicts are lightweight but offer no immutability guarantee.

2. Does `delivery.yaml` declare a `schema_version` field, and if so, does the loader enforce a minimum version? The cycle-model schema is v1. The model file may need a version marker for forward compatibility.

3. Does `cycle select` acquire an OS-level lock in this story, or is locking deferred entirely to EPIC 3? The architecture (§5.4) describes the lock protocol, but EPIC 1 scope lists "Revision conflict detection and locking (EPIC 3)" as out. Without a lock, concurrent sessions could overwrite state.
