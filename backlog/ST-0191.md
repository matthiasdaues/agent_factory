# Validate source pointers and reading-guide references with CX-SRC and CX-GUIDE-REF codes

Extend context-lint with four additional finding codes: CX-SRC (missing source pointer in index mode), CX-SRC-EXIST (source path does not resolve to a file on disk), CX-SRC-STALE (source file modified more recently than the index file), and CX-GUIDE-REF (reading-guide key-path reference does not resolve to a key in the target index file). These codes protect the integrity of the routing table's cross-references.

**Priority:** must-have

## Demo

You have agent-context files in `mode: index` (status quo from ST-0190 templates, manually set). You remove one `source:` pointer from `stack.yaml#frameworks.backend`, runs `context-lint`, and sees a CX-SRC warning. You restore the source pointer but points it at `docs/adr/nonexistent.md`, runs context-lint, and sees CX-SRC-EXIST. You fix the path to a real file, touches the source file to make it newer, runs context-lint, and sees CX-SRC-STALE info. You add `stack.yaml#frameworks.nonexistent` to `reading-guides.yaml`, runs context-lint, and sees CX-GUIDE-REF. You change the reference to `stack.yaml#frameworks.backend` (which exists) and context-lint passes with no CX-GUIDE-REF finding.

## Acceptance Criteria

- context-lint reports a CX-SRC warning when an index file has `mode: index` and a non-null, non-deferred field has a `name` but no `source` pointer (agent-context.feature Rule: context-lint validates, Scenario: CX-SRC reports missing source pointer when mode is index).
- context-lint reports a CX-SRC-EXIST warning when a `source` pointer does not resolve to a file on disk (agent-context.feature Rule: context-lint validates, Scenario: CX-SRC-EXIST reports unresolvable source path).
- context-lint reports a CX-SRC-STALE info finding when the source file was modified more recently than the index file (agent-context.feature Rule: context-lint validates, Scenario: CX-SRC-STALE reports stale index entry).
- context-lint reports a CX-GUIDE-REF warning when a reading-guide key-path reference does not resolve to a key in the target index file (agent-context.feature Rule: context-lint validates, Scenario: CX-GUIDE-REF reports unresolvable key path).
- context-lint does not report CX-GUIDE-REF when the referenced key exists, even if its value is null (agent-context.feature Rule: context-lint validates, Scenario: CX-GUIDE-REF checks key existence only not value).
- context-lint validates all reading-guide references against the actual key hierarchy in the target index file, not against the template.

## Scope

**Status quo:** context-lint exists with six core CX-\* codes (CX-FILE, CX-PARSE, CX-KEYS, CX-NULL, CX-MODE, CX-MODE-INVALID) from ST-0190. YAML templates and test fixtures exist. The script does not yet validate source pointers or reading-guide references.

**Adds:** A key-path parser that resolves dotted key paths (e.g. `stack.yaml#frameworks.backend`) against YAML structure. CX-SRC validation logic for source-pointer presence in index mode. CX-SRC-EXIST validation for source file existence on disk. CX-SRC-STALE mtime comparison logic. CX-GUIDE-REF validation for reading-guide cross-references. Additional contract tests in `tests/factory/test_context_lint.py` covering ACX-06 through ACX-09.

**Out of scope:** CX-FORMAT detection and legacy fallback (ST-0192). The format-detection chain (ST-0192). Consumer path updates (EPIC 4).

## Terminology

- Key-path notation: The `<file>#<dotted.key.path>` format used in reading-guides.yaml to reference specific sections in index files (e.g. `stack.yaml#frameworks.backend`).
- Source pointer: The `source:` field in an index-file entry that points at the authoritative document for that field's value (e.g. `source: docs/adr/004-use-fastapi.md`).

## Notes for the Implementer

The key-path parser needs to handle nested YAML structures and array-typed keys (referenced by parent, not by index). For CX-SRC-STALE, compare mtime of the source file against the mtime of the index file; when mtimes are equal, treat as not stale. New tests target the contract test layer under `tests/factory/`.
