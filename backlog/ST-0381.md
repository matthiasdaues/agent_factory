# Keep every number unique when claims run during a move or a move is cut off

**Priority:** must-have

## Goal

A claim that lands on the local counter while `next-id --move-to-origin` runs reaches `origin` with the move, so no number goes out twice. A move that was cut off after the marker finishes when the User runs `next-id --move-to-origin` again, without a seed and without a lost number.

## Contract

| Operation                  | Input state                                                                                                 | Outcome                                                                                                 | Persistence                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `next-id --move-to-origin` | The local counter is at C with `ST=0012`; after the read of C, a claim in a worktree raises it to `ST=0013` | The lease on C refuses the marker; the move reads again and exits `0`                                   | `origin` holds the claim commit with `ST=0013`; the marker's parent is that commit |
| `next-id --move-to-origin` | Every read is followed by a claim, so the lease on C goes stale every time                                  | After ten stale leases in a row, exit non-zero; the message names the move and the ten tries (CIFP-C09) | The local counter holds the last claim commit; no marker; the setting stays        |
| `next-id --move-to-origin` | The local counter holds the marker with parent C; `origin` holds no counter; the setting is set             | The move takes C from the marker's parent and pushes it; exit `0`                                       | `origin` holds C; the marker stays; the setting is gone                            |
| `next-id --move-to-origin` | The local counter holds the marker with parent C; `origin` holds C; the setting is set                      | The move only removes the setting; exit `0`                                                             | The setting is gone                                                                |
| `next-id --move-to-origin` | The local counter holds the marker with parent C; `origin` holds a claim commit D other than C              | A collision: exit non-zero; the message names both counters and prints the lines of C and D             | Both refs unchanged; the setting stays                                             |

## Demo Scenario

1. The User prepares the project `/tmp/race-demo` of Demo Data and runs `next-id --move-to-origin` while a second terminal runs `next-id ST` in `/tmp/race-demo-feature` in a loop. The move exits `0`.
2. The User reads the IDs that the loop printed. No ID appears twice. A claim that ran between the marker and the end of the move exited non-zero and printed no ID, and the IDs after the move continue from `origin`.
3. The User prepares `/tmp/cut-demo` of Demo Data, whose local counter already holds the marker with parent C at `ST=0012`, and runs `next-id --move-to-origin`. It exits `0`.
4. `/tmp/cut-origin.git` holds C, `git config agent-factory.counterRemote` prints nothing, and `next-id ST` in `/tmp/cut-demo` prints `ST-0013`.

## Boundaries

- A stale lease on C sends the move back to the read, at most ten times in a row, the limit of BR-072 (CIFP-C09).
- No claim lands on the local counter after the marker (BR-103).
- A second move recognises the marker by its one line `moved=<remote>` and takes C only from the marker's parent (DEC-14).
- When `origin` holds a claim commit other than C, the move cannot tell whether that counter grew from C, because a claim commit has no parent. It treats the case as a collision (BR-102).
- The forced race wraps the read of the local counter with `load_script` and runs a real `next-id ST` subprocess right after the first read, as `next_id_race.py` forces stale leases. The test uses no timing.
- The cut-off test kills nothing. It builds the state after the marker directly, or wraps the push to raise before git runs.
- No test prints a remote URL or a git config.
