# Create update-charter skill and register in agents

Create the `update-charter` shared skill and add it to the `skills:` list of the requirements-agent and architecture-agent. The skill owns the write target (`docs/charter/*.md`) — invoking agents do not need charter files in their `outputs:`.

**Priority:** must-have

## Acceptance Criteria

- Skill file at `factory/skills/update-charter/SKILL.md` with proper frontmatter
- Skill workflow: read current charter state, update the relevant section, preserve existing content, commit with format `docs: update charter <document> — <section> (<ID>)`
- `requirements-agent.md` frontmatter `skills:` list includes `update-charter`
- `architecture-agent.md` frontmatter `skills:` list includes `update-charter`
- Skill is category `utility` (shared across phases, like `domain-modeling`)
- No agent has `docs/charter/*.md` in its `outputs:`

## Implementation Notes

Same pattern as `domain-modeling` maintains `docs/CONTEXT.md`. One commit per update, attributable to the phase that made the decision. When no story/finding ID applies (e.g., during vision capture), the commit message omits the ID suffix.
