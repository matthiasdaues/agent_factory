# Surface navigation aids and playbook descriptions in the session menu

Add one-line descriptions to every B menu leaf, surface the explain-concept skill as a persistent footer, and add a "?" option that invokes the guided-tour skill.

**Priority:** should-have

## Demo

The user opens the session menu and sees a new option after D: `? -- Where am I? What can I do next?` The user picks B. Each playbook leaf now has a one-line description: `a -- poc-spike: build the smallest thing that proves the idea, then throw it away`. At the bottom of the B menu, a footer reads: "At any point, ask 'what is [concept]?' for a plain-language explanation." The user types "?" from the main menu and gets a guided-tour reorientation.

## Acceptance Criteria

- Every leaf in the B menu carries a one-sentence description after the playbook name, derived from the playbook's opening paragraph (design item 5)
- The session menu and the B menu each carry a footer line: "At any point, ask 'what is [concept]?' for a plain-language explanation" (design item 4)
- The session menu carries a "?" option after option D that invokes the guided-tour skill (design item 6)
- No changes are made to explain-concept, guided-tour, or any playbook file -- only `session-menu.md` is modified (design items 4, 5, 6)

## Scope

**Status quo:** session-menu.md presents options A through D. The B menu lists playbook names without descriptions. No footer mentions explain-concept. No "?" option exists.

**Adds:**

- One-line descriptions for each B menu leaf, derived from playbook opening paragraphs:
  - poc-spike: build the smallest thing that proves the idea, then throw it away
  - technical-poc: validate a technical risk with a decision-grade prototype
  - greenfield-development: build a real production system from requirements through deployment
  - brownfield-onboarding: understand an inherited codebase well enough to change it safely
  - feature-addition: add a feature to an existing system
  - bug-fix: fix a defect in production or development
  - refactoring: improve code structure without changing behavior
  - documentation-update: sync documentation with code when they have drifted
  - architecture-review: evaluate existing architecture without implementing changes
  - research-survey: source-grounded survey research
  - research-topic: test a hypothesis with falsification-driven research
- Explain-concept footer in session menu and B menu
- "?" option after D invoking guided-tour

**Out of scope:** Changes to explain-concept SKILL.md, guided-tour SKILL.md, or any playbook file.

## Notes for the Implementer

Read each playbook's opening paragraph to confirm descriptions are still accurate at implementation time -- the playbook file is the source of truth. The descriptions listed above are derived from the current opening paragraphs and may need adjustment if playbook files have changed.
