# Policy validator and three-stage validation entrypoint

Add the deterministic policy validator — the second stage of the validation
order — and the entrypoint that runs schema validation, then policy
validation, then hands off to semantic review. The policy validator enforces
the enforceable rules from the role-separation, claim-admission, evidence, and
report policies across a set of related research artifacts.

The validator checks role separation (author never reviews or votes on its own
claim, one agent never fills conflicting roles), reference integrity, quorum,
strict majority of decisive votes, current-claim-hash agreement across votes,
blocker handling, source-family independence, and report-to-claim traceability.
It carries the enforceable half of the proposal's "Required Tests". Semantic
judgements remain out of scope and pass to reviewers.

**Priority:** must-have

## Acceptance Criteria

- A new executable `factory/scripts/policy-validate` runs the enforceable
  policy checks over a related artifact set and exits non-zero on any
  violation.
- An entrypoint runs the stages in order — schema validation, then policy
  validation, then semantic review — and stops at the first failing stage.
- Enforced tests, each with a passing proof: an author cannot review or vote on
  its own claim; copied sources (same source family) do not count as
  independent evidence; a failed severe test blocks survival; an invalid test
  does not support a claim; a changed claim (new hash) invalidates prior reviews
  and votes; a new assumption starts a new review cycle; a tie does not produce
  survival; abstentions do not create a majority; a blocker prevents survival.
- Report-stage enforcement: a refuted or unresolved claim cannot enter the
  report as fact, an unsupported report statement fails validation, failed
  tests remain visible, and required qualifications remain in the report.
- The validator runs with no third-party dependencies (stdlib only).
