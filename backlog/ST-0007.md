# Prompt full artifact-class checklist when domain-modeling decides multi-context split

`factory/skills/domain-modeling/SKILL.md`'s "Domain awareness" section
currently says only: "During codebase exploration, also look for existing
documentation. See `context-format.md` for the single-context vs
multi-context file layout. Create `docs/CONTEXT.md` and `docs/adr/` lazily —
only when the first term or ADR is actually needed." It says nothing about
what happens *once* a repo is judged multi-context — it leaves each
affected artifact class to surface as its own separate discovery.

This session's retrospective (2026-07-10, Caused Friction row 1) found that
exact gap: the root `docs/` placement call took three separate rounds
(single-context → multi-context reversal → discovering root `backlog/` was
also needed), because each round only asked about one artifact class instead
of enumerating every artifact type a multi-context decision touches, once
that decision is made.

**Priority:** should-have

## Acceptance Criteria

- The "Domain awareness" section of `factory/skills/domain-modeling/SKILL.md`
  gains an explicit instruction: the moment a repo is judged multi-context,
  prompt the user with a single checklist enumerating every artifact class
  the split affects — docs/, ADRs, backlog/, `CONTEXT.md`, README — in one
  pass, rather than letting each surface as a separate follow-up round.
- The added instruction references the existing `context-format.md` pointer
  already in that section (for the `CONTEXT-MAP.md` structure) rather than
  duplicating it.
- No other section of the skill (Challenge against the glossary, Sharpen
  fuzzy language, Discuss concrete scenarios, Cross-reference with code,
  Update docs/CONTEXT.md inline, Offer ADRs sparingly) is restructured.
