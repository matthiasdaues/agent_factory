# Select and snapshot top-level JSONL files and route queries through the usage-query CLI

Deliver the Input Snapshot component and the `usage-query` CLI entry point so every downstream view operates on a fixed, sorted input set.

**Priority:** must-have

## Goal

After this story ships, the operator runs `usage-query capture_health --usage-dir dir/` and sees only sorted top-level JSONL files selected, subdirectories excluded, and no mid-query file changes affecting results. Running `usage-query` without `--usage-dir` defaults to `.agent-factory/usage/`. Running `usage-query` on an empty directory returns a typed empty schema. File enumeration order does not affect sorted rows or content digest. The query performs no network request. Analysis does not open, copy, index, or tokenize transcript content.

## Domain Rule

- Query input is the sorted set of top-level JSONL files in the selected directory. Subdirectories are excluded.
- The input set is snapshotted once at query start. No mid-query changes affect results. Each query creates a new snapshot (a new `list[Path]`).
- The `--usage-dir` directory is resolved to an absolute path before listing. The snapshot stores filenames only.
- File enumeration order does not affect sorted rows or content digest. The content digest is a SHA-256 over sorted filenames, each newline-terminated.
- The default input directory is `.agent-factory/usage/`.
- `--usage-dir` overrides the default directory.
- Analysis is local and transcript-blind — the query performs no network request and does not read transcript content.

## Demo Scenario

1. Create a directory with three top-level JSONL files and one subdirectory containing additional files.
2. Run `usage-query capture_health --usage-dir that-directory/`.
3. Verify the query snapshots only the three top-level files and excludes the subdirectory.
4. Run `usage-query capture_health --usage-dir that-directory/` with the same files listed in a different enumeration order. Verify sorted rows and content digest are identical.
5. Run `usage-query capture_health --usage-dir empty-directory/` on an empty directory. Verify the query returns a minimal typed empty result.
6. Run `usage-query unknown_view --usage-dir that-directory/`. Verify exit code 2 and stderr lists available views.
7. Run `usage-query capture_health --usage-dir nonexistent/`. Verify exit code 2 and stderr names the missing path.

## Required Behavior

The Input Snapshot component resolves the input directory to an absolute path via `Path.resolve()`. It lists top-level files matching `*.jsonl`, stores filenames only, sorts by filename encoded to UTF-8 bytes (`key=lambda name: name.encode('utf-8')`), and returns a `list[Path]` of absolute file paths. Files in subdirectories are excluded regardless of extension. It also returns a SHA-256 content digest computed over the sorted filenames, each newline-terminated.

The `usage-query` CLI accepts a view name as the first positional argument and `--usage-dir` (default `.agent-factory/usage/`). It validates that the directory exists (exit 2 if not). It creates an Input Snapshot, imports and runs the Contract Check module from ST-0241 on each selected file, and routes to the named view. Unknown view names exit 2 with a message to stderr listing available views. For this story, only `capture_health` is routable. It returns a minimal typed empty result (empty dict with view name key) — the real column contract belongs to ST-0244.

## Constraints

- No PyArrow dependency in this story. PyArrow is added in EPIC 4.
- The Input Snapshot is read-only. It never modifies, moves, or deletes files.
- No network requests during any query operation.
- No transcript content access — analysis depends only on usage record fields and the versioned query model.
- The CLI exit code contract: zero on success, exit 1 on validation failure, exit 2 on operational error (unknown view, missing directory, invalid arguments).
