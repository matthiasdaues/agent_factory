# Select and snapshot top-level JSONL files and route queries through the usage-query CLI

Deliver the Input Snapshot component and the `usage-query` CLI entry point so every downstream view operates on a fixed, sorted input set.

**Priority:** must-have

## Goal

After this story ships, the operator runs `usage-query capture_health --usage-dir dir/` and sees only sorted top-level JSONL files selected, subdirectories excluded, and no mid-query file changes affecting results. Running `usage-query` without `--usage-dir` defaults to `.agent-factory/usage/`. Running `usage-query` on an empty directory returns a typed empty schema. File enumeration order does not affect sorted rows or content digest. The query performs no network request. Analysis does not open, copy, index, or tokenize transcript content.

## Domain Rule

- Query input is the sorted set of top-level JSONL files in the selected directory. Subdirectories are excluded.
- The input set is snapshotted once at query start. No mid-query changes affect results.
- File enumeration order does not affect sorted rows or content digest.
- The default input directory is `.agent-factory/usage/`.
- `--usage-dir` overrides the default directory.
- Analysis is local and transcript-blind — the query performs no network request and does not read transcript content.

## Demo Scenario

1. Create a directory with three top-level JSONL files and one subdirectory containing additional files.
2. Run `usage-query capture_health --usage-dir that-directory/`.
3. Verify the query snapshots only the three top-level files and excludes the subdirectory.
4. Run `usage-query capture_health --usage-dir that-directory/` with the same files listed in a different enumeration order. Verify sorted rows and content digest are identical.
5. Run `usage-query capture_health --usage-dir empty-directory/` on an empty directory. Verify the query returns a typed empty schema.

## Outputs

- `packages/usage/src/usage/input_snapshot.py` — module that selects top-level JSONL files in a directory, sorts them by normalized path, excludes subdirectories, and returns a frozen list of paths. Snapshotted once at call time.
- `packages/usage/src/usage/cli.py` — CLI entry point parsing `usage-query <view-name>` with `--usage-dir` and `--format` arguments. Routes to view functions. Returns typed empty results for empty input. Exits non-zero for unknown views.
- `packages/usage/scripts/usage-query` — executable shebang wrapper invoking the CLI module.
- `packages/usage/pyproject.toml` gains DuckDB as a direct dependency and declares the `usage-query` script entry point.
- Integration tests verify file selection, subdirectory exclusion, sort-order independence, empty-directory handling, and transcript blindness.

## Required Behavior

The Input Snapshot component lists top-level files matching `*.jsonl` in the selected directory, normalizes each path relative to the directory, sorts by normalized path using unsigned UTF-8 byte order, and returns the frozen list. Files in subdirectories are excluded regardless of extension.

The `usage-query` CLI accepts a view name as the first positional argument, `--usage-dir` (default `.agent-factory/usage/`), and `--format` (default `table`). It creates an Input Snapshot, runs the Contract Check from ST-0241 on each selected file, and routes to the named view. For this story, only `capture_health` is a routable stub returning the typed empty schema when no valid lines exist.

## Constraints

- No PyArrow dependency in this story. PyArrow is added in EPIC 4.
- The Input Snapshot is read-only. It never modifies, moves, or deletes files.
- No network requests during any query operation.
- No transcript content access — analysis depends only on usage record fields and the versioned query model.
- The CLI exit code contract: zero on success, non-zero on failure.
