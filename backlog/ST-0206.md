# Add agent-context reconciliation to reconciliation-agent

Extend the reconciliation-agent to compare a project's agent-context index files against the factory's current interview guide and surface new suggested keys to the operator. This prevents amnesia when the factory evolves and adds new suggested keys that existing projects have never been asked about. See [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05).

**Priority:** should-have

## Demo

The factory ships a new version with `observability` as a suggested key in the interview guide. The reconciliation-agent runs against a project onboarded before this key existed. It reports: "The factory now suggests an `observability` key under workflow. Your project does not have one. Should it?" The operator confirms or dismisses.

## Acceptance Criteria

- The reconciliation-agent reads the factory's `context-interview-guide.yaml` during reconciliation passes.
- The reconciliation-agent compares the interview guide's suggested keys against the keys present in the project's index files.
- New suggested keys not present in the project are reported to the operator as suggestions, not errors.
- The operator can confirm (key is created) or dismiss (key remains absent) each suggestion.
- Dismissed suggestions are not re-surfaced in the same reconciliation pass.

## Scope

**Status quo:** The reconciliation-agent compares specification and architecture documentation against code-as-built. It does not examine agent-context files or the interview guide.

**Adds:** Agent-context key reconciliation against the interview guide as an additional reconciliation step.

**Out of scope:** Changes to context-lint (ST-0201). Interview guide creation (ST-0203).
