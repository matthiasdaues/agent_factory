# Wire pre-push full-suite test gate into canonical pre-commit config

Add the missing pre-push test gate to `factory/config/pre-commit-config.yaml`
— the canonical config `init-factory` splices into consumer projects — so the
"ready-to-share" full-suite gate that ADR-0003 (accepted, unsuperseded) and
`factory/README.md` already document is actually installed. This closes open
defect RECON-0017: the documentation is the intended truth, the configuration
drifted. `factory/scripts/run-tests` (built by ST-0009) already supports
`--full`; only the hook wiring is absent.

**Priority:** must-have

## Acceptance Criteria

- `factory/config/pre-commit-config.yaml` gains a new hook inside its existing
  `- repo: local` block with `id: agent_factory_hook-run-tests-full` (the
  `agent_factory_hook-` prefix is the removal key and must be preserved).
- The hook sets `entry: factory/scripts/run-tests --full`,
  `language: system`, `stages: [pre-push]`, `pass_filenames: false`, and
  `always_run: true`, with a brief comment naming it the "ready-to-share" gate
  and noting it has no `--no-verify` bypass.
- Running
  `merge-precommit-config --target <consumer>.pre-commit-config.yaml --template factory/config/pre-commit-config.yaml`
  carries the pre-push hook into the consumer config alongside the existing
  hooks; a second invocation is an idempotent no-op (the already-merged marker
  still keys on the template's first hook id).
- `init-factory` into a fresh consumer project produces a
  `.pre-commit-config.yaml` that contains `agent_factory_hook-run-tests-full`
  with `stages: [pre-push]` (asserted by a new init-factory test).
- Behaviorally: on `git push`, `run-tests --full` runs; exit `0` lets the push
  proceed, exit `1`/`2` blocks the push with test failures or the framework
  error on stderr. No bypass flag is introduced (matches UC-09 extension 1c).
- `factory/README.md`'s three-point test-regime description (pre-commit,
  pre-push, phase advance) matches what is actually installed: the pre-push
  point (point 2) now matches the canonical config, and a confirmation pass
  records that every described test hook is wired and every wired test hook is
  described. Any residual drift in point 1 (the pre-commit `--changed-only`
  test hook, which is also absent from the canonical config) is resolved in
  this same change or filed as a separate finding — never left silent.

## Investigation Notes

- **Originating defect:** RECON-0017 (severity major, category defect,
  artifact `factory/config/pre-commit-config.yaml`, status open). It records
  that ADR-0003 and `factory/README.md` § "Test execution hooks" both describe a
  pre-push hook running `run-tests --full` that blocks `git push` on failure,
  but the canonical config defines no `pre-push`-stage hook and no `run-tests`
  entry at all (`grep run-tests factory/config/pre-commit-config.yaml` returns
  nothing). This repo's own `.pre-commit-config.yaml` has only the pre-commit
  `run-tests --changed-only` hook; no `stages: [pre-push]` entry exists
  anywhere. ADR-0003 is accepted and unsuperseded, so the config — not the docs
  — is what drifted. RECON-0017 is the originating defect reference; no
  duplicate finding is filed.

- **Why the fix is config-only.** `merge-precommit-config` splices the entire
  `- repo: local` block from the template into a consumer's
  `.pre-commit-config.yaml`, keyed on the template's first hook id
  (`agent_factory_hook-mdformat`). Placing the new pre-push hook inside that
  same block means `init-factory` / `merge-precommit-config` carry it
  automatically — no script change is required, only a new hook entry in the
  canonical config. The existing `test_precommit_block_prefixed_and_on_top`
  init-factory test continues to hold.

- **Supersedes ST-0013.** ST-0013 ("Configure pre-push hook to run full test
  suite", status pending) previously proposed a raw git hook at
  `.github/hooks/pre-push` installed via `factory/scripts/install-hooks`, and
  carries a status correction noting it was never built. (An orphan
  `.github/hooks/pre-push` script does exist on disk, but it is untracked,
  not symlinked into `.git/hooks/`, and not carried to consumers by
  `init-factory` — so it is not the live mechanism the README describes.)
  RECON-0017 redirects
  the implementation to the pre-commit-framework `pre-push` stage, which is
  consistent with how the existing test and lint hooks are wired and with
  ADR-0003's "unavoidable hook" wording and the README's three-point
  description. ST-0073 supersedes ST-0013's approach; closing/superseding
  ST-0013 is an implementation-side bookkeeping step for this story (it is not
  listed in `deps` because ST-0013 is itself unbuilt and must not block this
  fix).

- **Adjacent drift (out of scope, flagged).** The canonical config also lacks
  the pre-commit `--changed-only` test hook (README point 1); that hook exists
  only in this repo's own merged `.pre-commit-config.yaml`. RECON-0017 scopes
  its fix to the pre-push full-suite gate, so this story wires point 2 only.
  The README consistency acceptance criterion above requires that drift to be
  either closed in the same change or filed as its own finding, so the
  three-point description never silently overstates what is installed. Point 3
  (phase advance) is already enforced by the FSM `tests_pass` entry condition
  and needs no config change.

- **Traceability.** UC-09 (Run Tests via Hook) extensions 1c (pre-push blocks
  on failure, no bypass) and 5a (failure exit `1`, JSON summary) and BR-026
  (`--full` runs the complete suite) define the behavior. ADR-0003 fixes the
  pre-push hook as the "ready-to-share gate — full suite, unavoidable, blocks
  work leaving local machine."
