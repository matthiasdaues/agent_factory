# Show each new minor finding with its fails_purpose sentence

**Priority:** must-have

## Goal

At the pause point, the user sees every new `minor` finding with its `no to fails_purpose` sentence before any file is written, and can raise it by changing the answer. A headless run lists each new register file with the same sentence in its final summary.

## Domain Rule

- A finding rated too low escapes later review, so the human sees its reason once (DEC-22).
- The pause point renders each new register file as text: ID, class, artifact, and the Why sentence.
- The stakeholder raises a `minor` finding by changing an answer at the pause point; after it is written, by replacing the register file with a finding file of the same ID.
- A headless run lists the files only after the loop ends, so a wrong downgrade can still reach implementation; the summary says so.

## Outputs

- `finding-format.md` § Pause point shows the `minor` findings and the raise.
- The final summary step of each playbook with a review loop lists the new register files with their sentence.

## Demo Scenario

1. The User runs `atam-review` interactively on a design whose gap in ADR-0026 rates `minor`.
2. At the pause point, before any file is written, the agent shows "ATAM-NNNN, document, `docs/adr/0026-layout-migration-runs-inside-the-factory-update.md#decision`: an implementer can pick the obvious behavior (no to fails_purpose)".
3. The User answers that the implementer cannot. The agent records `fails_purpose: true` and files a `major` finding file instead.
4. In a headless run, the final summary lists `docs/findings/register/document/ATAM-NNNN.json` with its sentence.
