# Install the factory on an old-layout project without moving a file

**Priority:** must-have

## Goal

The project maintainer installs the factory on a project in the old layout and
no file moves. The output lists each old path `init-factory` finds and names
`migrate-spec-layout` as a command the maintainer can run.

## Contract

| Operation      | Input state                                                  | Outcome                                                                                          | Persistence      |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ | ---------------- |
| `init-factory` | No `.agent-factory/install.json`; old-layout files exist     | No project file moves; one report line per old path found; one line naming `migrate-spec-layout` | Install as today |
| `init-factory` | No `install.json`; project in the new layout or without docs | No listing                                                                                       | Install as today |
| `init-factory` | Second run after the first install                           | No project file moves; the migration does not run                                                | As today         |

## Demo Scenario

1. The maintainer builds the fixture `fresh-old-layout` (Demo Data) and runs
   `packages/factory/scripts/init-factory --source <repo> --target <fixture>`.
2. The output holds `init-factory:` lines that name
   `docs/spec/payments.feature` and `docs/arc42/architecture.dsl`, and a line
   that names `migrate-spec-layout`.
3. `git -C <fixture> status` shows no rename and no deletion under `docs/`.

## Demo Data

The story extends the fixture helper of `tests/factory/test_init_factory.py`.

| Fixture            | Content                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------- |
| `fresh-old-layout` | The old-layout files of `old-layout-payments` (ST-0318), committed; no `.agent-factory/` |

## Boundaries

- `init-factory` leaves the project's own files alone on a first install and on
  a rerun.
- Only a missing `install.json` is a first install.
- The listing reuses the old-path detection of `migrate-spec-layout` rather
  than a second copy of the path table, so the two cannot drift. If that is not
  possible, the story stops (see Agent Stop Conditions).
- Report lines keep the `init-factory: <line>` form.

## Affected Paths

- `packages/factory/scripts/init-factory` — existing; first-install branch of
  the version test with the old-path listing.
- `tests/factory/test_init_factory.py` — existing; first-install and rerun
  cases.

## Inputs

- ST-0330: the version test and its three outcomes.
- ST-0318: the path-table planner of `migrate-spec-layout`, which can report
  old paths without changing a file (`--dry-run`).
- Contract: [interface-contracts.md § init-factory](../docs/spec/supplementary_specs/interface-contracts.md#factoryscriptsinit-factory), row Layout migration.
- Scenarios covered, in [core-artifact-layout.feature](../docs/spec/core-artifact-layout.feature):
  "A first install moves no file and lists the old paths", "A later run of
  init-factory at the same version moves nothing".
- Contract owned by this story (EPIC E5 Ownership Resolution): CAL-07-IT-02.

## Evidence

- [ ] On `fresh-old-layout`, `git status --porcelain` after the install shows
  no `R` or `D` entry under `docs/`, the output lists the old paths, and it
  names `migrate-spec-layout` (CAL-07-IT-02).
- [ ] A second `init-factory` run moves no file and does not list again as a
  migration.

## Verification

Suite `default`:

```bash
uv run pytest --tb=short --quiet tests/factory/test_init_factory.py
uv run pytest --tb=short --quiet -n auto -m "not container"
```

Test budget: CAL-07-IT-02 is `standard`; one case for the first install, one
for the rerun.

## Out of Scope

- Running the migration on a first install.
- The update path (ST-0330).

## Agent Stop Conditions

- Reusing the detection of `migrate-spec-layout` would make `init-factory`
  depend on a script outside its source tree. Report the dependency and the
  alternative.

## Resolve Before Implementation

1. Listing mechanism. Default: `init-factory` runs
   `migrate-spec-layout --dry-run <target>` and turns each planned move and
   removal into one `init-factory:` line, so one path table serves both.
