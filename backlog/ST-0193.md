# Initialize greenfield agent context with capture-context --init

Rename `factory/skills/capture-charter/SKILL.md` to `factory/skills/capture-context/SKILL.md` and implement the greenfield initialization path (`--init`). The skill creates three index-file templates in `docs/agent-context/` with `mode: primary` and null placeholders, does not create `reading-guides.yaml`, does not overwrite existing files, and includes the stakeholder interview flow for filling greenfield index values directly as inline content.

**Priority:** must-have

## Demo

Operator runs `capture-context --init` in a new, empty project. Three YAML files appear in `docs/agent-context/`: `stack.yaml`, `workflow.yaml`, `governance.yaml`, each with `mode: primary` and null placeholder values. `reading-guides.yaml` is not created. Operator runs `context-lint` and gets CX-NULL warnings but no errors. Operator runs `capture-context --init` again -- the existing files are preserved unchanged (skip-if-exists guard). Operator answers stakeholder questions about technology choices -- capture-context writes the answers as inline values to the appropriate index file fields.

## Acceptance Criteria

- capture-context --init creates `docs/agent-context/stack.yaml`, `workflow.yaml`, and `governance.yaml` from the EPIC 1 templates with `mode: primary` and null placeholders (agent-context.feature Rule: Operator initializes agent context for a greenfield project, Scenario: capture-context --init creates three index-file templates).
- capture-context --init does not create `reading-guides.yaml` (agent-context.feature Rule: Operator initializes agent context for a greenfield project, Scenario: capture-context --init creates three index-file templates).
- capture-context --init preserves existing files unchanged when `docs/agent-context/` already contains populated values (agent-context.feature Rule: Operator initializes agent context for a greenfield project, Scenario: capture-context --init does not overwrite existing context).
- capture-context writes stakeholder interview answers as inline values to index-file fields when `mode: primary` (agent-context.feature Rule: Operator initializes agent context for a greenfield project, Scenario: Stakeholder interview fills greenfield index values directly).
- context-lint passes on the files created by capture-context --init (no errors, CX-NULL warnings expected).
- The capture-context skill resolves through INDEX.yaml by its new name.

## Scope

**Status quo:** `factory/skills/capture-charter/SKILL.md` exists as the legacy skill for populating markdown charter files. Four YAML templates exist in `factory/rulebooks/templates/` (from ST-0190). context-lint validates YAML agent-context files (from ST-0190).

**Adds:** Renamed `factory/skills/capture-context/SKILL.md` with greenfield initialization logic. Template-copy logic with skip-if-exists guard. Stakeholder interview flow for inline value writes. Updated INDEX.yaml entry (via `index-lint`).

**Out of scope:** Brownfield onboarding with `--init --scan` (ST-0194). update-context skill (EPIC 3). Consumer path updates (EPIC 4).

## Notes for the Implementer

The capture-context skill is a markdown skill definition executed by an LLM agent, not a standalone script. The initialization logic describes the steps the agent follows: copy templates, check for existing files, run context-lint to validate. The stakeholder interview is a conversational flow where the agent asks about technology choices and writes responses to the appropriate index-file fields. Run `index-lint` after the rename to update INDEX.yaml.
