# Redesign story template to 13-section agent-ready body with risk_level field

Replace the current 7-section story body (Demo, Acceptance Criteria, Scope, Terminology, Notes for the Implementer) with a 13-section body that a developer-agent can implement from without rereading the planning context. Add `risk_level` as an optional enum field to backlog-lint frontmatter validation.

**Priority:** must-have

## Demo

1. Open `packages/factory/rulebooks/templates/story.md`. The body skeleton shows 13 sections in order: Goal, Domain Rule, Demo Scenario, Affected Paths, Inputs, Outputs, Required Behavior (conditional), Constraints, Suggested Agent Plan, Acceptance Criteria, Verification, Out of Scope, Agent Stop Conditions.
2. The frontmatter example includes `risk_level: low` with a comment listing valid values (low, medium, high).
3. The Affected Paths section definition documents the `touches` hygiene rule: most specific directories, no parent+child overlap, no speculative paths, every entry must resolve to an existing directory or one created by a dep.
4. Run `factory/scripts/backlog-lint --backlog-dir backlog` on a test story with `risk_level: medium`. Lint reports zero errors.
5. Change the story's `risk_level` to `extreme`. Lint reports a BL-ENUM error.
6. Remove `risk_level` entirely. Lint reports zero errors (the field is optional).
7. Run lint on existing old-format stories. They all pass unchanged.

## Acceptance Criteria

- The template body contains exactly 13 numbered sections in the order specified by the proposal (agent-ready-story-format.md § Body sections).
- Sections removed from the old template (Terminology, Notes for the Implementer, three-part Scope) do not appear in the new template body.
- The frontmatter example includes `risk_level` as an optional field with values `low | medium | high`.
- The template documents the `touches` hygiene rule under the Affected Paths section: most specific directories, no parent+child, no speculative paths, derive from Affected Paths.
- `tests` and `test-design-pass` fields remain unchanged in the frontmatter (they already exist per test-design layer redistribution).
- backlog-lint accepts `risk_level` with values `low`, `medium`, or `high` and rejects any other value.
- backlog-lint treats `risk_level` as optional: stories without it pass.
- backlog-lint adds no heading-match validation: existing old-format stories pass unchanged.

## Scope

**Status quo:** `packages/factory/rulebooks/templates/story.md` (v2.1.0) defines a 7-section body: Demo, Acceptance Criteria, Scope (Status quo / Delivers / Out of scope), Terminology, Notes for the Implementer. Frontmatter has `id`, `epic`, `title`, `tier`, `status`, `deps`, `traces`, `touches`, `concerns`, `quality-gates`, `tests`, `test-design-pass`. `packages/factory/scripts/backlog-lint` validates frontmatter fields against `ALL_FIELDS = REQUIRED_FIELDS | OPTIONAL_FIELDS` and rejects unknown fields. `risk_level` is not in either set.

**Delivers:** A redesigned template body with 13 sections and `risk_level` as an optional enum field in both the template and backlog-lint. The `touches` hygiene rule documented in the template. Full backward compatibility in lint.

**Out of scope:** Skill instruction changes (ST-0235 through ST-0238). Developer-agent reading cue changes (ST-0239). Migration of existing stories to the new format (explicitly deferred per proposal).

## Notes for the Implementer

Edit `packages/factory/rulebooks/templates/story.md` (source), not `factory/rulebooks/templates/story.md` (installed copy).

In backlog-lint, add `risk_level` to `OPTIONAL_FIELDS` and add a new enum validation block similar to the existing `tier` and `status` checks. The valid values set is `{"low", "medium", "high"}`.
