# Relax feature-addition prerequisites to anchor-file presence

Update `factory/playbooks/feature-addition.md` prerequisites from "existing project with spec and architecture" to "architecture.dsl, scope-map.md, and docs/CONTEXT.md exist." Full specification artifacts become optional inputs that deepen the process when present. Each feature-addition run naturally adds a Rule to the scope map and may update the DSL and CONTEXT.md.

**Priority:** must-have

## Acceptance Criteria

- Prerequisites section checks for three anchor files: `docs/arc42/architecture.dsl`, `docs/spec/scope-map.md`, `docs/CONTEXT.md`
- Prerequisites do not look for a Stage 1 completion marker file
- The playbook proceeds when all three anchor files exist, regardless of whether full spec artifacts are present
- Missing anchor files are reported with a suggestion to run brownfield-onboarding
- The requirements-agent step adds a new Rule to scope-map.md with status "specified"
- The architecture-agent step updates architecture.dsl when the structural shape changes
- New domain terms are added to docs/CONTEXT.md during requirements
- `spec-lint`, `link-check`, and `mdformat` pass

## Implementation Notes

- The prerequisites change is in the "Prerequisites" checklist at the top of the playbook
- Incremental deepening is described as expected behavior in Step 1.1 (Update Specification) and Step 2.1 (Update Architecture), not as new procedural steps
