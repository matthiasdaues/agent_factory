# Create derive-feature skill

Create the `derive-feature` skill that replaces `derive-spec` as the
primary specification step. Instead of producing intermediate Cockburn
documents, the skill uses the Cockburn reasoning sequence as an internal
working process and writes a consolidated `.feature` file directly, with
Rule-per-actor-goal structure and `@`-references to existing code.

**As a** requirements-agent,
**I want** a single skill that scans existing code, derives actor-goal
pairs, and outputs a Gherkin `.feature` file with code traceability,
**so that** the specification is a single-file, executable artifact that
coders and QA agents can read in one pass.

**Priority:** must-have

## Acceptance Criteria

01. `factory/skills/derive-feature/SKILL.md` exists and documents the
    Cockburn-as-Rules reasoning process, code-scan step, `@`-reference
    annotation, scope map lifecycle, and slice workflow.
02. The skill receives the proposal file path as its invocation argument and
    reads `impact.boundaries` from the proposal frontmatter.
03. The skill scans `src/` (or equivalent) against the proposal's
    `impact.boundaries` and annotates existing code with `@`-references in
    the `.feature` output.
04. Scenarios for new behavior carry no `@`-reference; absence means "to be
    implemented."
05. Output `.feature` file uses Rule-per-actor-goal structure: each Rule
    corresponds to one actor-goal pair, with actor identified in a comment.
06. Every actor-goal pair has at least one Rule; every Rule has at least one
    Scenario. Missing coverage goes to the gaps report.
07. Output location: `docs/spec/<feature-name>.feature` and
    `docs/spec/<feature-name>-gaps.md`.
08. The gaps report contains: actor-goal matrix, Rules without Scenarios,
    actor-goal pairs without Rules, ambiguous wording flags.
09. The skill fails with a diagnostic if the proposal path is missing,
    unreadable, or lacks an `impact.boundaries` field.
10. All outputs pass `factory/scripts/validate`.

## Implementation Notes

**Inputs:**

- `docs/proposals/agentic-quality-gates-and-specification-consolidation.md`
  § Design 2 (full design) and § Design 8 (traceability)
- `factory/skills/derive-spec/SKILL.md` — predecessor skill (for reference,
  not reuse)
- `factory/rulebooks/conventions/cross-reference-format.md` — `@`-reference
  convention (from ST-0095)

**Strategy:** new skill file. The Cockburn chain (actors, goals, scenarios)
is an internal reasoning discipline, not document production. The skill
outputs only the `.feature` file and the gaps report.

**Tier rationale:** standard. The skill must describe a multi-step reasoning
process, code-scan heuristics, and output format constraints. Requires
careful instruction design.
