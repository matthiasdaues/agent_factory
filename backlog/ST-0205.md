# Rewrite skills to discover structure through reading guide

Update all skills that read agent-context index files to discover structure through `reading-guides.yaml` instead of hardcoding second-level field paths. Skills read the reading guide to find which index-file sections are relevant to their concern, then inspect those sections for the facts they need. See [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05).

**Priority:** must-have

## Demo

A developer reads `implement-issue/SKILL.md` and finds no hardcoded references to `stack.yaml#frameworks.backend` or `workflow.yaml#testing`. Instead, the skill reads `reading-guides.yaml` for the concern relevant to the current story, follows the key-path references into index files, and reads whatever structure the project has defined there.

## Acceptance Criteria

- No skill references a second-level index-file key path directly (such as `stack.yaml#frameworks.backend` or `workflow.yaml#testing`).
- Every skill that needs project context reads `reading-guides.yaml` first and follows the key-path references it finds.
- Skills that operate on a specific concern (e.g. testing, backend) declare which concern they look for, and fall back gracefully when the concern does not exist in the reading guide.
- The reading guide's top-level concern keys and the key-path notation remain the sole discovery mechanism.

## Scope

**Status quo:** Multiple skills hardcode second-level field paths into index files. They assume specific keys like `frameworks.backend` or `testing` exist.

**Adds:** Reading-guide-first discovery pattern across all affected skills.

**Out of scope:** Changes to context-lint (ST-0201). Changes to update-context (ST-0204). Changes to agents (separate story if needed).
