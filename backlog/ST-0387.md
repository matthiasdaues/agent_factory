# File each review finding by its computed severity

**Priority:** must-have

## Goal

Each of the twelve review skills and agents names its review class, links its class section, and files its findings by the computed severity. A blocking finding becomes a finding file from the new template with its basis. A `minor` finding becomes one register file `docs/findings/register/<class>/<ID>.json` that its class schema describes.

## Contract

| Review result                                      | What the review writes                                                                                                                                                                                     | Persistence                                |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `critical` or `major`, category `defect` or `risk` | A finding file from `templates/finding.md` with `review_class`, `type`, `basis`, `rating`, the four human fields at `null`, and the `**Why this severity:**` line; `## Possible damage` only on `critical` | `docs/findings/<ID>.md`                    |
| `minor`                                            | One JSON object with the keys of the register-file contract and `status: open`; no finding file                                                                                                            | `docs/findings/register/<class>/<ID>.json` |
| `note`                                             | A row in the review report only                                                                                                                                                                            | the review report                          |
| `question`                                         | A todo entry only                                                                                                                                                                                          | `docs/spec/work/todo.md`                   |
| The fix of a `minor` finding                       | The fixing commit sets the register file's `status` to `resolved`                                                                                                                                          | the register file stays                    |

The twelve files and their classes are the rows of the Scenario Outline in FC-01: five document files, two code files, `security-review`, two architecture files, `bug-hunt`, and `qa-agent` with code, security, and runtime.

## Demo Scenario

1. The User opens `packages/factory/skills/fagan-review/SKILL.md`. It names the class `code` and links `Class: code` of `finding-classification.md`, and it defines no level of its own.
2. The User opens `packages/factory/rulebooks/templates/finding.md`. Its frontmatter holds `review_class`, `type`, `basis`, `rating`, `override_by`, `override_reason`, `stop_confirmed_by`, and `stop_confirmed_reason`, and its status line lists `waived` as stakeholder-only.
3. The User runs `security-review` on a story branch whose only finding is a `minor` one. The review writes `docs/findings/register/security/SEC-NNNN.json` with `status: open` and files no finding file.
4. The User runs `.agent-factory/factory/scripts/schema-validate docs/findings/register/security/SEC-NNNN.json packages/factory/rulebooks/schemas/finding-register-security.schema.json`. It exits `0`.
5. The User opens `finding-format.md`. It names two removals of a finding file, the migration of a `minor` finding and a lowering by the stakeholder, and each leaves a register file under the same ID.

## Demo Data

None. The demo review runs on any story branch; its ID comes from `next-id SEC`.

## Boundaries

- Each review file links its class section and keeps no severity definition (Completion Criteria 2 and 3).
- `qa-agent` links three sections: code, security, and runtime.
- The five schemas sit under `packages/factory/rulebooks/schemas/` as `finding-register-<class>.schema.json`. Each one makes the first thirteen keys of the register-file contract required and gives `basis` the shape of its class from `docs/spec/schemas/finding-basis.json`.
- The schemas use only what `schema-validate` supports, because `finding-lint` runs it with the standard library only.
- `architecture-review-agent.md` and `atam-review` state that a non-risk names the assumptions it rests on.
- Each review takes its finding ID from `next-id <PREFIX>`, for a finding file and a register file alike (DEC-32).
- The story regenerates `packages/factory/INDEX.yaml`, and `index-lint --check` passes.

- A review file has no step where it writes findings. Report the file; the class link alone may be enough.
