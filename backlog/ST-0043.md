# Capture Codex sessions through native hooks

Extend the same operational capture contract to Codex. Normalize the Codex
transcript, wire its human and sub-agent lifecycle events during Factory
installation, reverse only Factory-owned changes during removal, and prove the
installed consumer-project path end to end.

**Priority:** must-have

## Acceptance Criteria

- `usage-capture --cli codex` normalizes the full Codex transcript into
  canonical input and output text, extracts provider usage when present, and
  emits the shared record schema without Codex-specific fields.
- `init-factory` merge-safely installs Factory-owned Codex `Stop` and
  `SubagentStop` capture hooks through the supported project hook surface,
  preserves pre-existing Codex configuration and hooks, and is idempotent.
- `remove-factory` removes only Factory-owned Codex hook assets and entries,
  preserves project-owned `.codex` content, and leaves no Factory-created empty
  structure behind.
- An end-to-end consumer-project test invokes both installed hook paths and
  proves that a human Codex session and a Codex sub-agent session each append
  one well-formed record and persist the transcript referenced by that record.
- Capture failure is best-effort: either installed hook exits successfully and
  leaves the simulated Codex run unaffected when normalization or persistence
  fails.
- The native CLI hook remains the sole capture owner; a Codex session launched
  through another Factory path still creates exactly one record.

## Implementation Notes

Limit this story to the Codex support required for operational usage capture.
Do not modify the separate Codex CLI support proposal while implementing it.
Keep Codex payload parsing and hook configuration behind the per-CLI adapter.

## Analysis

Implement Codex as another adapter around the existing CLI-agnostic capture
pipeline, using only synthetic Codex transcript and native hook payload
fixtures. The Codex normalizer will retain the complete ordered root
transcript, split input from output, and map provider usage into the canonical
reported fields. Root transcripts are inclusive: child activity present in a
root transcript remains in its normalized and reported totals. A
`SubagentStop` record is attribution-only; it must not be added to its root
record by a future total-spend aggregator.

The installation slice will add a Factory-owned Codex capture script and
merge exact `Stop` and `SubagentStop` command entries into
`.codex/hooks.json`. It will preserve unrelated project hook configuration,
avoid duplicate entries on repeated initialization, and record sufficient
ownership metadata for removal. Removal will delete only those exact entries
and Factory-owned assets, retaining project-owned `.codex` content and pruning
only empty Factory-created structure.

Highest-level test seams:

1. Invoke the public `usage-capture --cli codex` entrypoint against synthetic
   full root and child transcripts; observe canonical JSONL records,
   persisted transcript copies, inclusive root totals, and attribution-only
   child records.
2. Invoke public `init-factory` and `remove-factory` entrypoints on consumer
   projects; inspect native `.codex/hooks.json`, preserved project entries,
   idempotency, exact Factory-entry reversal, and empty-directory pruning.
3. Invoke both installed hook commands with official synthetic `Stop` and
   `SubagentStop` payload shapes; observe one record per event and successful,
   silent failure handling. This also proves the native Codex hook remains the
   sole record writer.
