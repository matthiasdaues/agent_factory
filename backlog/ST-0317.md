# Declare the scope of .feature and .dsl files with one comment form

**Priority:** should-have

## Goal

An author of a `.feature` or `.dsl` file declares its scope with the same
first-line comment, `# scope: <id>`. Both `scope-lint` and the eligibility
engine accept it. The old `// scope:` form in `.dsl` files still passes, so
existing files keep working.

## Findings

- [BUG-0095](../docs/findings/BUG-0095.md): `scope-lint` syntax is
  inconsistent and fails in worktrees. This story fixes the syntax part.

## Scope

Markdown keeps its frontmatter, because `#` starts a heading there. YAML
entity files keep their top-level field. The `.dsl` form moves to `#`,
which the Structurizr DSL already uses for comments.

## Acceptance criteria

- `scope-lint` and `eligibility.py` read `# scope:` on line 1 of a `.dsl`
  file, and still read `// scope:`.
- Run `structurizr validate` once (Docker) on a `.dsl` file with
  `# scope:` on line 1. If it rejects the line, stop and report.
- `docs/arc42/architecture.dsl` line 1 uses the new form.
- The spec text in `docs/spec/activity-graph-orchestration.feature` (around
  lines 273-276) and `docs/spec/supplementary_specs/validation-rules.md`
  (around lines 287-288) names the new form.
- Tests cover both forms in both parsers.
- Each new test fails on the code before this story and passes after it.
- The full suite passes with `pre-commit run run-tests --all-files`.
- Commits name the finding, `fix: <what changed> (BUG-0095)`.
- No file outside the list below changes. Nothing under `.agent-factory/`
  changes.
