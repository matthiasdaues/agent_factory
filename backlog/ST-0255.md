# Detect code changes and run reconciliation assessment

The adapter detects whether the current cycle changed source code or canonical artifacts and passes that signal to the evaluator, enabling the semantic assessment path.

**Priority:** must-have

## Goal

After this story ships, the adapter records the commit SHA at cycle entry in the state file. When `cycle assess` runs, the adapter compares HEAD against the cycle-entry commit. When the diff touches source files or canonical artifacts (`docs/spec/scope-map.md`, `docs/spec/entity-model.yaml`, `docs/arc42/architecture.dsl`), the adapter passes `code_changed=True` to the readiness evaluator. Semantic validators run only in that case.

When nothing relevant changed, the assessment reports that reconciliation does not apply. The `code_changed` flag replaces the hardcoded `False` from ST-0253.

## Domain Rule

- The adapter owns commit comparison. The engine receives a boolean flag.
- Reconciliation assessment runs when the current cycle produced commits that changed source code or canonical artifacts.
- When nothing relevant changed, the assessment reports reconciliation as not applicable.
- The cycle-entry commit is recorded on every cycle transition (create or select).
- Canonical artifacts are: `docs/spec/scope-map.md`, `docs/spec/entity-model.yaml`, `docs/arc42/architecture.dsl`, and files matching `docs/spec/*.feature`.

## Demo Scenario

1. Create a workstream at IDEA. Note the cycle-entry commit in the state file.
2. Run `cycle assess`. No code changed since entry. The result reports reconciliation does not apply. Only mechanical validators run.
3. Commit a change to a source file.
4. Run `cycle assess`. The adapter detects the diff. `code_changed=True` passes to the evaluator. Semantic validators (when registered) would now run. The assessment reflects the change.
5. Commit a change to `docs/spec/scope-map.md`. Run `cycle assess`. Same result: reconciliation applies because a canonical artifact changed.

## Outputs

**State file schema (`cycle-state-v1.schema.json`):**

- New optional field `cycle_entry_commit` (string, nullable). Recorded by the adapter at cycle creation and on each transition.

**Adapter (`packages/factory/scripts/cycle`):**

- `_create` and `_transition` record `cycle_entry_commit` as the current HEAD SHA at write time.
- `cmd_assess` reads the state file's `cycle_entry_commit`, compares it against current HEAD using `git diff --name-only`. If the diff touches source files (`src/`, `packages/`, `tests/`) or canonical artifacts, passes `code_changed=True`. Otherwise passes `code_changed=False`.

**Tests (`tests/factory/`):**

- `test_reconciliation_detection.py`: code change detected when source files differ; canonical artifact change detected; no change when HEAD equals cycle-entry commit; no change when only unrelated files differ; `code_changed` flag reaches the evaluator.
- `test_cycle_select_integration.py`: updated to verify `cycle_entry_commit` field in state files after create and transition.
