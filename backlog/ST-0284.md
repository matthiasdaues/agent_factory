# Check for available updates without writes

**Priority:** should-have

## Goal

A project maintainer runs `update-factory --check` on an existing Factory installation and receives a report showing installed and candidate versions, source, digest, local modifications, and planned header changes. Check mode performs no writes.

## Contract

| Operation                                         | Input state                                     | Outcome                                                                                                                   | Persistence                                                  |
| ------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `update-factory --check`                          | Installation with a newer version available     | Report shows installed version, candidate version, source, candidate digest, no modifications, and planned header changes | No file changes, no staging directories, no manifest updates |
| `update-factory --check`                          | Installation at latest version                  | Report shows installed and candidate versions are equal                                                                   | No file changes                                              |
| `update-factory --check` with local modifications | Factory-owned files differ from installed state | Report lists the modified files                                                                                           | No file changes                                              |
| `update-factory --check` with header changes      | Candidate has different headers than installed  | Report shows planned header changes                                                                                       | No file changes                                              |
| `update-factory --check`                          | No install manifest present                     | Error reported, non-zero exit                                                                                             | No file changes                                              |

## Boundaries

- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.
- Check mode must not create staging directories, temporary files, or any filesystem artifacts.
- Check mode must not modify the install manifest.
- Actual update application is out of scope — ST-0285 handles that.

## Demo Scenario

1. Install Factory version `1.0.0` using `install-agent-factory --from-remote https://releases.example.com --target ./project --version 1.0.0`.
2. Publish version `1.1.0` to the same remote.
3. Run `update-factory --check` in `./project`.
4. The report shows installed version `1.0.0`, candidate version `1.1.0`, the source URL, the candidate archive digest, no local modifications, and any planned header changes.
5. Verify that no files in `./project` changed.
6. Modify a Factory-owned file in `./project/.agent-factory/factory/`.
7. Run `update-factory --check` again.
8. The report lists the modified file.
9. Verify that no files in `./project` changed.

## Demo Data

None. The demo exercises `update-factory --check` against an existing installation and a distribution remote with a newer version.

## Evidence

- [ ] `update-factory --check` exits without changing any file in the installation.
- [ ] The check report shows the installed and candidate versions.
- [ ] The check report shows the installation source and the candidate digest.
- [ ] When Factory-owned files differ from their installed state, the check report lists the modified files.
- [ ] When instruction headers would change, the check report shows the planned header changes.
- [ ] Check mode creates no staging directories, temporary files, or manifest updates.

## Stop Conditions

- The install manifest schema (`.agent-factory/install.json`) does not contain fields for installed version, source, or file checksums — report what fields are available and ask.
- The candidate version resolution requires network access that differs between local and remote sources — report both paths and ask for the resolution strategy for each source type.
- The local modification detection algorithm (file checksums, timestamps, or content comparison) is not specified — report and ask.
- Code in `packages/factory/scripts/update-factory` and the feature spec disagree on what the check report contains or whether check mode performs writes — report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. How does `update-factory` detect local modifications to Factory-owned files? Does the manifest record per-file checksums, or does the script compare against the installed archive?
2. How does check mode resolve the candidate version for a local source (where there is no remote release to query)?
