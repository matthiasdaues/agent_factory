# Integrate two-pass TDD into developer agent and record test traceability in story files and template

The developer agent gains `test-design` as a skill, invokes it conditionally post-GREEN, and writes `tests:` and `test-design-pass` fields into story frontmatter at commit time. The story template documents both fields.

**Priority:** must-have

## Demo

A developer agent picks up a non-`.feature`-governed story. After RED-GREEN-REFACTOR (pass 1: tests derived from acceptance criteria), it invokes `test-design` against the implemented code (pass 2). The skill identifies one additional integration test. The developer agent authors it. At commit time, the developer agent writes `tests: [tests/unit/test_widget.py, tests/integration/test_widget_seam.py]` and `test-design-pass: done` into the story file's frontmatter. A second developer agent picks up a `.feature`-governed story. After GREEN, it skips the `test-design` invocation and writes `test-design-pass: skipped-feature-governed`. The user reads the story template at `factory/rulebooks/templates/story.md` and sees both fields documented.

## Acceptance Criteria

- The developer agent's skill list at `factory/agents/developer-agent.md` includes `test-design` (completion criterion 5).
- After GREEN on non-`.feature`-governed stories, the developer agent invokes `test-design` to identify and author integration and edge-case tests (completion criterion 5).
- The developer agent skips the post-TDD `test-design` invocation for `.feature`-governed stories (completion criterion 6).
- The developer agent writes the `tests:` field in the story file at commit time, listing test modules the story owns (completion criterion 7).
- The developer agent writes the `test-design-pass` field in the story file at commit time: `done` or `skipped-feature-governed` (completion criterion 8).
- The story template at `factory/rulebooks/templates/story.md` documents the `tests:` and `test-design-pass` fields with their purpose and valid values (completion criterion 17).

## Scope

**Status quo:** The developer agent at `packages/factory/agents/developer-agent.md` (v0.6.1) has skills `implement-issue`, `spec-feedback`, and `handoff`. Its RED phase evaluates three conditions in order: failure scenarios, prior tests, freestyle. It does not invoke `test-design` and does not write `tests:` or `test-design-pass` fields. The story template at `packages/factory/rulebooks/templates/story.md` (v2.0.0) documents `id`, `epic`, `title`, `tier`, `status`, `deps`, `traces`, `touches`, `concerns`, and `quality-gates` — no `tests:` or `test-design-pass` fields. ST-0228 delivers the rewritten `test-design` skill.

**Delivers:** The developer agent's skill list includes `test-design`. Its workflow gains a two-pass TDD model: pass 1 (acceptance-criteria TDD, unchanged), pass 2 (conditional `test-design` invocation post-GREEN for non-`.feature` stories). The commit step writes `tests:` and `test-design-pass` into story frontmatter. The story template documents both fields.

**Out of scope:** Rewriting the test-design skill itself (ST-0228). QA agent review criteria (ST-0230). Reconciliation agent audit (ST-0231). Gate adaptation (ST-0232). Backward compatibility for pre-existing `#### Failure scenarios` — the developer agent's existing conditional path handles these already; this story does not change that path.

## Notes for the Implementer

The developer agent's RED phase logic (the "evaluate three conditions" block) stays as-is for backward compatibility with old stories. The two-pass TDD model adds a new step after GREEN, before the commit step. The `.feature`-governed check reads the story's `traces:` frontmatter — if any trace references a `.feature` Rule, the story is `.feature`-governed and pass 2 is skipped. The story template update adds two fields to the frontmatter example and two new subsections under "Frontmatter Fields" explaining each field's purpose and valid values.
