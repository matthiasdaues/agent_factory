# Follow each playbook to the new owner

**Priority:** must-have

## Goal

The human operator reads the new owner in every playbook step that produces a moved artifact. `run-step` states that the declared inputs set the order of the producers, and that the operator chooses when two agents are eligible.

## Contract

| Playbook or skill                                                    | Step that produces                     | Names                                                                                    |
| -------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| `feature-addition`                                                   | the structure files                    | domain-modeling agent                                                                    |
| `feature-addition`                                                   | the QA strategy                        | test-strategy agent                                                                      |
| `greenfield-development`                                             | the structure files                    | domain-modeling agent                                                                    |
| `greenfield-development`                                             | the QA strategy                        | test-strategy agent                                                                      |
| `brownfield-onboarding`                                              | glossary, entity model, state machines | domain-modeling agent                                                                    |
| `documentation-update`                                               | the fix of a stale core file           | the owner in each report row                                                             |
| `feature-addition`, `greenfield-development`, `documentation-update` | the review loop over open findings     | the agent in each finding's `owner:`; the loop reads all open findings, not `RECON-*.md` |
| `run-step`                                                           | the order of the producers             | the declared inputs; the operator chooses between two eligible agents                    |

## Demo Scenario

1. The operator reads the structure-file step of `packages/factory/playbooks/feature-addition.md`. It names the domain-modeling agent.
2. In the fixture `accepted-proposal` (Demo Data), the operator follows `run-step`. The requirements agent is eligible first, then the domain-modeling agent, then the spec-review agent.
3. In `review-running`, `run-step` shows the test-strategy agent beside the spec-review agent, and the operator chooses.

## Analysis

- Four playbooks name the owner of each moved artifact. `feature-addition` and `greenfield-development` name the `domain-modeling-agent` for the structure files and the `test-strategy-agent` for the QA strategy. `brownfield-onboarding` names the `domain-modeling-agent` for Steps 3.1, 3.2 and 3.7. `documentation-update` names the owner of each report row as the fixer of a stale core file.
- The three review loops read all open findings in `docs/findings/*.md` and send each one to the agent in its `owner:`. The `RECON-*` searches and the `RECON-*` input in the step frontmatter are gone.
- `run-step` states that the declared inputs set the order of the producers, and that the operator chooses between two eligible agents.
- Files changed: `packages/factory/playbooks/feature-addition.md`, `greenfield-development.md`, `brownfield-onboarding.md`, `documentation-update.md`, `packages/factory/skills/run-step/SKILL.md`, and the text checks in `tests/factory/test_core_artifact_ownership_text.py`.
- Scenario covered: "Human operator reaches the new owners through the playbooks and the routing" (CAO-18-LN-01).
- Not in this story: `intent select` and the demo fixtures. The demo steps run only on the fixtures, which this story does not build.
