# Follow each playbook to the new owner

**Priority:** must-have

## Goal

The human operator reads the new owner in every playbook step that produces a moved artifact. `run-step` states that the declared inputs set the order of the producers, and that the operator chooses when two agents are eligible.

## Contract

| Playbook or skill        | Step that produces                     | Names                                                                 |
| ------------------------ | -------------------------------------- | --------------------------------------------------------------------- |
| `feature-addition`       | the structure files                    | domain-modeling agent                                                 |
| `feature-addition`       | the QA strategy                        | test-strategy agent                                                   |
| `greenfield-development` | the structure files                    | domain-modeling agent                                                 |
| `greenfield-development` | the QA strategy                        | test-strategy agent                                                   |
| `brownfield-onboarding`  | glossary, entity model, state machines | domain-modeling agent                                                 |
| `documentation-update`   | the fix of a stale core file           | the owner in each report row                                          |
| `run-step`               | the order of the producers             | the declared inputs; the operator chooses between two eligible agents |

## Demo Scenario

1. The operator reads the structure-file step of `packages/factory/playbooks/feature-addition.md`. It names the domain-modeling agent.
2. In the fixture `accepted-proposal` (Demo Data), the operator follows `run-step`. The requirements agent is eligible first, then the domain-modeling agent, then the spec-review agent.
3. In `review-running`, `run-step` shows the test-strategy agent beside the spec-review agent, and the operator chooses.

## Demo Data

| Fixture             | Content                                                                                                   |
| ------------------- | --------------------------------------------------------------------------------------------------------- |
| `accepted-proposal` | `docs/proposals/payments.md` with `status: accepted`; no `docs/spec/`                                     |
| `review-running`    | `docs/spec/features/payments.feature`, `entity-model.md`, `interface-contracts.md`; no spec-review report |

- The `intent` routing of the two new agents comes from ST-0348 and ST-0357.
