# Read the guide's content as typed pages in the user handbook

A user opens the installed user handbook and finds each topic of the old guide on a short page of one type, in the chapter that owns its concept.

**Priority:** must-have

## Goal

A user who runs `update-factory` finds twelve chapters under `.agent-factory/factory/docs/handbook/`, and each topic of `factory-guide.md` sits on a page of the right type. The migration map names the page that holds each section of the guide. The guide itself stays in place until ST-0454 deletes it.

## Domain Rule

- The page types follow the type table of the proposal ([§ Page format](../docs/proposals/factory-handbooks.md#page-format)). A page holds what its `type` allows and leaves out what the table excludes.
- Each section of the guide at commit `4ebf5101f70c1540a0d53dcfb3d00cfa977d361a` keeps its facts, commands, and paths on the page that the migration map names. The text is rewritten in the factory voice (acceptance criterion 12).
- A page describes what the code does today. A topic of a chapter brief that no code supports yet becomes a stub.
- A page repeats a binding rule only in a `> Rule summary:` callout followed by a `> Source:` line that links to `packages/factory/rulebooks/` (BR-149, acceptance criterion 10).
- Guide content goes to the user handbook only, because an installed user never sees the contributor handbook (L-42).
- The `playbooks/` chapter documents the playbooks that exist today (DEC-11).
- The `installation-and-updates/` chapter names the current path `.agent-factory/user-changes/<timestamp>/` (PROP-05).

The proposed home of each guide section is a starting point. The developer may split a section over several pages or move it to another chapter when its concept belongs there, and records each choice in the migration map.

## Demo Scenario

1. The user runs `.agent-factory/factory/scripts/update-factory` in a project that holds the previous release.
2. The user opens `.agent-factory/factory/docs/handbook/index.md` and sees the twelve chapters, `getting-started/` first.
3. The user opens `getting-started/index.md` and follows the link under "Tutorials" to the tutorial page. It walks the steps of the guide's "Getting Started" section.
4. The user opens `installation-and-updates/index.md`, follows the how-to "Use the factory in an existing repository", and finds the brownfield order that the guide's "Using this in an existing repo" section gave.
5. The contributor opens `docs/spec/work/factory-handbooks-migration-map.md` and finds a row for each heading of the guide, each naming an existing page.

## Demo Data

None. The demo uses the page titles the developer writes. Step 4 names the expected title of the brownfield how-to; the developer may choose another title and records it in the map.

## Boundaries

- A user handbook page links only to files inside `packages/factory/`, because only those files install into a project. A link to this repository's `docs/` breaks in a user project (PROP-07).
- No page states a binding rule in ordinary prose (DEC-02). The code review checks this and the type table (QA strategy § Review checks).
- The story does not delete, shorten, or relink `factory-guide.md`. ST-0454 deletes it after every reference moves.
- No chapter folder holds a subfolder (BR-141, L-14).
- Every page passes `handbook-lint`, and `handbook-index` writes the page lists in the same commit.
- `test_core_layout_references.py` keeps its scan of every spec-writer file, with the handbook page in place of the guide. `test_brownfield_order.py` and `test_hook_missing_factory.py` keep their content checks and read the page that now holds the checked text (acceptance criterion 06).
- No edit of the feature file, `validation-rules.md`, `interface-contracts.md`, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-ST-0453.md`.
- `quality-gates` is empty, because the story changes Markdown and tests, not production code.

## Agent Stop Conditions

- A guide section describes behaviour that the code no longer has. Report the section and the code; do not document the old behaviour as current.
- A guide section holds a binding rule that no rulebook holds. Report the rule and the rulebook that should own it; do not keep it in a page.
- A chapter of the proposal gets no guide content and no code supports a page for it. Write its `index.md` only and report the chapter.
- The code and the proposal's chapter brief disagree on a path or a command. Report the conflicting files and the decision needed; do not add a workaround.

## Analysis

The story moves the content of `factory-guide.md` at `4ebf5101` into the user handbook. The guide at that commit and the guide in the worktree are identical, so the worktree copy is the source.

**What is built.** Twelve chapter folders under `packages/factory/docs/handbook/`, each with an `index.md` and its pages. The `Getting Started` section becomes the tutorial `getting-started/first-session.md`. Its background subsections move to the chapters that own their concepts: the five words and the author and reviewer split to `concepts/`, the files on disk to `reference/`, and the playbook table to `playbooks/`. The long sections split by type, for example `Linting and gating` into a concept page, a reference page, and pages in `branches-and-dispatch/` and `reference/`. The migration map `docs/spec/work/factory-handbooks-migration-map.md` holds one row for each heading of the guide, the title heading included.

**Files.** The pages under `packages/factory/docs/handbook/`, the migration map, and the three tests. `test_core_layout_references.py` scans every user handbook page in place of the guide. `test_brownfield_order.py` reads `playbooks/playbook-kinds.md`, which holds the paragraph "Brownfield has two stages". `test_hook_missing_factory.py` reads `quality-and-review/pre-commit-hooks.md`, which explains the key `agent-factory.installed`.

**Scenarios.** The story owns no Scenario row. FH-05-01 of ST-0454 reads the map this story writes.

**Checks against the code.** Three guide facts differ from the code:

- `update-factory` saves user changes under `.agent-factory/user-changes/<timestamp>/` (`USER_CHANGES_DIR`, `packages/factory/scripts/update-factory:146`). The guide and PROP-05 name `.agent-factory/factory-user-changes/<timestamp>/`. The page names the path of the code, and a spec-feedback row reports the conflict.
- `packages/factory/` holds `docker/` and `themes/`, which the guide's tree leaves out. The reference page lists them.
- The guide links to ADRs and a proposal under the repository's `docs/`. A user handbook page links only inside `packages/factory/` (PROP-07), so the pages name these files without a link.
