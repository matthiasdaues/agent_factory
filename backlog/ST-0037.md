# Claude Code transcript normalizer

Parse a Claude Code session or sub-agent `.jsonl` transcript into one plain
text stream for tokenizing, and — in the same read — extract the
per-message provider `usage` into the `reported_*` fields. One transcript
read yields both counts: `normalized_*` from tokenizing the text and
`reported_*` from the recorded usage, at `full` granularity.

The normalizer sits behind a per-CLI interface so that adding Pi or Copilot
later is a new normalizer, not a rewrite. Only the Claude Code normalizer
ships in this release.

**Priority:** must-have

## Acceptance Criteria

- A normalizer interface is defined as `parse(transcript_path)` returning a
  text stream plus the reported-usage totals, selectable per `cli`.
- The Claude Code normalizer reads the `.jsonl` transcript and concatenates
  the full run text — system prompt, every turn, tool inputs and tool
  results, and thinking — into one stream, not only the boundary prompt and
  final output.
- Where the transcript records per-message `usage`, the normalizer sums it
  into `reported_input`, `reported_output`, `reported_cache_read`, and
  `reported_cache_write` and sets `usage_granularity` to `full`.
- The `normalized_input` / `normalized_output` split is derived from message
  role so the two counts are meaningful.
- A fixture Claude Code `.jsonl` transcript proves both `normalized_*` and
  `reported_*` are produced from a single read.
- A transcript lacking usage fields still yields `normalized_*`, with
  `reported_*` left null and `usage_granularity` recorded accordingly.

## Analysis

Traces to Use Cases via spec sections "The Capture Tool" (normalizer as a
per-CLI internal seam), "Tokenization Strategy" (full-transcript scope, one
read yields both counts), and "The Usage Record" (`normalized_*`,
`reported_*`, `usage_granularity`).

**Seam.** A `TranscriptNormalizer` Protocol with one method
`parse(transcript_path) -> NormalizedTranscript`, selected per `cli` through
`get_normalizer(cli)`. Only `ClaudeCodeNormalizer` is registered now; a Pi or
Copilot normalizer is a new registry entry, not a rewrite (OCP). `parse`
returns text plus the reported-usage totals from one read; token counting
stays a separate step (`count_tokens`), so the normalizer needs no tiktoken.

**`NormalizedTranscript`.** Carries `input_text`, `output_text` (the
role-split streams), an ordered full-run `text` property (for the persisted
copy and whole-run tokenizing), and the four `reported_*` totals plus
`usage_granularity`. `normalized_input = count_tokens(input_text)`,
`normalized_output = count_tokens(output_text)`.

**Role -> input/output mapping** (block-type first, message-role fallback):

- `tool_result` block -> input.
- `tool_use` block -> output.
- `thinking` block -> output.
- plain `text`/string block -> message role: `assistant` -> output;
  `user`/`system`/`tool`/unknown -> input.

Block-type-first keeps tool inputs (model-produced) as output and tool
results (fed back in) as input even if a transcript nests them unusually,
while the role fallback classifies ordinary text turns. Both counts stay
meaningful.

**Usage summation.** Per line, read `message.usage` (fallback `obj.usage`),
summing `input_tokens -> reported_input`, `output_tokens -> reported_output`,
`cache_read_input_tokens -> reported_cache_read`,
`cache_creation_input_tokens -> reported_cache_write`. If any usage object is
seen, `usage_granularity = full`. If none is seen, `reported_* = null` and
`usage_granularity = null` — the documented "none" case: no reported
breakdown exists to characterize, so `full | aggregate` is not asserted.

**Tolerance.** Malformed lines (non-JSON) are skipped, never raised on
(spec: best-effort). Content may be a plain string or a list of typed
blocks; missing/extra keys are tolerated.
