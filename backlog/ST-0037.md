# Claude Code transcript normalizer

Parse a Claude Code session or sub-agent `.jsonl` transcript into one plain
text stream for tokenizing, and — in the same read — extract the
per-message provider `usage` into the `reported_*` fields. One transcript
read yields both counts: `normalized_*` from tokenizing the text and
`reported_*` from the recorded usage, at `full` granularity.

The normalizer sits behind a per-CLI interface so that adding Pi or Copilot
later is a new normalizer, not a rewrite. Only the Claude Code normalizer
ships in this release.

**Priority:** must-have

## Acceptance Criteria

- A normalizer interface is defined as `parse(transcript_path)` returning a
  text stream plus the reported-usage totals, selectable per `cli`.
- The Claude Code normalizer reads the `.jsonl` transcript and concatenates
  the full run text — system prompt, every turn, tool inputs and tool
  results, and thinking — into one stream, not only the boundary prompt and
  final output.
- Where the transcript records per-message `usage`, the normalizer sums it
  into `reported_input`, `reported_output`, `reported_cache_read`, and
  `reported_cache_write` and sets `usage_granularity` to `full`.
- The `normalized_input` / `normalized_output` split is derived from message
  role so the two counts are meaningful.
- A fixture Claude Code `.jsonl` transcript proves both `normalized_*` and
  `reported_*` are produced from a single read.
- A transcript lacking usage fields still yields `normalized_*`, with
  `reported_*` left null and `usage_granularity` recorded accordingly.
