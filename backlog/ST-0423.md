# File an unresolved mutant as a QA finding whose owner follows the cause

**Priority:** must-have

## Goal

A story merges while its surviving mutant is filed as a blocking `QA` finding, and that finding names its owner by the cause. At the wave close the implementation agent routes the open `QA` findings by owner, and one with `owner: planning-agent` runs in the next wave.

## Domain Rule

- The gate-check step files a blocking `QA` finding for a surviving mutant it cannot resolve. The owner is `planning-agent` for a test the step could not write, and `test-strategy-agent` for a mutant that no test should kill (RL-G24).
- Each `file-qa-finding` entry of the result file has the field `finding`, and `premerge-check` checks that the named finding file exists (BR-066).
- After a non-zero mutation command, the gate passes only when `mutants` holds at least one survivor and none is `unresolved`. A missing list, an empty list, a list without a survivor, or a time-out fails (RL-G25, OI-19).
- At the wave close, a `QA` finding with `owner: test-strategy-agent` goes to that agent, and the next wave waits until every such spawn returns. A finding with `owner: planning-agent` enters the next wave through `dispatch add`.

## Outputs

- `skills/mutation-testing/SKILL.md` writes the owner by cause and the field `finding`.
- The mutation gate result rule in `mutation-testing` and `premerge-check`.
- `implementation-agent.md` routes `QA` findings at the wave close.
- `test_st_0358_file_qa_finding_names_path_and_owner` changes in the same commit.

## Demo Scenario

1. In an orchestrated run, the gate-check step of ST-0350 cannot write a test that kills one mutant. It files `docs/findings/QA-0012.md` with `owner: planning-agent`, and the result file entry has `finding: QA-0012`.
2. `dispatch merge-story ST-0350` passes.
3. At `close-wave 1`, the implementation agent runs `dispatch add QA-0012`, and `dispatch status` shows QA-0012 in wave 2.
4. A result file with an empty `mutants` list and a non-zero exit makes `merge-story` of a second story exit 1.

## Boundaries

- An `unresolved` mutant always blocks its story's merge.
- No edit of `docs/proposals/mutation-gate.md`; its DEC-09 is a follow-up outside this backlog.
- `packages/factory/INDEX.yaml` is regenerated in the same commit.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.
