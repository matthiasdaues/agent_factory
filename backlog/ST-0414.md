# Rerun the gates at the branch head in a temporary worktree

**Priority:** must-have

## Goal

`premerge-check` refuses a branch head that fails a gate, even when a passing result file for that gate exists under `.current-work/`. The rerun leaves the primary checkout and the story's checkout exactly as they were.

## Domain Rule

- Each story merge check adds a temporary worktree at `.current-work/<feature-branch>/premerge/<id>` and removes it afterwards (BR-123).
- The gates run there with their full commands, tests included. No stored result counts, except for `mutation-testing`.
- The gate scripts come from the installed copy of the calling checkout, with the temporary worktree as the source root. The worktree builds its own `uv` environment (OI-10).
- Without `docs/spec/dependency-rules.dsl`, `premerge-check` skips `dependency-check` and names the skip.
- A worktree left by a crashed check does not block the next check.
- An untracked test file in the story's checkout takes no part in the rerun and is back afterwards.

## Outputs

- `premerge-check` runs the gates in the temporary worktree in place of reading result files.
- The `test_st_0359_*` tests that read stored results change to the rerun, as the retention policy lists.

## Demo Scenario

1. In an orchestrated run, ST-0350's head breaks a rule of `dependency-rules.dsl`, and `.current-work/dependency-check/` holds a passing result. `dispatch merge-story ST-0350` exits 1 and names `dependency-check`.
2. The primary checkout holds a changed tracked file and an untracked file. After a passing check, `git status` and `git stash list` show both files unchanged and no stash.
3. `git worktree list` shows no `premerge/ST-0350` worktree after the check.

## Demo Data

None. The tests build a repository with `docs/spec/dependency-rules.dsl` holding one rule and a story branch that breaks it.

## Boundaries

- The rerun never touches a file of the primary checkout or of the story's checkout.
- No stash is made.
- The stored result of `mutation-testing` still counts until `mutation-gate.md` settles it.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.

## Affected Paths

- `packages/factory/scripts/premerge-check` — temporary worktree, gate rerun, skip notice, crash recovery
- `tests/factory/` — new rows in `test_run_lifecycle_premerge.py`; changed `test_st_0359_*` tests in `test_premerge_check.py`
