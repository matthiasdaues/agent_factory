# Write feature files and working output to their folders

**Priority:** must-have

## Goal

The requirements agent, run on an accepted proposal named `payments`, writes
`docs/spec/features/payments.feature` and puts the gaps report, the QA strategy,
and `prd.md` into `docs/spec/work/`. The spec-review agent and the
specification skills read the core at its new paths.

## Contract

| Operation                                               | Input state      | Outcome                                                                                                            | Persistence       |
| ------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------- |
| `requirements-agent` on proposal `payments`             | Migrated project | `docs/spec/features/payments.feature`; `docs/spec/work/payments-gaps.md`; `docs/spec/work/payments-qa-strategy.md` | New files         |
| `write-prd`                                             | Migrated project | `docs/spec/work/prd.md`                                                                                            | New file          |
| `spec-review-agent`                                     | Migrated project | Reads feature files in `features/` and supplementary specs at the top of `docs/spec/`                              | Findings as today |
| Templates `qa-strategy.md`, `proposal.md`, `finding.md` | —                | Name only new paths                                                                                                | —                 |

## Demo Scenario

1. In the migrated fixture `requirements-project` (Demo Data), the maintainer
   runs the requirements agent on the accepted proposal
   `docs/proposals/payments.md`.
2. `ls docs/spec/features/` shows `payments.feature`.
3. `ls docs/spec/work/` shows `payments-gaps.md` and `payments-qa-strategy.md`.

## Demo Data

The agent runs in a session, so the demo uses a hand-built fixture. The retained
test is a text check.

| Fixture                | Content                                                                                                                                                                |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requirements-project` | New layout: `docs/spec/scope-map.md`, `docs/spec/glossary.md`, empty `docs/spec/features/` and `docs/spec/work/`, `docs/proposals/payments.md` with `status: accepted` |

## Boundaries

- Feature files land in `docs/spec/features/`; working output lands in
  `docs/spec/work/` (DEC-05).
- Supplementary specs live at the top of `docs/spec/`; area specs in
  `docs/spec/areas/`.
- Every old path and every `CONTEXT(-MAP)?\.md` mention leaves the files this
  story owns (CAL-G08).
- Source edits go to `packages/factory/`.
- The QA strategy edit adds the requirements-agent scenario to CAL-12-LN-01 and
  changes nothing else in that file.
