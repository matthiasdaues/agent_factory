# Create a validated entity model with projections and persistence

The entity modeler authors a LinkML schema and runs readiness checks that confirm structural correctness, generate documentation projections, and verify persistence behavior.

**Priority:** must-have

## Goal

After this story ships, the entity modeler authors `docs/spec/entity-model.yaml` as a LinkML schema and runs readiness checks. The checks report that the model passes LinkML metamodel validation, that `linkml-lint` finds no errors, that every referenced class and slot resolves, that JSON-backed slots reference defined inline classes, and that every persisted value-object class defines a `schema_version` slot.

The projection generator produces `docs/spec/entity-model.md` and `docs/assets/images/entity-model.svg` from the LinkML source. Neither projection contains information absent from the source.

A generated Pydantic model rejects an invalid payload before the payload reaches persistence. A valid generated value object with a schema-version discriminator stores and retrieves through SQLAlchemy without losing fields or schema-version data.

## Domain Rule

- `docs/spec/entity-model.yaml` is the single canonical domain source. All downstream artifacts derive from the LinkML schema.
- Every referenced class and slot must resolve within the model.
- A slot with a JSON-backed range must reference a defined inline class.
- Every persisted value-object class must define a `schema_version` slot.
- Generated projections must contain no information absent from the source model.
- Generated Pydantic models must reject invalid payloads before the payload reaches persistence.
- A valid generated object must round-trip through SQLAlchemy without data loss.

## Demo Scenario

1. Author `docs/spec/entity-model.yaml` with an entity class (e.g. `Workstream`), a value-object class with a `schema_version` slot (e.g. `UsageRecord`), and a JSON-backed slot referencing an inline class (e.g. `metadata` of type `RecordMetadata`).
2. Run the entity model readiness checks. LinkML metamodel validation passes. Linting reports no errors. All references resolve. The inline-class check passes. The schema-version check passes.
3. Remove a slot from `RecordMetadata`. Run the checks again. Validation reports the unresolved reference.
4. Restore the slot. Run the projection generator. `docs/spec/entity-model.md` and `docs/assets/images/entity-model.svg` appear.
5. Open `entity-model.md`. The documentation contains only entities, attributes, and relationships present in the source YAML.
6. Generate a Pydantic model from `UsageRecord`. Submit a payload missing the `schema_version` field. Pydantic raises a `ValidationError`.
7. Create a valid `UsageRecord` payload with `schema_version` set. Store the object through an SQLAlchemy session into a temporary SQLite database. Retrieve the object. All fields match the original.

## Outputs

**Entity model (`docs/spec/entity-model.yaml`):**

- A LinkML schema defining entity classes, value-object classes with `schema_version` slots, and slots with JSON-backed ranges referencing inline classes. The schema follows LinkML 1.x metamodel conventions.

**Generated projections:**

- `docs/spec/entity-model.md` contains Markdown documentation of all classes, slots, and relationships from the LinkML source. No additional entities, attributes, or relationships appear.
- `docs/assets/images/entity-model.svg` contains an entity-relationship diagram generated from the same source.

**Validation tooling (`packages/factory/engine/validators/entity_model.py`):**

- Runs five readiness checks against `entity-model.yaml`: (1) LinkML metamodel validation, (2) `linkml-lint` with zero errors, (3) all referenced classes and slots resolve, (4) JSON-backed slots reference defined inline classes, (5) persisted value-object classes define `schema_version` slots.
- Returns a structured result compatible with the validator result pattern from `proposal.py`.

**Projection generator (`packages/factory/engine/generators/entity_projections.py`):**

- Generates Markdown and SVG from the LinkML source. Wraps LinkML generation tools (`gen-markdown`, `gen-erdiagram`, or equivalent).

**Tests (`tests/factory/`):**

- `test_entity_model.py`: valid model passes all five readiness checks; model with an unresolved class reference fails; model with a JSON-backed slot missing its inline class fails; value-object class without `schema_version` fails; generated Pydantic model raises `ValidationError` for an invalid payload.
- `test_entity_projections.py`: generated Markdown and SVG contain no classes or slots absent from the source YAML.
- `test_entity_persistence_integration.py`: a valid generated value object stores and retrieves through an SQLAlchemy session with a temporary SQLite database; all fields including `schema_version` match after retrieval.

## Agent Stop Conditions

- If the LinkML version requires Python 3.11+ while the project targets 3.10, stop and ask about the version constraint.
- If `gen-pydantic` or `gen-sqla` output does not support schema-version discriminators natively, stop and ask about the generation strategy.
- If the existing handwritten entity model in `docs/spec/supplementary_specs/entity-model.md` conflicts with the LinkML model's domain classes, stop and ask about reconciliation.
- If SQLAlchemy integration requires a migration framework (Alembic) for the test fixtures, stop and ask about test infrastructure scope.

## Resolve Before Implementation

1. Which LinkML generators produce the Markdown and SVG projections — `gen-markdown` and `gen-erdiagram`, or a different tool chain? The LinkML ecosystem has multiple generation paths. The choice affects dependencies and output format.
2. Where do generated Pydantic models land — in `packages/factory/engine/generated/`, in a separate package, or generated on-the-fly in tests only? Committing generated models enables import-time validation but adds a regeneration step. Generating in tests keeps the tree clean but prevents runtime use.
3. Does the persistence round-trip test use a generated SQLAlchemy model (via `gen-sqla`) or a hand-wired ORM mapping from the Pydantic model? Generated SQLAlchemy models have a tighter LinkML coupling. Hand-wired mappings are more flexible but duplicate schema information.
