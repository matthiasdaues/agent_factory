# QA skills accept explicit base/head SHAs for diff scope

Update the scope-determination step in `fagan-review`, `security-review`, and `bug-hunt` skills plus the `qa-agent` workflow to accept and pass through explicit base/head commit SHAs. Add a three-tier fallback: (1) when base and head commits are provided, use `git diff <base>..<head>`; (2) when a PR number is provided, use `gh pr diff`; (3) fall back to `git diff $(git merge-base HEAD main)..HEAD` only when neither is given.

**Priority:** should-have

## Analysis

This is a documentation-only change affecting four skill/agent definition files. No production code, tests, or imports are involved. The goal is to address ST-0159 by making scope determination explicit and prioritized: explicit commit SHAs > PR number > merge-base fallback.

**Files to modify:**

- `factory/skills/fagan-review/SKILL.md` — Step 1 scope identification
- `factory/skills/security-review/SKILL.md` — Step 1 scope identification
- `factory/skills/bug-hunt/SKILL.md` — add Scope preamble before Phase: Hunt
- `factory/agents/qa-agent.md` — add scope-determination paragraph to Workflow section

**Test seams:** None (documentation-only). Changes validate by inspection against acceptance criteria and by mdformat formatting.

## Acceptance Criteria

- `factory/skills/fagan-review/SKILL.md` Step 1 documents all three scope-determination methods with the specified priority order
- `factory/skills/security-review/SKILL.md` Step 1 documents the same three-tier fallback
- `factory/skills/bug-hunt/SKILL.md` includes a scope preamble with the same three-tier fallback
- `factory/agents/qa-agent.md` workflow section documents how to accept base/head SHAs and pass them through to each skill invocation
- The fallback to `git diff $(git merge-base HEAD main)..HEAD` is explicitly documented as the last resort, not the default
- The phrase "Determine what to review" in each skill is replaced with the explicit three-tier instruction

## Implementation Notes

- The current "Determine what to review" wording causes models to default to `origin/HEAD`, which fails when `origin/HEAD` is dangling (see ST-0159)
- This is a documentation-only change: no scripts, no production code, only skill and agent definition Markdown files
- Tier is economy per dispatch-contract tier rubric: prose-only edits to existing skill definitions
