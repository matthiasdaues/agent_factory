# Generate Codex custom agents from canonical Factory agents

Create a deterministic, standard-library-only adapter from
`factory/agents/*.md` to project-scoped `.codex/agents/*.toml`.

**Priority:** must-have

## Acceptance Criteria

- Every canonical agent generates one TOML file with `name`, `description`, and
  the full Markdown body as `developer_instructions`.
- Generated TOML is parseable, stable, and marked as Factory-owned.
- Re-running refreshes only Factory-owned generated files.
- A real file, directory, or foreign symlink at a destination fails before that
  destination is overwritten.
- No model, reasoning-effort, sandbox, or MCP settings are pinned.
- Focused tests cover multiline descriptions, TOML escaping, idempotent refresh,
  stale owned-file pruning, and foreign collisions.

## Analysis

The generator is a standalone standard-library adapter with two explicit
boundaries: canonical Markdown agent definitions as input and project-scoped
Codex TOML files as output. It parses only the canonical scalar fields and
folded description form needed by `factory/agents/*.md`; the Markdown after
frontmatter is preserved as `developer_instructions`.

Generation is transactional with respect to validation and collision safety:
all sources and desired destinations are preflighted before any owned file is
refreshed or pruned. The focused tests own TOML validity, escaping, stable
refresh, stale owned-file cleanup, and foreign file, directory, and symlink
collisions. No specification change was needed because this story implements
the accepted Codex adapter contract without changing existing Factory
semantics.
