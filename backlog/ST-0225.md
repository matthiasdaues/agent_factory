# Replace project-native file lists with concern references and delete old YAML templates

Sweep all remaining agent and skill definitions to replace project-native file lists (`docs/handbook/`, `docs/spec/supplementary_specs/`, `docs/adr/` paths in `inputs:` sections) with concern references. Delete old YAML templates from `factory/rulebooks/templates/`. After this story, the old YAML files can be deleted without breaking any factory agent, skill, or gate.

**Priority:** must-have

## Demo

The user runs `grep -rn 'docs/agent-context/\*.yaml' factory/agents/ factory/skills/`. Zero matches. The user runs `grep -rn 'docs/handbook/\|docs/spec/supplementary_specs/' factory/agents/` and checks `inputs:` sections. Zero project-native paths remain (factory-canonical paths like `docs/spec/scope-map.md` and `docs/arc42/architecture.dsl` are retained). The user lists `factory/rulebooks/templates/context-*.yaml` -- zero files. The user deletes `docs/agent-context/stack.yaml`, `workflow.yaml`, `governance.yaml`, `reading-guides.yaml`, and the `docs/agent-context/` directory. No factory workflow breaks.

## Acceptance Criteria

- No agent definition `inputs:` list contains `docs/agent-context/*.yaml` references.
- No agent definition `inputs:` list contains `docs/charter/` references.
- No agent definition `inputs:` list contains project-native paths (`docs/handbook/`, `docs/spec/supplementary_specs/`) -- these are replaced with concern references directing the agent to follow relevant concerns in `agent-context.md`.
- Factory-canonical artifact paths (`docs/spec/scope-map.md`, `docs/arc42/architecture.dsl`, `backlog/ST-*.md`, `docs/spec/*.feature`, `docs/spec/prd.md`) are retained as concrete paths.
- `factory/rulebooks/templates/context-stack.yaml`, `context-workflow.yaml`, `context-governance.yaml`, `context-reading-guides.yaml`, and `context-interview-guide.yaml` are deleted.
- The old `docs/agent-context/` YAML files (stack, workflow, governance, reading-guides) can be deleted without breaking any factory agent, skill, or gate.

## Scope

**Status quo:** Agent definitions for architecture-agent, architecture-review-agent, requirements-agent, spec-review-agent, qa-agent, and reconciliation-agent carry project-native file lists in their `inputs:` sections. Five YAML templates exist in `factory/rulebooks/templates/`. Virgil, reconciliation-agent, developer-agent, planning-agent, and implementation-agent are already updated (ST-0222, ST-0223, ST-0224 deliverables).

**Adds:** Concern references replace project-native file lists in remaining agent definitions. YAML templates deleted. The distinction between factory-canonical (retained) and project-native (replaced) paths is applied consistently.

**Out of scope:** Deletion of this project's `docs/agent-context/` YAML files (those are project files, not factory files -- the owner decides when to delete them after migration). Skill definitions that reference agent-context paths but do not carry project-native file lists (those reference factory-canonical artifacts only and need no change).

## Terminology

Factory-canonical artifact: a file with a fixed name, fixed structure, and a factory-defined contract (e.g. `architecture.dsl`, `scope-map.md`, `testing.yaml`). Its path is the contract -- it stays as a concrete path in agent definitions.

Project-native knowledge: documentation that varies by project in shape, location, and quantity (e.g. handbook conventions, cookbook recipes, ADRs, supplementary specs). These are what the concern registry exists for -- agent definitions replace their paths with concern references.
