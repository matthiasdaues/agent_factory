# Refuse to close a wave while a drift row is unhandled

**Priority:** must-have

## Goal

`dispatch close-wave` fails while a row of the wave's spec-feedback reports is `open`, or `fixed` on an artifact of the core list, and names each such row. So the specification lags the code by one wave at most.

## Contract

| Operation    | Input state                                             | Outcome                                                         | Persistence     |
| ------------ | ------------------------------------------------------- | --------------------------------------------------------------- | --------------- |
| `close-wave` | Row `open` on any artifact                              | Exit non-zero; names the report, the artifact, and `open`       | Wave stays open |
| `close-wave` | Row `fixed` on `docs/spec/validation-rules.md`          | Exit non-zero; names the row                                    | Wave stays open |
| `close-wave` | Row `fixed` on `docs/spec/work/payments-qa-strategy.md` | Passes                                                          | Wave closed     |
| `close-wave` | Rows `confirmed` or `rejected`                          | Passes                                                          | Wave closed     |
| `close-wave` | A story of the wave has no report                       | Counts as no rows (CAO-G13)                                     | Wave closed     |
| `close-wave` | Any                                                     | Reads the installed `core-artifacts.yaml` to classify a row     | None            |
| `close-wave` | A row with an unknown status, such as `done`            | Exit non-zero; names the report file and the status (ATAM-0008) | Wave stays open |
| `close-wave` | A report without a row table                            | Exit non-zero; names the report file (ATAM-0008)                | Wave stays open |

## Demo Scenario

1. The operator builds the fixture ledger `wave-2` (Demo Data) and runs `packages/factory/scripts/dispatch close-wave`. It fails and names `spec-feedback-ST-0318.md`, `docs/spec/validation-rules.md`, and `open`.
2. The operator sets the row to `fixed`. `close-wave` still fails, because `validation-rules.md` is on the core list.
3. The operator sets the row to `confirmed`. `close-wave` passes.
4. A `fixed` row on `docs/spec/work/payments-qa-strategy.md` in `spec-feedback-ST-0319.md` does not block.
