# Review the dependency rules against the component view

**Priority:** must-have

## Goal

The architecture-review agent checks `docs/spec/dependency-rules.dsl` against the component view of `architecture.dsl`. In a project without the rules file, the review still runs.

## Contract

| Operation           | Input state                                       | Outcome                                 | Persistence               |
| ------------------- | ------------------------------------------------- | --------------------------------------- | ------------------------- |
| `atam-review`       | A rule names a component the component view lacks | Finding in the review                   | `docs/findings/ATAM-*.md` |
| `atam-review`       | Every rule names existing components              | No finding on the rules                 | Review report             |
| Architecture review | No `dependency-rules.dsl`                         | Review runs; the rules check is skipped | Review report             |

## Demo Scenario

1. The reviewer runs the architecture-review agent on the fixture `rules-unknown-component` (Demo Data). The review files a finding that the rule names `ledger`, which the component view lacks.
2. The reviewer runs it on `no-rules`. The review runs and reports no rules check.

## Demo Data

| Fixture                   | Content                                                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `rules-unknown-component` | `architecture.dsl` with the components `payments` and `api`; `dependency-rules.dsl` with a rule on `ledger` |
| `no-rules`                | `architecture.dsl` with `payments` and `api`; no `dependency-rules.dsl`                                     |

## Analysis

The story changes one skill file and adds one test class. No script changes.

- `packages/factory/skills/atam-review/SKILL.md` gains "Step 1b — Check the dependency rules against the component view". The step skips when `docs/spec/dependency-rules.dsl` does not exist and says so in the report. It files an `ATAM` finding with `owner: architecture-agent` when a rule names a module the component view lacks, or forbids a dependency the view draws as a relationship. Step 4 gets a "Rules check" item in the report.
- The step is numbered 1b, not 2. `finding-format.md` and `report-format.md` link to the anchor of Step 4, and both files lie outside `touches:`.
- `packages/factory/agents/architecture-review-agent.md` already lists `docs/spec/dependency-rules.dsl` as a context input since ST-0353. `packages/factory/rulebooks/core-artifacts.yaml` already marks it `optional: true`. Neither file changes; the text check reads both.
- `tests/factory/test_core_artifact_ownership_text.py` gets the text check CAO-09-LN-01.

Scenarios covered: both Scenarios of the Rule "Architecture-review agent reviews the dependency rules", as text checks.

Stop condition: Step 1 runs `arch-lint`, which reads the components of `architecture.dsl` (`dsl_core_components`). So a step reads the component view, and the stop condition does not apply. Step 1b reads the view itself, because `arch-lint` does not read relationships.

Concern: the first Scenario says the rules file "allows imports from cli to engine". The grammar of `dependency-rules.dsl` has only `must_not_depend_on`, so no rule allows anything. Step 1b checks the form the grammar can express: a forbidden dependency that the view draws. A spec-feedback row records the wording.
