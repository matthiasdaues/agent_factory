# Write concerns into story frontmatter and validate concern references

Update the planning-agent to write a `concerns:` field into each story's frontmatter, declaring which domain and technical concerns apply. Extend backlog-lint to accept the new field. Add the CTX-REFS check to concern-lint so that declared concern names are validated against `agent-context.md` headings. When a story needs a concern not in the registry, the planning-agent proposes the new section for user confirmation.

**Priority:** must-have

## Demo

The planning-agent writes a story with `concerns: {domain: [billing], technical: [backend, data-storage]}` in its frontmatter. Running `backlog-lint` accepts the `concerns:` field without error. Running `concern-lint` confirms via CTX-REFS that "billing", "backend", and "data-storage" all have matching headings in `agent-context.md`. The user changes "billing" to "invoicing" (which has no heading) -- `concern-lint` reports a CTX-REFS finding. The planning-agent encounters an unregistered concern "payments" -- it proposes a new section (name: "payments", description: "Payment processing and gateway integration", Read: docs/spec/supplementary_specs/payment-flow.md) for user confirmation.

## Acceptance Criteria

- The planning-agent writes `concerns:` into story frontmatter with structure `{domain: [string], technical: [string]}` (both keys optional).
- Cross-cutting concerns are not declared in `concerns:` because they are always active.
- The planning-agent draws concern names from the controlled vocabulary in `agent-context.md`.
- When a story needs a concern not in the registry, the planning-agent proposes the new concern section (name, description, initial file list) for user confirmation before adding it.
- backlog-lint accepts `concerns:` as a valid frontmatter field and does not reject stories that include it.
- backlog-lint does not require `concerns:` -- existing stories without the field remain valid.
- `concern-lint` CTX-REFS check validates that every concern name in any story's `concerns:` frontmatter has a matching heading in `agent-context.md`.
- `concern-lint` CTX-REFS reports a finding for each unmatched concern name.
- The story template (`factory/rulebooks/templates/story.md`) documents the `concerns:` field.

## Scope

**Status quo:** The planning-agent writes story frontmatter without a `concerns:` field. backlog-lint validates a closed set of frontmatter fields. concern-lint runs CTX-SECTIONS, CTX-PATHS, CTX-LEGACY (ST-0217 deliverables). The story template documents existing frontmatter fields.

**Adds:** `concerns:` field in planning-agent output. backlog-lint schema extension. CTX-REFS check in concern-lint. Story template documentation. Planning-agent behavioral rule for proposing new concerns.

**Out of scope:** Developer-agent concern consumption (ST-0222). Agent definition file list replacements (EPIC 12).

## Notes for the Implementer

The CTX-REFS check scans all `backlog/ST-*.md` files for `concerns:` frontmatter and cross-references each declared name against the level-3 headings (`###`) under "Technical concerns" and "Domain concerns" in `agent-context.md`. The planning-agent behavioral change is a prose addition to `factory/agents/planning-agent.md` describing when and how to write concerns and when to propose new ones.
