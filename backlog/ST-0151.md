# Update FSM gate conditions to resolve test_command from charter

Update the `script_exit_zero` gate conditions in `bug-fix.fsm.yml` (lines 37-40) and `greenfield-development.fsm.yml` (lines 65-69) to resolve `test_command` from `docs/charter/testing.yaml` instead of referencing `factory/scripts/run-tests --full`.

**Priority:** must-have

## Acceptance Criteria

- `bug-fix.fsm.yml` gate condition resolves `test_command` from `docs/charter/testing.yaml`
- `greenfield-development.fsm.yml` gate condition resolves `test_command` from `docs/charter/testing.yaml`
- If the charter has no `test_command`, the gate reports the gap and blocks advancement
- If `docs/charter/testing.yaml` does not exist, the gate reports the missing charter and blocks advancement
- Gate passes on exit code zero, fails on nonzero exit code
- The gate executes the command from the repository root

## Implementation Notes

- The FSM files use `script_exit_zero` condition type; the value changes from a hardcoded script path to a charter-resolved command
- Transition-lint must still pass on the modified FSM files
- Tier is standard per dispatch-contract tier rubric: risk domain is reliability
