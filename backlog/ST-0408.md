# Start a run by hand or an orchestrated run with dispatch init --mode

**Priority:** must-have

## Goal

The User starts a run in either way of driving it. A run by hand gets no worktree for its feature branch, and an orchestrated run starts beside other active runs. `dispatch status` shows `mode` and `feature_branch`, and `dispatch-contract.md` lists exactly the ledger fields that the code writes.

## Domain Rule

- The ledger's `mode` is `orchestrated` or `by-hand`. Without `--mode`, `init` writes `orchestrated` (BR-111).
- One ledger exists per feature branch, at `.current-work/<feature-branch>/dispatch-ledger.yaml`. Several runs may be active at once. A second run by hand is refused while one is active, because both need the primary checkout (BR-112).
- `init` on a feature branch whose ledger lists the same stories is a no-op that exits 0, so an interrupted start resumes. With other stories, `init` refuses.
- `init` refuses a story whose dependency outside the run is not `done` in the backlog, and names that dependency.
- The branch root is the tip of the feature branch at `init`. The test command comes from `docs/testing.yaml` only.
- The ledger has `feature_branch` in place of `invocation_branch` and no `gate_results` and no `closed`. `dispatch` reads the old names `invocation_branch` and `mode: automated` and writes only the new ones (OI-09).

## Outputs

- `dispatch init` accepts `--mode orchestrated|by-hand`. By hand it cuts the feature branch from `dev` and adds no worktree.
- The refusal of any other active ledger goes; the two refusals of BR-112 stay.
- The ledger model in `dispatch_lib.py` writes the new field names and reads the old ones.
- The fallback to `config/project.json` for the test command goes, with its two tests in `test_dispatch_run_blockers.py`.
- `dispatch-contract.md` lists exactly the fields the code writes, under the code's names.

## Demo Scenario

1. The User asks the implementation agent for a run by hand. The agent runs `dispatch init --mode by-hand --base dev --feature-branch feature/login --stories ST-0350` and exits 0.
2. `dispatch status` shows `mode: by-hand` and `feature_branch: feature/login`. `git worktree list` shows no worktree for `feature/login`.
3. The agent runs `dispatch init --base dev --feature-branch feature/search --stories ST-0352`. The orchestrated run starts beside the first, with a worktree for `feature/search`.
4. The agent runs `dispatch init --mode by-hand --base dev --feature-branch feature/admin --stories ST-0353`. It refuses and names the active run by hand on `feature/login`.

## Demo Data

The tests build a temporary repository with `dev`, `docs/testing.yaml` holding `test_command`, and story files `backlog/ST-0350.md`, `ST-0352.md` and `ST-0353.md` with `status: pending` and no dependencies. No seeding script exists; each test writes its files.

## Boundaries

- `mode` takes only `orchestrated` and `by-hand`. No code writes `automated` or `invocation_branch`.
- `init` reads the backlog for dependencies only at the start of the run. Later commands read the ledger.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.

## Evidence

- [ ] `init --mode by-hand` writes a ledger with `mode: by-hand` and adds no worktree; `init` without `--mode` writes `mode: orchestrated` and adds one (RL-01-IT-01, RL-01-IT-02).
- [ ] The ledger's branch root equals the tip of the feature branch at `init` (RL-01-IT-03).
- [ ] With `docs/testing.yaml` lacking a test command and `config/project.json` holding one, `init` does not take the command from `config/project.json` (RL-01-CT-01).
- [ ] An orchestrated `init` passes while another run is active; a second `init --mode by-hand` refuses while a run by hand is active (RL-01-IT-04).
- [ ] `init` with other stories on an existing ledger refuses; with the same stories it exits 0 and changes nothing (RL-01-IT-05).
- [ ] `init` refuses a story whose dependency outside the run is not `done`, and the message names that dependency (RL-01-IT-06).
- [ ] A ledger written by `dispatch` holds no `gate_results`, `closed` or `invocation_branch`, and a ledger with `invocation_branch` and `mode: automated` loads and saves under the new names (RL-17-CT-01, RL-17-CT-02).
- [ ] The field list of `dispatch-contract.md` equals the field list the code writes (RL-17-LN-01).
- [ ] A second session runs `dispatch status` and the next subcommand on an interrupted run and continues from the ledger (RL-17-IT-02).
