# JSONL logging adapter and transcript persistence

Persist a usage record behind a swappable logging-adapter seam. The JSONL
adapter appends one record per line to
`.agent-factory/usage/<session_id>.jsonl` and persists a copy of the
tokenized transcript so the audit link never dangles when a CLI cleans up
its own scratch transcript. Capture is best-effort: a failure to record must
never fail, block, or slow the run it measures.

The seam is the extension point: a later PostgreSQL adapter replaces the
JSONL adapter in one place without touching any capture site. That adapter
is out of scope here; only its interface is fixed.

**Priority:** must-have

## Acceptance Criteria

- A logging-adapter seam accepts a record plus the tokenized transcript;
  capture sites depend on this interface, not on the JSONL backend.
- The JSONL adapter appends one record per line to
  `.agent-factory/usage/<session_id>.jsonl`, creating the directory on
  demand.
- The adapter writes the tokenized transcript copy to
  `.agent-factory/usage/transcripts/<session_id>/<record_id>.jsonl` and sets
  `transcript_ref` to point at it.
- Appends use POSIX `O_APPEND`; a test writes many records concurrently and
  every line parses as valid JSON with no interleaving or loss.
- Any adapter failure (unwritable path, serialization error) is logged to
  stderr and swallowed, returning without raising, so the caller is never
  affected.
- The PostgreSQL backend is documented as a future adapter behind the same
  seam and is not implemented (deferred).

## Analysis

Traces to "Persistence", "Core Principles", and "Completion Criteria" in
`factory/docs/proposals/token-usage-tracking.md`. Grows
`factory/scripts/usage-capture` (ST-0035's foundation) with the persistence
seam:

- `LoggingAdapter` — a `typing.Protocol` (`@runtime_checkable`), the one
  method capture sites depend on: `record(usage_record, transcript_text)`.
  Its docstring documents the future PostgreSQL adapter as a same-interface
  swap-in (inserts instead of appends, behind a dedicated logging service)
  without implementing it — out of scope here.
- `JsonlLoggingAdapter` — the only implementation. `record()` writes the
  transcript copy first (`.../usage/transcripts/<session_id>/<record_id>.jsonl`),
  sets `transcript_ref`, then appends the serialized record as one line to
  `.../usage/<session_id>.jsonl`. Both directories are created on demand
  (`mkdir(parents=True, exist_ok=True)`). The whole `record()` body runs
  inside a `try/except Exception`, so any failure — mkdir colliding with a
  file, a non-serializable field — is logged to stderr and swallowed;
  `record()` always returns normally.

**Design decision worth flagging — the atomicity mechanism.** The append
uses `os.open(path, O_APPEND | O_CREAT | O_WRONLY)` plus exactly one
`os.write()` call carrying the whole line. POSIX guarantees an O_APPEND
write of this shape (single syscall, position set and write applied
atomically) never interleaves with another process's or thread's append to
the same file, so parallel-dispatch capture sites need no external lock.
The concurrency test exercises this with 100 records fired from 20 threads
at one adapter/session — `os.write` releases the GIL for the syscall, so
threads genuinely race at the OS level, which is what actually exercises
the O_APPEND guarantee (a pure-Python lock would have masked a broken
implementation; this doesn't use one). Every one of the 100 lines parses as
valid JSON with a unique `record_id` — no loss, no interleaving.

Two failure-path tests cover both failure classes the AC names: an
unwritable target (a plain file pre-created where the adapter needs a
directory, so `mkdir` raises) and a serialization error (a non-serializable
value poisoning `json.dumps`) — both are swallowed, both log to stderr
including the `record_id`, neither raises into the caller.

All acceptance criteria verified by
`orchestrator/tests/test_usage_capture.py` (25 tests: the 17 from ST-0035
plus 8 new); `uvx pytest orchestrator/tests/test_usage_capture.py` is fully
green, and the full `orchestrator/tests/` suite (295 tests) still passes.
No spec drift: "Persistence" describes exactly this seam, this append
shape, and this transcript-copy path.
