# JSONL logging adapter and transcript persistence

Persist a usage record behind a swappable logging-adapter seam. The JSONL
adapter appends one record per line to
`.agent-factory/usage/<session_id>.jsonl` and persists a copy of the
tokenized transcript so the audit link never dangles when a CLI cleans up
its own scratch transcript. Capture is best-effort: a failure to record must
never fail, block, or slow the run it measures.

The seam is the extension point: a later PostgreSQL adapter replaces the
JSONL adapter in one place without touching any capture site. That adapter
is out of scope here; only its interface is fixed.

**Priority:** must-have

## Acceptance Criteria

- A logging-adapter seam accepts a record plus the tokenized transcript;
  capture sites depend on this interface, not on the JSONL backend.
- The JSONL adapter appends one record per line to
  `.agent-factory/usage/<session_id>.jsonl`, creating the directory on
  demand.
- The adapter writes the tokenized transcript copy to
  `.agent-factory/usage/transcripts/<session_id>/<record_id>.jsonl` and sets
  `transcript_ref` to point at it.
- Appends use POSIX `O_APPEND`; a test writes many records concurrently and
  every line parses as valid JSON with no interleaving or loss.
- Any adapter failure (unwritable path, serialization error) is logged to
  stderr and swallowed, returning without raising, so the caller is never
  affected.
- The PostgreSQL backend is documented as a future adapter behind the same
  seam and is not implemented (deferred).
