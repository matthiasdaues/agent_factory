# Seed a project's counter and claim the next ID from it

**Priority:** must-have

## Goal

The User seeds a project's counter once with `next-id --seed`, and every `next-id <PREFIX>` then prints the next ID of that ID prefix. The claim works on `origin` or on a remote named with `--remote`, also outside any clone, and leaves the clone unchanged. A seed never changes a counter that exists.

## Contract

| Operation                             | Input state                                                              | Outcome                                                                                                  | Persistence                                                          |
| ------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `next-id --seed 1000`                 | No `refs/ids/counters` on `origin`                                       | Prints the line `start=1000`; exit `0`                                                                   | `refs/ids/counters` points at a claim commit with `start=1000`       |
| `next-id --seed 1000 ADR=6`           | No counter                                                               | Prints `start=1000` and `ADR=0006`; exit `0`                                                             | Claim commit holds `start=1000` and `ADR=0006`                       |
| `next-id --seed 1000`                 | Counter exists with `ST=1012`                                            | Exit non-zero; names the remote and `refs/ids/counters`                                                  | Ref at the same SHA as before                                        |
| `next-id --seed <arg>`                | `10000`, `abc`, `9999`, `-1`, `1000 XX=5`, `1000 ST=x`, `1000 ST=5 ST=7` | Exit non-zero before the remote is contacted; names the argument, the prefix and the list, or the prefix | No ref created                                                       |
| `next-id --seed 1000`, twice at once  | No counter                                                               | One call exits `0`, the other exits non-zero                                                             | Exactly one claim commit                                             |
| `next-id --seed 1000`                 | No `origin`, no `--remote`                                               | Exit non-zero; names `origin` and `--remote`                                                             | None                                                                 |
| `next-id --seed 1000`                 | `origin` does not answer                                                 | Exit non-zero; names the remote and git's error                                                          | None                                                                 |
| `next-id ST`                          | Claim commit holds `start=1000`, `ST=1012`                               | Prints `ST-1013` alone on standard output; exit `0`                                                      | New claim commit holds `ST=1013`, `start=1000`, and a new token      |
| `next-id BUG`                         | Same; no `BUG` line                                                      | Prints `BUG-1001`                                                                                        | Claim commit holds `BUG=1001` and `ST=1012`                          |
| `next-id FAGAN`                       | `start=1000`, `ST=1012`, `FAGAN=1003`                                    | Prints `FAGAN-1004`                                                                                      | `start=1000`, `ST=1012`, `FAGAN=1004`; the token line differs        |
| `next-id <prefix>`                    | Each of the ten ID prefixes, no line yet                                 | Prints `<prefix>-1001`                                                                                   | Line `<prefix>=1001`                                                 |
| `next-id XX`                          | Any; also `PROP`, `RETRO`                                                | Exit non-zero before any remote is read; nothing on standard output; names `XX` and the list             | None                                                                 |
| `next-id ST`                          | Clone without `user.name` and `user.email`                               | Exit `0`                                                                                                 | Author and committer `next-id <next-id@agent-factory.invalid>`       |
| `next-id ST`                          | Clone rewrites the `origin` URL with `url.<base>.insteadOf`              | Exit `0`                                                                                                 | Claim lands on the URL that `git remote get-url origin` prints       |
| `next-id ST --remote /tmp/remote.git` | Clone whose `origin` holds `ST=1012`; `/tmp/remote.git` holds `ST=1040`  | Prints `ST-1041`                                                                                         | `origin` still holds `ST=1012`                                       |
| `next-id ST --remote /tmp/remote.git` | Current directory outside any git repository                             | Prints an `ST` ID; exit `0`                                                                              | Line `ST` raised on `/tmp/remote.git`                                |
| `next-id ST`                          | Any claim, successful or failed                                          | —                                                                                                        | Clone has the same refs and objects; the throwaway directory is gone |
| `next-id ST`                          | No counter on `origin`                                                   | Exit non-zero; nothing on standard output                                                                | None                                                                 |

## Demo Scenario

1. The User creates the local bare repository `/tmp/remote.git` and clones it to `/tmp/clone` (Demo Data).
2. In `/tmp/clone`, the User runs `next-id --seed 1000 ADR=6`. It prints `start=1000` and `ADR=0006` and exits `0`.
3. The User runs `next-id --seed 1000` again. It exits non-zero and names `/tmp/remote.git` and `refs/ids/counters`.
4. The User runs `next-id ST` twice. It prints `ST-1001`, then `ST-1002`. `next-id ADR` prints `ADR-0007`.
5. The User runs `next-id PROP`. It exits non-zero, prints nothing on standard output, and names `PROP` and the list of ID prefixes.
6. The User runs `git for-each-ref` in `/tmp/clone` before and after `next-id BUG`. The output is the same, and `next-id BUG` printed `BUG-1001`.
7. In `/tmp`, outside any repository, the User runs `next-id FAGAN --remote /tmp/remote.git`. It prints `FAGAN-1001`.

## Demo Data

| ---------------- | ----------------------------------------------------------------------------------- |
| Bare repository  | `/tmp/remote.git`, made with `git init --bare`, no `refs/ids/counters`              |

No seeding script exists for this feature. The test fixtures write a given counter state inside the bare repository with `git commit-tree` and `git update-ref`, as the [QA strategy § Test setup](../docs/spec/work/counter-ids-qa-strategy.md#test-setup-on-a-local-bare-repository) describes.

## Boundaries

- `next-id` is a Python script, like `init-factory` and `backlog-lint`, so contract tests import it with `load_script` from `tests/conftest.py`.
- The prefix list lives in `next-id` and holds exactly the ten ID prefixes of BR-068. No config file exists (DEC-18).
- The script checks the prefix or the seed arguments before it looks for the remote.
- A claim runs in a new bare repository made with `git init --bare --template=` in a temporary directory, deleted at every exit (BR-075). It never writes to the clone.
- `next-id` runs every git command with `LC_ALL=C`.
- A seed pushes only with `--force-with-lease=refs/ids/counters:` and never retries. A claim pushes only with `--force-with-lease=refs/ids/counters:<old sha>`.
- Every number in a claim commit has four digits (BR-070).
- On failure, `next-id` prints nothing on standard output and writes its message to standard error.
- Tests never touch the project's real remote. Each test sets `HOME` to an empty directory and sets `GIT_CONFIG_NOSYSTEM=1` and `GIT_TERMINAL_PROMPT=0`.
- `quality-gates: []` because the installed Factory is not yet updated for gates.

## Resolve Before Implementation

These questions are open for the stakeholder at step 3.4. The story does not wait on them, because its tests assert nothing on these cases:

1. Does the seed output hold the token line (`Gap: CID-G03`)? The tests check the `start` line and the pair lines only.

3. What does a claim do on a claim commit without a `start` line, or with a line that is not a number (`Gap: CID-G05`)?
4. Does `--seed` also run in a throwaway repository and leave the clone unchanged (`Gap: CID-G06`)? CID-01-IT-06 checks only the file `backlog/ST-0327.md`.
