# Make research dispatch CLI-neutral

Define research dispatch in Factory terms and map it to each supported CLI
without weakening falsification independence or assuming Claude-specific model
names and tools.

**Priority:** must-have

## Acceptance Criteria

- Every research assignment declares `agent`, Factory `tier`, `task`, unique
  output path, and whether it requires an independent session.
- Research preflight blocks when source access is unavailable.
- Falsification mode blocks when independent agent identities cannot be
  established.
- Survey source gathering may fall back from a wave to sequential execution.
- Claude Code, Copilot, Codex, and Pi invocation mechanisms are documented and
  covered by installed-surface tests.
- Canonical research workflow artifacts contain no vendor model names or
  unqualified assumptions about a native Agent tool.

## Implementation Notes

Pi maps separate sessions to `run_agent` and file-disjoint waves to
`dispatch_wave`; Codex maps them to generated native agents and parallel
threads. Claude Code and Copilot use their native agent mechanisms.

## Analysis

ST-0063 will define a CLI-neutral logical research assignment contract and
apply it to both falsification and survey orchestration. The contract will
require `agent`, Factory `tier`, `task`, a unique `output` path, and
`independent_session`; it will also document the invocation mapping for Claude
Code, GitHub Copilot CLI, Codex, and Pi.

The implementation will modify the declared canonical artifacts:

- `factory/rulebooks/conventions/dispatch-contract.md` for the logical request,
  capability preflight, and CLI mapping;
- `factory/playbooks/research-topic.md` for falsification preflight and
  independent-session blocking;
- `factory/playbooks/research-survey.md` for the survey source-gathering path
  and sequential fallback;
- `factory/agents/research-orchestrator.md` for the orchestrator's portable
  dispatch responsibilities;
- `factory/docs/design/research-cli-portability-audit.md` for the implemented
  audit result;
- `orchestrator/tests/test_research_cli_portability.py` for acceptance-focused
  canonical-artifact and installed-surface coverage;
- `factory/INDEX.yaml` only when regenerated indexing requires it.

The tests cover the traced Dispatch Contract, Role Separation, and CLI
Portability scenarios: complete and uniquely addressed assignments, source
access preflight, strict independence blocking in falsification mode, survey
wave-to-sequential fallback, all four installed CLI mechanisms, and absence of
vendor model names or an unqualified native Agent assumption in canonical
research artifacts.

The story traces named behavioral contracts rather than existing use-case file
IDs; no matching `docs/spec/use_cases/` artifacts exist. The existing
role-separation rulebook remains authoritative. `research-survey.md` is a
declared overlap with ST-0062, so this story will add only its portable
dispatch/preflight contract and avoid implementing survey schemas, synthesis,
or other ST-0062 behavior.
