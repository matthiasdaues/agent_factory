# init-factory installs the capture hooks

Teach init-factory to install the Claude Code capture triggers the same way
it installs the git-safety guardrail: symlink `capture-usage.sh` into
`.claude/hooks/` and wire `Stop` and `SubagentStop` entries into
`.claude/settings.json` — created if absent, merged if present, never
clobbering hooks the project already owns. The wiring is idempotent and
reversible through `remove-factory` by its `agent_factory` marker.

The runtime area needs no new ignore entry: `.agent-factory/usage/` already
falls under the existing `/.agent-factory/` line in the init-factory ignore
manifest, resolving that open question.

**Priority:** must-have

## Acceptance Criteria

- init-factory symlinks `capture-usage.sh` into `.claude/hooks/` and adds
  `Stop` and `SubagentStop` command entries to `.claude/settings.json`,
  mirroring the guardrail install (created if absent, merged if present).
- Existing unrelated hooks in a project's `.claude/settings.json` are
  preserved; a second run is a no-op.
- The added entries carry the `agent_factory` marker so `remove-factory`
  extricates them without a trace.
- A test asserts `.agent-factory/usage/` is git-ignored via the existing
  `/.agent-factory/` manifest entry, with no new ignore line added.
- A test proves a fresh install adds both `Stop` and `SubagentStop` hooks and
  that re-running leaves settings unchanged.

## Analysis

**Traces:** Capture Triggers per CLI, Persistence, Completion Criteria
(proposal `token-usage-tracking.md`).

**Seam:** mirrored the existing guardrail install exactly — same symlink
helper (`ensure_symlink`), same settings-merge shape
(`_ensure_claude_guardrail_settings` → `_ensure_claude_capture_settings`),
generalized over two event names (`Stop`, `SubagentStop`) instead of the
guardrail's single `PreToolUse`/`Bash` matcher. New top-level step
`install_usage_capture`, called from `main()` right after
`install_git_guardrail`. No change to the `.gitignore` writer:
`.agent-factory/usage/` is already covered by the existing `/.agent-factory/`
entry, confirming the proposal's open question.

**Gap found and flagged, not fixed (`remove-factory` is not in this story's
declared outputs):** `remove-factory`'s `strip_settings_hook` only knows the
guardrail's `PreToolUse` shape — it never looks at `Stop`/`SubagentStop`.
Verified by hand: init-factory into a project with a **pre-existing**
`.claude/settings.json` (so `claude_settings_existed: true`, the capture
entries are merged into a file init-factory doesn't own outright), then
`remove-factory` strips the guardrail's `PreToolUse` entry but leaves the
`Stop`/`SubagentStop` capture entries behind. When `.claude/settings.json`
did **not** pre-exist, removal is clean today: init-factory creates the whole
file, records it in `remove_paths`, and `remove-factory` deletes it wholesale
— no gap in that case. `remove-factory` needs a follow-up story to learn the
`Stop`/`SubagentStop` shape (or a generic marker-list mechanism) before
removal is trace-free for projects that already owned `.claude/settings.json`
before Agent Factory was installed.
