# Run every gate that docs/testing.yaml enables

**Priority:** must-have

## Goal

`premerge-check` runs every entry under `gates` in `docs/testing.yaml` that has `enabled: true` and a command, including a gate the script does not name. A story's `quality-gates` field adds gates and never drops a gate the project enables.

## Domain Rule

- A key under `gates` is the gate's name with hyphens, such as `gates.crap-score`. Field keys keep underscores. The scripts also read `crap_score` and `mutation_testing`; with both keys, the key with hyphens wins with a warning (BR-055, OI-02).
- The gates of a unit of work are `dependency-check` with a rules file, `test-design-verify` with a Test Design or Prior Tests section, and each enabled entry with a command (BR-066).
- `premerge-check` builds the call of a gate it names; any other enabled gate needs a command.
- An enabled entry without a command, for a gate the script does not name, is refused and named (OI-15). A `quality-gates` entry that `docs/testing.yaml` cannot run is refused.
- The test-strategy agent owns the gates, their thresholds and their commands, and writes keys with hyphens.

## Outputs

- `premerge-check` reads the gate list from `docs/testing.yaml` and the story's `quality-gates`.
- `crap-score` and `mutation-testing` read both key forms.
- `test-strategy-agent.md` step 2 and `skills/crap-score/SKILL.md` name the keys with hyphens.
- `test_st_0359_gate_list` changes to the adding rule.

## Demo Scenario

1. `docs/testing.yaml` enables `gates.license-check` with `command: ./scripts/license-check`. `premerge-check` on ST-0350 runs it and lists it in its output.
2. With `gates.crap-score` enabled and `gates.mutation-testing` listed but not enabled, a story with `quality-gates: [mutation-testing]` runs both at the merge.
3. A story with `quality-gates: [spell-check]` and no such entry is refused, and the message names `spell-check`.

## Demo Data

| Key                      | enabled | command                   |
| ------------------------ | ------- | ------------------------- |
| `gates.license-check`    | true    | `./scripts/license-check` |
| `gates.crap-score`       | true    | (built by the script)     |
| `gates.mutation-testing` | false   | `mutmut run`              |

The tests write these entries into a temporary `docs/testing.yaml`.

## Boundaries

- This story does not edit this repository's `docs/testing.yaml`; the test-strategy agent proposes the keys with hyphens there.
- `packages/factory/INDEX.yaml` is regenerated in the same commit.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.
