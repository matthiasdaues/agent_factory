# Retain structured JSONL alongside text rendering at capture time

After this story ships, the usage capture pipeline writes a structured JSONL copy of the source transcript alongside the text rendering.

**Priority:** could-have

## Goal

When the usage capture pipeline processes a session with `retention=full`, it copies the source transcript verbatim as a `.structured.jsonl` file alongside the existing text rendering. Both files are stored under `.agent-factory/usage/transcripts/<session-key>/`. When `retention=omit`, neither the text rendering nor the structured transcript is written.

## Domain Rule

- Structured JSONL is a verbatim copy of the source transcript — no transformation, no filtering
- The file is stored alongside the text rendering as `<record-id>.structured.jsonl`
- `retention=full`: both files are written
- `retention=omit`: neither file is written
- The structured copy uses the same session-key directory as the text rendering

## Demo Scenario

1. Set the `AGENT_FACTORY_USAGE_TRANSCRIPT_RETENTION` environment variable to `full`.
2. Complete a factory session that triggers usage capture.
3. Inspect `.agent-factory/usage/transcripts/<session-key>/`. Two files exist per record: the text rendering (`<record-id>.jsonl`) and the structured copy (`<record-id>.structured.jsonl`).
4. Compare the structured copy against the source transcript file. The content is byte-identical.
5. Set `AGENT_FACTORY_USAGE_TRANSCRIPT_RETENTION` to `omit`.
6. Complete another factory session. Inspect the transcripts directory. No text rendering and no structured transcript are written for this session.

## Demo Data

No seeded data required. The demo uses a real factory session to trigger usage capture.

## Affected Paths

## Inputs

- ST-0275 deliverables — usage transcripts stored under `.agent-factory/usage/transcripts/`
- `packages/factory/scripts/usage-capture` — current capture pipeline: `UsageStoragePaths` manages directories and paths, `JsonlLoggingAdapter._write_reserved()` writes the text rendering, `resolve_transcript_retention()` reads the retention setting from CLI args or `AGENT_FACTORY_USAGE_TRANSCRIPT_RETENTION` env var
- Feature spec: `docs/spec/activity-graph-orchestration.feature` Rule "Usage capture retains structured transcripts"
- Ownership: this story owns the "Usage capture retains structured transcripts" contract

## Outputs

- `packages/factory/scripts/usage-capture` — `_write_reserved()` copies the source transcript as `<record-id>.structured.jsonl` alongside the text rendering when `retention=full`; `reserve_transcript()` reserves a path for the structured copy; when `retention=omit`, neither file is written (existing behavior preserved)

## Constraints

- The structured copy must be a verbatim byte-level copy of the source transcript — no parsing, no transformation
- The copy must follow the same best-effort contract as the text rendering: catch failures, log to stderr, return `False`, never raise into the caller
- The structured copy must use the same filesystem safety measures as the text rendering (`O_NOFOLLOW`, `_FILE_MODE`, `_require_regular_if_present`)
- Do not change the existing text rendering behavior or format

## Suggested Agent Plan

1. Read `packages/factory/scripts/usage-capture` to understand `_write_reserved()`, `reserve_transcript()`, and the retention flow

3. In `_write_reserved()`, when `retention == "full"`, read the source transcript file and write a verbatim copy to the structured path using the same atomic write pattern
4. When `retention == "omit"`, write neither file (existing behavior)
