# Create a validated phase handoff contract

Give an outgoing phase one CLI-neutral restart contract whose structural
defects are blocked mechanically and whose semantic completeness is reviewed
separately against durable evidence.

**Priority:** must-have

## Acceptance Criteria

- The handoff convention defines every Factory phase boundary, mandatory stop,
  fresh-session entry, and exemption for work remaining within one phase.
- The handoff skill preserves decisions, open items, artifact paths, branch and
  upstream state, gate and verification evidence, next action, and exact
  40-character SHAs in dense prose.
- `handoff-lint` reports all detectable missing sections, malformed declared
  fields, missing referenced paths, and malformed SHAs in one non-zero run.
- Passing structural lint makes no semantic-losslessness claim; the contract
  requires an independent semantic review before phase closure.
- Installation/index coverage proves the skill is generated for every
  supported CLI.

## Implementation Notes

Owns the handoff format, skill, deterministic validator, catalog entry, and
focused contract tests. It excludes in-place transcript compaction.

## Analysis

Implement the accepted Session Transcript Proposal's phase-boundary restart
contract by extending the existing handoff convention, adding one CLI-neutral
`handoff` skill, and adding a read-only, standard-library `handoff-lint` CLI.
The contract will retain the proposal's complete boundary set, hard-stop and
fresh-session rules, same-phase exemption, dense-prose losslessness invariant,
repository state, durable evidence, and separate semantic-review gate. The
generated catalog will expose the new skill without introducing a second
source of truth.

The implementation changes only the declared outputs: this story, the handoff
rulebook and skill, the validator, the generated Factory index, and focused
contract tests. Tests trace UC-11's successful structural validation, its
aggregate-error extension for missing or malformed fields, the BR-049 case
where lint passes but cannot certify an undeclared omission, and installation
of the canonical skill for every supported CLI.

Test seams are the public `factory/scripts/handoff-lint` process boundary, the
canonical Markdown contracts read by phase participants, and `init-factory`'s
installed CLI surfaces. Chicago-school tests use temporary repositories and
real files; no internal parser functions are treated as public seams.

No unresolved design choice remains. The exact boundary sequence, elevated
assurance, reliability/operations governance, semantic-review separation, and
exclusion of in-place transcript compaction come directly from the accepted
proposal and UC-11/BR-037…BR-039/BR-049.

## Spec Feedback

Compared the implementation with UC-11, the PRD's FR-K1…FR-K3, the entity and
state-machine models, the `handoff-lint` interface contract, validation rules,
and the arc42 container/runtime views. No drift was found: the validator remains
read-only and structurally scoped, the independent BR-049 semantic gate remains
authoritative for losslessness, no entity/state/component boundary changed, and
the accepted proposal explicitly declares `architecture_change: false` and
excludes in-place transcript compaction. No specification update or ADR is
needed.
