# Integrate test-design into the create-backlog sequence

Wire the `test-design` skill into the `create-backlog` sequence as optional step 2.5. Update `create-backlog-write-epics` to surface the test-design option. Update `create-backlog-stories` to carry Test Design, Prior Tests, and `tests:` from `epics.md` into story files when those sections exist.

**Priority:** must-have

## Demo

Open `factory/skills/create-backlog/SKILL.md`. The operational sequence table has a new row between phases 2 and 3: phase 2.5, `test-design`, marked optional. A planning agent runs `create-backlog-write-epics` and, after presenting `epics.md` for confirmation, sees a prompt: "Before proceeding to step 3, you may invoke `test-design` to enrich the epics with test scenarios." After running test-design, the planning agent runs `create-backlog-stories`. Each story file's `tests:` frontmatter is populated from the epic entry, and the `#### Test Design` and `#### Prior Tests` sections appear verbatim in the story body. When test-design was not run, stories are written identically to the current behavior.

## Acceptance Criteria

- The `create-backlog` parent skill's operational sequence table includes a step 2.5 row for `test-design`, marked optional (CC 3, test-design.feature Rule 6, Scenario 1).
- The `create-backlog-write-epics` skill surfaces the test-design option before the user proceeds to step 3 (CC 4, test-design.feature Rule 6, Scenario 2).
- The `create-backlog-stories` skill carries the `tests:` value from epic building-block entries into story frontmatter when test-design sections exist (CC 5, test-design.feature Rule 7, Scenario 1).
- The `create-backlog-stories` skill writes `#### Test Design` sections verbatim into story bodies when present in `epics.md` (CC 5, test-design.feature Rule 7, Scenario 1).
- The `create-backlog-stories` skill writes `#### Prior Tests` sections verbatim into story bodies when present in `epics.md` (CC 5, test-design.feature Rule 7, Scenario 1).
- When `epics.md` contains no test-design sections, `create-backlog-stories` behaves exactly as today (test-design.feature Rule 7, Scenario 2).
- The sequence proceeds normally when the user chooses not to invoke test-design (test-design.feature Rule 6, Scenario 3).

## Scope

**Status quo:** The `create-backlog` sequence has four phases (1-4). The `test-design` skill exists (delivered by ST-0185). The `create-backlog-stories` skill cross-references stories against the testing regime but does not carry test-design sections.

**Adds:** Step 2.5 row in the parent skill's sequence table. A prompt paragraph at the end of `create-backlog-write-epics`. Conditional section-propagation logic in `create-backlog-stories` for `tests:`, `#### Test Design`, and `#### Prior Tests`.

**Out of scope:** The test-design skill itself (ST-0185). Developer-agent consumption (ST-0187).

## Notes for the Implementer

The prompt text at the end of `create-backlog-write-epics` should explain that test-design prescribes the developer-agent's TDD RED phase, so the user understands the value proposition. The conditional logic in `create-backlog-stories` is: if the epic building-block entry has a `tests:` key, populate the story's `tests:` frontmatter; if `#### Test Design` or `#### Prior Tests` sections exist in the entry, write them verbatim into the story body after the Acceptance Criteria section.
