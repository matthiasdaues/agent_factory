# Hold back the stories that depend on a returned story

**Priority:** must-have

## Goal

`dispatch prepare-wave` and `dispatch prepare-story` refuse a story that depends on a returned story, directly or through another story, and name the return. A story that depends on none of them still starts.

## Domain Rule

- Both commands read only the ledger. A unit of work starts only when every story it depends on inside the run is `done` (BR-113).
- Both commands check every such dependency, not only the first.
- At the end of the run, the returned story and the stories that wait on it are `pending`, and they stay in the backlog.

## Outputs

- The dependency check of `prepare-wave` and `prepare-story` covers every dependency inside the run and names a return.
- `_scalar` in `dispatch_lib.py` writes a string plain only when it matches a conservative pattern and is no YAML 1.1 keyword, number or date. It quotes every other string with `json.dumps`, so PyYAML reads each ledger value unchanged (IMPL-0032).

## Demo Scenario

1. In a run with ST-0350, ST-0351 (depends on ST-0350) and ST-0352 (depends on ST-0351), the User returns ST-0350.
2. `dispatch prepare-story ST-0351` exits non-zero and names the return of ST-0350. `prepare-story ST-0352` refuses as well.
3. `dispatch prepare-story ST-0353`, which depends on none of them, passes.

## Demo Data

| Story   | deps    | ledger state       |
| ------- | ------- | ------------------ |
| ST-0350 | —       | pending (returned) |
| ST-0351 | ST-0350 | pending            |
| ST-0352 | ST-0351 | pending            |
| ST-0353 | —       | pending            |

The tests write these entries through the ledger model.

## Boundaries

- The commands do not read the backlog for dependencies inside the run.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.
