# Hold back the stories that depend on a returned story

**Priority:** must-have

## Goal

`dispatch prepare-wave` and `dispatch prepare-story` refuse a story that depends on a returned story, directly or through another story, and name the return. A story that depends on none of them still starts.

## Domain Rule

- Both commands read only the ledger. A unit of work starts only when every story it depends on inside the run is `done` (BR-113).
- Both commands check every such dependency, not only the first.
- At the end of the run, the returned story and the stories that wait on it are `pending`, and they stay in the backlog.

## Analysis

- **What:** a shared check in `dispatch_lib.py` reads the ledger only. It names each dependency inside the run that is not `done`, and it names each returned story that holds the dependency back, directly or through another story. `prepare-wave` and `prepare-story` (both modes) use it.
- **Returned entry:** `prepare-story` refuses an entry with `returned: true` in both modes and names the return. `prepare-wave` skips it, names the return, prepares the other stories of the wave, and exits `1`.
- **Every dependency:** `prepare-story` in an orchestrated run checked only its first dependency. It now checks every dependency inside the run, and it still cuts the branch from the merge commit of the first one.
- **Earlier waves:** `prepare-wave <N>` refused while an earlier wave held a `pending` entry. A returned entry and an entry that waits on one can never start in this run (BR-113), so they no longer block a later wave. The dependency check then names the return.
- **IMPL-0032:** `_scalar` writes a string plain only when it matches `^[A-Za-z0-9_./][A-Za-z0-9 _./,;()+-]*$` and no YAML 1.1 resolver of PyYAML reads it as a bool, null, number or date. Every other string gets `json.dumps`.
- **Files:** `packages/factory/scripts/dispatch`, `packages/factory/scripts/dispatch_lib.py`, `tests/factory/test_run_lifecycle_ledger.py`, new `tests/factory/test_run_lifecycle_close.py`.
- **Scenarios:** the four Scenarios of the Rule "Implementation agent starts a story only when its dependencies inside the run are done", and RL-17-CT-01 for IMPL-0032.
- **Concerns:** the Demo lets `prepare-story ST-0353` pass, but an orchestrated `prepare-story` refuses a story without a recorded predecessor. ST-0353 starts through `prepare-wave`, as the Scenario says. `dispatch close` does not exist yet (ST-0425), so RL-07-IT-01 checks the ledger and the backlog after the last wave of the run. The QA strategy puts RL-07-IT-01 into `test_run_lifecycle_dispatch.py`; the story's `touches` name `test_run_lifecycle_close.py`, and the test follows the story.
- **Seams:** contract tests call `dispatch.main` in process through the `Run` fixture of `test_run_lifecycle_ledger.py`, plus `Ledger.save` with `yaml` set to `None`. The integration test runs `dispatch` as a subprocess on a git repository in `tmp_path`.

## Outputs

- The dependency check of `prepare-wave` and `prepare-story` covers every dependency inside the run and names a return.
- `_scalar` in `dispatch_lib.py` writes a string plain only when it matches a conservative pattern and is no YAML 1.1 keyword, number or date. It quotes every other string with `json.dumps`, so PyYAML reads each ledger value unchanged (IMPL-0032).

## Demo Scenario

1. In a run with ST-0350, ST-0351 (depends on ST-0350) and ST-0352 (depends on ST-0351), the User returns ST-0350.
2. `dispatch prepare-story ST-0351` exits non-zero and names the return of ST-0350. `prepare-story ST-0352` refuses as well.
3. `dispatch prepare-wave 1` names the return of ST-0350 and exits non-zero, and it still starts ST-0353, which depends on none of them (RL-07-CT-01).

## Demo Data

| Story   | deps    | ledger state       |

| ST-0351 | ST-0350 | pending            |

## Boundaries

- The commands do not read the backlog for dependencies inside the run.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.
