# Assemble the published documents into a Quarkdown build

**Priority:** must-have

## Goal

A developer runs `_docs_assemble.py` on a project's `docs/` folder and gets a
build directory with `main.qd`, the Mermaid bodies and the copied images. The
sources stay unchanged.

## Rule

The [publish-docs proposal](../docs/proposals/publish-docs.md#design) owns the
manifest, the rewrite rules and the title page. This story implements Stages
0, 2 and 3 of its pipeline.

## Scope

1. Read `docs/publish-docs.yaml`: `title`, `chapters`, and an `appendix` with
   `title` and `documents`. Glob entries expand in sorted order. A missing file
   or an empty glob stops the run with exit 2.
2. A missing manifest exits 2 and prints a starter manifest built from
   `arc42/NN_*.md` and `adr/*.md`. The output mentions the optional
   `docs/publish-docs.css`.
3. Apply the rewrite rules: Mermaid blocks to `.read {dN.mmd}`, images copied
   (Structurizr views taken from the fresh export directory), links to
   manifest documents as anchors, links to other Markdown as plain text, links
   to other files as inline code, `[back to index]` lines and frontmatter
   removed, ADR `status` kept as a line under the heading.
4. Write `main.qd` with the paged doctype, numbering `none`, the factory and
   project stylesheets, the title page with the provenance line, the table of
   contents and the appendix title.
5. Write `expected.json` with the Mermaid block count and the raster image
   count for the render checks.

## Acceptance criteria

- Unit tests cover every rewrite rule, the manifest errors, the starter
  manifest and the provenance line with and without uncommitted changes.
- The tests need no Docker.
- Commits name the story, as `feat: <what changed> (ST-0309)`.
