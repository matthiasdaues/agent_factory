# Claim the literal ID prefix at each step that creates an artifact

**Priority:** must-have

## Goal

An agent that follows any of the nineteen ID producer files runs `next-id` with the one prefix of the artifact it creates, such as `next-id FAGAN` in `fagan-review`. No file asks the agent to choose a prefix from a list. The text test fails and names the file and the prefix when a file drops its claim.

## Contract

| File under `packages/factory/`                                             | Step that creates              | Claim it names                 |
| -------------------------------------------------------------------------- | ------------------------------ | ------------------------------ |
| `skills/create-backlog/SKILL.md`, `skills/create-backlog-stories/SKILL.md` | a story                        | `next-id ST`                   |
| `skills/retrospective/SKILL.md`                                            | a todo entry; a backlog story  | `next-id T`; `next-id ST`      |
| `skills/write-adr/SKILL.md`                                                | an ADR                         | `next-id ADR`                  |
| `rulebooks/conventions/todo-format.md`                                     | a todo entry                   | `next-id T`                    |
| `playbooks/bug-fix.md`, `skills/bug-hunt/SKILL.md`, `agents/qa-agent.md`   | a bug finding                  | `next-id BUG`                  |
| `skills/inspect-spec/SKILL.md`, `agents/spec-review-agent.md`              | a specification finding        | `next-id SPEC`                 |
| `skills/atam-review/SKILL.md`, `agents/architecture-review-agent.md`       | an architecture risk           | `next-id ATAM`                 |
| `skills/maintain-architecture/SKILL.md`                                    | an architecture finding        | `next-id ARCH`                 |
| `agents/code-review-agent.md`                                              | a code review finding          | `next-id IMPL`                 |
| `skills/fagan-review/SKILL.md`                                             | a Fagan finding                | `next-id FAGAN`                |
| `skills/security-review/SKILL.md`                                          | a security finding             | `next-id SEC`                  |
| `skills/mutation-testing/SKILL.md`                                         | a mutation testing finding     | `next-id QA`                   |
| `skills/reconcile-spec/SKILL.md`, `agents/reconciliation-agent.md`         | a drift finding; a code defect | `next-id RECON`; `next-id BUG` |

No line of these files holds `next-id <TAG>`.

## Demo Scenario

1. The User prepares the scratch project of Demo Data and opens an agent session in it.
2. The User asks the agent to run `fagan-review` on `src/calc.py`. The agent runs `.agent-factory/factory/scripts/next-id FAGAN`, which prints `FAGAN-0001`, and writes `docs/findings/FAGAN-0001.md`.
3. The User asks the agent to run `reconcile-spec`. The agent runs `next-id RECON` for the drifted rule and gets `RECON-0001`, and runs `next-id BUG` for the defect in `src/calc.py` and gets `BUG-0001`.
4. The User asks the agent to run `retrospective`. For its one action item, the agent runs `next-id T`, gets `T-0001`, and writes the entry in the form of `todo-format.md`.
5. The User asks the agent to write two stories with `create-backlog-stories`. The agent runs `next-id ST` twice and writes `backlog/ST-0001.md` and `backlog/ST-0002.md`.

## Boundaries

- Each file names the installed path `.agent-factory/factory/scripts/next-id` with the literal prefix at the step that creates the artifact (BR-107).
- The kind of artifact decides the prefix. A file that creates two kinds names one prefix at each of the two steps (DEC-10).
- Each claim tells the reader to read the ID from standard output, and to stop and report the message when `next-id` fails, never picking a number by hand, as the existing claims of ST-0372 do.
- `retrospective` points to `todo-format.md` at its todo step, so ST-0385 finds it by that pointer.
- `create-backlog-slice-story` keeps its letter scan and names no `next-id`.
- The checker of ST-0383 gains the dropped-prefix case. It reads the producer files from the ID producer column of `id-prefixes.md` and fails, naming the file and the prefix, when a file lacks `next-id <PREFIX>` (CIFP-C13).
- The text test checks that each file holds its claim. The story review checks that the claim stands at the creating step, because a text test cannot.
- The story regenerates `INDEX.yaml` in the same commit, and `index-lint --check` passes.

## Out of Scope

- Todo writers outside the Contract (ST-0385).
- `docs/spec/work/todos.md` and its writers (SPEC-0068, T-0008).
- A check of new file names (DEC-12).

## Agent Stop Conditions

- A file in `packages/factory/` outside the Contract tells its reader to create a story, finding, or ADR. Report the file and the step; the proposal's table does not name it.
- A file of the Contract has no step that creates its artifact. Report the file; do not add a step.
- Code and BR-107 disagree on the prefix of a kind of artifact. Report both files and the decision needed; do not add a workaround.
