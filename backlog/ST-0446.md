# Check a measuring command with the four checks of gate-setup-proof

Before a person enables the gate, a script checks that the measuring command reports true coverage of its own folder.

**Priority:** must-have

## Goal

`gate-setup-proof --measure python --plant <folder>` runs four checks in its own worktree: Repeatable, Catches CRAP, Sees the folder, and Reports a gap. An honest measuring command passes all four, and each lying command fails exactly the check it breaks. The project's branches and worktree list stay as they were.

## Domain Rule

- The proof makes its worktree at `.current-work/gate-setup-proof/worktree` and removes one left by a crashed run first (DEC-46).
- The first commit holds `docs/testing.yaml`, the measuring commands and the `ready` commands as they are in the working tree, plus the files of `base/` copied onto the worktree root. The second commit adds `gap/` (DEC-30, DEC-32).
- It finds `proof_untested` and `proof_tested` by name in the rows and reads the threshold from `gates.crap-score`, also with `enabled: false`.
- Repeatable: two gate runs on the first commit give the same verdict and rows. Catches CRAP: the gate fails and names `proof_untested`. Sees the folder: `proof_tested` shows full coverage and passes. Reports a gap: on the second commit the gate exits 2 (DEC-06).
- The gate always has changed code to judge, so the measuring command starts in each check, also without a change on the current branch.
- Exit 0 when all four checks pass, 1 when a check fails (BR-138). Nothing from the worktree reaches a branch of the project.

## Outputs

- New script `gate-setup-proof` in `packages/factory/scripts/`.
- New `tests/factory/test_crap_gate_proof.py`.

## Demo Scenario

1. A temporary repository has `dev` and `feature/login`. Its working tree holds, uncommitted, `docs/testing.yaml` with `gates.crap-score` `enabled: false`, threshold 8, the measure `python`, and the honest stub command.
2. The plant folder holds `base/packages/factory/scripts/proof-plant` with `proof_untested` and `proof_tested`, both of complexity 3, `base/` with `test_proof_plant.py`, and `gap/` with the failing `test_proof_gap.py`.
3. The User runs `gate-setup-proof --measure python --plant <folder>`. The output names the four checks, all passing, and the proof exits 0.
4. The User swaps in a command that reports 100 % for every function. Only "Catches CRAP" fails, and the proof exits 1.
5. `git worktree list` and the tips of `dev` and `feature/login` are as before.

- The story changes the built scripts in place and rebuilds none of them.
