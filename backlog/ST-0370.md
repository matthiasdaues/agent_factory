# See a failed ID claim stop and name its cause

**Priority:** must-have

## Goal

When an ID claim cannot reach the counter, `next-id` exits non-zero, prints no ID, and names one cause from the claim error table. It never waits for a person: git asks for no credentials, and no git call of a claim runs longer than 30 seconds.

## Contract

| Operation    | Input state                                                      | Outcome                                                                        | Persistence |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ | ----------- |
| `next-id ST` | `origin` holds no `refs/ids/counters`                            | Exit non-zero; no ID; names the remote and `next-id --seed`                    | None        |
| `next-id ST` | `origin` points at a closed local port                           | Exit non-zero; no ID; names the remote and git's error                         | None        |
| `next-id ST` | Clone without `origin`, no `--remote`                            | Exit non-zero; no ID; names `origin`, `--remote`, and `next-id --seed`         | None        |
| `next-id ST` | The remote answers every request with HTTP status `403`          | Exit non-zero; no ID; names the remote and git's error                         | None        |
| `next-id ST` | The remote asks for credentials that the git setup does not hold | No prompt; exit non-zero; no ID; names the remote and git's error              | None        |
| `next-id ST` | A git call of the claim runs longer than 30 seconds              | The call is stopped; exit non-zero; no ID; names the remote and the time limit | None        |

## Demo Scenario

1. The User runs `next-id ST --remote /tmp/empty.git` on the bare repository of Demo Data. It exits non-zero, prints no ID, and names `/tmp/empty.git` and `next-id --seed`.
2. The User runs `next-id ST --remote http://127.0.0.1:<closed port>/remote.git`. It exits at once, prints no ID, and names the URL and git's error.
3. In a clone without `origin`, the User runs `next-id ST`. It names `origin`, `--remote`, and `next-id --seed`.
4. The User runs `next-id ST --remote` against a local HTTP server that asks for a password. `next-id` shows no prompt, exits non-zero, and names the remote and git's error.

## Demo Data

| Item                   | Value                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| Empty bare repository  | `/tmp/empty.git`, made with `git init --bare`, never seeded                                                   |
| Closed port            | A port on `127.0.0.1` that the test binds, reads, and closes again                                            |
| Clone without `origin` | `/tmp/no-origin`, made with `git init`                                                                        |
| `403` server           | A small HTTP server on `127.0.0.1` that answers every request with status `403`                               |
| Password server        | A small HTTP server on `127.0.0.1` that answers every request with status `401` and `WWW-Authenticate: Basic` |

## Boundaries

- Every git call of a claim runs with `GIT_TERMINAL_PROMPT=0` and `GIT_SSH_COMMAND="ssh -o BatchMode=yes"` (BR-076).
- `next-id` stops any git call of a claim after 30 seconds. So ten stale leases end a claim after at most twenty git calls and nine waits.
- `--seed` keeps git's prompts and has no time limit, because a person runs it (ATAM-0012).
- No new flag or environment variable changes the time limit. A test that checks the limit replaces the limit or the git call inside the imported script.
- Each failure prints exactly one cause from the claim error table and nothing on standard output.
- No test waits for a network timeout.

## Out of Scope

- The retry and the refusal after one push (ST-0369).

## Agent Stop Conditions

- Code and the claim error table disagree on a cause or the names in its message. Report the conflicting files and the decision needed; do not add a workaround.
- A test can only check the time limit by waiting 30 seconds. Report it instead of adding a flag or an environment variable.
