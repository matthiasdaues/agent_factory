# Route agents by feature files in features/

**Priority:** must-have

## Goal

In a migrated project whose only feature file is in `docs/spec/features/`,
`intent select` counts the requirements stage as done and lists the agents
that follow it. The `INDEX.yaml` preconditions and the dispatch extensions
name no use-case folder.

## Contract

| Operation                          | Input state                                  | Outcome                                                                                                | Persistence |
| ---------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------- |
| `intent select`                    | Only `docs/spec/features/payments.feature`   | Requirements stage done; downstream agents eligible                                                    | None        |
| `intent select`                    | Only `docs/spec/payments.feature` at the top | Requirements stage not done                                                                            | None        |
| `intent assess`                    | `docs/spec/work/payments-qa-strategy.md`     | Counted as the QA-strategy artifact                                                                    | None        |
| `INDEX.yaml`                       | —                                            | Preconditions use `docs/spec/features/*.feature` and `docs/spec/work/*-qa-strategy.md`; no `use_cases` | —           |
| `dispatch-wave.ts`, `run-agent.ts` | —                                            | Name no `use_cases` folder                                                                             | —           |

## Demo Scenario

1. The maintainer builds the fixture `routed-project` (Demo Data) and runs
   `packages/factory/scripts/intent select` in it.
2. The output marks the requirements stage as done and lists the planning
   agent among the eligible agents.

## Demo Data

The story extends the fixtures of `tests/factory/test_intent_select.py`.

| Fixture          | Content                                                                                                                                              |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `routed-project` | `docs/spec/scope-map.md`, `docs/spec/features/payments.feature`, `docs/proposals/payments.md` (accepted); no feature file at the top of `docs/spec/` |

## Boundaries

- `intent` and the preconditions read only the new paths (DEC-11).
- An agent never looks for a use-case folder (DEC-10).
- `INDEX.yaml` stays valid for `index-lint`.
- Source edits go to `packages/factory/`. The generated `.claude/INDEX.yaml`
  and its siblings follow only through a reinstall (ST-0343 touchpoint).
- `tests/factory/test_onboarding_sandbox.py` is not part of this story; its old
  path is a docstring reference that ST-0343 fixes.

## Analysis

- `intent` discovers feature files in `docs/spec/features/` and QA strategies
  in `docs/spec/work/`. `intent select` needs no code change: the engine
  expands folder globs with `glob.glob`, so a precondition on
  `docs/spec/features/*.feature` matches.
- `INDEX.yaml` is generated by `index-lint` from the agent frontmatter. Every
  agent that still names an old path belongs to ST-0336 to ST-0341. This story
  leaves `INDEX.yaml` alone; a regeneration after those stories merge moves its
  preconditions.
- `TestArchitectureAgentBrownfieldEntry` in `test_precondition_evaluator.py`
  reads the real `architecture-agent.md`. Its feature fixture moves to
  `features/` together with ST-0341.
- The dispatch extensions drop the use-case reference and keep the ADR link.
