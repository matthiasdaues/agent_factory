# Update developer-agent with .feature workflow

Update the developer-agent to read `.feature` files as the acceptance
specification, write step definitions that wire Given/When/Then steps to
`@`-referenced code, and run the `.feature` file through the test framework
as part of the TDD cycle.

**As a** implementation-agent dispatcher,
**I want** the developer-agent to treat the `.feature` file as its primary
acceptance spec and produce executable step definitions,
**so that** the behavioral specification is verified mechanically during
implementation, not only during QA.

**Priority:** must-have

## Acceptance Criteria

1. The developer-agent reads `docs/spec/<feature-name>.feature` as its
   primary acceptance specification (not UC-XX files).
2. The agent writes step definitions under `tests/features/steps/` that
   wire each Given/When/Then step to code.
3. `@`-references in the `.feature` file tell the developer which existing
   modules and functions the steps should call or extend.
4. The agent runs the `.feature` file through the test framework (`behave`,
   `cucumber`, or equivalent) as part of the TDD cycle.
5. A passing `.feature` file means the behavioral specification is
   satisfied.
6. Step definitions are implementation artifacts (not specification
   artifacts) — the `.feature` file is the spec, step definitions are glue.
7. The agent definition documents the `.feature` workflow as a subsection.
8. All changes pass `factory/scripts/validate`.
