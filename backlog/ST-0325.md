# Run the architecture gates against the DSL in docs/spec/

**Priority:** must-have

## Goal

In a project in the new layout, `arch-lint`, `structurizr validate`, and
`dependency-check` each read their DSL from `docs/spec/` and exit non-zero on a
seeded error there. `arch-lint` still reads chapter 5 from `docs/arc42/`. In a
project installed from the factory's hook template, a change to
`docs/spec/architecture.dsl` triggers `arch-lint`.

## Contract

| Operation                                              | Input state                                                                       | Outcome                                                                               | Persistence                   |
| ------------------------------------------------------ | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------- |
| `arch-lint` (defaults)                                 | New-layout fixture; DSL names a component chapter 5 does not name                 | Error finding; exit non-zero                                                          | None                          |
| `arch-lint` (defaults)                                 | New-layout fixture without errors                                                 | Exit 0; reads `docs/spec/architecture.dsl` and `docs/arc42/05_building_block_view.md` | Re-exported SVGs when stale   |
| `structurizr validate`                                 | `docs/spec/architecture.dsl` with a broken relation                               | Exit non-zero                                                                         | None                          |
| `dependency-check` (defaults)                          | `docs/spec/dependency-rules.dsl` with a rule the fixture's imports break          | Exit non-zero                                                                         | Report under `.current-work/` |
| `pre-commit run --files docs/spec/architecture.dsl`    | Fixture with the hook block from `packages/factory/config/pre-commit-config.yaml` | Pre-commit runs `agent_factory_hook-arch-lint`                                        | None                          |
| Repository commit in the factory's own old-layout repo | Local hooks in `.pre-commit-config.yaml`                                          | `arch-lint` hook passes the old DSL path explicitly and stays green                   | None                          |

## Demo Scenario

1. The maintainer builds the fixture `new-layout-gates` (Demo Data) and, inside
   it, changes `docs/spec/architecture.dsl` so a relation names the missing
   element `ledger`.
2. The maintainer runs `packages/factory/scripts/arch-lint`. It reports the
   error and exits non-zero.
3. The maintainer runs `packages/factory/scripts/structurizr validate`. It
   exits non-zero.
4. The maintainer breaks a rule of `docs/spec/dependency-rules.dsl` and runs
   `packages/factory/scripts/dependency-check`. It exits non-zero.
5. In a fixture with the template's hook block, the maintainer runs
   `pre-commit run --files docs/spec/architecture.dsl`. Pre-commit runs
   `agent_factory_hook-arch-lint`.

## Boundaries

- Each gate reads the new path only. No gate falls back to an old path (DEC-11).
- A gate whose input file is missing at the new path must not pass silently on
  a seeded error. The seeded-error test proves the gate reads the file.
- In the template, the `files:` pattern of `agent_factory_hook-arch-lint`
  becomes exactly
  `^docs/(spec/(architecture|dependency-rules)\.dsl|arc42/05_building_block_view\.md|assets/images/.*|adr/.*\.md)$`.
- The repository's `.pre-commit-config.yaml` keeps its old `files:` patterns
  until ST-0343. Both of its `arch-lint` entries, the local hook and
  `agent_factory_hook-arch-lint`, pass the old DSL path explicitly. The factory
  hook runs the installed copy, and `dispatch merge-story` copies
  `packages/factory/` into that copy after every merge, so the installed
  `arch-lint` reads the new default as soon as this story merges.
- `arch-lint` passes its DSL path through to `structurizr` when it re-exports
  stale images, so the repository's local hook stays green on a DSL change.
- The `structurizr` row of the gate test carries the `container` marker.
- Each new argument and default is recorded in `interface-contracts.md`
  (CAL-G16).

  both layouts. Report it; no script may read both layouts.
- Code and `interface-contracts.md` disagree on today's `arch-lint` arguments.
  Report the files and the decision needed; do not add a workaround.
