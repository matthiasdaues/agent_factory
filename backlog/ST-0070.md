# Prove background dispatch permission argv

Exercise the actual Claude and Copilot child command construction so the
shipped repository-derived permissions cannot regress into blanket bypass or
bare-interpreter wildcards.

## Analysis

ST-0070 closes the evidence gap identified by UC-12/BR-047 without redesigning
the delivered UC-04 permission policy. A focused regression test will call the
real `trigger.main()` background-dispatch path for both supported CLIs, replace
only the subprocess execution seam, and inspect the exact child argv that the
runtime would launch.

The test will verify each CLI's scoped allow and deny arguments, rejection of
blanket permission flags and bare-interpreter wildcards, denial of the shipped
dangerous Git verbs, and retention of repository-evidenced validation,
formatting, and test commands. Only
`orchestrator/tests/test_trigger_background_permissions.py` and this story are
modified; `factory/scripts/trigger` remains unchanged unless the regression
test exposes a contract mismatch. No ambiguity or architecture decision was
found: UC-04, UC-12, BR-011, and BR-047 already define the expected behavior.

**Priority:** must-have

## Acceptance Criteria

- Tests inspect actual background argv for both supported trigger CLIs.
- Claude argv contains scoped allow and deny lists and excludes
  `--dangerously-skip-permissions` and bare interpreter wildcards.
- Copilot argv contains scoped allow and deny lists and excludes
  `--allow-all-tools` and bare interpreter wildcards.
- Dangerous Git verbs are denied and the repository-evidenced validation,
  formatting, and test commands remain allowed.

## Implementation Notes

This is an evidence-only story. If a test exposes a mismatch, restrict any
runtime edit to `factory/scripts/trigger` and update this story's declared
output before dispatch so pre-merge scope remains accurate.
