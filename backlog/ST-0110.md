# Update reconciliation-agent with @-ref backfill and scope-map reconciliation

Update the reconciliation-agent to fill missing `@`-references in the
`.feature` file after implementation and to diff scope-map Rules against
`.feature` file Rules at feature-branch merge time.

**As a** playbook orchestrator,
**I want** the reconciliation-agent to complete code traceability and
detect scope drift between the scope map and `.feature` files,
**so that** every Rule has verified code traceability and scope changes
are surfaced before merge.

**Priority:** must-have

## Acceptance Criteria

1. The reconciliation-agent fills missing `@`-references in the `.feature`
   file for Rules and Scenarios that were implemented but had no `@`-ref
   (new behavior).
2. After reconciliation, every Rule MUST have at least one `@`-ref. A Rule
   without one is filed as a finding.
3. The agent diffs scope-map Rules against `.feature` file Rules when the
   feature branch merges to dev.
4. Newly discovered Rules (in `.feature` but absent from scope map) enter
   the scope map as `implemented` with a filed finding.
5. Scope-map Rules marked `specified` but absent from the `.feature` file
   are surfaced as drift findings.
6. Agent-opened PRs against dev include newly discovered Rules in the PR
   body so human reviewers see scope changes before approving.
7. The agent skips Rule-level diff for scope-map rows pointing at UC-XX
   sources (old-format entries from migration).
8. Reconciliation timing: one feature branch = one slice = one `.feature`
   file = one reconciliation pass.
9. All changes pass `factory/scripts/validate`.
