# Add close ceremony to dispatch contract with completed and abandoned paths

Amend the dispatch contract, branching policy, and rules.md so that every dispatch has a defined end state. Today a dispatch can begin without ending — orphaned worktrees and branches accumulate because no convention requires closing a dispatch when it completes or is abandoned.

**Priority:** must-have

## Demo

1. Open `factory/rulebooks/conventions/dispatch-contract.md` and locate the new "Close" section after the existing "Dispatch Ledger" section.
2. The Close section defines two terminal paths: "Completed close" (verify terminal states, prune worktrees, delete merged branches, commit final ledger) and "Abandoned close" (record abandonment reason, force-remove worktrees, force-delete branches, commit ledger).
3. Open `factory/rulebooks/conventions/branching-policy.md` and confirm it references the dispatch close ceremony as the authoritative procedure for post-verification worktree and branch removal.
4. Open `factory/rulebooks/rules.md` and confirm the Dispatch section contains a new MUST rule: "MUST close every dispatch as completed or abandoned — a dispatch that begins without ending is a leak."

## Acceptance Criteria

- dispatch-contract.md contains a "Close" section with a "Completed close" subsection listing the four steps: verify terminal states, prune stale worktree references, remove/delete merged worktrees and branches, commit final ledger state (PROP-dispatch-close)
- dispatch-contract.md contains an "Abandoned close" subsection listing the three steps: record abandonment reason in ledger, force-remove all dispatch-owned worktrees and branches, commit ledger (PROP-dispatch-close)
- branching-policy.md references the dispatch close ceremony for worktree removal instead of defining its own independent removal procedure (PROP-dispatch-close)
- rules.md Dispatch section contains a MUST rule requiring every dispatch to close as completed or abandoned (PROP-dispatch-close)
- The close ceremony text distinguishes merged branches (safe delete with `git branch -d`) from blocked branches (left for manual resolution with reason recorded) (PROP-dispatch-close)

## Scope

**Status quo:** dispatch-contract.md defines ledger maintenance and wave boundaries but has no close procedure. branching-policy.md requires removing clean worktrees after verification but does not tie removal to a dispatch lifecycle event. rules.md requires verifying every story reaches a terminal state but does not require closing the dispatch itself.

**Adds:** Close section in dispatch-contract.md with completed and abandoned paths. Cross-reference from branching-policy.md. MUST rule in rules.md.

**Out of scope:** Automated `dispatch close` script command (follow-up). Worktree-agent branch allowlisting in guardrail (follow-up).

## Notes for the Implementer

The Close section should be placed after the "Wave Closeout Record" section and before the "Enforcement" section in dispatch-contract.md. The branching-policy.md change is a cross-reference addition to the existing worktree cleanup text, not a rewrite. The rules.md entry goes in the existing "Dispatch" section.
