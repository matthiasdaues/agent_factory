# Accept VIRGIL's offer to move the counter at the session start

**Priority:** should-have

## Goal

When a project has a local counter and has gained `origin`, the User meets an offer to move the counter at the next session start. VIRGIL runs the move only after the User confirms, and reports a collision by naming both counters. A project without `origin` gets no offer.

## Domain Rule

- The session start checks two things before it shows the menu: `git config agent-factory.counterRemote` prints a path, and `git remote get-url origin` succeeds (BR-106).
- When both hold, VIRGIL offers the move and says what it does: it carries the counter to `origin`, leaves a marker in the project's `.git`, and removes the setting.
- VIRGIL runs `.agent-factory/factory/scripts/next-id --move-to-origin` only after the User confirms (DEC-09).
- When the move reports a collision, VIRGIL says that two counters exist, names both, and shows the lines that `next-id` printed. VIRGIL changes nothing else.
- When the move fails for another reason, VIRGIL shows the message and names the next session start as the next chance.
- Without `origin`, or without the setting, VIRGIL offers no move.
- The check lives in `packages/factory/config/session-menu.md`, before the menu (CIFP-C07).

## Outputs

- `session-menu.md` holds the check, the offer, the run after confirmation, and the reports for success, collision, and failure, before the menu itself.
- `test_fitting_text.py` checks that text (CIF-09-LN-01).
- `test_block_dangerous_git.py` checks that the guardrail hook exits `0` for the shell command `.agent-factory/factory/scripts/next-id --move-to-origin` (CIF-09-IT-01).

## Demo Scenario

1. The User prepares the project `/tmp/offer-demo` of Demo Data and opens an agent session. Before the menu, VIRGIL says that the counter is local, that `origin` now exists, and offers to move the counter to `/tmp/offer-origin.git`.
2. The User confirms. VIRGIL runs `next-id --move-to-origin` and reports that the counter is on `/tmp/offer-origin.git` now. The menu follows.
3. The User opens a new session. VIRGIL offers no move, because the setting is gone.
4. The User opens a session in `/tmp/offer-taken` of Demo Data and confirms the offer. VIRGIL reports that two counters exist, names `/tmp/offer-taken` and `/tmp/offer-taken-origin.git`, and shows the `ST` lines of both.
5. The User opens a session in `/tmp/offer-none`, which has the setting and no `origin`. VIRGIL offers no move and shows the menu.

The story seeds nothing. It needs the local counter of ST-0379 and the move of ST-0380.

## Boundaries

- The story does not change `block-dangerous-git.sh`. The hook test only checks that the hook lets the move pass (counter-ids DEC-22).
- VIRGIL runs no plain `git push`. The move is a push through `next-id`, which ADR-0032 allows.
- The check reads only `git config` and `git remote get-url`. It prints no URL with user info; VIRGIL names a remote by the redacted form that `next-id` prints.
- The offer comes before the menu and never replaces a pending fitting prompt of the `AGENTS.*.md` files.
- The text test checks the rule, not one exact sentence.
- The story regenerates `INDEX.yaml` in the same commit if `index-lint --check` needs it.
