# Integrate semantic gates into premerge-check

Update the `premerge-check` script to require passing results from all
three semantic gates before allowing a merge. Each gate is an independent
hard gate — any single failure blocks the merge.

**As a** implementation-agent dispatcher,
**I want** `premerge-check` to enforce semantic gate results as merge
preconditions,
**so that** no branch merges without verified CRAP, mutation, and
dependency results.

**Priority:** must-have

## Acceptance Criteria

1. `premerge-check` reads the `quality-gates` field from the story file to
   determine which gate results are required.
2. `premerge-check` checks for the existence and pass status of each
   required gate's JSON report under `.agent-factory/<gate>/<story-id>.json`.
3. Each gate is an independent hard gate — failure of any one blocks the
   merge independently of the others.
4. `premerge-check` exits non-zero with a diagnostic naming the failing
   gate(s) when any required gate report is missing or shows failure.
5. The existing `premerge-check` checks (format, lint, tests) are preserved
   and run alongside the new gate checks.
6. The script follows the `quality-gates` precedence chain: story field >
   `house-rules.md` default > Factory hardcoded default.
7. All changes pass `factory/scripts/validate`.
