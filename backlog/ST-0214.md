# Gate story-branch commits on dispatch-ledger existence

Add two layers of enforcement so that story-branch work cannot proceed without a dispatch ledger. Today an implementation agent can create story branches directly without running `dispatch init`, bypassing invocation-branch creation and ledger setup entirely. No mechanical gate catches this — only post-hoc observation.

**Priority:** must-have

## Demo

1. Create a story branch `story/ST-9999` in a linked worktree (with verify-base-ok marker present) but without any dispatch ledger at `.current-work/<feature-branch>/dispatch-ledger.yaml` in the main checkout.
2. Attempt `git commit` on the story branch. The `block-dangerous-git.sh` hook denies the commit with a message explaining that no dispatch ledger exists.
3. Run `dispatch init --base dev --stories ST-9999` to create the ledger, then re-attempt the commit. The commit succeeds (assuming all other gates pass).
4. Open `factory/agents/implementation-agent.md` and confirm it contains a MUST requiring `dispatch init` as the first action before creating any story branches.

## Acceptance Criteria

- block-dangerous-git.sh denies `git commit` on branches matching `story/*` when no dispatch ledger exists in the main checkout (PROP-ledger-gate)
- The hook resolves the main checkout path from the worktree via `git rev-parse --git-common-dir` and checks for the ledger at `.current-work/*/dispatch-ledger.yaml` relative to the main checkout (PROP-ledger-gate)
- The denial message names the missing ledger and suggests running `dispatch init` (PROP-ledger-gate)
- implementation-agent.md contains a MUST requiring `dispatch init` as the implementation agent's first action before creating any story branches (PROP-ledger-gate)
- Commits on non-story branches (feature/\*, dev, main) are unaffected by this gate (PROP-ledger-gate)

## Scope

**Status quo:** block-dangerous-git.sh gates worktree commits on verify-base-ok marker existence and gates merges on premerge-check-ok marker. It does not check for dispatch-ledger existence. implementation-agent.md describes the branching model and dispatch workflow but contains no explicit MUST for `dispatch init` ordering. The dispatch close ceremony from ST-0212 is in place.

**Adds:** Dispatch-ledger existence check in block-dangerous-git.sh for story/\* branches. MUST clause in implementation-agent.md. Integration test covering the new gate.

**Out of scope:** Changes to the dispatch script itself. Changes to verify-base. Feature-branch or invocation-branch ledger checks.

## Terminology

- Dispatch ledger: the YAML file at `.current-work/<feature-branch>/dispatch-ledger.yaml` tracking every story in a dispatch, owned by `factory/scripts/dispatch`.
- Main checkout: the primary git working tree (not a linked worktree), where `.current-work/` lives.
- `git-common-dir`: the git directory shared by all linked worktrees, which points back to the main checkout.

## Notes for the Implementer

The hook must resolve the main checkout from a linked worktree. Use `git rev-parse --git-common-dir` to find the shared git directory, then derive the main checkout's working tree root. The ledger path pattern is `.current-work/*/dispatch-ledger.yaml` — the wildcard covers the feature-branch directory name. Existing tests in `tests/test_block_dangerous_git.py` cover the verify-base and premerge-check gates; add new test cases following the same subprocess-based pattern for the ledger gate.
