# Give every open finding an owner

**Priority:** must-have

## Goal

Every open finding in `docs/findings/` carries an `owner:` field, so the orchestrator sends it to the agent that acts on it next without the fallback of ST-0352. The story runs after ST-0363, because only then does every core artifact have exactly one producer.

## Contract

| Operation | Input state                                                                              | Outcome                                                                                         | Persistence  |
| --------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------ |
| Backfill  | Open `BUG` finding without `owner:`                                                      | `owner: developer-agent`                                                                        | Finding file |
| Backfill  | Open finding about an artifact with one producer in `INDEX.yaml`                         | `owner:` names that producer                                                                    | Finding file |
| Backfill  | Open finding about a factory file under `packages/factory/` or `.agent-factory/factory/` | `owner: developer-agent`; the fix goes into `packages/factory/`                                 | Finding file |
| Backfill  | Open `SEC` finding                                                                       | `owner: developer-agent`                                                                        | Finding file |
| Backfill  | Open finding without an artifact, such as a `RETRO` finding                              | `owner: virgil`, who shapes it into a proposal with the stakeholder                             | Finding file |
| Backfill  | Open finding about a proposal under `docs/proposals/`                                    | `owner: virgil`; the filer is not the owner, and Virgil revises proposals with `draft-proposal` | Finding file |
| Backfill  | Open finding that spans several owners, such as `RECON-cycle-retirement`                 | `owner: virgil`, who first splits it into work, the same rule as a finding without an artifact  | Finding file |
| Backfill  | Finding with status other than `open`                                                    | Unchanged                                                                                       | None         |
| Backfill  | Finding that already has `owner:`                                                        | Unchanged                                                                                       | None         |

## Demo Scenario

1. The maintainer runs `grep -L '^owner:'` on the open findings in `docs/findings/` before the story. It lists 39 files.
2. After the story, the same command lists none.
3. The maintainer opens a `BUG` finding about `packages/factory/scripts/dispatch` (Demo Data). It carries `owner: developer-agent`.

## Demo Data

The story seeds nothing. It changes the 39 open findings that exist in `docs/findings/` on 2026-11-04: 25 `BUG`, 5 `PROP`, 4 `RECON`, 4 `RETRO`, and 1 `SEC`. Several `BUG` findings name `packages/factory/scripts/dispatch` as their artifact.

## Boundaries

- Only the `owner:` line changes. Status, body, and other fields stay.
- The owner follows [interface-contracts.md](../docs/spec/interface-contracts.md), contract "finding frontmatter owner", and CAO-G26.
- `quality-gates: []` stays for the reason ST-0359's Boundaries give.

## Affected Paths

- `docs/findings/` — existing open finding files; `owner:` added.

- [gaps report § CAO-G26](../docs/spec/work/core-artifact-ownership-gaps.md#cao-g26-where-does-a-finding-without-owner-go).

```bash

```

## Out of Scope

- Closed or resolved findings.
- Any fix of the problems the findings describe.

## Agent Stop Conditions

- A finding names an artifact that matches two producers in `INDEX.yaml`. Report the finding and the producers.

## Resolve Before Implementation

None. The stakeholder settled the one open question on 2026-11-05: a finding about a factory file goes to the developer agent, because in this repository the factory is the product's source; a finding without an artifact goes to Virgil. The Contract holds the answer.

## Analysis

- Files modified: 33 open findings in `docs/findings/`. Each gains one `owner:` line before the closing frontmatter fence.
- Owners follow the Contract: `BUG` and `SEC` to `developer-agent` (26); `RECON-0018` and `RECON-0019` name factory files, so `developer-agent`; `RETRO` to `virgil` (4); `RECON-0023` names `docs/spec/scope-map.md`, whose only producer in `INDEX.yaml` is `requirements-agent`.
- Stop condition hit for six findings, left without `owner:`: `PROP-0020` to `PROP-0024` name `docs/proposals/{name}.md`, which `proposal-review-agent` and `virgil` both declare as outputs; `RECON-cycle-retirement` names `docs/` and `packages/factory/` and matches no single producer.
- Scenario covered: "Owner receives every finding it acts on next". The change is data only, so no test fits. Evidence comes from `grep` and `git diff`.
