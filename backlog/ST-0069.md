# Prove dispatch base and merge gates on negative paths

Close the verified assurance gaps around exact declared bases and contaminated
diffs without replacing the shipped preflight or pre-merge gates.

**Priority:** must-have

## Acceptance Criteria

- `verify-base --expect-base` rejects anything other than an exact lowercase
  40-character object name before writing a success marker.
- Direct tests prove stale-target and wrong-declared-base failures leave no
  marker that authorizes subsequent work.
- Direct tests prove stale/target-reverting, out-of-scope, and file-count
  blowout diffs block and that only a clean in-scope diff writes the matching
  merge marker.
- Tests use real temporary Git histories and distinguish usage errors from
  blocking findings.

## Implementation Notes

The target-revert case is evidenced through the shipped stale-base signature:
a branch missing target commits necessarily proposes their reversal. No new
diff algorithm is planned unless the regression test exposes a defect.

## Analysis

ST-0069 supplies the negative-path assurance required by UC-12, FR-L1/FR-L2,
and BR-043 through BR-046 without redesigning the delivered safeguards. Direct
tests will create real temporary Git histories and execute the public
`factory/scripts/verify-base` and `factory/scripts/premerge-check` process
boundaries. They cover stale target history, a wrong declared base, malformed
declared SHA syntax, target-reverting/stale pre-merge history, out-of-scope
changes, file-count blowout, a clean in-scope diff, and the exit-code
distinction between usage/invocation errors and blocking findings.

Only the declared outputs and this story will change. The verify-base tests are
expected to require the smallest implementation repair: validate
`--expect-base` as an exact lowercase 40-character hexadecimal object name,
classify malformed or unresolvable inputs as exit `2`, and invalidate any old
success marker before a new preflight can fail. The pre-merge tests preserve
the shipped stale-base signature as the target-revert detector and will not add
a second diff algorithm unless they expose a regression.

**Test seams.** Both suites observe subprocess exit status, diagnostics, and
marker files at the scripts' existing CLI boundaries. Git history construction
is test fixture setup rather than a mocked Git seam, so each tracer proves the
same ancestry and three-dot-diff behavior used in dispatch. Phase approval
confirms these seams; no additional user pause is required.

No ambiguity requires an ADR. The traced specification already defines exact
SHA form, halt-before-work evidence, the accepted four pre-merge blocking
modes, and the `complete` versus `verified gap` boundary.
