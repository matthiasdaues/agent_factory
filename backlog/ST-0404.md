# Count register file names as IDs in use in next-id --plan-seed

**Priority:** must-have

## Goal

A user runs `next-id --plan-seed`, and the seed command counts the ID of each register file `docs/findings/register/<class>/<PREFIX>-NNNN.json` as in use. The `id` of each line in an old `docs/findings/register/*.jsonl` still counts. So a seed never starts a finding sequence below a `minor` finding ID, before or after the migration.

## Contract

| ID source on a local or remote-tracking branch, or in the working tree | Counted                    |
| ---------------------------------------------------------------------- | -------------------------- |
| `docs/findings/register/security/SEC-0012.json`                        | `SEC` 12, by its file name |
| `docs/findings/register/code.jsonl` with a line `"id": "IMPL-0007"`    | `IMPL` 7, as before        |
| `docs/findings/register/code/notes.json`, no ID pattern                | not counted, no warning    |
| the body of a register file                                            | never read                 |

## Demo Scenario

1. The User creates a local bare repository `/tmp/seed-origin.git` and a clone `/tmp/seed-demo` whose `dev` holds `docs/findings/SEC-0005.md` and `docs/findings/register/security/SEC-0012.json`.
2. The User runs `next-id --plan-seed` in `/tmp/seed-demo`. It prints `next-id --seed 0 SEC=12` and exits `0`.
3. The User adds `docs/findings/register/code.jsonl` with one line for `IMPL-0007`. The command then also holds `IMPL=7`.

## Demo Data

| Path in `/tmp/seed-demo` on `dev`               | Content                                    |
| ----------------------------------------------- | ------------------------------------------ |
| `docs/findings/SEC-0005.md`                     | any finding text                           |
| `docs/findings/register/security/SEC-0012.json` | one register object, `id: SEC-0012`        |
| `docs/findings/register/code.jsonl`             | one line with `"id": "IMPL-0007"` (step 3) |
