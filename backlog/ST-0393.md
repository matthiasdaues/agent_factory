# Reject in_use false for lines that exist unchanged where they are in use

**Priority:** must-have

## Goal

The user sees `finding-lint` exit `1` with `artifact lines exist unchanged on <place>` when a code, runtime, or security finding answers `in_use: false` while every line of its artifact exists unchanged on `dev`, `main`, `origin/dev`, `origin/main`, or in the installed copy. Document and architecture findings skip the check. A true `in_use` passes even when git finds no match.

## Domain Rule

- A line is unchanged when its introducing commit and its original line number from `git blame -M -C --porcelain` match. The porcelain file name stays part of the identity only; it may name a path that no longer exists (FC-QG08).
- On each place, the lint blames the artifact path and every rename or copy source that `git diff -M -C <place> <reviewed branch>` names for it.
- A `path#anchor` artifact is the section under the heading, down to the next heading of the same or a higher level.
- The places are local `dev` and `main`, `origin/dev`, and `origin/main`. A branch the clone lacks is skipped and named, such as `skipped main: no such branch`.
- The installed copy is blamed with `--contents` when `packages/factory/` exists. From a linked worktree, `_main_checkout.py` finds it in the main checkout. A line no commit introduced, the all-zero commit, never counts as unchanged.
- A failed check names the first place in the order of the contract's message table.
- The check sets a lower bound only.

## Outputs

- The git check in `finding-lint` for each code, runtime, and security finding file and register file. Release tags are added by ST-0394, and the trigger by ST-0395; until then the check runs on every such file.

## Demo Scenario

1. The User builds `/tmp/inuse-demo` as the QA strategy's test setup defines: `main`, `dev`, and `feature/demo`, with `packages/factory/scripts/premerge-check` committed on `dev`, and an untracked copy in `.agent-factory/factory/scripts/`.
2. On `feature/demo`, 20 lines are inserted above the defect. `docs/findings/FAGAN-0042.md` names `packages/factory/scripts/premerge-check:120-134` with `in_use: false`.
3. The User runs `finding-lint`. It exits `1` and prints `artifact lines exist unchanged on dev`, because lines 120 to 134 are lines 100 to 114 on `dev`.
4. The User changes the finding to `review_class: document`. The lint skips the git check and exits `0`.
5. The User runs the lint from a linked worktree of `feature/demo` whose only `.agent-factory/` sits in the main checkout. It still finds the installed copy.

## Analysis

- **Behaviour added:** `finding-lint` checks `in_use` against git for each
  code, runtime, and security finding file and register file that answers
  `in_use: false` (BR-088). It blames the artifact range in the working tree
  with `git blame -M -C --porcelain` and collects one line identity per line:
  the introducing commit, the original line number, and the original file
  name. It then blames each place in the order of the contract's message
  table: `dev`, `main`, `origin/dev`, `origin/main`, and the installed copy.
  On a branch, it blames the artifact path and every rename or copy source
  that `git diff -M -C --name-status <place>` names for that path. The first
  place that holds every identity gives the message
  `artifact lines exist unchanged on <place>` or
  `... in the installed copy`. A missing branch prints
  `skipped <branch>: no such branch` once and is no violation.
- **Installed copy:** blamed with `--contents` against the tracked path under
  `packages/factory/`, only when `packages/factory/` exists. Without a local
  `.agent-factory/`, `_main_checkout.installed_copy_in_main_checkout` finds the
  copy in the main checkout. Its interface fits, so `_main_checkout.py` stays
  unchanged. The all-zero commit never counts, on either side.
- **Heading artifact:** the range runs from the heading line down to the line
  before the next heading of the same or a higher level, outside code fences.
  The anchor is the GitHub slug of the heading.
- **No range to compare:** an artifact file that is absent, untracked at
  `HEAD`, shorter than the range, or without the heading has no committed
  lines, so no place can hold them, and the check passes. Outside a
  repository and without a commit, the lint runs no git check. A git call that
  fails exits `2`.
- **Governing Rule:** "finding-lint checks in_use against git for code,
  runtime, and security findings", the Scenarios that do not name tags, the
  settings file, or the `HEAD` trigger (ST-0394, ST-0395).
- **Files changed:** `packages/factory/scripts/finding-lint`;
  `tests/factory/test_finding_lint.py` for FC-11-CT-01;
  `tests/factory/test_finding_lint_git.py` for FC-11-IT-01 to FC-11-IT-11,
  FC-11-IT-19, FC-11-IT-20, and FC-11-IT-22 to FC-11-IT-25. The module marker
  FC-10-IT-02 of that file moves onto its ST-0392 tests, so each test carries
  the marker of its own row.
- **Seams:** `parse_porcelain` and `section_range` for the contract test, and
  the script run as a subprocess on temporary git repositories for the
  integration tests.
