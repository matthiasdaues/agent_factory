# See from init-factory how to seed the counter

**Priority:** must-have

## Goal

When the User runs `init-factory`, it tells the User how to seed the counter if `origin` lacks it, how to add `origin` if the project has none, and warns when `origin` does not answer. The install finishes in each case, and `init-factory` never seeds.

## Contract

| Operation      | Input state                                               | Outcome                                                                    | Persistence                                 |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------- |
| `init-factory` | `origin` is a bare repository without `refs/ids/counters` | Prints "run `next-id --seed <number>` with a number above your highest ID" | `origin` still holds no `refs/ids/counters` |
| `init-factory` | The project has no `origin`                               | Prints "add the remote `origin`, then run `next-id --seed <number>`"       | None                                        |
| `init-factory` | `origin` points at a closed local port                    | Prints a warning that names the remote; finishes the install; exit `0`     | `.agent-factory/install.json` written       |

## Demo Scenario

1. In the project of Demo Data, the User runs `init-factory`. It prints the seed message, and `git ls-remote /tmp/origin.git refs/ids/counters` prints nothing.
2. The User runs `git remote remove origin` and `init-factory` again. It prints the remote message.
3. The User adds `origin` as `http://127.0.0.1:<closed port>/remote.git` and runs `init-factory`. It prints a warning that names that URL, finishes, and exits `0`.
4. The User sets `origin` back to `/tmp/origin.git` and runs `next-id --seed 1000`, as the message says. The next `next-id ST` prints `ST-1001`.

## Demo Data

| Item        | Value                                                              |
| ----------- | ------------------------------------------------------------------ |
| Project     | `/tmp/project`, made with `git init`, one commit                   |
| `origin`    | `/tmp/origin.git`, made with `git init --bare`, no counter         |
| Closed port | A port on `127.0.0.1` that the test binds, reads, and closes again |

## Boundaries

- `init-factory` only asks `origin` whether `refs/ids/counters` exists. It never seeds and never pushes (DEC-17).
- No counter case stops the install (DEC-23).
- The tests assert the messages only, not the exit code, for a missing counter and a missing `origin` (`Gap: CID-G02`).
- The check must not wait for a network timeout on a closed port.

## Resolve Before Implementation

Open for the stakeholder at step 3.4. The story does not wait on it, because its tests assert nothing on these cases:

1. Which exit code does `init-factory` give for a missing counter and for a missing `origin`, and what does it print when the counter exists (`Gap: CID-G02`)? Exit `0` is the likely intent, because the install needs no counter.
