# Keep the handbook page lists current and block a broken page at commit

A contributor gets each page list of both handbooks written by a script, sees every broken page in one lint run, and cannot commit a broken page.

**Priority:** must-have

## Goal

A contributor runs `handbook-index` and finds the page list of every `index.md` written between its markers. `handbook-lint` reports every broken page, folder, marker pair, duplicate title, and stale page list of both handbooks in one run. A commit fails while `handbook-lint` fails.

## Domain Rule

- BR-140 to BR-148 in [validation-rules.md § Factory handbooks](../docs/spec/validation-rules.md#factory-handbooks-handbook-index-handbook-lint-br-140br-152) are the normative rules. This story implements them as written and does not restate them.
- `handbook-index` writes only between `<!-- handbook-index:start -->` and `<!-- handbook-index:end -->`. A byte outside the markers never changes (BR-143).
- `handbook-index` refuses and writes no file when any page of either handbook breaks BR-140 (L-31).
- `handbook-lint` reports every failure of both handbooks, not only the first. A refusal of `handbook-index --check` stops no other check (BR-147).
- Both scripts read both handbook roots, `packages/factory/docs/handbook/` and `docs/handbook/`, and no other folder.
- Each root holds an `index.md` from this story on, because BR-141 fails a missing root and the hook runs on every commit. Each root `index.md` holds the frontmatter of BR-140, the marker pair, and an empty page list, since no chapter exists yet.

## Demo Scenario

1. The contributor creates `docs/handbook/testing/index.md` with `title: Testing`, `type: concept`, `status: implemented`, `order: 60`, and the marker pair.
2. The contributor creates `docs/handbook/testing/layers.md` with `title: Test layers`, `type: how-to`, `status: implemented`, and `description: Pick the test layer for one change.`
3. The contributor runs `packages/factory/scripts/handbook-index`. It exits 0. `docs/handbook/testing/index.md` lists "Test layers" under "How-to guides" with the description, and `docs/handbook/index.md` lists the chapter "Testing".
4. The contributor deletes the `type` line of `layers.md` and runs `packages/factory/scripts/handbook-lint`. It exits non-zero and names `docs/handbook/testing/layers.md` and the field `type`.
5. The contributor stages both files and runs `git commit -m "docs: add test layers"`. The hook `handbook-lint` fails, and `git log -1` shows no new commit.
6. The contributor removes the two demo files and runs `handbook-index` again. `handbook-lint` exits 0.

## Demo Data

None. The demo writes the two pages of steps 1 and 2 and removes them in step 6. The tests build the model chapter `cli-integrations/` of the feature description in a temporary folder with one helper in `test_handbook_index.py`. `test_handbook_lint.py` imports that helper (QA strategy).

## Analysis

Two scripts share one reader. `handbook-index` reads both handbook roots from the working directory, validates each page against BR-140 and each marker pair against BR-143, and writes the page lists between the markers. `handbook-lint` imports that reader, adds the folder rules (BR-141), the duplicate-title rule (BR-142), and the stale-list check (BR-146), and prints one line per failure. The hook goes into the development block of `.pre-commit-config.yaml` and runs the source script with `always_run: true`. Both handbook roots get an `index.md` with an empty page list. The tests cover FH-01-01 to FH-02-03 and FH-03-01. The `finding-lint` guard does not apply to a hook that runs the source script (spec-feedback row).
