# Grill stakeholder to shape the agent-context user interface

Run a structured grilling session (using the grill-with-docs skill) with the project stakeholder to shape the interface between the user's own workflow and the factory's agent-context machinery. The grilling determines the vocabulary the guidance will use, the mental model it presents (routing table vs. knowledge base), the customization points it highlights, and how it explains control boundaries. This is a design conversation that determines content -- not a review-after-the-fact.

**Priority:** must-have

## Demo

The stakeholder participates in a grill-with-docs session. The facilitator asks questions about the stakeholder's workflow: how they organize their project documentation, what conventions they maintain, how they want agents to discover project knowledge, and where they draw the line between what the factory controls and what they control. The session produces a design brief documenting: (1) the agreed vocabulary -- whether to say "routing table," "knowledge index," or another term; (2) the chosen mental model -- how to frame the relationship between source documents and agent-context files; (3) the customization points to highlight -- which parts of the reading guide the user should modify for their project; (4) the control boundaries to explain -- what the factory reads versus what the user owns.

## Acceptance Criteria

- A grilling session is conducted using the grill-with-docs skill with the project stakeholder.
- The grilling output documents the agreed vocabulary for agent-context guidance.
- The grilling output documents the chosen mental model (how to frame the routing table for a non-technical project owner).
- The grilling output documents the customization points to highlight in the factory guide.
- The grilling output documents the control boundaries between user-owned source documents and factory-read routing table.
- The grilling is a design step that shapes content before documentation is written, not a review of pre-written documentation.

## Scope

**Status quo:** The agent-context machinery is defined in proposals, ADRs, and specifications. No user-facing guidance exists that explains the feature to a project owner who has not read the proposal. The factory guide has no agent-context section. The grilling skill exists and is operational.

**Adds:** A design brief capturing the stakeholder's vocabulary preferences, mental model choice, customization expectations, and control-boundary understanding. This brief becomes the authoritative input for ST-0200 (writing the guidance).

**Out of scope:** Writing the actual factory-guide section (ST-0200). Path updates in agents/skills/playbooks (EPIC 4). Convention and rules.md entries (EPIC 1).

## Notes for the Implementer

Use the grill-with-docs skill to structure the conversation. The key questions to explore: (1) How does the stakeholder currently organize their project's source-of-truth documents? (2) What metaphor feels right -- is agent-context a "table of contents," a "routing table," a "knowledge map"? (3) Which customization points matter most -- adding concerns, changing source pointers, deferring decisions? (4) Where does the stakeholder want the boundary between "I control this" and "the factory reads this"? The output should be concrete enough to write documentation from, not abstract principles.
