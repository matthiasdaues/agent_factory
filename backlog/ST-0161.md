# Handle deletion stories in backlog-lint VR-027

Add `"deletion"` to `VALID_STRATEGIES` in `factory/scripts/backlog-lint` (line 51) and invert the VR-027 check when `strategy == "deletion"` and `status == "done"`: verify that NONE of the listed output files exist (confirming the deletion was successful). If any output files still exist, emit a VR-027 error. This allows deletion stories to pass lint without workarounds like self-referencing the backlog file.

**Priority:** should-have

## Acceptance Criteria

- `VALID_STRATEGIES` at line 51 of `factory/scripts/backlog-lint` includes `"deletion"`
- When `strategy == "deletion"` and `status == "done"`, VR-027 verifies that NONE of the output files exist
- When `strategy == "deletion"` and `status == "done"` and any output file still exists, VR-027 emits an error naming the surviving file(s)
- When `strategy == "deletion"` and `status != "done"`, the existing VR-027 logic applies unchanged
- Non-deletion stories are unaffected by this change
- Tests in `tests/factory/test_backlog_lint.py` cover: deletion story done with all files removed (pass), deletion story done with a surviving file (error), deletion story pending (normal VR-027), and non-deletion story behavior unchanged

- ST-0147 (delete run-tests and mutation-analysis scripts) used a self-referencing workaround (`backlog/ST-0147.md` listed as an output) to pass VR-027; this fix makes such workarounds unnecessary for future deletion stories
