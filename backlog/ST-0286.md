# Update across a source boundary with separate consent

**Priority:** should-have

## Goal

A project maintainer who changes the source kind (local to remote, or remote to local) or the remote URL during an update receives a separate consent prompt for the source-boundary change. No automatic fallback crosses the source boundary. The update proceeds only after explicit confirmation of the source change.

## Contract

| Operation                                   | Input state                             | Outcome                                                                                       | Persistence                            |
| ------------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------- |
| `update-factory --from-remote <new-URL>`    | Manifest records a different remote URL | Source-boundary prompt shows current and requested source; approval proceeds to normal update | Receipt records the new source         |
| `update-factory --from-local ./path`        | Manifest records a remote source        | Source-boundary prompt shows the source-kind change; approval proceeds to normal update       | Receipt records the new source kind    |
| `update-factory --from-remote <same-URL>`   | Manifest records the same remote URL    | No source-boundary prompt; normal update approval only                                        | Receipt records the same source        |
| Blank input at source-boundary prompt       | Any source mismatch                     | Update stops without changes                                                                  | No manifest or filesystem changes      |
| `update-factory --force` with source change | Manifest records a different source     | Source-boundary prompt still appears; `--force` does not bypass source consent                | No changes until source consent passes |

## Boundaries

- The source-boundary consent is a separate prompt from the normal update approval. Both must pass for the update to proceed.
- No automatic fallback crosses the source boundary.
- `--force` does not bypass source-boundary consent. Source consent is always required.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Affected Paths

- `packages/factory/scripts/update-factory` — existing script (modified by ST-0285), extended with source-boundary detection and consent.
- `tests/factory/test_update_factory.py` — existing test file, extended with source-boundary tests.

## Demo Scenario

1. Install Factory from `https://releases.example.com`. Run `update-factory --from-remote https://other.example.com`.
2. `update-factory` shows the current source, the requested source, and a warning. Approve the source change.
3. The update proceeds with the new source. The receipt records the new source.
4. Run `update-factory --from-remote https://other.example.com` again (same source). No source-boundary prompt appears; only the normal update approval.
5. Run `update-factory --from-local ./factory-src` (source kind change from remote to local). The source-boundary prompt appears again.
6. Submit blank input at the source-boundary prompt. The update stops without changes.

## Demo Data

None. The demo exercises `update-factory` against a project with an existing Factory installation. The install manifest records the original source.

## Evidence

- [ ] A different source kind triggers a separate source-boundary consent prompt (VFO-005).
- [ ] A different remote URL triggers a separate source-boundary consent prompt (VFO-005).
- [ ] The same source kind and URL skip the source-boundary prompt.
- [ ] Blank input at the source-boundary prompt stops the update without changes.
- [ ] The receipt records the new source after an approved source-boundary change (VFO-025).

## Stop Conditions

- The install manifest does not record the source kind or URL in a field the detection logic can read → report which manifest fields are available and ask for the schema.
- The existing `--force` flag interacts with source-boundary consent in a way that conflicts with VFO-005 → report the conflict and ask for precedence.
- Code in `packages/factory/scripts/update-factory` and the feature spec disagree on when the source-boundary prompt appears → report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. Does the source-boundary prompt show a diff between the old and new source, or just name both?
2. Should `update-factory --check` report a source-boundary change when the selected source differs from the manifest, even though `--check` performs no writes?
