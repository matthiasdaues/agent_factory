# State the consequence in the QA triage table

**Priority:** must-have

## Goal

The test-strategy agent fills the triage table of a QA strategy with a `Consequence` column instead of a severity column. Each row's action follows the severity that the consequence tree computes from that consequence.

## Contract

| Consequence      | Computed severity | Action in the row             |
| ---------------- | ----------------- | ----------------------------- |
| "harm if in use" | `critical`        | stops the run                 |
| "fails purpose"  | `major`           | fix in the same story; blocks |
| "raises cost"    | `minor`           | register file; does not block |

## Demo Scenario

1. The User opens `packages/factory/rulebooks/templates/qa-strategy.md` § Defect Severity Triage.
2. The table has a `Consequence` column with the three values of the Contract and no severity column.
3. The User asks the test-strategy agent for a QA strategy of any feature. Its triage table follows the template.
