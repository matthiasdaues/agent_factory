# Seed and claim IDs from the project's own repository without origin

**Priority:** must-have

## Goal

In a project without `origin`, fitting step 4 seeds the counter in the `.git` of the project's main repository, and every worktree and local clone then claims its IDs from that one counter. A clone without `origin` and without the setting still fails and names `origin` and `--remote`, so no counter starts by accident.

## Contract

| Operation                                 | Input state                                                                                        | Outcome                                                                                        | Persistence                                           |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Step 4 in `/work/demo-feature`            | `/work/demo` has no `origin`; `/work/demo-feature` is its second worktree                          | VIRGIL sets `agent-factory.counterRemote` to `/work/demo` before it runs `next-id --plan-seed` | `.git/config` of `/work/demo` holds the setting       |
| The seed of step 4                        | The setting holds `/work/demo`; the User confirms `next-id --seed 0`                               | `/work/demo/.git` holds `refs/ids/counters`; `counter_seeded` is `true`                        | The local counter                                     |
| `next-id ST`                              | The setting holds `/work/demo`; the local counter holds `ST=0012`                                  | Prints `ST-0013`                                                                               | The claim commit in `/work/demo/.git` holds `ST=0013` |
| `next-id ST`                              | The setting holds `/work/demo` at `ST=0012`; `origin` at `ST=0040`; `/tmp/remote.git` at `ST=0070` | Prints `ST-0013`                                                                               | `origin` still holds `ST=0040`                        |
| `next-id ST --remote /tmp/remote.git`     | The same three counters                                                                            | Prints `ST-0071`                                                                               | `origin` still holds `ST=0040`                        |
| `next-id ST`                              | A clone without `origin` and without the setting                                                   | Exit non-zero; no ID; the message names `origin`, `--remote`, and `next-id --seed`             | None                                                  |
| `next-id --plan-seed`, `next-id --seed 0` | The setting holds `/work/demo`; no `origin`                                                        | Both use the local counter, by the same order                                                  | The seed writes the local counter                     |
| Step 4, User declines                     | No `origin`; VIRGIL set the setting                                                                | No seed; `counter_seeded` stays `false`; the setting stays (CIFP-C04)                          | `.git/config` keeps the setting                       |

## Demo Scenario

1. The User creates the project `/tmp/local-demo` and its second worktree `/tmp/local-demo-feature` of Demo Data and opens an agent session in `/tmp/local-demo-feature`.
2. The User walks fitting step 4. VIRGIL says that the project has no `origin`, sets `agent-factory.counterRemote` to `/tmp/local-demo`, runs `next-id --plan-seed`, and shows `next-id --seed 0 ST=12`.
3. The User confirms. VIRGIL runs the command. `git -C /tmp/local-demo for-each-ref refs/ids` lists `refs/ids/counters`, and `fitting.counter_seeded` is `true`.
4. In `/tmp/local-demo-feature`, the User runs `next-id ST`. It prints `ST-0013`. In `/tmp/local-demo`, `next-id ST` prints `ST-0014`.
5. The User clones `/tmp/local-demo` to `/tmp/local-demo-clone`, removes its `origin`, and runs `next-id ST` there. It exits non-zero and names `origin` and `--remote`.

## Boundaries

- `next-id` resolves its remote in the order `--remote`, then `agent-factory.counterRemote`, then `origin`, for a claim, a seed, and `--plan-seed` (BR-096). One function holds the order.
- The setting holds the absolute path of the main repository: the parent of the directory that `git rev-parse --git-common-dir` prints. VIRGIL sets it with `git config agent-factory.counterRemote <path>`, so every worktree sees it in the shared `.git/config`.
- A claim on the local counter pushes its claim commit into the project's own `.git`. That push is the one write to the clone (BR-075). The claim still runs in a throwaway bare repository.
- A clone without `origin` and without the setting never falls back to its own `.git` (DEC-08).
- VIRGIL runs no plain `git push` and no `git update-ref` on the counter. The seed goes through `next-id` (ADR-0032).
- The story gives `test_st_0370_clone_without_origin_names_origin_remote_and_seed` the precondition "without `agent-factory.counterRemote`" and keeps its three assertions (CIF-08-IT-03, retention policy).
- The story regenerates `INDEX.yaml` in the same commit, and `index-lint --check` passes.
