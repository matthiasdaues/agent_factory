# Read the user handbook in the factory voice after one lector pass

A user reads every page of the finished user handbook in the factory voice, because the lector agent read it once and its fixes are in the pages.

**Priority:** must-have

## Goal

The lector agent's sentence pass has edited every page of the finished user handbook, and its report is saved in `docs/reviews/`. The pages keep their facts, commands, paths, headings, and link targets; only the wording changes.

## Domain Rule

- The sentence pass of the lector edits the pages in place and returns a report of at most 300 words, as `packages/factory/agents/lector-agent.md` § Report defines. The developer saves that report as a file in `docs/reviews/`.
- The lector changes wording, never meaning. The developer checks the diff for meaning changes and reverts an edit that changes a fact, a command, or a path.
- The lector runs in a separate session from the authors of ST-0453 and ST-0454, as the lector agent's definition requires.
- The pass covers every page of `packages/factory/docs/handbook/`, including the `concept` page that ST-0454 writes. It does not cover the contributor handbook.
- The lector also checks the two review checks of prose: no binding rule in ordinary prose (DEC-02, BR-149), and each page holds what its `type` allows.

## Demo Scenario

1. The developer starts the lector agent's sentence pass on `packages/factory/docs/handbook/` in a fresh session.
2. The lector edits the pages and returns its report. The developer saves it as `docs/reviews/lector-user-handbook-<date>.md`.
3. `git diff packages/factory/docs/handbook/` shows changes in sentence wording only; every heading, code span, and link target is unchanged.
4. The contributor opens the report, takes its before/after example of the most common fault, and finds the after-sentence on the page it came from.
5. `packages/factory/scripts/handbook-lint` exits 0.

## Demo Data

None. The demo uses the user handbook after ST-0454.

## Boundaries

- The lector leaves frontmatter unchanged, so the page lists stay current. A fix that needs a new `title` becomes a finding.
- A fix never removes a fact, a command, or a path that the migration map assigns to the page (acceptance criterion 12).
- The structural pass of the lector, which writes a cut plan, is not part of this story. A cut the lector proposes becomes a finding.
- No edit of the feature file, `validation-rules.md`, `interface-contracts.md`, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-ST-0457.md`.
- `quality-gates` is empty, because the story changes Markdown only.

## Out of Scope

- The contributor handbook.
- New pages, and any content the guide did not hold.
- The lector's structural pass.

## Agent Stop Conditions

- The lector proposes a fix that changes a fact, a command, or a path. Report the fix; do not apply it.
- The lector finds a binding rule in ordinary prose. Report the page and the rule as a finding for the page's owner.
- The lector report and the factory voice disagree on a wording rule. Report the conflicting text and the decision needed; do not add a workaround.

## Resolve Before Implementation

None. The lector agent's definition fixes the pass, and acceptance criterion 09 fixes its result.
