# Number a new story, finding, todo entry, or ADR with next-id

**Priority:** must-have

## Goal

An agent that creates a story, finding, todo entry, or ADR by following a Factory file runs `next-id` with the ID prefix and names the artifact with the printed ID. No Factory file tells its reader to scan for the highest number. A split story keeps its letter from the scan.

## Contract

| File                                                          | Rule after the story                                                                       | IDs                                                    |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| `packages/factory/skills/create-backlog/SKILL.md`             | The `id` rule: a new story takes its ID from `next-id ST`; a split keeps the letter scan   | `ST`                                                   |
| `packages/factory/rulebooks/conventions/finding-format.md`    | § File location and name: the `NNNN` comes from `next-id <TAG>`                            | `SPEC`, `FAGAN`, `SEC`, `BUG`, `RECON`, `ATAM`, `IMPL` |
| `packages/factory/playbooks/bug-fix.md`                       | The `docs/findings/BUG-NNNN.md` template takes its ID from `next-id BUG`                   | `BUG`                                                  |
| `packages/factory/rulebooks/conventions/todo-format.md`       | The `T-<NNNN>` rule: the number comes from `next-id T`                                     | `T`                                                    |
| `packages/factory/skills/write-adr/SKILL.md`                  | Step 3: the number comes from `next-id ADR`; the file stays `docs/adr/NNNN-short-title.md` | `ADR`                                                  |
| `packages/factory/skills/create-backlog-slice-story/SKILL.md` | Unchanged: split letters come from a scan of `backlog/ST-NNNN*.md`; no `next-id`           | `ST-NNNNA`                                             |

## Demo Scenario

1. The User prepares the scratch project of Demo Data and opens an agent session in it.
2. The User asks the agent to record the decision "Counter ref on the remote" with `write-adr`. The agent runs `next-id ADR`, which prints `ADR-0007`, and saves `docs/adr/0007-counter-ref-on-the-remote.md`.
3. The User asks the agent to file a code-review finding. The agent runs `next-id FAGAN`, which prints `FAGAN-1001`, and writes `docs/findings/FAGAN-1001.md`.
4. The User asks the agent to split `ST-0327`. The agent writes `backlog/ST-0327A.md` and `backlog/ST-0327B.md` and runs no `next-id`.

## Boundaries

- Each file names the installed path `.agent-factory/factory/scripts/next-id`, as the files name other Factory scripts.
- Each file tells its reader to read the ID from the standard output of `next-id`, because a shell variable does not survive from one agent command to the next (DEC-08).
- Each file tells its reader to stop and report the message when `next-id` fails, and never to pick a number by hand.
- `create-backlog-slice-story/SKILL.md` keeps its letter scan. Letters for split stories are deferred.
- The text tests check the rule of each file, not one exact sentence.
- The story regenerates `INDEX.yaml` in the same commit, and `index-lint --check` passes.
