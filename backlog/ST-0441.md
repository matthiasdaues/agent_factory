# Keep agents from writing the exceptions register

Only a person writes the exceptions register: every agent write is refused, and the finding tools leave the file alone.

**Priority:** must-have

## Goal

An agent's call that writes, edits, or redirects into `docs/findings/exceptions.md` is refused in every supported CLI, and the file stays unchanged. An agent can still read the file. `finding-lint` and the stop notice do not treat the register as a finding.

## Domain Rule

- BR-092 adds the register to the files that only the stakeholder writes.
- `guard-human-fields` refuses a Write, an Edit, and a shell command that writes the file, such as a redirect, `sed -i`, `tee` or `cp`, in the payload format of each supported CLI.
- A read such as `cat docs/findings/exceptions.md` passes, and a write of a finding file such as `docs/findings/BUG-0090.md` without a human field passes as before.
- `is_finding_path("docs/findings/exceptions.md")` is false, so `finding-lint` reports no problem for the file, and `stop_notice` never names it.

## Outputs

- `guard-human-fields`: the register path is guarded.
- `finding-lint`: the register is skipped by name.
- `stop_notice` in `dispatch_lib.py`: the register is skipped by name.
- Rows in `tests/factory/test_guard_human_fields.py`, `test_finding_lint.py` and `test_finding_stop.py`.

## Analysis

- `guard-human-fields`: `guarded()` gives `docs/findings/exceptions.md` its own kind `exceptions`. Every write, edit, patch, or shell write into a path of that kind is refused, whatever the call changes (BR-092, BR-132). A shell call names its write targets through a redirect, `tee`, `sed -i`, `perl -i`, an interpreter, and now also the destination of `cp` and `mv`. A `cat` names no write target, so it passes.
- `finding-lint`: `is_finding_path` returns false for the register by name.
- `dispatch_lib.py`: `stop_notice` drops the register from the working-tree versions and the `HEAD` versions by name.
- Tests: CG-06-IT-01 and CG-06-IT-02 in `tests/factory/test_guard_human_fields.py`, CG-06-CT-01 in `test_finding_lint.py`, CG-06-CT-02 in `test_finding_stop.py`.
- Scenarios covered: the Scenario Outline "guard-human-fields refuses an agent's write to the exceptions register", "finding-lint passes with the exceptions register present", and "The stop notice does not report the exceptions register" of the Rule "User keeps agents from writing the exceptions register".
- BR-092 and the Guarded row of the guard contract do not conflict: the row lists `docs/findings/*.md`, which holds the register path. The row does not say that every write into the register is refused, so the contract gets a spec-feedback row.
- The guard now reads `cp` and `mv` as writes into their destination. For a finding file this changes nothing, because a `cp` command text holds no human value; the blind spot of DEC-42 stays.

## Demo Scenario

1. A temporary repository holds `docs/findings/exceptions.md` with a section `## CRAP score` and one row.
2. An agent's tool call `tee docs/findings/exceptions.md` reaches `guard-human-fields` in the Claude Code payload format. The guard refuses it, and the file is unchanged.
3. The same refusal holds for an Edit call and for `sed -i` in the payload formats of Codex, Copilot, Pi and OpenCode.
4. `cat docs/findings/exceptions.md` passes.
5. The User runs `finding-lint` on `docs/findings/`. It passes and does not name the register.

## Demo Data

The tests write the register into temporary repositories. No seeding script is involved. The row is the one of ST-0440's Demo Data.
