# Seed the counter in fitting step 4 after confirming the command

**Priority:** must-have

## Goal

A User who walks the fitting meets step 4, "Seed the ID counter", directly after step 3, "Decide on hooks". VIRGIL shows the command that `next-id --plan-seed` prints, says what it does, and runs it only after the User confirms. The fitting then counts six keys and is `fitted` only when all six are `true`.

## Domain Rule

- Step 4 follows step 3, because a seed is a push and the User decides on the hooks before the Factory's first push (DEC-01).
- VIRGIL runs the seed only after the User confirms the shown command. ADR-0032 lets an agent push the claim ref through `next-id` (DEC-03).
- VIRGIL says that the command creates `refs/ids/counters` on the counter's remote once and that every later ID continues from it.
- When the User declines, VIRGIL runs no seed, names the reason, and leaves `fitting.counter_seeded` `false`. The next session start lists the step as open.
- When the remote does not answer, VIRGIL runs no seed, names the unreachable remote, and leaves the key `false`.
- When `--plan-seed` reports a counter in use, VIRGIL runs no seed and sets the key `true`.
- A greenfield project walks step 0 and step 4. Its first story is `ST-0001` (DEC-06).
- `fitting.status` is `fitted` only when all six keys are `true` (BR-104).

## Outputs

- `virgil.md` § Fitting: step 4 with the behaviour above, the count "six", the greenfield sentence that names step 0 and step 4, and § Completion with six keys.
- `_fitting_status` in `init-factory` checks the six keys `model_matrix_configured`, `fingerprint_confirmed`, `agent_context_populated`, `test_regime_detected`, `hooks_decided`, and `counter_seeded`.
- Each of the four `AGENTS.*.md` files reads six fitting keys, holds the row `counter_seeded` with the step name "ID counter seed" as the sixth row, and shows "X/6".
- `session-menu.md` shows the fitting status as "X/6" and reruns all six fitting steps, the sixth being the seed (CIFP-C12).

## Demo Scenario

1. The User prepares the scratch project of Demo Data and opens an agent session. The session start reports "Fitting is 5/6 done" and names the open step "ID counter seed".
2. The User continues the fitting. VIRGIL runs `next-id --plan-seed`, shows `next-id --seed 0 ST=375 ADR=32`, and says that the command creates `refs/ids/counters` on `/tmp/fit-origin.git` once and that every later ID continues from it.
3. The User declines. VIRGIL runs no seed, says that the User declined, and `fitting.counter_seeded` stays `false`.
4. The User starts a new session. It lists the seed step as open. The User continues and confirms the command. VIRGIL runs it and sets `fitting.counter_seeded` to `true`, and `fitting.status` becomes `fitted`.
5. The User runs `next-id ST` in the project. It prints `ST-0376`.

- VIRGIL runs no plain `git push`. The seed is a push through `next-id`, which ADR-0032 allows.
- The no-`origin` branch of step 4, where VIRGIL sets `agent-factory.counterRemote`, belongs to ST-0379. Until then, step 4 names a missing `origin` as the reason it stops.
