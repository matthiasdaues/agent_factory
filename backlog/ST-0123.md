# Implementation-agent rewrite and convention documentation updates

Rewrite the implementation-agent workflow to call dispatch subcommands instead
of performing git operations directly. The agent's remaining job after this
rewrite is: review the plan, spawn subagents, and call script subcommands in
sequence. Update `dispatch-contract.md` with the `prepared` status,
script-owned ledger under `.current_work/`, pre-spawn verify-base, and
`premerge-check --scope`. Update `branching-policy.md` with the note that
verify-base is now script-owned.

**As a** dispatch operator,
**I want** the implementation agent to delegate all git operations to the
dispatch script,
**so that** deterministic orchestration is mechanical, not dependent on LLM
judgment.

**Priority:** must-have

## Acceptance Criteria

1. `implementation-agent.md` calls `dispatch init`, `dispatch plan`,
   `dispatch prepare-wave`, `dispatch mark-dispatching`,
   `dispatch mark-dispatched`, `dispatch verify-story`, `dispatch merge-story`,
   and `dispatch close-wave` instead of performing raw git operations.
2. The agent definition does not contain raw `git worktree`, `git merge`,
   `git branch`, or ledger-write instructions.
3. `dispatch-contract.md` documents the `prepared` status, the script-owned
   ledger at `.current_work/`, pre-spawn verify-base, and
   `premerge-check --scope`.
4. `branching-policy.md` notes that verify-base is invoked by the dispatch
   script, not by agent prose.
