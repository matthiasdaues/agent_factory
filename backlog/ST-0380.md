# Move the local counter to origin, or see why the move was refused

**Priority:** must-have

## Goal

The User runs `next-id --move-to-origin` in a project whose local counter now has an `origin`, and the counter moves to `origin` with every sequence intact. When `origin` already holds a counter or refuses the push, the move changes nothing and names the reason. Every claim and `--plan-seed` that later reads the local counter fails and names the remote that holds the counter now, without advising a seed.

## Contract

| Operation                  | Input state                                                                                                                                   | Outcome                                                                                                                         | Persistence                                                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `next-id --move-to-origin` | The setting holds `/work/demo`; the local counter is at C with `ST=0012`; `origin` is `https://user:token@host/demo.git` and holds no counter | Exit `0`; the next `next-id ST` prints `ST-0013` from `origin`                                                                  | `origin` holds C; the local counter holds a marker with parent C and the one line `moved=https://***@host/demo.git`; the setting is gone |
| `next-id --move-to-origin` | The local counter is at C; `origin` holds a claim commit D                                                                                    | Exit non-zero; the message names both counters by their redacted remotes and prints the `key=value` lines of C and D (CIFP-C15) | The local counter at C; `origin` at D; the setting stays                                                                                 |
| `next-id --move-to-origin` | The local counter is at C; `origin` refuses every update with a `pre-receive` hook that prints `read-only`                                    | Exit non-zero; the message holds git's message with `read-only`                                                                 | The local counter at C again; the setting stays                                                                                          |
| `next-id --move-to-origin` | No setting                                                                                                                                    | Exit non-zero; the message says that no local counter is set (CIFP-C16)                                                         | None                                                                                                                                     |

| `next-id ST`               | A local clone whose `origin` is `/work/demo`, which holds the marker `moved=https://***@host/demo.git`                                        | Exit non-zero; no ID; the message names `https://***@host/demo.git` as the remote that holds the counter; no `--seed`           | None                                                                                                                                     |
| `next-id --plan-seed`      | The same local clone                                                                                                                          | Exit non-zero; no seed command; the same message                                                                                | None                                                                                                                                     |

A move that reads a marker at the local counter belongs to ST-0381. Until then, the move names the marker and changes nothing.

## Demo Scenario

1. The User prepares the project `/tmp/move-demo` of Demo Data, adds `origin` as `/tmp/move-origin.git`, and runs `.agent-factory/factory/scripts/next-id --move-to-origin`. It exits `0`.
2. `git -C /tmp/move-origin.git log -1 --format=%B refs/ids/counters` shows `ST=0012`. `git -C /tmp/move-demo log -1 --format=%B refs/ids/counters` shows `moved=/tmp/move-origin.git`. `git config agent-factory.counterRemote` prints nothing.
3. The User runs `next-id ST` in `/tmp/move-demo`. It prints `ST-0013`.
4. The User runs `next-id ST` and `next-id --plan-seed` in the local clone `/tmp/move-clone`. Each exits non-zero and names `/tmp/move-origin.git` as the remote that holds the counter, and neither mentions `--seed`.
5. The User prepares a second project `/tmp/move-twice` of Demo Data, whose `origin` `/tmp/move-taken.git` holds a counter at `ST=0040`, and runs `next-id --move-to-origin`. It exits non-zero, names both counters, and prints `ST=0012` and `ST=0040`. Both refs and the setting are as before.

## Boundaries

- The move runs the four steps of BR-102 in order: read C, set the marker with a lease on C, push C with `--force-with-lease=refs/ids/counters:`, and remove the setting. A failed push puts C back with a lease on the marker.
- The marker commit has C as its only parent and the one line `moved=<remote>`, redacted by BR-077 (DEC-14).
- The move keeps its read of the local counter and its push as separate functions, so ST-0381 and its tests can wrap them with `load_script`.
- The create-only push never overwrites a counter on `origin`.
- Every git call of the move runs without prompts and with the 30-second limit of BR-076 (CIFP-C09).
- A message that reads a marker never mentions `--seed` (BR-097).
- Every refused or failed move exits non-zero (CIFP-C08).
- The move is a push through `next-id`, so ADR-0032 allows it. The story does not change `block-dangerous-git.sh`.
- No test prints a remote URL or a git config. Every failing path runs `_assert_no_token`.
