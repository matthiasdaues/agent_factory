# Exclude hook-regenerated files from update-factory checksums

Break the chain that forces `update-factory --force` after hook-modified files. When `index-lint` (a pre-commit hook) regenerates INDEX.yaml, the checksum changes, and `update-factory` detects a "user modification" that requires `--force`. But the modification is not a user choice — it is a hook doing its job. The source copy is always authoritative, and the hook will regenerate INDEX.yaml on the next commit anyway.

**Priority:** must-have

## Demo

1. Run `init-factory .` to install the factory with fresh checksums.
2. Make a change that triggers `index-lint` on the next commit (e.g. add a new skill). Commit — the pre-commit hook regenerates INDEX.yaml in the installed `factory/` directories.
3. Run `update-factory` (without `--force`). The update completes successfully — INDEX.yaml is not flagged as a user modification.
4. Inspect the checksum file at `.agent-factory/factory-checksums.json` and confirm INDEX.yaml is not present as a checksummed path.

## Acceptance Criteria

- `update-factory` does not flag INDEX.yaml as a user modification after a pre-commit hook regenerates it (PROP-stale-factory)
- Hook-regenerated file paths (initially INDEX.yaml per CLI directory) are listed in a named constant or configuration in the init-factory and update-factory scripts (PROP-stale-factory)
- The `_should_checksum` function in update-factory excludes hook-regenerated paths from checksum computation (PROP-stale-factory)
- The `compute_factory_checksums` function in init-factory excludes the same paths so that fresh installs and updates use the same exclusion list (PROP-stale-factory)
- `update-factory` overwrites excluded paths unconditionally during an update — no checksum comparison, no `--force` required (PROP-stale-factory)

## Scope

**Status quo:** Both init-factory and update-factory compute checksums for all files in `factory/` except `__pycache__/` and `.pyc` files. INDEX.yaml is checksummed. When index-lint rewrites INDEX.yaml, update-factory detects a mismatch and requires `--force`.

**Adds:** A `HOOK_REGENERATED_PATHS` constant listing paths that hooks regenerate (initially INDEX.yaml per CLI directory). Exclusion of these paths from `_should_checksum` / `compute_factory_checksums`. Unconditional overwrite of these paths during update.

**Out of scope:** Changes to `shutil.copytree` symlink handling. Changes to index-lint. Automatic `update-factory` triggers after merge. `--check` / `--dry-run` modes for init-factory.

## Notes for the Implementer

The exclusion list should be defined as a constant (e.g. `HOOK_REGENERATED_PATHS`) near the existing `CHECKSUM_SKIP_PREFIXES` and `CHECKSUM_SKIP_SUFFIXES` in both scripts. The paths to exclude are relative to the factory directory, matching the format used in existing checksum logic: `"skills/init-factory/INDEX.yaml"` and each CLI-specific copy. Alternatively, a simpler glob like `"**/INDEX.yaml"` or a suffix match on `"/INDEX.yaml"` may be cleaner — choose whichever is consistent with the existing skip patterns. The init-factory source is at `packages/factory/scripts/init-factory`; the installed copy at `factory/scripts/init-factory` is derived. Existing tests in `tests/test_update_factory.py` cover checksum behavior; add a test case that verifies INDEX.yaml modification does not trigger the force-required path.

## Analysis

Traced both scripts to their shared checksum machinery: `compute_factory_checksums` / `_should_checksum` in `packages/factory/scripts/init-factory` (around `CHECKSUM_SKIP_PREFIXES`/`CHECKSUM_SKIP_SUFFIXES`, originally lines 254-264) and the duplicated `_compute_checksums` / `_should_checksum` in `packages/factory/scripts/update-factory` (lines 75-108). The only INDEX.yaml file that actually exists under `factory/` is the single canonical `factory/INDEX.yaml` (checksum key `"INDEX.yaml"`); the per-CLI copies referenced in the story notes are symlinks into each dot-dir, not separate checksummed files, so no nested `skills/init-factory/INDEX.yaml` path exists in this repo today.

`update-factory` always replaces the entire `factory/` directory (move-aside, then a full `shutil.copytree` via the sourced `init-factory`) rather than copying file-by-file, so "unconditional overwrite of excluded paths" falls out of the existing full-replace architecture once the path is no longer flagged by `_detect_modifications` — no separate overwrite logic was needed.

Chose a suffix-aware match (`rel == p or rel.endswith(f"/{p}")`) over a literal string list so the same constant also covers a possible future nested `INDEX.yaml`, consistent with the existing `CHECKSUM_SKIP_PREFIXES` style of prefix/suffix matching rather than exact-path enumeration.
