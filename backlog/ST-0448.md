# Set up the CRAP gate with setup-crap-score through the test-strategy agent

The test-strategy agent sets the gate up with a skill that tries every proposal and leaves each decision to the User.

**Priority:** must-have

## Goal

The test-strategy agent runs the skill `setup-crap-score`. It proposes tried tools, exclusions with reasons, a threshold and a time limit, and writes the entry with `enabled: false` only after the User confirms. It runs the proof and `crap-score --all`, and enables the gate last, in one commit.

## Domain Rule

- Step 1 reads languages, test commands and suites from `docs/testing.yaml`. Step 2 tries the first candidate tool on a real project file before it proposes it; for a language outside the table, the agent looks tools up and tries them.
- The candidate table names `radon` and `lizard` with coverage.py for Python, and ESLint `complexity` and `lizard` with Vitest or Jest with v8 or `node --test --experimental-test-coverage` for TypeScript and JavaScript.
- Step 3 proposes each exclusion with a reason. Step 4 shows the change and writes the entry only after the User confirms. Step 5 runs the proof. Step 6 runs `crap-score --all`, reports the failures and the run time, and writes `measured_minutes` next to `timeout_minutes`. Step 7 runs the proof again when the threshold changed, then sets `enabled: true` after the User confirms (DEC-08).
- The skill writes the plant: `base/` and `gap/` in the project's layout, `proof_untested` and `proof_tested` with the same complexity at or below the threshold, and `proof_untested` above the threshold at 0 %.
- The skill writes the measuring command from the template of ST-0435 and fills its test-command constant in step 4. The command refers to nothing under `.agent-factory/`.
- The skill writes no register row and no commit hook, and commits `docs/testing.yaml`, the measuring commands and the `ready` commands once, after step 7 (DEC-05, DEC-32).
- The skill refers to `crap-score/SKILL.md` for the gate and does not repeat it (DEC-01). The test-strategy agent runs the proof and `crap-score --all` during setup and runs no gate on a story.

## Demo Scenario

1. In a small temporary Python project with `docs/testing.yaml` from `detect-test-regime`, the User asks the test-strategy agent to set up the CRAP gate.
2. The agent proposes the measure `python` from the template, tried on `src/parser.py`, with threshold 8 and `timeout_minutes: 10`. The User confirms, and the entry appears with `enabled: false`.
3. The agent runs `gate-setup-proof --measure python --plant .current-work/gate-setup-proof/python/` and shows four passing checks.
4. The agent runs `crap-score --all`, reports 2 failing functions and a run time of 1 minute, and writes `measured_minutes: 1`.
5. The User confirms threshold 8. The agent sets `enabled: true` and commits once. `git log` shows one setup commit.
