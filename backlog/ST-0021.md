# Templates and schemas for test-record, review, and vote

Author the paired template and JSON Schema for the three adversarial-stage
artifacts: the test record, the review, and the vote.

The test-record schema requires claim ID and version, test question, the
result that would refute the claim, method, evidence examined, observed
result, limitations, and an outcome restricted to `SURVIVED`, `REFUTED`,
`INCONCLUSIVE`, or `INVALID_TEST`. The review schema captures the ten review
checks and a defect classification restricted to `BLOCKER`, `MAJOR`, `MINOR`,
or `NOTE`. The vote schema requires a reference to one completed review, one
exact claim hash, one eligible reviewer, and a value restricted to `SURVIVE`,
`REFUTE`, `UNRESOLVED`, or `ABSTAIN`. These enum and reference constraints are
what later lets policy enforce quorum, majority, and current-version rules.

**Priority:** must-have

## Acceptance Criteria

- Templates exist for test-record, review, and vote with required headings and
  short field instructions, using the same field names as their schemas.
- The test-record schema restricts outcome to the four allowed values and
  requires the claim ID and version it tested.
- The review schema restricts defect level to the four allowed values.
- The vote schema restricts vote value to the four allowed values and requires
  a review reference, a claim hash, and a reviewer identity.
- Negative tests prove that an out-of-range outcome, defect level, or vote
  value fails `schema-validate`.
- A negative test proves a vote missing its claim-hash reference fails
  `schema-validate` (supports "changed claim invalidates prior votes").
