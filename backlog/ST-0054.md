# Consolidate shared capture lifecycle and installation tests

Make the shared lifecycle suite own cross-adapter drain, cancellation, fencing,
and supervisor cleanup; keep installation and removal cases at their filesystem
boundary without repeating adapter behavior.

**Priority:** must-have

## Acceptance Criteria

- Record before/after collected cases and lines for the three modules.
- Express equivalent native-adapter lifecycle outcomes once rather than as a
  full CLI-by-operation cross-product.
- Preserve distinct installation security, idempotency, capability-probe, and
  project-owned configuration boundaries.
- Preserve removal byte-identity and no-resurrection contracts.
- Demonstrate a representative lifecycle and install/remove fault is detected by
  the surviving owner.
- The affected modules and full suites pass with warnings treated as errors.

## Implementation evidence

Base verification used the full SHA
`ca73faab81b32d3880aa98139a935cfb67a64c9c` and reported zero commits ahead
of `feat/sustainable-testing` before implementation.

### Inventory and ownership

The three declared modules collected **48 cases in 1,041 lines** before the
change and **40 cases in 1,039 lines** afterwards: eight collected cases and
two lines removed.

- Shared native lifecycle outcomes use a representative pairwise matrix: all
  three native adapters are exercised, while drain/cancel and source/runtime
  failure outcomes are each owned without repeating their full cross-product.
- Installation owns runtime hashing and offline provisioning, capability-probe
  degradation, hook configuration merging, project configuration preservation,
  and rerun idempotency. Equivalent Claude, Copilot, and Codex rerun identity
  checks now share one snapshot contract.
- Removal retains separate byte-identical round trips for fresh and
  project-owned configurations, double-init/single-remove idempotency,
  manifest-less no-op behavior, selective hook removal, and fresh Codex
  directory cleanup. These preserve byte identity and prevent resurrection or
  deletion of project-owned state.

### Fault detection and verification

Three surviving owners were run explicitly with their built-in injected faults:

- supervisor spawn raises `OSError`, and lifecycle registration/snapshot state
  must still be cleaned;
- offline runtime provisioning fails, and capture hooks must remain inactive;
- pre-existing Codex hooks/configuration survive an install/remove round trip
  byte-identically.

All three fault cases passed, demonstrating that the surviving tests detect the
required cleanup, activation-fencing, and ownership boundaries.

- Declared affected modules: **40 passed** with warnings as errors.
- Full suite outside process/network sandbox restrictions: **381 passed** with
  warnings as errors.
- The sandboxed full run produced four environmental failures (one dependency
  download and three Pi process/worktree operations); the unrestricted rerun
  passed all 381 cases without a code change.
