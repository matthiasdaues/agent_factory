# Enable unrestricted selection, rework without ceremony, and end-to-end delivery

Verify and guarantee the behavioral properties of the activity-graph model: unrestricted agent selection, ceremony-free rework, research routing through preconditions, and stageless delivery.

**Priority:** should-have

## Goal

After this story ships, selecting an agent with unsatisfied inputs requires no override, confirmation dialog, or justification field. Editing an upstream artifact requires no workstream state transition, reconciliation evidence, or ceremony. Re-running the evaluator after an edit reflects the change. Research agent outputs satisfy downstream agent preconditions through the evaluator. No `origin_cycle` or `return_cycle` fields exist in research briefs. The developer follows a proposal through specification, architecture, planning, and implementation by selecting agents based on satisfied preconditions — no named stage transitions occur.

## Domain Rule

- Evidence does not block selection — the developer always picks any agent
- No confirmation dialog, override flag, or justification field is presented when selecting an agent with unsatisfied inputs
- The precondition graph has no forward direction to violate; the developer works on any artifact at any time
- Fixing an upstream artifact is just fixing an artifact — no state machine update, no cycle transition, no reconciliation step
- Re-running the evaluator checks the current repository state and reflects any fix
- Research agent output (research report) satisfies downstream preconditions when declared as a required input
- No `origin_cycle` or `return_cycle` fields exist in any research brief template or agent definition
- The delivery sequence from proposal to implementation emerges from the dependency chain, not from named stages

## Demo Scenario

1. Run `intent select`. Agent `developer-agent` shows one unsatisfied input: no pending story file matches its requirement.
2. Select `developer-agent`. The agent is dispatched without a confirmation dialog, override flag, or justification prompt.
3. A grilling session discovers a flaw in `docs/spec/scope-map.md`. Edit the file directly.
4. Run `intent select` again. The evaluator checks the current repository state. The evidence for agents that reference the scope map reflects the edited version. No workstream state transition or reconciliation step was needed.
5. Agent `researcher` produces a research report at `docs/research/findings.md`. Agent `architecture-agent` declares that report as a required input. Run `intent select`. The `architecture-agent` requirement referencing the report shows as satisfied.
6. Inspect the research brief template. No `origin_cycle` or `return_cycle` field exists.
7. Start with an accepted proposal. Select `requirements-agent` (preconditions satisfied by the proposal). After specification, select `architecture-agent` (preconditions satisfied by the spec). After architecture, select `planning-agent`. After planning, select `developer-agent`. Each selection is based on satisfied preconditions. No named stage transition occurs at any point.
