# Update requirements-agent with scope-map and derive-feature integration

Update the requirements-agent to replace the `derive-spec` invocation with
`derive-feature`, add the scope map as a Phase 1 output, and produce the
per-feature QA strategy document. The agent's workflow now produces three
primary outputs: the `.feature` file, the scope map, and the QA strategy.

**As a** playbook orchestrator,
**I want** the requirements-agent to produce an executable specification,
scope map, and QA strategy in one pass,
**so that** Phase 1 output is a complete, single-pass deliverable for
planning and implementation.

**Priority:** must-have

## Acceptance Criteria

01. The requirements-agent invokes `derive-feature` instead of `derive-spec`
    as its primary specification step.
02. The agent produces `docs/spec/scope-map.md` with all Rules from the
    accepted proposal, each with status, slice assignment, and feature-file
    link.
03. The agent produces `docs/spec/<feature-name>.feature` with
    Rule-per-actor-goal structure for the current slice.
04. The agent produces `docs/spec/<feature-name>-gaps.md`.
05. The agent produces `docs/spec/<feature-name>-qa-strategy.md` via the
    `qa-strategy-from-spec` skill.
06. The scope map lifecycle is implemented: Rules start as `deferred`, move
    to `specified` when a slice `.feature` file is produced, and move to
    `implemented` after merge.
07. Before running `derive-feature`, the agent checks for existing
    `docs/spec/scope-map.md`. If absent but `derive-spec` output artifacts
    exist (any `UC-XX-*.md` under `docs/spec/`), it runs
    `scope-map-migration` first.
08. Supplementary specs (`entity-model.md`, `interface-contracts.md`,
    `state-machines.md`, `validation-rules.md`) are still produced — they
    carry structural facts the `.feature` file does not.
09. The UC-XX document chain and `actor-goal-list.md` are no longer produced
    as separate artifacts.
10. All outputs pass `factory/scripts/validate`.
