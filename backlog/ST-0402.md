# Refuse the call in Pi and block it when the guard script is missing

**Priority:** must-have

## Goal

An agent in Pi is refused when its edit, write, patch, or shell call sets a human field, through a project-local extension that calls the guard from the `tool_call` event. When the guard script is missing, the extension blocks the call. `init-factory` links the extension into `.pi/extensions/` beside `step-guard.ts`.

## Contract

| Pi `tool_call` event                  | Guard script | Result                  |
| ------------------------------------- | ------------ | ----------------------- |
| edit, write, patch, or shell call     | exits `0`    | the call runs           |
| same                                  | exits `2`    | the call is blocked     |
| same                                  | missing      | the call is blocked     |
| a call outside the list, such as read | any          | not passed to the guard |

## Demo Scenario

1. The User runs `init-factory --cli pi` on `/tmp/guard-demo`. `.pi/extensions/` holds the guard extension beside `step-guard.ts`.
2. In Pi, the User asks the agent to waive FAGAN-0042. The call is blocked.
3. The User renames the guard script in `.agent-factory/factory/config/hooks/` and asks for a harmless edit of a finding. The call is blocked and names the missing script.

## Demo Data

Reuses `/tmp/guard-demo` and its findings from ST-0400.

## Boundaries

- `step-guard.ts` keeps letting a call through when its own script is missing; only the guard extension blocks (proposal § Fields only the human writes).
- The extension decides nothing about fields; the guard script decides, which the integration tests cover.
- The test runs in the `typescript` suite of `docs/testing.yaml` with `envelope-loader.mjs`, needs Node 22.6 or later, and adds no package (ADR-0036).
