# Copilot CLI pre_tool_use event surface spike

Verify that GitHub Copilot CLI exposes `PreToolUse` events for `Read`,
`Edit`, and `Write` tool calls in a format that `step-guard` can consume.
Document the event JSON schema, any differences from Claude Code's event
format, and confirm or deny feasibility of the shared adapter approach.
Produce a finding document with the results.

**As a** Factory developer,
**I want** to know whether Copilot CLI's hook surface supports tool-call
interception for read and write guards,
**so that** the CLI wiring story (ST-0129) can plan the adapter correctly or
identify needed workarounds.

**Priority:** must-have

## Acceptance Criteria

1. The spike produces a finding document at
   `docs/findings/copilot-pretooluse-spike.md`.
2. The finding documents the Copilot CLI `PreToolUse` event JSON schema for
   `Read`, `Edit`, and `Write` tool calls.
3. The finding confirms or denies that the event provides the file path in a
   field extractable by `jq` or equivalent.
4. The finding lists any differences from Claude Code's event format that
   require adapter logic.

## Analysis

- Update `docs/findings/copilot-pretooluse-spike.md` so it explicitly records
  the hook envelope, the file-tool JSON shape, the jq-extractable path, the
  Claude Code delta, and the feasibility conclusion.
- Modify only `docs/findings/copilot-pretooluse-spike.md` and this story file.
- No separate test file is required; the acceptance criteria are satisfied by
  the finding's content and section structure.
- Ambiguities to call out: Copilot docs use both `cwd` and `toolArgs` in the
  hook surface, and file-tool names vary between `read_file`/`write_file`
  examples and `view`/`edit`/`create` in the SDK source.
