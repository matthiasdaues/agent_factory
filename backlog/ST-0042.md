# Capture GitHub Copilot CLI sessions through native hooks

Deliver the first non-Claude vertical slice of the CLI-agnostic capture path.
Normalize a Copilot `events.jsonl` transcript into the canonical usage record,
install native hooks for human and supported sub-agent sessions, and prove the
installed consumer-project path is reversible and produces the same record and
transcript-copy contract as Claude Code.

**Priority:** must-have

## Acceptance Criteria

- `usage-capture --cli copilot` normalizes the full Copilot transcript into
  canonical input and output text, extracts provider usage where the transcript
  supplies it, and emits the shared record schema without Copilot-specific
  fields.
- `init-factory` merge-safely installs Factory-owned `agentStop` and
  `subagentStop` hook entries under `.github/hooks`, preserves pre-existing
  project hooks, and is idempotent.
- `remove-factory` removes only the Factory-owned Copilot hook assets and
  entries, preserves project-owned `.github` content, and leaves no
  Factory-created empty structure behind.
- An end-to-end consumer-project test runs both installed hook paths and proves
  that human and supported custom sub-agent sessions append one well-formed
  record each and persist the transcript referenced by each record.
- Capture failure is best-effort: either installed hook exits successfully and
  leaves the simulated Copilot run unaffected when normalization or persistence
  fails.
- The documented Copilot caveat is made an explicit contract: the built-in
  `general-purpose` agent does not emit `subagentStop`. Its activity MUST still
  be included in the parent `agentStop` record's normalized and reported totals.
  A synthetic executable test proves this inclusive accounting. Child
  `subagentStop` records are attribution drill-down only: future aggregation
  MUST use root records for totals and MUST NOT add child records again.

## Implementation Notes

Use Copilot's native event names and payload shape only in its adapter and hook;
the tokenizer, canonical record, logging adapter, and persistence path remain
shared. Do not add orchestrator-side capture, which would duplicate records.

## Analysis

### What will be implemented

- Add a `CopilotNormalizer` behind the existing transcript-normalizer registry.
  It will parse synthetic `events.jsonl` message and usage-summary events,
  preserve event order, split user/system/tool-result text from
  assistant/reasoning/tool-call text, and map available provider totals onto
  the existing canonical `reported_*` fields. `usage-capture --cli copilot`
  will continue through the shared tokenizer, record, and logging adapter.
  Parent transcripts are normalized inclusively: child events already present
  in a parent `events.jsonl`, including `general-purpose` activity, contribute
  to the parent's normalized and reported totals.
- Add a Copilot-specific best-effort command hook that reads GitHub's documented
  camelCase `agentStop` / `subagentStop` payload (`sessionId`,
  `transcriptPath`, and `agentName` for supported subagents), invokes the shared
  capture command, and always exits successfully.
- Install a Factory-owned version-1 JSON hook file plus its script under
  `.github/hooks/`. A dedicated file avoids rewriting project-owned hook files:
  Copilot combines all `.github/hooks/*.json` files, so existing entries remain
  intact and a repeat install is byte-stable.
- Record only Factory-owned Copilot paths in the install manifest. Removal will
  delete those paths, preserve all pre-existing `.github` content, and prune
  only directories left empty by the removal.
- Report the native limitation that Copilot's built-in `general-purpose` agent
  emits neither `subagentStart` nor `subagentStop`; automatic subagent capture
  therefore has no separate attribution record for that agent. Its spend is not
  lost because the inclusive parent record remains the source of total spend.
  Future aggregation must count root records and not add child drill-down
  records again.

### Scenarios the tests will cover

- `Capture Triggers per CLI`: invoking the public capture CLI with a synthetic
  Copilot transcript yields one canonical record, ordered persisted transcript,
  normalized input/output counts, and available reported usage without adding
  Copilot-only record fields.
- `Capture Triggers per CLI`: a fresh install exposes both native hook events;
  a second install is a no-op; unrelated project hook files survive unchanged.
- `Completion Criteria`: feeding synthetic official `agentStop` and supported
  `subagentStop` payloads through the installed command paths appends exactly
  one record per invocation and leaves each referenced transcript copy present.
- `Completion Criteria`: malformed input, missing transcripts, and persistence
  failures do not change the simulated Copilot run's successful outcome.
- `Capture Triggers per CLI`: no hook invocation is fabricated for
  `general-purpose`; a synthetic parent transcript containing its child events
  proves those events contribute to the parent's normalized and reported
  totals, while guidance explains why no separate attribution hook fires.
- `Completion Criteria`: init followed by remove restores a synthetic consumer
  project byte-for-byte, including projects with their own `.github/hooks`
  content.

### Highest-level test seams

1. The installed `.github/hooks/*.json` command entries, exercised by sending
   GitHub's documented JSON payloads to the installed hook script in a synthetic
   consumer project.
2. The standalone `factory/scripts/usage-capture --cli copilot` process,
   observed through its canonical JSONL record and persisted transcript copy.
3. The public `init-factory` / `remove-factory` entrypoints, observed through
   installed hook discovery, idempotency, preservation, and byte-identical
   round-trip removal.

### Concerns and ambiguities

- GitHub documents the hook configuration and payload contracts, including the
  `general-purpose` exception, but does not document the internal
  `events.jsonl` schema as a stable public contract. The adapter should therefore
  tolerate unknown/malformed events, and fixtures must be synthetic rather than
  copied from a private local transcript. Any supported event shapes will be
  explicit in tests and kept isolated inside `CopilotNormalizer`.
- `agentStop` fires when the main agent finishes a turn, not only when an
  interactive session exits. The acceptance criterion says one record per hook
  invocation, so repeated turns in one `sessionId` intentionally append
  sequenced records rather than being deduplicated as one session record.
