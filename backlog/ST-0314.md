# Let reverse-map run without a stakeholder and mark its scope map as a draft

**Priority:** must-have

## Goal

An orchestrator hands `reverse-map` to a subagent with a brief. The subagent
finishes without asking anyone and writes a scope map marked as a draft. The
brownfield Stage 1 exit refuses that draft until a stakeholder has confirmed
it.

## Findings

- [BUG-0096](../docs/findings/BUG-0096.md): `reverse-map` has no unattended
  mode.

## Decisions

The stakeholder decided on 2026-10-16: the draft marker is a field in the
scope map's frontmatter, for example `status: draft`. Confirming the map
removes the field or sets it to the confirmed value. The "draft pending
confirmation" convention the finding mentions does not exist in this
repository; this story defines it.

## Acceptance criteria

- `reverse-map/SKILL.md` documents an unattended mode: when it applies, that
  the domain grouping is recorded as a draft instead of asked, that
  discrepancies become open questions in the output, which extra sources it
  reads (only those the brief names), and that it writes the draft marker.
- The attended mode is unchanged.
- The brownfield Stage 1 exit names the check: a scope map with the draft
  marker does not pass.
- `spec-lint` reports a scope map with the draft marker, so the check is
  mechanical. A test shows it reports a draft map and passes a confirmed one.
- The new test fails on the code before this story and passes after it.
- The full suite passes with `pre-commit run run-tests --all-files`.
- Commits name the finding, `fix: <what changed> (BUG-0096)`.
- No file outside the list below changes. Nothing under `.agent-factory/`
  changes.
