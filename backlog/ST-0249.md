# Extend distribution scripts with component lifecycle and manifest management

Add component lifecycle operations to `init-factory`, `update-factory`, and `remove-factory` so a project maintainer can install, update, and remove the usage-analysis component without losing raw evidence.

**Priority:** should-have

## Goal

After this story ships, the maintainer runs `init-factory --with-usage` and sees `.agent-factory/usage-analysis/` installed with the self-contained module and `factory-install.json` recording `usage` under `installed_components`. Running `--update usage` with a compatible module replaces only the component and updates install metadata. Running `--update usage` with an incompatible contract version exits non-zero with a compatibility diagnostic and leaves the component unchanged. Running `--remove usage` removes the component and manifest entry but leaves `.agent-factory/usage/` unchanged. Running `update-factory` refreshes Factory core without changing installed components. Running `remove-factory` removes the entire `.agent-factory/` directory. Every lifecycle operation is idempotent.

## Domain Rule

- `--with-usage` and `--add usage` install the component at `.agent-factory/usage-analysis/` with the self-contained module and installed contract copy.
- `factory-install.json` records `usage` under `installed_components`.
- Raw evidence (`.agent-factory/usage/`) is never modified by component install, add, update, or remove. Only full Factory removal (`remove-factory`) deletes it.
- Compatible updates replace only the module and update install metadata. Incompatible updates abort before replacement.
- Component lifecycle operations are idempotent — repeating a completed operation against the resulting state succeeds as a clean no-op.
- Factory has no import dependency on Usage Analysis.

## Demo Scenario

1. Run `init-factory --with-usage` on a target project with no usage-analysis component. Verify `.agent-factory/usage-analysis/` contains the self-contained module. Verify `factory-install.json` records `usage`.
2. Verify `.agent-factory/usage/` (raw evidence) remains untouched.
3. Run `init-factory --update usage` with a compatible replacement module. Verify only the component is replaced and install metadata records the new source version.
4. Run `init-factory --update usage` with an incompatible contract version. Verify the command exits non-zero with a compatibility diagnostic and the installed component remains unchanged.
5. Run `init-factory --remove usage`. Verify the component and manifest entry are removed. Verify raw evidence remains unchanged.
6. Run `update-factory`. Verify Factory core may refresh but the installed component remains unchanged.
7. Run `remove-factory`. Verify the entire `.agent-factory/` directory including raw evidence is removed.
8. Run `init-factory --with-usage` again (idempotency). Verify it succeeds as a clean no-op when the component is already installed.

## Outputs

- `init-factory` gains `--with-usage` (initial install), `--add usage` (post-hoc add), `--update usage` (compatible update with version comparison), and `--remove usage` (component removal). Each operation is idempotent.
- `init-factory --update usage` reads the contract version from the installed component and the replacement source, compares major versions, and aborts before replacement when incompatible.
- `init-factory` manages `factory-install.json` — adds `usage` to `installed_components` on install/add, removes it on `--remove usage`.
- `update-factory` skips installed components during core refresh.
- `remove-factory` removes the entire `.agent-factory/` directory including components and raw evidence.
- Integration tests verify install, update (compatible and incompatible), remove, core update, full removal, and idempotency.

## Constraints

- Raw evidence (`.agent-factory/usage/`) must survive every lifecycle operation except full Factory removal.
- Do not add DuckDB or PyArrow imports to the distribution scripts.
- Distribution scripts remain stdlib-only Python.
- Do not modify the existing capture pipeline or any Factory core behavior beyond component awareness.
- Compatibility checking compares contract major versions only.
