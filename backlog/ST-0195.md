# Update agent-context fields and manage source pointers with update-context

Rename `factory/skills/update-charter/SKILL.md` to `factory/skills/update-context/SKILL.md` and implement mode-aware field writing. In primary mode, the skill writes inline values directly. In index mode, it writes both `name` and `source` together and refuses writes without a source pointer. The skill records deferred decisions as `deferred: "reason"` at the field's leaf position. When the first `source:` pointer is written and no `reading-guides.yaml` exists, the skill proposes creating one from the template.

**Priority:** must-have

## Demo

Operator has three index files in `mode: primary` with some null fields (status quo from EPIC 2 greenfield init). Operator invokes `update-context` to record a technology choice for `stack.yaml#frameworks.backend` -- update-context writes the inline value `FastAPI 0.100` directly. Operator adds a source pointer for the same field -- update-context writes both `name: FastAPI` and `source: docs/adr/004-use-fastapi.md`. Since this is the first source pointer and no `reading-guides.yaml` exists, update-context proposes creating the reading guide from the template. Operator defers the `data_stores` decision with reason "evaluating options" -- update-context writes `deferred: "evaluating options"` to the field, replacing any prior value. Operator runs `context-lint` and the files pass validation.

## Acceptance Criteria

- update-context writes inline values directly to index-file fields when `mode: primary` (agent-context.feature Rule: Operator updates agent context as decisions emerge, Scenario: update-context writes inline values when mode is primary).
- update-context writes both `name` and `source` together when `mode: index` (agent-context.feature Rule: Operator updates agent context as decisions emerge, Scenario: update-context writes name and source together when mode is index).
- update-context rejects writes without a source pointer when `mode: index` (agent-context.feature Rule: Operator updates agent context as decisions emerge, Scenario: update-context refuses hand-edit when mode is index).
- update-context proposes creating `reading-guides.yaml` from the template when the first `source:` pointer is written and no reading guide exists (agent-context.feature Rule: Operator updates agent context as decisions emerge, Scenario: update-context proposes reading-guide creation on first source pointer).
- update-context records `deferred: "reason"` as the sole key at the field's leaf position, with no coexistence of `name` or `source` (agent-context.feature Rule: Operator updates agent context as decisions emerge, Scenario: update-context writes deferred field).
- context-lint passes on files modified by update-context.
- The update-context skill resolves through INDEX.yaml by its new name.

## Scope

**Status quo:** `factory/skills/update-charter/SKILL.md` exists as the legacy skill for updating markdown charter files. YAML templates, context-lint, and the capture-context skill exist (from ST-0190, ST-0193). No skill handles mode-aware YAML field writing.

**Adds:** Renamed `factory/skills/update-context/SKILL.md` with mode-aware write logic. Primary-mode inline value writing. Index-mode name-and-source pair writing with source-pointer enforcement. Deferred-field handling. Reading-guide creation trigger. Updated INDEX.yaml entry (via `index-lint`).

**Out of scope:** Mode-transition logic (ST-0196). capture-context skill (EPIC 2). Consumer path updates (EPIC 4).

## Notes for the Implementer

The update-context skill is a markdown skill definition executed by an LLM agent, not a standalone script. The mode-aware logic describes the decision tree the agent follows when modifying a field: check the current mode, apply the appropriate write pattern, run context-lint to validate. The deferred-field handling must replace any existing value at the field position with a single `deferred:` key -- no `name` or `source` may coexist. Run `index-lint` after the rename to update INDEX.yaml.
