# Surface fitting progress when fitting is partially complete

Add handling for `fitting.status == "fitting"` in AGENTS.md's session-start flow so that a returning user or new collaborator sees which fitting steps are done and which remain.

**Priority:** should-have

## Demo

A user opens a session in a project where `project-context.json` shows `fitting.status: "fitting"` with `model_matrix_configured: false` and the other 4 keys `true` (status quo from ST-0210's derivation). Instead of seeing "Want to walk through the fitting?" with no context, the session-start flow presents: "Fitting is 4/5 done (project fingerprint, agent context, test regime, pre-commit hooks). Model matrix remains. Continue the fitting, or skip to the menu?" The user chooses to continue. VIRGIL resumes at step 0 (model matrix).

## Acceptance Criteria

- AGENTS.md's session-start check handles `fitting.status == "fitting"` as a third state alongside `"unfitted"` and the implicit `"fitted"` / other pass-through (design item 8)
- When status is `"fitting"`, AGENTS.md instructs the model to read fitting keys from `project-context.json`, count completed vs. remaining, and present a progress summary with step names before offering to continue or skip (design item 8)
- Step names map to fitting keys per the proposal's mapping table: `model_matrix_configured` -> "Model matrix", `fingerprint_confirmed` -> "Project fingerprint", `agent_context_populated` -> "Agent context", `test_regime_detected` -> "Test regime", `hooks_decided` -> "Pre-commit hooks" (design item 8)
- VIRGIL's fitting procedure includes guidance to resume from the first incomplete step when the user chooses to continue from a `"fitting"` state (design item 8)

## Scope

**Status quo:** AGENTS.md's session-start check handles only `fitting.status == "unfitted"` (offers the fitting or the menu). Any other value, including `"fitting"`, falls through to step 2 (present the session menu). VIRGIL's fitting procedure already supports resumption ("check which keys are still false and resume from the first incomplete step") but the session-start routing never reaches it for the `"fitting"` state. ST-0210 has shipped, so `project-context.json` now correctly contains `fitting.status: "fitting"` when artifacts indicate partial completion.

**Adds:**

- A third routing case in AGENTS.md step 1: when `fitting.status` is `"fitting"`, read the 5 fitting keys, map them to human-readable step names, count completed vs. remaining, and present the progress summary with an offer to continue or skip to the menu
- Guidance in virgil.md's fitting section for the session-start-to-fitting handoff when status is `"fitting"`

**Out of scope:** Changes to init-factory (handled by ST-0210). Changes to the session menu. Playbook-level breadcrumbs.

## Notes for the Implementer

AGENTS.md is a short markdown file (33 lines). The change adds a conditional block in the "Check fitting state" section. The current text:

> If the file is missing or `fitting.status` is anything other than `"unfitted"` -> continue to step 2.

This needs to become two cases: `"fitting"` (show progress, offer to continue) and everything else (continue to step 2).

The step-name mapping table is specified in the proposal's design item 8 and should be written into the AGENTS.md instructions so any CLI can render the progress summary without needing to read virgil.md.
