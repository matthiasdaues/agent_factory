# Deterministic two-pass commit helper

This repo's pre-commit hooks rewrite staged files (mdformat, ruff, index-lint, arch-lint), aborting the commit with "files were modified by this hook" and forcing a manual re-add + retry on nearly every commit (retro 2026-07-21). `factory/scripts/commit-safe` wraps the deterministic two-pass sequence into one command.

**Priority:** must-have

## Acceptance Criteria

- `commit-safe -m "<msg>" [<path>...]` stages the given paths (if any), commits, and — if a hook rewrote a staged file — re-stages (`git add -u`) and commits once more, without a third pass.
- It never bypasses a hook (no `--no-verify`); a genuine hook failure still surfaces as a non-zero exit.
- A missing `-m` message exits non-zero with a clear error.
- Referenced from the [git-workflow convention](../factory/rulebooks/conventions/git-workflow.md).
- A test drives it against a temp repo whose pre-commit hook rewrites a staged file on first run, proving the two-pass lands the commit in exactly one commit.
