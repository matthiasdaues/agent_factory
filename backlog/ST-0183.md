# Add gates and risk_classes configuration to testing.yaml

Add a `gates` section and an optional `risk_classes` section to `docs/charter/testing.yaml` and the charter template at `factory/rulebooks/templates/charter-testing.yaml`. The `gates` section centralizes gate configuration (enabled flags, thresholds) that the dispatcher reads at runtime. The `risk_classes` section allows per-project overrides of Factory convention risk-class defaults.

**Priority:** must-have

## Demo

Open `docs/charter/testing.yaml`. A `gates:` section declares `crap_score` (enabled: true, threshold: 8) and `mutation_testing` (enabled: false). An optional `risk_classes:` section shows how to override the default risk-class settings. Open `factory/rulebooks/templates/charter-testing.yaml` and see the same sections with a concrete YAML example including the `financial` custom risk class with `format`, `budget`, and `requires` fields.

## Acceptance Criteria

- `docs/charter/testing.yaml` contains a `gates` section with `crap_score` (enabled: true, threshold: 8) and `mutation_testing` (enabled: false) (test-design.feature Rule 12, Scenarios 1-2).
- `factory/rulebooks/templates/charter-testing.yaml` includes a `gates` section with `crap_score` and `mutation_testing` entries, each documenting enabled flag and threshold parameters (test-design.feature Rule 12, Scenario 3).
- `factory/rulebooks/templates/charter-testing.yaml` includes a `risk_classes` section with a concrete YAML example showing `format`, `budget`, and optional `requires` fields (test-design.feature Rule 11, Scenario 3).
- The `risk_classes` example demonstrates at least one custom risk class (e.g. `financial`) to show the extension mechanism (test-design.feature Rule 11, Scenario 2).
- The `gates` section does not define gate execution ordering; a comment references ADR-0012 as the authority for gate sequence.

## Scope

**Status quo:** `docs/charter/testing.yaml` declares `test_command`, `test_staged_command`, and `layers.contract_test`. No `gates` or `risk_classes` sections exist. The charter template mirrors this structure.

**Adds:** `gates` section with two entries to both files. `risk_classes` section with schema-by-example to the template and an empty/commented placeholder to the project's testing.yaml. Comments referencing ADR-0012 for gate execution ordering.

**Out of scope:** The CRAP threshold migration in the crap-score script (ST-0184). Dispatcher reading the gates section (ST-0189).

## Notes for the Implementer

The `test_design_verify` gate entry is intentionally absent from the `gates` section -- it is implicitly enabled when test-design output exists in a story and skipped otherwise. Document this with a YAML comment. The schema for `risk_classes` is defined by example in the proposal's Design Details section. Keep the project's `testing.yaml` minimal (just `gates`); the template should carry the full schema-by-example including the `financial` custom class.
