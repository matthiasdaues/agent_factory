# Find the content of the three old files at its new home after they are deleted

A user or contributor who follows any link to the old guide, `concepts.md`, or `beginner-intro.md` lands on the handbook page that now holds the linked section.

**Priority:** must-have

## Goal

Every link to `packages/factory/docs/factory-guide.md`, `docs/arc42/concepts.md`, or `docs/arc42/beginner-intro.md` points to the page that holds its section, and the three files are gone from the source and from an installed copy. The phase chain and the key ideas of `concepts.md` sit on a `concept` page of the user handbook, and its corrected directory tree sits on a `reference` page of the contributor handbook. `link-check` over every live document exits 0.

## Contract

The rewrite applies BR-151 to every Markdown link and reference definition of every tracked Markdown file outside `.agent-factory/` (BR-150).

| Link in a tracked Markdown file                                                                         | New destination                                                                     | Effect on the file                               |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------ |
| To one of the three files, with an anchor whose section the map assigns to a page that has that heading | That page, with the anchor                                                          | Only the destination changes                     |
| Same, and the page lacks the heading                                                                    | That page, without the anchor                                                       | Only the destination changes                     |
| To `factory-guide.md`, without an anchor                                                                | The user handbook's top-level `index.md`                                            | Only the destination changes                     |
| To `concepts.md`, without an anchor                                                                     | The `concept` page of the user handbook's `concepts/` chapter                       | Only the destination changes                     |
| To `beginner-intro.md`, without an anchor                                                               | The `tutorial` page of the user handbook's `getting-started/` chapter               | Only the destination changes                     |
| To the installed guide under `.agent-factory/factory/docs/`                                             | The same page under `.agent-factory/factory/docs/handbook/`, the prefix kept (L-11) | Only the destination changes                     |
| Inside a code span or a fenced code block                                                               | Unchanged                                                                           | No change (L-26)                                 |
| A reference-style definition                                                                            | Rewritten like an inline link (L-26)                                                | Only the destination changes                     |
| In a file of a record folder                                                                            | As in the rows above                                                                | The diff changes only link destinations (DEC-14) |

`rewrite_links` in `_link_rewrite.py` maps one old path to one new path and keeps the anchor, so it cannot send two anchors of one file to two pages (PROP-08). The story adds a section map to the module: for an old path, it maps each section anchor to a page, and it gives the page for a link without an anchor. The existing behaviour of `rewrite_links` for `move-docs` stays as it is. The developer runs the rewrite once over the repository; the story adds no new command and no new option to `move-docs`.

## Demo Scenario

1. The contributor opens `docs/README.md` and follows the link to the phase chain. It opens the `concept` page in `packages/factory/docs/handbook/concepts/` at the heading "The phase chain".
2. The contributor opens `docs/adr/0003-test-execution-via-hooks.md` and follows its former link to the guide. It opens the user handbook page that the migration map names for that section.
3. The contributor runs `packages/factory/scripts/link-check` over every live document. It exits 0.
4. The contributor runs `rg factory-guide packages/ tests/ README.md docs/spec/features/ --glob '!CHANGELOG.md' --glob '!docs/spec/features/factory-handbooks.feature'`. It prints nothing.
5. A user runs `update-factory` in a project with the previous release. `.agent-factory/factory/docs/factory-guide.md` does not exist, and `.agent-factory/factory/docs/handbook/index.md` lists the twelve chapters.
6. The user opens `packages/factory/CHANGELOG.md` in the release and finds the entry that names the move to `.agent-factory/factory/docs/handbook/`.

## Analysis

- **Section map.** `_link_rewrite.py` gets `read_section_map`, which reads the rows of the migration map for the three old files, and `rewrite_section_links`, which repoints each inline link and reference definition by that map. The first row of a file is its opening, so it gives the page of a link without an anchor. `rewrite_links` stays as it is.
- **Links found.** A scan with the link parser of `_link_rewrite.py` finds links to the three files in 16 tracked files besides the three files themselves. The other files in `touches` match only names such as `08_crosscutting_concepts.md` or name the files in a code span, so they stay unchanged.
- **Installed links.** Ten links point to `.agent-factory/factory/docs/factory-guide.md`. The run lead decided L-62: a file of this repository outside `packages/factory/` links to the source page under `packages/factory/docs/handbook/`. `rewrite_section_links` takes `installed_links=False` for those files. A file inside `packages/factory/` ships, so it keeps the installed prefix.
- **Pages.** A new `concept` page `concepts/how-the-factory-works.md` holds "The phase chain" and "Key ideas". A new `reference` page `docs/handbook/architecture/repository-layout.md` holds the corrected tree. The install inventory joins `reference/local-configuration.md`, and the test execution reference joins `quality-and-review/gate-scripts.md`; neither needs a new page.
- **Tests.** `test_handbook_link_rewrite.py` holds the contract tests. `test_handbook_links.py` holds FH-05-IT-02. FH-05-IT-01 and FH-05-LN-01 join `test_handbook_content.py`. FH-04-IT-01 joins `test_update_factory.py`.
- **Decisions.** The record `docs/reviews/reconciliation-2026-11-03.md` also changes in table padding, because `mdformat` pads a table to its widest cell; FH-05-IT-02 compares records without padding. Links without an anchor follow BR-151 to the opening page; where a live text names the guide, the link text changes and a second link names the page of the topic.
- **Stop, resolved.** CAL-14 and the commit hooks failed on the ten installed links, because the main checkout's installed copy has no handbook. L-62 resolves the stop.
- **Demo step 2.** `docs/adr/0003-test-execution-via-hooks.md` never linked to the guide; its links go to `08_crosscutting_concepts.md`. ADR-0002 and ADR-0006 hold the guide links.
