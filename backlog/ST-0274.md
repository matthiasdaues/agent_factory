# Add scope declarations to existing governed artifacts and wire scope filtering

Every governed artifact in the repository carries a valid scope declaration, and the precondition evaluator uses these declarations to filter candidates by workstream.

**Priority:** should-have

## Goal

After this story ships, every existing governed artifact carries a scope declaration in the format required by its type. Proposals carry `scope` in YAML frontmatter (replacing the `title` field; the display name moves to the document heading). Feature files carry `# scope: <value>` as their first line. The Structurizr DSL carries `// scope: global` as its first line. The entity model carries a top-level `scope` field. The scope map carries `scope: global` in its frontmatter. `scope-lint` passes across the full repository. The evaluator's scope filtering step reads these declarations to narrow candidates by workstream.

## Domain Rule

- Every governed artifact must carry a scope declaration before this story is done
- Proposals: move `title` from frontmatter to the document heading; replace with `scope` set to the workstream identifier matching the proposal filename
- Epics: add `scope` to YAML frontmatter set to the workstream identifier
- Stories: add `scope` to YAML frontmatter set to the workstream identifier
- Feature files: add `# scope: <value>` as the first line before the `Feature:` keyword
- Structurizr DSL: add `// scope: global` as the first line before the `workspace` keyword
- Entity model: add `scope: global` as a top-level YAML field (or Markdown frontmatter field if the file is `.md`)
- Scope map: add `scope: global` to YAML frontmatter
- The evaluator's scope filtering step reads the scope declaration from each candidate and keeps only candidates whose scope matches the bound workstream or equals `global`
- In Open Stage (no workstream bound), scope filtering is skipped and all candidates pass

## Demo Scenario

1. Open `docs/proposals/activity-graph-orchestration.md`. The frontmatter contains `scope: activity-graph-orchestration` and no `title` field. The document heading `# Activity-Graph Orchestration` carries the display name.
2. Open `docs/spec/activity-graph-orchestration.feature`. The first line reads `# scope: activity-graph-orchestration`. The `Feature:` keyword is on line 2.
3. Open `docs/arc42/architecture.dsl`. The first line reads `// scope: global`.
4. Open `docs/spec/scope-map.md`. The frontmatter contains `scope: global`.
5. Run `scope-lint`. All governed artifacts pass. No errors.
6. Bind to workstream `activity-graph-orchestration`. Run the precondition evaluator. The evaluator filters candidates: only proposals with `scope: activity-graph-orchestration` or `scope: global` survive. Proposals scoped to other workstreams are filtered out.
7. Enter Open Stage (no workstream). Run the evaluator. All candidates pass scope filtering regardless of their scope value.
