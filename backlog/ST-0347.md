# Find each core artifact without exactly one reviewed producer

**Priority:** must-have

## Goal

The factory maintainer runs the contract test and sees each core list entry pass, or fail with the agents whose patterns match it. Today's gaps stay visible in the expected-failure list, so the suite passes while the later EPICs remove them.

## Contract

| Operation     | Input state                                                            | Outcome                                                               | Persistence |
| ------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------- | ----------- |
| Contract test | Entry matched by one declaration with a non-empty `reviewed_by:`       | Entry passes                                                          | None        |
| Contract test | Entry matched by no declaration                                        | Entry fails and names the sample path                                 | None        |
| Contract test | Entry matched by two declarations, a wide pattern included             | Entry fails and names both agents                                     | None        |
| Contract test | Matching declaration without `reviewed_by:`, or with `reviewed_by: []` | Entry fails, also when another agent reads the artifact               | None        |
| Contract test | A matching declaration with `edits: wording`                           | That declaration is not counted                                       | None        |
| Contract test | Several agents declare `docs/spec/work/term-candidates.md`             | No finding; working output is not on the core list                    | None        |
| Contract test | Real catalog: every entry fails as listed, every unlisted entry passes | Test passes                                                           | None        |
| Contract test | Real catalog: a listed entry passes                                    | Test fails and names the entry as an expected failure that now passes | None        |

## Demo Scenario

Demo exception: the stakeholder accepted the contract test as this demo's interface (2026-11-04). The demo runs it through the `run-tests` hook or `validate`, never through `pytest` directly (BR-024).

1. The maintainer runs `pre-commit run run-tests --all-files`. It passes. The expected-failure list in the contract test names twelve entries, `docs/spec/entity-model.md` among them. `docs/spec/architecture.dsl` is not on the list.
2. The maintainer adds a fixture agent `demo-rules` that declares `docs/spec/dependency-rules.dsl` with `reviewed_by: [architecture-review-agent]` and regenerates the catalog. The hook fails and names `docs/spec/dependency-rules.dsl` as an expected failure that now passes.
3. The maintainer removes `demo-rules` and regenerates. The hook passes.

## Analysis

- **What:** a new contract test module, `tests/factory/test_core_artifact_ownership.py`. It counts the producers of each core list entry and checks the producer's `reviewed_by:`. Only output declarations count as producers; a declaration with `edits: wording` does not.
- **Matching:** the test reuses `pattern_matches` from `index-lint` (ST-0346). It replaces `{name}` with `*` and calls `dispatch_lib.glob_match`. That `**` rule agrees with [validation-rules.md § Glob matching](../docs/spec/validation-rules.md#glob-matching-outputs-ownership). The story's second stop condition does not apply.
- **Counting:** each matching declaration counts once. Two declarations from one agent also fail the entry, as BR-056 counts matches.
- **Real catalog:** the test runs once per core list entry and reads only `packages/factory/rulebooks/core-artifacts.yaml` and `packages/factory/INDEX.yaml`. A listed entry must fail. An unlisted entry must pass. A listed entry that is missing from the core list also fails the test. The preview run gave the twelve entries of the Demo Data table, and only `docs/spec/architecture.dsl` passes. The first stop condition does not apply.
- **Scenarios covered:** the six Scenarios of the Rule "Factory maintainer finds exactly one producer for every core and seam artifact" on fixture catalogs, "The single-producer rule does not count working output", and "A reader is never counted as a review". The Scenario Outline with the thirteen producers stays red for twelve entries, held in the expected-failure list.
- **Files:** only `tests/factory/test_core_artifact_ownership.py` is new. No script and no agent definition changes.
