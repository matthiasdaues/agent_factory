# Control whether context capture scans the project

**Priority:** should-have

## Goal

When the newcomer selects an action that needs project context, onboarding explains the scan, its confirmation decisions, the `docs/agent-context.md` output, `concern-lint` validation, and how humans and agents use the file before starting. Onboarding defines a concern (a routing topic that directs agents to project-specific knowledge) before using the term without a paraphrase. Deferral or cancellation before scanning produces no scan and no output file.

## Contract

| Operation                             | Input state                       | Outcome                                                                                                                                                                                                 | Persistence                                         |
| ------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Select action needing project context | No `docs/agent-context.md` exists | Explanation appears: what the scan reads, what decisions it asks, where output goes, how `concern-lint` validates, how humans and agents use the file; "concern" defined before first unparaphrased use | No file changes                                     |
| Accept scan after explanation         | Explanation displayed             | `capture-context` skill runs                                                                                                                                                                            | `docs/agent-context.md` created                     |
| Defer scan after explanation          | Explanation displayed             | No scan runs                                                                                                                                                                                            | No `docs/agent-context.md` created; no file changes |
| Cancel scan after explanation         | Explanation displayed             | No scan runs                                                                                                                                                                                            | No `docs/agent-context.md` created; no file changes |
| Blank input after explanation         | Explanation displayed             | No scan runs                                                                                                                                                                                            | No `docs/agent-context.md` created; no file changes |

## Boundaries

- The explanation is a structural change to the skill flow, not a new skill. The existing `capture-context` scan logic is unchanged.
- Deferral and cancellation leave the project in its prior state. No partial output files, no partial scans.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Demo Scenario

1. Open a Factory session. The session reports project insight (ST-0287). Select an action that needs project context.
2. Onboarding explains the context capture scan: what it reads, what decisions it asks, where the output goes (`docs/agent-context.md`), how `concern-lint` validates the output, and how humans and agents use the file.
3. Onboarding defines a concern as "a routing topic that directs agents to project-specific knowledge" before using the term without a paraphrase.
4. Defer the scan. Verify no scan ran, no `docs/agent-context.md` was created, and no files changed.
5. Select the same action again. Read the explanation. Accept the scan.
6. The `capture-context` skill runs and produces `docs/agent-context.md`.
