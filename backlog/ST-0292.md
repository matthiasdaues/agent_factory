# Complete a first task in a repository without commits

**Priority:** could-have

## Goal

When a repository has no HEAD, the sandbox management module creates a plain directory at `.current-work/onboarding-spike/<uuid4>/` instead of a detached worktree. The poc-spike playbook runs inside the plain sandbox, and the same three outcome paths (discard, retain, production handoff) apply.

## Contract

| Operation                              | Input state                                             | Outcome                                                  | Persistence                                                |
| -------------------------------------- | ------------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------- |
| Approve first-task preview             | Repository without HEAD (`git init` only), install done | Plain directory created; no `git worktree add` attempted | `.current-work/onboarding-spike/<uuid4>/` exists           |
| poc-spike playbook runs in sandbox     | Plain sandbox exists                                    | Inspectable result displayed                             | Result files inside sandbox path                           |
| Newcomer chooses discard               | Plain sandbox with completed task                       | Directory removed; path verified absent                  | `.current-work/onboarding-spike/<uuid4>/` no longer exists |
| Newcomer chooses retain with selection | Plain sandbox with completed task, artifacts selected   | Only confirmed artifacts copied; sandbox not promoted    | Selected artifacts at `docs/spikes/<name>/`                |
| Newcomer chooses production handoff    | Plain sandbox with completed task                       | Normal workstream created; sandbox not promoted          | Workstream active; sandbox does not become production work |

## Required Script Behavior

### HEAD detection

The sandbox module checks for HEAD with `git rev-parse HEAD`. When HEAD is absent (exit code 128 in a bare `git init` repository), the module creates a plain directory instead of a detached worktree.

### Plain-directory creation

The module creates `.current-work/onboarding-spike/<uuid4>/` as a regular directory using `os.makedirs`. The session-id is a UUID4 string from `uuid.uuid4()`, matching the format from ST-0291. No `git worktree add` is attempted.

### Task execution

The poc-spike playbook runs inside the plain sandbox directory. Behavior is identical to the worktree sandbox in ST-0291.

### Outcome selection

The three outcome paths (discard, retain, production handoff) reuse ST-0291's outcome logic. Discard removes the directory with `shutil.rmtree` instead of `git worktree remove`. Retain and production handoff behave identically to the worktree case.

## Boundaries

- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.
- Outcome selection logic from ST-0291 is reused, not duplicated.
- The plain sandbox must not attempt `git worktree add` when HEAD is absent.
- The task runs only inside the sandbox directory.

## Demo Scenario

1. Initialize a new Git repository with `git init` (no commits).
2. Install Factory (ST-0281) and complete first-session insight (ST-0287).
3. The session recommends a first task. Approve the preview.
4. A plain sandbox appears at `.current-work/onboarding-spike/<uuid4>/`. No `git worktree add` was attempted.
5. The poc-spike playbook runs inside the sandbox. An inspectable file appears.
6. Choose retain. Select one artifact. The artifact appears in `docs/spikes/<name>/`.
7. The sandbox is not promoted.

## Stop Conditions

- `git rev-parse HEAD` returns unexpected results in an empty repository (e.g., shallow clones or orphan branches) — report the Git version and the observed behavior.
- The plain sandbox path conflicts with other `.current-work/` consumers — report the conflict.
- Code in `packages/factory/` and the feature spec disagree on how sandbox creation detects the absence of HEAD — report the conflicting files and the decision needed; do not add a workaround.
