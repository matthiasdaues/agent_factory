# dispatch init: feature branch, ledger, and .current_work directory layout

Implement `dispatch init --base <branch> --stories ST-NNNN,...` and its
variants. The subcommand creates the feature branch from `--base`, initializes
the dispatch ledger at `.current_work/<feature-branch>/dispatch-ledger.yaml`,
and records all named stories as pending. Preflights `test_command` from
`config/project.json`. Supports `--baseline-commit` (commits untracked state
before branching) and `--feature-branch` (adopts an existing branch). Update
`init-factory` to add `.current_work/` to `.gitignore`.

**As a** dispatch operator,
**I want** dispatch init to create the feature branch and ledger atomically,
**so that** I have a clean starting state for the dispatch with no manual git
setup.

**Priority:** must-have

## Acceptance Criteria

01. `dispatch init` creates a feature branch from the base branch tip, a
    worktree for the feature branch, and a dispatch ledger with all named stories
    recorded as pending.
02. `dispatch init` exits non-zero when `config/project.json` lacks a
    `test_command` key.
03. `dispatch init` exits non-zero on untracked files in target directories
    unless `--baseline-commit` is given.
04. `--baseline-commit` creates a baseline commit on the base branch before
    cutting the feature branch.
05. `--feature-branch <name>` adopts an existing branch without creating a new
    one. The branch must exist and its tip must be reachable from `--base`.
06. `--feature-branch` with a non-existent or unreachable branch exits non-zero.
07. `--baseline-commit` and `--feature-branch` are mutually exclusive; using
    both exits non-zero with a diagnostic.
08. The ledger is written to `.current_work/<feature-branch>/dispatch-ledger.yaml`.
09. `init-factory` adds `.current_work/` to `.gitignore`.
10. Every subcommand invocation is idempotent: re-running after success is a
    no-op.
