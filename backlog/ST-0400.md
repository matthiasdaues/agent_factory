# Refuse a Claude Code agent's call that sets a human field

**Priority:** must-have

## Goal

An agent in Claude Code is refused with exit `2` when its `Edit`, `MultiEdit`, `Write`, `NotebookEdit`, or `Bash` call sets a human field in a finding file, a register file, or the Appendix table of a proposal. Its legitimate calls pass. `init-factory` registers the guard, and `update-factory` adds it to a project installed earlier.

## Contract

| Call                                                                                                                | Result   |
| ------------------------------------------------------------------------------------------------------------------- | -------- |
| `Edit` of `docs/findings/BUG-0037.md` whose `new_string` sets `stop_confirmed_by: human` over `null`                | exit `2` |
| `Bash` `sed -i 's/status: open/status: waived/' docs/findings/FAGAN-0042.md`                                        | exit `2` |
| `Bash` `sed -i` that writes `waived` into the Status cell of an Appendix row of `docs/proposals/review-loop-cap.md` | exit `2` |
| `Write` of an existing finding file whose new content sets `stop_confirmed_by: human`                               | exit `2` |
| `Edit` of `docs/findings/register/code/FAGAN-0032.json` that adds `override_by` or sets `"status": "waived"`        | exit `2` |
| `MultiEdit` of `docs/findings/BUG-0037.md` with one edit that sets `override_reason`                                | exit `2` |
| `Write` of a new finding from the template, all human fields `null`                                                 | exit `0` |
| `Edit` that fixes a typo in a waived finding and leaves its `status: waived` line unchanged                         | exit `0` |
| `Edit` of `packages/factory/rulebooks/templates/finding.md`                                                         | exit `0` |
| `Bash` `grep "status: waived" docs/findings/*.md`                                                                   | exit `0` |
| `Bash` heredoc that writes a test fixture under `tests/`                                                            | exit `0` |

"Sets" means a value appears that was not there before: `Edit` compares `old_string` with `new_string`, `Write` compares with the current file, and `Bash` is checked only when it writes into a guarded path.

## Demo Scenario

1. The User installs the Factory from this branch into `/tmp/guard-demo` with `init-factory --cli claude`. `.claude/settings.json` holds `guard-human-fields` entries for `Edit`, `MultiEdit`, `Write`, `NotebookEdit`, and `Bash`, beside the `step-guard` entries.
2. The User copies `docs/findings/BUG-0037.md` from ST-0397's Demo Data into the project, starts Claude Code, and asks the agent to write `stop_confirmed_by: human` into it. The hook refuses the edit and names the field.
3. The User asks the agent to run `grep "status: waived" docs/findings/*.md`. It runs.
4. The User writes the field in an editor. Nothing refuses it.

## Boundaries

- The guard checks only `docs/findings/*.md`, `docs/findings/register/**/*.json`, and the Appendix tables of `docs/proposals/*.md` (DEC-45, DEC-56, DEC-60). Templates, the rulebook, and test fixtures lie outside.
- The guard checks the text of each call, as `block-dangerous-git.sh` does. A hidden field name is deferred (DEC-42); the story names that limit in the hook's help text.
- The guard reads stdin and the current target file, and writes nothing. It exits `2` with a message on standard error that names the field and says only the stakeholder writes it.
- `init-factory` writes the entries beside `step-guard`, never in place of it. `remove-factory` removes them.
- The tool-call fixtures follow the formats of the guard contract. The story names a manual check in a real Claude Code session in its review report (FC-QG23).

## Analysis

**What gets built.** One Python hook script, `packages/factory/config/hooks/guard-human-fields`. It reads a Claude Code `PreToolUse` payload on standard input. It exits `2` when the call sets a human field in a guarded path, and `0` otherwise. Only the Claude Code format is parsed; ST-0401 to ST-0403 add the other formats.

**How the guard decides.**

- A path is guarded when, relative to the git top level of the file, it is `docs/findings/<name>.md`, `docs/findings/register/**/<name>.json`, or `docs/proposals/<name>.md`. A fixture under `tests/fixtures/<name>/docs/findings/` lies outside.
- A human value is a non-null `override_by`, `override_reason`, `stop_confirmed_by`, or `stop_confirmed_reason`, or the status `waived`. A finding file is read as YAML lines, a register file as JSON keys, and a proposal by the Status cell of each table under `# Appendix`.
- `Edit` and `MultiEdit` apply each edit to the current file and compare the values before and after. When the file is missing or an `old_string` is not in it, the guard compares `old_string` with `new_string`, as BR-092 says. `Write` and `NotebookEdit` compare the new content with the current file.
- `Bash` is checked only when it writes into a guarded path: a redirect, `tee`, `sed -i`, `perl -i`, or an interpreter such as `python3` that names the path. Then any human value in the command text refuses it. For a proposal, the word `waived` refuses it, because a command text does not show which cell it writes.

**Registration.** `init-factory` links `.claude/hooks/guard-human-fields` and writes five `PreToolUse` entries (`Edit`, `MultiEdit`, `Write`, `NotebookEdit`, `Bash`) beside the `step-guard` entries. `update-factory` reruns `init-factory`, so an earlier install gets the entries. `remove-factory` strips them.

**Files.** New: the hook script, `tests/factory/test_guard_human_fields.py`. Changed: `init-factory`, `remove-factory`, `tests/factory/test_init_factory.py`, `tests/factory/test_update_factory.py`.

**Scenarios covered.** All Scenarios of the Rule "Agent is refused when it sets a field that only the stakeholder writes" that name Claude Code: the four refusals, the proposal row, the headless confirmation, the five legitimate calls, and the Claude Code row of the installer Outline (FC-18-IT-01 to FC-18-IT-06, FC-18-IT-11, FC-18-IT-12, FC-18-IT-14).

**Notes.**

- `NotebookEdit` carries `notebook_path`, so the guard can read its target. No stop condition holds.
- The `sed -i 's/status: open/status: resolved/'` step of `bug-fix.md` sets no human value, so the guard lets it through.
- The Copilot CLI registration file under `config/hooks/` belongs to ST-0401, because this story covers Claude Code only.
