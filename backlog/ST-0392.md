# Refuse a lowering or removal of a filed finding

**Priority:** must-have

## Goal

The user sees `finding-lint` exit `1` when a change lowers a filed finding, removes it, drops its `review_class`, or removes a register file without a finding file of the same ID. The stakeholder's lowering with the override fields, and a raise of a register file into a finding file, pass.

## Contract

| Change against `HEAD`                                                                         | Result                           |
| --------------------------------------------------------------------------------------------- | -------------------------------- |
| Finding file with `review_class` at `HEAD` gets a lower severity, no override fields          | exit `1`, file and lowering rule |
| Same lowering with `override_by` and `override_reason`, and a register file of the same ID    | exit `0`                         |
| Finding file raised to a higher severity                                                      | exit `0`                         |
| Finding file removed, no register file of the same ID with the override fields                | exit `1`, names the ID           |
| Finding file loses `review_class`                                                             | exit `1`                         |
| Register file at `HEAD` removed, no finding file of the same ID                               | exit `1`, names the ID           |
| Register file `FAGAN-0032` removed and `docs/findings/FAGAN-0032.md` added at `major`, `open` | exit `0`                         |
| `--staged`                                                                                    | compares the staged version      |
| no flag                                                                                       | compares the working tree        |

## Demo Scenario

1. The User creates `/tmp/lower-demo` with `git init`, commits `docs/findings/FAGAN-0042.md` at `major` and `docs/findings/register/code/FAGAN-0032.json`.
2. The User changes FAGAN-0042 to `minor` in the working tree and runs `finding-lint`. It exits `1` and names the lowering rule.
3. The User stages the change and runs `finding-lint --staged`. It exits `1` too.
4. The User restores FAGAN-0042, removes `FAGAN-0032.json`, and adds `docs/findings/FAGAN-0032.md` at `major` and `open`. `finding-lint` exits `0`.

## Boundaries

- The lint reads `HEAD` with `git show HEAD:<path>` and writes nothing.
- A file without `review_class` at `HEAD` and in the checked version is skipped, as BR-109 states.
- A git call that fails exits `2`.
- Tests build their repositories in `tmp_path` with the git config of the QA strategy's test setup.
