# Create factory/CONTEXT.md

`factory/` (agents, skills, playbooks, gates — the system dynamically run
by an AI CLI) is a real bounded context with its own vocabulary, but has
no domain glossary yet. The convention that every context/subproject gets
its own `CONTEXT.md` is itself a whole-repo, cross-cutting policy — that's
why this story is filed at root even though the artifact it produces
(`factory/CONTEXT.md`) lives inside `factory/`. `docs/CONTEXT-MAP.md`
(ST-0002) already carries a stub row for `factory/` reading "planned, no
docs yet"; this story is what fulfills that stub. Depends on ST-0002
existing first (same root `backlog/` namespace, so a formal `deps:` entry
is fine here — unlike a cross-*directory* dependency into
`orchestrator/backlog/`, which would need prose-only treatment).

Per `factory/rulebooks/conventions/context-format.md`, `CONTEXT.md` is
created lazily, when the first term is resolved — not written
speculatively up front. This story does not invent factory terminology;
it scaffolds the eventual creation, most likely triggered by a future
`grill-with-docs` or `domain-modeling` session that resolves factory's
first real term.

**Priority:** could-have

## Acceptance Criteria

- `factory/CONTEXT.md` is created only once a first factory-specific term
  is actually resolved (e.g. during a `grill-with-docs`/`domain-modeling`
  session) — not authored speculatively as part of closing this story.
- Its content follows `context-format.md`'s structure: a one/two-sentence
  context description, then a `## Language` section of opinionated
  term definitions (with `_Avoid_` alternates where relevant), grouped
  under subheadings if natural clusters emerge.
- Terms are drawn from real `factory/` vocabulary (agents, skills,
  playbooks, gates, rulebooks, etc.) as actually used in
  `factory/agents/`, `factory/skills/`, `factory/playbooks/`,
  `factory/rulebooks/` — not invented ahead of that review.
- Once `factory/CONTEXT.md` exists, `docs/CONTEXT-MAP.md`'s `factory` row
  (ST-0002) is updated to link to it, replacing the "planned, no docs yet"
  stub.
