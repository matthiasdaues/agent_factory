# Close the verify-base enforcement gap in the git guardrail

The guardrail's worktree-commit check (`factory/config/hooks/block-dangerous-git.sh`) only tests that a `.current-work/verify-base-ok` marker is **present**, not that `verify-base` actually passed for the current worktree's branch and base. So a worktree cut from a stale base can still commit — as it did in the 2026-07-21 session, where a developer-agent committed on base `da899a9` (missing 144 commits) and `premerge-check` was the only thing that caught it (retro 2026-07-21).

`verify-base` already writes `target=`, `expect_base=`, and `head=` into the marker, but the guardrail ignores those fields.

**Priority:** must-have

## Acceptance Criteria

- Reproduce the stale-base bypass: a test drives the hook against a linked worktree whose `verify-base-ok` marker does not correspond to the worktree's actual branch/base, and asserts the commit is blocked.
- The worktree-commit check binds the marker to the worktree identity — it confirms `verify-base` passed for THIS worktree (matching the marker's `target`/branch), not merely that some marker file exists.
- Legitimate TDD commits still pass: a worktree whose HEAD has advanced past the verified base (normal red-green commits) is NOT blocked — the check must not require current-HEAD to equal the marker's recorded head.
- No weakening of existing blocking: the guardrail regression suite (`test_guardrail_parser.py`, `test_init_factory_guardrail.py`) stays green.
- Any marker-format change is coordinated with `factory/scripts/verify-base` so the two stay in lockstep.

## Investigation notes

The subtlety that makes this a `strong`-tier, reproduce-first story: the marker records `head=` at verify time (the base). Matching current HEAD to it would block every commit after the first, since HEAD advances during TDD. The likely correct check is to match the marker's branch/`target` to the current worktree and require the marker's recorded base to be an ancestor of the current HEAD (the work descends from a verified base), rather than an exact head match. Reproduce the bypass first, then decide the exact predicate.
