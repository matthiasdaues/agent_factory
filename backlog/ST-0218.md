# Rewrite capture-context greenfield mode to produce agent-context.md with concern sections

Rewrite the `capture-context --init` invocation mode so that it produces a concern-format `docs/agent-context.md` instead of four YAML files. The skill scans the repository for languages, frameworks, and test runners, seeds six generic cross-cutting concern sections from factory templates, proposes project-specific technical concerns from the detected stack, and proposes domain concerns from the scope map if one exists.

**Priority:** must-have

## Demo

The user runs `capture-context --init` in a new project that has `pyproject.toml` listing FastAPI and SQLAlchemy. The skill scans the repo and proposes: "I found FastAPI and SQLAlchemy -- proposing technical concerns: backend, data-storage. Confirm or adjust?" The user confirms. `docs/agent-context.md` appears with six cross-cutting sections (Branching, Committing, Testing discipline, Review, Scope discipline, Security) and two technical concern sections ("backend" and "data-storage"), each with a description line and `Read:` paths resolved from the scan. The domain section is empty with a note that the planning-agent populates it during backlog creation. Running `concern-lint` passes with zero findings.

## Acceptance Criteria

- `capture-context --init` produces `docs/agent-context.md` instead of YAML files.
- The output file contains three category headings: "Always (cross-cutting)", "Technical concerns", "Domain concerns".
- Six generic cross-cutting concern sections are seeded: Branching, Committing, Testing discipline, Review, Scope discipline, Security.
- Project-specific technical concerns are proposed from the detected stack and confirmed by the user before writing.
- Domain concerns are proposed from scope-map areas when a scope map exists; the domain section is left empty with a note otherwise.
- Each concern section has a description line and at least one `Read:` path.
- `concern-lint` passes on the output file (CTX-SECTIONS, CTX-PATHS).
- `capture-context --init` does not create YAML files (`stack.yaml`, `workflow.yaml`, `governance.yaml`, `reading-guides.yaml`).
- `capture-context --init` does not overwrite an existing `docs/agent-context.md`.
- The `--minimal` variants are dropped from the invocation table.

## Scope

**Status quo:** `capture-context --init` creates three YAML index files from templates, runs a stakeholder interview, and fills inline values. Four invocation modes exist (--init, --init --scan, --init --minimal, --init --scan --minimal). The concern-lint and rulebook from ST-0217 exist.

**Adds:** Rewritten `--init` mode that produces `agent-context.md` with concern sections. Repository scan proposes technical concerns. Scope-map scan proposes domain concerns. `--minimal` variants removed.

**Out of scope:** Brownfield documentation discovery and concern-based interview (ST-0219). YAML migration (ST-0220). Deletion of YAML templates (ST-0220).

## Notes for the Implementer

The skill definition is prose (SKILL.md), not executable code. The scan logic described in the skill definition is executed by the model at invocation time. The existing scan detection patterns (pyproject.toml, package.json, go.mod, etc.) can be reused; only the output format changes from YAML to markdown concern sections. The six generic cross-cutting concerns and their descriptions are defined in the proposal's "Generic cross-cutting concerns" table.
