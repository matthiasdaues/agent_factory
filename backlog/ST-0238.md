# Update create-backlog-stories to fill 13-section agent-ready story body

Rewrite the Phase 4 story-writing skill so it produces stories in the new 13-section format. Add 11 section-filling instructions that direct the planning agent to populate Goal, Domain Rule, Demo Scenario, Affected Paths, Inputs, Outputs, Required Behavior, Constraints, Suggested Agent Plan, Verification, and Agent Stop Conditions. Fold the existing testing.yaml cross-reference into Verification and Inputs. Carry ownership assignments into Inputs.

**Priority:** must-have

## Demo

1. Open `packages/factory/skills/create-backlog-stories/SKILL.md`.
2. Step 2 (Break EPICs into User Stories) contains 11 numbered section-filling instructions matching the proposal's list: Goal derivation, Domain Rule extraction, Demo as numbered steps, Affected Paths from codebase survey, Inputs as reading manifest, Outputs with behavioral detail, Required Behavior (conditional), Constraints from ADRs + conventions, Suggested Agent Plan, Verification from testing.yaml, Agent Stop Conditions from risk and ambiguity.
3. The existing testing.yaml cross-reference steps (1-6 in current skill) are folded into the Verification and Inputs section instructions instead of producing a separate Notes for the Implementer subsection.
4. The instruction for carrying test-design output references the Inputs section for ownership assignments, not "Notes for the Implementer."
5. The skill references the story template for the complete section list and references the parent skill for composition rules.
6. The quality gate includes the 8-question agent-answerability check and the International Readability gate (consistent with ST-0235).
7. A plain-language pass instruction follows the quality gate: reread Goal, Domain Rule, and Demo Scenario for understandability.

## Acceptance Criteria

- Step 2 contains 11 numbered instructions, one per new body section (agent-ready-story-format.md § Changes to create-backlog-stories, items 01 through 11).
- Goal derivation writes Goal from the EPIC's actor goals and the story's scope-map rules.
- Domain Rule extraction reads domain concerns and follows Read paths to supplementary specs and glossary.
- Demo Scenario instruction requires numbered steps with concrete values, not 2-4 sentence paragraphs.
- Affected Paths instruction extends the current Status Quo survey to list specific files per layer.
- Inputs instruction lists deps deliverables, spec rules, architecture references, and current implementation files as a reading manifest.
- Outputs instruction requires per-layer behavioral detail in observable terms.
- Required Behavior instruction is marked conditional and instructs the agent to include it only when Outputs does not fully capture the behavior.
- Constraints instruction gathers must-nots from traces, agent-context technical concerns, and testing.yaml.
- Suggested Agent Plan instruction writes numbered implementation steps referencing Affected Paths and Outputs.
- Verification instruction lists exact shell commands per suite from the testing regime.
- Agent Stop Conditions instruction identifies ambiguity, conflicting patterns, and missing infrastructure, scaled by risk_level.
- The existing testing.yaml cross-reference is folded into Verification and Inputs sections, not into a Notes for the Implementer subsection.
- Ownership assignments from epics.md go into the Inputs section, not Notes for the Implementer.
- The plain-language pass instruction follows the quality gate section.
- References to "Notes for the Implementer" are removed from the skill text.

## Scope

**Status quo:** `packages/factory/skills/create-backlog-stories/SKILL.md` instructs writing Demo first, then a three-part Scope (Status quo / Delivers / Out of scope), Acceptance Criteria, and Notes for the Implementer. Testing.yaml cross-reference (6 steps) produces output in Notes for the Implementer. Test-design output (Failure scenarios, Prior Tests) goes into story body after Acceptance Criteria. Ownership assignments go into Notes for the Implementer.

**Delivers:** A rewritten Step 2 with 11 section-filling instructions for the 13-section body, folded testing.yaml cross-reference, ownership assignments in Inputs, plain-language pass, and updated quality gate.

**Out of scope:** Template changes (ST-0234). Parent skill composition rules (ST-0235). Epic-level skill changes (ST-0236). Slice table changes (ST-0237). Developer-agent changes (ST-0239).
