# Block a merge on a failing CRAP or mutation gate

**Priority:** must-have

## Goal

The implementation agent blocks a merge when a gate it picked fails or cannot run. It runs the project's mutation command from `testing.yaml`. The developer agent runs the same gates in manual mode before it hands a story back.

## Contract

| Operation | Input state                                                       | Outcome                                               | Persistence |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------- | ----------- |
| Gate run  | Any story                                                         | `dependency-check` runs                               | None        |
| Gate run  | Story has a Test Design or Prior Tests section                    | `test-design-verify` runs                             | None        |
| Gate run  | Story `quality-gates: [crap-score]`                               | Runs `crap-score`; ignores the `gates` section        | None        |
| Gate run  | No story field; `gates.crap_score.enabled: true`                  | Runs `crap-score`                                     | None        |
| Gate run  | No story field, no `gates` section                                | Runs `crap-score`; no mutation testing                | None        |
| Gate run  | `crap-score` reports 42 against a threshold of 30                 | Merge blocked                                         | None        |
| Gate run  | Mutation testing picked, `gates.mutation_testing.command` missing | Gate fails; the message names the test-strategy agent | None        |
| Gate run  | Mutation command exits 1                                          | Merge blocked                                         | None        |

## Demo Scenario

1. The operator runs `packages/factory/scripts/premerge-check` on the fixture `crap-over` (Demo Data). It exits non-zero and names `plan_moves` at 42.
2. On `mutation-no-command`, it exits non-zero and names the test-strategy agent.
3. On `mutation-fails`, it exits non-zero after the command `scripts/mutate.sh` exits 1.
4. On `no-gates`, it runs `crap-score` and `dependency-check` and no mutation testing.
5. The operator reads the developer agent's manual-mode workflow. It runs the same gates before the handback.

| --------------------- | --------------------- | ---------------------------------------------- | --------------------------- |

## Boundaries

- The story field and the `gates` section pick only `crap-score` and mutation testing (CAO-G24, CAO-G25).
- No default runs mutation testing.
- A gate that cannot run fails.
- `quality-gates` of this story is empty because `docs/testing.yaml` enables no gate for the factory. Enabling one waits for the stakeholder (DEC-31).
