# Take the gate list from the story, then from testing.yaml

**Priority:** must-have

## Goal

`premerge-check` picks a story's test guardrails from the story's `quality-gates` field, then from the `gates` section of `docs/testing.yaml`, then from a default that runs `crap-score` only. It warns when the house rules still carry the old gate list. A picked gate that failed blocks the merge.

## Contract

| Operation        | Input state                                                                                     | Outcome                                                                                        | Persistence |
| ---------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------- |
| `premerge-check` | Any story                                                                                       | Requires the `dependency-check` result                                                         | None        |
| `premerge-check` | Story has a Test Design or Prior Tests section                                                  | Requires the `test-design-verify` result                                                       | None        |
| `premerge-check` | Story `quality-gates: [crap-score]`                                                             | Requires the `crap-score` result; ignores the `gates` section                                  | None        |
| `premerge-check` | No story field; `gates.crap_score.enabled: true`, `gates.mutation_testing.enabled: false`       | Requires the `crap-score` result only                                                          | None        |
| `premerge-check` | No story field, no `gates` section                                                              | Requires the `crap-score` result; no mutation testing                                          | None        |
| `premerge-check` | The `crap-score` result reports 42 against a threshold of 30                                    | Exit non-zero; merge blocked                                                                   | None        |
| `premerge-check` | `docs/charter/house-rules.md` has `default_quality_gates`; `testing.yaml` has a `gates` section | Prints a warning that names `docs/charter/house-rules.md`; takes the gates from `testing.yaml` | None        |

## Demo Scenario

1. The operator runs `packages/factory/scripts/premerge-check` on the fixture `crap-over` (Demo Data). It exits non-zero and names `plan_moves` at 42.
2. On `testing-yaml-gates`, it requires only the `crap-score` and `dependency-check` results.
3. On `old-house-rules`, it prints a warning that names `docs/charter/house-rules.md` and takes the gates from `testing.yaml`.
4. On `no-gates`, it requires `crap-score` and `dependency-check` and no mutation testing.

## Boundaries

- The story field and the `gates` section pick only `crap-score` and mutation testing (CAO-G24, CAO-G25).
- No default runs mutation testing.
- The `gates` section of `testing.yaml` replaces `default_quality_gates` in the house rules (CAO-G28).
- `quality-gates: []` stays on this story and on every open story of this backlog until this story ships and the factory is reinstalled with `update-factory`. The installed `premerge-check` ignores `testing.yaml`; without the field, it falls back to all three gates, mutation testing included, which has no script yet. `dispatch` calls the installed copy.
- DEC-31 note: while stories of this backlog with `quality-gates: []` are open, the stakeholder does not enable a gate in `docs/testing.yaml`. Otherwise the stakeholder removes the field from those open stories at that moment, because an empty list overrides the enabled gate.
