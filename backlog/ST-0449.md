# Enable the CRAP gate on this repository for Python and TypeScript

This repository runs the CRAP gate on every merge, with one proved measure for Python and one for TypeScript.

**Priority:** must-have

## Goal

After this feature is installed, `docs/testing.yaml` of this repository enables `crap-score` with a measure `python` and a measure `typescript`, each passed by `gate-setup-proof`. Every function in a script that starts with `uv run` shows measured coverage. T-0402 names the two proposals.

## Domain Rule

- The story runs in its own run on `feature/crap-gate-self-host`, cut from `dev` after `feature/crap-gate-setup` merges and `update-factory` installs the new scripts. It runs the installed `setup-crap-score` and `gate-setup-proof` (DEC-49).
- The test-strategy agent writes `docs/testing.yaml`, because it owns the file. The entry keeps `mutation-testing`, the `dispatch` section and every suite.
- The Python measure covers the scripts without an ending. No `exclude` pattern matches a script that starts with `uv run` (DEC-04).
- The TypeScript measure runs `node --test --experimental-test-coverage`, because this repository has no `package.json`.
- `timeout_minutes` is at least `measured_minutes`, the run time of `crap-score --all` from setup step 6. The entry has no `ready` line.
- The two measuring commands refer to nothing under `.agent-factory/`.

## Outputs

- This repository's Python and TypeScript measuring commands, in the folder the User confirms during setup.
- `docs/testing.yaml`: `gates.crap-score` with `enabled: true`, threshold, `timeout_minutes`, `measured_minutes`, and the measures `python` and `typescript`.
- `docs/spec/work/todo.md`: T-0402 names `docs/proposals/crap-gate-setup.md` and `docs/proposals/mutation-gate.md`.
- New `tests/factory/test_crap_gate_repository.py`; a row in `tests/factory/test_crap_gate_text.py`.

## Demo Scenario

1. After `update-factory`, the User asks the test-strategy agent to set up the CRAP gate on this repository.
2. The installed `gate-setup-proof` passes for `python` and for `typescript`, and `crap-score --all` reports the failing functions and the run time.
3. The User confirms the threshold and `timeout_minutes`. `docs/testing.yaml` shows `gates.crap-score` with `enabled: true` and the two measures.
4. In the next run, a story that changes `packages/factory/scripts/finding-lint` gets its changed function scored at the merge.

## Demo Data

The story seeds nothing. The integration tests plant a `uv run --script` script with a test that runs it as a subprocess, and a `.ts` file with a `node:test` test, in temporary folders.

- No retained test runs a real measuring command against this repository's root; CG-13-IT-03 is the one-time setup run.
- The story edits `docs/spec/work/todo.md` only at T-0402.
