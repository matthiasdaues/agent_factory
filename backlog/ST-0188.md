# Create the test-design-verify gate script

Create a new gate script at `factory/scripts/test-design-verify` that validates test-design completeness by resolving the trace-to-scenario chain and verifying that owned contracts have assertions.

**Priority:** must-have

## Demo

Create a story file with `traces: [DOM-01]` and a `#### Test Design` section covering all scenarios under DOM-01's `.feature` rule. Run `factory/scripts/test-design-verify --story backlog/ST-0200.md`. The gate exits 0. Remove one scenario from the Test Design section and run again -- the gate exits 1, reporting which scenario lacks a test assertion. Add a waiver line `> Waiver: DOM-01 -- owned by tests/test_domain.py::test_entity_uniqueness` pointing to a non-existent module. The gate exits 1, reporting the invalid waiver. Create the test module and run again -- the gate exits 0.

## Acceptance Criteria

- The gate script exists at `factory/scripts/test-design-verify` (CC 8).
- The gate reads `traces:` from story frontmatter and resolves each trace ID through `docs/spec/scope-map.md` to the `.feature` file and rule (test-design.feature Rule 14, Scenario 1).
- The gate collects scenarios under the matching rule and verifies each has a corresponding entry in `#### Test Design` (test-design.feature Rule 14, Scenario 1).
- The gate exits 0 when all owned contracts have assertions (test-design.feature Rule 14, Scenario 2).
- The gate exits 1 when an owned contract lacks an assertion, reporting which scenario is missing (test-design.feature Rule 14, Scenario 3).
- The gate accepts valid waivers in blockquote format (`> Waiver: <ID> -- owned by <path>::<function>`) when the named test module exists (test-design.feature Rule 14, Scenario 4).
- The gate rejects waivers when the named test module does not exist (test-design.feature Rule 14, Scenario 5).
- The gate validates non-owning stories' `#### Prior Tests` entries point to resolvable test modules and functions (test-design.feature Rule 14, Scenario 6).
- The gate exits 0 and produces no findings when the story has no `#### Test Design` and no `#### Prior Tests` sections (test-design.feature Rule 14, Scenario 7).
- The gate exits 2 on configuration errors such as unresolvable trace IDs or missing scope-map entries (test-design.feature Rule 14, Scenario 8).
- Integration tests verify the gate's end-to-end behavior with real story files and scope map.

## Scope

**Status quo:** The test-design skill exists (delivered by ST-0185) and writes Test Design and Prior Tests sections into `epics.md`. No gate validates these sections.

**Adds:** `factory/scripts/test-design-verify` -- a stdlib-only Python script with the resolution chain (traces -> scope-map -> .feature -> scenarios -> Test Design section). Waiver parsing and validation. Integration tests at `tests/factory/test_test_design_verify.py`.

**Out of scope:** Gate execution ordering (owned by ADR-0012). Dispatcher integration (ST-0189). The test-design skill itself.

## Notes for the Implementer

The script follows Factory conventions: stdlib-only Python 3.10+, `#!/usr/bin/env -S uv run --script` shebang, exit codes 0/1/2 per the existing gate convention. The resolution chain is documented in [interface-contracts.md](../docs/spec/supplementary_specs/interface-contracts.md). Use the minimal YAML subset parser for frontmatter extraction. Scope-map parsing extracts the Rule column and Sources column to map trace IDs to `.feature` files. New tests target the integration test suite at `tests/factory/test_test_design_verify.py` (QA strategy IDs TD-IT-01 through TD-IT-05).
