# Translate a portable envelope through an OpenCode adapter

After this story ships, the engine can build a portable envelope for any agent definition and translate it into OpenCode CLI arguments through an adapter.

**Priority:** must-have

## Goal

A developer creates an `Envelope` from an agent definition's frontmatter and a model tier. The `OpenCodeAdapter` translates that envelope into the parts needed to invoke `opencode` — model ID, instruction text, tool permissions, and token limit. The adapter returns an `AdapterResult` that names the agent, records the command parts, and carries the declared outputs for a subsequent fence run.

No CLI is actually invoked. The PoC proves the data path: agent definition in, translated command parts out, with enough structure for the fence to know what to check.

## Domain Rule

- The envelope is runtime-agnostic. It carries logical values (model tier, not model ID).
- The adapter is runtime-specific. It maps logical values to OpenCode equivalents.
- Model tier mapping is hardcoded in the adapter for this story. A configuration file replaces it later.
- The adapter result must include the agent name and declared output patterns so the fence can use them.

## Inputs

- Agent definition frontmatter (from any `.md` agent file in `factory/agents/`)
- `packages/factory/engine/fence.py` — existing FenceResult / DeclarationResult for structural compatibility
- `packages/factory/engine/eligibility.py` — existing frontmatter reader `_read_frontmatter`

## Acceptance Criteria

1. `Envelope` dataclass exists with fields: agent_name, model_tier, instructions, input_paths, tool_permissions, token_limit, timeout_seconds.
2. `OpenCodeAdapter.translate(envelope)` returns an `AdapterResult` with fields: agent_name, runtime_name, command_parts (list of strings), declared_outputs, evidence (dict).
3. Given an envelope with `model_tier="standard"`, the adapter's command_parts contain the OpenCode model ID for that tier.
4. Given an envelope with `tool_permissions=["Read", "Edit", "Bash"]`, the adapter's command_parts contain the corresponding OpenCode tool flags or arguments.
5. `AdapterResult.declared_outputs` carries the same structure as agent definition `outputs.declarations` so it can be passed to the fence.
6. All tests pass under `uv run pytest`.

## Failure Scenarios

#### Failure scenarios

1. Envelope created with an unknown model tier raises `ValueError`.
2. Adapter called with an empty instructions string raises `ValueError`.
3. Adapter called with `tool_permissions=[]` produces command_parts with no tool flags (tools are optional, not defaulted).

## Resolve Before Implementation

None — design decisions are settled in the spike brief and proposal.
