# Declare a review and see index-lint check the reviewer

**Priority:** must-have

## Goal

The factory maintainer finds `reviewed_by:` and `edits:` beside each output declaration in `INDEX.yaml`. `index-lint --check` fails when a declared reviewer is no agent, or is an agent that does not read the artifact. The story also creates the core list that the check reads its sample paths from.

## Contract

| Operation            | Input state                                                                                   | Outcome                                                                 | Persistence            |
| -------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------- |
| `index-lint`         | A declaration with `reviewed_by: [spec-review-agent]` and one with `edits: wording`           | Both fields appear in `INDEX.yaml` beside `path_pattern`                | `INDEX.yaml` rewritten |
| `index-lint --check` | `reviewed_by: [qa-reviewer]`, and no agent `qa-reviewer` exists                               | Exit 1; the message names `qa-reviewer` and the declaring agent         | None                   |
| `index-lint --check` | `reviewed_by: [developer-agent]` on the feature files; the developer agent does not read them | Exit 1; the message names the reviewer and the sample path              | None                   |
| `index-lint --check` | `reviewed_by: [stakeholder]`                                                                  | Exit 0                                                                  | None                   |
| `index-lint --check` | The reviewer declares the artifact as a context input only                                    | Exit 0                                                                  | None                   |
| `index-lint --check` | Producer `docs/spec/features/{name}.feature`, reviewer input `docs/spec/features/*.feature`   | Exit 0; both match the sample path `docs/spec/features/example.feature` | None                   |
| `index-lint --check` | The factory's own agent definitions after this story                                          | Exit 0                                                                  | None                   |

## Demo Scenario

1. The maintainer runs `packages/factory/scripts/index-lint`. `packages/factory/INDEX.yaml` shows `reviewed_by: [spec-review-agent]` on the requirements agent's `docs/spec/features/{name}.feature` and `edits: wording` on the lector agent's `docs/**/*.md`.
2. The maintainer changes that `reviewed_by:` to `[qa-reviewer]` and runs `index-lint --check`. It exits 1 and names `qa-reviewer` as no agent.
3. The maintainer changes it to `[developer-agent]`. `index-lint --check` exits 1, because the developer agent does not declare the feature files as an input.
4. The maintainer reverts the change. `index-lint --check` exits 0.

## Demo Data

The demo uses the factory's own agent definitions. The tests build fixture agent directories in `tmp_path`:

| Fixture             | Content                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| `reviewer-unknown`  | Producer of `docs/spec/features/{name}.feature` with `reviewed_by: [qa-reviewer]`                           |
| `reviewer-no-input` | Same producer with `reviewed_by: [developer-agent]`; `developer-agent` has no feature-file input            |
| `reviewer-context`  | Same producer with `reviewed_by: [spec-review-agent]`; the reviewer lists the feature files as context only |

## Boundaries

- `reviewed_by:` holds agent names or `stakeholder` ([interface-contracts.md § Output declaration fields](../docs/spec/interface-contracts.md#output-declaration-fields)).
- The reviewer check matches a producer's pattern and a reviewer's pattern through the sample path of the core list entry, and `{name}` matches like `*` (CAO-G06, CAO-G14).
- Working output carries no `reviewed_by:`.
- The core list holds exactly the thirteen entries and the fields `path_pattern`, `sample_path`, `family`, and `optional` of [interface-contracts.md § core-artifacts.yaml](../docs/spec/interface-contracts.md#packagesfactoryrulebookscore-artifactsyaml).
- `quality-gates` is empty because `docs/testing.yaml` enables no gate. `dependency-check` is not a pickable value (CAO-G25).
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
