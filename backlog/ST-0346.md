# Declare a review and see index-lint check the reviewer

**Priority:** must-have

## Goal

The factory maintainer finds `reviewed_by:` and `edits:` beside each output declaration in `INDEX.yaml`. `index-lint --check` fails when a declared reviewer is no agent, or is an agent that does not read the artifact. The story also creates the core list that the check reads its sample paths from.

## Contract

| Operation            | Input state                                                                                                           | Outcome                                                                 | Persistence            |
| -------------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------- |
| `index-lint`         | A declaration with `reviewed_by: [spec-review-agent]` and one with `edits: wording`                                   | Both fields appear in `INDEX.yaml` beside `path_pattern`                | `INDEX.yaml` rewritten |
| `index-lint --check` | `reviewed_by: [qa-reviewer]`, and no agent `qa-reviewer` exists                                                       | Exit 1; the message names `qa-reviewer` and the declaring agent         | None                   |
| `index-lint --check` | `reviewed_by: [developer-agent]` on the feature files; the developer agent does not read them                         | Exit 1; the message names the reviewer and the sample path              | None                   |
| `index-lint --check` | `reviewed_by: [stakeholder]`                                                                                          | Exit 0                                                                  | None                   |
| `index-lint --check` | `reviewed_by:` on a declaration whose pattern matches no core list entry, such as `docs/spec/work/term-candidates.md` | Exit 1; the message names the agent and the declaration                 | None                   |
| `index-lint --check` | The reviewer declares the artifact as a context input only                                                            | Exit 0                                                                  | None                   |
| `index-lint --check` | Producer `docs/spec/features/{name}.feature`, reviewer input `docs/spec/features/*.feature`                           | Exit 0; both match the sample path `docs/spec/features/example.feature` | None                   |
| `index-lint --check` | The factory's own agent definitions after this story                                                                  | Exit 0                                                                  | None                   |

## Demo Scenario

1. The maintainer runs `packages/factory/scripts/index-lint`. `packages/factory/INDEX.yaml` shows `reviewed_by: [spec-review-agent]` on the requirements agent's `docs/spec/features/{name}.feature` and `edits: wording` on the lector agent's `docs/**/*.md`.
2. The maintainer changes that `reviewed_by:` to `[qa-reviewer]` and runs `index-lint --check`. It exits 1 and names `qa-reviewer` as no agent.
3. The maintainer changes it to `[coaching-agent]`. `index-lint --check` exits 1 with a reviewer finding, because the coaching agent does not declare the feature files as an input. (`developer-agent` would pass the reviewer check: it reads `docs/spec/features/*.feature`.)
4. The maintainer reverts the change. `index-lint --check` exits 0.

## Resolve Before Implementation

None. The grilling (stakeholder, 2026-11-04) settled the one open question: `index-lint --check` fails on `reviewed_by:` on a declaration that matches no core list entry. The Contract and Boundaries hold the answer.

## Analysis

`index-lint` already keeps every key of an output declaration through `_parse_entry`, so the first stop condition does not apply. Two gaps block the story. `_parse_entry` reads `reviewed_by: [a, b]` as the string `"[a, b]"`, not as a list. `_render_structured_field` writes only `path_pattern`, `validator`, and `required` of a declaration, so `reviewed_by:` and `edits:` never reach `INDEX.yaml`.

The implementation:

- `_parse_entry` reads an inline list `[a, b]` after the first key as a list of strings.
- `_render_structured_field` writes `reviewed_by:` as a flow list and `edits:` as a scalar after `required`, only when the declaration carries them.
- `load_core_list` reads `core-artifacts.yaml` from the rulebooks directory with PyYAML, imported inside the function so that `trigger` can still import the module without PyYAML. A missing file gives an empty list.
- `reviewer_findings` checks every declaration that carries `reviewed_by:`. It finds the core list entries whose `sample_path` matches the declaration's pattern. No match is a finding. A reviewer other than `stakeholder` must be an agent. That agent must have a required input, an `any_of` alternative, or a context entry that matches each sample path. Matching uses `dispatch_lib.glob_match` after `{...}` placeholders become `*` (BR-057).
- `main` fails with exit 1 on a reviewer finding in both modes, before it writes. The pre-commit hook runs plain mode, so a failure only in `--check` mode would let a bad reviewer reach a commit. The other structural errors of `index-lint` behave the same way.
- `packages/factory/rulebooks/core-artifacts.yaml` holds the thirteen entries of the interface contract with `path_pattern`, `sample_path`, `family`, and `optional`.
- The requirements agent declares `reviewed_by: [stakeholder]` on `docs/spec/scope-map.md` and `reviewed_by: [spec-review-agent]` on `docs/spec/features/{name}.feature`. The architecture agent declares `reviewed_by: [architecture-review-agent]` on `docs/spec/architecture.dsl`. VIRGIL declares `reviewed_by: [stakeholder]` on `docs/agent-context.md`. The lector agent declares `edits: wording` on `docs/**/*.md`. Each named reviewer already reads its artifact as a required input.

Scenarios the tests cover, from the Rule "Factory maintainer sees every declared review checked against the reviewer's inputs": the `reviewed_by` and `edits` catalog Scenario, the context-input Scenario, the sample-path Scenario, the unknown-reviewer Scenario, the reviewer-without-input Scenario, the stakeholder Scenario, and the up-to-date catalog Scenario. "A reader is never counted as a review" belongs to the contract test of ST-0347.

Concerns: the interface contract says `index-lint` exits 1 on a reviewer finding "in `--check` mode" and 0 otherwise. This story also fails plain mode, for the hook reason above. The hook's `files:` trigger does not match `rulebooks/core-artifacts.yaml`, so an edit to the core list alone does not run the hook. The first goes to the [Spec feedback](#spec-feedback) section.
