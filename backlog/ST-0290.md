# Configure hooks grouped by protected outcome with source-only triggers filtered

**Priority:** must-have

## Goal

When fitting introduces hook configuration, the session presents hooks grouped by protected outcome and asks only about automatic file changes or material execution cost. Unavailable hooks appear with a description, not as errors or choices. The consumer hook set omits `index-lint` and any hook that matches only ignored Factory runtime paths (BUG-0029). `matrix-lint` runs after model configuration and before dispatch.

## Contract

| Operation                                                             | Input state                           | Outcome                                                                                                          | Persistence                                           |
| --------------------------------------------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Fitting presents hook configuration                                   | Gate demonstration complete (ST-0289) | Hooks grouped by protected outcome (e.g., "Formatting: mdformat", "Dangerous git commands: block-dangerous-git") | No configuration written yet                          |
| Hook performs automatic file changes                                  | Hook listed in group                  | Session asks for consent                                                                                         | Configuration written on approval                     |
| Hook carries no automatic file changes and no material execution cost | Hook listed in group                  | Hook auto-included without asking                                                                                | Configuration includes the hook                       |
| Hook unavailable for detected project                                 | Hook exists in Factory set            | Hook appears with a description, not as an error or choice                                                       | Hook excluded from configuration                      |
| `index-lint`                                                          | Consumer hook subset generated        | `index-lint` absent from consumer set                                                                            | `index-lint` not in generated config                  |
| Hook matches only ignored Factory runtime paths                       | Consumer hook subset generated        | Hook excluded from consumer set (BUG-0029)                                                                       | Hook not in generated config                          |
| `matrix-lint`                                                         | Model configuration complete          | `matrix-lint` scheduled after model configuration and before dispatch                                            | `matrix-lint` in generated config at correct position |

## Boundaries

- Do not remove hooks from `pre-commit-config.yaml` — filter them at subset generation time.
- Do not rewrite `merge-precommit-config` from scratch — extend or wrap the existing script.
- The hook presentation does not default to selecting all hooks. Each hook that performs automatic file changes or carries material cost requires separate consent.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Demo Scenario

1. Open a Factory session on a project where hooks have not been configured.
2. Complete the gate demonstration (ST-0289).
3. Fitting presents hooks grouped by protected outcome: e.g., "Formatting: mdformat", "Dangerous git commands: block-dangerous-git".
4. The session asks about mdformat (automatic file changes). Approve.
5. The session does not ask about block-dangerous-git (no automatic file changes, no material execution cost).
6. An unavailable hook (e.g., a linter for a language not detected in the project) appears with a description, not as an error.
7. Verify `index-lint` is absent from the consumer hook set.
8. Verify no hook in the generated consumer set matches only paths under `.agent-factory/factory/`.
9. Configure the model matrix. Verify `matrix-lint` runs after model configuration and before dispatch.

## Stop Conditions

- Hook file patterns use regex syntax that the filter cannot evaluate without executing the hook → report which patterns and ask for a static evaluation strategy.
- `merge-precommit-config` has undocumented side effects that conflict with subset filtering → report the conflict.
- The outcome-group metadata format conflicts with existing hook configuration consumers → report the conflict and ask for precedence.
- Code in `packages/factory/config/pre-commit-config.yaml` and the feature spec disagree on which hooks belong in the consumer set → report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. What data structure holds the mapping from hook id to protected outcome and trade-off category — a YAML companion file, inline comments in `pre-commit-config.yaml`, or a Python dictionary in the filter script?
2. How does the filter determine whether a hook matches "only" gitignored paths — by comparing the hook's `files` regex against `.gitignore` patterns statically, or by testing against a representative file list?
