# Relocate testing.yaml to docs/testing.yaml and update all resolution chains

Move `testing.yaml` from its current locations (`docs/agent-context/testing.yaml` or `docs/charter/testing.yaml`) to `docs/testing.yaml`. Update every consumer that resolves testing.yaml: the `detect-test-regime` skill (which writes it), the `crap-score` script (which reads gate thresholds), the `init-factory` script (which scaffolds it), and all agent definitions that reference its path. No fallback to legacy paths.

**Priority:** must-have

## Demo

The user moves `testing.yaml` to `docs/testing.yaml`. Running `crap-score` resolves it at the new location without error. Running `detect-test-regime` writes to `docs/testing.yaml`. Running `init-factory` scaffolds `testing.yaml` at `docs/testing.yaml`. Grepping agent definitions for `docs/agent-context/testing.yaml` or `docs/charter/testing.yaml` returns zero matches -- all references point to `docs/testing.yaml`.

## Acceptance Criteria

- `detect-test-regime` skill writes `testing.yaml` at `docs/testing.yaml` (no fallback to legacy paths).
- `crap-score` script resolves `testing.yaml` at `docs/testing.yaml` (no fallback).
- `init-factory` script scaffolds `testing.yaml` at `docs/testing.yaml`.
- All agent definitions that reference `docs/agent-context/testing.yaml` or `docs/charter/testing.yaml` are updated to `docs/testing.yaml`.
- No file in `factory/agents/`, `factory/skills/`, or `factory/scripts/` contains the string `docs/agent-context/testing.yaml` or `docs/charter/testing.yaml`.
- The planning-agent's pre-flight check resolves `testing.yaml` at `docs/testing.yaml`.

## Scope

**Status quo:** `testing.yaml` lives at `docs/agent-context/testing.yaml` (or `docs/charter/testing.yaml` for legacy projects). `detect-test-regime` writes to the old path. `crap-score` resolves via format detection with charter fallback. Agent definitions hardcode the old path.

**Adds:** Single canonical path `docs/testing.yaml`. All consumers updated. No fallback chain.

**Out of scope:** Moving `testing.yaml` during YAML migration (ST-0220 handles that as part of the interactive migration flow). Concern model changes to agent definitions (ST-0224, ST-0225).
