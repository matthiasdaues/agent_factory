# Seed the domain vocabulary into the glossary during reverse mapping

**Priority:** must-have

## Goal

During brownfield onboarding, `reverse-map` writes the domain terms it extracts
from the code into Term/Definition/Avoid tables of `docs/spec/glossary.md`. It
writes no `docs/CONTEXT.md`.

## Contract

| Operation                     | Input state                                        | Outcome                                                                        | Persistence             |
| ----------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------- |
| `reverse-map` vocabulary step | New-layout project without `docs/spec/glossary.md` | Creates the glossary from the template of ST-0336 with one section per context | `docs/spec/glossary.md` |
| `reverse-map` vocabulary step | Glossary exists with section "Billing"             | Adds rows to existing sections; a term already in a section is not added twice | `docs/spec/glossary.md` |
| `reverse-map` vocabulary step | Any                                                | No `docs/CONTEXT.md` is written                                                | None                    |

## Demo Scenario

1. The maintainer runs `reverse-map` in brownfield onboarding on the fixture
   `brownfield-payments` (Demo Data).
2. `docs/spec/glossary.md` holds a "Payments" section whose table has the
   columns Term, Definition, and Avoid and rows for "Invoice" and "Settlement".
3. `ls docs/CONTEXT.md` reports that the file does not exist.

## Demo Data

The skill runs in an agent session, so the demo uses a hand-built fixture. The
retained tests are text checks.

| Fixture               | Content                                                                                                                                                   |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `brownfield-payments` | `src/payments/invoice.py` with class `Invoice`, `src/payments/settlement.py` with class `Settlement`; `docs/agent-context.md`; no `docs/spec/glossary.md` |

## Boundaries

- Terms land only in `docs/spec/glossary.md`, in the template's table form.
- `reverse-map` never writes `docs/CONTEXT.md`.
- Spec edits stay in the reverse-map Rule of `newcomer-onboarding.feature`
  (`Reverse-map skill populates scope map from forensic evidence`, scenario
  `Reverse-map seeds docs/CONTEXT.md with domain vocabulary`) and its
  scope-map row (CAL-G15). The three anchor-file Rules belong to ST-0335.
- `docs/spec/newcomer-onboarding.feature` stays at its current path until
  ST-0343.
