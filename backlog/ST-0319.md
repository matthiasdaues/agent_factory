# Remove the actor-goal list and the use-case files, also from the archive

**Priority:** must-have

## Goal

The project maintainer runs `migrate-spec-layout`, and git records
`actor-goal-list.md` and every file in a `use_cases/` folder under `docs/` as
removed, `docs/~archive/` included. Every other archived file stays. A file in
that removal set that git cannot remove safely stays in place and appears in a
list of files for the developer to delete.

## Contract

| Operation                       | Input state                                                                                 | Outcome                                                                            | Persistence                                                                |
| ------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `migrate-spec-layout`           | Clean tracked `actor-goal-list.md` or `use_cases/*.md` anywhere under `docs/`               | `git status` shows `deleted:`; exit 0                                              | `git rm`                                                                   |
| `migrate-spec-layout`           | Removal-set file that is untracked, ignored, or tracked with a staged or an unstaged change | File stays with its content; the output lists its path as a file to delete; exit 0 | None for that file                                                         |
| `migrate-spec-layout`           | Other files in `docs/~archive/`                                                             | Unchanged                                                                          | None                                                                       |
| `migrate-spec-layout --dry-run` | Old layout with a removal set                                                               | Prints one line per planned removal and per file to delete by hand; exit 0         | None                                                                       |
| `migrate-spec-layout`           | A later step fails after a removal                                                          | The removed file is back in the index and the working tree; exit 1                 | Restored by `git reset` and `git checkout` of that path, or the equivalent |
| `migrate-spec-layout`           | New-layout project with no removal-set file                                                 | No output; exit 0                                                                  | None                                                                       |

## Demo Scenario

1. The maintainer copies the fixture `old-layout-archive` (Demo Data) into
   `/tmp/demo` and runs `packages/factory/scripts/migrate-spec-layout /tmp/demo`.
2. `git -C /tmp/demo status` shows `deleted: docs/~archive/spec/actor-goal-list.md`
   and `deleted: docs/~archive/spec/use_cases/UC-04-dispatch-an-agent-via-trigger.md`.
   `docs/~archive/spec/old-notes.md` is unchanged.
3. On a fresh copy, the maintainer adds an unstaged change to
   `docs/spec/use_cases/UC-07.md` and runs the script again.
4. `UC-07.md` still exists with the change, and the output lists
   `docs/spec/use_cases/UC-07.md` among the files to delete.

## Boundaries

- Risk domain: `data_integrity`. A wrong removal loses content git cannot
  restore, so the tier is `strong` per the tier rubric.
- The script never runs `git rm -f` and never removes a file with a plain
  removal (CAL-G17).
- Only `actor-goal-list.md` and files inside a folder named `use_cases` under
  `docs/` are in the removal set. Every other file in `docs/~archive/` stays
  (DEC-10).
- Removals join the undo journal of ST-0318, so a failed run restores them.
- A removed file that a Markdown link names is ST-0320's concern. This story
  does not touch links.

## Evidence

- [ ] On `old-layout-archive`, `git status --porcelain` shows `D` for
  `actor-goal-list.md` and every `use_cases/` file, `R` for the moved files,
  and no entry for `docs/~archive/spec/old-notes.md` (CAL-03-IT-01).
- [ ] For each of the four git states of `UC-07.md` (untracked, ignored, staged
  change, unstaged change), the file keeps its content, the output names it,
  and the script exits 0 (CAL-03-IT-06).
- [ ] When a step after a removal fails, the removed file is back with its
  content and `git status --porcelain` equals the state before the run.
- [ ] No code path of the script calls `git rm -f`, `git rm --force`,
  `os.remove`, `Path.unlink`, or `shutil.rmtree` on a removal-set file.

## Out of Scope

- Rewriting links to removed files into code spans (ST-0320).
- Removing anything outside `docs/`.

## Agent Stop Conditions

- The proposal's path table and the contract's Removes row disagree on which
  files form the removal set. Report both and stop.
- A git version on the runner treats one of the four git states differently
  from the contract, so `git rm` would succeed and lose the change. Report the
  git version and the state.
- The undo journal of ST-0318 cannot restore a `git rm` without a new design.
  Report the gap.

## Resolve Before Implementation

None. The removal rule and the listing are fixed by CAL-G17 in the contract.
The listing uses the same output format as the old-path listing of ST-0321;
until ST-0321 lands, each line reads `delete by hand: <path>`.
