# Get the factory hook block from the new template during an update

**Priority:** must-have

## Goal

After the project maintainer approves an update of a project in the old
layout, each factory hook in `.pre-commit-config.yaml` has the `files:` value
of the new template. A change to `docs/spec/architecture.dsl` or to
`docs/arc42/05_building_block_view.md` triggers `arch-lint`, and the maintainer
was not asked about the hooks.

## Contract

| Operation                                                     | Input state                                                     | Outcome                                                                              | Persistence               |
| ------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------- |
| `update-factory`, update approved                             | Old layout; factory hook block with the old `arch-lint` pattern | Every factory hook has the template's `files:` value; no hook question in the output | `.pre-commit-config.yaml` |
| `pre-commit run --files docs/spec/architecture.dsl`           | After that update                                               | Runs `agent_factory_hook-arch-lint`                                                  | None                      |
| `pre-commit run --files docs/arc42/05_building_block_view.md` | After that update                                               | Runs `agent_factory_hook-arch-lint`                                                  | None                      |
| `merge-precommit-config`                                      | Any input                                                       | Names no old path in its code or messages                                            | —                         |

## Demo Scenario

1. The maintainer builds the fixture `installed-1.3.3-hooks` (Demo Data) and
   runs `update-factory` from a source with `VERSION` `1.4.0`, approving once.
2. The output holds no question about `.pre-commit-config.yaml`.
3. In the fixture, the maintainer runs
   `pre-commit run --files docs/spec/architecture.dsl`. Pre-commit runs
   `agent_factory_hook-arch-lint`.
4. The maintainer runs `pre-commit run --files docs/arc42/05_building_block_view.md`.
   Pre-commit runs `agent_factory_hook-arch-lint` again.

## Demo Data

| Fixture                 | Content                                                                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `installed-1.3.3-hooks` | `installed-1.3.3` of ST-0330, with the factory hook block as the `1.3.3` template wrote it, and `docs/arc42/05_building_block_view.md` |

## Boundaries

- The factory owns the `agent_factory_hook-*` block. The update changes it
  without a separate question (DEC-17). The project's own hooks stay as they
  are.
- `files:` values come from the template, never from a path substitution.
- The diff question of `refresh_precommit_hooks` (BUG-0110) stays for updates
  that run no migration.
- Every old path in `merge-precommit-config` and its test goes.

## Affected Paths

- `packages/factory/scripts/merge-precommit-config` — existing; old paths
  removed; template values applied.
- `packages/factory/scripts/update-factory` — existing; `refresh_precommit_hooks`
  applies the block without a question when the update ran the migration.
- `tests/factory/test_merge_precommit_config.py` — existing; old paths removed.
- `tests/factory/test_update_factory.py` — existing; the hook integration case.

  appear for a reason outside this feature. Report the difference.
