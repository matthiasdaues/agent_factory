# Replace index-file templates and create interview guide

Strip the three index-file templates to top-level keys only — no second-level keys, no `null` placeholders, no `mode` field. Create a separate interview guide that structures VIRGIL's greenfield and brownfield conversations. See [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05).

**Priority:** must-have

## Demo

A developer opens `context-stack.yaml` template and sees only the top-level comment and no pre-defined second-level keys. VIRGIL reads `context-interview-guide.yaml` and finds a structured question set: what to ask, in what order, and what index file and concern each answer maps to. VIRGIL uses the guide to create project-specific second-level keys during the interview — only keys the operator confirms as relevant.

## Acceptance Criteria

- `context-stack.yaml` template contains only a top-level comment. No `mode` field, no second-level keys, no `null` placeholders.
- `context-workflow.yaml` template contains only a top-level comment. Same constraints.
- `context-governance.yaml` template contains only a top-level comment. Same constraints.
- `context-interview-guide.yaml` exists and contains a structured question set covering stack, workflow, and governance domains.
- The interview guide maps each question to the target index file and suggested key name.
- The interview guide maps each question to the reading-guide concern it belongs to.
- The interview guide is consumable by VIRGIL and capture-context without hardcoding field paths in those skills.

## Scope

**Status quo:** Templates carry `mode: primary`, second-level keys with `null` placeholders, and mode-related comments. The interview structure is embedded in `capture-context/SKILL.md` as a question-to-field mapping table.

**Adds:** Minimal templates. A standalone interview guide artifact.

**Out of scope:** Changes to capture-context skill prose (ST-0202). Skill path discovery rewrite (ST-0205).
