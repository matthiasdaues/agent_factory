# Create charter-testing.yaml template and Factory's own testing.yaml

Create the machine-readable template at `factory/rulebooks/templates/charter-testing.yaml` defining the schema by example (top-level command fields plus optional `layers` section with fidelity maps). Create Factory's own `docs/charter/testing.yaml` declaring its test commands, replacing the deleted `run-tests` script as Factory's own test declaration.

**Priority:** must-have

## Acceptance Criteria

- `factory/rulebooks/templates/charter-testing.yaml` exists with documented fields: `test_command` (required), `test_staged_command` (optional), `test_changed_command` (optional)
- The template includes the `layers` section schema defined by example, with `tool`, `infrastructure`, `entry_point`, `anti_patterns`, and `fidelity` fields
- Unused layers are omitted in the example, not set to null
- Layer names use the same vocabulary as `factory/rulebooks/conventions/testing-strategy.md`: `deterministic_linter`, `acceptance_test`, `contract_test`, `integration_test`, `e2e_smoke_test`
- `docs/charter/testing.yaml` declares `test_command: "uv run pytest --tb=short --quiet"` and `test_staged_command: "uv run pytest --tb=short --quiet"`
- Factory's gates resolve `test_command` from `docs/charter/testing.yaml` the same way any consumer project would
- Template is valid YAML with inline comments explaining each field

## Implementation Notes

- Fields are project-defined shell commands, not framework names
- The `fidelity` map per layer records what is real versus substituted in the test environment
- This story creates the foundation that ST-0149, ST-0150, and ST-0151 consume
