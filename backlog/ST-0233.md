# Document the two-pass test authoring model in testing-strategy.md convention

Add a section to the `testing-strategy.md` convention documenting the two-pass test authoring model — TDD contract tests first (pass 1), design-driven integration tests second (pass 2) — so that the rationale is available to agents and humans independently of the proposal.

**Priority:** should-have

## Demo

A developer (human or agent) reads `factory/rulebooks/conventions/testing-strategy.md`. After the existing "Three-layer model" and risk-class sections, a new "Two-pass test authoring" section explains: pass 1 is TDD from acceptance criteria (always runs), pass 2 is test-design for integration gaps (runs post-GREEN for non-`.feature` stories, skipped for `.feature`-governed stories). The section names the `test-design-pass` field values and their meaning. A new developer agent reads this section and understands when to invoke `test-design` and when to skip it, without reading the proposal.

## Acceptance Criteria

- The `testing-strategy.md` convention at `factory/rulebooks/conventions/testing-strategy.md` includes a section on the two-pass test authoring model (completion criterion 16).
- The section explains pass 1 (TDD from acceptance criteria) and pass 2 (test-design for integration gaps), when each runs, and the conditional skip for `.feature`-governed stories.
- The section names the `test-design-pass` field and its valid values (`done`, `skipped-feature-governed`) with their meaning.
- The section does not duplicate the full test-design skill procedure — it documents the model and rationale, referencing the skill for procedure details.
- The convention's version number increments to reflect the addition.

## Scope

**Status quo:** The `testing-strategy.md` convention at `packages/factory/rulebooks/conventions/testing-strategy.md` (v2.0.0) covers the three-layer test model (base/middle/top), risk classes (critical/standard/structural), the admit-a-test gate, and contract ownership principles. It does not describe when test authoring happens relative to implementation or the two-pass model. ST-0228 delivers the rewritten test-design skill; ST-0229 delivers the developer agent's two-pass workflow.

**Delivers:** A new section (after the existing content, before any appendix) titled "Two-pass test authoring" documenting the model, its rationale, the `test-design-pass` field, and the `.feature`-governed skip. Version bumps to 2.1.0 (additive, non-breaking).

**Out of scope:** Rewriting existing sections of testing-strategy.md. Changes to risk-class definitions or budget rules (unchanged by this proposal). The test-design skill procedure itself (documented in the skill, not the convention).

The convention at `packages/factory/rulebooks/conventions/testing-strategy.md` is currently ~200 lines. The new section should be 30-50 lines — concise enough for agents to parse, detailed enough for humans to understand the model without reading the proposal. Reference the `test-design` skill for procedure details and the `testability-probe` skill for the planning-time counterpart. The version in frontmatter changes from `2.0.0` to `2.1.0`.
