# Update developer-agent for charter and tests field

Update the developer-agent to read the charter before writing code and to respect the `tests:` field for pre-existing test workflows.

**Priority:** must-have

## Acceptance Criteria

- `developer-agent.md` `inputs:` includes `docs/charter/*.md`
- Agent workflow describes reading the charter to know what to install, how to run tests, and what conventions to follow
- When `tests:` field is present and non-empty on a story, the agent reads the listed test files as its specification and implements code to make them pass (Green phase only, no Red-Green)
- When `tests:` is absent or empty, the agent follows the default TDD workflow unchanged
- Epic 0 stories are implemented like any other story — no special handling needed beyond what the charter provides

## Implementation Notes

The charter replaces the guessing and re-asking that happens today when a developer-agent starts coding without knowing the linter, test runner, or repo layout. The `tests:` field is the mechanism for the house-rules mandate "test cases written manually before code."

## Analysis

Updated `factory/agents/developer-agent.md` to:

1. Added `docs/charter/*.md` to the `inputs:` section so the agent reads the charter when starting.
2. Enhanced the **Analyse** step to explicitly read the charter to learn installation, test-running, and convention details.
3. Enhanced the **Agree seams** step to check for the story's `tests:` field and use it as specification if present.
4. Enhanced the **Red-Green-Refactor** step to:
   - When `tests:` is present and non-empty, skip the Red phase and go straight to Green (implement code to pass the pre-written tests).
   - When `tests:` is absent or empty, follow the full Red-Green-Refactor cycle.
5. Added a new "Note: Epic 0 Stories" section clarifying that Epic 0 stories follow the standard workflow with no special handling.

All changes maintain backward compatibility — existing stories without a `tests:` field continue to use the full TDD cycle.
