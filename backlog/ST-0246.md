# Expose raw snapshots, latest-run snapshots, dimensional totals, and cache signals as stable views

Deliver the remaining four published DuckDB views to complete the six-view query surface.

**Priority:** must-have

## Goal

After this story ships, the operator runs `usage-query usage_by_dimension --dimensions cli,project --granularity day` and sees each total equal the additive sum of canonical session rows. Omitting dimensions defaults to one all-input total. Duplicate or unsupported dimensions are rejected. Running `usage-query cache_efficiency` preserves null and input-only cache fields without coercing them to zero. Running `usage-query raw_usage_snapshots` and `latest_run_snapshots` returns all valid snapshots and one canonical snapshot per logical run.

## Domain Rule

- Dimensional totals equal the additive sum of canonical session rows.
- Omitted dimensions default to one all-input total for non-empty input.
- Duplicate or unsupported dimensions are rejected.
- A time dimension with granularity `none` is rejected.
- Time granularity options: `none`, `hour`, `day`, `week`, `month`.
- Cache signals preserve null and input-only states. Unavailable values are never coerced to zero.
- `raw_usage_snapshots` returns all valid snapshots with their evidence identity.
- `latest_run_snapshots` returns one canonical snapshot per logical run using deterministic evidence identity.

## Demo Scenario

1. Run `usage-query usage_by_dimension --usage-dir fixtures/multi-cli/ --dimensions cli,project --granularity day`. Verify each total equals the additive sum of canonical session rows.
2. Run `usage-query usage_by_dimension --usage-dir fixtures/multi-cli/` with no dimensions or granularity. Verify one all-input total.
3. Run `usage-query usage_by_dimension --dimensions cli,cli`. Verify duplicate dimensions are rejected.
4. Run `usage-query usage_by_dimension --dimensions time --granularity none`. Verify it is rejected.
5. Run `usage-query cache_efficiency --usage-dir fixtures/multi-cli/`. Verify null and input-only cache fields are preserved, not coerced to zero.
6. Run `usage-query raw_usage_snapshots --usage-dir fixtures/multi-cli/`. Verify all valid snapshots appear with evidence identity.
7. Run `usage-query latest_run_snapshots --usage-dir fixtures/multi-cli/`. Verify one canonical snapshot per logical run.

## Outputs

- `packages/usage/src/usage/views/raw_usage_snapshots.py` — DuckDB view returning all valid snapshots from the preflight valid relation with evidence identity columns (source path, line number, capture sequence).
- `packages/usage/src/usage/views/latest_run_snapshots.py` — DuckDB view returning one canonical snapshot per logical run using the deterministic evidence identity from ST-0245.
- `packages/usage/src/usage/views/usage_by_dimension.py` — DuckDB view accepting an ordered dimension list and time granularity. Groups canonical session rows by the selected dimensions. Validates: rejects duplicate dimensions, unsupported dimension names, and time dimension with granularity `none`. Omitted dimensions default to one all-input total.
- `packages/usage/src/usage/views/cache_efficiency.py` — DuckDB view reporting cache fields per session. Preserves null (unavailable) and input-only states without coercing to zero.
- `packages/usage/src/usage/cli.py` gains `--dimensions` (comma-separated ordered list) and `--granularity` (none|hour|day|week|month) arguments, and routes for all four new views.

## Constraints

- Dimensional totals must be mathematically verifiable as the additive sum of canonical session rows.
- No dimension or granularity validation changes the SQL accounting model.
- Cache null preservation is a column-level property, not a post-processing step.
- Do not duplicate conservation-rule SQL from ST-0245.
