# Fold the context map into the agent context file

**Priority:** must-have

## Goal

The project maintainer runs `capture-context --fold-context-map` and gets one
domain concern in `docs/agent-context.md` per context of the context map and
per routing-only `CONTEXT.md`. Each folded concern carries a mark that
`concern-lint` checks, and every Markdown link under `docs/` to a
`CONTEXT.md` or to `CONTEXT-MAP.md` points at `docs/agent-context.md`.

## Domain Rule

- `docs/agent-context.md` is the project's one routing file (DEC-07).
- A folded concern is a domain concern. Its `Read:` paths pass `concern-lint`
  `CTX-PATHS`, and it also routes to `docs/spec/glossary.md`.
- The fold never deletes `CONTEXT-MAP.md` or a `CONTEXT.md`. The developer
  deletes them after the review.
- A `CONTEXT.md` with a `## Language` section is not routing-only. The fold
  skips it; `migrate-spec-layout` removes its terms first (ST-0324).
- The fold mark is valid only under `## Domain concerns`.

## Outputs

- **Skill text.** `capture-context/SKILL.md` gains a section
  `## --fold-context-map` with its steps: guard, read the map and the
  routing-only `CONTEXT.md` files, propose one concern per context, review with
  the developer, write, rewrite links, run `concern-lint`, and name the
  deletion of the old files as the developer's next step. The invocation table
  lists the mode. Every other old path in the skill moves to the new layout.
- **Mark check.** `concern-lint` accepts the fold mark under a domain concern
  and reports `CTX-SECTIONS` as an error for a malformed mark or a mark outside
  `## Domain concerns`.
- **Template.** `rulebooks/templates/context-map.md` is removed, and no factory
  file links to it.
- **Contracts.** `interface-contracts.md` § `capture-context --fold-context-map`
  records the mark (CAL-G03), the guard, and the review order (CAL-G14).
  `entity-model.md` § Agent Context Entities names the mark's form.

## Demo Scenario

1. The maintainer opens the fixture `folding-project` (Demo Data) in a session
   and runs `capture-context --fold-context-map`.
2. The skill shows three proposed domain concerns, "Billing", "Ledger", and
   "Shipping", and asks for confirmation.
3. After the confirmation, `docs/agent-context.md` holds the three concerns,
   each with the fold mark, and `packages/factory/scripts/concern-lint` passes.
4. `docs/arc42/concepts.md` and `docs/reviews/2026-10-01-review.md` link to
   `docs/agent-context.md`.
5. The maintainer deletes `docs/CONTEXT.md` and `docs/arc42/CONTEXT-MAP.md` and
   runs `packages/factory/scripts/link-check` on every Markdown file under
   `docs/`. It passes.

## Boundaries

- Source edits go to `packages/factory/`, never to `.agent-factory/`.
- The mode runs in the orchestrating session with the developer present, like
  every mode of the skill.
- The fold section of `capture-context` is the only place in `packages/factory/`
  that may name `CONTEXT.md` or `CONTEXT-MAP.md` after E9 (CAL-13-LN-02).
- `concern-lint` stays read-only.

## Out of Scope

- The rescan rule for folded concerns (ST-0329).
- The fold on the factory's own repository (ST-0344).
- Moving terms out of `CONTEXT.md` (ST-0324).

## Agent Stop Conditions

- The fold mark cannot pass `CTX-SECTIONS` without a change to the section
  grammar that other concerns rely on. Report the grammar conflict.
- The skill's existing modes and the contract disagree on where the developer
  confirms. Report both.

## Resolve Before Implementation

1. CAL-G03, the fold mark. Default: a line `Folded: yes` directly after the
   concern's description line. `concern-lint` accepts it only under
   `## Domain concerns` and only with the value `yes`.
2. CAL-G14, missing `docs/agent-context.md`. Default: the mode stops and names
   `capture-context --init` as the first step.
3. CAL-G14, review order. Default: the skill shows the proposed concerns and
   link rewrites, writes them after the developer confirms, then shows the
   `concern-lint` result.
