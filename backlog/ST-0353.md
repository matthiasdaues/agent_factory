# Own the dependency rules and report state-machine contradictions

**Priority:** must-have

## Goal

The architecture agent declares `docs/spec/dependency-rules.dsl` with its review and writes no `state-machines.md`. When its components contradict the state machines, it files an `ARCH` finding for the domain-modeling agent. It can build the baseline before the domain structure exists.

## Contract

| Operation                         | Input state                                  | Outcome                                                                                           | Persistence               |
| --------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------- |
| Read the outputs                  | After this story                             | `dependency-rules.dsl` with `reviewed_by: [architecture-review-agent]`; `docs/findings/ARCH-*.md` | —                         |
| Read the context inputs           | After this story                             | `entity-model.md`, `state-machines.md`                                                            | —                         |
| `intent select`                   | Feature file, no `entity-model.md`           | Architecture agent eligible                                                                       | None                      |
| `intent select`                   | Its outputs exist; `entity-model.md` changed | Its step counts as done; nothing restarts it                                                      | None                      |
| Step 5 of `maintain-architecture` | No `state-machines.md`                       | Step skipped                                                                                      | None                      |
| Step 5                            | A component contradicts `state-machines.md`  | `ARCH` finding with `owner: domain-modeling-agent`                                                | `docs/findings/ARCH-*.md` |
| Step 5                            | Any input                                    | No write to `state-machines.md`                                                                   | None                      |

## Demo Scenario

1. The architect builds the fixture `feature-no-entities` (Demo Data) and runs `packages/factory/scripts/intent select`. The architecture agent is eligible.
2. The architect reads Step 5 of `maintain-architecture`. It compares components with `state-machines.md` and files an `ARCH` finding with `owner: domain-modeling-agent` on a contradiction.
3. Demo exception: the stakeholder accepted the contract test as this step's interface (2026-11-04). The architect runs `pre-commit run run-tests --all-files` (the `run-tests` hook or `validate`, never `pytest` directly, BR-024). It passes, and `docs/spec/dependency-rules.dsl` is no longer on the expected-failure list.

## Analysis

The story changes four instruction files and adds two test classes. No script changes.

- `packages/factory/agents/architecture-agent.md` gains two outputs: `docs/spec/dependency-rules.dsl` with `required: false` and `reviewed_by: [architecture-review-agent]`, and `docs/findings/ARCH-*.md` with `required: false`. It gains two context inputs: `docs/spec/entity-model.md` and `docs/spec/state-machines.md`. Workflow step 4 runs the read check instead of writing state machines.
- `packages/factory/agents/architecture-review-agent.md` gains `docs/spec/dependency-rules.dsl` as a context input. The reviewer check of `index-lint` needs it (CAO-G01).
- `packages/factory/skills/maintain-architecture/SKILL.md` turns Step 5 into a read check. Without `state-machines.md` the step is skipped. A contradiction becomes an `ARCH` finding with `owner: domain-modeling-agent`. The step never writes `state-machines.md`.
- `packages/factory/skills/run-step/SKILL.md` states the done rule: a step is done once its outputs exist, and a changed input never restarts it.
- `packages/factory/rulebooks/core-artifacts.yaml` already marks `dependency-rules.dsl` as `optional: true` since ST-0346. It needs no change.
- `tests/factory/test_core_artifact_ownership.py` drops `docs/spec/dependency-rules.dsl` from `EXPECTED_FAILURES`.
- `tests/factory/test_core_artifact_ownership_text.py` gets the text check CAO-07-LN-01.
- `tests/factory/test_intent_select.py` gets the fixtures `feature-no-entities` and `entities-changed` for CAO-07-IT-02. ST-0348 and ST-0357 put their eligibility tests there too.

Scenarios covered: the four Scenarios of the Rule "Architecture agent owns the components and their dependency rules" except the `dependency-check` owner Scenario (ST-0355).

Concern: `intent select` reports eligibility only. It has no notion of "done". The test for `entities-changed` therefore checks two things: every required output of the agent exists, which is the done rule of `run-step`, and the output of `intent select` does not change when `entity-model.md` appears. A spec-feedback row records the wording.
