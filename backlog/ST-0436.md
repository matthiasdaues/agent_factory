# Get a CRAP verdict on the changed functions of a story

`crap-score` judges only the functions a story changed, from the rows of the project's measuring commands, in any language.

**Priority:** must-have

## Goal

`crap-score --base feature/login` judges only the functions whose lines the story changed and exits 1 with the file, function and score of each one above the threshold. `crap-score --all` judges every measured function. The gate exits 2 when its settings are missing or a measuring command fails, and it holds no language-specific code.

## Domain Rule

- The call is `crap-score (--base <revision> | --all) [--story-id <id>] [--report-dir <folder>]`. Neither or both of `--base` and `--all` make it exit 2 and name the two arguments before it reads a setting (BR-127, DEC-16). `--base` takes a branch or a commit (DEC-42).
- The settings come from `gates.crap-score` in `docs/testing.yaml` of the folder the gate runs in, each run, whatever `enabled` says. `threshold`, `timeout_minutes` and `measures` are required, and each measure needs `name`, `files` and `command`. A missing value, an empty list, or two measures with one name make it exit 2 and name the cause (BR-128). The old key `crap_score` is still read; with both keys, the key with hyphens wins with a warning.
- The measures run in list order, each command from the root of the folder with its own `GATE_OUTPUT`. A measuring command that exits non-zero makes the gate exit 2 and name the measure, the command and its message; no later measure starts (BR-129).
- Only rows whose `file` matches the measure's `files` and no `exclude` pattern count. `*` matches within one path segment, `**` any number of segments (BR-131, DEC-35).
- A function is judged when its range holds a changed or deleted line of the diff from the merge base of `--base` to `HEAD`. A deletion between two functions counts for both (DEC-29, DEC-37). A `parse_error` row for a changed file fails and names the file and the message (DEC-34).
- The score is `complexity² × (1 − coverage_pct/100)³ + complexity`, rounded to two decimals, half up. A function passes when its rounded score is at or below the threshold (DEC-36).
- Exit 0 when every judged function passes, also when none is judged; exit 1 when one fails; exit 2 when the gate cannot measure (BR-133).
- On exit 0 or 1, the report `<report-dir>/<story-id>.json` holds the measurement fields plus `crap_score` and `pass_fail`, and replaces an earlier one. The default folder is `.current-work/crap-score/`. On exit 2, no report is written. The story ID comes from `--story-id`, then `STORY_ID`, then the ID in `story/ST-0350` or `story/BUG-0090`, then `adhoc`, and never holds a slash (DEC-27).
- `crap-score` imports no `radon` and no coverage module and holds no file pattern of a language.

## Demo Scenario

1. A temporary repository has `dev`, `feature/login` and `story/ST-0350`. Its committed `docs/testing.yaml` holds `gates.crap-score` with `threshold: 8`, `timeout_minutes: 10`, and the measure `python` with `files: "packages/factory/scripts/*"` and a stub command that copies planted rows.
2. On `story/ST-0350`, `tree_severity` in `packages/factory/scripts/finding-lint` changes and its planted row scores 9. `bug_bar_level` in the same file also scores 9 and does not change.
3. The User runs `crap-score --base feature/login --story-id ST-0350`. It exits 1 and names `packages/factory/scripts/finding-lint`, `tree_severity` and `9.00`. It does not name `bug_bar_level`.
4. `.current-work/crap-score/ST-0350.json` holds the row of `tree_severity` with `crap_score` 9.0 and `pass_fail` `fail`.
5. The User runs `crap-score --all --story-id ST-0350`. It exits 1 and names both functions.
6. The stub exits 1. `crap-score --base feature/login` exits 2, names `python` and the stub's message, and the report of step 4 stays unchanged.

## Analysis

- **What changes.** `packages/factory/scripts/crap-score` is rewritten in place. It reads `gates.crap-score` of `docs/testing.yaml` in the current folder, runs each measuring command with its own `GATE_OUTPUT`, keeps the rows that match `files` and no `exclude`, and judges the kept rows. With `--base`, it judges only the functions that `git diff -U0 <merge base> HEAD` touches. It reuses `glob_match` of `dispatch_lib`, the one glob dialect of the scripts folder (DEC-35). It computes the score in `Decimal`, so 8.125 rounds half up to 8.13 (DEC-36).
- **Deletion between two functions.** A deletion lies between two new lines. When both lines lie in one function's range, that function counts. Otherwise the nearest function above and the nearest function below count, when both exist (DEC-37). A deletion above the first or below the last function of a file counts for no function, because BR-131 names only the case between two functions. This edge case becomes a row of the spec-feedback report.
- **Kept out.** The shape check and the duplicate checks (ST-0437), `ready` commands, the time limit and the lock (ST-0438), and the register (ST-0440) stay out. A row without a field the judging needs gives exit 2, so a traceback never gives exit 1.
- **Tests.** Contract tests in `test_crap_gate_judging.py` cover CG-04-CT-01, -02, -03, -05, -06, -08, -09. `test_crap_score.py` becomes the rewritten CG-04-CT-05 class of the old key. Integration tests in `test_crap_gate_score.py` cover CG-04-IT-01 to -05, -07, -09 to -12 on temporary repositories with a stub that copies planted rows. `test_crap_gate_text.py` gains CG-03-LN-03, CG-12-LN-01 and CG-12-LN-04.
- **Deleted.** The `crap-score` tests of `test_quality_metrics.py` and the fixture `high-crap/`, which no other test uses; the class `TestSt0415CrapScoreScoresTheDiff` of `test_premerge_check.py`.
