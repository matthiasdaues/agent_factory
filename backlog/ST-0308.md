# Begin every YAML file the factory writes with ---

**Priority:** must-have

## Goal

Fix the findings of cluster `yaml-document-start` in the [bug-hunt fix run](../docs/reviews/bug-hunt-2026-10-15-fix-run.md).

## Rule

The stakeholder decided on 2026-10-15 that every YAML file begins with the
document marker `---`. This repository already enforces it with
`yamllint`. The gap lies in what the factory writes into other projects:
`init-factory` writes `docs/testing.yaml` without the marker, and the
format example in `packages/factory/skills/detect-test-regime/SKILL.md`
lacks it, so agents copy the gap.

## Scope

1. State the rule in the conventions: every YAML file the factory creates,
   and every YAML example it gives agents, begins with `---`.
2. Add a test that runs every factory writer that produces YAML and
   extracts every YAML example from skills and templates. The first line
   that is not a comment must be `---`.
3. Fix each gap the test finds. A file that belongs to the developer, such
   as an existing `.pre-commit-config.yaml`, stays untouched.

Out of scope: enforcing the marker inside consumer projects, and the two
legacy fixtures under `tests/fixtures/concern-lint/`.

## Acceptance criteria

- The new test fails on the code before this story and passes after it.
- New tests go into `tests/factory/test_yaml_document_start.py`, unless a test file
  for the changed script already exists.
- The full suite passes with `pre-commit run run-tests --all-files`.
- Commits name the story, as `fix: <what changed> (ST-0308)`.
- No file outside the list below changes, except tests and the
  documentation of a changed script. Nothing under `.agent-factory/`
  changes.
- The final report names each fix in one or two sentences, the test that
  proves it, and any finding that turned out wrong or needs a decision.
