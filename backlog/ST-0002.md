# Write docs/CONTEXT-MAP.md for the multi-context repo

This repo is multi-context, and root-level `docs/` is the confirmed home
for whole-repo, cross-cutting topics spanning all of them — distinct from
each subproject's own nested docs. Per
`factory/rulebooks/conventions/context-format.md`, a multi-context repo
needs a `CONTEXT-MAP.md` listing the contexts and how they relate, instead
of a single flat `CONTEXT.md`, and this project's own convention is
`docs/CONTEXT.md` rather than a bare root `CONTEXT.md` — so the map lives
at `docs/CONTEXT-MAP.md` to match. Three contexts, three rows:

- **orchestrator** — the Python CLI, real content already in place:
  `orchestrator/docs/adr/` and `orchestrator/CONTEXT.md`.
- **factory** — the agent/skill/playbook system, dynamically run by an AI
  CLI. Real architecture exists (building blocks = agents, skills, gates;
  runtime view = phase handoffs) but nobody has written it up yet —
  created lazily, per this repo's own convention, not this story's job.
- **factory_api** — a future subproject, no docs and no code yet: the
  vision is an API server connecting `run-step`/`run-phase` invocations to
  a web interface via message piping. Not scheduled — a stub row only, so
  the map stays honest about what's coming.

Depends on orchestrator's ST-0062 (move top-level `docs/` back into
`orchestrator/docs/`) being done first, tracked informally since
`backlog-lint` validates `deps:` referential integrity per-directory —
root `backlog/` and `orchestrator/backlog/` are independent lint passes,
so this cannot be a formal `deps:` entry pointing across directories.

**Priority:** should-have

## Acceptance Criteria

- `docs/CONTEXT-MAP.md` follows the `context-format.md` structure: a
  `## Contexts` section listing each bounded context with a one-line
  description and a link to its glossary/docs.
- The **orchestrator** row links to `orchestrator/CONTEXT.md` and
  `orchestrator/docs/adr/`.
- The **factory** row notes it has no docs yet — created lazily, not this
  story's job to write them — rather than a broken link or empty section.
- The **factory_api** row notes it is a future subproject (API server
  connecting `run-step`/`run-phase` to a web interface via message piping)
  with no docs and no code yet — a stub entry, not a broken link.
- A `## Relationships` section (or an explicit note that none exist yet
  beyond each context being independent) states how the three contexts
  relate, per the `context-format.md` template.
- The file lives at `docs/CONTEXT-MAP.md`, matching this repo's
  `docs/CONTEXT.md`-not-root-`CONTEXT.md` convention.
