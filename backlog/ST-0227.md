# Wire testability-probe into the create-backlog sequence and update planning-integration skills

Update three existing skills so the create-backlog sequence references the new `testability-probe` at phase 2.5 and story files receive ownership assignments instead of failure scenarios.

**Priority:** must-have

## Demo

The user reads the `create-backlog` parent skill's operational sequence table. Phase 2.5 shows `testability-probe` (mandatory) instead of `test-design` (optional). The user reads the `create-backlog-write-epics` skill's post-EPIC section — it says "Invoke testability-probe" and explains the mandatory probe step, not the old "Optional: Invoke test-design" section. The user runs `create-backlog-stories` against an `epics.md` that contains testability-probe output (ownership tables, no failure scenarios). Each story file receives ownership assignments in its Notes for the Implementer — no `#### Failure scenarios` or `#### Prior Tests` sections appear.

## Acceptance Criteria

- The `create-backlog` parent skill's sequence table at `factory/skills/create-backlog/SKILL.md` references `testability-probe` at phase 2.5 instead of `test-design`, and marks it as mandatory (completion criterion 13).
- The `create-backlog-write-epics` skill at `factory/skills/create-backlog-write-epics/SKILL.md` surfaces the `testability-probe` step instead of the `test-design` option before the user proceeds to story slicing (completion criterion 14).
- The `create-backlog-stories` skill at `factory/skills/create-backlog-stories/SKILL.md` carries ownership assignments from `epics.md` into story files and does not carry `#### Failure scenarios` or `#### Prior Tests` sections for new stories (completion criterion 15).
- The `create-backlog-stories` skill's test-design carry-forward logic distinguishes probe output (ownership tables) from old test-design output (failure scenarios) and handles both.

## Scope

**Status quo:** The `create-backlog` parent skill's sequence table (line 28 of `packages/factory/skills/create-backlog/SKILL.md`) lists `test-design` at phase 2.5, marked "(optional)". The `create-backlog-write-epics` skill ends with an "Optional: Invoke test-design" section. The `create-backlog-stories` skill's carry-forward logic looks for `tests:`, `#### Failure scenarios`, and `#### Prior Tests` sections from test-design output. ST-0226 delivers the `testability-probe` skill.

**Delivers:** The sequence table references `testability-probe` (mandatory). The write-epics skill's post-EPIC section references the probe. The stories skill carries ownership assignments and handles both probe output and legacy test-design output.

**Out of scope:** Creating the testability-probe skill itself (ST-0226 delivers that). Refactoring the test-design skill (ST-0228). Changes to backlog-lint validation rules (explicitly deferred).
