# Name next-id T at every step that adds a todo entry

**Priority:** must-have

## Goal

An agent that adds an entry to `docs/spec/work/todo.md`, such as a review that records an open question, claims its number with `next-id T` at that step. The text test finds every such file by its pointer to `todo-format.md` and fails for a todo writer without `next-id T`. A file that only links to `todo.md` needs no claim.

## Contract

| File under `packages/factory/`                 | State before the story                                                      | Rule after the story                                                      |
| ---------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `skills/create-backlog-make-concrete/SKILL.md` | Moves deferred questions to `todo.md` per `todo-format.md`, without a claim | The step names `next-id T` and keeps the pointer                          |
| `rulebooks/conventions/report-format.md`       | Records a question in `todo.md` per `todo-format.md`, without a claim       | The step names `next-id T` and keeps the pointer                          |
| `rulebooks/rules.md` § Todos                   | Links to `todo-format.md` above the rule to file every deferred question    | The rule names `next-id T`, because it tells every agent to file an entry |
| `rulebooks/templates/todo-entry.md`            | The template of one entry                                                   | Unchanged; the checker skips templates                                    |
| `skills/write-prd/SKILL.md`                    | Links to todo entries, no pointer to `todo-format.md`                       | Unchanged; no claim needed (CIF-15-LN-02)                                 |
| `rulebooks/conventions/id-prefixes.md`         | The `T` row of ST-0383                                                      | The `T` row lists every todo writer this story finds                      |

A step adds an entry when the sentence that points to `todo-format.md` tells the reader to write, record, file, or move an entry into `todo.md`.

## Demo Scenario

1. The User prepares the scratch project of Demo Data and opens an agent session in it.
2. The User asks the agent to run `create-backlog-make-concrete` on `backlog/ST-0001.md`, whose grilling deferred one question. The agent runs `next-id T`, which prints `T-0001`, and writes `## T-0001` into `docs/spec/work/todo.md` in the form of `todo-format.md`.
3. The User asks the agent to review `docs/spec/rules.md` and the review records one question. The agent runs `next-id T`, gets `T-0002`, and adds the entry.
4. The User opens `id-prefixes.md`. The `T` row lists `create-backlog-make-concrete`, `report-format.md`, `rules.md`, `retrospective`, and `todo-format.md`.

## Boundaries

- The checker finds a todo writer by its pointer to `todo-format.md` at a step that adds an entry, never by a mere link to `todo.md` (BR-107, CIF-G12).
- The checker skips `rulebooks/templates/` and `todo-format.md` itself, which ST-0384 already checks.
- The checker of ST-0383 gains the todo-writer case and fails, naming the file, for a writer without `next-id T` (CIFP-C13).
- Each claim tells the reader to read the ID from standard output and to stop and report the message when `next-id` fails.
- `docs/spec/work/todos.md` and its writers stay as they are (SPEC-0068, T-0008).
- The story regenerates `INDEX.yaml` in the same commit, and `index-lint --check` passes.
