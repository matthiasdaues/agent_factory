# Add batch-fix guidance to commit conventions

Amend commit-conventions.md so that developers know to address multiple failure modes in the same file with one commit rather than a series of incremental patches. Today no guidance exists; the observed pattern was six sequential commits to run-dev.sh, each fixing one symptom.

**Priority:** must-have

## Demo

1. Open `factory/rulebooks/conventions/commit-conventions.md` and locate the new "Batch Fix" subsection.
2. The subsection contains guidance: when multiple failure modes surface in the same file or script, read and understand the file as a whole before committing. Prefer one commit that addresses all known failure modes over a series of incremental patches.
3. The guidance explains the rationale: incremental symptom-chasing produces commits that are individually correct but collectively hard to review, bisect, and reason about.

## Acceptance Criteria

- commit-conventions.md contains a "Batch Fix" subsection under the "Project-Specific Rule" section (PROP-batch-fix)
- The subsection states the preference for one commit addressing all known failure modes in a file over incremental patches (PROP-batch-fix)
- The subsection includes the rationale that incremental symptom-chasing harms reviewability and bisectability (PROP-batch-fix)

## Scope

**Status quo:** commit-conventions.md covers conventional commit format, story/bug ID requirements, commit types, and version bump rules. No guidance on handling multiple failure modes in the same file.

**Adds:** Batch Fix subsection with guidance and rationale.

**Out of scope:** Mechanical enforcement of batch-fix patterns. Changes to any other convention document.
