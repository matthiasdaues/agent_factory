# Publish a project's documentation with one command

**Priority:** must-have

## Goal

A developer runs `.agent-factory/factory/scripts/publish-docs pdf` in a
project root and gets `docs/dist/<project>-architecture.pdf`, or no PDF and a
list of failed checks.

## Rule

The [publish-docs proposal](../docs/proposals/publish-docs.md#completion-criteria)
owns the completion criteria. This story wires all stages together and
proves them on a fixture project.

## Scope

1. `publish-docs pdf`: preflight, Structurizr validate and export into the
   build copy, the assemble step and the render image, then the PDF to
   `docs/dist/`. Exit codes 0, 1 and 2 as the proposal defines.
2. Build the render image on first use. `PUBLISH_DOCS_IMAGE` overrides it.
3. Add `docs/dist/` to the project's `.gitignore` when it is missing.
4. A fixture project with every rewrite case, one PNG, a stale committed SVG,
   an ADR with frontmatter and a project stylesheet case.
5. The `publish-docs` skill and its `INDEX.yaml` entry.

## Acceptance criteria

- `tests/factory/test_publish_docs.py` covers the completion criteria of the
  proposal on the fixture. A `requires_docker` marker skips it with a named
  reason when `docker info` fails.
- The full suite passes with `pre-commit run run-tests --all-files`.
- Commits name the story, as `feat: <what changed> (ST-0311)`.
