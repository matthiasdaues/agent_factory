# usage-capture CLI entrypoint

Wire the standalone entrypoint that every capture site invokes uniformly.
It parses the CLI arguments, selects the normalizer for `--cli`, runs the
transcript through the `cl100k_base` tokenizer, assembles the record, and
hands it to the logging adapter. One CLI-invokable command gives polyglot
callers — a Claude Code hook, a Pi extension, the orchestrator — one uniform
way in.

The whole path is best-effort: a capture error is logged to stderr and
swallowed, and the command exits zero, so measuring a run never changes what
is measured.

**Priority:** must-have

## Acceptance Criteria

- `factory/scripts/usage-capture` remains executable for exact-locked offline
  source tests; installed automatic capture uses the provisioned runtime
  launcher and performs no dependency resolution.
- It parses `--cli` and `--transcript` plus the context flags that populate
  the record (session, parent-session, depth, agent, skill, model, phase,
  playbook, story-id, loop-role, iteration, branch, base-commit, commit,
  exit-status).
- It composes the selected normalizer, the `cl100k_base` tokenizer, and the
  logging adapter to produce and persist exactly one record per call.
- An unknown `--cli` value is a best-effort no-op: it logs to stderr and
  exits zero rather than failing.
- The top level catches every exception, logs it to stderr, and exits zero
  so a capture failure never fails, blocks, or slows the measured run.
- The proposal's example invocation runs against a fixture transcript and
  appends a well-formed record with a persisted transcript copy.

## Analysis

Traces to "The Capture Tool", "Core Principles", and "Completion Criteria"
in `factory/docs/proposals/token-usage-tracking.md`. This slice is pure
composition over ST-0035/36/37's already-tested seams — no new domain
logic, only the wiring the proposal's example invocation names:

- `_build_arg_parser()` — argparse parser for `--cli`/`--transcript` plus
  every context flag the AC lists, `dest=`-mapped onto the matching
  `UsageRecord` field name (`--parent-session` -> `parent_session_id`,
  `--story-id` -> `story_id`, `--commit` -> `commit_id`, etc.).
- `_capture()` — one pass: `get_normalizer(args.cli).parse(...)` ->
  `count_tokens()` over `input_text`/`output_text` -> one `UsageRecord` ->
  `JsonlLoggingAdapter(base_dir).record(...)`. Raises upstream of
  persistence (unknown cli, unreadable transcript); `JsonlLoggingAdapter`
  already swallows its own persistence failures (ST-0036).
- `_main()` — the best-effort boundary: preserves the `--count-tokens`/
  `--normalize` dev seams unchanged, then wraps arg-parsing (including
  argparse's own `SystemExit` on a missing required flag) and `_capture()`
  in `try`/`except`, always returning 0 and logging failures to stderr.
  An unknown `--cli` funnels through the same boundary via
  `get_normalizer`'s existing `ValueError` — no separate check needed.

One correctness gap surfaced during implementation, not previously
specified: `RecordIdSequencer` counters are process-local, but this CLI is
a new process per invocation (one capture per Stop/SubagentStop event,
many events per real session). An unseeded sequencer would assign
`<session>-0001` on every single call, silently overwriting the previous
call's persisted transcript copy. Fixed by adding `RecordIdSequencer.seed()`
(additive, does not change ST-0035's tested `next_id()` contract) and
`_next_record_id()`, which seeds the counter from however many lines
already exist in the session's own JSONL file before assigning the next
id. Covered by
`TestCliEntrypointHappyPath.test_repeated_invocations_same_session_do_not_collide_record_ids`.
This is the proposal's own "Open Questions" item ("confirm the exact
`record_id` scheme") resolved toward session-sequence-seeded-from-disk,
consistent with the session-sequence-with-UUID-fallback scheme ST-0035
already chose.

No `--base-dir` flag was added (out of scope: not in the AC's flag list);
the CLI persists under `.agent-factory/usage/` relative to its own cwd,
matching `JsonlLoggingAdapter`'s existing default.
