# usage-capture CLI entrypoint

Wire the standalone entrypoint that every capture site invokes uniformly.
It parses the CLI arguments, selects the normalizer for `--cli`, runs the
transcript through the `cl100k_base` tokenizer, assembles the record, and
hands it to the logging adapter. One CLI-invokable command gives polyglot
callers — a Claude Code hook, a Pi extension, the orchestrator — one uniform
way in.

The whole path is best-effort: a capture error is logged to stderr and
swallowed, and the command exits zero, so measuring a run never changes what
is measured.

**Priority:** must-have

## Acceptance Criteria

- `factory/scripts/usage-capture` is executable and self-bootstrapping via
  its PEP 723 shebang, matching `index-lint` and `schema-validate`.
- It parses `--cli` and `--transcript` plus the context flags that populate
  the record (session, parent-session, depth, agent, skill, model, phase,
  playbook, story-id, loop-role, iteration, branch, base-commit, commit,
  exit-status).
- It composes the selected normalizer, the `cl100k_base` tokenizer, and the
  logging adapter to produce and persist exactly one record per call.
- An unknown `--cli` value is a best-effort no-op: it logs to stderr and
  exits zero rather than failing.
- The top level catches every exception, logs it to stderr, and exits zero
  so a capture failure never fails, blocks, or slows the measured run.
- The proposal's example invocation runs against a fixture transcript and
  appends a well-formed record with a persisted transcript copy.
