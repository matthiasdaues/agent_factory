# End a finished or dropped run with dispatch close

**Priority:** must-have

## Goal

After `dispatch close`, the ledger, the worktrees, the gate results, the markers and the briefs of the run are gone, and its merged branches are deleted. Untracked files of each worktree are in a named stash, and the close lists each stash and each unmerged branch. `dispatch close --drop` ends a run whose unfinished stories are returned.

## Domain Rule

- `close` and `close --drop` refuse while a unit of work is `failed` or `blocked`, and name it. They accept a run whose units of work are `done` or `pending` (BR-119).
- `close` refuses a feature branch that is not merged into `dev`; `--drop` needs no merge.
- Before it removes a worktree, `close` stashes its untracked files under a name such as `run feature/login ST-0350 2026-11-24`, and does not put them back.
- It removes the ledger, the story and feature worktrees, the temporary premerge worktrees, the gate results of the run's stories under `.current-work/`, the `premerge-check-ok` and `verify-base-ok` markers, and the briefs under `.current-work/<feature-branch>/`.
- It deletes merged branches with `git branch -d` and lists unmerged ones. A stop allows `close`, because it starts and merges nothing.
- After the close, the record of the run is the merge commits in `dev` and the `done` status in each story file.

## Outputs

- The subcommand `close` with `--drop`.
- `dispatch-contract.md` describes the close.
- An end-to-end test of a run by hand from `init` to `close`.

## Demo Scenario

1. The User merges `feature/login` into `dev` and runs `dispatch close`.
2. `ls .current-work/feature/login` fails, `git worktree list` shows only the primary checkout, and `git branch` no longer lists `story/ST-0350`.
3. The output lists `run feature/login ST-0350 2026-11-24` and the unmerged branch `story/ST-0351`. `git stash list` shows that stash.
4. In a second run with ST-0360 `failed`, `dispatch close --drop` refuses and names ST-0360. After `return-story ST-0360`, it passes.

## Demo Data

None. The tests build a run with ST-0350 `done` and an untracked `notes.txt` in its worktree, and ST-0351 `pending` on an unmerged branch.

## Boundaries

- `close` never deletes an unmerged branch or drops a stash.
- `close` closes a ledger with the old names `invocation_branch` and `mode: automated`.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.

## Analysis

`dispatch close` and `dispatch close --drop` are new. The subcommand `cmd_close` goes into `packages/factory/scripts/dispatch`. Two pure helpers go into `dispatch_lib.py`: `close_refusals`, which names each unit of work that blocks the close, and `stash_name`, which builds the stash name of BR-119. `close` joins `READ_SUBCOMMANDS`, so a stop allows it (BR-091).

The close runs in this order, and every git command runs with `-C` on the primary checkout or on the worktree it acts on:

1. Load the ledger. Refuse each unit of work that is not `done` or `pending`, and name it with its state. Without `--drop`, refuse a feature branch that is not an ancestor of `dev`, and name `dispatch close --drop`. A refusal changes nothing.
2. Collect the worktrees of the run: the worktree of each entry's `branch` or `worktree`, each registered worktree under `.current-work/<feature-branch>/premerge/`, and the worktree of the feature branch. A worktree is taken only when git lists it, it lies under `.current-work/` of the primary checkout, and it is not the primary checkout.
3. For each worktree with a change, run `git stash push --include-untracked -m "run <feature-branch> <label> <date>"`. The label is the story ID, `premerge/<id>` for a premerge worktree, and `feature` for the worktree of the feature branch. Then run `git worktree remove` without `--force`. A failed stash or a failed removal stops the close with exit `1` and keeps the ledger.
4. Remove the ledger, the `premerge-check-ok` marker of the primary checkout when its `branch=` line names a branch of the run, and `verify-base-ok` of the primary checkout for a run by hand.
5. Remove `.current-work/<gate>/<id>.json` of the primary checkout for each unit of work of the ledger.
6. Remove `.current-work/<feature-branch>/` when no registered worktree is left under it.
7. Run `git branch -d` on each story branch of the ledger and on the feature branch. List each branch that git keeps as unmerged.
8. Print each stash and each unmerged branch.

Concerns:

- BR-119 accepts `done` and `pending` and refuses `failed` and `blocked`. It does not name `prepared`, `dispatching` and `dispatched`. The close refuses them too, because their worktrees hold work in progress. This goes into the spec-feedback report.
- BR-119 names the stash of a story worktree only. The labels `feature` and `premerge/<id>` are a choice of this story and go into the report.
- The section Close of `dispatch-contract.md` describes an older close with a forced branch delete and an `abandonment:` entry. This story replaces the section.
- The stop condition on tracked changes does not hold: BR-119 and the `close` entry of `interface-contracts.md` put tracked changes into the same stash.
