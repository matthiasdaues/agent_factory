# Let scope-lint find the workstream IDs in a linked worktree

**Priority:** must-have

## Goal

An agent working in a dispatch worktree declares a known workstream as the
scope of a file. `scope-lint` accepts it, as it would in the main checkout.

## Findings

- [BUG-0095](../docs/findings/BUG-0095.md): `scope-lint` syntax is
  inconsistent and fails in worktrees. This story fixes the worktree part;
  ST-0317 fixes the syntax.

## Acceptance criteria

- When `.agent-factory/workstreams/` is missing under `--base-dir`,
  `scope-lint` reads the workstream IDs from the main checkout, found through
  `git rev-parse --git-common-dir`, the way `concern-lint`'s
  `_main_checkout` already does.
- A test runs `scope-lint` in a linked worktree with a known workstream ID
  and sees it pass; before this story only `global` passed.
- Outside a git repository, or when the main checkout has no workstreams,
  the behavior stays as it is.
- The new test fails on the code before this story and passes after it.
- The full suite passes with `pre-commit run run-tests --all-files`.
- Commits name the finding, `fix: <what changed> (BUG-0095)`.
- No file outside the list below changes. Nothing under `.agent-factory/`
  changes.
