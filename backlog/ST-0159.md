# Fix origin/HEAD symref during init-factory setup

Add a `fix_origin_head()` function to `factory/scripts/init-factory` that detects and repairs a dangling `origin/HEAD` symref. Call it from `main()` immediately after the existing `ensure_git()` call (line 2161). The function prevents tools that rely on `origin/HEAD` from failing silently when the symref points to a nonexistent ref (e.g. `origin/master` when only `origin/main` exists).

**Priority:** should-have

## Acceptance Criteria

- A new function `fix_origin_head()` exists in `factory/scripts/init-factory`
- `main()` calls `fix_origin_head()` immediately after `ensure_git()` (after line 2161)
- When `origin/HEAD` exists and points to a valid ref, the function is a no-op
- When `origin/HEAD` is dangling, the function attempts `git remote set-head origin --auto`
- When network is unavailable, the function falls back to scanning local `refs/remotes/origin/*` for `main` or `master` and sets the symref locally
- The function tolerates all failures gracefully (best-effort repair, never aborts init)
- A test file `tests/orchestrator/test_init_factory_origin_head.py` covers all three paths: valid symref, auto-repair via network, and offline fallback

## Implementation Notes

- The retro recorded 25 minutes lost to 3 QA agent failures caused by this issue in the test-gate-presence campaign
- The offline fallback should prefer `main` over `master` when both exist locally
- Tier is standard per dispatch-contract tier rubric: script logic with branching fallback paths

## Analysis

`traces: []` — no UC-XX or `.feature` file governs this story; it is a
self-contained fix against `factory/scripts/init-factory`, so the story text
above is the acceptance spec.

**Seam.** `fix_origin_head(target: Path, report: list[str]) -> None`, added
next to `ensure_git()` and called from `main()` right after it (before
`copy_factory`). Same signature shape as the other `main()` steps
(`target`, `report`), so it composes with the existing `try/except Collision`
wrapper in `main()` without changing that wrapper's contract.

**Repair order**, mirroring the acceptance criteria: (1) `git rev-parse --verify -q refs/remotes/origin/HEAD` decides valid vs. dangling; (2) on
dangling, try `git remote set-head origin --auto`; (3) on that failing
(no network, unreachable remote, or no `origin` at all), scan
`git for-each-ref refs/remotes/origin/` locally and `git symbolic-ref` the
first of `main`, `master` found. All `subprocess.run(..., check=False)`,
wrapped in one `except OSError` so a missing `git` binary or other OS-level
failure degrades to a logged skip rather than aborting `main()` — matching
the "tolerates all failures gracefully" acceptance criterion and the
existing tolerant-failure style used elsewhere in this file (e.g.
`provision_usage_runtime`'s `except OSError as exc` at line ~2060).

**Tests** (`tests/orchestrator/test_init_factory_origin_head.py`) build real
bare-origin + clone git repos per case (same Chicago-school, no-mock style
as `test_commit_safe.py`) rather than mocking `subprocess`: an unreachable
`git remote set-url origin <nonexistent path>` stands in for "network
unavailable," which lets the auto-repair and offline-fallback paths run
through real git rather than a mocked contract. 6 cases:

- valid symref is a no-op
- dangling symref repaired via `git remote set-head --auto`
- offline fallback prefers `main` when both `main` and `master` exist locally
- offline fallback uses `master` when `main` is absent locally
- no `origin` remote configured — tolerates the failure
- dangling symref but no local fallback candidate — tolerates the failure
