# Review every structure file and the glossary

**Priority:** must-have

## Goal

The spec-review agent reports on each structure file that exists and on the glossary. It files a finding for every term that waits for the stakeholder's confirmation. It runs in a project without schemas or area specs.

## Contract

| Operation      | Input state                                                                       | Outcome                                     | Persistence               |
| -------------- | --------------------------------------------------------------------------------- | ------------------------------------------- | ------------------------- |
| Spec review    | Feature files, scope map, glossary, `entity-model.md`; no `schemas/`, no `areas/` | Review runs                                 | Review report             |
| `inspect-spec` | Each present structure file                                                       | One check section per file                  | Review report             |
| `inspect-spec` | Glossary holds `Batch` and `PaymentBatch` for one concept                         | Finding: two terms for one concept          | `docs/findings/SPEC-*.md` |
| `inspect-spec` | A term used without a definition                                                  | Finding: term not defined                   | `docs/findings/SPEC-*.md` |
| `inspect-spec` | A term from an Avoid column in use                                                | Finding: avoided term in use                | `docs/findings/SPEC-*.md` |
| Spec review    | Work-file row with status `proposed`                                              | Finding with `owner: domain-modeling-agent` | `docs/findings/SPEC-*.md` |
| Spec review    | Scope map                                                                         | Read only; no finding on its content        | None                      |

## Demo Scenario

1. The operator runs the spec-review agent on the fixture `structure-review` (Demo Data). The review runs, although `schemas/` and `areas/` are missing.
2. The review report holds a section for `entity-model.md`, `state-machines.md`, and the glossary.
3. The report records a finding for `Batch` and `PaymentBatch`, and a `SPEC` finding for the `proposed` row `LedgerLine` with `owner: domain-modeling-agent`.

## Analysis

- **What changes.** The spec-review agent declares `docs/spec/work/term-candidates.md` as a context input. Its Read step keeps the scope map read only. Its Inspect step runs the `inspect-spec` check for each structure file that exists, for the glossary, and for the `proposed` rows.
- **`inspect-spec`.** Step 2 gains four subsections: one check per structure file, the three glossary defects, the `proposed` rows, and the read-only scope map. Each defect and each `proposed` row becomes a Major `SPEC` finding with `owner: domain-modeling-agent`. Step 3 adds a Structure checks section to the report. The step numbers stay, because `report-format.md` and `finding-format.md` link to Step 3.
- **Scenarios covered.** All four Scenarios of `Rule: Spec-review agent reviews behaviour and domain structure`, and the spec-review side of `Terms that the layout migration moved count as confirmed`.
- **Tests.** `tests/factory/test_core_artifact_ownership_text.py` gains text checks for CAO-08-LN-01. One behaviour check runs `engine.eligibility.evaluate_agent` on the real agent frontmatter in a project without `schemas/` and `areas/`.
- **Stop condition.** `spec-lint` has one glossary rule, `GLOSS001`, for an unused term. None of the three new checks repeats it, and the skill tells the reviewer not to report an unused term again.
- **Demo Scenario.** The demo needs a live spec-review session on the `structure-review` fixture. This story did not run it.
