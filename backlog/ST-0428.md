# Give OpenCode the same git guardrail

**Priority:** must-have

## Goal

In a real OpenCode session, the git guardrail refuses an agent `dispatch return-story` through the `shell` tool and through the `execute` tool. The plugin passes each command to `block-dangerous-git.sh`, and fast contract tests show this for both tools without a real session.

## Domain Rule

- OpenCode's plugin `config/plugins/agent-factory.ts` calls the same script as the other four tools and holds no rule of its own.
- The plugin checks the `shell` and the `execute` tool.
- Only OpenCode needs a real session (OI-06). It runs as an opt-in pytest test behind the marker `opencode_session`, which the suite runs leave out, as they leave out `container` (OI-07).
- The User starts it before each release through the manual pre-commit hook `run-opencode-session-test`, entry `uv run pytest --tb=short --quiet -m opencode_session`, after `run-container-tests` (OI-12).

## Outputs

- The git guardrail in `agent-factory.ts` for `shell` and `execute`.
- `node:test` contract tests with a stub script: one for the `shell` path and one for the `execute` path.
- `tests/factory/test_run_lifecycle_opencode_session.py` with the real-session tests.
- The marker `opencode_session` in `pyproject.toml` and the hook in `.pre-commit-config.yaml`.
- A spec-feedback row asks the test-strategy agent to list `opencode_session` under the `default` suite's `markers` in `docs/testing.yaml` and to leave it out of the four commands, at the wave close.

## Demo Scenario

1. The User runs `pre-commit run run-opencode-session-test --hook-stage manual` with OpenCode (v2.2.7 on this machine) and a free tier model that OpenCode configured on its own.
2. In the session, the agent's `dispatch return-story ST-0350` through the `shell` tool is refused with the script's reason.
3. The same command through the `execute` tool is refused.
4. The `typescript` suite shows the two stub tests passing without OpenCode installed.

## Analysis

- **The real API.** OpenCode v2.2.7 loads the default export of `.opencode/plugins/agent-factory.ts` as `{ id, setup }`. `setup(ctx)` registers a hook through `ctx.tool.hook("execute.before", hook)`, and the hook gets `{ tool, input, sessionID, agent, messageID, id }`. A hook that throws refuses the call with the error's message. `ctx.location.directory` names the project. The tool names are `shell` and `execute`. A probe session in a temporary project showed each of these.
- **Why the plugin never ran.** The plugin returned its hooks from `setup` and read `call.args`, and OpenCode registers no hook from a return value. It also imported `@opencode-ai/plugin`, which a project with an installed Factory cannot resolve, so OpenCode logged `failed to load plugin` and ran every call unguarded. `Plugin.define` returns its argument as it is, so the plugin now exports the definition itself.
- **What changes.** The plugin registers one `execute.before` hook. For `shell` and `execute` it passes `{ toolName, input: { command } }` to `block-dangerous-git.sh`, with the command of a `shell` call or the JavaScript of an `execute` call as `command`. It finds the script through the common git directory, as pi's extension does, and blocks the call when the script is missing. The human-field guard keeps its tools, its payload `{ cwd, toolName, input }`, its script lookup and its fail-closed check; it now reads the arguments from `input`.
- **Files.** `agent-factory.ts`, `__tests__/agent-factory.test.ts`, the new `tests/factory/test_run_lifecycle_opencode_session.py`, the marker in `pyproject.toml`, the hook in `.pre-commit-config.yaml`, and this story file for the analysis and the status.
- **Scenarios covered.** "OpenCode has a git guardrail that calls the same script" and the OpenCode rows of the first Outline, with `dispatch return-story`. The `execute` Outline is covered with `execSync("dispatch return-story ST-0350")`.
- **Tests.** RL-16-CT-02 and its `execute` test in `agent-factory.test.ts`, with stub scripts and a stub context. RL-16-E2-01 and RL-16-E2-02 in the session test file. The FC-18-CT-02 tests move to the stub context.
- **Opt-in.** Until `docs/testing.yaml` lists `opencode_session`, the suite runs select the session tests. So the tests skip themselves unless the marker expression names `opencode_session`.
- **Session folder.** OpenCode takes its project folder from `PWD`, not from the folder of its process. The test sets `PWD` to the temporary project.
