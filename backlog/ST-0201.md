# Strip mode concept from context-lint

Remove all mode-related logic and lint codes from `factory/scripts/context-lint`. The mode concept (primary/index) was eliminated during the stakeholder grilling (see [proposal § Stakeholder Grilling Results](../docs/proposals/yaml-charter-lifecycle.md#stakeholder-grilling-results-2026-09-05)).

**Priority:** must-have

## Demo

A developer runs `context-lint` against a project with `docs/agent-context/` files. The linter validates YAML parsing, required top-level keys, source-pointer link resolution, reading-guide key-path references, and format consistency. It does not check for a `mode` field, does not branch on mode values, and does not run mode-gated source-coverage checks. A `null` value in any index file produces a `CX-NULL` error regardless of lint mode.

## Acceptance Criteria

- `CX-MODE` lint code is removed — context-lint does not check for or report on a `mode` field.
- `CX-MODE-INVALID` lint code is removed.
- `CX-SRC` (mode-gated source coverage check) is removed.
- `CX-NULL` fires as an error unconditionally — no warning-vs-error distinction, no file-level leniency for governance.yaml.
- All remaining lint codes (`CX-FILE`, `CX-PARSE`, `CX-KEYS`, `CX-SRC-EXIST`, `CX-SRC-STALE`, `CX-GUIDE-REF`, `CX-FORMAT`) continue to function as specified.
- Existing tests for non-mode lint codes continue to pass.

## Scope

**Status quo:** `context-lint` on `feature/agent-context` validates `mode` fields, branches on mode values for `CX-SRC`, and treats `CX-NULL` severity differently per file and lint mode.

**Adds:** Removal of mode-related branches and codes. `CX-NULL` as unconditional error.

**Out of scope:** Changes to capture-context or update-context (ST-0202). Template changes (ST-0203).
