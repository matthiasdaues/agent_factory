# Prove nested addressing and bounded dispatch contracts

Add focused evidence for the intentionally prompt-enforced nested reply,
scope-splitting, and checkpoint rules without inventing a new routing or
budget-control runtime.

**Priority:** must-have

## Acceptance Criteria

- Contract tests require a resolvable parent instance ID and reject agent-type
  names as reply addresses on every nested-dispatch-capable canonical surface.
- Contract tests require fallback to local work instead of indefinite waiting
  on an unreachable or declining child.
- Contract tests require whole-codebase work to be split by module/directory or
  checkpointed between rounds with independently verifiable output scopes.
- Existing `dispatch_wave` scope enforcement remains the mechanical evidence;
  live token-budget control is absent.

## Implementation Notes

This is an evidence-only story for rules that BR-048 deliberately permits to
remain contract-enforced.

## Analysis

Add one Chicago-school contract test at
`orchestrator/tests/test_dispatch_contract_assurance.py`; no Factory runtime,
agent, rulebook, playbook, specification, or generated catalog source changes.
The test reads the shipped canonical surfaces named by the dispatch safeguard
audit and proves their combined contract remains complete.

For UC-12/BR-047, the nested-dispatch seam is
`factory/rulebooks/conventions/dispatch-contract.md` plus
`factory/agents/reconciliation-agent.md`, the canonical agent explicitly
permitted to fan out recursively. Evidence requires a resolvable parent
instance ID, rejects an agent-type name as a reply address, and requires local
fallback rather than indefinite waiting when a child declines or is
unreachable.

For BR-048, the bounded-dispatch seam is the dispatch contract, root
`factory/rulebooks/rules.md`, `factory/agents/implementation-agent.md`, and the
existing `factory/config/extensions/dispatch-wave.ts` premerge scope handoff.
Evidence requires whole-codebase tasks to split into independently verifiable
module/directory scopes or checkpoint commits between rounds. Runtime source
assertions also preserve the accepted exclusion: dispatch exposes scope
enforcement but no live token-budget parameter or control loop.

The assignment explicitly confirms this evidence-only boundary and these
acceptance concerns, satisfying the analysis and seam pause points. A failing
test may identify only a contract-evidence gap; it does not authorize silent
runtime or canonical-document expansion.

## Spec Feedback

dispatch safeguard validation rules, the audit matrix, and the accepted

prompt-enforced addressing, fallback, split/checkpoint, and Pi scope contracts

generated index update is needed.
