# Judge every story by the gate settings of the integration branch

A story can no longer loosen its own CRAP gate, because the threshold, the patterns and the register come from the integration branch.

**Priority:** must-have

## Goal

A story that raises its threshold, adds an `exclude` pattern, narrows a `files` pattern or drops a measure in its own `docs/testing.yaml` gets the same verdict as without that change. The gate-check step and `dispatch merge-story` both judge it with the values on the integration branch. Only `gate-setup-proof` judges uncommitted setup values, through `--settings-from-folder`.

## Domain Rule

- What counts as accepted is decided outside the story. So `threshold`, the `files` pattern and the `exclude` list of each measure, and the exceptions register come from `refs/heads/<integration branch>` (DEC-67, DEC-69, DEC-75).
- The integration branch is `integration_branch` in `docs/factory-settings.yaml` of the folder, and `dev` without the file or the key (DEC-68). A value that is not a non-empty string exits 2 and names the key (DEC-74).
- A named branch that git does not hold, or whose tip is the judged `HEAD`, exits 2 and names the key and the branch. Only the default `dev` falls back when its ref is missing (DEC-76).
- `enabled`, `timeout_minutes`, and the `name`, `command` and `ready` of each measure stay at the story head. The folder still must hold the three required values, so every check of BR-128 still runs on it (DEC-75).
- A measure that the branch does not name takes `files` and `exclude` from the head, and the output names it as not yet trusted. A measure that the branch names and the head lacks exits 2 and names the measure (DEC-69, DEC-70).
- A branch `docs/testing.yaml` that cannot be parsed, or a branch entry without `threshold`, exits 2 and names the branch, the file and the cause. Only a missing ref, file or entry falls back to the folder, and the output then says which values came from where and why (DEC-74, DEC-13).
- The gate logic reaches the threshold, the patterns and the exceptions only through one reader, the trusted gate source. The git ref is its only backend, and no plugin loading is built (DEC-72, ADR-0041).
- `--settings-from-folder` takes `threshold`, `files` and `exclude` from the folder and reads no `docs/testing.yaml` from the branch, so the check of DEC-70 does not run. The register still comes from the integration branch (DEC-71).
- `gate-setup-proof` passes `--settings-from-folder` and copies `docs/factory-settings.yaml` of the working tree into its first commit (DEC-71, DEC-73). `premerge-check`, `dispatch` and the gate-check step never pass the option.
- `GATE_FILES` and `GATE_EXCLUDE` carry the patterns that the trusted gate source returns (BR-129).

## Demo Scenario

1. A temporary wave repository holds `dev` with `gates.crap-score`, threshold 8 and the measure `python` with the `files` pattern `packages/factory/scripts/*`. `feature/login` is cut from `dev`, and `story/ST-0350` from `feature/login`.
2. On `story/ST-0350`, the developer changes one line inside `tree_severity` of `packages/factory/scripts/finding-lint`, which then scores 9, and raises the threshold to 10 in `docs/testing.yaml`.
3. The implementation agent runs `crap-score --base feature/login --story-id ST-0350 --report-dir .current-work/crap-score/`. It exits 1 and names `tree_severity` and `9.00`, because it judges with the threshold 8 of `dev`.
4. The User runs `dispatch merge-story ST-0350`. `premerge-check` exits 1 and names `tree_severity` and `9.00`. The entry stays `dispatched`, and the tip of `feature/login` does not move.
5. In a second repository, the User changes the threshold to 10 in the working tree without a commit and runs `gate-setup-proof --measure python --plant .current-work/gate-setup-proof/plant/python/`. The proof judges with the threshold 10 and reads the register from `dev`.

## Analysis

- **Reader.** `crap-score` gets the abstract class `TrustedGateSource` with two methods: `gate_values(folder)` returns the threshold, the `files` and `exclude` of each measure, and the notices; `exceptions()` returns the register rows and the notices. `GitRefSource` is the only backend and reads `refs/heads/<integration branch>`. `read_register` and `REGISTER_BRANCH` are gone, and their code moved behind the interface (DEC-72).
- **Join.** `join_values` joins the branch entry with the folder by measure `name`, and `apply_trusted` puts the result into the folder settings. So `command` and `ready` always stay at the head (DEC-75).
- **Branch.** `integration_branch` reads the key from `docs/factory-settings.yaml` of the folder. A named branch that git does not hold, or whose tip is `HEAD`, exits 2 in the constructor of `GitRefSource` (DEC-76).
- **Option.** `--settings-from-folder` reaches only `gate_values`. The register still comes from the branch (DEC-71).
- **Proof.** `gate-setup-proof` passes the option and copies `docs/factory-settings.yaml` of the working tree into its first commit (DEC-73).
- **Seam for tests.** `main(argv, source=None)` takes a backend, so CG-14-CT-02 judges with a test backend and runs no git command.
- **Tests that changed.** CG-04-IT-10 now shows the folder through its own `command`. The lock fixture commits a `dev` without the entry `gates.crap-score`. The CG-04-CT-07 test of a wrong shape runs in `tmp_path`, so it no longer reads the `dev` of this repository.
- **Decided without a rule.** A `docs/factory-settings.yaml` that is no valid YAML or no mapping exits 2 and names the file. A branch entry without `measures` names no trusted measure. A branch measure without `name` or `files` exits 2 and names the branch. The spec-feedback report lists these gaps.
