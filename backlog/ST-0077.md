# Create capture-charter skill

Create the `capture-charter` lifecycle skill with three modes that scaffold, scan, and complete the project charter.

**Priority:** must-have

## Acceptance Criteria

- Skill file at `factory/skills/capture-charter/SKILL.md` with proper frontmatter
- `--init` mode: creates the three charter files from templates under `docs/charter/`, fills answers already known from the vision conversation, unfilled sections get "To be decided."
- `--init --scan` mode (brownfield): scans the codebase for existing configuration files (`pyproject.toml`, `package.json`, `docker-compose.yml`, `.github/workflows/`, linter configs, test configs, `.pre-commit-config.yaml`), pre-populates the charter skeleton, and presents findings for stakeholder confirmation
- Default mode (completeness sweep): walks every "To be decided" entry, forces a decision or explicit deferral, checks whether corresponding artifacts already exist, derives Epic 0 stories for missing artifacts, and writes them to `backlog/ST-NNNN.md` using the standard story format with `epic: "Epic 0 — Project Setup"`, `tier: economy`, MoSCoW `must-have`
- Completeness sweep creates a final "Update development.md with actual commands and paths" story that depends on all other Epic 0 stories
- The skill runs in the orchestrating session (not a spawned subagent)
- Skill references `charter-lint` for validation

## Implementation Notes

The completeness sweep's Epic 0 derivation checks for existing artifacts before creating stories. When an artifact exists, it creates a smaller "verify/adapt" story or no story. The stakeholder can point at existing work during the sweep. Epic 0 stories use the lowest available ST numbers.
