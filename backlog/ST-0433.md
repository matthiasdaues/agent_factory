# Merge a story in a project without a CRAP gate entry

A merge in a project that has not set up the CRAP gate runs no `crap-score` and says which skill sets it up.

**Priority:** must-have

## Goal

In a project whose `docs/testing.yaml` has no entry for a built-in gate, `premerge-check` does not run that gate and prints one line. The line names each built-in gate without an entry and the skill that sets it up, and the merge continues. A project set up from the charter template gets no CRAP gate.

## Domain Rule

- No gate has a default. A gate runs at the merge only when `docs/testing.yaml` enables it or the story's `quality-gates` field names it (BR-066).
- The not-set-up line names `crap-score` with the skill `setup-crap-score` and `mutation-testing` with the skill `mutation-testing`, each only when its entry is missing (DEC-20, DEC-33).
- The not-set-up line is a notice. It never refuses a merge and never changes the exit code.
- The charter template keeps its entry `mutation_testing`, which BR-055 still reads, and has no entry `crap_score` or `crap-score` (DEC-41).

## Outputs

- `premerge-check`: `DEFAULT_GATES` and the fallback to `crap-score` in `resolve_gates` are gone. A run without an entry for a built-in gate prints the not-set-up line.
- `packages/factory/rulebooks/templates/charter-testing.yaml`: the entry `crap_score` with `threshold: 8` is gone.
- `pyproject.toml`: the description of the marker `spec` gains the prefix CG ([QA gap 3](../docs/spec/work/crap-gate-setup-qa-strategy.md#gap-findings)).
- `tests/factory/test_premerge_check.py`: the rows of `test_st_0359_gate_list` with `NO_GATES` or without `docs/testing.yaml` expect no `crap-score` (CAO-11-CT-01). `TestSt0359DemoFixtures.test_st_0359_no_gates_requires_crap_and_skips_dependency_without_rules` gives way to CG-11-IT-01.
- New `tests/factory/test_crap_gate_premerge.py` and `tests/factory/test_crap_gate_text.py` with the owned rows.

## Demo Scenario

1. A temporary repository has `dev`, `feature/login`, and `story/ST-0350` with a review report. Its `docs/testing.yaml` holds `test_command: "true"` and no `gates` section.
2. The User runs `dispatch merge-story ST-0350`. The output holds one line that names `crap-score` with `setup-crap-score` and `mutation-testing` with `mutation-testing`. No `crap-score` runs, and `dispatch status` shows ST-0350 `done`.
3. The User adds only `gates.mutation-testing` and merges ST-0351. The line names `crap-score` with `setup-crap-score` and does not name `mutation-testing`.
4. The User copies `packages/factory/rulebooks/templates/charter-testing.yaml` byte for byte to `docs/testing.yaml` and merges ST-0352. No `crap-score` runs, and the line names `crap-score` with `setup-crap-score`.
