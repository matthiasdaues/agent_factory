# Check cycle models and workstream states for migration integrity

The project maintainer runs `transition-lint` to validate cycle models and state files, runs `phase` to see a diagnostic naming the replacement, and runs characterization tests confirming that kept contracts still work.

**Priority:** must-have

## Goal

After this story ships, `transition-lint` reads the cycle model (`delivery.yaml`) and workstream state files (`.current-work/cycles/*.yaml`) instead of the legacy playbook FSM and playbook-state marker. An invalid cycle model produces finding code `TL-CYCLE-MODEL` (error) and a non-zero exit. A malformed state file produces `TL-CYCLE-STATE` (error) and a non-zero exit. Failed recommendation evidence produces `TL-ROUTE-EVIDENCE` (warning) at exit zero. The pre-migration finding codes (`TL-NOMARKER`, `TL-MARKER`, `TL-NOFSM`, `TL-STATE`, `TL-ORDER`) are retired.

`phase advance` exits 2 and prints a message naming `factory/scripts/cycle select` as the replacement. `phase retry` exits 2 and prints a message naming `factory/scripts/cycle retry` as the replacement. Neither subcommand reads or writes state.

Characterization tests confirm that `mdformat`, `link-check`, `mermaid-lint`, `spec-lint`, `arch-lint`, `backlog-lint`, `concern-lint`, `matrix-lint`, `statemachine-lint`, `index-lint`, `verify-base`, and `premerge-check` retain their command name, triggers, result format, and exit behavior after the migration. Every indexed agent and skill name from the acceptance commit still exists in the post-migration index.

## Domain Rule

- `transition-lint` is read-only. It never writes state or lock files.
- Invalid cycle models and malformed state files are errors.
- Failed recommendation evidence is a warning at exit zero.
- The pre-migration finding codes are retired.
- The diagnostic `phase` stub exits 2 and names the replacement command.
- Kept contracts retain their behavior after migration.
- Every indexed agent and skill name at the acceptance commit is preserved.

## Demo Scenario

1. Run `factory/scripts/transition-lint`. With a valid delivery model and no workstream state files, it exits 0 with no findings.
2. Create a workstream at IDEA. Run `transition-lint`. It reports no findings and exits 0.
3. Edit `delivery.yaml` to remove a required cycle. Run `transition-lint`. It reports `TL-CYCLE-MODEL` and exits with a non-zero count.
4. Restore `delivery.yaml`. Edit a workstream state file to set `schema_version` to an invalid value. Run `transition-lint`. It reports `TL-CYCLE-STATE` and exits non-zero.
5. Restore the state file. Create a scenario where route evidence fails (e.g. no proposal file for a recommend_if condition). Run `transition-lint`. It reports `TL-ROUTE-EVIDENCE` as a warning and exits 0.
6. Run `factory/scripts/phase advance`. It exits 2 and prints "Use factory/scripts/cycle select" (or equivalent message).
7. Run `factory/scripts/phase retry`. It exits 2 and prints "Use factory/scripts/cycle retry" (or equivalent message).
8. Run the characterization test suite. All standard checks and branch safety commands pass.

## Outputs

**Migrated transition-lint (`packages/factory/scripts/transition-lint`):**

- Reads `factory/engine/models/delivery.yaml` through the Cycle Model Loader. If the model is invalid, emits `TL-CYCLE-MODEL` (error) with a description naming the fault.
- Reads workstream state files under `.current-work/cycles/*.yaml`. For each file, validates against `cycle-state-v1.schema.json`. If invalid, emits `TL-CYCLE-STATE` (error).
- For each valid state file, evaluates route evidence. If evidence for a recommended route fails, emits `TL-ROUTE-EVIDENCE` (warning).
- Exit code is the count of error-severity findings. Warnings do not affect the exit code.
- Supports `--format text|json` and `--report-only` (always exits 0).
- When invoked against a pre-migration repository (no cycle state files, only `.current-work/playbook-state.yml`), reports no findings and exits 0.

**Diagnostic phase stub (`packages/factory/scripts/phase`):**

- `phase advance` prints to stderr: "phase advance is retired. Use factory/scripts/cycle select." Exits 2.
- `phase retry` prints to stderr: "phase retry is retired. Use factory/scripts/cycle retry." Exits 2.
- Reads nothing. Writes nothing.

**Characterization tests (`tests/factory/test_characterization.py`):**

- For each standard check (`mdformat`, `link-check`, `mermaid-lint`, `spec-lint`, `arch-lint`, `backlog-lint`, `concern-lint`, `matrix-lint`, `statemachine-lint`, `index-lint`): invokes the command and verifies exit code, trigger compatibility, and output format.
- For each branch safety command (`verify-base`, `premerge-check`): invokes the command and verifies exit code and contract preservation.
- Runs `index-lint --check` and verifies every agent and skill name from the acceptance commit exists.

## Constraints

- `transition-lint` must remain a pre-commit hook. The script must exit quickly (under two seconds for typical repositories).
- The diagnostic phase stub must not emulate old transition behavior. It prints guidance and exits.
- Characterization tests must persist as long as the compatibility contract holds.
- The characterization suite must not depend on workstream state or cycle model state. It verifies command contracts independent of cycle infrastructure.
- Python 3.10 minimum (agent-context.md § Python toolchain).
- No quality gates enabled: both `crap_score` and `mutation_testing` are disabled in testing.yaml.

## Agent Stop Conditions

- If the existing `test_transition_lint.py` covers contracts that overlap with the new `test_transition_lint_integration.py`, stop and ask about consolidation vs. coexistence.
- If the characterization tests require fixtures that are expensive to set up (e.g. full repository clones), stop and ask about fixture scope.
- If any standard check command has changed its contract since the acceptance commit (e.g. new exit codes, renamed flags), stop and ask about whether the characterization test should verify the old or current contract.
- If `transition-lint` cannot import the Cycle Model Loader without pulling in heavy dependencies, stop and ask about the import boundary.
