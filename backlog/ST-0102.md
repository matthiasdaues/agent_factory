# Create mutation-analysis gate skill, script, and fixture

Create the mutation analysis gate: a skill document, a CLI wrapper script,
and a test fixture. The gate verifies that test coverage is behaviorally
meaningful — every surviving mutant requires action: remove dead code, add
the missing test, or file a finding for QA. Zero survivors to pass.

**As a** implementation-agent dispatcher,
**I want** a mutation analysis gate that detects untested behavioral
contracts,
**so that** surviving mutants are resolved before merge rather than
discovered during QA review.

**Priority:** must-have

## Acceptance Criteria

01. `factory/skills/mutation-analysis/SKILL.md` exists and documents the
    mutation analysis gate, survivor classification, and diff-scoping.
02. `factory/scripts/mutation-analysis` is an executable script that runs
    mutation testing on the given source files.
03. The script accepts `--diff-base <ref>` to scope mutations to production
    files in the story's diff. When omitted, falls back to full module.
04. Diff-scoping: `git diff --name-only --diff-filter=ACMR <ref> HEAD`,
    filtered to production files (excluding test files matching
    `test_*.py`, `*_test.py`, `*_test.go`, `*.test.ts`, `*.test.js`,
    `*.spec.ts`, `*.spec.js`, and files under `tests/` or `__tests__/`).
05. The script produces a JSON report per mutant: operator, location,
    killed/survived, resolution action.
06. Reports are logged to
    `.agent-factory/mutation-analysis/<story-id>.json`.
07. The script exits non-zero when any mutant survives without resolution.
08. Each surviving mutant requires one of: dead code removed, missing
    contract test added, or finding filed for QA. Unresolved survivors
    block the merge.
09. Tool candidate: `mutmut` (Python reference implementation).
10. `factory/fixtures/quality-gates/surviving-mutant/` contains a
    self-contained test project with: one arithmetic operator (`+`) whose
    mutation (`-`) is not detected by any test (expected survivor), and one
    operator whose mutation is killed (expected kill).
11. The script runs against the fixture and produces the expected results.
12. All outputs pass `factory/scripts/validate`.
