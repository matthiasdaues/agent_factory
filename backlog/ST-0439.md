# Get the same CRAP verdict in the gate-check step and at the merge

The gate-check step and the merge call `crap-score` the same way, so a story in any language gets one verdict at both points.

**Priority:** must-have

## Goal

`premerge-check` calls `crap-score --base <target>` in its temporary worktree, so a story that changes only scripts without a file ending gets its changed functions scored at the merge. The report of a refused merge stays in the primary checkout. The gate-check step runs `crap-score` as a background job with `--base <feature-branch>`.

## Domain Rule

- `premerge-check` builds `crap-score --base <target> --story-id <id> --report-dir <primary>/.current-work/crap-score/`, with no list of files and no threshold (BR-136).
- The measuring command at the merge runs in `.current-work/<target>/premerge/<story-id>` and measures the code of the story branch (ADR-0038).
- `premerge-check dev feature/login`, the feature merge, runs no `crap-score`.
- The implementation agent starts `crap-score` in the gate-check step as a background job, passes `--base <feature-branch>` and `--report-dir` set to `.current-work/crap-score/` of the folder it runs in, and reads the verdict only from the exit code (BR-134).

## Outputs

- `premerge-check`: the new `gate_command` for `crap-score`; `changed_python_files`, `crap_score_skip_notice` and the notice "changed no .py file" are gone; the report folder is the primary checkout's.
- `implementation-agent.md`: the gate-check step runs `crap-score` as a background job with `--base` and `--report-dir`.
- `tests/factory/test_premerge_check.py`: `test_st_0415_the_built_call_of_crap_score` and its sibling without a threshold give way to CG-08-CT-01; `test_st_0415_premerge_check_reads_the_old_key_crap_score` and `test_st_0415_with_both_keys_the_key_with_hyphens_wins_with_a_warning` lose the assertion on `--threshold 8`; the fixture `GATES_CRAP_ONLY` gains `timeout_minutes` and `measures`.

## Demo Scenario

1. In the repository of ST-0436, ST-0350 changes only `tree_severity` in `packages/factory/scripts/finding-lint`, and a test file that exists only at the head of `story/ST-0350` covers it.
2. The User runs `dispatch merge-story ST-0350`. The measuring command runs in `.current-work/feature/login/premerge/ST-0350`, and the row of `tree_severity` shows 100 % coverage.
3. A planted score of 9 refuses the merge. The refusal names `tree_severity`, and no line about `.py` files appears.
4. The temporary worktree is gone, and `.current-work/crap-score/ST-0350.json` of the primary checkout holds the report.
5. The User runs `premerge-check dev feature/login`. No `crap-score` runs.

## Analysis

- `premerge-check`: `gate_command` takes the merge target and the primary checkout. For `crap-score` it builds `crap-score --base <target> --story-id <id> --report-dir <primary>/.current-work/crap-score`. `rerun_gate` and `check_semantic_gates` pass the target instead of the `.py` files. `changed_python_files`, `crap_score_skip_notice` and the early pass "scored nothing" go. The exit code stays the verdict. A refusal still names the failing functions from the report in the primary checkout, so the report gives the detail and never the verdict.
- `implementation-agent.md`: the gate-check step starts `crap-score` as a background job with `--base <feature-branch>` and `--report-dir`, waits for its exit, and reads the verdict only from the exit code. The sentence about a hardcoded default threshold goes.
- `tests/factory/test_crap_gate_premerge.py`: CG-08-CT-01, CG-08-IT-01, CG-08-IT-02, CG-08-IT-06 and CG-08-IT-07. The integration tests run the real `crap-score` of `packages/factory/scripts/` through an installed wrapper, with a measuring command stub.
- `tests/factory/test_crap_gate_text.py`: CG-04-LN-01.
- `tests/factory/test_premerge_check.py`: the two tests of the old built call go to CG-08-CT-01; RL-09-CT-04 and RL-09-CT-05 lose the threshold assertion; `GATES_CRAP_ONLY` gains `timeout_minutes` and `measures`.
- Scenarios covered: "premerge-check passes its merge target to crap-score", "A story that changes only scripts without a file ending is scored at the merge", "The measuring command at the merge measures the code of the story branch", "The report of a refused merge stays in the primary checkout", "The feature merge runs no crap-score", "The gate-check step waits for crap-score as a background job", "The implementation agent runs crap-score as a background job".
- Concern: interface-contracts.md says that `premerge-check` reads no report of `crap-score`. The refusal reads the report for the names of the failing functions, as before. The spec-feedback report records the question.
