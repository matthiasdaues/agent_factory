# Build intent assess subcommand to validate artifacts and report results

The developer runs `intent assess` to validate artifacts on disk and see results in a consistent format.

**Priority:** should-have

## Goal

The `intent assess` subcommand runs all applicable validators against governed artifacts on disk and reports results in the shared validator format. Each result includes the artifact type, artifact reference, assessed commit, individual checks, and warnings. The command reads agent definitions and governed artifacts, runs mechanical validation (file existence, format lint, required fields), and formats output for the terminal.

## Domain Rule

- `intent assess` runs all applicable validators — both mechanical (file existence, format lint, required fields) and triggered semantic validators.
- Each validator result follows the shared format: artifact type, artifact reference, assessed commit, individual checks, and warnings.
- The command is read-only — it writes nothing to the repository.
- Exit code `0` on success; `2` on invalid input.
- The `--workstream` flag narrows validation to artifacts matching that workstream's scope.
- The `--format` flag selects text (default) or JSON output.

## Demo Scenario

1. Run `intent assess`. The command scans governed artifacts on disk.
2. The output shows a result per artifact: artifact type (proposal), artifact reference (docs/proposals/activity-graph-orchestration.md), assessed commit (HEAD short SHA), individual checks (frontmatter present: pass, status field valid: pass, scope field present: pass), and no warnings.
3. A second artifact has a warning: "story ST-0100 references nonexistent dep ST-9999." The result shows the warning alongside passing checks.
4. Run `intent assess --format json`. The same results appear as a JSON array with one object per artifact.
5. Run `intent assess --workstream activity-graph-orchestration`. Only artifacts scoped to that workstream are validated.

## Outputs

- `packages/factory/scripts/intent` — `assess` subcommand that:
  - Discovers governed artifacts on disk (proposals, epics, stories, features, DSL, entity model, scope map)
  - Runs applicable validators against each artifact (mechanical: file existence, format lint, required fields)
  - Collects results in the shared validator format: artifact type, artifact reference, assessed commit (current HEAD), individual checks (name + pass/fail), warnings
  - Formats output as text (default) or JSON (`--format json`)
  - Filters by workstream when `--workstream` is provided
  - Exits `0` on success, `2` on invalid input
  - Writes nothing to the repository

## Constraints

- The command is strictly read-only — no file writes, no state changes.
- Exit codes must match the interface contract: `0` success, `2` invalid input.
- Output format must follow the shared validator result format specified in the interface contracts.
- The command must work without a bound workstream (validates all artifacts).
- Must not duplicate validation logic that exists in standalone lint scripts — call them instead.
