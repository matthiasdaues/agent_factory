# Merge a story by hand after premerge-check passes

**Priority:** must-have

## Goal

After the User's go, `dispatch merge-story` merges a story into the feature branch only when `premerge-check` passed with the story branch checked out. It sets `status: done` in the story file in the merge commit, and no other command sets `done`.

## Domain Rule

- By hand, `merge-story` runs `premerge-check` with the story branch checked out and checks out the feature branch only after exit 0 (BR-124).
- A refused `premerge-check` leaves the primary checkout on the story branch. A refused checkout of the feature branch stops `merge-story`, and git's own refusal stays.
- Only `merge-story` sets `done`, in the merge commit. `dispatch` has no `mark-done` (BR-118).
- After a merge, `commit_sha` holds the merge commit, and `prepare-story` reads it as the base of the next story in a serial chain.

## Outputs

- In a run by hand, `merge-story` runs without the feature branch checked out. Today a check around line 1824 of `dispatch` requires it.
- `mark-done` and its parser entry go; `STOP_SUBCOMMANDS` and the dispatch contract follow.

## Demo Scenario

1. With ST-0350 `dispatched` on `story/ST-0350` in the primary checkout, the implementation agent stops and shows `premerge-check` output. After the User's go it runs `dispatch merge-story ST-0350`.
2. `git branch --show-current` prints `feature/login`. `git show HEAD:backlog/ST-0350.md` reads `status: done`, and `dispatch status` shows ST-0350 `done`.
3. On a second story whose gate fails, `merge-story` exits 1, and the primary checkout stays on its story branch.
4. `dispatch mark-done ST-0350` fails with an unknown-subcommand error.

## Analysis

- `merge-story` accepts the ledger of a run by hand. By hand it needs the story branch checked out in the primary checkout. It skips `refresh-story`, because the story branch starts at the feature branch tip. It runs `premerge-check` first and checks out the feature branch only after exit 0 (BR-124).
- A refused checkout exits 1, prints git's refusal, and names the primary checkout. The entry stays `dispatched`, and the story branch stays checked out. A refused merge checks the story branch out again and also keeps the entry `dispatched`.
- An interrupted merge by hand leaves the feature branch checked out at the merge commit. `merge-story` then resumes the way the orchestrated path does.
- The checks that read `HEAD` read the feature branch by name, so they hold on both ways.
- `mark-done`, its parser entry and `cmd_mark_done` go, and `READ_SUBCOMMANDS` loses `mark-done` (BR-118).
- Tests: RL-03-IT-03 to RL-03-IT-05, RL-02-IT-02 and RL-17-IT-01 in `tests/factory/test_run_lifecycle_dispatch.py`; RL-02-CT-01 in `tests/factory/test_run_lifecycle_ledger.py`.
- Outside `touches`: `tests/factory/test_finding_stop.py` lists `mark-done` among the subcommands that run during a stop, so its list loses `mark-done`.
- Callers of `mark-done` that stay: `docs/arc42/06_runtime_view.md` line 1024 and the Examples of `docs/spec/features/finding-classification.feature` line 889. Both become rows of the spec-feedback report.
- `close-wave` still refuses the ledger of a run by hand; ST-0421 owns that. RL-17-IT-01 writes the wave record into the ledger itself.
