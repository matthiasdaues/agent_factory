# Block a merge on a failing or slow mutation command

**Priority:** must-have

## Goal

The implementation agent runs the project's mutation command from `docs/testing.yaml` through a gate script. The merge is blocked when the command fails, is missing, or runs past its time limit. The developer agent runs the same gates in manual mode before it hands a story back.

## Contract

| Operation        | Input state                                                       | Outcome                                               | Persistence         |
| ---------------- | ----------------------------------------------------------------- | ----------------------------------------------------- | ------------------- |
| Mutation gate    | Mutation testing picked, `gates.mutation_testing.command` missing | Fails; the message names the test-strategy agent      | Failing result file |
| Mutation gate    | Command exits 0                                                   | Passes                                                | Passing result file |
| Mutation gate    | Command exits 1                                                   | Fails; merge blocked                                  | Failing result file |
| Mutation gate    | Command runs past `gates.mutation_testing.timeout_minutes`        | The script stops the command and fails; merge blocked | Failing result file |
| Mutation gate    | `timeout_minutes` unset                                           | Limit of 30 minutes                                   | —                   |
| `premerge-check` | A failing mutation result file                                    | Exit non-zero                                         | None                |

The result file is `.current-work/mutation-testing/<story-id>.json`, which `premerge-check` already reads.

## Demo Scenario

1. The operator runs the mutation gate script for ST-0318 on the fixture `mutation-no-command` (Demo Data). It fails and names the test-strategy agent.
2. On `mutation-fails`, it fails after `scripts/mutate.sh` exits 1, and `premerge-check` exits non-zero.
3. On `mutation-slow`, it stops `scripts/mutate.sh` after 1 minute and writes a result file with `passed: false`.
4. The operator reads the developer agent's manual-mode workflow. It runs the same gates before the handback.

## Analysis

The story adds a gate script for the mutation command and names it in both agents. Four places change.

- `packages/factory/scripts/mutation-testing`: new gate script, named after its gate like `crap-score`. It reads `gates.mutation_testing.command` and `timeout_minutes` from `docs/testing.yaml` and runs the command in its own process group. At the limit it stops the whole group, first with `SIGTERM`, then with `SIGKILL`. It writes `{"passed": ...}` to `<report-dir>/<story-id>.json`, the shape `premerge-check` already reads. It exits 0 on a pass and 1 on a failure. A missing command or a missing `testing.yaml` fails the gate, and the message names the test-strategy agent.
- `packages/factory/agents/implementation-agent.md`: § Gate execution names the script and the background run. The manual-mode line now hands the gates to the developer agent.
- `packages/factory/agents/developer-agent.md`: a new step "Run the gates" for manual mode lists the four gates before the handback.
- `tests/factory/test_core_artifact_ownership_gates.py`: the three Demo fixtures (CAO-11-IT-01, CAO-11-IT-02). `tests/factory/test_core_artifact_ownership_text.py`: the text check (CAO-11-LN-01).

Scenarios covered: "An enabled mutation gate without a command fails and names its owner", "A mutation command that runs past its time limit blocks the merge", and "The developer agent runs the gates in manual mode".

Concerns:

- The `mutation-slow` fixture sets a limit of 1 minute. A test run cannot wait that long, so the slow test calls the script's run function with a limit of 1 second. A second test checks that `timeout_minutes: 1` gives 60 seconds and an unset limit gives 1800.
- A child that starts its own session leaves the process group, and the script cannot stop it.
