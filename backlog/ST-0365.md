# Block a merge on a failing or slow mutation command

**Priority:** must-have

## Goal

The implementation agent runs the project's mutation command from `docs/testing.yaml` through a gate script. The merge is blocked when the command fails, is missing, or runs past its time limit. The developer agent runs the same gates in manual mode before it hands a story back.

## Contract

| Operation        | Input state                                                       | Outcome                                               | Persistence         |
| ---------------- | ----------------------------------------------------------------- | ----------------------------------------------------- | ------------------- |
| Mutation gate    | Mutation testing picked, `gates.mutation_testing.command` missing | Fails; the message names the test-strategy agent      | Failing result file |
| Mutation gate    | Command exits 0                                                   | Passes                                                | Passing result file |
| Mutation gate    | Command exits 1                                                   | Fails; merge blocked                                  | Failing result file |
| Mutation gate    | Command runs past `gates.mutation_testing.timeout_minutes`        | The script stops the command and fails; merge blocked | Failing result file |
| Mutation gate    | `timeout_minutes` unset                                           | Limit of 30 minutes                                   | —                   |
| `premerge-check` | A failing mutation result file                                    | Exit non-zero                                         | None                |

The result file is `.current-work/mutation-testing/<story-id>.json`, which `premerge-check` already reads.

## Demo Scenario

1. The operator runs the mutation gate script for ST-0318 on the fixture `mutation-no-command` (Demo Data). It fails and names the test-strategy agent.
2. On `mutation-fails`, it fails after `scripts/mutate.sh` exits 1, and `premerge-check` exits non-zero.
3. On `mutation-slow`, it stops `scripts/mutate.sh` after 1 minute and writes a result file with `passed: false`.
4. The operator reads the developer agent's manual-mode workflow. It runs the same gates before the handback.

## Boundaries

- A gate that cannot run fails.
- The gate script enforces the time limit itself; the agent session sets none (CAO-G27).
- The implementation agent runs the mutation gate in the background, because a foreground Bash call ends after 10 minutes.
- The mutation tool's configuration stays in the project's files (DEC-36).
- `quality-gates: []` stays on this story for the reason ST-0359's Boundaries give.
