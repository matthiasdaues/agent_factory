# Run a measure that needs a running service within one time limit

A measure that tests against a service checks the service first, never runs twice at once, and stops within the time limit.

**Priority:** must-have

## Goal

A measure with a `ready` command runs that command before its measuring command, and two runs of the same measure never overlap. One time limit covers every command of a gate run. When the limit runs out, `crap-score` stops the running command, exits 2, and names the measure and the limit.

## Domain Rule

- For each measure, `crap-score` runs the `ready` command first, when the measure has one. A `ready` command that exits non-zero makes the gate exit 2 and name the measure and the command; no later measure starts (BR-129).
- A disabled gate that a story names still runs its `ready` commands.
- `timeout_minutes` limits all `ready` and measuring commands together. When it runs out, the gate stops the command and its child processes and exits 2.
- A measure with a `ready` command runs under an exclusive operating-system lock on `crap-score/<measure>.lock` under the git common directory, from the `ready` command through the measuring command (DEC-43, DEC-47).
- A run waits for the lock within the time limit and exits 2 when the time runs out while it waits, naming the measure and the lock. A measure without a `ready` command takes no lock. A killed run leaves no lock that blocks the next run.

## Outputs

- `crap-score`: the `ready` run, the time limit over the whole run, and the lock per measure.
- Rows in `tests/factory/test_crap_gate_score.py` and new `tests/factory/test_crap_gate_lock.py`.

## Demo Scenario

1. In the repository of ST-0436, `docs/testing.yaml` adds the measure `backend` with `ready: scripts/crap-ready-backend` before the measure `python`.
2. The User runs `crap-score --base feature/login`. The stubs' log shows `scripts/crap-ready-backend`, then the command of `backend`, then the command of `python`.
3. The User starts the gate in the worktrees of ST-0350 and ST-0351 at once. The log shows that the second `ready` command starts only after the first run of `backend` ends.
4. The User sets `timeout_minutes: 0.05` and a sleeping stub for `python`. The gate exits 2 and names `python` and the limit.
5. The ready stub exits 1. The gate exits 2, names `backend` and `scripts/crap-ready-backend`, and no measuring command starts.
