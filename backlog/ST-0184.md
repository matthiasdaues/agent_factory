# Migrate CRAP threshold to testing.yaml gates section

Replace the dead-code `read_threshold_from_house_rules()` lookup in the `crap-score` script with a live path that reads `gates.crap_score.threshold` from `docs/charter/testing.yaml`. The script continues to accept `--threshold` as the highest-priority override and falls back to its hardcoded default of 30 when `testing.yaml` has no `gates` section.

**Priority:** must-have

## Demo

Set `gates.crap_score.threshold: 8` in `docs/charter/testing.yaml` (delivered by ST-0183). Run `factory/scripts/crap-score` without a `--threshold` flag. The script reports `threshold=8` instead of the old hardcoded default of 30. Remove the `gates` section and run again -- the script reports `threshold=30` (hardcoded fallback).

## Acceptance Criteria

- The `crap-score` script reads `gates.crap_score.threshold` from `docs/charter/testing.yaml` when the `gates` section exists (test-design.feature Rule 15, Scenario 1).
- The `crap-score` script falls back to the hardcoded default of 30 when `testing.yaml` has no `gates` section (test-design.feature Rule 15, Scenario 2).
- The `read_threshold_from_house_rules()` function is removed and replaced by a `testing.yaml` lookup (test-design.feature Rule 15, Scenario 3).
- The `--threshold` CLI flag remains the highest-priority override (existing behavior preserved).
- The `crap-score` skill documentation at `factory/skills/crap-score/SKILL.md` reflects the new threshold source.
- A contract test verifies threshold resolution from `testing.yaml` and fallback to default.

## Scope

**Status quo:** The `crap-score` script's `resolve_threshold()` function tries `--threshold` (CLI), then `read_threshold_from_house_rules()` (which looks for `docs/charter/house-rules.md`, a file that has never existed), then hardcoded default 30. ST-0183 has added the `gates` section to `testing.yaml`.

**Adds:** A YAML-reading function that parses `docs/charter/testing.yaml` and returns `gates.crap_score.threshold`. Replaces `read_threshold_from_house_rules()`. Updates the skill documentation. Contract tests for threshold resolution.

**Out of scope:** Changing the CRAP formula. Changing the default threshold value. Mutation testing gate configuration.

## Notes for the Implementer

The script already uses stdlib-only Python (no PyYAML). Parse `testing.yaml` using the same minimal YAML subset parser pattern used elsewhere in Factory scripts (see `factory/scripts/phase` for precedent). The precedence chain becomes: `--threshold` CLI > `testing.yaml` `gates.crap_score.threshold` > hardcoded 30. New tests target the contract test suite at `tests/factory/test_crap_score.py` (QA strategy IDs TD-CT-09, TD-CT-10).
