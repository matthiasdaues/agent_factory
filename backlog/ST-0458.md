# Read the optional usage add-on's documentation in the handbooks

A user who records usage opens the installed user handbook, learns that the usage add-on is optional, and follows its pages to install it and query the views.

**Priority:** must-have

## Goal

A user finds on the pages of `usage-capture/` in the installed user handbook that the usage add-on `packages/usage/` is optional, how to install it, how to query its views, the two browser UIs, the output formats, and the Python API. A contributor finds the add-on's data pipeline and project structure in `docs/handbook/architecture/` and its three `usage-*-check` scripts in `docs/handbook/testing/`. `packages/usage/docs/ui-exploration.md` is gone, and `usage-ui-doc-check` checks the handbook page instead.

## Domain Rule

- The `usage-capture/` chapter states that the add-on is optional and that the factory runs without it (DEC-15, acceptance criterion 13).
- Each section of `packages/usage/README.md` and `packages/usage/docs/ui-exploration.md` at commit `4ebf5101f70c1540a0d53dcfb3d00cfa977d361a` keeps its facts, commands, and paths on the page that the migration map names. Each section gets one map row.
- A page describes what the code does today. The two source files name paths that the code no longer uses: `factory/scripts/`, `.agent-factory/usage-analysis/`, and an automatic install during fitting. The pages give the current ones: `.agent-factory/factory/scripts/usage-query` and `usage-explore`, `.agent-factory/usage/analysis/`, and `init-factory --with-usage` or `--add usage`. The kept part of the package README is corrected the same way.
- The package README keeps its description, its prerequisites, and its installation steps, as DEC-15 sets. Every other section moves out, and the README links to the `usage-capture/` chapter and to the contributor `architecture/` chapter.
- `usage-ui-doc-check` reads the user handbook page that holds the launch commands, and keeps its three checks: the bootstrap path registers the six views, the `--persist` and explorer commands are documented, and `explorer.py` exists. The page shows the path a user runs in an installed project, so the check resolves `.agent-factory/usage/analysis/` to `packages/usage/` before it reads the bootstrap SQL.
- A file in a record folder changes only in its link destinations (DEC-14, BR-150).

The proposed home of each section is a starting point. The developer may split a section or move it, and records each choice in the migration map.

## Demo Scenario

1. The user runs `update-factory` in a project with the previous release and opens `.agent-factory/factory/docs/handbook/usage-capture/index.md`. The chapter page says that the usage add-on is optional and lists its pages.
2. The user follows the install how-to, runs `.agent-factory/factory/scripts/init-factory --add usage`, and follows the query how-to to `.agent-factory/factory/scripts/usage-query session_usage --format table`, which prints the token usage per CLI tool.
3. The contributor runs `packages/usage/scripts/usage-ui-doc-check`. It reads the handbook page and prints `OK: bootstrap registers 6 published views, explorer module present, persist+explorer documented`.
4. The contributor opens `packages/usage/README.md`. It shows the description and the installation steps, and links to both handbooks.
5. The contributor opens `docs/spec/work/factory-handbooks-migration-map.md` and finds a row for each heading of both source files, each naming an existing page.

## Boundaries

- A user handbook page links only to files inside `packages/factory/`, because only those files install into a project (PROP-07). The links to ADR-0015 and to the bootstrap SQL stay on contributor pages and in the package README.
- No page states a binding rule in ordinary prose (DEC-02, BR-149).
- The story changes no page that ST-0453 wrote outside `usage-capture/`, and no page that ST-0456 wrote outside `architecture/` and `testing/`.
- Every page passes `handbook-lint`, and `handbook-index` writes the page lists in the same commit.
- `init-factory` copies `packages/usage/docs/` only when the folder exists, so the deletion needs no install change. `tests/factory/test_distribution_lifecycle.py` seeds its own copy of the folder and stays unchanged.
- No edit of a feature file, `validation-rules.md`, `interface-contracts.md`, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-ST-0458.md`.
- `quality-gates` is empty. The story changes one Python script, `usage-ui-doc-check`, but the crap-score gate of `docs/testing.yaml` measures only `packages/factory/scripts/*`.
