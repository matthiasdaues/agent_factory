# Create detect-test-regime skill

Create the `detect-test-regime` skill at `factory/skills/detect-test-regime/SKILL.md`. The skill scans a project for evidence that a test regime exists and records the result in `docs/charter/testing.yaml`. Code is the source of truth; the charter is a derived record.

**Priority:** must-have

## Acceptance Criteria

- `factory/skills/detect-test-regime/SKILL.md` exists as a complete skill definition
- The skill scans for: Makefile with a `test` target, `package.json` with a `test` script, `tox.ini` or `tox` section in `pyproject.toml`, `noxfile.py`, `Justfile` with a `test` recipe, `Taskfile.yml` with a `test` task, and other conventional entrypoints
- When one entrypoint is found: records it in `docs/charter/testing.yaml` as `test_command`
- When multiple entrypoints are found: asks the user for disambiguation; does not guess
- When no entrypoint is found: surfaces the gap to the operator
- The skill also scans for identifiable test layers (conftest.py, test directories, Makefile targets, runner configs) and records layer bindings in the `layers` section when identifiable
- The skill follows the standard skill file format with frontmatter, inputs, outputs, and steps

## Implementation Notes

- Detection surface should be broad; code is the source of truth
- The skill is invoked by `init-factory` (wired in ST-0154) and by the kit-manager during onboarding
- The charter serves as a backup reference when detection is ambiguous
- Tier is standard per dispatch-contract tier rubric: default tier, no simpler rule matches
