# Get different IDs from claims that run at the same time

**Priority:** must-have

## Goal

When several sessions run `next-id` at the same moment, for one ID prefix or for several, every call exits `0` with its own ID, and no number of a prefix is skipped. A claim that the remote refuses for a reason other than a stale lease ends after one push and shows git's message.

## Contract

| Operation               | Input state                                                                           | Outcome                                                                                  | Persistence                                      |
| ----------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `next-id ST`            | Another claim pushes a new claim commit after this claim read the counter             | Waits a random 0.1 to 1 second, reads the counter again, and prints the next free number | Line `ST` raised once more                       |
| Race harness, 20 rounds | Two clones of one seeded bare repository; 10 rounds `ST`+`ST`, 10 rounds `ST`+`FAGAN` | All 40 IDs differ; no `ST` or `FAGAN` number is skipped; every call exits `0`            | Lines `ST` and `FAGAN` match the printed maximum |
| Eight claims at once    | One seeded bare repository; mixed prefixes                                            | All eight exit `0` with eight different IDs; none uses up its ten stale leases (QS-19)   | Each prefix line raised by its number of claims  |
| `next-id ST`            | A `pre-receive` hook moves `refs/ids/counters` before every push                      | Ten stale leases, then exit non-zero; nothing on standard output; names `ST` and `1001`  | Ref holds the hook's last claim commit           |
| `next-id ST`            | A `pre-receive` hook prints `read-only` and exits `1`                                 | One push; exit non-zero; nothing on standard output; the message holds `read-only`       | Ref unchanged                                    |
| Stale-lease check       | git output `stale info`, or `cannot lock ref … is at <sha> but expected <sha>`        | Counts as a stale lease                                                                  | —                                                |
| Stale-lease check       | Any other refusal, such as `pre-receive hook declined`                                | Counts as final                                                                          | —                                                |

## Demo Scenario

1. The User runs `uv run python tests/factory/next_id_race.py --rounds 20`. The harness creates its own local bare repository, seeds it with `next-id --seed 1000`, makes two clones, and runs two `next-id` calls per round.
2. It reports 40 different IDs, no skipped number of `ST` or `FAGAN`, and 40 calls with exit `0`.
3. The User installs the `read-only` `pre-receive` hook of Demo Data in `/tmp/remote.git` and runs `next-id ST --remote /tmp/remote.git`. It exits non-zero after one push, prints no ID, and shows `read-only`. The hook log holds one line.

## Demo Data

| Item             | Value                                                                                                                             |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Bare repository  | `/tmp/remote.git`, seeded with `next-id --seed 1000` (ST-0368)                                                                    |
| `read-only` hook | `/tmp/remote.git/hooks/pre-receive`: appends one line to `/tmp/hook.log`, prints `read-only` on standard error, exits `1`         |
| Stale-lease hook | `pre-receive` that writes a claim commit with only `start=1000` and a fresh token, moves the ref with `git update-ref`, exits `0` |

The race harness seeds its own repository, so the story extends no seed set.

## Boundaries

- Only `stale info` and `cannot lock ref … is at <sha> but expected <sha>` lead to a retry (BR-072, DEC-23). Every other refusal ends the claim after one push.
- The wait before a retry is a random time between 0.1 and 1 second. After ten stale leases in a row, the claim fails.
- The harness takes `--remote <url>` and `--rounds <n>`. Without `--remote`, it creates its own local bare repository. Its usage text says that a run with `--remote` needs a repository without a counter in use and that the person deletes `refs/ids/counters` there afterwards (`CID-QG03`).
- The harness keeps the round plan of `poc/counters/ref-claim-race.sh`: odd rounds claim `ST` twice, even rounds claim `ST` and `FAGAN`.
- Ten stale leases are tested as the feature file states (`Gap: CID-G01`, CIDP-C05), not with a refusing `pre-receive` hook.
- Each test uses its own bare repository, so the tests run in parallel under `-n auto`.
