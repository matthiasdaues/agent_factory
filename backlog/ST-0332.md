# See a failed migration roll the whole update back

**Priority:** must-have

## Goal

When `migrate-spec-layout` fails during an approved update, the project
maintainer finds every project file, `.pre-commit-config.yaml`, the factory
tree, and the factory version as they were before the update, and
`update-factory` reports the failure.

## Contract

| Operation                         | Input state                                                                                          | Outcome                                                                                                                                               | Persistence            |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| `update-factory`, update approved | Old layout, installed `1.3.3`; the migration fails after one link rewrite and the hook-block rewrite | Project files at old paths with old content; `.pre-commit-config.yaml` old; factory tree old; `install.json` `1.3.3`; failure reported; exit non-zero | All restored           |
| `update-factory`, update approved | Same project; migration succeeds                                                                     | As ST-0330                                                                                                                                            | New layout and version |

## Demo Scenario

1. The maintainer builds the fixture `installed-1.3.3-failing` (Demo Data) and
   copies the project and its `.agent-factory/factory/` tree aside.
2. The maintainer runs `update-factory` from a source with `VERSION` `1.4.0`
   and approves the update.
3. The output reports the failed `init-factory` and the rollback.
4. `diff -r` of the project and the factory tree against the copies shows no
   difference, and `install.json` records `1.3.3`.

## Demo Data

The story extends the fixture helper of `tests/factory/test_update_factory.py`.

| Fixture                   | Content                                                                                                                                                                    |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `installed-1.3.3-failing` | `installed-1.3.3` of ST-0330 plus `old-layout-hooks` content of ST-0322, with one folder made read-only so the migration fails after the link rewrite and the hook rewrite |

## Boundaries

- `_rollback_update` restores the factory tree, the manifest, the checksums,
  and the wiring, as for any failed `init-factory` (ADR-0023 step 6).
- `migrate-spec-layout` restores the project files and the hook block itself
  (ST-0322). `update-factory` does not add a second project-file undo.
- Pre-alpha: only an installed `update-factory` `v1.1.0-rc` or later is
  covered.
- No test-only switch in a production script forces the failure.

## Affected Paths

- `packages/factory/scripts/update-factory` — existing; only if the integration
  test shows a gap in `_rollback_update` or in the failure report.
- `tests/factory/test_update_factory.py` — existing; the rollback integration
  case.

## Inputs

- ST-0330: the migration call and the version write after success.
- ST-0322: the full undo of `migrate-spec-layout`, the hook block included.
- Current code: `_rollback_update` and its call after `_run_init` in
  `packages/factory/scripts/update-factory`.
- ADR: [ADR-0026](../docs/adr/0026-layout-migration-runs-inside-the-factory-update.md).
- Scenario covered, in [core-artifact-layout.feature](../docs/spec/core-artifact-layout.feature):
  "A failed migration rolls the update back".
- Contract owned by this story (EPIC E5 Ownership Resolution): CAL-07-IT-03.

## Evidence

- [ ] After the forced failure, every project file and `.pre-commit-config.yaml`
  are byte-equal to the copy taken before the update, the factory tree equals
  the old tree, `install.json` records `1.3.3`, and the output names the
  failure (CAL-07-IT-03).

Test budget: CAL-07-IT-03 is `critical`; one case with a Forbidden line for

## Out of Scope

- Changes to `migrate-spec-layout` itself.
- Updaters before `v1.1.0-rc`.

## Agent Stop Conditions

- The read-only folder does not make the migration fail on the test runner,
  for example because tests run as root. Report it and propose another
  file-system seam; do not add a flag to the script.
- `_rollback_update` cannot restore the factory tree because the backup is
  missing at that point. Report the order of steps.
