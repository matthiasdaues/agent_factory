# Install Codex skills agents aliases and hooks

Extend `init-factory` with a dedicated Codex adapter instead of treating Codex
as another shared dot-directory layout.

**Priority:** must-have

## Acceptance Criteria

- Each Factory skill is symlinked individually under `.agents/skills`.
- Every Factory agent is generated under `.codex/agents`; INDEX, playbooks,
  rulebooks, and scripts are linked under `.codex`.
- `.codex/hooks.json` merge-installs `PreToolUse`/`^Bash$`, `Stop`, and
  `SubagentStop` entries using Git-root-resolved commands.
- Re-runs are idempotent and refresh Factory-owned generated agents.
- Project-owned `.agents`, `.codex`, hooks, skills, agents, and root `AGENTS.md`
  are preserved; collisions stop without overwriting.
- Orientation documents Codex's local skill and agent paths and full 40-character
  SHA rule.
- Installation reports skipped project orientation and `/hooks` trust actions.

## Analysis

Codex requires a dedicated adapter because repository skills live under
`.agents/skills`, native custom agents are generated TOML, and supporting
catalog aliases and hooks live under `.codex`. The installer therefore runs a
read-only Codex preflight before creating the shared root orientation or any
Codex artifact. It rejects unsafe ancestors and hook files, checks every
Factory-named destination, and treats a generated ownership marker as
refreshable only when the prior installation manifest also owns that exact
path.

The adapter installs individual skill links, generates agents from the copied
canonical definitions, links the Codex catalog aliases, and merges root-resolved
guardrail and capture commands into project hooks. The manifest records the
exact generated agents and only the hook handlers this installation appended.
Focused tests cover fresh and mixed project layouts, idempotent refresh,
collision atomicity, unsafe ancestors, spoofed ownership, handler provenance,
orientation reporting, and execution from a nested working directory.

No specification change was needed: this implements the approved Codex proposal
resolution while retaining the existing non-interference and local-first
contracts.
