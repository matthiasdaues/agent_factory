# Migrate the factory's own repository into the new layout

**Priority:** must-have

## Goal

The factory maintainer runs `packages/factory/scripts/migrate-spec-layout` on
the factory's own repository, and it exits 0. A newcomer who lists
`docs/spec/` then finds only single-file core artifacts and the folders
`features/`, `areas/`, and `work/`. The seven gates exit 0 on the migrated
repository, and the repository's local hooks read the new paths.

## Domain Rule

- The factory's repository moves with the same script that installed projects
  receive. No file moves by hand (Proposal Scope).
- Every chapter 12 section, "Acronyms and Abbreviations" included, ends as a
  Term/Definition/Avoid table.
- No actor-goal list and no `use_cases` folder remain under `docs/`.
- An old path the script lists is fixed by hand in this story. `CHANGELOG.md`
  and `reports/` keep their history and are not edited.
- `docs/CONTEXT.md` and `docs/arc42/CONTEXT-MAP.md` stay until ST-0344 folds
  them.

## Outputs

- **Migration.** The repository in the new layout, as the script leaves it.
  The script's output is recorded in this story's report as the acceptance
  record of CAL-14-AC-01.
- **Glossary.** `docs/spec/glossary.md` with one Term/Definition/Avoid table per
  section. Where the script copies a two-column table with other column names,
  such as Abbreviation and Meaning, the columns read Term and Definition.
- **Local hooks.** The `repo: local` hooks of `.pre-commit-config.yaml` read the
  new paths; every explicit old-path argument added by E3 goes. The factory
  hook block matches the new template after the human touchpoint.
- **Hand fixes.** Every file the script lists, outside `CHANGELOG.md` and
  `reports/`, names the new path. That includes `backlog/` references to
  `docs/spec/core-artifact-layout.feature` and `supplementary_specs/`,
  `pyproject.toml`, and the docstrings of `test_context_lint.py`,
  `test_context_lint_legacy.py`, `test_format_detection.py`,
  `test_hook_demo.py`, and `test_onboarding_sandbox.py`, which name this
  repository's QA strategies.
- **Tests.** `test_core_layout_gates.py` gains the all-pass test on the
  repository (CAL-14-IT-01). `test_core_layout_references.py` gains the layout
  check of `docs/spec/` (CAL-01-LN-01) and the glossary and no-use-case check
  (CAL-14-LN-01). `test_precommit_config_contract.py` gains the factory row of
  CAL-09-IT-02.
- **Test markers.** Remove the `xfail(strict=True)` markers that ST-0325 put on
  `test_hook_missing_factory.py::test_repo_config_factory_block_matches_template`
  and `test_update_factory.py::TestRefreshPrecommitHooks::test_this_repository_needs_no_refresh`.
  Both tests pass again once the factory hook block matches the template.
- **Paired story.** ST-0343 first merges `story/ST-0327`, then runs the
  repository's migration. Both land on the invocation branch before the
  spec-lint hook runs there, because ST-0327's `spec-lint` reads only the new
  paths (stakeholder decision of 2026-11-02).

## Human Touchpoint

After the migration and before this story commits, the factory maintainer runs
this command in their own terminal, in the checkout that holds the migrated
working tree:

```bash
.agent-factory/factory/scripts/update-factory --target .
```

The command asks for confirmation, so no agent can run it. It reinstalls the
factory from `packages/factory/` and rewrites the factory hook block of
`.pre-commit-config.yaml` from the new template. Until it has run, the
installed copy under `.agent-factory/factory/` and the factory hook block do
not match the new layout, and the commit's hooks may fail.

This story runs in manual mode in the primary checkout, not in a worktree.
Every worktree shares the primary checkout's `.agent-factory/`, and
`install.json` there records `1.3.3`. So the update runs `migrate-spec-layout`
on its target. On the migrated working tree that run has no work. On a primary
checkout still in the old layout, it would move the files there.

**Blocking condition.** The developer agent stops after the migration, the hand
fixes, and a green test run, and reports that it waits for this command. It
commits only after the maintainer confirms the run.

   It prints nothing.
5. The maintainer runs `pre-commit run --files docs/spec/architecture.dsl`.
   Pre-commit runs `arch-lint`.

## Boundaries

- Run the script, then fix what it lists. Never move a core file by hand.
- Do not edit `packages/factory/CHANGELOG.md` or anything under `reports/`.
- Do not edit `.agent-factory/`. The touchpoint reinstalls it.
- Markdown edits under `packages/factory/` come only from the script's link
  rewrites. A non-Markdown old path in `packages/factory/` outside the
  exclusions means an earlier story missed a file; stop (see Agent Stop
  Conditions).
- The container suite runs before this story merges (CAL-G09).
- Rules that hold for every EPIC apply: no DBML, no blocking glossary gate, no
  todo-list merge.

## Agent Stop Conditions

- The script exits non-zero on this repository. Report its output; do not move
  files by hand.
- The script lists an old path in a non-Markdown file under `packages/factory/`
  outside `CHANGELOG.md` and `reports/`. An earlier story missed it; report the
  file and the story that owns it by the CAL-G08 assignment.
- A gate fails on the migrated repository for a reason other than an old path.
  Report the gate and the finding.
- The touchpoint has not run. Stop before the commit and report that the story
  waits for the factory maintainer.
- The story was dispatched into a worktree. Stop before the touchpoint and
  report it: the update would run on the primary checkout, which is still in
  the old layout.
- `update-factory` reports that it has nothing to update, so the factory hook
  block keeps old values. Report its output; the maintainer decides how to
  refresh the block.
- Docker is not available, so the container suite cannot run before the merge.
  Report it.
