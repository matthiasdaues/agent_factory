# Count only the project's release tags and fail closed without the setting

**Priority:** must-have

## Goal

The user lists the project's release tag patterns in `docs/factory-settings.yaml` and sees the git check count only the tags that match. Without the file or the key, a due git check exits `1` and names both. `init-factory` and `update-factory` never write the file.

## Contract

| `docs/factory-settings.yaml`                         | Git check due                       | Lines only at `v1.0.0` | Result                                                   |
| ---------------------------------------------------- | ----------------------------------- | ---------------------- | -------------------------------------------------------- |
| `release_tag_patterns: ["v[0-9]*"]`                  | yes                                 | `in_use: false`        | exit `1`, `artifact lines exist unchanged at tag v1.0.0` |
| same; lines only at `1.1.0` or `orchestrator-v0.1.0` | yes                                 | `in_use: false`        | exit `0`                                                 |
| `release_tag_patterns: []`                           | yes                                 | `in_use: false`        | exit `0`; branches and installed copy still count        |
| file missing, or key missing                         | yes                                 | any                    | exit `1`, the message of the contract                    |
| file missing                                         | no, only a document finding changed | any                    | exit `0`, no setting named                               |
| key holds no list of strings                         | yes                                 | any                    | exit `1`, names the file and the key                     |

A tag counts when `git tag --list '<pattern>'` lists it for one pattern.

## Demo Scenario

1. The User takes `/tmp/inuse-demo` from ST-0393 and adds the tags `v1.0.0`, `v1.1.0-rc`, `1.1.0`, and `orchestrator-v0.1.0`.
2. Without `docs/factory-settings.yaml`, `finding-lint` on FAGAN-0042 exits `1` and prints `docs/factory-settings.yaml: key release_tag_patterns is missing. Add the list of git tag patterns that count as releases, such as ["v[0-9]*"], or [] for none.`
3. The User commits `release_tag_patterns: ["v[0-9]*"]`. With the lines only at `v1.0.0`, the lint exits `1` and names `tag v1.0.0`.
4. The User sets `release_tag_patterns: []`. The lint exits `0`.

## Demo Data

Extends `/tmp/inuse-demo` of ST-0393 with the four tags of the QA strategy's test setup.

## Boundaries

- The parser reads the one key with the standard library only. It accepts a flow list of quoted strings and `[]`, which the contract names, and the block list only if question 1 says so.

- The setting is read only when a git check is due.
