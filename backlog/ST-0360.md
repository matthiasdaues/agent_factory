# Report drift as a row of the story's spec-feedback report

**Priority:** must-have

## Goal

When an implementation reveals drift, the developer agent writes a row into its story's own spec-feedback report and changes no specification file. The row names the artifact's owner, so the owner can fix it.

## Contract

| Operation                      | Input state                                          | Outcome                                                                                                                              | Persistence                                  |
| ------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| Read the output declarations   | After this story                                     | Developer and implementation agents declare no `docs/spec/**/*.md`; the developer agent declares `docs/spec/work/spec-feedback-*.md` | —                                            |
| `spec-feedback` Step 2         | `validation-rules.md` lacks a rule the code needs    | Row with Artifact, Drift, Evidence, `owner: domain-modeling-agent`, status `open`                                                    | `docs/spec/work/spec-feedback-<story-id>.md` |
| `spec-feedback` Step 2         | Any drift                                            | No specification file changes                                                                                                        | None                                         |
| Two developer agents of a wave | Both find drift                                      | Two reports, one per story                                                                                                           | Two files                                    |
| Harness-mismatch check         | The test harness cannot test a contract at its layer | Row with `owner: test-strategy-agent`                                                                                                | The story's report                           |
| Read `INDEX.yaml`              | After this story                                     | The developer agent declares `docs/findings/QA-*.md` as working output (ST-0358 row 3)                                               | —                                            |

## Demo Scenario

1. While implementing ST-0318, the developer agent finds that the migration script must refuse a dirty repository, and `validation-rules.md` has no such rule.
2. `docs/spec/work/spec-feedback-ST-0318.md` gains the row `docs/spec/validation-rules.md | refuse a dirty repository | scripts/migrate-spec-layout:88 | domain-modeling-agent | open`.
3. `git status` shows `docs/spec/validation-rules.md` unchanged.

## Demo Data

None. The row uses the story ID ST-0318 and the file `docs/spec/validation-rules.md`, which exist in the repository.

## Analysis

- **What changes.** The developer agent and the implementation agent drop the output `docs/spec/**/*.md`. The developer agent declares `docs/spec/work/spec-feedback-*.md` and `docs/findings/QA-*.md` as working output, with `required: false` and no `reviewed_by:`. Step 2 of `spec-feedback` writes a row into `docs/spec/work/spec-feedback-<story-id>.md` and changes no specification file. The harness-mismatch check of the developer agent writes a row with `owner: test-strategy-agent`.
- **Files.** `packages/factory/agents/developer-agent.md`, `packages/factory/agents/implementation-agent.md`, `packages/factory/skills/spec-feedback/SKILL.md`, `packages/factory/INDEX.yaml` (regenerated), `tests/factory/test_core_artifact_ownership_text.py` (new class for CAO-13-LN-01), and `tests/factory/test_core_artifact_ownership.py` (the strict xfail of CAO-10-LN-02 becomes a plain case).
- **Scenarios.** All four Scenarios of the Rule "Developer agent reports specification drift without editing the specification". The tests read the text of the agent definitions, the skill, and `INDEX.yaml`. No test runs an agent, so the Demo Scenario stays a text check of the instructions.
- **Seams.** The frontmatter of the two agent definitions, their entries in `INDEX.yaml`, the `## Step 2` section of `spec-feedback`, and step 6 of the developer agent's workflow.
- **Stop conditions.** No other skill of the developer agent writes into `docs/spec/`. `implement-issue` Step 5 still says "spec is either confirmed accurate or updated"; it only calls `spec-feedback`, so it writes nothing itself. The code and ADR-0029 agree on the report path.
