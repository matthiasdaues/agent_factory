# Start feature work in a migrated project with the four anchor files

**Priority:** must-have

## Goal

The project maintainer starts `feature-addition` in a migrated project and
passes the anchor-file check with `docs/spec/architecture.dsl`,
`docs/spec/scope-map.md`, `docs/spec/glossary.md`, and `docs/agent-context.md`,
without a `docs/CONTEXT.md`. When a file is missing, the playbook names it and
suggests `brownfield-onboarding`. The Stage 1 exit of `brownfield-onboarding`
checks the same four files.

## Contract

| Operation                            | Input state                                                  | Outcome                                                                    | Persistence |
| ------------------------------------ | ------------------------------------------------------------ | -------------------------------------------------------------------------- | ----------- |
| `feature-addition` start             | All four anchor files; no `docs/CONTEXT.md`                  | Check passes; the playbook proceeds                                        | None        |
| `feature-addition` start             | One anchor file missing, for example `docs/spec/glossary.md` | Names `docs/spec/glossary.md` as missing; suggests `brownfield-onboarding` | None        |
| `brownfield-onboarding` Stage 1 exit | DSL, scope map, glossary; no `docs/agent-context.md`         | Names `docs/agent-context.md` as missing                                   | None        |

## Demo Scenario

1. In the migrated fixture `anchored-project` (Demo Data), the maintainer
   starts `feature-addition`. The anchor-file check passes, and the playbook
   proceeds.
2. The maintainer deletes `docs/spec/glossary.md` and starts `feature-addition`
   again. It reports `docs/spec/glossary.md` as missing and suggests
   `brownfield-onboarding`.

## Demo Data

The playbook check runs in an agent session, so the demo uses a hand-built
fixture. The retained test is a text check and needs no fixture.

| Fixture            | Content                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `anchored-project` | `docs/spec/architecture.dsl`, `docs/spec/scope-map.md`, `docs/spec/glossary.md`, `docs/agent-context.md`; no `docs/CONTEXT.md` |

## Boundaries

- The anchor set is exactly the four files (`ANCHOR_FILE_SET`). `docs/CONTEXT.md`
  is never an anchor file.
- Each missing file is named on its own.
- No other change to the two playbooks.
- Spec edits stay in the three `implemented` Rules of
  `newcomer-onboarding.feature` that CAL-G15 names for this story, their
  scope-map rows, and § Anchor-file prerequisite of `validation-rules.md`.
  The reverse-map Rule belongs to ST-0337.
- `docs/spec/newcomer-onboarding.feature` moves to `docs/spec/features/` only in
  ST-0343. This story edits it at its current path.
