# Class-aware re-dispatch disposition logic

Extend `dispatch re-dispatch` to apply the per-class disposition rules from the
failure-class vocabulary. Each class determines whether re-dispatch proceeds at
the same tier, requires escalation first, or is terminal. The `contract_violation`
class is terminal after two occurrences. Classes `acceptance_unmet` and
`contradictory_evidence` require escalation before re-dispatch.

**As a** dispatch user,
**I want** re-dispatch to follow the documented disposition for each failure
class,
**so that** the correct recovery action is applied mechanically and escalation-
requiring failures cannot bypass the escalation gate.

**Priority:** must-have

## Acceptance Criteria

1. `context_missing` re-dispatches at the same tier with amended handoff.
2. `contract_violation` first occurrence re-dispatches at the same tier.
3. `contract_violation` second occurrence is terminal (non-zero exit).
4. `environment` re-dispatches at the same tier.
5. `spend_death` re-dispatches at the same tier.
6. `seam_defect` re-dispatches the seam session at the same tier.
7. `acceptance_unmet` requires escalation before re-dispatch (non-zero exit
   without prior escalation).
8. `contradictory_evidence` requires escalation before re-dispatch.
