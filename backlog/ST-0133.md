# Failure-class vocabulary and evidence validation on dispatch mark-failed

Extend `dispatch mark-failed` with `--class` (seven-value closed vocabulary)
and `--evidence <path>` (must be a tracked artifact). Reject unknown classes
and untracked evidence paths. Record the failure class and evidence in the
ledger's story entry.

**As a** dispatch user,
**I want** failure classification to use a validated vocabulary with tracked
evidence,
**so that** re-dispatch disposition and escalation decisions are based on
structured data, not free text.

**Priority:** must-have

## Acceptance Criteria

1. `dispatch mark-failed --class <class> --evidence <path>` accepts exactly
   these seven classes: context_missing, contract_violation, environment,
   spend_death, seam_defect, acceptance_unmet, contradictory_evidence.
2. An unknown failure class is rejected (non-zero exit).
3. An untracked evidence path is rejected (non-zero exit); tracked is verified
   via `git ls-files`.
4. The failure class and evidence path are recorded in the ledger's story entry.
5. The `--class` and `--evidence` flags are required (omitting either exits
   non-zero).

## Analysis

Implemented as specified: `--class` uses `choices=FAILURE_CLASSES` (the
seven-value closed vocabulary, defined once in `dispatch_lib.FAILURE_CLASSES`)
and is `required=True`; `--evidence` is `required=True` and validated via
`git ls-files -- <path>` returning a non-empty match before any ledger
mutation happens. `StoryEntry` gained `failure_class` and `evidence` fields
(persisted in `to_dict`/`from_dict` only when set, matching the existing
optional-field convention). `cmd_mark_failed` performs the evidence check
first, then transitions the story to `FAILED` via the existing state
machine, and only overwrites `failure_class`/`evidence` when the transition
was not a same-state no-op (preserving original failure metadata on repeated
`mark-failed` calls against an already-`FAILED` story, consistent with
existing idempotency behaviour for `mark-blocked`'s `reason`).
Extended `tests/test_dispatch_lifecycle.py` with the required five test
names plus updated the two pre-existing `mark-failed` CLI tests, since they
now must supply valid `--class`/`--evidence` and a tracked evidence file to
reach the transition logic being tested.
