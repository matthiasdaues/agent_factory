# Stop every dispatch and merge while a critical finding is unconfirmed

**Priority:** must-have

## Goal

The stakeholder sees `dispatch` and `premerge-check` exit `1` and print the stop notice while a `critical` finding has no text in both `stop_confirmed_by` and `stop_confirmed_reason`. Reads and status queries still answer. Once both fields hold text, both scripts run again.

## Contract

| Finding state (working tree or `HEAD`)                                                              | `dispatch` start or merge subcommand          | `dispatch` read subcommand | `premerge-check`                 |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------- | -------------------------- | -------------------------------- |
| One version `severity: critical` with `status: open` or a `review_class`, neither version confirmed | exit `1`, stop notice                         | runs                       | exit `1`, stop notice, no marker |
| `stop_confirmed_by: human` and an empty `stop_confirmed_reason`                                     | exit `1`                                      | runs                       | exit `1`                         |
| One version holds text in both fields                                                               | runs                                          | runs                       | runs its other checks            |
| `HEAD` critical and unconfirmed; working tree lowered to `major`, `waived`, or removed              | exit `1`; the notice reads the `HEAD` version | runs                       | exit `1`                         |
| No critical finding                                                                                 | runs                                          | runs                       | runs                             |

The start or merge subcommands are `init`, `prepare-wave`, `prepare-story`, `mark-dispatching`, `mark-dispatched`, `re-dispatch`, `escalate`, `refresh-story`, `merge-story`, and `close-wave`. The read subcommands are `status`, `plan`, `suggest-merge-args`, `verify-story`, `mark-done`, and the other names of BR-091. Every subcommand of the parser is in exactly one list.

The stop notice goes to standard output, byte for byte the same from both scripts, as the example of the stop contract shows: the `STOP` line, the finding ID and title, the artifact, the `in_use` evidence, each `## Possible damage` item with its check, and the confirmation step.

## Demo Scenario

1. The User prepares `/tmp/stop-demo` with the ledger fixture of `test_dispatch_run_blockers.py` and writes `docs/findings/BUG-0037.md` from the Demo Data.
2. The User runs `dispatch prepare-wave 1`. It exits `1` and prints the stop notice with "merges on `dev` from dispatch runs since the installed copy was last updated — check: compare `git log --merges dev` with the merges the dispatch log records".
3. The User runs `dispatch status`. It answers.
4. The User runs `premerge-check dev feature/core-artifact-ownership`. It prints the same notice, exits `1`, and writes no `.current-work/premerge-check-ok`. An agent's `git merge feature/core-artifact-ownership` is then denied by `block-dangerous-git.sh`.
5. The User writes `stop_confirmed_by: human` and `stop_confirmed_reason: compared 14 merges, none lost` in an editor. Both scripts run again.

## Boundaries

- The stop check reads `docs/findings/*.md` of the working tree it runs in and their `HEAD` versions with `git show`, and changes no file.
- A status change, a lower severity, or a removed file in the working tree never ends a stop (DEC-57 to DEC-59).
- A new subcommand of `dispatch` that is in neither list fails the contract test, so a later subcommand cannot slip past the stop (FC-QG13).
- During a stop, `premerge-check` runs the stop check before any other check and writes no marker.
- The story does not change `block-dangerous-git.sh`.
- Tests build their repositories in `tmp_path`.
