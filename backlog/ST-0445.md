# Refuse to start a run while a ready command of the CRAP gate fails

`dispatch init` checks every `ready` command of an enabled gate once and starts no run while one fails.

**Priority:** must-have

## Goal

`dispatch init` runs the `ready` command of every measure of an enabled gate once, from the root of the primary checkout, before it cuts the feature branch or writes the ledger. When one fails, `init` exits 1, names the measure and the command, and leaves no branch, worktree or ledger behind. A gate with `enabled: false` runs no `ready` command.

## Domain Rule

- The check runs before any change to the repository (BR-137, DEC-23).
- It runs on both ways, `--mode orchestrated` and `--mode by-hand`.
- Only an enabled gate counts here; a disabled gate that a story names runs its `ready` commands later, in the gate run.
- `crap-score` already holds three rules that `init` relies on when it reads the measures, and this story adds their tests: a measure name that is no safe file name, or a `ready` value that is not a non-empty string, makes the gate exit 2 (DEC-59). The shape check covers every row, also rows that the filter drops (DEC-53). The register is read from `refs/heads/dev` only, only its first table under `## CRAP score` counts, and the accepted score is a plain decimal (DEC-55).

## Outputs

- `dispatch init`: the `ready` run and the refusal.
- Rows in `tests/factory/test_crap_gate_dispatch.py`.

## Demo Scenario

1. A temporary repository has `dev` and an enabled `gates.crap-score` with the measure `backend` and `ready: scripts/crap-ready-backend`. The ready stub exits 1.
2. The User runs `dispatch init --mode by-hand --feature-branch feature/login --stories ST-0350`. It exits 1 and names `backend` and `scripts/crap-ready-backend`.
3. `git branch` shows no `feature/login`, `git worktree list` shows only the primary checkout, and no ledger exists.
4. The ready stub exits 0. `dispatch init` starts the run, and the stub's log shows one start in the primary checkout.

## Demo Data

The tests write the repository and the ready stub. No seeding script is involved. The measure is `backend` of ST-0438.

## Boundaries

- A refused `init` changes nothing in the repository.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- The story changes the built scripts in place and rebuilds none of them.
- No edit of the specification, the architecture, the proposal, or the QA strategy. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
