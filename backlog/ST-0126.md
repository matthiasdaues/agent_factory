# step-guard script: read guard and write guard with security deny-list

Create `factory/scripts/step-guard`, a shared enforcement script that accepts
a tool event as JSON and a guard type. Implement the `read` and `write` guard
types. The read guard checks file paths against declared `inputs` globs and
always-allowed prefixes. The write guard checks against declared `outputs`
globs, allows `docs/findings/*` and gate markers, and explicitly denies writes
to `dispatch-ledger.yaml` and `current-step.yml` (security boundary).

**As a** step agent,
**I want** the read and write guards to enforce my declared scope,
**so that** I cannot accidentally read undeclared inputs or write outside my
declared outputs, and I can never corrupt script-owned state files.

**Priority:** must-have

## Acceptance Criteria

### Read guard

1. A file matching a declared input glob is allowed.
2. A file matching an always-allowed prefix (`factory/`, `.claude/`, `.github/`,
   `.pi/`, `.codex/`, `.current_work/`) is allowed regardless of declared
   inputs.
3. A file outside declared inputs and allowed prefixes is denied.
4. No enforcement when the step manifest is absent.

### Write guard

05. A file matching a declared output glob is allowed.
06. `docs/findings/*` is always allowed.
07. Gate markers (`.current_work/verify-base-ok`,
    `.current_work/premerge-check-ok`) are always allowed.
08. `dispatch-ledger.yaml` under `.current_work/` is always denied.
09. `current-step.yml` under `.current_work/` is always denied.
10. A file outside declared outputs and allowed paths is denied.
11. No enforcement when the step manifest is absent.

### Script structure

12. `step-guard` is an executable script accepting `--guard-type read|write`
    and a JSON tool event on stdin.
13. The script uses the shared glob matching from `dispatch_lib.py`.
