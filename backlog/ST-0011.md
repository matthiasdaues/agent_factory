# Add --changed-only mode to run-tests for fast pre-commit feedback

Extend `factory/scripts/run-tests` with a `--changed-only` mode that applies
framework-specific fast filters for sub-second feedback on small changes
(BR-025). This mode is invoked by the pre-commit hook to catch test failures
immediately without waiting for the full suite.

Framework-specific optimizations: pytest uses `--lf` (last-failed) or
`--testmon` if available, jest uses `--onlyChanged`, go test and cargo test
filter by package/crate path derived from git diff.

**Priority:** must-have

## Acceptance Criteria

- `--changed-only` flag implemented in `factory/scripts/run-tests`.
- Reads `git diff --name-only HEAD` to get list of changed files since last
  commit.
- Applies framework-specific fast filtering (BR-025):
  - **pytest**: uses `uv run pytest --lf` (last-failed) or `uv run pytest --testmon` if testmon is installed; if neither available, falls back to
    filtering test files from git diff
  - **jest**: uses `npm test -- --onlyChanged` (jest's built-in changed file
    detection)
  - **go test**: derives package paths from changed `.go` files, runs `go test <packages>`
  - **cargo test**: derives crate names from changed `Cargo.toml` or `.rs`
    files, runs `cargo test -p <crate>`
- If no changed files: exit `0` with message "No changed files to test"
  (success, nothing to validate).
- If changed files but none trigger tests: exit `0` with message "No tests for
  changed files".
- If tests are triggered: runs filtered tests, emits JSON summary, exits with
  appropriate code (0/1/2).
- Same stderr/stdout separation as `--full` mode.
- Usage help updated to document `--changed-only` mode.

## Implementation Notes

**Fast filter intent:**

The goal is sub-second feedback for small changes. Each framework's filter
should prefer "run less but run smart" over exhaustive coverage — the pre-push
hook and phase advance gate run `--full` to ensure nothing is missed.

**pytest --lf vs --testmon:**

- `--lf` (last-failed) re-runs only tests that failed in the previous run
- `--testmon` uses coverage tracing to re-run tests affected by code changes
- Check for testmon install: `python -c "import pytest_testmon"` → if succeeds,
  use `--testmon`; if fails, use `--lf`

**jest --onlyChanged:**

Jest has built-in git-aware change detection. Simply pass `--onlyChanged` and
jest handles the rest.

**go test package filtering:**

- Extract directory of each changed `.go` file
- Map to Go package path (relative to module root from `go.mod`)
- Run `go test <pkg1> <pkg2> ...`

**cargo test crate filtering:**

- If `Cargo.toml` changed: re-run all tests (workspace structure may have
  changed)
- Else: extract directory of each changed `.rs` file, map to crate name, run
  `cargo test -p <crate>`
