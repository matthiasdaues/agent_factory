# Update playbook FSMs with tests_pass entry condition

Add `tests_pass` entry condition (using `script_exit_zero: factory/scripts/run-tests --full`) to the appropriate phase transitions in
`bug-fix.fsm.yml` and `greenfield-development.fsm.yml`, so phases refuse to
advance while tests are red.

The specific phase transitions that need test gates are:

- **bug-fix.fsm.yml**: DIAGNOSING → IMPLEMENTING (tests must pass to confirm
  diagnosis before writing fix)
- **bug-fix.fsm.yml**: IMPLEMENTING → VERIFYING (tests must pass to confirm fix
  before verification)
- **greenfield-development.fsm.yml**: IMPLEMENTATION → QA (tests must pass
  before QA review begins)

**Priority:** should-have

## Acceptance Criteria

- `factory/playbooks/bug-fix.fsm.yml` updated:
  - `DIAGNOSING → IMPLEMENTING` transition gains entry condition: `tests_pass: {script_exit_zero: factory/scripts/run-tests --full}`
  - `IMPLEMENTING → VERIFYING` transition gains entry condition: `tests_pass: {script_exit_zero: factory/scripts/run-tests --full}`
- `factory/playbooks/greenfield-development.fsm.yml` updated:
  - `IMPLEMENTATION → QA` transition gains entry condition: `tests_pass: {script_exit_zero: factory/scripts/run-tests --full}`
- Each condition includes an inline comment explaining: "# Full test suite must
  pass before advancing"
- No other phase transitions modified (tests are not required to leave PLANNING
  or ARCHITECTURE, for example — those phases have no runnable code).

## Implementation Notes

**YAML syntax for entry condition:**

```yaml
- source: IMPLEMENTING
  target: VERIFYING
  entry_conditions:
    tests_pass:
      script_exit_zero: factory/scripts/run-tests --full  # Full test suite must pass
```

**Why these transitions?**

- **DIAGNOSING → IMPLEMENTING** (bug-fix): Diagnosis phase should produce a
  failing test that reproduces the bug. That test must pass (meaning the bug is
  confirmed reproducible) before moving to fix implementation.
- **IMPLEMENTING → VERIFYING** (bug-fix): Implementation phase writes the fix.
  All tests (including the reproduction test) must pass before moving to
  verification.
- **IMPLEMENTATION → QA** (greenfield): Implementation phase writes features and
  tests. All tests must pass before QA can begin reviewing and testing.

**Why not other transitions?**

- **PLANNING → ARCHITECTURE**: No code or tests exist yet
- **ARCHITECTURE → IMPLEMENTATION**: Architecture phase produces diagrams and
  ADRs, no runnable tests
- **QA → DONE**: QA phase verifies manually; test gate already enforced at entry

**Traceability:**

Each FSM file should reference ADR-0003 in a comment near the first
`tests_pass` condition, linking the FSM to the architectural decision.
