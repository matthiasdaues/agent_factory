# Refuse a story that names crap-score before the gate is set up

A story that asks for the CRAP gate before anyone set it up is refused, and the refusal names the setup skill.

**Priority:** must-have

## Goal

A story whose `quality-gates` field names `crap-score` while `docs/testing.yaml` has no entry for it is refused in the gate-check step and by `premerge-check`. The refusal names `crap-score` and the skill `setup-crap-score`. No Factory document names a default that runs `crap-score` alone.

## Domain Rule

- The refusal is exit 1 of `premerge-check`, like any other refused check, so `merge-story` keeps the story `dispatched` (DEC-21).
- This refusal is never a case of "gate cannot measure": it gives no exit 3 and no `blocked`.
- The implementation agent refuses the same story in the gate-check step before it runs any gate, and names `setup-crap-score`.
- The precedence of gates is: the story's `quality-gates` field, then the `gates` section of `docs/testing.yaml`. Nothing else.

## Outputs

- `premerge-check`: the refusal of a `quality-gates` entry without an entry names `setup-crap-score` when the gate is `crap-score`.
- `implementation-agent.md`: the gate-check step refuses the story and names the skill; the precedence list loses the default of `crap-score` alone.
- `packages/factory/rulebooks/templates/story.md`: the comment on `quality-gates` loses the default of `crap-score` alone.
- `tests/factory/test_premerge_check.py`: `test_st_0415_the_merge_is_refused_and_names_the_gate` stays for `license-check`; the row `[crap-score, mutation-testing, dependency-check]` without a file in `test_st_0359_gate_list` expects the refusal (CAO-11-CT-01).

## Demo Scenario

1. In the repository of ST-0433 without a `gates` section, ST-0351 has `quality-gates: [crap-score]`.
2. The User runs `dispatch merge-story ST-0351`. `premerge-check` exits 1, and the refusal names `crap-score` and `setup-crap-score`.
3. `dispatch status` shows ST-0351 `dispatched`, and its refusal holds no line `GATE CANNOT MEASURE`.
4. The User reads the gate-check step in `implementation-agent.md`: it refuses the same story and names `setup-crap-score`.

## Demo Data

The story seeds nothing. It uses the repository of ST-0433 without a `gates` section, with ST-0351 changed to `quality-gates: [crap-score]`.
