# Rewrite the rulebook for the concern model and build concern-lint with CTX-SECTIONS, CTX-PATHS, and CTX-LEGACY

Replace the YAML-based agent-context composition rules with the concern-oriented model and build the deterministic validation gate that enforces it. The rulebook defines the structural contract; concern-lint is the mechanical check; the validate skill and pre-commit hook are the enforcement points.

**Priority:** must-have

## Demo

The user creates a `docs/agent-context.md` with "Always (cross-cutting)", "Technical concerns", and "Domain concerns" category headings, each containing concern sections with description lines and `Read:` paths pointing at real files. Running `concern-lint` reports zero findings. The user removes the "Technical concerns" heading -- `concern-lint` reports CTX-SECTIONS. The user restores it but points a `Read:` line at a nonexistent file -- `concern-lint` reports CTX-PATHS. The user creates `docs/agent-context/stack.yaml` alongside `docs/agent-context.md` -- `concern-lint` reports CTX-LEGACY. The user runs the validate skill -- gate #12 runs `concern-lint` instead of `context-lint`.

## Acceptance Criteria

- `agent-context-composition.md` describes three concern categories (cross-cutting, technical, domain), the `agent-context.md` markdown structure, the controlled vocabulary rule, and the advisory nature of concern declarations.
- `agent-context-composition.md` does not reference YAML agent-context files, modes, source pointers, reading-guides.yaml, or the format-detection chain -- those concepts are retired.
- `concern-lint` reports CTX-SECTIONS when a required category heading ("Always (cross-cutting)", "Technical concerns", "Domain concerns") is missing or when a concern section lacks a description line or at least one `Read:` path.
- `concern-lint` reports CTX-PATHS when a path in a `Read:` or `Boundary:` line does not resolve to an existing file or glob match.
- `concern-lint` reports CTX-LEGACY when any `.yaml` file other than `testing.yaml` exists under `docs/agent-context/` or when a `docs/charter/` directory exists alongside a concern-format `docs/agent-context.md`.
- `concern-lint` exits 0 when all checks pass and non-zero when any check fails.
- The validate skill's gate #12 runs `concern-lint` instead of `context-lint`.
- `.pre-commit-config.yaml` references `concern-lint` instead of `context-lint`.

## Scope

**Status quo:** `agent-context-composition.md` describes the YAML model (four files, two modes, source pointers, field states, write-path ownership, format exclusivity, testing.yaml carve-out). `context-lint` validates YAML agent-context files with CX-\* codes. The validate skill runs `context-lint` at gate #12. `.pre-commit-config.yaml` has a `context-lint` hook entry.

**Adds:** Rewritten `agent-context-composition.md` for the concern model. New `concern-lint` Python script with CTX-SECTIONS, CTX-PATHS, CTX-LEGACY checks. Updated validate skill gate #12. Updated pre-commit hook entry. Test fixtures for all three checks.

**Out of scope:** CTX-REFS check (ST-0221). Deletion of `context-lint` script (retained until all consumers are migrated; concern-lint coexists temporarily). Capture-context and update-context skill changes (EPIC 10). Agent definition updates (EPICs 11, 12).

## Notes for the Implementer

The `context-lint` script is retained temporarily -- it coexists with `concern-lint` until EPIC 12 completes the migration. The validate skill and pre-commit hook switch to `concern-lint` immediately. New tests target the `tests/` directory under `tests/factory/` or `tests/fixtures/concern-lint/`. The concern-lint script should have no third-party dependencies (Python 3.10+ stdlib only), matching the pattern of context-lint.
