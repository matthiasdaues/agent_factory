# Rewrite qa-strategy-from-spec for charter-grounded contract ownership

Rewrite `factory/skills/qa-strategy-from-spec/SKILL.md` to ground contract-owner assignments in the project charter rather than applying the Factory convention as a generic backbone. Add two new inputs (charter layer bindings and repository scan), rewrite Step 3 for charter-grounded assignment, introduce new layer status states, emit test IDs per contract-owner row, and check fidelity before assigning contract ownership.

**Priority:** must-have

## Acceptance Criteria

- `qa-strategy-from-spec` reads `docs/charter/testing.yaml` layer bindings as a new input before Step 1
- `qa-strategy-from-spec` scans the repository's test infrastructure (conftest.py, test directories, Makefile targets, runner configs, pyproject.toml pytest config, vitest.config.\*) as a second new input
- Step 3 assigns contract owners using the charter's layer bindings as the governing policy; `testing-strategy.md` provides vocabulary and the overlap-deletion protocol
- When a contract needs a layer the charter has not declared, a gap finding is emitted rather than silently assuming the layer exists
- When charter layer bindings are absent, the skill falls back to the Factory convention's generic five layers and emits a gap finding
- When declared entry points or infrastructure do not match the repository scan, mismatches are recorded as gap findings
- The "Generated from" header includes charter layer bindings and repo test infrastructure sources
- The "Test Layers in Scope" table uses status states: `available`, `partially covered`, `planned`, `blocked`, `out`
- `available` means the harness works but no tests exist yet for this feature; `partially covered` takes precedence over `available` when any test exists
- Each contract-owner row emits a test ID following the pattern `<scope-ID>-<layer-abbreviation>-<sequence>` (abbreviations: LN, AC, CT, IT, E2)
- The contract-owner table includes columns: Contract, Source scenario or gap, Owner layer, Test ID, Test location, Command, State
- Per-row State uses: `implemented`, `planned`, `blocked`
- When assigning a contract to a layer, fidelity declarations are checked against contract requirements; insufficient fidelity triggers a gap finding
- A recommended `@pytest.mark.spec("<scope-ID>")` marker convention is documented in the output
- `mdformat` passes on the modified file

## Implementation Notes

- This is the largest single rewrite in the feature: the skill gains two new inputs, a revised Step 3, new output table format, and fidelity checking
- Tier is strong per dispatch-contract tier rubric: the rewrite requires reasoning about testing conventions, contract-to-layer mapping, and fidelity constraints
- Depends on ST-0155 (kit-manager layer bindings) so that the charter data the skill reads is populated
