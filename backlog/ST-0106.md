# Create module-graph mechanical check script

Create a deterministic script that reads `architecture.dsl`, derives the
current module map, and compares it against a feature's Phase 1 outputs
(`interface-contracts.md`, `entity-model.md`) to determine whether the
feature changes module boundaries, dependency directions, or public
interfaces.

**As a** playbook orchestrator,
**I want** a mechanical check that determines architecture phase routing
from the module graph's actual state,
**so that** features that touch no module boundaries skip Phase 2 without
manual declaration.

**Priority:** must-have

## Acceptance Criteria

01. `factory/scripts/module-graph-check` is an executable script.
02. The script reads `docs/arc42/architecture.dsl` and derives the current
    module map (which directories own which modules, which modules depend
    on which).
03. The script reads Phase 1 outputs: `interface-contracts.md` (new or
    changed interfaces) and `entity-model.md` (new entities).
04. For each interface or entity declared by the feature, the script checks:
    (a) does it target a module not present in the DSL (new module)?
    (b) does it change a public interface already declared in the DSL?
    (c) does it introduce or invert a dependency direction between modules?
05. If any check is true → output `architecture_change=true`.
    Otherwise → output `architecture_change=false`.
06. A new entity in an existing module does NOT trigger `true` — the check
    tests module-graph topology only.
07. The script updates the proposal's `impact.architecture_change` field
    in the proposal frontmatter file.
08. Override semantics: field was `false`, machine says `true` → machine
    wins, field updated, annotated `# mechanical detection`. Field was
    `true`, machine says `false` → prior human declaration respected
    conservatively, field stays `true`.
09. The script runs against `interface-contracts.md` and `entity-model.md`,
    not story outputs.
10. All outputs pass `factory/scripts/validate`.
