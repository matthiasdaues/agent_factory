# Seams-first strategy: two-session dispatch with tier arithmetic

Implement the seams-first two-session workflow in `prepare-wave` and
`prepare-story`. A seams-first story runs two sessions: the seam session
(declared tier) receives only `seam_outputs` in its manifest and writes test
files; the implementation session (one tier lower, floored at economy) receives
only `impl_outputs` and makes the tests pass. The implementation session's
inputs include the seam session's outputs. A `seam_defect` failure returns to
the seam session at the same tier without consuming the escalation slot.

**As a** dispatch operator,
**I want** seams-first stories to run two focused sessions with correct tier
and scope assignment,
**so that** test-writing and implementation use appropriately-tiered models and
neither session can write outside its scope.

**Priority:** must-have

## Acceptance Criteria

1. The seam session's manifest contains only `seam_outputs` as outputs.
2. The implementation session's manifest contains only `impl_outputs` as
   outputs.
3. The implementation session's inputs include the story's declared inputs plus
   the `seam_outputs` paths (so it can read the tests the seam session wrote).
4. The implementation session runs one tier below the declared tier, floored at
   economy.
5. A story declaring tier economy with seams-first runs the implementation
   session at economy (floor).
6. A `seam_defect` failure re-dispatches the seam session at the same tier
   without consuming the story's escalation slot.
7. Repeated `seam_defect` failures block the story for human decision (no
   automatic escalation of the seam session).
