# Receive project insight before configuration decisions

**Priority:** must-have

## Goal

A newcomer opens the first Factory session on an installed project and sees the detected stack, test entry point (or its absence), and one safety signal (or its absence) without changing project files. The session recommends one next action. Advanced configuration (model tiers, hooks, extended context) waits until the newcomer selects an action that depends on each setting.

## Analysis

VIRGIL is a Markdown agent definition, not executable code — its behavior is the prose an LLM follows, not a function a test can call directly. The seam this story adds is a new `## First-session insight` section in `packages/factory/agents/virgil.md`, placed before `## Fitting`, that documents: the read-only scan (reusing `init-factory`'s `LANGUAGE_MANIFESTS`, `SCAN_SKIP_DIRS`, and CI/linter signals — no re-implemented detection), the four-field key-value report (Stack, Test entry, Safety signal, Recommended action) with explicit "not detected" / "none observed" language, the three-step recommendation order (context capture → gate demonstration → hook configuration), and the deferral of model tiers, hooks, and extended context until the newcomer selects a dependent action. The `## Fitting` section's intro paragraph was edited to state it starts only after that selection, not automatically at session start. `packages/factory/skills/capture-context/SKILL.md` gained one note: `--init --scan` is invoked as the recommended action, not automatically.

Tests live in `tests/factory/test_value_first_routing.py`, following this repo's existing convention for Markdown-agent contracts (see `tests/factory/test_capture_context_update.py`): read the `.md` files and assert section presence, ordering, and required phrases. This covers the two contracts the QA strategy (`docs/spec/value-first-onboarding-journey-qa-strategy.md`) assigns a contract-test layer to (`VFO-06-CT-01`, "configuration appears only before an action that needs it") and adds static coverage for the evidence-reporting contract, whose dynamic/end-to-end form (VFO-06-AC-01) is owned by `tests/factory/test_onboarding_journey.py` — not yet built, tracked separately.

`Scenario: Ready-host insight meets the decision and time bounds` has no contract-owner row in the QA strategy; its two-minute / three-decision budget is measured by the moderated journey protocol (EPIC 6), so this story documents the budget in `virgil.md` but does not attempt to measure it in a unit test.

Files created or modified: `packages/factory/agents/virgil.md`, `packages/factory/skills/capture-context/SKILL.md`, `tests/factory/test_value_first_routing.py` (new).

## Required Script Behavior

### Project scan

The scan reuses `init-factory`'s detection logic (`LANGUAGE_MANIFESTS`, `SCAN_SKIP_DIRS`, CI and linter detection). It reports:

- **Stack**: all detected languages (e.g. "Python, JavaScript"). "Not detected" when none found.
- **Test entry**: the detected test command (e.g. "pytest"). "Not detected" when none found.
- **Safety signal**: one observed signal (e.g. "pre-commit hooks present"). "None observed" when absent.
- **Recommended action**: the next step in the onboarding sequence — context capture, gate demonstration, or hook configuration, depending on detected state.

### Display format

Key-value list. Each field on its own line. Unknown values stated explicitly.

### Next-action logic

The recommendation points to the next incomplete onboarding step:

1. Context capture — if the project needs context and `docs/agent-context.md` does not exist.
2. Gate demonstration — if context is handled but the newcomer has not seen a gate.
3. Hook configuration — if gates are demonstrated.

Exactly one action is recommended per session.

### Deferred configuration

Model tiers, hooks, and extended context configuration are not requested until the newcomer selects an action that depends on each setting.

## Boundaries

- The scan is read-only. No project files, configuration files, or manifest entries change during the scan.
- The insight appears within two minutes on a ready host. No more than three user decisions occur before the insight.
- Virgil is not rewritten from scratch. This story reorders the first-session flow within the existing agent definition.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Resolve Before Implementation

1. What is the exact priority order for stack detection when multiple language indicators are present (e.g., both `pyproject.toml` and `package.json`)?

   > No priority order. `init-factory`'s scan uses `LANGUAGE_MANIFESTS` (line 2094) and reports all detected languages via a `seen_languages` set. When multiple languages are present, all are listed. The insight reports all detected languages, not a single primary. Decided 2026-09-24.

2. When the session recommends one next action, is the recommendation always the gate demonstration, or does it vary based on detected state?

   > It varies. The recommendation points to the next step in the onboarding sequence: context capture if the project needs it, gate demonstration if context is already handled, or hook configuration if gates are done. The insight always recommends exactly one action — the next step, not a menu. Decided 2026-09-24.

3. Does the insight display format use a structured table, a prose paragraph, or a key-value list?

   > Key-value list. Concise, scannable, consistent with the existing fitting output style. Fields: "Stack", "Test entry", "Safety signal", "Recommended action". Unknown values are stated explicitly ("not detected", "none observed"). Decided 2026-09-24.
