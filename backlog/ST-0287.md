# Receive project insight before configuration decisions

**Priority:** must-have

## Goal

A newcomer opens the first Factory session on an installed project and sees the detected stack, test entry point (or its absence), and one safety signal (or its absence) without changing project files. The session recommends one next action. Advanced configuration (model tiers, hooks, extended context) waits until the newcomer selects an action that depends on each setting.

## Contract

| Operation                                                                           | Input state                                                     | Outcome                                                                                                                                               | Persistence              |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| Open first session                                                                  | Project with Python source, `pytest`, `.pre-commit-config.yaml` | Session reports stack (Python), test entry point (`pytest`), safety signal (pre-commit hooks present); recommends one next action                     | No file changes          |
| Open first session                                                                  | Project with no test framework and no pre-commit hooks          | Session reports detected stack or states not detected, states no test entry point found, states no safety signal observed; recommends one next action | No file changes          |
| Open first session                                                                  | Ready host with one detected interface                          | Insight appears within two minutes; no more than three decisions after installation approval                                                          | No file changes          |
| Newcomer has not selected an action needing model tiers, hooks, or extended context | First session active                                            | Session does not request those configuration decisions                                                                                                | No configuration written |

## Boundaries

- The scan is read-only. No project files, configuration files, or manifest entries change during the scan.
- The insight appears within two minutes on a ready host. No more than three user decisions occur before the insight.
- Virgil is not rewritten from scratch. This story reorders the first-session flow within the existing agent definition.
- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.

## Demo Scenario

1. Complete a Factory installation on a Python project with a `pytest` entry point and an existing `.pre-commit-config.yaml`.
2. Open the first Factory session.
3. The session reports the detected stack (Python), the test entry point (`pytest`), and one safety signal (pre-commit hooks present).
4. The session recommends one next action.
5. Verify no project files changed.
6. The session does not ask about model tiers, hooks, or extended context before the newcomer selects an action.
7. Open the first Factory session on a project with no test entry point and no pre-commit hooks.
8. The session reports the detected stack (or states not detected), states no test entry point was found, and states no safety signal was observed.
9. The session recommends one next action.

- The project scan requires reading files outside the project directory → ask whether that is acceptable.
- The two-minute timing constraint cannot be met with the scan logic → report which detection steps exceed the budget and ask which to skip.
- Code in `packages/factory/agents/virgil.md` and the feature spec disagree on what the first session reports → report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. What is the exact priority order for stack detection when multiple language indicators are present (e.g., both `pyproject.toml` and `package.json`)?
2. When the session recommends one next action, is the recommendation always the gate demonstration, or does it vary based on detected state?
3. Does the insight display format use a structured table, a prose paragraph, or a key-value list?
