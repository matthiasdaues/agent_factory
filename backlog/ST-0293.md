# Run an automated end-to-end journey test

**Priority:** should-have

## Goal

A quality researcher runs a pytest end-to-end test that checks the safe non-interactive path through preflight diagnosis, cancellation handling, consent gates, installation, receipt contents, and first-session routing. The test declares an end-to-end layer binding in `docs/testing.yaml`. The test does not exercise updating or the first task.

## Contract

| Operation                                 | Input state                                       | Outcome                                                             | Persistence                                              |
| ----------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------- |
| Run journey test: preflight checkpoint    | Controlled fixture (temporary repo, local source) | Preflight produces readiness result without changing files          | No file changes in target                                |
| Run journey test: cancellation checkpoint | Controlled fixture, blank input at consent        | Bootstrap stops without changes                                     | Target unchanged                                         |
| Run journey test: consent checkpoint      | Controlled fixture, declined installation         | Target remains unchanged                                            | No new files in target                                   |
| Run journey test: installation checkpoint | Controlled fixture, affirmative consent           | Installation completes                                              | Factory installed in target                              |
| Run journey test: receipt checkpoint      | Installation complete                             | Receipt contains changed paths, interface, version, next command    | Receipt written                                          |
| Run journey test: routing checkpoint      | Installation complete, session opened             | Session reports detected stack, test entry point, and safety signal | No file changes in target                                |
| Run full test suite                       | All six checkpoints                               | Exit code 0; all assertions pass                                    | End-to-end layer binding declared in `docs/testing.yaml` |

## Required Script Behavior

### Controlled fixture

The test creates a temporary Git repository with one commit, containing files that trigger known detections (e.g. `pyproject.toml` for Python, `conftest.py` for pytest, `.pre-commit-config.yaml` for safety signal). A local Factory source tree is copied from the working directory. No network access is used.

### Consent simulation

The test imports `get_consent` and `select_interface` from install-agent-factory and passes a callable via the `input_func` parameter. Predetermined answers drive each checkpoint without stdin piping.

### Six checkpoints

1. **Preflight**: run preflight diagnosis functions on the fixture. Assert readiness result. Assert no file changes in target.
2. **Cancellation**: call `get_consent(input_func=lambda _: "")`. Assert the bootstrap returns without changes.
3. **Consent gate**: call `get_consent(input_func=lambda _: "no")`. Assert target unchanged.
4. **Installation**: call the full bootstrap with `input_func` returning "yes" and the detected interface. Assert Factory installed in target (`.agent-factory/` exists, manifest written).
5. **Receipt**: assert the receipt contains changed paths, selected interface, installed version, and next command.
6. **Routing**: assert `project-context.json` observations include the expected languages, test runners, and linters for the controlled fixture. Virgil is an NL agent definition and is not invoked directly.

### Layer binding

The test declares an `end_to_end` layer binding in `docs/testing.yaml` with path `tests/factory/test_onboarding_journey.py`.

### Cleanup

All temporary directories and Git repositories are removed in `tearDown` or a pytest fixture finalizer.

## Boundaries

## Stop Conditions

- The bootstrap requires interactive terminal input that cannot be simulated in a pytest subprocess — report the interaction model and what prevents simulation.
- The first-session routing requires a live Claude Code session that cannot be tested in isolation — report the dependency.
- The temporary Git repository setup conflicts with the test runner's own Git state — report the conflict.
- Code in `packages/factory/scripts/` and the feature spec disagree on the consent checkpoint behavior or receipt contents — report the conflicting files and the decision needed; do not add a workaround.

## Resolve Before Implementation

1. How does the test simulate interactive consent prompts — through stdin piping, environment variables, or a non-interactive mode flag on the bootstrap?

   > Inject a callable via the `input_func` parameter. Both `get_consent()` and `select_interface()` accept `input_func` (default `input`). The test imports these functions and passes a lambda or list-based callable that returns predetermined answers. No stdin piping or environment variables needed. Decided 2026-09-24.

2. How does the test simulate first-session routing — by invoking Virgil's project scan directly, or by running the full session entry point with controlled inputs?

   > The test verifies the installation output that Virgil's routing reads. Virgil is an NL agent definition, not a callable function. The test runs install-agent-factory and init-factory on a controlled fixture, then asserts `project-context.json` contains the expected observations (languages, test runners, linters, CI). The routing checkpoint verifies the data is correct, not that Virgil renders it. Decided 2026-09-24.
