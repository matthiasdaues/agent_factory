# Return bounded child-result envelopes from Pi dispatch

Keep complete child results in tracked artifacts while returning only the
cross-CLI result envelope from Pi's separate-session and wave transports.

**Priority:** must-have

## Acceptance Criteria

- The report convention defines the exact four-field bounded envelope and
  forbids verbatim finding detail or full reasoning in it.
- `run_agent` and `dispatch_wave` reject successful completion when required
  canonical result artifacts were not persisted.
- Both transports return disposition, explicit severity counts, every artifact
  path, and a one-to-three-sentence next action, with usage/exit metadata kept
  outside the envelope.
- Tests prove verbose child detail is absent from returned content and remains
  available through the complete artifact-path list.

## Implementation Notes

The native-agent behavior is governed by ST-0066's agent contracts; this story
owns only Pi transport enforcement and its tests.

## Analysis

Implement the BR-040 boundary at the two Pi transport adapters. Each spawned
child must finish with one exact JSON object containing only `disposition`,
`finding_counts`, `artifact_paths`, and `next_action`. The transports validate
that shape, the pass/fail/block disposition, non-negative integer severity
counts, a one-to-three-sentence next action, and every repository-relative
artifact path before treating an exit-zero child as successful. Each artifact
must exist inside the child checkout and be known to Git; absolute,
non-canonical, escaping, missing, and untracked paths are rejected.

The complete result stays in the listed tracked artifacts. `run_agent` returns
the validated envelope verbatim as parent-visible content and keeps agent,
model, usage, and exit code in transport details. `dispatch_wave` validates
each child against its own worktree before premerge or merge, aggregates the
validated dispositions, severity counts, and artifact paths into one exact
four-field wave envelope, and exposes only bounded per-item runtime metadata
outside it. Neither adapter retains or returns the child's raw final prose.

Chicago-school transport tests execute the installed TypeScript extensions
through their registered Pi tools with a fake `pi` process. Tracer bullets
cover a verbose complete report reachable through all listed paths, rejection
of an exit-zero child with missing or untracked artifacts, the exact four-field
parent content, and separation of usage/exit metadata from the envelope. The
report convention is the serialization contract; the existing JSONL
`message_end` parser, subprocess boundary, Git worktree, and tool-result
`content`/`details` split remain the highest practical seams.

The dispatcher authorized adding
`orchestrator/tests/test_usage_capture_pi_e2e.py` to the output contract. Its
existing fake Pi successes return plain text without artifacts, which the new
acceptance rule must reject; only those fixtures are updated to emit valid
tracked-artifact envelopes while their usage-capture assertions stay intact.

Changing the canonical report convention also changes its generated token
count in `factory/INDEX.yaml`. The dispatcher authorized naming and
regenerating that deterministic projection so `index-lint` remains clean; it
adds no runtime behavior or documentation scope.

## Spec Feedback

Compared the implementation with UC-10, UC-11, FR-K4, BR-034, BR-040, the
child-result interface contract, validation rules, and accepted Session
Transcript Proposal. No drift was found: the transports now enforce the exact
already-specified four-field boundary, canonical tracked artifact obligation,
and separation of usage/exit metadata without changing the Pi process model,
usage-capture lifecycle, entity model, or deployment boundary. No
specification update or ADR is needed.

Focused envelope, installation, large-stream, and delayed-capture tests pass.
The broader applicable run passed 48 tests; its sole failure is the existing
nested-dispatch telemetry case under the managed sandbox, where a
second-generation fake Pi exits zero but its parent receives zero stdout bytes.
The attempted external confirmation was interrupted while awaiting approval;
the failure occurs before envelope parsing and is recorded as an execution
environment limitation rather than hidden or repeatedly rerun.
