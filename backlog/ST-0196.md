# Transition agent context from primary to index mode

Extend update-context with mode-transition logic. The skill checks the transition condition (every non-null, non-deferred leaf field across all three index files has a `source:` pointer), prompts the operator for confirmation, and executes the atomic flip: setting `mode: index` in all three files in a single commit, stripping inline values to names only, and preserving source pointers. The transition is operator-confirmed and one-directional -- once in index mode, files do not revert to primary.

**Priority:** must-have

## Demo

Operator has three index files in `mode: primary` with source pointers on all non-null, non-deferred fields (status quo from ST-0195 update-context writes). Operator fills the last missing source pointer. update-context detects that the transition condition is met and prompts: "All context fields now have sources. Switch to index mode?" Operator confirms. update-context flips `mode` to `index` in all three files in a single commit, strips inline values to names only, and preserves source pointers. Operator runs `context-lint` and the index-mode files pass validation. In a second scenario, operator has a null field without deferral -- update-context does not prompt for transition because the condition is not met.

## Acceptance Criteria

- update-context prompts the operator to switch to index mode when every non-null, non-deferred leaf field across all three index files has a `source:` pointer (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Transition condition is met).
- When the operator confirms, all three index files are set to `mode: index` in a single atomic commit (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Operator confirms mode transition).
- Inline values are stripped to names only during transition, and source pointers are preserved (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Operator confirms mode transition).
- When the operator declines, all three files remain in `mode: primary` (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Operator declines mode transition).
- The transition condition is not met when a non-deferred, non-null field lacks a source pointer (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Transition blocked by null field without deferral).
- Deferred fields are excluded from the transition condition (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Transition not blocked by deferred fields).
- Null fields are excluded from the transition condition (agent-context.feature Rule: Operator transitions context from primary to index mode, Scenario: Transition not blocked by null fields).
- context-lint passes on the files after mode transition.

## Scope

**Status quo:** update-context exists with mode-aware field writing, deferred-field handling, and reading-guide creation trigger (from ST-0195). context-lint validates all CX-\* codes including CX-SRC in index mode (from ST-0190, ST-0191). No mode-transition logic exists.

**Adds:** Transition-condition checking logic that evaluates all three index files. Operator confirmation prompt. Atomic flip logic: set `mode: index`, strip inline values, preserve sources, commit all three files. Contract tests in `tests/factory/test_mode_transition.py` covering ACX-15 (deferred sole-key invariant) and ACX-16 (transition-condition evaluation).

**Out of scope:** capture-context brownfield mode proposal (ST-0194 handles that separately). Reverse transition from index to primary (not supported per ADR-0014). Consumer path updates (EPIC 4).

## Terminology

- Transition condition: The invariant that every non-null, non-deferred leaf field across all three index files has a `source:` pointer. When met, update-context prompts the operator to switch to index mode.
- Atomic flip: The single-commit operation that changes `mode` from `primary` to `index` in all three index files simultaneously, strips inline values to names only, and preserves source pointers.

## Notes for the Implementer

The transition-condition check must walk the YAML structure of all three index files and classify each leaf as null, deferred, or valued. Only valued leaves are checked for source-pointer presence. The atomic flip must happen in a single git commit -- stage all three files, then commit. The value-stripping logic converts inline values (e.g. `frameworks.backend: "FastAPI 0.100"`) to name-only form (e.g. `frameworks.backend: {name: FastAPI, source: docs/adr/004.md}`). New tests target the contract test layer under `tests/factory/`.
