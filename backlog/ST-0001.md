# Show orchestrator/ in root README's Project Directory Tree

Root `README.md`'s "Project Directory Tree" section currently lists only
`factory/`, `docs/`, `config/`, `.claude/`, `.github/` and a handful of
root files — it has no entry for `orchestrator/` at all. Orchestrator's
role is now confirmed: a permanent, live, nested sub-project (not
flattened to repo root, not retired). The tree needs an `orchestrator/`
node so a reader of the README understands it's there and what it is.

**Priority:** could-have

## Acceptance Criteria

- The "Project Directory Tree" code block in root `README.md` gains an
  `orchestrator/` entry alongside the existing `factory/`, `docs/`,
  `config/` entries, in the same annotated-tree style (a trailing `#`
  comment per line).
- Immediately before or after the tree, one paragraph explains what
  `orchestrator/` is: the Python CLI that drives agent sessions
  (`run-step`/`run-phase`/etc.), nested permanently as its own
  sub-project with its own `src/`, `tests/`, `docs/`, `backlog/`,
  `pyproject.toml`.
- The explanation makes clear `orchestrator/` is not part of `factory/`'s
  copy-wholesale distribution — it is not touched by `init-factory`.
- No other section of the README is restructured beyond this addition.
