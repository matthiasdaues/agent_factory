# Implement workstream state v2 and session binding format

Workstream state files become immutable identity records; session bindings attach sessions to workstreams without cycle vocabulary.

**Priority:** must-have

## Goal

Workstream state v2 files are created at `.agent-factory/workstreams/<workstream-id>.yaml` with four fields: `schema_version: 2`, `workstream_id`, `topic`, and `origin_ref`. The file is immutable after creation — modification attempts fail. Session binding files are created at `.agent-factory/workstreams/sessions/<session-id>.yaml` with `session_id`, `workstream_id`, and `bound_at`. A known workstream identifier means bound, explicit null means Open Stage, and a missing `workstream_id` key fails validation. Existing v1 cycle state files under `.current-work/cycles/` and v1 session binding files under `.current-work/session-bindings/` are deleted.

## Domain Rule

- Workstream state file contains only: `schema_version: 2`, `workstream_id`, `topic`, `origin_ref`. No other fields.
- The state file is immutable after creation — any modification attempt fails without changing the file.
- Session binding records `session_id`, `workstream_id` (must be present), `bound_at`.
- `workstream_id` with a known identifier means bound; explicit null means Open Stage; missing key fails validation.
- Multiple sessions can bind to the same workstream; the state file stays unchanged.
- Selecting a different workstream updates the binding, not the state file.
- Open Stage creates a session binding with `workstream_id: null`.
- The workstream state lifecycle has two states: ABSENT and CREATED (no transitions after creation).

## Demo Scenario

1. Create a workstream with topic "activity graph orchestration" and origin_ref "docs/proposals/activity-graph-orchestration.md".
2. Inspect `.agent-factory/workstreams/activity-graph-orchestration.yaml`. The file contains exactly four fields: `schema_version: 2`, `workstream_id: activity-graph-orchestration`, `topic: activity graph orchestration`, `origin_ref: docs/proposals/activity-graph-orchestration.md`. No other fields exist.
3. Attempt to modify the state file (add a field, change the topic). The modification fails. The file is unchanged.
4. Create a session binding for session `sess-abc` bound to workstream `activity-graph-orchestration`. Inspect `.agent-factory/workstreams/sessions/sess-abc.yaml`. The file contains `session_id: sess-abc`, `workstream_id: activity-graph-orchestration`, `bound_at: 2026-09-18T10:00:00Z`.
5. Create a second session binding for session `sess-def` bound to the same workstream. Both binding files exist. The workstream state file is unchanged.
6. Create a session binding with `workstream_id: null` (Open Stage). The binding file is valid.
7. Attempt to create a session binding without the `workstream_id` key. Validation fails.
8. Verify that `.current-work/cycles/` contains no v1 state files and `.current-work/session-bindings/` contains no v1 binding files.

## Constraints

- Workstream state files must contain exactly four fields — no extra fields permitted.
- Immutability must be enforced at the application level (the engine refuses to write to an existing state file).
- Session binding validation must reject files missing the `workstream_id` key entirely (not just null).
- V1 file deletion must not remove `.current-work/` itself or other subdirectories (worktrees, dispatch ledgers, verification markers).
- No external dependencies beyond the Python standard library and PyYAML.
