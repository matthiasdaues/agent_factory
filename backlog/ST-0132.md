# Tier rubric in dispatch plan and tier mismatch enforcement in dispatch init

Extend `dispatch plan` to compute a suggested tier per story using the
first-match-wins rubric. Add `safety_critical_paths` to `config/project.json`.
Extend `dispatch init` to block on a `strong` suggestion against a lower
declared tier and warn on every other mismatch.

**As a** dispatch operator,
**I want** the rubric to suggest an appropriate model tier per story and block
when a safety-critical story is under-tiered,
**so that** model tier selection is evidence-based and safety-critical work is
never dispatched at an insufficient tier.

**Priority:** must-have

## Acceptance Criteria

### Tier rubric (dispatch plan)

1. `risk_domains` including security, privacy, or data_integrity produces a
   `strong` suggestion.
2. Outputs matching a `safety_critical_paths` glob in `config/project.json`
   produce a `strong` suggestion.
3. Outputs spanning 2+ top-level directories produce a `standard` suggestion.
4. 3+ entries in `deps` produce a `standard` suggestion.
5. Single directory with non-empty `tests` produces an `economy` suggestion.
6. No matching condition defaults to `standard`.
7. First match wins when multiple conditions apply.
8. Each story's suggested tier is included in the wave plan YAML.

### Tier mismatch (dispatch init)

09. `dispatch init` exits non-zero when a story is suggested as `strong` by
    the rubric but declares a lower tier.
10. `dispatch init` warns (but proceeds) on every other mismatch.

### Configuration

11. `config/project.json` gains a `safety_critical_paths` key (list of glob
    patterns). An empty or absent list means the safety-critical rule never
    fires.

## Analysis

Implemented `suggest_tier(story_frontmatter, project_config)` in
`dispatch_lib.py` as a first-match-wins rubric (risk domains -> safety-critical
paths -> multi-directory outputs -> 3+ deps -> single-dir-with-tests ->
default standard). `dispatch plan` now loads `config/project.json` (via
`load_project_config`) and attaches a `suggested_tier` field per story in the
wave-plan YAML. `dispatch init` loads each named story's backlog frontmatter
(`backlog/<id>.md`) before creating the branch/worktree/ledger, computes the
rubric suggestion, and blocks (exit 1) only when the suggestion is `strong`
and the declared tier is lower; every other mismatch is a warning on stderr
and initialization proceeds. Added `safety_critical_paths: []` to the
(newly-created) `config/project.json`. Stories with no matching backlog file
are skipped silently (no rubric data available). Covered by 9 new rubric unit
tests in `tests/test_dispatch_planning.py` and 2 new integration tests in
`tests/test_dispatch_init_integration.py`.
