# Derive fitting state from tracked artifacts in init-factory

## Analysis

Traces to design item 7 of `docs/proposals/progressive-fitting-and-session-continuity.md`
(no `.feature` file governs this story; no UC-XX applies). `tests:` is
present and non-empty, so this story went straight to the Green phase
against `tests/factory/test_init_factory.py` — no `#### Failure scenarios`
or `#### Prior Tests` section is present.

Seams (highest existing level): `_scan_project_context` (pure scan ->
`dict`, already has a dedicated `TestScanProjectContext` class) and
`write_project_context` (already has `TestWriteProjectContext`). Both are
called with a bare `tmp_path`, no fixtures beyond what the suite already
provides — new coverage extends these seams rather than adding new ones.

Two design decisions not spelled out in the story, resolved during
implementation:

- **No YAML dependency.** The project has zero third-party dependencies
  (`pyproject.toml` declares none) and `init-factory` is stdlib-only.
  `context-lint` already carries a hand-rolled restricted-YAML parser for
  the same agent-context file shapes, but it is not import-friendly from
  another no-extension script. Added `_parse_simple_yaml_mapping`, a
  smaller purpose-built parser (block mappings only, no sequences —
  sufficient for `stack.yaml`/`workflow.yaml`) local to `init-factory`,
  rather than reusing or duplicating context-lint's full parser.
- **`fingerprint_confirmed` requires an existing cache file.** Both the
  Derivation Rules table and the Acceptance Criteria state the rule
  literally: true when `config/project-context.json` *exists* with
  non-empty `languages`/`frameworks`. Since that file is gitignored
  (`.gitignore` line `/config/project-context.json`, written by
  `write_project_context` itself), a truly first-ever scan can never
  satisfy it — it only becomes true once `write_project_context`'s
  reconciliation path re-reads a cache that already has signals in it.
  This is consistent with the already-passing `test_fitting_state_
  brownfield` (pyproject.toml only, no cache -> `fingerprint_confirmed`
  is `False`). The Demo section's "4 of 5 keys true" narrative is
  achieved via the reconciliation path (a pre-existing cache with
  language signals), not via a from-scratch `_scan_project_context` call
  with zero pre-existing artifacts.

Contract-test gap check: no new module was introduced (only two existing
functions in `init-factory` were extended plus new private helpers in the
same file), so no additional contract-test owner was needed beyond the
new unit tests. No user-facing path (CLI command/API/UI) was added or
changed, so no additional smoke test was needed — `init-factory` is
already exercised end-to-end by the existing `run-tests` pre-commit hook.

Harness-mismatch note (see Spec Feedback below): `factory/scripts/
crap-score` globs only `*.py` files; `packages/factory/scripts/
init-factory` has no extension, so the quality gate declared in this
story's frontmatter cannot literally execute against it via the CLI as
currently invoked. Flagged in Spec Feedback rather than silently skipped.

Change init-factory's `_scan_project_context` function to derive fitting keys from tracked artifacts instead of defaulting everything to `false`, so that a collaborator who clones a fitted repo inherits the team's fitting decisions.

**Priority:** must-have

## Demo

A collaborator clones a repo where another user completed the full fitting (agent-context populated, hooks configured, test regime detected). The collaborator runs `init-factory`. Instead of writing all fitting keys as `false`, init-factory checks tracked artifacts: `docs/agent-context/stack.yaml` exists with non-deferred leaves, `.pre-commit-config.yaml` has the factory marker block, `docs/agent-context/testing.yaml` exists. The resulting `project-context.json` shows `fitting.status: "fitting"` with 4 of 5 keys true. Only `model_matrix_configured` is `false` because `config/model.conf` is untracked (model choice is user-specific).

## Acceptance Criteria

- `fingerprint_confirmed` is derived as `true` when `config/project-context.json` exists with non-empty `languages` or `frameworks` observations (design item 7)
- `agent_context_populated` is derived as `true` when `docs/agent-context/stack.yaml` exists with at least one non-deferred leaf field (design item 7)
- `test_regime_detected` is derived as `true` when `docs/agent-context/workflow.yaml#testing` is non-null and non-deferred, or when `testing.yaml` exists under `docs/agent-context/` or `docs/charter/` (design item 7)
- `hooks_decided` is derived as `true` when `.pre-commit-config.yaml` is tracked and contains the factory marker block (design item 7)
- `model_matrix_configured` is never derived -- it defaults to `false` when the cache is absent, because `config/model.conf` is untracked and model choice is user-specific (design item 7)
- `fitting.status` is derived: `"fitted"` when all 5 keys are true, `"unfitted"` when none are true, `"fitting"` otherwise (design item 7)
- When `project-context.json` already exists and a derivable fitting key contradicts its cached value, the artifact wins and the cache is overwritten silently (design item 7)
- All derivation rules have test coverage in `tests/factory/test_init_factory.py`

## Scope

**Status quo:** `_scan_project_context` in init-factory (line ~2354) writes all fitting keys as `False` when the project has signals (brownfield) or as `True` (except `model_matrix_configured`) when greenfield. It does not inspect tracked artifacts. `write_project_context` (line ~2375) skips writing if `project-context.json` already exists.

**Adds:**

- Derivation logic in `_scan_project_context`: after the existing scan, check each derivable artifact and set the corresponding fitting key
- Cache reconciliation in `write_project_context`: when `project-context.json` already exists, read it, re-derive fitting keys from artifacts, overwrite any contradictions, and write back
- Test cases in `test_init_factory.py`: one test per derivation rule, plus a test for cache reconciliation when artifacts contradict cache

**Out of scope:** Changes to VIRGIL's session-start check (that is ST-0211). Changes to the greenfield fitting path (greenfield already skips derivation since there are no artifacts to derive from).

## Terminology

- Fitting key: one of the 5 boolean flags in `project-context.json`'s `fitting` object that tracks whether a fitting step is complete.
- Factory marker block: the section in `.pre-commit-config.yaml` written by init-factory that identifies factory-managed hooks.
- Deferred leaf: a YAML field whose value is a mapping with a single `deferred` key (e.g., `deferred: "full context pass pending"`), indicating the field has not been populated yet.

## Notes for the Implementer

The derivation logic goes in `_scan_project_context` (around line 2354 of `packages/factory/scripts/init-factory`). The existing `write_project_context` function (line 2375) currently returns early if `project-context.json` exists -- the cache reconciliation path needs to replace that early return with a read-derive-overwrite cycle.

Test file `tests/factory/test_init_factory.py` already has fixtures for init-factory. New tests should cover:

1. Brownfield project with all tracked artifacts present -> 4/5 keys true, status "fitting"
2. Brownfield project with no tracked artifacts -> all keys false, status "unfitted"
3. Brownfield project with partial artifacts -> mixed keys, status "fitting"
4. Existing project-context.json with stale cache contradicted by artifact -> artifact wins
5. Greenfield project -> existing behavior unchanged (model_matrix_configured false, others true)
