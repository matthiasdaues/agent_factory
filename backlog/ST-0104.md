# Extend implementation-agent with gate-check loop

Extend the implementation-agent's per-story workflow with a gate-check step
between the developer's commit and the merge. The dispatcher runs each gate
script on committed artifacts, and on failure spawns a fresh developer
agent with only the gate reports and affected files.

**As a** playbook orchestrator,
**I want** the implementation-agent to run semantic gates after each
developer commit and iterate fixes with fresh developer agents,
**so that** gate failures are resolved mechanically within the story's
implementation cycle rather than discovered at QA.

**Priority:** must-have

## Acceptance Criteria

01. The implementation-agent's per-story loop includes: developer commits →
    dispatcher runs gate scripts → if any fail, spawn fresh developer with
    gate reports → iterate until gates pass or cap is reached.
02. The dispatcher reads `quality-gates` from the story file to determine
    which gates apply. Precedence: story field > `house-rules.md` default >
    Factory hardcoded default (all three).
03. Each gate script (`crap-score`, `mutation-analysis`, `dependency-check`)
    is called directly by the dispatcher as a CLI script.
04. The dispatcher reads each gate's JSON output to decide: spawn fix
    iteration or proceed to merge.
05. Each fix iteration starts a **fresh** developer agent with only the gate
    reports and affected files as input (no accumulated context).
06. Maximum fix iterations: 3 per tier (Factory default, tunable in
    `house-rules.md`). When the cap is hit, the story is marked failed.
07. Effective maximum: 6 developer spawns (3 at current tier + 3 at tier+1
    per cost-aware escalation) before the story is terminal.
08. When all gates pass, the dispatcher proceeds to `premerge-check` and
    merge.
09. The gate loop runs per developer iteration, not per git commit, not on
    every push, not only at PR time.
10. The agent definition documents the gate-check loop, iteration cap, and
    interaction with `premerge-check`.
11. All outputs pass `factory/scripts/validate`.
