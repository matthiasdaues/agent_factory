# CLI hook wiring and init-factory step-guard installation

Wire `step-guard` into the `PreToolUse` hook surface of all four supported
CLIs. Create CLI-specific adapters that normalize tool events before calling
`step-guard`. Update `init-factory` to install step-guard wiring alongside
existing hooks (e.g., `block-dangerous-git.sh`).

**As a** Factory user,
**I want** step-guard enforcement installed automatically across all supported
CLIs,
**so that** step isolation applies regardless of which CLI runs the subagent.

**Priority:** must-have

## Acceptance Criteria

1. Claude Code: `.claude/settings.json` includes a `PreToolUse` hook entry
   that invokes `step-guard` with the tool event for `Read`, `Edit`, `Write`,
   and `Bash` tool calls.
2. Codex: `.codex/hooks.json` includes equivalent hook entries.
3. Copilot CLI: `.github/hooks/` contains an adapter script that normalizes
   Copilot CLI's event format and calls `step-guard`.
4. Pi: `.pi/extensions/` contains a TypeScript adapter that normalizes Pi's
   event format and calls `step-guard`.
5. `init-factory` installs step-guard hook wiring alongside existing hooks
   without disturbing them.
6. Existing hooks (e.g., `block-dangerous-git.sh`) continue to function after
   step-guard installation.

## Analysis

Implement step-guard installation in `init-factory` for all four supported
CLIs. The wiring will:

- add a shared shell adapter under `factory/config/hooks/step-guard.sh` for
  Claude Code, Codex, and Copilot CLI;
- add a Copilot hook config at `factory/config/hooks/step-guard.json`;
- add a Pi wrapper at `factory/config/extensions/step-guard.ts`;
- update `factory/scripts/init-factory` so each CLI installs the new step
  guard wiring alongside the existing git-safety and usage-capture hooks;
- preserve existing hooks and make the new files removable through the
  existing manifest-based uninstall flow.

Planned test coverage:

- fresh install wires Claude Code, Codex, Copilot CLI, and Pi step-guard
  assets;
- rerun is idempotent and leaves the existing hook files unchanged;
- pre-existing Codex hooks still retain unrelated entries while gaining the
  new step-guard handlers;
- existing guardrail/usage-capture tests continue to pass after the new wiring
  lands.

Concerns / ambiguities:

- Copilot CLI documents several file-tool aliases (`read_file`, `view`,
  `edit`, `write_file`, `create`), so the adapter and matcher config need to
  cover those aliases explicitly.
- The shared adapter must normalize raw CLI payloads before calling
  `step-guard`, because the hook surfaces are not isomorphic.
