# Update planning-agent and create-backlog for charter

Update the planning-agent and its `create-backlog` skill to read the charter, acknowledge Epic 0 stories already in the backlog, and populate the `tests:` field when pre-existing tests cover a story's acceptance criteria.

**Priority:** must-have

## Acceptance Criteria

- `planning-agent.md` `inputs:` includes `docs/charter/*.md`
- `create-backlog` skill instructs the agent to read `docs/charter/*.md` before creating stories
- When Epic 0 stories already exist in the backlog (from `capture-charter` completeness sweep), the planning-agent derives feature stories with `deps:` on the final Epic 0 story
- The skill instructs the agent to check for pre-existing tests matching acceptance criteria and record them in the `tests:` field
- Feature story acceptance criteria use concrete names from the charter (actual test framework, deployment target, API framework) rather than generic placeholders

## Implementation Notes

The planning-agent does not create Epic 0 stories — `capture-charter` does that. The planning-agent finds them already in the backlog and schedules feature stories after them. The `tests:` population happens at story creation time; amendments after backlog approval are owned by the orchestrating session.
