# Create dependency-check gate skill, script, and fixture

Create the dependency-check gate: a skill document, a CLI wrapper script,
and a test fixture. The gate enforces module dependency directions declared
in `architecture.dsl`. Neither TDD nor the testing strategy addresses
dependency direction; this gate fills the gap.

**As a** implementation-agent dispatcher,
**I want** a deterministic dependency-check gate that validates import
directions against `architecture.dsl`,
**so that** architectural rules are enforced mechanically rather than
discovered during architecture review.

**Priority:** must-have

## Acceptance Criteria

01. `factory/skills/dependency-check/SKILL.md` exists and documents the
    dependency-rule enforcement gate.
02. `factory/scripts/dependency-check` is an executable script that reads
    `docs/arc42/architecture.dsl` and checks source imports against declared
    dependency rules.
03. The script produces a JSON report per rule: rule name, pass/fail,
    violating import (file, line, imported module).
04. Reports are logged to
    `.agent-factory/dependency-check/<story-id>.json`.
05. Default threshold: 0 violations (architectural rules are binary).
06. The script exits non-zero on any violation.
07. Tool candidates: `deptrack` (general), `dependency-cruiser` (JS/TS),
    `arch-pkg` (Go).
08. `factory/fixtures/quality-gates/dependency-violation/` contains a
    self-contained test project with: an `architecture.dsl` declaring
    module A must not depend on module B, a source file in A importing B
    (expected violation), and a conforming import (expected pass).
09. The script runs against the fixture and produces the expected results.
10. All outputs pass `factory/scripts/validate`.
