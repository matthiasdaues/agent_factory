# Validate and document first-class Codex operation

Close the feature with an executable installation smoke test and concise
operator instructions for discovery, native subagents, trust, and removal.

**Priority:** must-have

## Acceptance Criteria

- A temporary consumer repository proves installed skills, generated agent TOML,
  aliases, hook configuration, idempotency, and traceless removal.
- The test validates all generated TOML through Python's `tomllib`.
- The guide explains Codex native subagents, inherited permission behavior,
  `agents.max_concurrent_threads_per_session`, and the `/hooks` trust step.
- The proposal records implementation status and any bounded manual limitation.
- The full repository suite passes with warnings treated as errors.

## Analysis

The lower-level Codex tests already own generation, collision, hook, manifest,
and removal contracts. This story adds one consumer-level smoke rather than
duplicating them: install into a temporary repository, validate all discovered
skills and every generated TOML, check aliases and hook events, re-run
byte-stably, remove, and compare the original consumer files byte-for-byte.

The guide now describes native Codex subagent threads, inherited parent
permissions, the `agents.max_concurrent_threads_per_session` setting, local
discovery paths, and the mandatory project-trust and `/hooks` review steps. The
proposal is marked implemented and records the bounded manual limitation:
automated tests prove the on-disk contract, but cannot make the user's Codex
trust decision.
