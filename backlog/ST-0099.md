# Create scope-map-migration skill

Create a one-time migration skill that backfills `docs/spec/scope-map.md`
from existing `derive-spec` output artifacts. Used once per project
adopting `derive-feature`, before the first new feature is specified.

**As a** requirements-agent,
**I want** a migration skill that populates the scope map from existing
UC-XX documents and actor-goal lists,
**so that** brownfield projects can adopt `derive-feature` without losing
traceability to prior specification work.

**Priority:** should-have

## Acceptance Criteria

1. `factory/skills/scope-map-migration/SKILL.md` exists and documents the
   migration process.
2. The skill reads all available `derive-spec` output artifacts in priority
   order: `actor-goal-list.md` (primary), `UC-XX-short-name.md` files,
   then cross-check inputs (`system-use-cases.md`, `entity-model.md`,
   `interface-contracts.md`, `state-machines.md`, `validation-rules.md`).
3. When `actor-goal-list.md` exists, one Rule per actor-goal row is created
   in the scope map.
4. When `actor-goal-list.md` is missing, the skill falls back to deriving
   Rules from `UC-XX-short-name.md` filenames and their Summary fields.
5. When both are missing but other spec artifacts exist, the skill creates
   a scope map with a `NOTE: manual population required` entry and exits
   without error.
6. All entries are populated with status `implemented` and source column
   pointing at the originating UC-XX file (not a `.feature` file).
7. No `.feature` files are created for old features; UC-XX documents stay
   as-is.
8. The output passes `factory/scripts/validate`.
