# Create YAML templates, codify agent-context convention, and validate with core CX-\* codes

Deliver the four YAML template files that define the agent-context schema, the convention document and rules.md entry that codify composition rules, and a renamed context-lint script that validates agent-context files with the six core CX-\* finding codes (CX-FILE, CX-PARSE, CX-KEYS, CX-NULL, CX-MODE, CX-MODE-INVALID). Rename the pre-commit hook entry from charter-lint to context-lint.

**Priority:** must-have

## Analysis

Traced to `docs/spec/agent-context.feature` Rule "context-lint validates agent context structure and references" (the six in-scope Scenarios: CX-FILE ×2, CX-PARSE, CX-KEYS ×2, CX-NULL ×2, CX-MODE, CX-MODE-INVALID) and Rule "Convention codifies agent context composition rules", plus [ADR-0013](../docs/adr/0013-yaml-agent-context-replaces-markdown-charter.md) (YAML format) and [ADR-0014](../docs/adr/0014-two-layer-routing-with-two-mode-lifecycle.md) (two-layer routing, two-mode lifecycle). Schema and convention text traced to [yaml-charter-lifecycle.md](../docs/proposals/yaml-charter-lifecycle.md).

Three discrepancies found between this story's own text and the proposal/ADRs it traces to; the proposal and ADRs were treated as authoritative since they are the design origin and this story's job is to implement, not to redecide:

- **CX-NULL scope.** The proposal's validation table restricts `CX-NULL` to `stack.yaml` and `workflow.yaml`; the story's Demo section says "every null placeholder field" with no file restriction, and the mode-transition condition (ADR-0014) is explicitly "across all three index files." Implemented `CX-NULL` across all three index files (including `governance.yaml`) for consistency with the transition condition and the Demo's plain reading. Flagged in Spec Feedback for the proposal's validation table to be corrected to match.
- **Template `mode` field.** This story's Acceptance Criteria states "the four YAML templates each contain ... `mode: primary`," but the proposal and ADR-0014 both specify that `reading-guides.yaml` (Layer 1) carries no `mode` field — only the three Layer 2 index files do. Implemented per the proposal/ADR: three index templates carry `mode: primary`; `reading-guides.yaml` does not.
- **Pre-commit hook rename.** No `charter-lint` hook entry exists in `.pre-commit-config.yaml` (verified: `git log --all -- .pre-commit-config.yaml` and `grep charter-lint` across history both come back empty). There was nothing to rename. Added a new `context-lint` hook entry (in both hook blocks, mirroring the existing `backlog-lint` pattern) instead, which delivers the acceptance criterion's intent — a working `context-lint` pre-commit gate.

Out of scope, confirmed unaffected: CX-SRC/CX-SRC-EXIST/CX-SRC-STALE/CX-GUIDE-REF (ST-0191), CX-FORMAT and format detection between `docs/agent-context/` and `docs/charter/` (ST-0192), and consumer path updates across skills/playbooks/agents that still reference `charter-lint` by name (EPIC 4) — the legacy CH-\* validation logic and its CLI path (`--charter-dir`) are preserved unchanged in `context-lint` for ST-0192 to wire in via format detection.

## Demo

Operator copies the four YAML templates into `docs/agent-context/` and runs `context-lint`. context-lint reports CX-NULL warnings for every null placeholder field and a CX-MODE info message confirming `mode: primary`. Operator introduces a YAML syntax error in `stack.yaml` and re-runs -- context-lint reports a CX-PARSE error. Operator fixes the syntax, removes the `languages` key entirely, and re-runs -- context-lint reports a CX-KEYS error. Operator sets `mode: staging` and re-runs -- context-lint reports a CX-MODE-INVALID error for the unrecognized mode value. Operator opens `factory/rulebooks/conventions/agent-context-composition.md` and finds binding rules for derived content, mode semantics, write-path ownership, format exclusivity, and source-pointer direction of truth.

## Acceptance Criteria

- context-lint reports a CX-FILE error for each missing required file when `docs/agent-context/` exists but a file is absent (agent-context.feature Rule: context-lint validates, Scenario: CX-FILE reports missing required file).
- context-lint does not report CX-FILE for reading-guides.yaml when all index files have `mode: primary` (agent-context.feature Rule: context-lint validates, Scenario: CX-FILE does not require reading-guides.yaml when mode is primary).
- context-lint reports a CX-PARSE error for any file with invalid YAML syntax (agent-context.feature Rule: context-lint validates, Scenario: CX-PARSE reports invalid YAML).
- context-lint reports a CX-KEYS error for any index file missing a required top-level key (agent-context.feature Rule: context-lint validates, Scenario: CX-KEYS reports missing required top-level keys).
- context-lint reports a CX-KEYS error when a `deferred` key coexists with `name` or `source` at the same field (agent-context.feature Rule: context-lint validates, Scenario: CX-KEYS reports deferred coexisting with name or source).
- context-lint reports a CX-NULL warning for null values in default mode and a CX-NULL error when run with `--planning-gate` (agent-context.feature Rule: context-lint validates, Scenarios: CX-NULL default + planning-gate).
- context-lint reports a CX-MODE info finding for valid mode values and a CX-MODE-INVALID error for unrecognized mode values (agent-context.feature Rule: context-lint validates, Scenarios: CX-MODE + CX-MODE-INVALID).
- The four YAML templates each contain the required top-level keys with null placeholder values and `mode: primary`.
- `agent-context-composition.md` documents binding rules for derived content, mode semantics, write-path ownership, format exclusivity, and source-pointer direction of truth.
- `rules.md` contains an "Agent context composition" section with MUST and MUST NOT entries referencing the convention.
- The pre-commit hook entry for charter-lint is renamed to context-lint in `.pre-commit-config.yaml`.

## Scope

**Status quo:** `factory/scripts/charter-lint` validates legacy markdown charters with CH-\* codes. `.pre-commit-config.yaml` references `charter-lint` as a hook. No YAML templates exist for agent-context. No convention document exists for agent-context composition rules. `rules.md` references charter-era wording ("MUST derive Epic 0 from the charter").

**Adds:** Four YAML template files under `factory/rulebooks/templates/`. A new `agent-context-composition.md` convention. An updated "Agent context composition" section in `rules.md`. The `context-lint` script (renamed from `charter-lint`) with six core CX-\* finding codes. A renamed pre-commit hook entry. Test fixtures under `tests/fixtures/agent-context/`. Contract tests in `tests/factory/test_context_lint.py` covering ACX-01 through ACX-05.

**Out of scope:** CX-SRC, CX-SRC-EXIST, CX-SRC-STALE, CX-GUIDE-REF codes (ST-0191). CX-FORMAT detection and CH-\* fallback (ST-0192). capture-context and update-context skills (EPICs 2, 3). Consumer path updates (EPIC 4).

## Terminology

- context-lint: The renamed validation script (formerly charter-lint) that validates agent-context YAML files with CX-\* finding codes.
- CX-\* codes: Finding codes emitted by context-lint for agent-context validation issues (CX-FILE, CX-PARSE, CX-KEYS, CX-NULL, CX-MODE, CX-MODE-INVALID).
- Index file: One of the three Layer 2 YAML files (stack.yaml, workflow.yaml, governance.yaml) that carry project context fields.
- Reading guide: The Layer 1 YAML file (reading-guides.yaml) that routes work-type concerns to index-file sections via key-path references.

## Notes for the Implementer

The context-lint script is a rename of `factory/scripts/charter-lint`. Preserve the existing CH-\* validation logic for later use in ST-0192; this story adds only the CX-\* code paths for YAML validation. The four templates should follow the schema described in the proposal's "Templates" section. The required top-level keys for each template are defined by the proposal. Test fixtures under `tests/fixtures/agent-context/` should include both valid and invalid YAML files for each CX-\* code. New tests target the contract test layer under `tests/factory/`.
