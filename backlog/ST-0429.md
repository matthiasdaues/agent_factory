# Merge a story without touching the installed copy

**Priority:** must-have

## Goal

`dispatch merge-story` leaves `.agent-factory/factory` unchanged. The test suite of this repository passes without reading this repository's installed copy.

## Domain Rule

- The Factory repository is a project like any other: its code and tests live in `packages/factory` and `tests/`, and the tests run the code from there.
- Tests that install the Factory into a temporary project keep using that project's `.agent-factory`.
- The `.agent-factory` link for `scope-lint` in `test_core_layout_gates.py`, line 484, is no read of the installed copy (OI-08).
- A static scan cannot see a runtime read; the story runs the suite once in a linked worktree, which holds no `.agent-factory/`.

## Outputs

- Lines 1954 to 1962 of `dispatch`, the copy of `packages/factory` over `.agent-factory/factory`, and their comment go.
- The `spec` marker description in `pyproject.toml` gains the prefix RL.
- Each runtime read of the installed copy that the worktree run finds moves to `packages/factory`.

## Demo Scenario

1. The implementation agent runs `dispatch merge-story ST-0350` in an orchestrated run.
2. `find .agent-factory/factory -newer <marker-file>` in the calling checkout prints nothing.
3. The maintainer runs the test suite in a linked worktree with no `.agent-factory/`, and it passes.

## Demo Data

None. The test builds a temporary repository with `packages/factory/` and `.agent-factory/factory/` and compares the installed copy before and after the merge.

## Boundaries

- This story runs in wave 1, before every other story that edits `dispatch`, so later merges of this backlog do not change the running copy.
- No test of a temporary project changes its use of that project's `.agent-factory`.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.

## Affected Paths

- `pyproject.toml` — the `spec` marker description
- `tests/factory/` — new rows in `test_run_lifecycle_dispatch.py` and `test_run_lifecycle_text.py`

- Installing the Factory into this repository with `update-factory`.

## Agent Stop Conditions

- The worktree run finds a test that needs the installed copy and cannot read `packages/factory` instead. Report the test and stop.

## Analysis

- `merge-story` loses the block that copies `packages/factory` over `.agent-factory/factory`, together with its comment. Nothing else in `cmd_merge_story` changes.
- `pyproject.toml` adds RL to the prefixes in the description of the `spec` marker.
- `tests/factory/test_run_lifecycle_dispatch.py` holds RL-18-IT-01. The test builds a repository in `tmp_path` with a tracked `packages/factory` and an ignored `.agent-factory/factory` that differ, runs `merge-story` from the feature branch worktree, and compares every file of the installed copy before and after.
- `tests/factory/test_run_lifecycle_text.py` holds RL-18-LN-01 and RL-18-LN-02. A scanner finds each path expression that starts at the repository root of a test file (`REPO_ROOT`, `PROJECT_ROOT`, `ROOT`) and names `.agent-factory`. A link target passed to `symlink_to` that names `.agent-factory` alone does not count, so the `scope-lint` link of `test_core_layout_gates.py` stays allowed. Paths under a temporary project start at `tmp_path` or a fixture root, so the scanner does not see them.
- Scenarios covered: `merge-story copies nothing into the installed copy`, `The test suite of this repository reads no installed copy of its own`, `A link to this repository's .agent-factory for scope-lint is no read of the installed copy`.
- The story worktree holds no `.agent-factory/`, so the suite run in it is the run in a linked worktree that the Evidence asks for.
