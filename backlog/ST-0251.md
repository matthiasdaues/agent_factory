# Verify the documented DuckDB UI launch command resolves all six published views

Create the DuckDB UI launch documentation, bootstrap SQL, and a smoke gate that verifies the bootstrap registers all six published views without starting the UI.

**Priority:** could-have

## Goal

After this story ships, the operator runs `usage-ui-doc-check` and sees it parse the documented launch command, resolve the query-model-v1 bootstrap SQL, and confirm all six views are registered — without starting or fetching the DuckDB UI. The documentation supplies no repository-owned dashboard formulas or saved charts.

## Domain Rule

- The documented UI launch command resolves the query-model-v1 bootstrap SQL.
- The bootstrap SQL registers exactly six published views: `raw_usage_snapshots`, `latest_run_snapshots`, `canonical_session_usage`, `usage_by_dimension`, `cache_efficiency`, and `capture_health`.
- DuckDB UI assets being absent or unavailable does not block deterministic analysis, query, or accounting gates.
- The repository supplies no dashboard formulas or saved charts.

## Demo Scenario

1. Read the usage-analysis component's documented DuckDB UI launch command in the component documentation.
2. Run `packages/usage/scripts/usage-ui-doc-check`.
3. Verify the smoke check parses the documented command, resolves the bootstrap SQL, and confirms six views registered.
4. Verify the smoke check completes without starting, fetching, or installing the DuckDB UI.
5. Verify the documentation contains no dashboard formulas or saved charts.

## Affected Paths

- `packages/usage/docs/ui-exploration.md` — new file (DuckDB UI launch documentation)
- `packages/usage/sql/bootstrap-v1.sql` — new file (bootstrap SQL registering six views)
- `packages/usage/scripts/usage-ui-doc-check` — new file (smoke gate)

## Outputs

- `packages/usage/docs/ui-exploration.md` — documentation specifying the exact DuckDB UI launch command and its relationship to the query model. Contains no dashboard formulas or saved charts.
- `packages/usage/sql/bootstrap-v1.sql` — SQL script that registers all six published views for UI exploration.
- `packages/usage/scripts/usage-ui-doc-check` — executable Python script that parses the documented command from `ui-exploration.md`, resolves the bootstrap SQL path, reads the SQL, and verifies it registers exactly the six expected view names. Exits zero on success, non-zero on failure. Does not start, fetch, or install the DuckDB UI.

## Constraints

- The smoke gate must not start, fetch, or install the DuckDB UI.
- The smoke gate is stdlib-only Python (no DuckDB import needed — it parses SQL text).
- The bootstrap SQL references the same view definitions used by `usage-query`.
- No dashboard formulas, saved charts, or custom UI plugins in the repository.

## Suggested Agent Plan

1. Create `packages/usage/sql/bootstrap-v1.sql` with SQL statements registering all six published views.
2. Create `packages/usage/docs/ui-exploration.md` documenting the DuckDB UI launch command and referencing the bootstrap SQL.
3. Create `packages/usage/scripts/usage-ui-doc-check` that parses the documented command, resolves the bootstrap path, and verifies six view registrations.
4. Write tests verifying the smoke gate detects missing or extra views.
5. Run `packages/usage/scripts/usage-ui-doc-check` and verify exit zero.
