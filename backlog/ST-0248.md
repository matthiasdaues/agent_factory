# Export a published view as atomic attributable Parquet and verify the dependency boundary

Deliver the Parquet Exporter with atomic replacement and provenance, and the `usage-dependency-check` gate verifying locked DuckDB and PyArrow declarations.

**Priority:** should-have

## Goal

After this story ships, the operator runs `usage-query usage_by_dimension --format parquet -o report.parquet` and sees the file contain the correct rows, schema, query-model version, and input-set digest as provenance metadata. A second export that fails mid-write leaves the prior `report.parquet` unchanged. Running `usage-dependency-check` exits zero, confirming DuckDB and PyArrow are directly declared and locked, and the package runs from a complete offline cache.

## Domain Rule

- Parquet export writes a temporary sibling, verifies rows and schema through a round-trip read, records provenance (query-model version and input-set digest), and atomically replaces the destination.
- Interrupted or failed export leaves the prior destination unchanged.
- No scheduled, incremental, or automatically refreshed Parquet state is created.
- Export happens only on explicit operator request.
- DuckDB and PyArrow are directly declared and version-locked.

## Demo Scenario

1. Run `usage-query usage_by_dimension --format parquet -o report.parquet`. Verify `report.parquet` contains the correct rows and schema.
2. Read Parquet metadata. Verify query-model version and input-set digest are recorded.
3. Place a valid `report.parquet` at the destination. Simulate a corrupted or interrupted replacement. Verify the prior `report.parquet` remains unchanged and the command exits non-zero.
4. Run `packages/usage/scripts/usage-dependency-check`. Verify it confirms DuckDB and PyArrow are directly declared and locked, and the package runs from a complete offline cache.

## Outputs

- `packages/usage/src/usage/parquet_exporter.py` — module that:
  1. Writes the view result to a temporary sibling file next to the destination.
  2. Reads the temporary file back and verifies rows and schema match the source view.
  3. Writes query-model version and input-set digest as Parquet metadata.
  4. Atomically replaces the destination using `os.rename`.
  5. On failure at any step, removes the temporary file and exits non-zero, leaving the prior destination unchanged.
- `packages/usage/src/usage/cli.py` gains `--format parquet` with required `-o` output path. Rejects `parquet` format without an output path.
- `packages/usage/scripts/usage-dependency-check` — executable Python script verifying:
  - DuckDB and PyArrow are directly declared in `pyproject.toml` (not transitive).
  - Versions are locked (pinned or bounded).
  - The package runs from a complete offline cache (simulates network-disabled execution).
- Integration tests covering: successful export with provenance, round-trip verification, interrupted export (prior file preserved), and dependency-check gate.

## Constraints

- Atomic replacement uses `os.rename` (same filesystem). No cross-filesystem copy.
- The temporary sibling is always cleaned up on failure.
- No automatic, scheduled, or incremental Parquet materialization.
- `usage-dependency-check` is stdlib-only Python.
- Do not modify accounting SQL or view definitions.
