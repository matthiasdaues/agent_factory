# Report capture health when preflight fails and refuse stable views until evidence is valid

Deliver the `capture_health` DuckDB view, stable-view refusal on preflight failure, and diagnostic mode.

**Priority:** must-have

## Goal

After this story ships, the operator runs `usage-query capture_health` on an input set containing failures and sees valid counts and failures grouped by stable failure code and source file. Running `usage-query canonical_session_usage` on the same set exits non-zero before accounting runs and emits no partial stable result. Running `usage-query capture_health --diagnostic` labels valid and invalid lines as incomplete and cannot produce a stable export.

## Domain Rule

- When preflight finds any failure, `capture_health` remains available.
- All stable views other than `capture_health` refuse partial results and exit non-zero before accounting.
- Diagnostic mode labels valid and invalid lines as incomplete and cannot emit a stable export.
- `capture_health` reports valid counts and failures grouped by failure code and source file.

## Demo Scenario

1. Prepare an input set containing valid records and records with various ancestry defects.
2. Run `usage-query capture_health --usage-dir that-set/`. Verify the health view reports valid line counts and failures grouped by failure code and source file.
3. Run `usage-query canonical_session_usage --usage-dir that-set/`. Verify exit non-zero with no partial output.
4. Run `usage-query capture_health --usage-dir that-set/ --diagnostic`. Verify valid and invalid lines are labeled as incomplete.
5. Attempt a stable export in diagnostic mode. Verify it is refused.

## Outputs

- `packages/usage/src/usage/views/capture_health.py` — DuckDB view that queries the preflight valid and failure relations. Reports: valid line count, failure count grouped by failure code, failure count grouped by source file, and total selected line count.
- `packages/usage/src/usage/cli.py` gains:
  - `capture_health` view routing to the new view module.
  - Stable-view refusal: when preflight failures exist, all views except `capture_health` print a message and exit non-zero before accounting.
  - `--diagnostic` flag: when set, `capture_health` labels all lines (valid and invalid) as incomplete. Stable export requests are refused in diagnostic mode.

## Constraints

- `capture_health` must be available even when all other views are blocked.
- Stable-view refusal must exit non-zero before any accounting SQL runs (no partial results).
- Diagnostic mode is informational only. It cannot produce a stable export.
- Do not implement accounting or conservation rules (EPIC 3).

## Suggested Agent Plan

1. Create `packages/usage/src/usage/views/` directory and `capture_health.py` with the DuckDB view querying valid/failure relations.
2. Update `cli.py` to route `capture_health` to the new view module.
3. Implement stable-view refusal: check preflight failure count before routing to any view other than `capture_health`. Exit non-zero with a message.
4. Add `--diagnostic` flag handling: when set with `capture_health`, label all lines as incomplete and refuse stable exports.
5. Write tests: health view with mixed valid/failure input, stable-view refusal, diagnostic mode.
6. Run `usage-query capture_health --usage-dir packages/usage/fixtures/ancestry/` and verify grouped output.
