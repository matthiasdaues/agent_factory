# Send each drift row to its owner and reviewer after a merge

**Priority:** must-have

## Goal

After a story merges, the implementation agent dispatches the owner of each drift row, and then the owner's reviewer. A rejected row becomes a `BUG` finding against the code. Every writer of the shared working output declares the paths it writes.

## Contract

| Operation                         | Input state                                   | Outcome                                                                                                                                                               | Persistence              |
| --------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| Implementation agent, after merge | Row `open`, `owner: domain-modeling-agent`    | Dispatches the domain-modeling agent, which sets `fixed`                                                                                                              | The story's report       |
| Implementation agent              | Row `fixed`                                   | Dispatches the owner's reviewer, which sets `confirmed` or `rejected`                                                                                                 | The story's report       |
| Reviewer rejects                  | Row `rejected`                                | The reviewer files a `BUG` finding with `owner: developer-agent`                                                                                                      | `docs/findings/BUG-*.md` |
| Stakeholder rejects               | Row `rejected` in a stakeholder session       | The agent that ran the session files the `BUG` finding                                                                                                                | `docs/findings/BUG-*.md` |
| Manual mode                       | A story's report has an `open` or `fixed` row | The dispatch contract says the human does not close the story                                                                                                         | —                        |
| Manual mode, story close          | An open `QA` finding                          | The implementation agent dispatches the test-strategy agent for it, as after `close-wave` in automated mode (CAO-G31; ST-0358 row 5)                                  | The finding              |
| Read `INDEX.yaml`                 | After this story                              | Each writer of the Working output table declares its paths                                                                                                            | —                        |
| Read `INDEX.yaml`                 | After this story                              | The developer agent declares no `docs/adr/*.md` output. A stale or missing ADR becomes a spec-feedback row with `owner: architecture-agent` (stakeholder, 2026-11-04) | —                        |

## Demo Scenario

1. `docs/spec/work/spec-feedback-ST-0318.md` holds the `open` row from ST-0360's demo. ST-0318 merges.
2. The implementation agent dispatches the domain-modeling agent. It adds the rule and sets the row to `fixed`.
3. The implementation agent dispatches the spec-review agent. It sets the row to `confirmed`.
4. For a second row, the spec review finds that the code breaks an accepted requirement. It sets `rejected` and files `BUG-0012` with `owner: developer-agent`.

## Analysis

**What changes.** The implementation agent gets a post-merge sub-step 4e in automated mode. It dispatches the owner of each `open` row of the merged story's report, and then the reviewer of each `fixed` row. The reviewer is the `reviewed_by:` entry of the owner's declaration for the row's artifact. The dispatch contract gets a new section, Drift Rows After A Merge, with that order and the `BUG` rule. Its § Manual Mode gets the per-story rule and the QA routing at story close (CAO-G31). Manual steps 5 and 8 of the implementation agent apply both rules without new step numbers. Step 6 "Route the QA findings" stays as it is.

**Declarations.** The seven agents of the writer outline declare `docs/spec/work/spec-feedback-*.md` and `docs/reviews/reconciliation-*.md`. The spec-review, architecture-review, requirements, domain-modeling, and test-strategy agents and Virgil also declare `docs/findings/BUG-*.md`. Each new declaration has `required: false` and no `reviewed_by:`. The developer agent drops `docs/adr/*.md`, and its step 6 turns a stale or missing ADR into a row with `owner: architecture-agent`. The reconciliation agent already declares its report; ST-0363 owns the rest of its declarations.

**Files.** `packages/factory/agents/` (implementation, developer, requirements, domain-modeling, architecture, test-strategy, spec-review, architecture-review agents, and Virgil), `packages/factory/rulebooks/conventions/dispatch-contract.md`, `packages/factory/INDEX.yaml`, `tests/factory/test_core_artifact_ownership.py`, and `tests/factory/test_core_artifact_ownership_text.py`.

**Scenarios covered.** "After a merge the implementation agent dispatches each row's owner and then the reviewer", "A rejected row becomes a BUG finding against the code", "The agent of a stakeholder session records the stakeholder's review", "In manual mode the human closes a story only after its rows are handled" (CAO-14-LN-01), and the outline "Each writer of a shared working-output file declares its path" (CAO-17-LN-01).

**Concern.** The proposal and the manual-mode Scenario say a story stays open while any row is `open` or `fixed`. In automated mode a `fixed` row about a non-core artifact passes (DEC-35), and such a row has no reviewer. A literal per-story rule would keep such a story open forever. The manual-mode text follows DEC-35, and the spec-feedback section records the mismatch.

**Seams.** Text checks on the agent definitions and the dispatch contract, and the real-catalog check on `INDEX.yaml`. No code path changes.
