# Send each drift row to its owner and reviewer after a merge

**Priority:** must-have

## Goal

After a story merges, the implementation agent dispatches the owner of each drift row, and then the owner's reviewer. A rejected row becomes a `BUG` finding against the code. Every writer of the shared working output declares the paths it writes.

## Contract

| Operation                         | Input state                                   | Outcome                                                               | Persistence              |
| --------------------------------- | --------------------------------------------- | --------------------------------------------------------------------- | ------------------------ |
| Implementation agent, after merge | Row `open`, `owner: domain-modeling-agent`    | Dispatches the domain-modeling agent, which sets `fixed`              | The story's report       |
| Implementation agent              | Row `fixed`                                   | Dispatches the owner's reviewer, which sets `confirmed` or `rejected` | The story's report       |
| Reviewer rejects                  | Row `rejected`                                | The reviewer files a `BUG` finding with `owner: developer-agent`      | `docs/findings/BUG-*.md` |
| Stakeholder rejects               | Row `rejected` in a stakeholder session       | The agent that ran the session files the `BUG` finding                | `docs/findings/BUG-*.md` |
| Manual mode                       | A story's report has an `open` or `fixed` row | The dispatch contract says the human does not close the story         | —                        |
| Read `INDEX.yaml`                 | After this story                              | Each writer of the Working output table declares its paths            | —                        |

## Demo Scenario

1. `docs/spec/work/spec-feedback-ST-0318.md` holds the `open` row from ST-0360's demo. ST-0318 merges.
2. The implementation agent dispatches the domain-modeling agent. It adds the rule and sets the row to `fixed`.
3. The implementation agent dispatches the spec-review agent. It sets the row to `confirmed`.
4. For a second row, the spec review finds that the code breaks an accepted requirement. It sets `rejected` and files `BUG-0012` with `owner: developer-agent`.
