# Enforce fresh sessions at workflow phase boundaries

Make each multi-phase workflow stop after a reviewed handoff and make the next
phase restart from durable artifacts, bounded reads, and bounded child-result
envelopes.

**Priority:** must-have

## Acceptance Criteria

- Both multi-phase playbooks mark every phase transition as a handoff and hard
  stop before the next phase.
- Every listed multi-phase agent defines phase entry from the handoff and
  referenced artifacts and phase exit through the handoff skill.
- Agent contracts require large artifacts to be read initially through bounded
  chunks and expanded only on demand.
- Before return, child work is persisted in canonical tracked artifacts; the
  parent-facing content is limited to disposition, severity counts, all
  artifact paths, and a one-to-three-sentence next action.
- Contract tests cover every declared playbook and agent surface without
  replaying a prior transcript.

## Implementation Notes

This story owns all canonical playbook/agent prose, avoiding file overlap with
the validator and runtime-envelope stories.

## Analysis

Implement UC-11's hard phase boundary in the two declared multi-phase
playbooks and eight declared agent contracts. Each playbook will enumerate its
forward, review/remedy, skip, reconciliation, and quality routes as reviewed
handoff points: the outgoing session invokes `handoff`, passes structural lint
and independent semantic review, then stops; a fresh session reads the handoff
before durable artifacts. Each agent will declare the same phase-entry and
phase-exit responsibilities, bounded initial reads with on-demand expansion,
and the BR-040 child-return envelope after full results are persisted.

Only the two playbooks, eight agents, this story, and the focused contract test
will change. The work preserves the accepted proposal's reliability/operations
governance and its exclusions: no prior-transcript replay, in-place transcript
compaction, prose-only cache-restabilisation ritual, live cache control, or
verbatim child-result injection.

Chicago-school contract tests observe the canonical Markdown surfaces read by
Factory participants. They cover every routed transition in both playbooks,
every listed agent's declared `handoff` skill plus phase entry/exit, BR-041
bounded artifact reads, and BR-040 persistence and bounded parent envelope.
The handoff convention and validator from ST-0065 remain unchanged seams.

The playbooks contain role-level review/remedy/reconciliation routes in
addition to named Factory phases. These are enumerated explicitly, while the
existing handoff contract remains authoritative for deciding whether a route
crosses a mandatory boundary or qualifies for its same-phase exemption. The
accepted proposal deliberately excludes `planning-agent` from this story's
agent outputs, so its contract is not modified here.

Implementation revealed one generated-output dependency: changing canonical
agent and playbook bodies changes their token counts and totals in
`factory/INDEX.yaml`. The dispatcher authorized amending this story's output
contract to name that deterministic derivative explicitly; regeneration is
required for `index-lint` and creates no new behavioral scope. ST-0066 merges
before ST-0068, whose later regeneration will use the combined catalog state.

## Spec Feedback

Compared the playbook and agent contracts with UC-11, FR-K1/FR-K4/FR-K5,
BR-039…BR-041, the entity/state/interface/validation supplementary specs, and
the arc42 container/runtime views. No drift was found: the change operationally
applies the already specified fresh-session, durable-artifact, bounded-read,
and bounded-child-envelope behavior without adding an entity, state,
component, deployment boundary, live cache control, or in-session compaction.
No specification update or ADR is needed. `factory/INDEX.yaml` was regenerated
only as the catalog's existing deterministic projection of the changed source
contracts.
