# Add explicit persona transition at the VIRGIL/playbook boundary

Add an exception clause to VIRGIL's boundaries and update the newcomer-tour's boundary wording so that playbook selection cleanly drops VIRGIL's constraints.

**Priority:** must-have

## Demo

A newcomer completes the newcomer tour. VIRGIL offers poc-spike at step 10. The user accepts. The model reads VIRGIL's exception clause, drops VIRGIL's constraints (including "MUST NOT write code"), reads the poc-spike playbook, and follows its operational procedure. The user sees code written without a refusal or unexplained constraint drop.

## Acceptance Criteria

- VIRGIL's boundaries section contains an exception clause stating that VIRGIL's constraints apply while VIRGIL is the active persona and do not carry into a playbook session selected through the session menu or accepted from a skill offer (design item 3)
- The exception clause does not apply to skills invoked within VIRGIL's own session (explain-concept, capture-context, grilling) -- those continue to run under VIRGIL's constraints (design item 3)
- The newcomer-tour boundary "Do not spawn agents or launch a playbook" is replaced with "Do not launch a playbook directly -- offer it and let the session menu handle the transition" (design item 3)
- session-menu.md already says "read the playbook's markdown file and follow its operational procedure" -- this story does not modify session-menu.md

## Scope

**Status quo:** VIRGIL's boundaries say "MUST NOT write code" and "does not run those playbooks itself" with no exception clause. The newcomer-tour boundary says "Do not spawn agents or launch a playbook." When poc-spike follows the newcomer tour, the persona constraints contradict the playbook's step 2 ("Build it yourself"), producing either a refusal or a silent constraint drop.

**Adds:**

- Exception clause in virgil.md Boundaries section: "VIRGIL's constraints -- including 'MUST NOT write code' and 'does not run those playbooks itself' -- apply while VIRGIL is the active persona. When the user selects a playbook from the session menu or accepts a playbook offer, the model drops the VIRGIL persona, reads the playbook's markdown file, and follows its operational procedure per session-menu.md. VIRGIL's MUST NOTs do not carry into the playbook session."
- Updated newcomer-tour boundary wording

**Out of scope:** Changes to session-menu.md; changes to any playbook file; persona-transition logic for skills (those stay under VIRGIL's constraints).

## Notes for the Implementer

The exception clause text is specified verbatim in the proposal's design item 3. The newcomer-tour boundary replacement is also specified verbatim. Both changes are additions/replacements of specific sentences in existing markdown files.
