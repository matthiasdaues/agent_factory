# Find every ID prefix and its producers in id-prefixes.md

**Priority:** must-have

## Goal

A User or an agent who needs an ID prefix finds all twelve prefixes of `next-id` in one table, each with its kind of artifact and the files that claim it. `rules.md`, `branching-policy.md`, and `finding-format.md` point to that table instead of listing prefixes themselves. A text test fails when the table and the list in `next-id` differ.

## Contract

| File                                                         | Rule after the story                                                                                                                                                                                        |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/factory/rulebooks/conventions/id-prefixes.md`      | New. One table with the columns Prefix, Artifact, and ID producer, one row per prefix of `PREFIXES`: `ST`, `BUG`, `SPEC`, `FAGAN`, `SEC`, `RECON`, `ATAM`, `IMPL`, `T`, `ADR`, `ARCH`, `QA`                 |
| `packages/factory/rulebooks/conventions/finding-format.md`   | § File location and name points to `id-prefixes.md` and holds no `next-id <TAG>`. The table keeps one row per finding prefix with the review that files it, and gains `RECON` with the reconciliation agent |
| `packages/factory/rulebooks/rules.md`                        | The prefix sentence of § Branching points to `id-prefixes.md`                                                                                                                                               |
| `packages/factory/rulebooks/conventions/branching-policy.md` | The prefix sentence points to `id-prefixes.md`                                                                                                                                                              |

The ID producer column names the files of the proposal's [§ Each requestor names its prefix](../docs/proposals/counter-ids-fitting.md#each-requestor-names-its-prefix), by their paths under `packages/factory/`.

## Demo Scenario

1. The User opens `packages/factory/rulebooks/conventions/id-prefixes.md` and finds twelve rows. The `RECON` row names a drift finding and the files `skills/reconcile-spec/SKILL.md` and `agents/reconciliation-agent.md`.
2. The User opens `rules.md` § Branching and follows its link on prefixes to `id-prefixes.md`.
3. The User opens `finding-format.md`. Its table has nine rows, among them `RECON` with the reconciliation agent, and no line holds `next-id <TAG>`.
4. In a scratch session, the User asks the agent which prefix a drift finding of `reconcile-spec` takes. The agent reads `id-prefixes.md` and answers `RECON`.

## Demo Data

None. The story reads and changes Factory text only.

## Boundaries

- The text checker is one function that takes the paths it reads: `id-prefixes.md`, `next-id`, and the producer files. A test feeds it broken copies in `tmp_path` and never edits a file of `packages/factory/` (CIF-17-CT-01).
- The checker reads `PREFIXES` from `next-id` with `load_script` and compares it with the Prefix column as sets. It names each prefix in one and not the other (BR-108).
- The checker fails when a file in the ID producer column does not exist.
- This story builds the checker and its table case. ST-0384 adds the dropped-prefix case and ST-0385 the todo-writer case to the same function (CIFP-C13).
- The story removes `FINDING_FORMAT` from `PRODUCERS` in `tests/factory/test_counter_ids_text.py`, replaces `test_st_0372_finding_format_names_every_tag_for_next_id` with CIF-16-LN-03, and removes the `finding-format.md` row from `docs/spec/work/counter-ids-qa-strategy.md`: line 36 and line 91 say "five" ID Producer files, which become four (CIFP-C14).
- Until ST-0384 merges, `finding-format.md` points reviewers to `id-prefixes.md` for the prefix. Both stories ship on one feature branch (CIFP-C14).
- The story regenerates `INDEX.yaml` in the same commit, and `index-lint --check` passes.
