# Build fence runner with output validation and evidence storage

After an agent activity completes, a deterministic fence validates what the agent produced and stores the result as evidence.

**Priority:** should-have

## Goal

After an agent activity completes, the fence runner reads the agent's `outputs.declarations`, snapshots the declared output path patterns before invocation, compares them with the post-activity filesystem state, runs applicable validators against changed outputs, checks required/optional/minimum_changed rules, aggregates a pass/fail result, and stores evidence at `.agent-factory/checks/fences/<session-id>/<invocation-id>.yaml`. The evaluator uses fence evidence when checking downstream agent preconditions.

## Domain Rule

- The fence snapshots output path patterns before the activity and compares after.
- A required output with no created or modified match fails the fence.
- An optional output without a match is skipped; if a match changed, its validator runs.
- Fewer than `minimum_changed` declarations with changes fails the fence.
- Aggregate passes only when: all required outputs changed, minimum met, every invoked validator passed.
- Evidence is stored at `.agent-factory/checks/fences/<session-id>/<invocation-id>.yaml`.
- Fence failure is reported without blocking the developer.
- The fence has three terminal states: PENDING (before snapshot), CHECKING (after snapshot, during validation), PASSED or FAILED (terminal).

## Demo Scenario

01. An agent definition declares two `outputs.declarations` entries: one required (`backlog/ST-*.md`, validator `backlog-lint`, required `true`) and one optional (`docs/adr/*.md`, validator `adr-lint`, required `false`).
02. Snapshot the output patterns before the agent runs. Record which files match each pattern and their modification timestamps.
03. The agent activity completes. It created three new story files matching `backlog/ST-*.md` and wrote no ADR.
04. The fence compares post-activity state against the snapshot. The required pattern has three new matches. The optional pattern has no new or changed matches.
05. The fence runs `backlog-lint` against the three new story files. All pass.
06. The fence skips the optional ADR output because no match changed.
07. The fence checks `minimum_changed`: the agent declares `minimum_changed: 1`, and one declaration changed. Minimum met.
08. The aggregate result is PASSED. Evidence is stored at `.agent-factory/checks/fences/sess-001/inv-001.yaml`.
09. The evaluator checks a downstream agent whose `inputs.required` references `backlog/ST-*.md` with condition `check: backlog-lint`. The fence evidence satisfies the requirement.
10. In a second run, the required output produces no new files. The fence result is FAILED. The developer can still select any agent.

## Outputs

- `packages/factory/engine/fence.py` — fence runner module that:
  - Reads agent `outputs.declarations` and `outputs.minimum_changed`
  - Snapshots output path patterns (glob expansion, file existence, modification timestamps) before the activity
  - Compares post-activity filesystem state against the snapshot
  - Identifies created and modified matches per declaration
  - Runs the named validator against each changed required output and each changed optional output
  - Checks: all required outputs have at least one changed match; `declarations_changed >= minimum_changed`; every invoked validator passed
  - Aggregates pass/fail following the PENDING → CHECKING → PASSED/FAILED lifecycle
  - Stores evidence YAML at `.agent-factory/checks/fences/<session-id>/<invocation-id>.yaml`
  - Returns the evidence dict for the evaluator to consume
- `packages/factory/engine/eligibility.py` — integration: the evaluator reads fence evidence and uses it when checking downstream agents whose `inputs.required` conditions reference a `check:` validator
- `packages/factory/engine/schemas/` — fence evidence schema defining the YAML structure (session_id, invocation_id, agent_name, timestamp, declarations with per-declaration status, aggregate result)

## Constraints

- The fence runner never writes repository state beyond its evidence directory.
- Fence failure does not block the developer — no confirmation dialog, no override flag.
- The fence runner calls existing validators by name; it does not create new validators.
- Evidence storage path must match the contract: `.agent-factory/checks/fences/<session-id>/<invocation-id>.yaml`.
- The module must be named `fence.py` per the interface contracts specification.
- No external dependencies beyond the Python standard library and existing factory engine modules.
