# Update feature-addition and brownfield playbooks for charter

Add charter integration points to the feature-addition and brownfield-onboarding playbooks.

**Priority:** must-have

## Acceptance Criteria

- Feature-addition playbook Step 0.1 (or a new sub-step): asks "Does this feature require charter amendments?" If yes, amend via `update-charter`, re-run the planning gate for changed documents, derive any additional Epic 0 stories. If no, proceed unchanged
- Brownfield-onboarding playbook: `capture-charter --init --scan` runs after the Phase 5 ATAM architecture review passes (the brownfield playbook's final architecture quality gate)
- Brownfield flow: scans codebase, pre-populates skeleton, stakeholder confirms. No Epic 0 derivation — mise en place already exists
- Brownfield flow: planning gate (`charter-lint --planning-gate` + stakeholder approval) runs before any specification or planning work that follows onboarding

## Implementation Notes

Feature-addition is a small insertion at proposal intake. Brownfield is a new step after ATAM review. Neither changes the existing phase structure — they add decision points within existing phases.
