# Update developer-agent to consume prescribed RED phase

Update the developer-agent's step 3 (Red-Green-Refactor) to consume `#### Test Design` sections as its prescribed RED phase and run `#### Prior Tests` before writing new code. Preserve the existing fallback behavior for stories without test-design output.

**Priority:** must-have

## Demo

A developer-agent opens `backlog/ST-0200.md` (hypothetical). The story has a `#### Test Design` section with two Given/When/Then/Forbidden scenarios for a critical contract. The developer-agent writes exactly those two scenarios as failing tests -- no additional invented tests. It then implements code to make them pass. A second story (`backlog/ST-0201.md`) has a `#### Prior Tests` section listing `tests/test_domain.py::test_entity_uniqueness`. The developer-agent runs that test first and ensures its implementation keeps it green. A third story (`backlog/ST-0202.md`) has neither section -- the developer-agent follows its existing Red-Green-Refactor cycle.

## Acceptance Criteria

- When a story has a `#### Test Design` section, the developer-agent writes exactly the specified failure scenarios as failing tests (CC 9, test-design.feature Rule 8, Scenario 1).
- The developer-agent does not invent additional test cases when test-design output exists (CC 12, test-design.feature Rule 8, Scenario 3).
- The risk-class and layer assignment in the Test Design section determine where each test file lives (test-design.feature Rule 8, Scenario 1).
- When a story has a `#### Prior Tests` section, the developer-agent runs those tests first before writing new code (test-design.feature Rule 8, Scenario 2).
- The developer-agent's implementation must keep Prior Tests green (test-design.feature Rule 8, Scenario 2).
- When neither `#### Test Design` nor `#### Prior Tests` exists, the developer-agent follows the existing Red-Green-Refactor cycle (test-design.feature Rule 9, Scenario 1).
- Stories created before the test-design skill cause no workflow failures (test-design.feature Rule 9, Scenario 2).

## Scope

**Status quo:** The developer-agent's step 3 says: "If `tests:` is absent or empty, follow the full Red-Green-Refactor cycle." The test-design skill exists (delivered by ST-0185) and the create-backlog-stories skill carries test-design sections into stories (delivered by ST-0186).

**Adds:** A new condition in step 3, before the existing `tests:` check: if `#### Test Design` exists, use it as the RED phase; if `#### Prior Tests` exists, run those first. The existing fallback behavior is preserved.

**Out of scope:** The test-design skill itself (ST-0185). The gate script (ST-0188). Changing the developer-agent's Green or Refactor phases.

## Notes for the Implementer

The change is to the developer-agent's markdown definition at `factory/agents/developer-agent.md`. The new condition goes into step 3, structured as a three-branch conditional: (1) Test Design section present -- write exactly those scenarios; (2) Prior Tests section present -- run those first, keep green; (3) neither present -- fall back to current behavior. The wording must be unambiguous: "writes exactly the failure scenarios specified" means no additions, no substitutions, no reinterpretation.
