# Extend testing strategy with risk-class definitions

Add three default risk classes to the testing strategy convention at `factory/rulebooks/conventions/testing-strategy.md`: critical, standard, and structural. Each class defines a failure-scenario format and a test-budget rule. These convention-level defaults serve as the fallback when a project does not override them in `testing.yaml`.

**Priority:** must-have

## Demo

Open `factory/rulebooks/conventions/testing-strategy.md`. A new "Risk classes" section defines three classes in a table: critical (atomicity, concurrency, security -- Given/When/Then/Forbidden format, unbounded budget), standard (CRUD, validation -- concrete scenario format, equivalence budget), and structural (declarative structure -- linter-owned, no test-design output). The section explains the precedence chain: `testing.yaml` inline overrides take priority over the convention defaults.

## Acceptance Criteria

- The testing strategy defines three risk classes: `critical`, `standard`, `structural` (test-design.feature Rule 10, Scenario 1).
- `critical` specifies Given/When/Then/Forbidden format and unbounded budget covering every distinct failure mode (test-design.feature Rule 10, Scenario 2).
- `standard` specifies concrete scenario text format and equivalence budget of one per equivalence class plus boundaries (test-design.feature Rule 10, Scenario 2).
- `structural` delegates to the deterministic linter layer with no test-design output (test-design.feature Rule 10, Scenario 3).
- The section documents the precedence chain: `testing.yaml` inline > project-linked strategy document > Factory convention defaults.
- Each risk class documents characteristics that trigger it (atomicity/concurrency/security for critical, CRUD/validation for standard, declarative structure for structural).

## Scope

**Status quo:** The testing strategy defines five layers, the one-contract-one-owner principle, the admit-a-test gate, and the choose-cases-by-behavior heuristic. It does not define risk classes or failure-scenario formats.

**Adds:** A "Risk classes" section with a three-row table (critical, standard, structural), their failure-scenario formats, budget rules, and the precedence chain. A "Failure-scenario format" subsection with the Given/When/Then/Forbidden template for critical contracts.

**Out of scope:** Project-level risk-class overrides in testing.yaml (ST-0183). Custom risk classes. The test-design skill itself.

## Notes for the Implementer

The risk-class definitions are original to the test-design-skill proposal (Design Details section). Place the new section after the existing "Choose cases by behavior" section and before "Delete overlapping tests safely." The Forbidden line in the Given/When/Then/Forbidden format is the test's reason for existence -- emphasize this.
