# Send a refused story back to the gate-check step in an orchestrated run

**Priority:** must-have

## Goal

In an orchestrated run, a refused `premerge-check` sends the story back to the gate-check step. An uncommitted change to a tracked file in the worktree of the feature branch stops `merge-story`, unless `dispatch.refuse_dirty_feature_worktree` is `false`.

## Domain Rule

- `merge-story` merges nothing when `premerge-check` refuses, when the feature worktree of an orchestrated run holds an uncommitted change, or when git refuses the checkout or the merge. In each case it exits 1 (BR-124).
- The refusal of an uncommitted change applies only before a new merge. On the rerun after a refused amend, `merge-story` finds the merge commit at `HEAD` and runs no refresh, no `premerge-check` and no merge, and the change to `backlog/<id>.md` that the amend left stays allowed (BR-124, BR-118, SPEC-0110).
- A missing `dispatch.refuse_dirty_feature_worktree` means `true`. Only an orchestrated run reads it.
- After a refusal, the implementation agent runs the gate-check step again with a fresh developer agent.

## Analysis

- **What changes.** `cmd_merge_story` in `packages/factory/scripts/dispatch` gets a check of the feature worktree. It runs in an orchestrated run, after `premerge-check` exits `0` and before the merge. It reads `git status --porcelain --untracked-files=no`, so only tracked files count. On a change it exits `1`, names the files and the worktree, and keeps the entry `dispatched`.
- **Where the check sits.** The check lives inside the `not already_merged` branch. The rerun after a refused amend therefore skips it, and the leftover change to `backlog/<id>.md` stays allowed (SPEC-0110). `--dry-run` skips it too, because a dry run runs `premerge-check` only.
- **The key.** `_read_refuse_dirty_feature_worktree` reads `dispatch.refuse_dirty_feature_worktree` from `docs/testing.yaml` the way `_read_attempt_limits` reads `gates`. A missing file, section or key means `true`. A value that is no bool refuses the merge and names the file. The shared root lookup moved into `_checkout_roots`.
- **The agent text.** Step 4d of the orchestrated workflow in `implementation-agent.md` now sends a refused `premerge-check` back to the fix-iteration loop. It also tells the agent to report a dirty-worktree refusal to the User unchanged and leave the worktree alone.
- **Seams.** The `dispatch merge-story` subprocess in a `tmp_path` repository with a feature worktree, built by `_orchestrated_on_login` (RL-08-IT-15, RL-08-IT-16). The folded section text of `implementation-agent.md` (RL-08-LN-01).
- **Scenarios covered.** "A refused premerge-check sends a story in an orchestrated run back to the gate-check step", "An uncommitted change in the worktree of the feature branch stops merge-story in an orchestrated run", and "merge-story merges past an uncommitted change when dispatch.refuse_dirty_feature_worktree is false".
- **Stop conditions.** An untracked file does not stop the merge; a test proves it. Code and BR-124 agree on exit `1`.
- **RL-08-IT-15 was green before the change.** ST-0410 already ordered `premerge-check` first, so its tests pass without new code and guard that order.

## Outputs

- `merge-story` checks the feature worktree before it merges and reads the key.
- `implementation-agent.md` sends a refused story back to the gate-check step.
- A spec-feedback row asks the test-strategy agent to add `dispatch.refuse_dirty_feature_worktree` to this repository's `docs/testing.yaml` at the wave close.

## Demo Scenario

1. In an orchestrated run on `feature/login`, the feature worktree holds a changed tracked file. `dispatch merge-story ST-0350` exits 1 and names the file.
2. With `dispatch.refuse_dirty_feature_worktree: false` in `docs/testing.yaml`, the same merge passes.
3. With a failing gate, `merge-story` exits 1, and the implementation agent spawns a fresh developer agent with the gate output.

## Demo Data

None. The tests build an orchestrated run with a feature worktree and write the key into a temporary `docs/testing.yaml`.

## Boundaries

- The run by hand keeps git's own refusal and does not read the key.
- The story does not edit `docs/testing.yaml`; it records the change as a spec-feedback row.
- `packages/factory/INDEX.yaml` is regenerated in the same commit.
- Source edits go to `packages/factory/`, never to `.agent-factory/factory/`.
- No edit of the specification, the architecture, the QA strategy, or `docs/testing.yaml`. A needed change there becomes a row of `docs/spec/work/spec-feedback-<id>.md`.
- Each pytest test carries `@pytest.mark.spec("<Test ID>")` with the Test ID of its QA strategy row. Every git test builds its own repository in `tmp_path`.
- `quality-gates` is empty, because `docs/testing.yaml` disables both test guardrails.
