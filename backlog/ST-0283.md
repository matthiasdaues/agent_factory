# Fix a missing prerequisite during installation with consent and verification

**Priority:** should-have

## Goal

When preflight during `install-agent-factory` reports a fixable missing prerequisite (managed Python or uv), the bootstrap offers the fix with its purpose, command, scope, reversal, and verification. The fix runs only after affirmative consent. The related check passes after the fix before the next fix is offered. Unsupported fixes (Git, shell, network, coding interface) receive guidance only.

## Analysis

**Implemented:**

- `PreflightCheck` gained a `fixable` flag distinguishing prerequisites the bootstrap may run a fix command for (uv, managed Python) from ones it can only describe (Git, shell, platform).
- `check_uv()` updated to the decided contract: scope `~/.local/bin`, reversal `uv self uninstall` (previously stated `~/.cargo/bin/` and `rm ~/.cargo/bin/uv`, which did not match this story's resolved decision).
- New `check_managed_python()` checks `uv python list | grep 3.10`; its fix is `uv python install 3.10` (scope `~/.local/share/uv/python`, reversal `uv python uninstall 3.10`). The check reuses the exact verification-command string used by the fix, since the fix loop "repeats the related check."
- New `run_fix_command()` / `run_verification_command()` run a fix or verification string through the shell (curl-pipe fixes need shell semantics; no platform branching, per this story's resolved decision).
- New `get_fix_consent()` shows the five required fields and treats blank input, decline, or `EOFError`/`KeyboardInterrupt` (cancel) as refusal.
- New `run_fix_loop(checks, input_func=, run_fix=, run_verify=)` iterates fixable, failed checks in order: offers consent, runs the fix, runs verification, and either continues to the next fix or stops (on refusal or failed verification) and reports completed fixes with their reversal commands. Per-prerequisite recovery guidance (`FIX_RECOVERY_GUIDANCE`) is shown verbatim from this story's resolved text on failed verification.
- `main()` calls `run_fix_loop(checks)` right after the `Blocked` readiness check and before interface detection — the fix loop only ever runs when readiness is `Ready` or `Ready with limitations`.
- Non-fixable checks (Git, shell) are never offered through `run_fix_loop` — they are skipped silently there; their guidance text is still shown in the existing preflight diagnosis printout, unchanged from ST-0281.

**Files changed:**

- `packages/factory/scripts/install-agent-factory`
- `tests/factory/test_install_agent_factory.py`

**Scenarios covered** (Rule "Newcomer controls each prerequisite fix", `docs/spec/value-first-onboarding-journey.feature`):

- Confirmed fix runs and is verified alone — `TestFixLoop::test_confirmed_fix_runs_and_verifies_alone`.
- Declined or blank fix input stops the sequence — `TestFixConsent`, `TestFixLoop::test_fix_stops_on_decline_and_reports_reversal`, `test_blank_input_stops_and_skips_fix`, `test_cancelled_input_stops_and_skips_fix`.
- Failed fix verification stops the sequence — `TestFixLoop::test_failed_verification_stops_sequence` plus the two recovery-guidance tests.
- Unsupported fix receives guidance only — `TestFixableChecksContract::test_git_and_shell_checks_are_not_fixable`, `TestFixLoop::test_unsupported_check_never_offered_fix`.
- One subprocess-level smoke test (`TestFixLoopIntegration`) exercises the real CLI with `uv` hidden from `PATH`, confirming the fix offer and its five fields appear and that a blank answer leaves the target unchanged.

**Concern flagged, not blocking:** the feature file's unsupported-fix scenario names Git, shell, network access, and a coding command-line interface. Only Git and shell exist as preflight checks in this codebase (from ST-0281); there is no network or coding-interface check to exercise. This is an existing scope boundary from ST-0281, not a conflict introduced by this story — noted in Spec Feedback below rather than treated as a Stop Condition.

**Real fix commands are not run end-to-end in tests.** The uv fix (`curl -LsSf https://astral.sh/uv/install.sh | sh`) reaches the network and mutates the host; it is exercised only through unit-level tests that inject fake `run_fix`/`run_verify` callables, matching this file's existing convention for prerequisite checks (e.g. `TestMissingPrerequisiteReport`).

## Contract

| Operation                                               | Input state                              | Outcome                                                                      | Persistence                    |
| ------------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------ |
| Offer fix for missing `uv`                              | Preflight detects `uv` absent            | Fix offered with purpose, command, scope, reversal, and verification command | No change until consent        |
| Approved fix                                            | Affirmative consent                      | Fix command runs; related check repeats before next fix is offered           | Tool installed per fix command |
| Approved fix, verification fails                        | Fix ran but check still fails            | Fix sequence stops; recovery guidance shown                                  | Partial fix may remain         |
| Declined fix                                            | Newcomer declines                        | Fix does not run; completed fixes and their reversal commands reported       | No change from this fix        |
| Blank input at fix prompt                               | Empty input submitted                    | Fix does not run; completed fixes and their reversal commands reported       | No change from this fix        |
| Cancelled fix                                           | Newcomer cancels                         | Fix does not run; completed fixes and their reversal commands reported       | No change from this fix        |
| Unsupported fix (Git, shell, network, coding interface) | Prerequisite is not fixable by bootstrap | Guidance text shown; no command runs                                         | No change                      |

## Required Script Behavior

### Supported fixes

Two prerequisites are fixable by the bootstrap. Each fix has five fields shown to the user before consent:

| Prerequisite   | Purpose                                 | Command                                            | Reversal                   | Verification                  | Scope                      |
| -------------- | --------------------------------------- | -------------------------------------------------- | -------------------------- | ----------------------------- | -------------------------- |
| uv             | Package manager for Python dependencies | `curl -LsSf https://astral.sh/uv/install.sh \| sh` | `uv self uninstall`        | `uv --version`                | Installs to `~/.local/bin` |
| Managed Python | Python runtime managed by uv            | `uv python install 3.10`                           | `uv python uninstall 3.10` | `uv python list \| grep 3.10` | `~/.local/share/uv/python` |

All commands work identically on macOS, Linux, and WSL. No platform branching.

### Fix sequence

The bootstrap offers fixes one at a time. After each approved fix:

1. Run the fix command.
2. Run the verification command.
3. If verification passes, offer the next fix.
4. If verification fails, stop the sequence and show recovery guidance.

### Unsupported prerequisites

Git, shell support, network access, and coding command-line interfaces are not fixable by the bootstrap. Preflight reports the missing prerequisite with guidance text only. The bootstrap does not run sudo, a system package manager, a global package install, or a coding interface installer.

### Recovery guidance

When fix verification fails, the bootstrap shows a per-prerequisite message:

- **uv**: "Fix ran but verification failed. Restart your shell and check `uv --version`. If uv is still not found, see https://docs.astral.sh/uv/getting-started/installation/. The fix may have partially applied. Reversal: `uv self uninstall`."
- **Managed Python**: "Fix ran but verification failed. Check `uv python list`. If the version is missing, run `uv python install 3.10` manually. The fix may have partially applied. Reversal: `uv python uninstall 3.10`."

### Cancellation report

When the user declines, submits blank input, or cancels, the bootstrap reports each completed fix with its reversal command, then stops.

## Boundaries

- All edits go to `packages/factory/`. Never edit `.agent-factory/factory/`.
- The fix loop must not run sudo, a system package manager, a global package install, or a coding interface installer for unsupported fixes.
- Blank input is never treated as consent.
- The fix loop extends preflight from ST-0281; it does not replace it.

## Demo Scenario

1. Run `install-agent-factory --from-local ./factory-src --target ./my-project` on a host where `uv` is not installed.
2. Preflight reports `Ready with limitations` and offers a fix for `uv` with its purpose, command, scope, reversal, and verification command.
3. Approve the fix. The bootstrap runs the fix command and repeats the `uv` check. The check passes.
4. Preflight continues with the next check.
5. (Alternative to step 3) Submit blank input. The fix does not run. The bootstrap reports completed fixes and their reversal commands.
6. (Alternative to step 3) Approve the fix, but the verification fails (simulated). The bootstrap stops the fix sequence and shows recovery guidance.
7. Run `install-agent-factory` on a host missing Git. Preflight reports the missing prerequisite with guidance. No fix command runs.
