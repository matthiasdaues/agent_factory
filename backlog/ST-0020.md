# Templates and schemas for source-record and conjecture

Author the paired template and JSON Schema for the evidence and claim-forming
artifacts: the source record and the conjecture.

The source-record schema requires source identity, author or issuing body,
publisher, publication date, relevant event date, source family, precise
evidence location, method, limitations, and provenance — the source-family
field is what later lets policy detect that copied sources are not
independent. The conjecture schema requires one claim, its scope, its
assumptions, supporting evidence, contrary evidence, possible refuting
evidence, planned tests, qualifications, and a content hash. The
"possible refuting evidence" field is mandatory so that a claim which cannot
state what would count against it is structurally incomplete.

**Priority:** must-have

## Acceptance Criteria

- Templates exist for source-record and conjecture with required headings and
  short field instructions, using the same field names as their schemas.
- The source-record schema requires the source-family field and all evidence
  fields listed in the proposal's Step 4.
- The conjecture schema requires exactly one claim plus scope, assumptions,
  supporting and contrary evidence, possible refuting evidence, planned tests,
  qualifications, and a content hash.
- A negative test proves a conjecture instance without "possible refuting
  evidence" fails `schema-validate` (supports "unfalsifiable claim cannot
  enter review").
- A negative test proves a source-record missing a required field fails
  `schema-validate`.
