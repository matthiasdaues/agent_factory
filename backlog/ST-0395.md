# Check in_use only when a finding is new or its basis or artifact changed

**Priority:** must-have

## Goal

The user waives a `major` finding after its branch merged into `dev`, and `finding-lint` still exits `0`, because `in_use` records a fact at the time of the review. A finding that is new against `HEAD`, or whose `basis` or `artifact` changed, gets the git check. A register file that replaces an old `.jsonl` line with the same values keeps that line's earlier check.

## Contract

| File state against the compared base                                                                                                                  | Git check |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| No version at `HEAD`                                                                                                                                  | yes       |
| `basis` or `artifact` differs from `HEAD`                                                                                                             | yes       |
| Only status, override fields, confirmation fields, or text differ                                                                                     | no        |
| New register file; the old `.jsonl` register of its class at `HEAD` holds a line with the same `id`, `basis`, and `artifact`, compared as parsed JSON | no        |
| New register file; that line differs in `basis` or `artifact`, or no line has the `id`                                                                | yes       |

The compared base is the staged version with `--staged` and the working tree without it, against `HEAD` in both cases.

## Demo Scenario

1. In `/tmp/inuse-demo`, the User commits FAGAN-0042 at `major` with `in_use: false` on `feature/demo`, then merges `feature/demo` into `dev`.
2. The User sets `status: waived` with `override_by` and `override_reason` in an editor and runs `finding-lint`. It exits `0`.
3. The User adds a new, uncommitted finding with `in_use: false` on lines unchanged on `dev` and runs `finding-lint` without `--staged`. It exits `1`.
4. The User commits `docs/findings/register/code.jsonl` with the line of FAGAN-0032, then stages its removal and `docs/findings/register/code/FAGAN-0032.json` with the same basis and artifact. `finding-lint --staged` exits `0`. With a changed `artifact`, it exits `1` with `artifact lines exist unchanged on dev`.

## Demo Data

Extends `/tmp/inuse-demo` of ST-0393 and ST-0394 with `docs/factory-settings.yaml` at `["v[0-9]*"]` and `docs/findings/register/code.jsonl` holding one line for FAGAN-0032 at `in_use: false`.

## Boundaries

- The trigger compares parsed values, so another key order or whitespace counts as unchanged.
- The moved-line rule reads only the `.jsonl` file of the same class at `HEAD`.
- The pre-commit hook and `validate` give the same answer for the same content.
