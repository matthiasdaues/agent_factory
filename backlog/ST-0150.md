# Update block-dangerous-git.sh to read charter allowlist

Replace the hardcoded `factory/scripts/run-tests --staged` allowlist in `block-dangerous-git.sh` (lines 19-23) with a charter reader that allowlists commands declared in `docs/charter/testing.yaml`. The guardrail still blocks bare `pytest`, `npm test`, etc. — the allowlist source changes from a hardcoded path to the charter declaration.

**Priority:** must-have

## Acceptance Criteria

- `block-dangerous-git.sh` reads `docs/charter/testing.yaml` to build the agent test allowlist
- `test_command`, `test_staged_command`, and `test_changed_command` are each allowlisted when present
- The match is exact: the full command string from the YAML field must match the agent's command; no prefix matching
- When `docs/charter/testing.yaml` does not exist, no agent test commands are allowed
- Bare test command deny patterns (`pytest`, `npm test`, etc.) still apply
- When `remove-factory` runs, the guardrail is removed and bare test commands become available again
- Exit code 2 is returned when a command is denied

## Implementation Notes

- Replace the hardcoded allowlist at lines 19-23 with YAML reading logic
- Use simple `grep`/`sed` YAML parsing (the file has a flat key-value structure for command fields) or source a helper
- The guardrail logic is bash; keep it self-contained with no external dependencies beyond standard POSIX tools
- Tier is standard per dispatch-contract tier rubric: outputs span `factory/config/hooks/` and the risk domain is reliability
